## 一、这一刀做了什么

`/compass` 直接渲染完整方向树。原方向台一级（`CompassShell.vue`：主航线 + 内嵌项目详情展板）与主航线面板（`LighthousePanel.vue`：愿景/使命锚点条、主攻聚焦条、状态筛选、目标卡 3 列网格、项目行卡、右键菜单）**两个文件物理删除**（110 + 392 = 502 行）；代码索引总量 176 文件/43,171 行 → **174 文件/42,693 行**（净 −478：删 502，树内预计算表/停滞标/页头摘要与深链改指吃回 24）。

```
/compass            → CompassTree（name: 'compass'，标题「方向台」）
/compass/projects   → ProjectCuration（从 Shell 的 children 平铺成一级）
/compass/tree       → redirect: to => ({ path: '/compass', query: to.query })   // 老深链保命
```

`App.vue` 的 keep-alive include 由 `…CompassShell…` 换成 `…CompassTreeView,ProjectCurationView…`——原来这两页靠 Shell 内层那个 `<keep-alive>` 缓存，一级化后收归 App 级，缓存收益不回退（R148-P1a 口径）。

## 三、★顺手修掉一条既存坏链：指标下钻的「定位」按钮

`MetricDrillDrawer.locateGoal()` 原先只做 `window.dispatchEvent(new CustomEvent('zy-locate-goal'))`，而**全站唯一监听者是 LighthousePanel**。问题是这条抽屉挂在**调度台首页**（`CompassHome` → `MetricBar` → 下钻），主航线住在 `/compass`——在调度台点「定位」既不会跳转、也没有监听者，**什么都不会发生**（此前无人发现，因为断言只核「LighthousePanel 里有 addEventListener」，代码在=判据过）。

改法与 `locateCurio` 同一条口径：`router.push({ path: '/compass', query: { hl: dirId } })`，由方向树既有的 `locateHlGoal()` 承接滚动 + `goal-flash`。事件链两端一起清零，新增断言把「发起端走深链 + 全站无 zy-locate-goal」写死。

## 四、★树担得起首屏的第二刀：预计算表

树升为一级后，R83-7 那条性能红线（模板内不逐项调 `projectProgress`/`isProjectStalled`）的管辖对象变成了它。原状是每张项目卡头在模板里调 **4 次** `projectProgress(proj)`，任务数还在模板里现算一次 `d.tasks.filter(...)`。补 `projMeta` 预计算表（pct/done/total/tasks/stall 一次算齐），并把这条判据从"已退役文件"搬到树，用 `segOf(t,'<template>','</template>')` 判模板段零命中——**判据跟着真实现走，不跟着尸体走**。

## 七、本轮踩到并修掉的三处自身错误（如实记账）

1. **E2E 跑的是 `dist`，不是源码**：改完源码没 build 就跑 E2E，三条方向台断言全红（旧包里 `/compass` 还是主航线，`.tp-head` 命中 0、`/compass/tree` 不重定向）。当时差点判成"一级化把树弄坏了"。顺序必须是 build → e2e（或先 `rm -rf dist && npm run build`）。
2. **注释自匹配陷阱又踩一次**：为解释"一级台面没有返回钮"写的注释里出现了 `返回方向台` 字面量，直接让新写的负判据恒假。同类问题在 R2-⑥（`curSplit`）、R2-⑧（`fileImportInput`）各踩过一次——**负判据一律走 `codeOnly()`**，这条纪律本轮再次自证。
3. **批量替换脚本两处工具性错误**：python 原始串里写 `\"` 会原样落进 JS 造成语法错（两次，均被 `node` 加载期抓出）；块替换的结束锚点没考虑"单行 check 以 `});` 收尾"，会一路吞到下一个块尾（幸而写文件在末尾，异常先抛、未落盘）。
