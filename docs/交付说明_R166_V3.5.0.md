## 二、与交接清单的一处偏离（重要）

清单 T5 要求"新建 `AiCompareModal.vue`"。**实际没有新建**——核对后发现 R161 起 `AiSuggestionDrawer.vue` 已经是中央 `Modal` + 左右双栏 + 角色下拉（切换即带指令重跑）+ 一次性指令条 + 「应用并重跑」，定案 7 描述的形态**线上已经存在**。再建一个 `AiCompareModal` 就是全站第二套评审弹窗，直接违反这个仓库反复立的"不新建第二套"纪律（R146-5 徽标、R152 懒单例、R129 链接通道都是这么收的）。

改为补它离定案 7 真缺的三处：
1. **D9 单一编辑处**：角色下拉补「⚙ 管理专家」跳 `设置 → AI 助手`，弹窗内不建第二套编辑器（R166-10）。
2. **定案 7「Esc 分层关闭」是坏的**：`Modal.vue` 注释声称"一次 Esc 只关一层"，但它的 `stopPropagation` **挡不住同一节点（document）上更早注册的监听**——任务抽屉比弹窗先注册，实测一次 Esc 两层同关。修法是在下层宿主让位（`if (aiJob.value) return`），不动 14 宿主共用的 Drawer/Modal（R166-8）。
3. **定案 8 需要契约支撑**：`AiJob.adoptLabel` 新增，抽屉优先用它（R166-9）。

> 这条偏离记下来是因为方向反了容易看错：不是"我少做了一个组件"，是"清单假设线上还是旧形态"。**交接文档的基线是 Mac 那台的 HEAD，写清单时中央弹窗已经存在两轮了。**

## 三、门禁自己照出来的三个真缺陷

1. **退役字段会从"导入"这条路回流**。`stripKeys` 只在 `loadData` 跑，而设置页导入的 `mergeById` 是 `{...existing, ...incoming}` 覆盖、**导入发生在载入之后** ⇒ 旧导出包里的 `mountedResourceIds` / `fromCuriosityId` 会重新钻进内存并立刻写回存储。新增 K5a「导入当场剥离」用例第一次跑就红，抽出 `RETIRED_CARD_KEYS` + `stripRetiredCardKeys()` 单一真源，载入与导入两条路都过（红线断言同步要求两处都调）。
2. **注释里的退役词把负向断言全撞红**。本轮 R144 系 + 红线共 5 条同时假红，原因都是"讲为什么退役 X 的注释里必然提到 X"。新增 `codeOnly()`：负向判据先剥注释（块注释 / `//` 行 / 模板 `<!-- -->`）再查——**剥完还在才是真残留**。同轮的 `import type` 误判是同一族问题（R135-5 静态判定改为先剥类型导入，否则合法类型引用会被逼成复制定义）。
3. **升版本号的"全局替换"把依赖锁改脏了（R166-11 收下）**。六处版本同步不含 `package-lock.json`，但"把旧版号 `3.4.2` 整体换成新版号"的写法会命中 lock 里 `"node_modules/consola": { "version": … }` 这一行：装的、`resolved` tarball 都是 **3.4.2**，字段却被连着改成 `3.4.3`（R165-A 补漏轮）→ `3.5.0`（本轮）。**它长得就是一个版本号，人眼扫过去只会认为"已经同步过了"**，且 lock 根节点的 `version` 三轮里从未被真正更新（一直停在 3.4.0），说明那条"第六处"其实一直没落地。
   处置：consola 字段改回 `3.4.2`；新增 **R166-11** 机器判 —— 遍历 lock 内所有 `.tgz` 依赖，`version` 字段必须等于 tarball 文件名里的版本，不符即红并点名条目；活性验证已做（把该字段注入成 `9.9.9` → 单条红、错误消息 `version=9.9.9 ≠ tarball=3.4.2` → 撤回即绿）。lock 根节点版本**不并入六处**（本轮不动它，避免与"六处一致"的既有口径混谈），但它漂移与否现在由同一条断言的框架兜住，日后要并入只需扩该检查。
