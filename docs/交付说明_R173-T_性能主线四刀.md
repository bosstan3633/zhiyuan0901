## 一、T0 量具修正（先修尺，再量活）

两条 R172 遗留量错：
1. 「卡片定位」「切台」实测**未命中**——不是慢，而是探针盲等 `.res-card`，而真库默认视图是金字塔 ⇒ 量到的是"我等错东西"。
2. 只报单条最大长任务，不报**窗口内合计** ⇒ 「一次切换里多条中等任务」被系统性低估。

修法（`perf.cjs` / `perf-census.cjs`）：

- （T2 期间再补）census 加「就绪墙钟 + 预热步 + prep 2500→4600 清上一窗口落盘尾」——把上次的落盘长任务清出量区。

## 二、T1 看板列窗口化（视口驱动）

**问题**：R169 立的阈值「列数 > 60 才裁剪」在真库 50 台 / 33 列（48 台资源台）下**永不触发、等于没做**——R172 实测切看板 +1143 节点 / 阻塞 249ms，仍是全站最慢的同屏切换。

**修法**（`useResourceView.ts` + `Workspace.vue` + `workspace.css`）：
- 窗口 = **滚动位置 ± KANBAN_COL_BUFFER（2 列 ≈548px）**；滚到即原位换真列（`measureKanbanWin` 由滚动 / 缩放 / keep-alive 归位驱动）。
- 窗口外两侧渲染**等宽 ghost 占位**（1 节点/列，透明空壳）——保横向几何与滚动条：scrollWidth 恒 6288px，滚动位置不因窗口漂移而跳（原「列尾显式入口」退役）。
- 拖拽源列由 `setKanbanDragCol` 钉住（源节点中途被摘 ⇒ dragend 可能不触发、dragState/dropMark 残留）。
- ★**空哨兵必须 null**：「待分类」列 key 就是 `''`，用 `''` 表空闲会 findIndex 恒命中最后一列（实测 hi 恒 = n-1、窗口右缘永远收不回、切看板仍全量 23 列）。

**验收（同批 A/B**，`t3b_perf_A/B.txt`；A = pre-T1 快照 `zy_r173_base_dist`，B = T1 后）：
| 量 | A（pre-T1） | B（T1 后） |
|---|---|---|
| 看板切换 同批最小 | 73.2ms | **33.3ms** |
| 看板切换 中位 | 80.5ms | 34.7ms |
| 看板渲染项数（结构量） | 102 | **36** |
| census DOM 增量 | +1143 | **+127** |
| census 实列 | 23（实 23 + ghost 0） | **8（实 8 + ghost 15）** |
| census 滚动宽 | 6288px | 6288px 恒 |

其余视图未受影响（同批最小值：卡片 17.6→20.1 / 列表 33.3→34.5 / 金字塔 38.9→39.2ms）；滚动最差帧 19ms、无掉帧。

## 三、T2 开详情 116ms 拆账（三条真相）

「116ms」出处锁定 = **R172 census 的开详情步阻塞合计、会话首次冷路径**（不是每次开卡都付）。

三条真相（`t2_perf1-3.txt` · `t2_census2.txt` · CDP tracing 拆账探针）：
1. **不是"每次开卡"成本**：会话**首次**挂载付一次长任务 **88~111ms**（同批逐轮 88/0/0、111/0/0），第 2 次起 0；census 热对照 0~53ms、关抽屉 0。
2. 那笔 116ms 还混着**进台 4s 后整库写盘**（49~84ms，Workspace.vue 节流）——旧量具窗口没清它 ⇒ T3-a 修掉（拍板 a）。
3. 点击→抽屉出现：perf 三批**最小 291ms** / 中位 ~300ms，其中 **260ms 是单双击判别器常量**（R73 交互设计；拍板 b：保持）；真正开详情动作只剩 **~40ms 首帧**。census 同量级（就绪 312~380ms）。

结构量：**懒 chunk = 0**（开详情子树全静态 import）· DOM +85（抽屉 83 节点）· **主数据重写 0 次** · 关抽屉全回收。
主程序归因第一手：CDP Profiler 自时间几乎为零（headless 采样被节流 ⇒ v1 结论作废），改用 **Tracing 权威拆账**——成本在挂载/样式布局一次性段，与 3 条真相一致。
量具随本刀重写：perf R3 由「click() 同步段」改「点击→`body > .drawer` 出现」墙钟 + 逐轮阻塞 + 写盘计数（`__openDetailWall`）；`R164-9` 断言随迁带备案。

## 四、T3 检索与卡片定位响应

### T3-a 「进台 4s 后整库写盘」改走热度键小载荷（拍板 a：可以）

进台/切台只改 `workspaces[].callCount/lastCalledAt` 两个字段，原实现 4s 后走 `persist()` **整库**（真库每次 49~84ms，每次进台都付）。现：
- `hotStats.ts` 帧扩 **`ws` 段**（id → [callCount, lastCalledAt] 与 cards 同形）；`extractHot`/`applyHot` 同步。
- `app.ts` `persistHot(immediate?)`；Workspace 4s 定时器 → `persistHot()`；**页隐藏/卸载补写 → `persistHot(true)`（跳 250ms 防抖）**——防抖定时器会随页面冻结/销毁，补写必须立即落盘（这正是原 flush 存在的意义）。
- 另两处台跳转（GlobalPopups locateCat / 检索 ws 条目）同步改走 `persistHot()`。

**运行期 A/B**（`t3b_wswrite2_old/t3.txt`；monkey-patch `chrome.storage.local.set/remove` 直采，10s 轮询）：
| | 进台 4s 那笔写 | 载荷 |
|---|---|---|
| 旧（pre-T1 快照） | `set zy_data_v2,zy_stats_v1 @+8524ms` | **276,094 B**（整库） |
| 新（终版） | `set zy_stats_v1 @+8450ms` | **9,912 B**（仅热度键） |

⇒ **载荷 27.9× 减载**；启动写两包同为整库一笔（行为一致）。

**功能验收**（`t2a_probe1.txt`，P1~P3 全过）：进台 4s 恰 1 笔热度键写（帧含 ws[台id]、计数=种子+1）· 零整库写；重启后 `applyHot` 恢复（7→8，防"恢复成 1"回归）；隐藏补写跳防抖（实测延迟 **+5ms** < 150ms 闸值）。

### T3-b 「检索面板独立合成层（will-change）」提案 → 证伪撤下

- 早前判据「will-change 消除换词尖峰」的 lpanel=0 是**顺序混淆**：lpanel 恒排最后跑，且「预热后首轮重、后续轻」普遍（blur2 base#1 225→#2 62；blur3 897→#2 191）。
- **真包三包 A/B**（`t3b_blur_*`，7 轮）：三包同批最小值**均 0ms**；base 自身首轮量级 543/322/95 = **5.7× 散布**（纯噪声）。
- **顺序平衡变体轮转**（`t3b_spike1/2.txt`）：none vs off 差 1.8×→1.5×→1.2×，全部低于本机可判幅（>2×）。
- 结论：**无可复现收益，撤下不入包**——源码 / dist / regression 三处已清（dist 重建后 GlobalPopups CSS 无 will-change）。

### T3-c 卡片定位：看板（含远端列）定位静默落空 —— 真缺陷，修

**病根**：T1 列窗口化后，目标列不在窗外 ⇒ kc-card **节点根本不渲染**；且 kc-card 从 R117 起没接 flash（此前定位到看板既不滚也不亮）。
**修法**（`useResourceView.ts` ensureCardRendered 看板分支 + Workspace.vue + workspace.css）：定位前先把 `.kanban` 横滚到目标列（`scrollLeft = max(0,(ci-2)*274)` → 立即 `measureKanbanWin`），再抬列内限额；kc-card 补 `:data-rid` + `flash` 类。
**运行期 A/B**（`t3b_kanban_base/t3.txt`；远卡 rc_mu1045wi4vxa 在 ci=21/23，初始窗=前 8 列）：
- base（T1 快照）：节点 **false** · flash false · scrollLeft **0** · 视口 null —— **静默落空复现**
- T3（终版）：节点 **true** · flash true · scrollLeft **5146** · 视口内 true

### 检索引擎成本重定位（结论：无新可修项，账留档）

主导成本 = **面板 mount（~600ms）+ 首次结果渲染（~600-900ms）一次性**（点击后 +37~+50ms 首个尖峰）；**稳态换词（面板已开再打字）两包一致 ~70-150ms**。检索路径的可感成本 = 一次性成本 + 既有交互设计常量（260ms 判别器，拍板 b 保持），本轮无进一步可摘动作。
