## 一、十二项交付明细

### B1 · keep-alive 切台空白（原：经 /compass 换台不复位 → 资源台白屏）

**缺陷**：`Workspace.vue` 的换台复位守卫是 `if (nv && ov && nv !== ov)`。KeepAlive 下**离开资源台**也会触发该 watch（`nv=undefined`），于是 A→/compass→B 真换台时 `ov` 已是 undefined，条件判假 → 局部状态不复位 → `activeCategory` 仍指旧台分类 → 渲染集为空 = 空白页。

**实现**：改记「上次所在台」（`lastResetWsId`）：`nv` 与记忆相同（同台重返）→ 保留状态；不同 → 复位（分类/搜索/多选/折叠五件套）。同台重返不再误伤、经途换台必复位。`App.vue` keep-alive **维持不带 route key** 的组件级缓存（评估结论：加 key 等于每次换台重挂载，R65-F7 的 595ms 免重挂载收益全部作废；复位已由本守卫承担）。

### B2 · 拖拽越界重写 curOrder（原：'all' 视图拖一张卡，兄弟子分类排序全被打乱）

**缺陷**：R64-F9 树状递归分组后 `resourceGroups` 已按**单分类**分区（组 key = 分类自身 id），而 `useResourceDragDrop.groupKeyOf` 仍按 root 家族聚合（'all' 视图返家族根 id、父台直属返 `'direct'`）。两套 key 错位使「落位分区按物理序全量重写 curOrder」扫到同家族**所有兄弟子分类**，把它们的拖拽序一并打乱；`crossGroup` 判定也随之失真（同家族跨分类移动改了归属却不提示）。

**实现**：`groupKeyOf` 与渲染分区合一——`isUncat → 'uncat'`，否则返 `r.categoryId`。curOrder 重写范围自然收窄到实际落位分区；跨子分类落卡「已移动至「X」」提示恢复准确。`activeCategory` / `familyIds` 随本函数退役（从 ctx 与解构中删除，接口收窄）。

### B3 · 待分类判据合一（原：计数看得见、点进去消失）

**缺陷**：`applyViewFilters` 用严格 `!r.categoryId`，而左树计数（`uncategorizedCount`）与分组（`resourceGroups` 的 uncat 桶）用宽松 `isUncat`（含「分类已删/失效」）。悬空卡被计入「待分类 N」，点进「待分类」却一张不显。

**实现**：过滤管线改走 `isUncat(r, catIdx.byId)`；金字塔「关联资源卡」弹窗的 `__uncat__` 过滤同步宽松口径（无分类**或**分类已删）。至此「待分类」全站单一判据。

### B4 · 子标签重命名谎报「同步 0 张卡片」

**缺陷**：卡上存的是「父/子」路径标签，`tagUsage(name)` 按裸名匹配恒得 0，重命名 toast 永远谎报。

**实现**：`tagUsage` 叶子/全路径双口径匹配（判据注释明确「不含子树」，与 R127 拍板一致）；toast 改报 swap 的**实际命中卡数**（`synced`，逐卡前后对比），零命中时显式提示「该标签当前无卡片挂载」。

### B5 · 链接协议全站统一 + 附件落盘文件名消毒

**实现**：`CuriosityPanel` 自建 `toOpenableCurioLink`、`TaskManagerPanel` 自建 `toOpenableLinkUrl` 双双退役，统一走 `shared/utils/link.toOpenableRawLink + openExternalLink`；好奇卡详情模板 `:href="c.sourceUrl"` 裸绑改 `:href="toOpenableRawLink(c.sourceUrl)"`（不可开协议降级为纯文本 span，导入数据不能再携带伪协议链接）；`htmlAsset.targetPath` 落盘文件名过 `safeAssetId`（`/^[\w-]{1,64}$/`，导入的附件 id 不能再穿越「知源附件/」目录或注入路径分隔符）。

### B6 · 监听器/定时器泄漏四处归零

1. `ProjectCuration.vue`：匿名「点外部关菜单」click 监听从不移除 → 改具名 `onDocCloseProjMenu` + `onUnmounted` 双摘除；
2. `useCatSidebar.ts`：拖拽宽度往 document 挂 mousemove/mouseup、只在 mouseup 里摘——拖拽中途卸载即永久残留并持有整个作用域 → 补 `onUnmounted` 兜底；
3. `useResourceView.ts`：搜索防抖 150ms 尾随定时器卸载不清 → 补清；
4. `usePyramid.ts`：resize 节流尾随定时器补清 + `enterPyFullscreen` 的 `await requestFullscreen()` 之后加 `pyDisposed` 卸载守卫（防把已脱离文档的宿主交给 `setOverlayFsHost`）。

### B7 · 「今日」边界与 30s 心跳解耦

**缺陷**：`nowTick` 每 30s 推进一次，`todayStart` 派生其上做 computed——首屏把 `todayIn/todayOut/todayCalled` 三个**整库三集合扫描**挂在心跳链上，靠 Vue 的等值短路才没全量重算，但每 30s 唤醒一次脏检查链，且零点边界最多滞后 30s。

**实现**：删心跳 ref，改「精确到次日零点」的自滚动 setTimeout（`new Date(y, m, d+1)` 构造，DST 安全；回调内以 `midnightOf(Date.now())` 再归一防时钟漂移）。30s 定时器只剩 `lastOkTick`（保存状态灯轮询，本就必要）。零点翻篇即时生效，卸载 `clearTimeout`。

### B8 · 批量移动对镜像浅拷贝空写（原：不落库却谎报成功）

**实现**：`useWorkspaceBatch` 移动入口只遍历 `natives`（镜像浅拷贝写字段不进库，镜像走 `moveMirrorTo` 既有通道）；「待分类」分类解析补 `!c.deletedAt`。

### B9 · 搜索收缩后键盘导航越界

**实现**：`TaskManagerPanel.onTaskNavKey` 前置空列表守卫（Enter 不再传 `undefined`）+ `taskNavIndex` 钳制回 `list.length - 1`。

### B10 · 北极星「本周 WRR」实为累计（周口径翻周）

**缺陷**：`stats.ts` 跨周分支只重置 `lastVisits`，`wrr.thisWeekUsage` 从不归零——「本周调用率」分子越滚越大，跨周冒充累计。

**实现**：`Stats['wrr']` 新增可选 `thisWeekStart`（周戳，向后兼容：无戳旧数据读数按 0 处理、当周首次写入即补戳）；新周分支归零 `thisWeekUsage` 并落 `weekStartKey` 戳；新增读出口 `weekUsageOf(data)`——`compass.ts`（北极星）、`MetricBar.vue`（指标条）、`GlobalSettings` 导入合并（两侧各自折算本周值再 `Math.max` + 盖当前周戳）三处统一消费。`weeklyReport.ts` 上周窗口 `dow - 7 * DAY` 改 `new Date(y, m, d - dow - 7)`（DST 安全，`DAY` 常量退役）。

### B11 · 书签导入可落进回收站分类

**实现**：`useWorkspaceImport` 目标分类 `find` 补 `!c.deletedAt`（卡落进软删分类 = 既不显示又难恢复）；`bkBookmarks` 从一次性快照改响应式 `ref`（面板常开时二次导入读到的是旧清单）。

### B12 · 台名剥图标唯一口径（★ 数据腐蚀级修复）

**缺陷**：`setWsIcon('')` 后各处硬写 `name.replace(/^[^\s]+\s/, '')` **无条件剥首段**——清除图标或从未设图标的台，台名首词被永久吃掉（存盘即腐蚀）。全应用 24 处各写各的。

**实现**：新增 `shared/utils/wsName.ts` 双 helper——`wsDisplayNameOf`（**仅当 icon 存在且确为 name 前缀**才剥）与 `wsNameWithIcon`（拼接唯一入口）；`useWsMeta`（含 setWsIcon/renameWs/deleteWorkspace 落库路径）、`GlobalSettings`（10 处）、`RecycleBin`、`ResourceDetailDrawer`、`useResourceDrawer`、`App.vue`、`GlobalPopups`、`overlay-impl`、`CuriosityPanel` 全量收编。**顺带揪出**：`CuriosityPanel` 那份副本写成 `/^[^s]+s/`（漏两个转义符）从未生效——好奇卡「转为任务」下拉里图标重复显示，本轮一并修复。
