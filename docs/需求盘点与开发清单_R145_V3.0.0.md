- 功能账：批次 G + 子任务软层级（R144）交付后，R139~R144 六轮功能项无遗留待办；R145 候选（骨架可视化/手动结父/研判记忆/体裁库/跨台引用）**是增强项不是欠账**。

- 唯一未达项：ZIP 607KB 超预算 7KB（原因与压回项见 §三），以及**真实网关实测仍为零**（按你指示延后）。

## 二、沉淀资产

- **门禁可跑性**：perf / import-compat 补齐与 e2e 同款的浏览器回落（pinned → `ZY_CHROME` → 本机任一 Chromium → 系统 Chrome）。「本机没那个版本的浏览器」从此不再是跳过门禁的理由——这正是 06-2 §B-1「门禁不跑 = 没有门禁」的落地。
- **外部种数据的规矩**：往 `chrome.storage` 直写以后**必须整页 reload** 再断言；SPA 内存态不重读存储，任何一次 persist 都会把种进去的数据盖掉。E2E-5/6/19/20 四条红与 K3 一条红全是这一条的代价，脚本注释已写明。
- **假指标要定期验尸**：钉死的 class 一旦改名，`__waitFor` 会把「超时」记成「耗时」。perf 的 M2c 就带着 15008ms 的假数据活了 33 轮（真值 16ms）。
- **V3.0.0 基线**：M1 460ms / M2a 75ms / M4b 20.8ms / M2c 16ms / M6a 1ms / M6b 11ms / M3 21659ms·50 次——下一轮性能对比以此为起点，别再拿 V2.80 的数字比。

## 三、R146 待办（按性价比排序）

1. **ZIP 压回 600KB 以内**：305KB 的拼音字典是最大单项——字典分段（首包只带常用字，其余按需取）或换更紧的编码；其次手册全文（约 280KB 分两块 chunk）可考虑折叠加载或外置 JSON。预算数不许改，压产物。
2. **M5 指标拆名**：唤起 / 键入 两栏分开，消除与 R112 的口径歧义。
3. **`scripts/lib/chrome.cjs`**：三处浏览器路径解析合一（唯一实现纪律）。
4. **G1 骨架与金字塔 L2 打通**（承 R144 清单）：论点骨架目前写在主题卡描述里，与金字塔分支是两套结构；「按骨架预演分支」只读预览先行。
5. **软层级手动结父 + 父行折叠**：目前只有拆解会自动挂父。
6. **G2 研判记忆 / G4 体裁库 / G3 跨台引用**（承 R144 清单）。
7. **真实网关实测**：G1/G2/G4 各跑一次，记录 token 与口味。
