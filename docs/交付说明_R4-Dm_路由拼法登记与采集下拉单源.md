## 一、把 R2-④ 那类判据换成能盯住"变量拼法"的形态

R2-④ 清死链时判的是「代码内 `/workspace/zy-curation` 该路由字面量零残留」。缺陷的实际形状却是
**`/workspace/${变量}`** —— 字面量扫描对它天生失明，所以这条断言一路绿着，同一族先后漏了两个入口
（⌘K 转资源的「查看」、指标下钻抽屉的佐证行，R4-Dk 已修）。本轮改成两张**每次现扫再比对的登记表**：

**表一 · 以模板字面量拼 `/workspace/` 的导航站点**（剥注释后按文件计数）：

| 文件 | 条数 | 为什么允许 |
|---|---|---|
| `shared/utils/locate.ts` | 1 | 唯一算式 `resourceLocateRoute` 的 else 分支本体 |
| `newtab/App.vue` | 3 | 台签、新建台后跳转、数字快捷键跳台——来源都是 `store.workspaces` getter（已过滤池） |
| `newtab/components/GlobalPopups.vue` | 3 | `locateOnly` 的池分支之后、`ws` 类型行、分类树定位——三处都在 `!== CURATION_WS_ID` 过滤之后 |

多一处红、少一处也红：新增站点要么走算式，要么在提交里**显式改这张表**（改表会在 diff 里露出来，评审看得见理由）。

**表二 · `workspaces[0]` 这一族"取第一枚实体当默认落点"的形状**（R4-Pa/R4-Dk 两条实测都栽在它上面）：

| 文件 | 条数 | 理由 |
|---|---|---|
| `content/overlay-impl.ts` | 1 | 采集面板分类下拉的默认台，与「存入位置」的默认项同源（选中池 ⇒ 分类只剩「待分类」，正是池语义） |
| `shared/storage/migration.ts` | 2 | V1 老数据导入兜底：v1 里根本没有池实体，取第一枚真台是导入语义，不是新卡落点 |
| `newtab/views/RecycleBin.vue` | 1 | 恢复兜底，且它前一项已显式 `w.id !== CURATION_WS_ID` |

外加两条硬约束：`/workspace/` 与池 id（字面量或 `${CURATION_WS_ID}`）全站不许同串；
`GlobalPopups`/`MetricDrillDrawer` 两个刚修过的文件里 `workspaces[0]` 与变量拼法一律不许回流（走 `codeOnly`，负判据不裸读）。

## 二、★量出来的新缺陷：网页采集面板里，用户能找到「资源台」

手册第 96 行明写：*"早期版本'顶部导航里有一个资源台'的说法已作废——照那句去找是找不到的"*。
**但采集面板里就有一个。** 探针 `/tmp/zy_dm_capture.cjs`（存量库形状：hub 实体排在数组第一项）实测改前：

```
台选项 = ["资源台→zy-curation", "事业策展台→ws-biz-000"]   默认选中 = "资源台"
```

也就是：隐藏池那枚实体被当成一枚普通台印进下拉、用的是退役实体名（没走 R4-Dg 的显示名单源）、
而且因为排在第一项所以是**默认选中项**。落点本身（存进池）其实符合今天的池语义，
坏的是它向用户展示了一枚本该不可达的退役台面，标签还是「存入台面」。

修法两处，都不新增口径：台名走 `wsName.ts` 单源（同一文件 668 行的 `wsName` 映射早就这么做了，
这一栏是漏网消费者），池那一枚显示 `POOL_DISPLAY_NAME`；标签文案「存入台面」→「存入位置」。复测：

```
台选项 = ["资源卡池→zy-curation", "事业策展台→ws-biz-000"]  默认选中 = "资源卡池"  分类 = ["📥 待分类"]
```

## 四、方法账：★我自己在这轮复现了本仓库最狠的那条坑

M4 第一次跑的时候，我把还原备份路径写成了上一轮遗留的 `/tmp/zy_gp_final.vue`（R4-Pa 时的旧副本），
`shutil.copy` 一执行 ⇒ **`GlobalPopups.vue` 被退回到 R4-Dk 之前的状态**，还原校验当场报错才暴露。
代价与处置：`git checkout -- v2/src/...` 从 HEAD 取回（R4-Dk 已提交，这是"一轮一提交"作为还原点的价值），
再用四条 `grep -c` 自证 R4-Pa 与 R4-Dk 的关键符号都在位（`convertToResource` 2 / 落点 1 / 拼音闸门 2 / `normedParts` 3），
M4 重跑一遍才算数。

这条与 R4-Pa 记的"A/B 文件状态漂移"是同一个错误的第二次成形：**探针/变异脚本引用的文件副本必须当场命名、当场自证，
不能复用上一轮留下的同名文件。** 已经把它写回判据纪律（还原后一律 `filecmp` 逐字节比，而不是只看回归绿了没）。

## 六、边界如实

- **登记表是白名单，不是定理**：它挡的是"没想过这件事就抄一份"，挡不住"想过之后加一条"——所以改表必须出现在 diff 里，而**新增站点的正确做法是走 `resourceLocateRoute`**。
- **overlay 那处默认台仍是 `workspaces[0]`**（表二第一条）：本轮只修了它显示的台名，没动它的取法。若哪天把 hub 实体从 `d.workspaces` 里删掉（待拍板项），这一处与 `migration.ts` 那两处要一起重看。
- **采集面板的下拉没有像素/运行时门禁**：这条修的是 content 侧的渲染串，theme-audit 不拍浮层、e2e 不驱动采集面板，只有 /tmp 探针量过改前改后各一次。要长期守住，需要给浮层补一类场景（另立）。
- **本轮没有改 `src/` 的路由表**：`/workspace/zy-curation` 仍然是能匹配的（存量库里它渲染一枚退役台面），彻底封掉需要先决定"那枚实体是改名还是删除"（待你拍板），或在 `Workspace.vue` 加一条 id 守卫——那是产品决策，不是我这轮该替你做主的事。
- #114 剩下三件（唤起 ~100ms 阻塞需拍板、键入尺子稳定性、结果表 ~1.3MB 驻留）与 R4-Dl 遗留的 2 张 0.001% 微差不在本轮。
