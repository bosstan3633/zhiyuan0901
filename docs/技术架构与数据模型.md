## 1. 技术栈

| 层 | 选型 |
|---|---|
| 框架 | Vue 3（Composition API / `<script setup>`）+ TypeScript strict |
| 构建 | Vite 5 + @crxjs/vite-plugin（MV3 打包 + HMR） |
| 状态 | Pinia（`useAppStore` 单一数据仓 + `useCompass`/`useCuriosity` 组合式） |
| 路由 | Vue Router（hash 模式） |
| 样式 | 原生 CSS Variables（tokens.css）+ scoped CSS；UnoCSS 仅引入 |
| 扩展规范 | Manifest V3；Service Worker + Content Script（纯 Vanilla JS，不引入 Vue 运行时） |
| 存储 | chrome.storage.local（单根 JSON），**无 IndexedDB、无云端** |

## 4. 存储结构

| 键 | 内容 |
|---|---|
| `zy_data_v2` | AppData 单根 JSON（见下） |
| `zy_ui_v2` | UIPrefs：theme / viewMode / fieldViewCfg / tcSplitRatio / wsSwitchMod / compassTab |
| `zy_capture_pref` | 采集默认工作台等偏好 |
| `zy_qc_prefill`（session） | 降级弹窗预填（标题/URL/mode） |
| `lm_data_v5` | 旧版数据（检测到则自动迁移至 zy_data_v2，并备份为 `lm_data_v5_backup`） |

### AppData（TypeScript 摘要，完整定义见 `shared/models/index.ts`）

```ts
interface AppData {
  version: 2
  compass: {
    vision: CompassNode; mission: CompassNode   // content/pinnedToLighthouse/linkedResourceIds?/linkedCuriosityIds?
    directions: Direction[]                      // { id, name, status, term?, pinnedToLighthouse?, projects: Project[] }
  }                                              // Project: { id, name, isFocused, pinnedToLighthouse?, order?, status, metrics: Metric[] }
  workspaces: Workspace[]                        // { id, name(含icon前缀), icon, coverTheme, order, archived, hotkey? }
  categories: Category[]                         // { id, workspaceId, name, order, parentId?(最多2级), pinned? }
  resources: ResourceCard[]                      // linkType: url|file|obsidian；tags/pinned/callCount/lastCalledAt/deletedAt…
  tasks: TaskCard[]                              // projectId+metricId 双挂；mountedResourceIds/mountedCuriosityIds（单向）；tags?
  curiosities: CuriosityCard[]                   // question/sourceUrl/status(todo|doing|done|shelf)/pinned/tags?
  dailyFocus: Record<'YYYY-MM-DD', FocusSlot[]>  // ≤3 槽：{ id, sourceType, sourceId?, text, done }
  tagTree: TagNode[]                             // { id, name, children? }（最多 3 级）
  fieldConfig: { resource: FieldDef[]; task: FieldDef[]; curiosity: FieldDef[] }
  stats: { weekly; lastReuse; lastVisits; wrr }  // lastVisits 跨周自动重置
  activityLogs: ActivityLog[]
}
```

**红线**：Resource / Curiosity / TagNode 的 Schema 中**禁止出现 taskId**（单向挂载：只有 Task 持有 mounted* 数组；愿景/使命的 linked* 为持有方引用，同样单向）。

## 5. 关键数据流

### 5.1 读写链路
```
组件 → useAppStore.data（响应式）→ store.persist() → repository.saveData()
  → 300ms 防抖 → chrome.storage.local.set → storage.onChanged
  → 其他上下文 syncCache + data.value 替换（跨页同色）
```
- content script / popup **直接读写** storage（不经 Pinia）；新标签页通过 `storage.onChanged` 感知外部写入（`syncCache` 保持 cache 一致）

### 5.2 工作台单例定位（G）
```
发起方 sendMessage('zy-locate-workspace',{wsId,hl})
→ background：query 所有扩展新标签页 → 逐个 sendMessage('zy-where') 询问路由
→ 命中 /workspace/{wsId} → 激活窗口+Tab → tabs.sendMessage('zy-locate')
→ 未命中：发送方是新标签页则本页跳转；否则任一新标签页跳转；无 → tabs.create
```
⚠ 注意：`chrome.tabs.query` 的 URL 匹配**不含 hash**，因此必须用询问机制而非 URL 过滤定位 hash 路由。

### 5.3 通用路由跳转（B4）
`zy-open-route {route}` → background 复用任一新标签页 → `zy-route {route}` → App.vue `router.push`。

### 5.4 打开资源（WRR 口径）
`recordResourceOpen(data, resource)`：callCount++ / lastCalledAt / stats.lastVisits[id]++（跨周自动重置并滚动 weekly）。调用点：工作台单击详情、双击打开、搜索打开。

## 6. 消息协议汇总

| 消息 | 方向 | 载荷 | 语义 |
|---|---|---|---|
| `zy-ping` | SW→Tab | — | 探测 content script 存活 |
| `zy-open-search/capture/curiosity` | SW→Tab | — | 唤起对应浮层 |
| `zy-locate-workspace` | 任意→SW | wsId, hl | 工作台单例定位请求 |
| `zy-locate` | SW→新标签页 | wsId, hl | 页内路由到工作台并高亮 |
| `zy-open-route` | 任意→SW | route | 通用路由打开（复用新标签页） |
| `zy-route` | SW→新标签页 | route | 页内执行 router.push |
| `zy-where` | SW→新标签页 | — | 回答当前路由 path（单例询问用） |
| `zy-qc-prefill` | storage.session | title,url,mode | 降级弹窗预填 |
