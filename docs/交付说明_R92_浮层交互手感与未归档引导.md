## 二、改动明细

### T1 · D1：四处 `setTimeout(…, 50)` → 一个 `focusWhenReady()`

**勘验发现不是一处，是四处**同一个写法（写法各异、语义相同 —— 按"一个口径、多个出口"必须收敛）：

| 原行 | 场景 |
|---|---|
| 361 | 搜索浮层输入框 |
| 1203 | 资源卡采集（聚焦标题并全选） |
| 1395 | 任务卡采集（有选区聚焦描述，否则标题） |
| 1477 | 好奇心采集（聚焦并把光标移到末尾） |

四处都在 `root.appendChild(panel)` **之后**，且 `openOverlay()` 里 `.open` 已先置（`.open{display:block}`）⇒ **同步 `focus()` 完全可行**；50ms 只是历史遗留的"等入场动画"，代价是唤起后立刻打字时前几个字符被宿主页面吃掉。

```ts
function focusWhenReady(el: HTMLElement | null, opts?: { select?: boolean; toEnd?: boolean }) {
  if (!el) return
  const doFocus = () => { el.focus(); /* select / toEnd 按 opts 处理 */ }
  doFocus()
  // 兜底：宿主页面若在同步阶段抢回焦点，下一帧再争一次（≈16ms，远小于原 50ms）
  requestAnimationFrame(() => { if (document.activeElement !== el) doFocus() })
}
```

⚠ **`toEnd` 条件必须保留**：好奇心采集原本只在 `!selection`（无选区）时才把光标推到末尾 —— 有选区时文本已预填，光标应停在开头供检查。**已由 `R92-7` 把守**，防止后人"顺手统一"掉。

### T2 · D2：Esc 两段式

```ts
} else if (e.key === 'Escape') {
  const input = document.getElementById('__zy_si__') as HTMLInputElement | null
  if (input && input.value) {

```

**★ 一个刻意的"不一致"**：右端那个 `Esc` **按钮**（`#__zy_esc__`）**保持直接关闭**。

> 按钮是**显式点击意图**（点它就是要关），键位是**反射性动作**（手快按错很常见）。
> 二者语义不同是有意的 —— 已写进注释，并给按钮补了
> `title="关闭浮层（键盘 Esc 会先清空搜索框，空了才关闭）"`，免得后人当成 bug "统一"掉。
> 由 `R92-5` 把守。

> **勘验另发现**（不本轮改）：**没有 document 级 Esc 监听** —— 焦点离开搜索框后按 Esc 无效。修它要把监听挂到 document，会与宿主页面快捷键抢事件，属 D5「浮层内快捷键」范畴，已登记遗留。

### T3 · E1：未归档轻引导

"归位"对两类卡含义不同，但**判据都是现成的**：

| 卡类型 | 归位 = | 判据 |
|---|---|---|
| 资源卡 | 放进某个分类 | 「分类」下拉的 `<option value="">📥 待分类</option>` 是**默认项** ⇒ `catSelect.value === ''` 即未归档 |
| 任务卡 | 挂到某个项目 | `projSel.value` 为空即未归档（指标依附于项目，项目为空时指标必然为空，**只判项目即可**） |

```ts
// 资源卡
showSaved(filed ? '✓ 已入台 · Enter 打开看板' : '✓ 已入台 · 未归档 · Enter 去归位', …)
// 任务卡
showSaved('✓ 任务已保存 · ' + (filed ? 'Enter 打开项目' : '未归档 · Enter 去归位'), …)
```

> **动作不变，只换措辞**：Enter 的落点本来就是"定位到那张卡"，未归档时这句提示只是**告诉用户为什么要去那儿**。不新增路由、不新增写入。

### T4 · ★ 顺带修：回执文案指错了页面

```ts
const tcRoute = task.projectId ? '/compass/projects?p=' + task.projectId : '/?hl=' + task.id
showSaved('✓ 任务已保存 · Enter 打开' + (task.projectId ? '项目' : '方向台'), …)   // ← 改前
```

无项目时路由是 `/?hl=<id>` —— **`/` 是调度台**，不是方向台（`/compass`）。回执却写「打开**方向台**」。

这与 R91 刚清偿的「同步至任务中心顶部」（注释指向 R49 已退役页面）是**同一类坏账：文案指向的页面与实际落点不一致**。一行文案，零风险，顺手修掉。

## 四、★ 本轮最重要的一条经验：断言全绿 ≠ 断言在守门

`R92-1` 第一次跑是**绿**的。按惯例做活性验证（注入一个 `setTimeout(() => input?.focus(), 50)` 探针）时 —— **它仍然是绿的**。

**判据本身有洞**：

```js
!/setTimeout\([^)]*,\s*50\s*\)/      // ← 错
!/setTimeout\([^\n]*,\s*50\s*\)/     // ← 对
```

`[^)]*` **穿不过 `focus()` 里的那个右括号** ⇒ 整条正则对 `setTimeout(() => input?.focus(), 50)` 根本不匹配。

- 改对后：注入探针 → `R92-1` **正确变红**；撤掉探针 → 回绿。
- 同批验证：`R92-2`（调用数 5→4 变红）、`R92-7`、`R92-8` 均正确变红。

> 这条已写进技能。**"951 全绿"只能证明代码当前符合断言，不能证明断言会拦住回归 —— 只有活性验证能证明。**
