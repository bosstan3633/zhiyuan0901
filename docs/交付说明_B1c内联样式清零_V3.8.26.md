## 一、为什么这批值得单独发版

G2「内联样式清零」在排期里被估成「半天顺手活」，实测是 41 项方案里触面最广的一件。原因不在代码量，而在这句话：

> **内联样式是颜色令牌唯一的合法绕行口。**

写死一个 `color:#3A6B4C` 进模板，等于在那个位置钉死了「浅色主题下的深绿」——深色主题切过去，它不会跟着变，而 `vue-tsc`、`build`、回归、死 CSS 扫描**全都看不见**。它和 B0 那批 8 处「静默失能」是同一类病：类型对、构建过、门禁绿、界面在某个主题下不对。

所以这批的验收不是「代码里没有 style」，而是**「换主题时每一处颜色都会跟着变」**。

## 三、做法与边界

1. **只抽静态写法**：`(?<!:)style="…"` 负向断言排除 `:style="…"`。动态绑定按 Q2 拍板**保留**（树深度缩进、抽屉宽度、进度条百分比、文本框高度等由运行时求值）。
2. **值逐字等价**：除 §四 那一处修复外，所有新规则的声明与原内联一一对应，不做「顺手优化间距」。
3. **作用域按既有架构走**：
   - 有 `<style scoped>` 的组件 → 规则写进自身；
   - `Heatmap` / `ReviewPanel` / `PiHero` / `PiRhythm` / `PiYear` 依赖共享 CSS → 规则写进 `dashboard.css` / `pi-timeline.css`；
   - 组合选择器（如 `.picker-modal.pm-modal-export`）用于压过既有同名单类规则，避免被 `width:480px` 反压。
4. **命名按页面前缀**：`pm-*`（调度台）/ `pi-*`（画像）/ `tm-*`（任务面板）/ `gp-*`（全局弹层）/ `cz-*`（好奇心）/ `dz-*`（仪表盘）/ `rb-*`（回收站），与既有类名体系一致。

## 四、顺手挖到的一处真缺陷（本批唯一改像素处）

`GlobalPopups.vue:259` 原文：

```html
<span style="color:var(--text-tertiary);font-size:11px;">· 标签保存后自动补</span>
```

`tokens.css` 里**没有** `--text-tertiary` 这个令牌（实测 `grep -c` = 0）。浏览器遇到未定义且无 fallback 的自定义属性，会把**整条 `color` 声明丢弃**——这行提示从上线起一直在继承父级颜色，从未按「次要提示」显示过。

处置：按实际令牌阶梯改指 `--text-3`，并写进 `.gp-status-note`。**这是本批唯一故意改变像素的地方**，属修复不属收口。

> 与 B1-a 的 `var(--ok, var(--info-green, #3A6B4C))` 是同一族：**两个令牌都不存在，只有兜底值在生效**。区别是那处还能显示（硬编码绿），这处连兜底都没有。

## 五、判据侧改动

| 项 | 改动 |
|---|---|
| **P0-S7 扩面** | `FILES` 从 **2 个 → 22 个**（B1 全量收口文件）。每收一个文件就把文件名加进数组——不收口加棘轮，下一轮"顺手写个 style"就把活白做了 |
| **P0-S7 取段逻辑修正** | 原用 `indexOf('<template')` 到 `indexOf('<script')`，隐含「template 在 script 之前」；本轮 20 个文件里 **19 个是 `<script setup>` 在前**，原逻辑会把它们全判成「取不到模板段」。改为 `indexOf('<template')` 到 `lastIndexOf('</template>')`，SFC 两种写法都成立 |
| **判据正文** | 补记 `--text-tertiary` 这一例，并把边界三条（只算静态 / 只算模板段 / 先剥注释）保留 |

> 这条修正本身是一次「尺子跟不上数据」：**判据写死了文件组织顺序**，而 Vue SFC 允许两种顺序。扩面时必须先让尺子能读全部 22 个文件，否则会得到 19 条假红。
