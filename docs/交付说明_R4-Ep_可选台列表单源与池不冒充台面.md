## 一、改前实测（`/tmp/zy_ep_probe.cjs`，两种库形状各真点一次）

| 形状 | 下拉选项（文本→值） | 默认选中 | 点「✓ 确认转化」后的回执 | 落库 workspaceId |
|---|---|---|---|---|
| ① 存量库（hub 实体排数组第一） | `["🗂 资源台→zy-curation", "💼 事业策展台→ws-biz-000"]` | **🗂 资源台** | `✓ 已归档至「🗂 资源台」资源台` | zy-curation |
| ② 新库（没有那枚实体） | `["💼 事业策展台→ws-biz-000", "🧪 另一个台→ws-b-1"]` | **💼 事业策展台** | `✓ 已归档至「💼 事业策展台」资源台` | ws-biz-000 |

四个坏点全在同一个弹窗里，且**根因是一条**：这个组件自己从**原始 `d.workspaces`** 数组搓了一份"可选台列表"
（`convWorkspaces = store.data!.workspaces.filter(w => !w.archived)`），于是：

1. 隐藏池那枚 R61 遗留实体被当普通台面印进下拉，用的还是退役实体名「资源台」（没走 R4-Dg 显示名单源）；
2. 它排在数组第一项 ⇒ **既是首个选项又是默认项**，标签却写着「存入策展台」；
3. **同一个动作在两种库形状下默认落点不同**（存量库落池 / 新库落策展台）——这正是 R4-Dk 那条 ①、R4-Dm 那条表二钉过的形状，是这一族的**第三个活口**；
4. 回执硬拼 ``「${ws.name}」资源台`` ⇒ 存量库实测连印成「已归档至「🗂 资源台」资源台」，一个字符串里撞出两个旧世界词。

同一形状还在别处：**批量移动**的「目标策展台」下拉（`useWorkspaceBatch.ts` 同样自己 filter 原始数组），
存量库里它的第一项也是「🗂 资源台」，而选中它 = 把卡移进池 + 顺手新建一枚 `workspaceId=zy-curation` 的「待分类」分类（`confirmBatchMove` 会为不存在的目标分类造一枚），
而 R179 起池卡只由标签组织——这不是"另一个名字问题"，是会往库里写脏结构的入口。

## 二、修了什么

`shared/utils/wsName.ts` 补上**列表构造的单源**（此前它只单源化了"单个 id→展示名"）：

```ts
export function selectableWsOptions(ws)   // 池显式排第一 + 未归档策展台，label 已含图标
export function boardWsOptions(ws)       // 只列策展台（显式排除池）
```

四个消费者接上，各自按语义选一个：

| 站点 | 用哪个 | 变化 |
|---|---|---|
| `content/overlay-impl.ts` 采集「存入位置」 | `selectableWsOptions` | 默认落点从"实体顺序巧合"变**显式归池**；选项文本不再在本文件抄一份判池算式 |
| `CuriosityPanel.vue` 归档弹窗 | `selectableWsOptions` | 默认 `CURATION_WS_ID`；标签「存入策展台」→**「存入位置」**；回执走 `wsNameById` ⇒ `✓ 已归档至「资源卡池」` |
| `useWorkspaceBatch.ts` 批量移动 | `boardWsOptions` | 池不再出现在"目标策展台"里（堵住造池分类那条）；模板走 `w.label` |
| `Workspace.vue` 移动弹窗模板 | 同上 | 不再现拼 `{{ w.icon }} {{ wsDisplayNameOf(w) }}` |

**为什么这不是我替你做的产品决定**：新资源卡的默认落点早已定——R2-⑧ 池控制行「新建」落池、
R4-Dk ⌘K 快路径转化显式归池、R4-Df3 AI 报告卡落点恒池、R4-Dm 采集面板默认选中显示为「资源卡池」的那一枚。
这次是把剩下两处"靠实体顺序"的写法并回同一条口径，不是新增口径。改后实测（同一探针重跑）：

```
① 存量库  台选项=["资源卡池→zy-curation","💼 事业策展台→ws-biz-000"] 默认=资源卡池 标签=["存入位置",…] 落点=zy-curation toast=✓ 已归档至「资源卡池」
② 新库    台选项=["资源卡池→zy-curation","💼 事业策展台→ws-biz-000","🧪 另一个台→ws-b-1"] 默认=资源卡池 落点=zy-curation toast=✓ 已归档至「资源卡池」
```

## 三、行为变化如实（不同意就说这几处）

- **新库里**好奇心归档 / 采集面板的默认落点由「第一枚策展台」变成「资源卡池」。存量库（含你的真实库）不变，只是名字不再印「资源台」。
- **批量移动的目标列表里从此没有池**。存量库以前能选到它（选中会造一枚池「待分类」），现在选不到；要把台内卡迁进池请走池管理面或标签，而不是这个弹窗。
- 归档弹窗的分类栏没动：选中池时仍列池名下现有分类（你的库实测 22 枚，且 260 张池卡**全部**带 categoryId——那是 R179 之前的存量形状，不是这轮造的）。

## 四、判据 +5 与随迁 4

新增（`97-r3-rounds.cjs` 的 R4-Ep 段）：① 列表构造只许一处（含三处消费者 + 三条"不许再自己 filter 原始数组"负锚，走 codeOnly）·
② 好奇心弹窗三处偏差一起修（默认显式归池 / 回执走单源 / 标签改口，旧拼法逐条不许回流）·
③ **"取第一枚实体"族的扫描形态换成宽形态登记表**：`[A-Za-z_]*[Ww]orkspaces[A-Za-z_]*(\.value)?\[\d\]` ——
R4-Dm 那张窄表用的字面正则 `/workspaces\[0\]/` 对 **`convWorkspaces.value[0]`** 天生失明（别名 + `.value` 都不匹配），
所以它立表之后同一族又漏出第三个活口；这是"判据形态必须和缺陷形态同构"那条账的第二次记账 ·
④ 批量移动排除池 + 模板走 label 单源 · ⑤ E2E-39 运行时覆盖锚点。

随迁 4 条（**都是既有判据拿本轮改掉的写法当证据**，按"实现上收到一处、判据跟着改且强度不降"处理）：

## 七、顺带量到的另一件事（不是本轮修的）

给 popup 做同族测量时发现：**`src/popup/index.html` 在产品里被三条命令当降级弹窗打开，但它从没进过构建**。
实测：`dist/src/popup/index.html` 仍是源码那份，`<script type="module" src="./main.ts">` 原样保留，dist 里没有 `main.ts` 也没有 popup 的 chunk，
`action` 只有 `default_title` 没有 `default_popup` ⇒ 用 `chrome.windows.create` 打开它时 **控制台报 `ERR_FILE_NOT_FOUND`、页面空白**（`/tmp/zy_ep_popup_probe.cjs` 实测 `#app` 内 0 个控件）。
触发路径：`quick-capture` / 快速采集任务 / 灵感采集三条命令在**内容脚本注不进去的页面**（`chrome://`、扩展页、Web Store）走降级分支
（`background/index.ts:208/223/236/320`）。所以用户在那类页面按快捷键，得到的是一个 460×640 的空窗口。
我没顺手修，因为两条修法都是产品取舍不是笔误：**A 把 popup 补成构建入口**（多个 html input，包体与 ZIP 预算已超 3,008B 要一起看）；
**B 撤掉降级弹窗**，那些页面直接提示"请在可注入的页面采集"。挂 **#117 待你拍板**，本轮只在表二里把 popup 那两处 `workspaces.value[0]` 登记成带理由的白名单（写明白它是待修的白屏死路，不许有人以为它是活的落点）。

## 八、边界如实

- ①/②/④ 那三处文案与列表是**同一个弹窗**里的，一起修才自洽；池名下 22 枚历史分类与 260 张带 categoryId 的池卡没动——清它们是迁移级动作，另说。
- `overlay-impl.ts` 里还有几处自己 filter 原始数组的写法（分类树、热力图台签、搜索台名），它们**不是**"给用户选台"的列表，本轮按语义没并进来；要并得先证明它们要的确实是同一份口径。
- 用户可见字符串里"资源台"仍有 ~13 处活在 AI 文案（`govern/select/batchG/scenarios/project` 的 hint/main/投料标签）、采集重复确认那句「已存在于资源台」、Airtable 字段说明「调度台/方向台/资源台/策展台名」。
  这条需要一个"用户可见字符串现扫 + 退役说明白名单"的登记表才守得住（本轮的宽形态表管的是列表构造，不是文案），已另立任务，不在这一轮顺手改——AI 提示词文案一动会牵一批以 hint 原文为证据的判据，值得单独一轮。
- popup 上下文仍没有 e2e/theme-audit 触点（#117 里连它自己都是白屏），本轮 E2E-39 覆盖的是 newtab 侧好奇心弹窗。
- 没动那枚 hub 实体的存废与改名（待拍板项）；也没动 `/workspace/zy-curation` 路由能否匹配（同前一轮边界）。
