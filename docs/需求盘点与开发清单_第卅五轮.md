### REQ-034 修复新建任务出现重复项 · 项目策展 & 二级树/成功指标

| 项 | 内容 |
|---|---|
| 类型 | Bug 修复（真 Bug，**根因已定位**） |
| 涉及文件 | `newtab/components/TaskAddDrawer.vue`（三处入口共享：CompassTree / ProjectCuration / ProjectDetailDrawer） |
| **根因** | TaskAddDrawer 输入框**双重 keydown 绑定**（:137-138）：`@keydown.enter.prevent="createTask"` + `@keydown.ctrl.enter.prevent="createTask"`。Vue 的 `@keydown.enter` 仅匹配 `e.key === 'Enter'`，**不校验 ctrlKey** → 用户按 Ctrl+Enter 时**两个 handler 同时触发 → `createTask()` 被执行两次** → `d.value.tasks.unshift(task)` 两次 → 界面渲染两条同内容任务（id 不同）。关联模式 :156 `linkTasks` 同源问题（影响小：taskIds 有去重保护，但也会重复遍历） |
| 佐证 | 第卅三轮 REQ-015 已定口径「Ctrl+Enter 保存」；第卅四轮 REQ-030 曾修 GlobalPopups 同款「裸 Enter + Ctrl+Enter 冲突」（批次1 遗留同类问题未收敛到 TaskAddDrawer） |
| 改动点 | ① 移除 `@keydown.enter` 裸绑定，统一 `@keydown.ctrl.enter.prevent`（+ 兼容 Cmd）；② `createTask`/`linkTasks` 加**防重复提交**（submitting 标志，进入即锁，emit('close') 后解锁）；③ 渲染侧防御：`tasksForMetric` 结果按 task.id 去重（双保险） |
| 验收对应 | 1. 单次创建仅 1 条 ✓（根治触发两次）；2. 刷新无脏数据 ✓（storage 只存 1 条） |

### REQ-037 快捷键：新增「打开全局设置」命令 · 浏览器快捷键页可配置入口

> 用户第 4 点（结合截图澄清后）：在 `chrome://extensions/shortcuts` 为知源工作台**新增一个「打开设置」命令项**，用户在那里给它分配一个键后，任意场景下（甚至扩展外）按该键即可一键跳到工作台的全局设置页面。

**① 现状澄清（截图佐证 2026-09-01）**

- 用户浏览器里**已经能看到 5 个知源工作台命令项**：激活该扩展程序（未设置）/ 好奇心采集（Alt+G）/ 打开知源工作台（Alt+E）/ 快速采集（Alt+Q）/ 打开全局搜索（Ctrl+O）。说明当前扩展实际加载版本已包含 manifest `commands` 注册。
- 用户当前诉求：在已有的「5 个命令」之上**新增第 6 个**——「打开全局设置」命令。

**② Chrome 限制验证（不超限）**

- **命令数无上限**，Chrome 限制仅 4 个 **suggested_key**（manifest 中预填的默认键）；截图里已有「激活该扩展程序（未设置）」= 第 5 个无 suggested_key 命令，证明「命令数 > 4 + suggested_key = 4」完全合法
- 我们新增 `open-settings` 不配 suggested_key → 用户在 `chrome://extensions/shortcuts` 看到「打开全局设置（未设置）」项，手动分配一个键 → 共 5 命令、4 suggested_key，未超限 ✓
- 描述文案（`description`）**必填**（非 action 类命令），否则 chrome://extensions/shortcuts 不显示该项

**③ 技术路径确认（基于现有架构）**

- 新标签页路由 `/settings` 已存在（`newtab/router.ts:44` + `App.vue:65` `route.path.startsWith('/settings')` + `GlobalPopups.vue:473` `router.push('/settings')`）
- background 已有 `zy-route` 消息通道（`App.vue:266` 接收 `router.push(msg.route)`），`open-dashboard` 命令用了「聚焦已开标签 + 发送 zy-route」模式（`background/index.ts:117-127`）—— 新命令直接复用
- 现有 options 页面（`src/options/index.html`）功能轻量，主要设置在 newtab `/settings` 路由下的 GlobalSettings.vue → 命令触发后**选项 B**：开/聚焦新标签页 + 路由到 `/settings`（无缝衔接工作台体验）

**④ 落地方案（REQ-037，纳入后范围）**

1. **manifest `commands` 新增 `open-settings`**
   ```ts
   'open-settings': {
     description: '打开全局设置'   // 不配 suggested_key，让用户自行分配
   }
   ```
2. **background onCommand 新增分支**：复用 `open-dashboard` 模式（`background/index.ts:117-127`）
   - 查 `chrome.tabs.query({url: base + '*'})` 找已开新标签页
   - 有则 `chrome.windows.update(focused)` + `chrome.tabs.sendMessage({type:'zy-route', route:'/settings'})`
   - 无则 `chrome.tabs.create({url: chrome.runtime.getURL('src/newtab/index.html#/settings')})`（hash 路由直接定位）
3. **可选增强（不阻断）**：GlobalSettings.vue 顶部新增「快捷键」折叠区，列出 5 命令 + 当前绑定（`chrome.commands.getAll()` 只读）+ 一行提示「如需修改请到 chrome://extensions/shortcuts」（互为入口引导）。该步为锦上添花，可放批次6 末尾或下轮。
4. **回归断言**：manifest 含 `'open-settings'` 键 + description 匹配「打开全局设置」+ background 含 `case 'open-settings':` + chrome.tabs.create URL 含 `#/settings`

**⑤ 边界外（本轮不做）**

- 修复 `search: Ctrl+K` 与 Chrome 地址栏保留键冲突的实际问题（用户已自行改键 = Ctrl+O，说明用户已规避；本轮不动）
- 页面内快捷键（B 层）自定义录制器（产品已能容忍默认键，本轮不做）
- 全局命令（`global: true`，浏览器外触发）—— 暂不需要
