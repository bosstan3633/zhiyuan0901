## 二、三个"顺手就错"的地方，以及它们怎么被钉住

1. **合并入口绕过红线**（R165-A 的旧账）。两枚并一枚之后，"新词闸装在哪个工厂"变成漂移点。`R147-4` 的判据从"按次数==2"升级为**按写库文件分段核**：`buildResourceEnrichJob` 段内必有 `badge: '新词'…` + `freshTagsOf(`，`buildTaskEnrichJob` 段内同样必有——计数相同但分布错了照样红。
2. **凭据记账从"次数"改"点名"**。`aiTouchedAt` 落戳点从 2 处变 6 处（select / resourceLinkTask / batchG / chain / taskEnrich / taskSupport）。`R165-A4` / `R152-4` 改为**按文件点名缺哪家**——并入口之后次数会漂，"谁没盖戳"不会。
3. **工厂清单不该手写**。`R157-3` 原来把 16 个工厂名写死在断言里，等于每轮加工厂就得记着改断言（漏改即绿）。改为**从 `src/shared/ai/*.ts` 现扫 `export function build*Job`**，注册表少一条即红并点名；反向也核：注册表声明的 `factory + factoryFile` 必须真在该文件里。

**活性验证（探针实测，两枚都有效）**：
- 探针 A：往 `ResourceEditForm` 正文塞回一份可编辑标题 → `R167-3` 与 `R165-A1` 当场变红，撤探针即绿。
- 探针 B：往 `ResourceDetailDrawer` 直引 `buildResourceEnrichJob` → `R167-2`（两宿主零 AI 接线）当场变红，撤即绿。
- ⚠ 本轮踩到探针自身的坑：第一版探针脚本用 `execFileSync`，回归非零退出时抛异常、**恢复语句没跑**，污染的文件被下一次探针当成"原始状态"读回。已手工清除污染行并全绿复核。⇒ 记进 06-2 通则：**探针必须用 `spawnSync`（非零退出不抛）+ 结束后立刻 grep 复核文件已还原**。

## 三b、性能 A/B（V3.5.0 基线 → V3.6.0 · Windows 本机 · 三批采集）

基线包由 `git worktree add ~/r167-base v3.5.0` + `node_modules` 目录 junction 现建，`--dist=` 零移动源码；两侧 `manifest.version` 由 perf 现场自证（3.5.0 / 3.6.0）。

**先说环境这件事，因为它决定了下面所有数字的可读法**：三批采集（① 无暖机 3 对、② 暖机后 3 对、③ 暖机后 4 对）**散布全部 >2 倍**（M1 散布 4.96×/4.38× → 2.81×/4.69× → 3.96×/5.28×），且慢样本在 A/B 两侧随机出现（第 3 批最慢的一次是 B 的 2467ms 与 A 的 3215ms）——本机当前有别的负载在抢 CPU，**不是包与包的差异**。按 06-2 通则「散布 >2 即作废」，中位数在本机今天**不可用作结论**，故：

- **改用「同批最小值」＝无噪声下界**做对照（三批互相印证），并如实声明"这是下界对照，不是统计结论"。
- **M14 结构量六次全同**，因此它是唯一可以按字面读的数字。

| 指标 | B = V3.5.0 最小值（三批） | A = V3.6.0 最小值（三批） | 读法 |
|---|---|---|---|
| M1 冷启动→首屏可交互 | 588.7 / 645.9 / **622.5** ms | 698.2 / 642.8 / **608.7** ms | 同档；方向在两批里相反 ⇒ 差异不显著 |
| M2a 切到资源台 | 115 / 87 / **103** ms | 116 / 85 / **92** ms | 同档（本次最新批 -10.7%，在噪声幅度内） |
| M14 首屏卡片数 / AI 徽标数 | 32 / 34（六次全同） | 32 / 34（六次全同） | **零变化** |
| M14 可见节点 / svg | **1643 / 37**（三次全同） | **1672 / 38**（三次全同） | ★ 唯一稳定的结构差：**+29 节点 / +1 svg** |
| M14 最差帧 | 17~241 ms | 19~280 ms | 噪声主导，不下结论 |

**+29 节点是什么**：`Workspace.vue` 的内联资源抽屉**常驻 DOM**（旧实现靠 `transform` 移出视口，不用 `v-if`），本轮给它加了抽屉头（kicker + 标题）与两格 AI 入口行 ⇒ 台面无交互时也多出 29 个节点。它不在计时里（M2a/M1 都没变慢），但它是**真实的结构成本**，且正落在"切台"路径上 ⇒ 已登记为 **V3.6.1 第一项候选**（内联抽屉 `v-if` 化 / 与 `Drawer.vue` 容器合并，见 §六）。

⇒ **结论：无劣化**（耗时类指标同档、结构类只有 +29 节点的常驻 DOM 已定量），但本机已不适合做 ms 级 A/B —— **V3.6.1 的性能盘建议换静置更久的时段或换机跑**，否则优化收益会被噪声吞掉。
