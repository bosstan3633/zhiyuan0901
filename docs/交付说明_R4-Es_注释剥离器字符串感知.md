# 交付说明 · R4-Es · 先修尺子：注释剥离器不再吃掉字符串里的代码（#119）

**日期**：2026-10-02 · 基线 V3.7.1（`8972be1` R4-Er）· **未升版**
**来源**：#119 —— R4-Er 给 perf.cjs 加两段块注释时，既有判据 R4-Pa 的 M5c/M5d 正锚**集体红**。
查下去不是那两条注释的问题，是**剥注释的工具不跳字符串**。

---

## 一、缺陷形状

`scripts/regression/helpers.cjs` 的 `codeOnly()` 原本是三条整段正则：

```js
text.replace(/\/\*[\s\S]*?\*\//g, '')      // 块注释整段删
    .replace(/<!--[\s\S]*?-->/g, '')        // HTML 注释整段删
    .split('\n').filter(l => !/^\s*(\/\/|\*)/.test(l))
```

第一条不认字符串：**只要源码里出现"斜杠紧跟星号"这两个字符，不管它在不在字符串里**，
就被当成块注释起点，一路吃到下一个"星斜杠"。于是这五类常见写法都会触发：
URL 通配 `'file:///*'`、`matches: ['http://*/*']`、`accept="image/*"`、glob `'src/**'`、
被嵌进模板串的 HTML/CSS 注释。

**实测吞掉了什么**（`codeOnly` 前后逐行对比）：

| 文件 | 被吞掉又找回来的真代码 |
|---|---|
| `src/manifest.ts` | **32 行** —— `host_permissions: ['<all_urls>', 'file:///*'],` 之后的 `chrome_url_overrides` / `options_page` / `background: {` / `action.default_title` 全部隐形（第 10 行那个 `file:///*` 起吃） |
| `src/newtab/components/GlobalPopups.vue` | `const tabs = await chrome.tabs.query({ url: ['http://*/*', 'https://*/*'] })` 整行 |
| `src/content/overlay-impl.ts` | 46 行（这里是反向：字符串里的 CSS 注释块旧口径**误删**、新口径按字符串保留） |
| `src/newtab/views/GlobalSettings.vue` | 2,748 字符差异（同上，主要来自字符串内的注释/样式串） |

**危害不对称**：正锚被吃掉会红（响亮，本轮就是被 R4-Pa 抓到的）；**负锚被吃掉是静默永久绿**——
"这文件里不许再出现 X" 的判据，如果 X 曾出现在被吞的那段里，它永远查不到。

**本次复核结论**：1,621 条既有断言在新口径下 **0 翻转**，且 39 处读 `manifest.ts` 的判据全部走 `read()` 原文，
所以**没有现存假绿被抓出来**——这颗雷上了膛但没响过。修它是因为下一条负判据就会踩。

## 二、修法（以及两次把我自己绊倒的地方）

`codeOnly` 改成**分派器**，内部两块：

1. `codeOnlyJs()`：字符状态机——单/双引号串、模板串（`${ }` 按代码递归、花括号深度配对）、
   正则字面量（只在运算符之后才认，避开 `a / b`）、块注释、行首 `//`/`*` 行注释、字符串外的 `<!-- -->`。
2. 分派规则：整份 SFC ⇒ `template/style 区走旧正则 + script 区走状态机`；
   整段以 `<` 开头的片段（判据常切的 `<template>…</template>`）⇒ 旧正则；其余（.ts / 脚本切片）⇒ 状态机。

两处反直觉，都是我自己先做错才发现的：

- **第一版让状态机直吃整份 `.vue`**：HTML 文本里的引号不是 JS 字符串定界符，一个带反引号的**行尾注释**
  就让机器误判"模板串还没结束"，后半份文件的 HTML 注释全不剥——实测 `Workspace.vue` 第 656 行注释里的
  `bookmarkInput` 因此露给 R4-Db 的负锚，判据**假红**。→ 加"整段标记退回旧口径"。
- **第二版顺手把行注释从"只看行首"扩到"字符串外一律算注释"**：一次翻红 **13 条**（既有判据的锚点里
  就有带尾注的代码行）。→ 退回行首限制，只保留"字符串外才生效"这一处口径变化。
  教训：**修尺子要一次只改一件事**，改完立刻全量跑；我那次同时改两处，红 13 条时根本分不清是哪一处造成的。

## 三、判据 +2 与活性变异

- **Es① 现场锚**：`codeOnly(manifest.ts)` 必须看得见 `host_permissions` 那行本身、`chrome_url_overrides`、
  `background: {`、`default_title:`，`codeOnly(GlobalPopups.vue)` 必须看得见那行 `tabs.query`——
  这条钉的是"以后谁也不许把字符串里的注释符当注释起点"。
- **Es② 分派锚**：对 `<template>` 切片与整份 SFC，模板注释必须剥干净（`parked 的 bookmarkInput` 不许出现），
  同时真代码 `const pyLayout = computed` 必须还在——双向钉，防止有人再把 HTML 当 JS 剥。

变异：**S1** 把"引号开启字符串"改成"引号当普通字符"（回到原洞）⇒ Es① 红**且 R4-Pa 一起红**（两条独立哨兵钉同一个洞）；
**S2** 去掉"整段标记退回旧口径"⇒ Es② 红**且既有 R169-17 一起红**（说明这条老判据本来就依赖该分派）；
**S3** 去掉 SFC 分区块 ⇒ Es① 红。三条各自 `filecmp` 逐字节还原 + 复跑回绿。

## 五、边界如实

- `stripComments()`（另一把行式剥离器，perf/theme-audit 类判据在用）**没动**：它按行过滤所以不会跨行吞代码，
  但会把块注释中间"不以 `*` 开头"的行留下——失准方向是"多看见"，不是"看不见"，风险低。要不要统一成同一把尺子，是下一件事。
- Vue 的 **template 区仍沿用旧正则**（那区里没有 JS 字符串语义可言）；若哪天模板里直接写 `'/*'` 这种串，
  旧问题会在那一小段重现——本轮的 Es② 只保证 script 区与 .ts/.js 的可见性。
- 新状态机对**极端畸形源码**（引号跨行的正则字符类里含反引号等）不保证完美；它有 Es①/Es② 两条行为哨兵，
  坏在响亮方向（会红），不会静默。
- #114 的内存账结论仍按 R4-Er 那份（本轮没有新的驻留数字）；#117 popup 白屏等拍板。
