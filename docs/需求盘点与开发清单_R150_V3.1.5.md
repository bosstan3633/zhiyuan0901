## 二、沉淀资产（下轮直接复用的规矩）

1. **"扫了多少"必须是界面里的一句话，不是日志。**语义检索最容易骗人的形态就是说"库里没有"，而实际只看了三成——所以 `投料 180/202 张` 与 `挑出 M 条` 同屏，兜底钮只在 `scanned < total` 时出现。
2. **新入口优先"吞掉"旧入口，而不是并排。**两枚 AI 钮并排 = 把"该按哪个"的判断成本推给用户；合并后旧通道整体删除（`rerankSearch`/`rerankSystem`/`rerankReady`/UI 字样），断言随之退场，不留死代码。
3. **要一致，就复用到"同一个函数"。**手势一致不是抄一遍 DOM：AI 行按 id 回查主列表的同一张 `allResults`、调同一个 `pickRow`、用同一句 title 字面量——断言用"这段文案在源码里出现 ≥2 次"反向钉住这条。
4. **渲染顺序 = 键盘顺序。**置顶组一旦渲染在主列表之上，就必须排在 `flatList` 之前；否则方向键选中的行与眼睛看到的行错位（这坑在旧「AI 理解」上已经存在，本轮一并修）。
5. **流式早停的中止器不能跨批复用。**一批的"JSON 一闭合就掐连接"会把共用的 `AbortController` 永久置为 aborted，下一批必然开局失败——多批场景一律"每批一把 + 外部取消靠广播"。
6. **computed 里的插值必须带 `.value`**，而且这种错**只有真跑一遍界面才看得见**（typecheck 不报，`[object Object]` 直接印在按钮上）。跑动态这类"文案 + 数字"的东西要进冒烟断言，不进代码审查直觉。
7. **测不到就等于没有：慢夹具是必需品。**mock 34ms 答完，"跑动态/取消/批进度"全都不可观测——沿用 R146 的「慢」关键词把网关拖慢，才拿到可断言的窗口；同时把断言写成"要么看得见进度、要么快到不需要"。
8. **入口 chunk 守卫要能自我解释**：把"AI 实现字面量"与"UI 文案 / CSS 类名 / 动态 import 解构名"分成两类各写各的口径，才不会让"全 0"这句话变成谁都能解释的模糊话。
