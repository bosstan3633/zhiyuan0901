| ③a | **严重 bug：A 卡上传 HTML 附件后所有卡都有该附件** | 根因：抽屉宿主用**单例 reactive** 复用（`editingResource`/`editing`），`Object.assign` 不清除「本次源对象没有的键」——上一张卡的 `assets` 残留给下一张卡，保存即写进 B 卡。修复：新增 `resetEditing()`（先删全部键再灌入），两处宿主四个入口全走；`emptyResource()` 补 `assets: []`。 |
| ③b | **PDF/HTML 双击后在浏览器中打开；HTML 交互失效修复** | 打开通道按**文件权限分流**：已开「允许访问文件网址」→ 落盘后 `file://` 本浏览器打开（原通道）；**未开**（原实现静默失败降级 blob → 内联脚本被 MV3 CSP 拦，即用户所见"交互无响应"）→ `chrome.downloads.open(下载 id)` 用系统默认程序打开**刚下载的副本**（HTML→浏览器 / PDF→阅读器，交互完整）。附件行新增 `@dblclick`（AssetManager 行 + AssetBadge 浮层行）+ 400ms 去抖（双击不再触发两次下载/两个标签页）。 |
| ④ | **AI 补全标签优先从标签管理里选，确无合适才新建** | 三层落地：**投料**——词表改喂「父/子」路径（原只给裸名，模型看不到层级）；**指令**——批量补全与全方位优化提示词补「优先复用给定标签词表（含父/子路径），确无近义才可新增」；**归一**——新增 `canonicalTagOf/canonicalTagsOf`（全名/叶子名/路径三口径回查，与标签体检 findTagIn 同源），单卡补全 / 批量补全 / 全方位优化三处 parse + 两处 apply 全链归一——模型写裸子名会被升级成体系里的「父/子」路径落库；确无匹配才保留为新词（仍单独成行、默认不勾，由人拍板）。 |

## 三、说明（3 条）

1. **注册表数量锚变更**：AI 入口 22→21 条、工厂 17→16 条（`buildRecommendJob` 退役）；「推荐挂载」能力随挂载关系一并退场，不做保留——无 `mountedResourceIds` 该任务书无落点。
2. **存量数据清理是幂等的**：启动期只删任务上的 `mountedResourceIds` 键，不改其它字段；旧备份/导入包再进来也会在下次启动被清。
3. **串卡 bug 的存量影响**：修复只保证"以后不再串"；若此前已有卡片被写进他人附件，请到该卡详情手动移除（附件本体若仍被源卡引用会保留，删除是安全的）。
