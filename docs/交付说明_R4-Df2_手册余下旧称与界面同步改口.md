## 三、★手册改对了，界面还在打对台（而且我自己第一次没抓全）

改完手册回头核界面，设置页有**五处**用户可见文案仍在指名已退役的台面与不存在的命令：

1. 快捷键页头「系统级快捷键（含方向台/**资源台**/完整方向树/任务调度）」——那两条命令早已下架，
   界面还在教用户去 `chrome://extensions/shortcuts` 分配它们；
2. 快捷键卡片副标「由 Chrome 统一管理 · **方向台/资源台**/完整方向树无默认键，需手动分配」——同一个错误的第二处，
   而且它就紧贴在第 1 处下面两行；
3. Airtable 同步范围「**资源台**资源卡」；
4. 应用内速查表「**资源台**：双击卡片打开链接」；
5. 应用内速查表「资源卡批量管理 → **资源台**工具条「☑ 批量管理」」——池面板控制行那枚钮现在就叫「批量」。

★第 2 处是我自己漏的，漏法值得记一条纪律：我先写的判据是**把我改过的四条旧说法逐条列进负判据**——
它核的是"我做了哪些编辑"，不是"界面还剩下什么错"，所以它全绿的同时，
第 1 处下面两行就挂着同族、同一种骗人的句子。这种判据只会让人把"改完"误当成"改对"。

处置不是再补一条枚举，而是把判据换成**从真源现算**：

- 「N 条无默认键命令」里的 **N 由 `manifest.ts` 数出来**（新增共用 `noKeyCmds()`，与 D-f1 那条手册↔manifest 判据同源），
  中文数字由 `CN_NUM` 映射；将来加/删一条命令，界面与手册这两句都得跟着改口，否则红。
  ★原本判据体里写死的 `noKey.length === 6` 与手抄的六条命令名单一并收进这个函数（语义未变，去重）。
- 加一条**语境判据**：设置页（`codeOnly`）里每一枚「资源台」字样，前后 14 字内必须出现"退役/已删/旧世界"，
  否则即为"把退役物当现役功能指给用户"——这条不依赖我事先想到有哪几处，是它能自己抓住我漏的那一处。
- 第 2 处改成不列条数、不点命令名的说法：下表就是 Chrome 里的全部命令，显示「未设置」的即无默认键。

**活性已证**（改坏必须能红，否则上面两条仍是空转）：三处变异各自命中对应判据——
M1 界面退回「方向台/资源台/完整方向树无默认键」→ 判据一红；
M2 界面「六条」改「七条」→ 判据一红（证明 N 真的在跟 manifest 比）；
M3 手册「入口只有一个」改回「入口有三处」→ 判据二红。三次变异后文件均原样还原。

  纯叙述性的号没动——**全部删干净需要逐条判断哪些句子离了号就站不住**，那是独立一轮的活。
