## 二、整体梳理这一刀：难点不在提示词，在四个藏着的坑

需求原文是「采纳后标签数**完全**变更为方案描述的状态，并同步更新卡片标签」。要真做到"完全"，得先挖掉四条既有链路：

1. **合并策略会盖掉你的删除**。`repository` 的标签树合并是"按 id 取并集"——旧节点哪怕被你换掉，下一次写入还会被并回来。加 **`AppData.tagTreeRevision` 版本戳**：换树 +1、还原也 +1，合并按版本高者胜（`mergeTagTree`）。多开一个窗口也不会把旧标签复活。
2. **阶段③靠内存态读定义**。原来 `lastTagTreeBlueprint` 是模块变量，刷新即丢，归架时读不到"这个标签收什么卡"。**`TagNode.definition` 落库**，阶段③直接读盘上的树，内存态整个删掉。
3. **快照不含描述**。「③ 归架」会填卡上空描述，而还原只回滚了标签——还原后描述留着 AI 写的，等于回滚不干净。快照现在带 `tags + description`，实测还原回执「树 + 8 张卡的标签与描述全部回滚」。
4. **投料越界**。旧口径读链接正文（`fetchLinkText` 抽样）——与你要的"完全依据卡片现有字段"正相反，且是这一刀里唯一会外发网页内容的一段。**正文段整体撤掉**，投料换成三类卡台账（`[res]/[task]/[curio]` 各一行、只用卡面字段），冒烟直接把出网的 prompt 截下来断言「没有正文节选段」。

`若卡片不足 6 张` 的门槛口径也随任务改了：从"资源卡 6 张"变成**三类合计 6 张**（toast 与 tooltip 同步改口，不再说"资源卡还太少"）。

**实测留证**（200 卡规模外的 8 卡种子）：subject 明写 `🏷 全量盘点 8 张卡（资源 6 · 任务 1 · 好奇 1）`；`旧标B → 学习方法/时间管理` 本地数出 **3 张**（两张资源 + 一张任务）；采纳后 `tagTreeRevision=1`、`悬空旧标` 从卡上消失、根标签角标显示 7 卡（含子树）；还原后 `rev=2` 且旧标签回来。

## 三、入口补齐这一刀：真正贵的是那 1500 行硬闸

需求 4 = 三类卡 × {卡片 / 列表 / 看板 / 详情}。缺口实测如下（**注意：R147-5 那条断言当时写了"看板已覆盖"，实际按字面数了行数没核视图**）：

| 卡种 | 补前 | 补后 |
|---|---|---|
| 资源卡 | 只有卡片视图 hover 有 ✦；列表/看板/行内详情抽屉**四处全缺** | 三视图动作条各一枚 + 详情抽屉页脚「✦ AI 优化」（同一组件，零新 DOM） |
| 任务卡 | 卡片/列表 6 处在位；**看板 6 处缺** | 看板每卡底部 ✦ 菜单，共用同一个 `TaskAiMenu` |
| 好奇卡 | 只有页头批量「转化研判」 | 卡片 hover / 列表行 / 看板卡 / 详情抽屉页脚四处**单卡研判** |

三条实现纪律：

- **`Workspace.vue` 压在 1500 行硬闸上（1499 行 = 闸值），加三行就破**。没有拆组件（拆出去要把 10 个动作回调改成 emits + 把 hover 显现的 CSS 复制一份，纯为凑行数的风险动作），改用本文件既有先例：把 5 个单行 import 并成一行（同一文件第 14 行一直是这么写的）。**净 +3 −4，行数一字未涨**。
- **一钮两形，不是两个钮**：`CardAiEntry` 加 `label` prop——不带 label 时是动作条里的 `.rc-action`，带 label 时按页脚钮 `.dr-footer-btn` 渲染。样式全在 `workspace.css`（非 scoped），所以 fragment 根的子组件照样吃宿主样式，实测三视图那枚分别是 24px / 22px / 页脚钮自然高。
- **单卡研判不新开场景**：好奇卡走的是**同一条 `buildCurioTriageJob`**，只是把「3 条才够比较」的门槛变成 `single ? 1 : 3`。**jobKey 必须带卡 id**（`triage:<cardId>`），否则换一张卡点研判会 attach 到上一张的结果——冒烟 B2-9 专门量了这条：点乙之后请求数 1→2，标题从「单条研判「B2 好奇甲…」」变成乙，且已搁置/已转任务的好奇直接拒跑并说清为什么。

## 六、M3c：这一轮**给出结论**了（并推翻我自己上一轮的猜测）

R148~R150 三轮都记着「窗口三 6~9s 长任务，改前改后一模一样，未归因」，R150 我猜是"环境噪声"。**这个猜测被本轮实测否掉**：

- 新加 `--idle-control` 静置对照：**同样的库、同样的页面，零交互等 20 秒 → 长任务 0 条**。所以它不是环境自己周期性抖动。
- 新加窗口三单独一段 CDP CPU 采样（`--profile` 现在也覆盖窗口三）：21.6s 采样里 **(idle) 13.4s + (program) 7.5s + GC 0.2s**，落到我们能读懂的函数上**不足 0.4s**，Top 也只有 `insertBefore` / `remove` 与 Vue chunk 内部函数。

结论：M3c 是**交互之后发生在 Blink 侧（样式/布局/绘制/存储 IPC 这一层）的非 JS 主线程时间**，不是知源的 JS 算得慢；但它由交互触发，所以**不能当噪声丢掉**。JS 采样器到此已经问不出更多——**R152 的下一刀换成 trace 分类采样（layout/paint 类目）**，把「1.2s 一次」这笔账落到具体是重排还是绘制。工具留在 `perf.cjs` 里（断言 R151-8 钉住，防下一轮又现推）。
