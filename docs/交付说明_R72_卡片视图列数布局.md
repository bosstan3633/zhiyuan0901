# 交付说明 · R72（V2.41.0）卡片视图列数布局

**发版日期**：2026-09-11 ｜ **版本**：V2.41.0 ｜ **基线**：V2.40.0（R71 → 本轮待 commit）

> 本轮为**布局自由度版**：只做一件事——把「一行放几张卡」从写死在样式表里的常量，交回用户手上。**零数据模型破坏性改动、零存储格式改动、零交互习惯改动**（各模块默认列数 = 改造前等效列数，升级后视觉零变化）。

## 一、为什么这一轮是「列数」

卡片视图是四个台面共用的主要阅读形态，但**网格列数此前是写死的**，而且各模块各写各的：

| 模块 | 改造前 | 问题 |
|---|---|---|
| 好奇心培育 `CuriosityPanel.vue` `.cz-grid` | `repeat(4, 1fr)` | 固定 4 列，窄窗口把卡片压扁 |
| 任务调度 `TaskManagerPanel.vue` `.tm-grid-inner` | `auto-fill minmax(240px, 1fr)` | 宽屏铺到 6 列、窄屏掉到 3 列，用户无法干预 |
| 资源台 `CurationCenter.vue` `.cur-grid` | `auto-fill minmax(240px, 1fr)` | 同上 |
| 资源台 / 策展台 `Workspace.vue` `.card-grid` | `auto-fill minmax(var(--card-min-w), 1fr)` | 同上 |

用户的真实诉求是「这一屏我想一次看多少张」——它随屏幕宽度、数据密度、当下任务（浏览 vs 精读）而变，是个**偏好**，不该由样式表替他决定。

### 2.3 接入层（G3 / G4）

四处宿主，覆盖需求点名的三个模块（资源台因 `R16` 尚未收敛，暂时有两个入口）：

| 宿主 | 偏好键 | 网格容器 | 选择器位置 |
|---|---|---|---|
| 好奇心培育 `CuriosityPanel.vue` | `curio` | `.cz-grid` | `.cz-views` 首项（右端工具组） |

选择器一律 `v-if="viewMode==='card'"`——只在卡片视图出现，列表 / 看板 / 金字塔视图不占位。

### 2.4 网格公式（G5）——「卡片大小自适应」的落点

四套网格模板统一改为：

```css
grid-template-columns: repeat(auto-fill,
  minmax(max(<最小卡宽>, calc((100% - (N - 1) * <卡间距>) / N)), 1fr));
```

语义 = **首选 N 列；容器放不下 N 列时自动降列**，卡片始终保持最小可用宽度。

| 模块 | 最小卡宽 | 卡间距 | 默认 N |
|---|---|---|---|
| 好奇心培育 | 200px | 12px | 4 |
| 任务调度 | 240px | 12px | 5 |
| 资源台（旧入口） | 240px | 10px | 5 |
| 资源台 / 策展台 | `var(--card-min-w)`（舒适 260 / 紧凑 220） | `var(--card-gap)`（14 / 10） | 5 |

`--grid-cols` 由宿主以行内自定义属性下发（`.cz-grid` / `.tm-grid` / `.page` / `.ws-page`），CSS 侧只读变量——**列数不进样式表，也不散落在模板里**。

### 2.5 与既有密度档位的关系

`density`（舒适 / 紧凑）调的是**最小卡宽**，`cardCols` 调的是**目标列数**，两者正交、可叠加：紧凑密度 + 4 列 = 更小更密的卡。
