## 二、N3 周报按钮点击无反应 —— P0 BUG

### 2.1 根因（确凿，证据链完整）

`CompassHome.vue:896` 在模板中使用了 `<WeeklyReportOverlay>`，但同文件 `<script setup>` 的 import 区（`:8-25`）**从未 import 该组件**。项目既无全局组件注册（`main.ts:42-46` 仅 `createApp` + `use(Pinia)` + `use(router)`，无 `app.component`），也无自动导入插件（`package.json:18-29` 无 `unplugin-vue-components`）。

→ Vue 把该标签当作**未解析组件**，渲染为空注释节点。点击按钮只把 `wrOpen` 置 `true`，页面上没有任何东西被渲染，表现为"完全没反应"。

**反向佐证**：dist 产物全目录搜 `wr-overlay`（该组件根 class）**零命中** → 组件从未进入打包图。`git log -S "import WeeklyReportOverlay"` 空输出 → 历史上从未存在过这条 import。

**为什么门禁没拦住**：`regression.cjs:3056`（R111-4）只断言 `h.includes('<WeeklyReportOverlay :open="wrOpen"')` —— 只查模板字符串存在，不查 import。

### 2.2 修复

| 项 | 位置 | 动作 |
|---|---|---|
| T3.1 | `CompassHome.vue:24` 附近 | 补 `import WeeklyReportOverlay from '../components/WeeklyReportOverlay.vue'` |
| T3.2 | `regression.cjs:3056` | R111-4 断言加固：增加"组件名已被 import 语句引用"检查 |
| T3.3 | `e2e.cjs` | 补一条 E2E：点周报 → 断言 `.wr-overlay` 可见（防回归到"孤儿组件"） |

> 其余链路（`wrOpen` 定义 `:679`、`onWrDrill` `:680-690`、子组件 `v-if="open"` + `Teleport to="body"`、emits 名）**均已就绪，无需改动**。

### 2.3 验收

- 点调度台「📊 周报」→ 全屏周报浮层打开，四段式内容正常渲染，下钻可点

## 六、N5 金字塔全屏下交互缺失

### 6.1 现状（架构性根因）

全屏不是 Class 切换、不是路由，而是**元素级原生全屏**：

- 全屏宿主 `pyWrapRef` = `.pyramid`（`Workspace.vue:477`），进入逻辑 `:2487-2531`（`:2495-2501` 调 `el.requestFullscreen()`）
- 路线 B 降级：`pyFsFallback`（`:2491/2504-2506`）→ `.pyramid.py-fs-fallback`（`:3343`，`position:fixed; inset:0; z-index:240`）

**关键事实：没有任何 `v-if` 把工具栏/侧栏藏起来**。消失是浏览器语义造成的 —— 原生全屏只绘制全屏元素子树，而下列浮层**全部在 `.pyramid` 之外**：

| 浮层 | 位置 | z-index |
|---|---|---|
| 详情抽屉 `.drawer` / `.overlay` | `:556-557` | 201 / 200（`:3244-3246`） |
| 关联资源卡弹窗 `.modal-overlay` | `:690-716` | 300（`:3264`） |
| 镜像分类弹窗 | `:833` | 300 |
| 节点菜单 `.node-menu`（Teleport→body） | `:819-830` | 691（`:3404`） |
| 卡片右键菜单 / 批量栏 | `:813` / `:545-552` | — / 150 |

→ **真全屏**：以上全部消失。**降级模式**：抽屉（200/201）被 z 240 盖住，弹窗（300）与节点菜单（691）能浮出 —— 层级倒挂，行为不一致。

用户要的两件事正好都命中抽屉：`➕ 新建卡片`（`:531` → `addResourceToCategory` → `.drawer`）与卡片详情（`:523` → `onCardClick` → `.drawer`）。节点底栏 `.py-node-foot`（`:528-532`）**本身在全屏内可见**，消失的是它点开后弹出的抽屉。

### 6.2 方案（待拍板）

| 方案 | 做法 | 代价 / 风险 |
|---|---|---|
| **A（推荐）** | **弃用原生全屏，统一走 CSS 覆盖层**：`.pyramid` 常态 `position:fixed; inset:0`，z-index 定在浮层之下（如 100），抽屉/弹窗 z 保持 200+ 自然盖在上面；自实现 Esc 退出、`F` 键切换 | 不是浏览器级全屏（不隐藏浏览器 UI）。**但全部交互零改动保留**，实现量最小、回归风险最低 |
| B | 保留原生全屏，给 `.pyramid` 内加浮层宿主节点，抽屉/弹窗/菜单的 Teleport 目标动态切到该节点 | 保留真全屏；但需逐个改造 5 处浮层挂载点，`node-menu` 已 Teleport 到 body 要再套一层，回归风险高 |
| C | 混合：原生全屏 + 全屏内专用内嵌面板替代全局抽屉 | 改动最大，两套 UI 需同步维护 |

> 用户原话含"如果技术上可行的话" → 建议采纳 **A**：以"视觉全屏 + 交互完整"换掉"必须原生全屏"。

| 项 | 动作 |
|---|---|
| T5.1 | 按所拍板方案重构 `enterPyFullscreen/exitPyFullscreen`（`:2492-2513`）+ CSS（`:3338-3343`） |
| T5.2 | 理顺层级：覆盖层 < 抽屉 < 弹窗 < 节点菜单，消除倒挂 |

**Q2 · 三类卡呈现方式**：(a) 顶部实体切换（资源卡 / 任务卡 / 好奇心卡 / 全部）+ 下方沿用原型三态结构；(b) 同屏三栏分区并列；(c) 单一列表 + 类型标签。
> 推荐 **(a)**：最贴近原型视觉语言，且单屏信息不过载。

**Q3 ·「记录」的定义**：(a) **生命周期变更流水**（何时从活跃→冷却（自动）/ →归档（手动），需新增存储，可复用 `zy_event_log` 或新增 `lifecycleLog`）；(b) **当前状态卡片明细列表**（即现有 `lc-list`，行内已有「归档 / 忽略 30d / 重新激活」）。
> 用户原话"记录可操作转化卡片状态"完全对应 (b) 的行内操作。推荐 **(b) 为主**，并把"下钻"明确为"点数字 → 过滤该状态明细"；(a) 若要做则单列一项。

**Q4 · 三类卡的活跃口径是否统一**：任务卡 `status==='doing'` 恒活跃（`lifecycle.ts:53` 已有特判）；资源卡 / 好奇心卡无 `status`。
> 建议按现状保留（任务进行中即活跃）。

### 7.4 已发现的口径隐患（需一并处置）

`snoozeCard`（`lifecycle.ts:63-66`）为"忽略 30d"会**覆盖 `lastCalledAt` / `updatedAt`**。而资源卡的 `lastCalledAt` 同时是"最近打开时间"，被热度排序与 `MetricDrillDrawer.vue:54-56` 的 WRR 口径直接消费 → **"忽略"会污染资源热度/复用统计**。
> 生命周期升为全局视图后该耦合会放大。建议增设备注位或改 `updatedAt` 单字段，避免双口径互污。
