# 交付说明 · W7 / V3.8.7 —— 调度台视觉焦点契约

> **日期**：2026-10-12
> **一句话**：**给调度台一个视觉主角。** 今日三件事升为全页唯一 22px display 级主体并配重框；三张卡与年度热力图标题降级让位；年度热力图默认收成「近 26 周」概览条。
> **性质**：视觉层级调整（CSS 为主）+ 一处呈现折叠（热力图默认态）。**数据模型、存储、卡模型、AI 边界一律未动。**

## 一、这轮从哪来：一次产品侧的读码诊断

用户问「每个页面的重点和视觉焦点应该是什么，现状是否满足」。读码（不是读文档）得到两个硬事实：

1. **`--fs-display`（22px，令牌注释自述「首屏大数 / 品牌位」）在四个主工作面 0 次使用**。全站仅 4 处，全在工具页与图标位：`ManualPage.mn-sec-title` / `RecycleBin.rb-title` / `ConfirmDialog.cdf-icon` / `GlobalSettings.gs-io-icon`。
2. **调度台的两个主角视觉等权**。`W5（V3.8.5）「三标题统一 17px」`把 `.card.focus`（今日三件事）、`.decks-title`（三张卡）、`.dz-t`（年度热力图）做成同一字号 + 同一框体（`--shadow-sm` + `--radius` + border）。

结论：调度台**结构清楚但没有焦点**，「今天」这个语义只靠文案承载，没有视觉重量。产物是一份对照原型（`评审交接包/原型_调度台视觉焦点调整_审核稿.html`，色值全部取自 `tokens.css` 实测），用户审核通过并拍板 A 案。

用户要求「整体主题缩减为 linear、raycast、apple，外加 Notion 风格的纸墨白」。**回仓核实：现状已经满足，故本项零改动**，只在交付说明里备案：

| 主题 | 状态 | 关键值 |
|---|---|---|
| `linear` | 已存在（暗 · 薰衣草紫） | bg `#0D0E11` / accent `#5E6AD2` |
| `raycast` | 已存在（暗 · 冷蓝） | bg `#08080A` / accent `#1E6FD9` |
| `apple` | 已存在（亮 · 冷紫） | bg `#F5F5F7` / accent `#5E5CE6` |

`shared/utils/theme.ts` 的 `THEME_IDS` 就是这五个（含 `auto` 跟随系统，解析为 linear/apple）。notion 的暖墨体系（暖白底 + 深墨字 + `--shadow-sm` 用暖黑低 alpha 而非灰）**已是标准纸墨白**，不需要新增或改造。

> ★**为什么敢这么判**：不凭印象。`tokens.css` 143~420 行四个主题块逐个读过，色值与阴影全部对得上。若用户本意是「砍掉别的、只留这四个」，现状即目标；**若本意是想要一个与 notion 不同的新纸墨主题，需要用户再明确一次**。

### 热力图压缩的边界（重要）

折叠的是**呈现**，不是数据。以下全部原样保留在展开态，一件不少：

- 全年 366 格网格 + 月首偏移 + 悬停放大
- 切年（上一年/下一年）、年份显示
- 导出三件套（PNG / 自包含 HTML）
- 六档语义图例 + 年活跃日均 / P90 说明
- 点格子开日详情（今日战报）—— **概览条上点某一周也会展开并选中该周最活跃的那天**

概览条本身：26 根竖条，**条高编码周强度**（6~26px），色阶仍走 `--heat-0..5` 令牌 ⇒ 六主题自动适配。旁附两枚数字：近 26 周活跃天数、今日操作数。

> ★**口径纪律**：今日操作数走 `dailyStats.ts` 的 **`actsOf(r)` 单一真源**。第一版我写成 `r.n` 被 `vue-tsc`当场抓住（`DayRec` 无 `n` 字段）——不自造字段是这个项目的既有纪律，实跑比人记可靠。

### ⚠ 真机截图当场抓到的一处施工缺陷（已修，记在此处不藏）

用户真机截图反馈「不是说收成概览条的吗」。核实过程：
1. 先确认**不是构建没生效**——量了截图像素：「今日三件事」文字高 38px、「年度热力图」26px，折算回 1.881 倍缩放分别约 **22px / 15px**，正是 V3.8.7 的新值（旧构建两者应同为 17px）。**结论：跑的就是新构建。**
2. 截图里出现的是全年网格 + 摘要卡 + 导出/切年——这些全在 `v-else` 分支 ⇒ 运行态 `expanded === true`，即**当时处于「看全年 ›」展开态**（概览条是默认态，代码 `expanded = ref(false)` 无误）。
3. 顺着这条线查出一个**真缺陷**：V3.8.7 首版**只给了「看全年 ›」，没有给回来的路**——`grep 'expanded = false'` 零命中，折叠是**单向门**。展开后既与旧版长得一模一样，又回不去，用户自然认为「没改成」。

**修法**：展开态头部加「收起」按钮（`@click="expanded = false"`），并在 W7-3 补钉**双向**——同时锚 `@click="expanded = true"` 与 `@click="expanded = false"` 两个完整绑定串（不锚 `expanded` 这个词，否则「声明了变量但没接按钮」也会绿）。

> ★**这条是本轮最值钱的一条**：它不是门禁能发现的——回归、typecheck、build、变异自证全绿，**因为它是一个"少做了"而不是"做错了"的缺陷**。只有真机点一下才会暴露。**已把它列为交付说明 §七真机复核清单的第一项，教训是：单向开关类交互，判据只能钉"双向都在"，不能靠人工记忆。**

## 六、边界与如实（未复跑 / 未验证的都在这里）

1. **★视觉未亲验**：本轮改了 4 处字号 + 2 处阴影 + 1 处框体尺寸 + 一处折叠态，**但本机无 Chromium，`theme-audit` / 像素 A/B / E2E 一条都没跑**。字号提升是否在真实四主题下挤压（尤其三件事格在窄栏、`tc-title` 14→17px 后长任务名换行）与概览条 26 根的实际观感，**需在有 Chromium 的机器上跑视觉走查看**。不假装已验。
2. **热力图首屏默认态变了**：老用户升版后首屏不再直接看到全年网格，需点一次「看全年 ›」。这是**用户可感知的行为变化**，已写进 changelog 与根 README。
3. **概览条的周强度取「该周最高 lv」**：不是该周均值。理由是条高要能反映「这周有没有动过」；代价是一周内只有一天活跃时也会显示为较高强度。这是**取舍**，若要改成均值需重跑视觉。
4. **概览条不随年份切变**：它取「最近 26 周」，与 `year` prop 无关 ⇒ 在展开态切到上一年再折叠，条仍显示最近 26 周。**已知不一致**，未修（修它要引入年锚点，属新增逻辑）。
5. **W7-2 的豁免是判断**：工具页标题允许 display、图标位不计，是我的产品判断，写在判据注释里可被你推翻。
6. **未 push、未推标签**：远端是共享状态，按约定需单独授权。
7. **`docs/` 仍是只读归档**，本轮只**追加**了这份交付说明，未回改任何旧文档。
