# 交付说明 · R4-Db —— 书签导入单路线合一（未升版）

轮次 D 第二刀。计划里这一条原本写作「书签导入单路线」，开工前先把现场拉出来，结果**前提就不对**：
全站根本没有 `chrome.bookmarks` 那条路（manifest 都没申请 `bookmarks` 权限），两条"书签导入"都是
**读浏览器导出的 Netscape 书签 HTML 文件**。所以这一刀不是"改走 API"，是**把两份重复实现合成一份**。

## 一、做了什么

| 文件 | 行数 | 变化 |
| --- | --- | --- |
| `composables/useBookmarkImport.ts` | **+128（新）** | 书签导入的唯一实现 |
| `composables/useWorkspaceImport.ts` | 289 → 176 | 书签整段搬出，只剩「策展台数据包 JSON」+「本地文件」两条 |
| `views/GlobalSettings.vue` | 3206 → 3145 | 删自带的那份解析器与导入器，改消费唯一实现 |
| `views/Workspace.vue` | 1406 → 1379 | 删 parked input + 文件夹勾选弹窗 + 解构绑定 |
| `views/workspace.css` | 653 → 636 | 删 `.bk-*` 一族（**原先是逐字重复的两份**） |

- **死的那一份**：`useWorkspaceImport` 里的「文件夹勾选弹窗 → 按前 2 级在隐藏池 `CURATION_WS_ID` 下建分类」。
  它自 V3.7.0 起就是**够不着的代码**——宿主 `Workspace.vue` 那枚 `bookmarkInput` 全站零 `.click()`。
  更糟的是它写的形状模型里不许存在：`models` 明令「池卡 `categoryId` 恒空、hub 分类实体已由迁移器移除」，
  而清理器 `poolMigration` 被 `d.catsMigratedAt` 幂等戳挡住不会重跑 ⇒ **谁哪天真触发一次，就留下金字塔仍在枚举的永久残留**。
- **活的那一份升为唯一口径**：目标台下拉（`__new__` = 新建「🔖 书签导入 <今天>」）+ 台内单「待分类」+ 文件夹全路径转标签，**不建分类树**（设置页文案早就是这么写的，R169-17 逐字钉着）。

## 二、★合一不是"留下活的那份"就完事

死的虽然是死链，身上却带着活的没有的三处硬化——**活的才是带 BUG 的那一份**：

| 硬化 | 来源 | 合一前活的那份 |
| --- | --- | --- |
| `safeDecodeText` 解码文件夹名与书签标题 | R29-6 | **漏了** ⇒ percent-encoding 名以乱码落库 |
| 复用「待分类」时查 `!c.deletedAt` | R129-B11 当年就修过 | **至今没修** ⇒ 同名分类在回收站时，导入的卡既不显示也不可恢复 |
| 根文件夹名按 `BK_ROOT_NAMES` 八枚排净 | R30-4/5 | **只排 `'书签栏'` 一枚** ⇒ `'收藏栏'` / `'Bookmarks Toolbar'` / `'移动书签'` 当成标签贴到每张卡上 |

三处全部搬进唯一实现，并由新断言 `R4-Db ★合一不是"留下活的那份"就完事` 逐条点名。
顺带清掉两处旧痕：`makeHubResource`（`hub` 是已废弃旧称，又硬编码池 id）随死链删除，书签卡构造式改名
`makeBookmarkCard`；`useWorkspaceImport` 里 `CURATION_WS_ID` 成了**未使用 import**，被新写的"绝不写隐藏池"
判据当场抓出来。

## 三、断言：10 条重指 + 3 条新增（1551 → 1554）

- **能力按设计退役**（不是搬家）：`R30-4`「前 2 级建分类」判据转三条腿——两份实现剥注释后建树符号零命中 /
  存活口径点名（层级只进标签 + 单「待分类」）/ 设置页文案照旧写明"建树导入已随资源台退役"，两处不许互相打架。
- **持有者改点名**：`R65-4` 与 `R100-1` 原要求 `Workspace.vue` 必须持有 `handleBookmarkImport`（即**要求死代码留在原地**），
  现改为 `useBookmarkImport` 持有，并把"宿主不得自带解析器"的负判据从 Workspace **扩到 GlobalSettings**——
  它原先真的有一份副本，这正是本轮要合的东西。
- `R29-6` / `R30-5` / `R73-6` / `R129-11` / `R138-5` / `R154-9` 锚点跟着实现搬到新落点，口径一字未松。
- `R168-2`「台面零常驻浮层」弹窗数 **7 → 6**：减的那一副是书签文件夹勾选弹窗，随死链一起删；
  `openConds` 少一项、计数判据同步下调，并加一条负判据不许那副弹窗回流。**这条是本轮最容易漏的**——
  它守的东西一个用户都看不见，删任何一副弹窗都会撞它。
- ★**自己写的判据也被注释自匹配咬了一次**：新加的「绝不写隐藏池」用裸 `read()`，而唯一实现的头注释
  为了讲清退役缘由点了 `CURATION_WS_ID` 的字面量 ⇒ 判据恒假。改走 `codeOnly()`。这是该纪律在本仓库**第四次**咬人，
  第一次咬的是我自己刚写下的判据。

## 四、E2E：书签链路第一次有行为覆盖（31 → 32）

这条链路此前**只有源码文本断言**在管，零运行时覆盖——删一整条死链却没有活性凭据，"合一"就可能只是"删坏了"。
新增 `E2E-32`：真喂一份 Netscape 书签 HTML 进那枚 input，核 ① 落库张数==解析张数 ② 层级进标签且根栏名被排除
③ `%E4%B9%A0%E6%83%AF%E5%85%BB%E6%88%90` 解出「习惯养成」④ 卡不落 `zy-curation` + 回执行「刚导入 3 张卡」在位。
实测 `落库=3 总数=3→6 标签=["AI工具"] 解码="习惯养成" 型=["obsidian","url"] 台="🔖 书签导入 2026/9/30" 落池=false 回执=true`。
★首轮红在回执：那个钮的文案是**条件式**的（未接入 AI 时印「先在 AI 助手完成接入」），按「归类并补全这批」找永远命不中，
而导入本身其实已经成功——改核那一行无条件存在的「刚导入 N 张卡」。

## 六、边界如实

  如果真要直读浏览器书签，那是一个独立需求，得先谈权限申请的取舍。
