**为什么板底不用 `--surface` 直接铺**：树板里躺着的东西（项目舱、泳道、层级列表）**本身就是 `--surface`**。直接铺同色，"卡在板上"会变成"卡与板同色"，刚刚补出来的层级反而被抹平。55% 混合在两套光向下都留得住差：暗色主题是"比页面亮一点"，亮色主题是"比页面灰一点"。

## 三、四件值得单独说

### ① `<Transition>` 加了没生效，是因为同标签节点被复用

三个分支原本是 `CompassLayerList` / `CompassPano` / `div.tower-list`——其中两个是**不同的组件**，但第三个是裸 `div`。Vue 在 patch 时按"标签 + key"判断是否复用；不带 key 时，同一位置上的同标签节点会被认成同一个、直接改 props 了事，**过渡的 enter/leave 钩子根本不触发**。所以不是"过渡写错了"，是"没有发生替换"。

三个分支各补 key（`'lv-' + layerView` / `pano` / `tower`）后立即生效。另外 `mode="out-in"` 是必须的：两个形态同时存在会互相挤压，位置和宽度都在跳。

**只给形态切换，路由切换仍然零动画**——`V13-5` 这条老判据守的就是"路由级不许 `out-in`"，本批没碰它。

### ② `theme-audit` 里有一条长期"空转红"，本批把它改成显式跳过

方向树的项目层折叠判据，前提是数据里 `directions[].projects` 非空。这台机器的备份里该字段**全空**（方向层只有骨架，没有挂项目），于是判据每次都在"一张项目舱卡头都没有"上记失败——从 R3-B′ 建立到现在，它一直是红的，而红的原因不在代码。

处置：单列 `treeSkip`，输出 `⚠ 跳过` 而不是 `✓ 通过`，并把"数据前置"写进代码注释。**跳过不等于通过**，这是刻意的：如果哪天数据里真有项目、判据却还在跳过，说明选择器又漂了，那时应当红。同理，`treeFail` 现在只在"有数据但读不到卡头"时才记失败——那才是真问题。

### ③ `P0-S6` 又抓了一次新分片没入库

`16-b5-compass.cjs` 建好、单跑通过、全量也通过——因为它在磁盘上。但 `P0-S6` 要求 `SHARDS` 里每个分片**文件存在且已被 git 跟踪**，于是它红了一次。这条判据是 B3 那次（`14-mirror-whip.cjs`）之后加的，这次它替我把关成功了。

顺带发现另一个静默失能：**新分片建了但没加进 `SHARDS` 数组**，全量跑出来是 1,833——和改之前一模一样，看不出少跑了 7 条。所以"新分片"实际是三件事：建文件 → 进 `SHARDS` → `git add`。缺任何一件，本地都是绿的。

### ④ 截图的"主题看起来没切"是错觉，验像素才算

四主题截图出来后，apple（极简白）那张在第一眼看上去外框仍是深的，我一度怀疑主题没生效——下拉框里显示的仍是"深空薰衣草"。直接解 PNG 采像素：apple 背景 `(245,245,247)`、linear `(13,14,17)`，**主题是对的**，下拉框标签是截图时未重绘的旧文案。

结论：**主题是否生效，只认像素，不认控件文案**；这与 `theme-contrast` 只看令牌值不看渲染结果是同一类分工。

另外，本批两个归档目录（`B5a-compass` / `B5a-before`，后者是用上一版产物拍的对照）都**不带日期**。`dead-css-scan` 找普查只认 `^\d{4}-\d{2}-\d{2}$` 的目录，所以这两个各含 24 场景的窄普查不会顶掉 `2026-10-04` 那份 104 场景 / 831 token 的字典——这是 S2 那次被毒三条判据后定下的命名纪律，本批直接沿用。
