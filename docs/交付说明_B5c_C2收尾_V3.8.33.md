## 三、三件值得单独说

### ① 它本来就不是"树的一部分"

横幅的病根不在样式，在**位置**：它挂在 `<div class="tl-head-row">` 之后、项目舱之前，是画布内的一个块级元素。于是只要一开筛选，树区就被一条整宽色带从中间切开——上下两段各自成立，但"这是一整棵树"的连续感没了。

它真正表达的是"**整页视图正在被什么收窄**"：收窄的是视图，不是某一棵子树。这属于页头状态，和「项目塔 / 项目全景」这枚视图切换是同一层语义。所以位置从画布搬到 `hero-acts`，落在 `view-seg` 之后、右对齐的开关组之前——**跟着它语义上的邻居走**。

形态随之从"横幅"变"胶囊"：横幅要占满一行才有存在感，而胶囊在动作行里只需要占据自己那句话的宽度。

### ② 移动会打断判据，但打断的方式值得记一笔

两处历史判据同时指到这枚元素：

- `W11-9` 钉 `class="filter-bar"` —— 这是**位置性锚点**（它假定提示条住在画布里）；
- `W11-3 ⑤` 钉 `<Icon name="x" :size="13"/> 清除筛选` —— 这是**尺寸性锚点**（图标 13px）。

两处都在搬完之后变红。处置方式分两种：

- `W11-9` **重指到新类名，并补一句"钉的是'这页任何视图下都看得到被什么收窄'，不是钉它横在哪"** —— 语义没变，只是宿主换了；
- `W11-3 ⑤` **去掉尺寸，只钉 `class="hf-clear"` + 「清除筛选」文案** —— 这与 `R39-12` 那次是同一个教训：**图标尺寸不是契约**，它随字号档位调整而变，锚上去等于给下一次降噪埋一颗雷。

### ③ `theme-audit` 崩了，修的是脚本不是页面

本轮跑四主题审计时，脚本在 `st-airtable` 场景直接抛 `TypeError: parameter 1 is not of type 'Element'` —— 原因是对 `document.querySelector('.gs-card')` 的结果**裸调** `getComputedStyle`，页面没进到设置页时参数是 `null`。

后果比"某一屏失败"严重：**整个脚本中断**，linear 之后三个主题、十余个场景一张都没拍。一张截图失败的代价是"少一张"，脚本崩掉的代价是"这一轮审计根本不存在"——而它不产出红，只产出一行栈。

修法：取卡片前先判存在，`ok` 里也把"卡片在不在"算进去，`txt` 显式打印 `卡片=false`。**门禁工具自己的健壮性也是门禁的一部分**（与 P0-S6「分片必须入库」同一条道理：不执行的检查=没有检查）。

## 六、四主题走查（筛选态）

`theme-audit` 的 `VIEWS` 循环不支持 `act`（镜头定义只有 `hash` / `name`），而本批要看的恰恰是"点了筛选之后"的形态。给它加常驻场景会牵动 `class-census` 的场景数与既有判据，属独立活（已列进 §八欠账），所以本批用一次性脚本取证，产物落在 `docs/视觉归档/B5c-compass/`（4 张 + `readings.json`，目录已 gitignore）。

| linear | ✓ | ✓ | ✓ | ✗ | 27 × 394 | ✓（top 72 / seg 68） |
| raycast | ✓ | ✓ | ✓ | ✗ | 27 × 394 | ✓ |
| apple | ✓ | ✓ | ✓ | ✗ | 27 × 394 | ✓ |

三条读数值得记：

1. **高 27px、宽 394px** —— 若还是横幅，宽度会是内容宽（约 1368）；394 说明宽度真由内容决定。
2. **top 72 而 view-seg 是 68** —— 27px 高与 21px 高的元素在 `align-items: center` 下居中对齐，差 2px 上下正好是高度差的一半，说明**它和主焦点按钮在同一行**，没有掉到第二行去。
3. **四主题读数完全一致** —— 说明胶囊尺寸不依赖主题令牌，只依赖字号与内距，换主题不会破行。

同源文本：`只看战略目标「个人 IP 与内容系统」命中 1 个目标 · 1 个项目舱 清除筛选`（四主题逐字相同）。

> **取证时踩到的一个真坑（记在这里，因为它大概率还会再咬人）**：`theme-audit` 的默认 `--tag` 是**当天日期**，于是它写出的 `docs/视觉归档/2026-10-18/class-census.json` 会顶掉 `dead-css-scan` 的字典（该脚本取"最新一份 census"）。而本机备份库几乎是空库，那一轮拍出来的 106 张图有大量是空页，token 只有 744 个（有效字典是 `2026-10-04` 的 831 token / 104 场景）⇒ 死 CSS 立刻浮出一批**假**祖先断，连带 `R4-Ev①` / `W13-7` 变红。
> 处置：删掉那次空转产生的日期目录，字典回到 `2026-10-04`，两桶复归为零。**结论：跑 `theme-audit` 必须显式给 `--tag=<批次名>`，不要用默认日期** —— 这条纪律之前记过，本批又踩了一次，说明"记在备忘里"不够，得写进脚本默认值才有用（见 §八）。

## 七、ZIP 预算上调（用户拍板 2026-10-18）

**700KB → 900KB。** 理由链已写进 `pack.cjs` 文件头（防下一轮再问"凭什么是 900"），核心四条：

1. **700KB 是被用完的，不是被优化的**：V3.8.25 上调时 687,229 B（余 29KB），V3.8.32 是 694,942 B（余 4,902 B / 0.7%）。七个版本净增约 7.7KB。
2. **剩余工作必然还要加**：41 项还剩 17 项未开工（B6 六项 + B7），每批都要动样式与组件；4.9KB 盖不住一个版本的自然增长。
3. **900KB 是按既有速率折算的额度**：20 个版本 +78KB（≈3.9KB/版本），205KB ≈ 50+ 个版本，够走完 41 项。
4. **反向止损线写死**：若 900KB 也被很快吃满，说明增长是结构性膨胀，须查重复依赖与打包冗余，**不得再抬数字**。只放宽 ZIP，生产包仍 ≤2M、单文件仍 ≤400KB。

同步位置：`v2/scripts/pack.cjs`（文件头 + 日志行 + 告警线）· `文档中心/06_测试与发布/06-2_发布验收清单.md §G`（表格口径 + 新增 V3.8.33 复核结论）· `评审交接包/01_项目透视卡.md`（两处）· `UI迭代剩余任务与开发计划_V3.8.25起.md`（第 3 条决策）· `docs/模板_交付说明.md` · `知源调度台_产品认知基线_V3.8.24.md`。
