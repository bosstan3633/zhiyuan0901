## 二、真正的问题：同一张卡，换个视图就少一半功能

推平之前，同一张资源卡在三个视图里的待遇：

| 视图 | hover 动作条 | 🔥 调用次数 |
|---|---|---|
| **卡片** | `📌 ⭐ 📂 📡 🗑`（5 个） | ✅ `.rc-calls` |
| **列表** | `📌 ⭐ 🗑`（3 个） | ❌ |
| **看板** | `🗑`（1 个）+ 一个**点不动**的 ⭐ 图标 | ❌ |

用户从卡片视图切到看板，同一张卡能做的事从 5 件掉到 1 件——**这不是"看板本来就简洁"，是漏做**。

## 三、交付内容

### 3.1 三视图推平

| 视图 | 改前 | 改后 |
|---|---|---|
| 卡片 | `📌 ⭐ 📂 📡 🗑` | **`↗`** `📌 ⭐ 📂 📡 🗑`（六动作） |
| 列表 | `📌 ⭐ 🗑` | **`↗`** `📌 ⭐` **`📂`** **`📡`** `🗑` + **`🔥 N`**（六动作 + 调用次数） |
| 看板 | `🗑` + 只读 ⭐ | **`↗ 📌 ⭐ 📂 📡 🗑`**（六动作）+ **⭐ 可点切换** + **`🔥 N`** |

**六个动作、同一顺序**：`↗ 打开 · 📌 置顶 · ⭐ 星标 · 📂 移动分类 · 📡 镜像 · 🗑 删除`
（`📡` 三视图同为 `v-if="isHub && !isMirrorView(r)"`——镜像卡是引用，不提供镜像入口。）

### 3.2 两个设计判断

**① `↗ 打开` 在无链接时也保留（不隐藏）**

点击会给「⚠ 请先补全链接（本地文件需完整路径…）」。这看起来是多一次无效点击，实为**把"待补全"显性化**——按钮消失则用户永远发现不了这张卡缺链接。

**② `callCount` 不走字段池，沿用硬编码**

`callCount` 没有 `FieldDef`（字段池里没有这个键，也不该有——它是系统统计值，不是用户可配置的显示字段）。故列表/看板与卡片视图一致，硬编码一行 `🔥 N`。
`listFields` 的 `.slice(0, 3)` 与 `hasField('assets')` 门控**均未改动**，字段池语义不受影响。

### 3.3 改动量

| 文件 | 改动 |
|---|---|
| `v2/src/newtab/views/Workspace.vue` | 卡片视图动作条首加 `↗`（+4 行含注释）；列表视图加 `🔥` 一行 + 动作条补 3 个；看板视图 `kc-del` → 完整 `.kc-actions` 六动作 + `⭐` 可点 + footer 加 `🔥`；新增 4 条样式规则 + `.kc-card` 加 `position: relative` |

## 四、回归门禁

```
新增：R79-1 ~ R79-8
重指：R56-19（kc-del → .kc-action delete，能力仍在）
总数：828 → 836
```

| ID | 断言 |
|---|---|
| R79-1 | 卡片视图补 `↗ 打开`（`openResourceLink` 已挂 + 无链接提示补全） |
| R79-2 | 卡片视图六动作齐全**且顺序固定** |
| R79-3 | 列表视图补齐 `↗ / 📂 / 📡`，六动作同顺序 |
| R79-4 | 列表视图 `🔥 调用 N 次`（`rr-calls`，与卡片同为 `v-if="r.callCount"`） |
| R79-5 | 看板新增完整动作条，`.kc-card` 已 `position: relative` |
| R79-6 | 看板 `⭐` 由只读标记改为可点切换（只读图标仍保留） |
| R79-7 | 看板 `🔥 调用 N 次`（`kc-calls`） |
| R79-8 | 三视图 `📡 镜像` 口径一致：均 `isHub && !isMirrorView(r)` |

> **断言写法**：用 `segOf(src, head, next)` 截出**动作条片段**，再用 `inOrder()` 校验六个处理函数的**相对顺序**——比逐个 `includes` 更严（能防住"六个都在但顺序被打乱"），也比全文匹配更抗注释干扰。
