## 一、本轮交付摘要（3-5 条）

1. **REQ-058 HTML 附件「file:// 完整打开」通道 🔴 用户痛点根治**：自包含 HTML 的 blob:chrome-extension:// 页面继承扩展 MV3 CSP（script-src 'self'），内联 `<script>` 被静默拦截 →「双击完整、知源打开丢内容」。新建 `shared/utils/htmlAsset.ts`：`openHtmlAsset()` 三态返回（落盘 file:// 打开 / blob 降级 / 缺失提示），首次打开经 `chrome.downloads.download` 落盘到「下载目录/知源附件/」确定性路径（`<assetId>-<净化原名>`），落盘后记录路径记忆（独立存储键 `zy_html_paths`，不进主 JSON、不碰卡片模型），再次打开先 `fetch(file://…)` 探测复用不重复下载（conflictAction overwrite 同路径覆盖）；`downloads` 不可用/落盘失败（如未开「允许访问文件网址」）自动降级 blob + Toast 引导。**修复漏网 bug：manifest `permissions` 补 `'downloads'`**（R42-18 防回归）——否则 file:// 通道全部静默失效。
2. **REQ-059 附件导出/导入闭环（备份迁移能力补齐）**：新建 `shared/utils/zip.ts`（零依赖 STORE 模式 + CRC32，~150 行）+ `shared/storage/assets.ts` 增 `getAllAssets`/`putAssets` 批量能力；GlobalSettings「数据管理」新增**导出附件包 / 导入附件包**：导出 = 全量 Blob 读 IndexedDB → buildZip（附件本体进 zip，主 JSON 只存 AssetMeta 的红线不变）；导入 = 读 zip → **同 ID 覆盖写回**（拍板 q-3）→ 配合原 JSON 导出/导入即可完整迁移备份（数据 + 附件双轨）。
3. **REQ-060 高频操作性能专项（结论：无红线，无需修复）**：Playwright 真机实测五项基线全部健康——启动主框架 200ms、首卡渲染(317卡) 24ms、搜索 DOM 稳定 325ms（含 150ms 设计内防抖）、工作台切换 595ms（往返含首卡 331ms）、单击开 Drawer 104ms、persist 纯净清洗 9ms@107KB。此前用户疑虑的「搜索 2.5~6 秒」经排查为**测量假象**（`performance.now()` 页面时钟与脚本 `Date.now()` 混比 + 命中词区分度低致 DOM 长尾刷新），统一同源时钟 + MutationObserver 精测后真实值 ~175ms 计算+渲染。本轮不引入任何性能改动（避免无谓回归风险）。
4. **REQ-061 卡片附件上传规范（用户拍板落地）**：AssetManager 硬化**图片 ≤9 张（单张 ≤10MB）**（超限 Toast 跳过）、**HTML 单卡唯一（重复上传 = 替换旧的）**（`replacedOld` 回传供宿主清旧引用）；HTML 上传成功 emit `html-added(meta, replacedOld)`，三类宿主联动——资源卡 `ResourceEditForm.onHtmlAdded`（标题仅空/旧文件名时联动为文件名去扩展名 + linkType=file + link=zy-asset://<id>，手打标题不覆盖）；好奇卡/任务卡同构接入（question/title 侧）；**双击卡片打开挂 HTML 附件的资源卡**（link=zy-asset:// 正则 → openHtmlAsset）；AssetPreview 升级**多图左右切换**（posLabel「n/N」+ ‹ › 箭头 + ←/→ 键盘，宿主管理 url 状态机）。
5. **工程治理**：版本号 2.18.0 五处同步（manifest/package/关于页动态/ManualPage/regression）；R42 回归批次 18 项（REQ-061×7 / REQ-058×5 / REQ-059×4 / REQ-060×2）+ 6 项过时断言改写（R36-20/R39-4/R39-6/R40-6/R40-11/R41-5）；回归 **339 → 358 项全绿**；vue-tsc 0 错误；dist 干净重建（2.18.0 + downloads 权限）；真机端到端 **10/10 ALL PASS**（DataTransfer 真实上传链路）。

## 四、技术要点

- **REQ-058 CSP 根因**：MV3 扩展页面（含 blob:chrome-extension:// 子资源）受 `script-src 'self'` 约束，**内联 `<script>` 一律静默拦截**——这是「双击完整、知源打开丢内容」的根因；blob URL 方案在 MV3 下无解，**file:// 是唯一与双击 100% 等效的通道**（内联脚本/localStorage/编码一致）。
- **REQ-058 确定性路径设计**：落盘目录固定「下载目录/知源附件/」，文件名 `<assetId>-<净化原名>`（assetId 保证确定性、原名保证可读）。复用探测 `fetch(file://…)` 返回 200 即复用——用户删了下载文件才重新落盘（conflictAction:'overwrite'，同路径覆盖不产生「xxx(1).htm」副本）。
- **REQ-058 路径记忆隔离**：存独立存储键 `zy_html_paths`（不进 `zy_data_v2` 主 JSON、不碰卡片模型/AssetMeta），彻底绕开附件「主 JSON 只存 meta」红线，且路径映射丢失只触发重新落盘（无害）。
- **REQ-058 三态返回**：`openHtmlAsset` 明确三态——`file`（file:// 新标签打开成功）/ `blob`（降级，Toast 引导开「允许访问文件网址」或手动确认下载）/ `missing`（IDB 无此附件，Toast 提示）。宿主无需感知链路细节，只按返回值提示。
- **REQ-059 zip 零依赖取舍**：STORE 模式（不压缩）——附件本体是图片/HTML，压缩收益趋近于零，换来 ~150 行无依赖实现 + 极速打包；CRC32 表驱动保证数据完整性；三种 PK 头锚点（Local File Header / Central Directory / EOCD）对齐标准 zip，任何解压工具可开。
- **REQ-060 测量方法论（重要）**：早期 2558ms/6057ms 假数据根因——① `performance.now()`（页面时钟，含页面自身时间线偏移）与脚本 `Date.now()` 混比；② 命中词区分度低导致 DOM 尾部反复重渲染被误判为「搜索未稳定」。修正：**统一 `Date.now()` 同源时钟 + MutationObserver 打点「首帧/稳定」双时刻 + 高区分度命中词**，真实搜索 = 键入 → 首帧 325ms（含 150ms 防抖）→ 稳定 325ms，纯计算+渲染 ~175ms。
- **REQ-061 联动回传**：AssetManager 只负责「文件→IDB→meta 列表」，**业务联动一律 emit 上抛**（html-added），三类宿主各自按语义落地（资源卡→linkType/link/标题、好奇卡→question、任务卡→title），组件零业务知识。
- **REQ-061 双击 vs 单击**：单击卡片 = 开编辑抽屉（260ms 防抖），双击 = 打开链接。挂 HTML 附件的资源卡 link=zy-asset://<id> 走 openHtmlAsset（双击与卡片链接打开行为一致）。

## 八、修复记录（本轮真机链路暴露的 Bug）

### 🔴 Bug：manifest 缺 `downloads` 权限（REQ-058 漏网缺陷）
- 现象：E2E 2a/2b 失败——双击后无下载事件、无 file:// 新标签。
- 根因：REQ-058 代码正确调用了 `chrome.downloads.download`，但 `manifest.ts` 的 `permissions` 只有 `storage/unlimitedStorage/tabs/activeTab/commands/scripting`，**漏加 `'downloads'`** → 扩展无下载权限时 `chrome.downloads.download` 为 undefined → `hasDownloads()` 返回 false → `openHtmlAsset` 静默走 blob 降级分支——「代码写了、权限没给」，静态层面完全看不出来。
- 修复：manifest `permissions` 追加 `'downloads'`；R42-18 断言锁死（防后续重构误删）。
- 为什么此前的门禁没发现：静态断言无法验证「API 存在性」，注入式验证不会走 downloads 分支；只有 DataTransfer 真实链路 + 双击触发才走到该 API——再次印证 V2.17.1 教训：**端到端必须走真实链路**。
