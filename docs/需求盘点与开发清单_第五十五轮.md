## 二、任务明细

### A · 策展卡片平权与混排（原 #1）

**实测定性**：投射卡移入原生分类后再拖往其他分组，链路是通的（targetCatId 正确迁移）；"没法拖拽"的实质 = **原生卡与投射卡分属两个区块，无法混排相互排列**。

- **A1 统一混排列表**：分类视图内原生卡+投射卡合并为一张网格；`CurationProjection` 新增可选 `curOrder?: number` 与原生卡 `curOrder` 同键，排序权重 `置顶 > curOrder > createdAt`；拖拽排序对混合列表统一重编号。
- **A2 移动语义固化**：镜像卡 A→B 后 A 消失 B 出现（现行为保持）+ E2E 断言固化。
- **A3 平权交互**：原生卡可入镜像分类、镜像卡可回原生分类/未分类/待分类、混排列表内相互排列。
- **A4 视觉区分保留**：原生蓝竖线 / 投射虚线+📡；「📡 源分类实时镜像」区保持独立（不参与策展排序）。

### B · 任务调度迁方向台（原 #2a，Q3 已拍板）

- **B1 迁移**：`TaskManagerPanel` 迁至方向台项目总览之下，模块头「任务调度 · 全域任务管理」，**默认展开平铺**；**卡片/列表/看板三视图 + 全部筛选能力原样保留**（组件整体迁移）。
- **B2 调度台底部简化（Q2）**：移除「任务调度」Tab 与 zone Tab 机制，好奇心培育**去掉 Tab 头单区直呈**（标题行保留）。
- **B3 定位链路改造**：任务类定位统一改指方向台——`/?zone=task` → `/compass?zone=task`（CompassShell 滚动定位到任务管理模块+高亮）；MetricDrillDrawer 未归档任务、写入记录 locateRec、搜索任务直达等消费方同步。

### C · 快速采集任务（原 #2b）

- **C1 采集弹窗**：任务名称 / 任务内容 / 所属项目 / 所属指标（项目→指标级联，全**非必填**）；Ctrl+Enter 保存；保存进全域任务（未挂项目=未归档任务）。
- **C2 三端链路**（照资源快速采集模式）：content 浮层（overlay-impl 新面板）+ 应用内 GlobalPopups 新面板 + popup 降级；background 分发 `zy-open-task-capture`，工作台当前页与非当前页均可一键触发。
- **C3 快捷键语义变更**：`open-tasks` 描述「打开任务调度」→「**快速采集任务**」（键位不变）；设置页快捷键中心 + 手册同步。

### D · 方向状态迁调度台（原 #3，Q1 已拍板）

- **D1 迁移**：`MetricBar`（四格 + 日/周/累计 + 详细指标下钻）迁至**调度台最顶部**（今日记录条之上）。
- **D2 调度台 4 指标降级**：项目调度左列 2×2 大卡 → **一行状态栏**（小号数字横排，卡片头部右侧），下钻弹窗交互不变。
- **D3 DHI 新口径（已拍板）**：在轨 = 窗口内有任务完成 **或** 有进行中任务 **或** 项目任务已全部完成；主数字 = 在轨项目占已投射项目百分比（2 投射 1 在轨 → 50%，已投射=0 显示 —）；档位 清晰≥75% / 关注≥40% / 模糊>0 / 未启动=0；副标「N方向·M已投射·K在轨」。
- **D4 方向台收口**：主航线置顶，布局与断言同步。

### E · 分栏拖拽修复（原 #4）

**实测定性**：拖拽 handler 运行且 `curSplit` 已持久化（38→49），但 **`.cur-cols` 行内 `gridTemplateColumns` 未渲染到 DOM**——绑定层真 bug。

- **E1 修复列宽绑定**：先最小复现定位 Vue 绑定失效原因，再重实现（`:style` 字符串绑定或 flex+width）；拖动实时反馈。
- **E2 分隔条常显可见**：常显弱色抓取纹理（当前 6px 透明仅 hover 变色，用户难发现），命中区加宽。
- **E3 钳制修正**：`minmax(240px, X%)` 小宽度下钉死列宽造成"拖不动"假死 → `minmax(0, X%)` + 内容 min-width:0。

### F · 性能与体积（原 #5）

**实测构成**：icons 328K（icon512=228K + icon256=68K **均未被 manifest 引用**）｜ 拼音字典 308K ｜ vendor 208K。

- **F1 图标瘦身**：删除未引用的 icon512/icon256（-296K），同步源 public/icons；预计 1.7M → ~1.4M。
- **F2 chunk 构成核查**：vendor 208K 与 96K×2 的构成；manual-data（~42K 源码）若入主包则改动态 import。
- **F3 拼音缓存 LRU**：3000 上限整表清空 → 逐出最旧。
- **F4 切工作台渲染试验**：卡片网格 `content-visibility: auto`（针对实测最慢项 595ms 的渲染段），真机前后对比。
- **F5 体积前后对比报告**；搜索倒排/虚拟滚动仍列后续大项。

### G · 项目详情页改版（新 #1，v4 修订：左栏双列目录）

- **G1 左栏双列联动目录（拍板采纳谭老板方案，替代变形式）**：左栏升级为两列（合计约 350px，sticky）：
  - **第一列（约 140px）＝全部项目**：项目列表恒显（名称省略号+进度百分比），当前项目高亮，**单击即切换**——第二列与右侧展板即时刷新；
  - **第二列（约 210px）＝当前项目详情目录树**：根 = 项目名称（含进度）→ 成功指标（进度/任务计数）→ 任务（状态点+标题，含 ⚠ 未归类区）；
  - **树上拖拽**：拖任务到另一指标节点 = 变更所属指标（syncMetricTaskIds 双写，右侧展板即时反映）；拖指标节点整体移动 = 重排 `metrics` 数组（数组序即排序），调度台「项目调度」指标组**天然实时同步**；与右侧主展板共用同一操作函数，避免双实现漂移；
  - **节点单击** = 右侧展板滚动定位 + 高亮（任务行复用 hl 机制）；
  - 落地视图（未选中项目）第二列空态提示；窄窗口（<1080px）第二列自动收起退化为单列；
  - 拖拽命中反馈沿用策展中心 drop-line 三段位视觉。
- **G2 归属链横向化**：愿景→使命→战略目标→项目 四节点由纵向改为**横向一行**（小卡横排，跳树能力保留），压缩纵向空间，突出项目全景焦点。
- **G3 主展板保持**：「成功指标 → 任务」展板既有能力不变（任务拖拽排序/跨指标归属/添加任务/指标删除），目录树是导航+结构操作的增量层。

### H · 全局检索删除免确认（新 #2，v3 修订：网页端也能删）

- **H1 应用内搜索（GlobalPopups）**：结果卡 🗑 去掉 `useConfirm` 二次确认——直接软删 + Toast「已删除，可在回收站恢复」+ 结果数组即时过滤（卡片从列表消失）。
- **H2 网页浮层（overlay-impl）补删除**：搜索结果行新增 🗑（资源/任务/好奇三类自有卡）——**无二次确认**，直接软删（content 侧走既有 storage 读写路径写 `deletedAt`）+ 从结果数组即时移除 + 浮层内 Toast；软删后其他端经 storage.onChanged 同步。
- **H3 范围**：popup 降级窗不涉及（无搜索）；策展中心/工作台内删除维持各自既有确认策略，不受影响。
