## 二、REQ-048 卡片附件（最小版本）

### 2.1 拍板参数（第卅九轮开工前用户确认）

| 决策点 | 结果 |
|---|---|
| 支持范围 | ✅ **三类卡全部支持**：资源卡 / 好奇心卡 / 任务卡 |
| 单文件上限 | ✅ **20 MB** |
| 附件总数 | ✅ **不设上限**（设置页显示占用与清理入口兜底） |
| 性能红线 | 主 JSON `zy_data_v2` **绝不存 base64**；二进制全部进 IndexedDB，按 key 读取 |

### 2.2 架构：IndexedDB 附件库 + 元数据引用

```
卡片字段（主 JSON，KB 级）                     IndexedDB 库 zy_assets（独立，Blob）
┌─────────────────────────────┐               ┌──────────────────────────────┐
│ assets?: AssetMeta[]        │               │ objectStore 'assets'         │
│  └ { id: 'at_xxx',          │  putAsset     │  key = assetId               │
│      kind: 'image'|'html',  │ ───────────►  │  value = Blob（原二进制）     │
│      name, size, mime,      │               │  读写 O(1)，不影响主树         │
│      createdAt }            │               └──────────────────────────────┘
└─────────────────────────────┘
```

- `AssetMeta`（models/index.ts）：仅存引用，注释明示性能红线（不存 base64/ArrayBuffer/Uint8Array 二进制承载字段）。
- `shared/storage/assets.ts`（新，135 行）：`openDb` 惰性单例 → `putAsset / getAssetBlob / deleteAsset / getAssetStats / getAllAssetIds / cleanupOrphanAssets / assetIdsOf`；不支持 indexedDB 环境返回 null 安全降级。
- **软删/硬删语义**：卡片软删（deletedAt）只隐藏不删附件；回收站**硬删（purge）时先清附件**（`purgeAssetsOf` → 逐条 `deleteAsset`）。

### 2.3 共享组件 AssetManager.vue（新，199 行）

| 能力 | 实现 |
|---|---|
| 上传 | `onPick/onFilesChange`：校验类型（图片 / 自包含 HTML）+ 单文件 ≤ `maxSizeMB`（默认 20）→ `putAsset(uid('at'), file)` → emit 元数据列表 |
| 展示 | 附件 chip（图标 + 名称 + 大小 + 删除 ×），`removeAsset` 同步 `deleteAsset` |
| 打开·图片 | `URL.createObjectURL(blob)` → **全屏弹窗预览**（Teleport body），60s 后 revoke |
| 打开·HTML | `chrome.tabs.create({url: objectURL})`（fallback `window.open`），仅支持自包含单文件 HTML |
| 类型判定 | `guessKind(name, mime)` 扩展名兜底 |

### 2.4 三卡 UI 接入（编辑表单即所见）

| 卡片 | 位置 | 接入点 |
|---|---|---|
| 资源卡 | Workspace 内联抽屉 + ResourceDetailDrawer（搜索抽屉） | 双入口经共享 `ResourceEditForm` 内嵌 `<AssetManager v-model="model.assets">`，变更即时持久化（新卡暂挂、保存入库） |
| 任务卡 | CompassActions 任务侧边栏 | `selectedTask.assets` + `onTaskAssetsChange` → `touchTask` |
| 好奇心卡 | CuriosityPanel 详情抽屉 | `detailItem.assets` + `onCurioAssetsChange` → `update(detailId, { assets })` |

### 2.5 兜底与运维

- **回收站硬删联动**：`RecycleBin.vue` 三类 purge 前先 `purgeAssetsOf`（附件物理删除只在硬删发生）。
- **设置页「📎 附件存储」卡片**：`getAssetStats` 实时显示附件数 + 占用字节；「清理孤儿附件」按钮 → `cleanupOrphanAssets(keepIds)` 删除主 JSON 中已无引用的残留 Blob；导出页 watch 自动刷新。

## 三、#61 共享资源编辑表单 ResourceEditForm.vue（技术债清偿）

### 3.1 背景

第卅七轮 REQ-042 把搜索抽屉升级为可编辑时，字段表单在 **Workspace 内联抽屉（dr-*）** 与 **ResourceDetailDrawer（red-*）** 存在**双份实现**，任何字段改动需两处同步，已记技术债。本轮抽取单份共享组件，行为保持一致。

### 3.2 组件边界（抽取原则）

```
ResourceEditForm.vue（共享单份，222 行）
├─ 标题行：textarea + 可选关闭按钮 ×（show-close）+ highlight 高亮
├─ 字段主体：链接类型（URL/本地文件/Obsidian）+ 输入 + file 补全路径告警
│            工作台选择（wsOptions）→ 分类联动（catOptions 随 model.workspaceId）
│            TagPicker 标签 · 描述框（拖拽高度记忆 height-key）· 附件（REQ-048）
│            <slot name="extra"> 宿主差异内容（如 RDD 使用统计，插在附件与挂载之间）
│            被任务挂载（只读，点击 emit goto-task）
│            创建/更新时间戳
└─ emit 收敛：save（Ctrl+Enter）/ goto-task(t) / close —— footer 动作条留在宿主
```

**行为约定（与两宿主原实现完全一致）**：
① 标题/链接/描述 Ctrl+Enter → emit save（宿主保存+关闭）；② 切换工作台 → 清空分类（REQ-005）；③ 附件变更即时持久化（已入库卡写回 + persist；新建卡暂挂 model）；④ 挂载任务点击 → 跳任务中心；⑤ footer 删除/复制/打开/保存由宿主各自 handler 实现（新建/编辑差异在宿主）。

### 3.3 宿主改动

| 文件 | 改动 |
|---|---|
| `Workspace.vue` | 内联抽屉 dr-header/dr-body 字段区（标题/链接/工作台/分类/TagPicker/描述/附件/挂载/时间戳，约 90 行模板 + 10 个本地函数）整体替换为 `<ResourceEditForm :model="editingResource" height-key="ws-note" :show-close="true">`；**删除已迁入本地的** `isFullPath / drawerWsOptions / drawerCatOptions / onDrawerWorkspaceChange / fmtTs / onResAssetsChange / noteH+startNoteResize / removeTag(死) / mountedTasks / linkPlaceholder`；保留宿主动作 handler（saveResource / deleteCurrentResource / copyLink / openResourceLink / closeDrawer / goToTask）；清 40+ 行已无引用的 dr-* 字段样式 |
| `ResourceDetailDrawer.vue` | 删除表单上 3 个死绑定（@remove/@copy-link/@open-link——emit 已收敛，footer 四按钮直接调宿主函数）；保留 Drawer 容器 + 统计区（extra 插槽）+ footer 动作条 |

**高度记忆键延续**：Workspace 用 `ws-note`、RDD 用 `res-drawer-note`——与原两处拖拽记忆完全同一键，用户已有高度设置无缝保留。

## 六、已知边界与后续（如实记录）

1. **HTML 附件仅支持自包含单文件**：依赖相对路径资源的本地页面请继续用 `linkType='file'` 完整路径卡片（第卅八轮调研已明确）。
2. **附件随 JSON 导出未打包**：当前导出仅元数据；Blob 本体随浏览器数据走。附件全量迁移方案（zip 打包）待后续轮次评估。
3. 附件统计卡片与回收站硬删为**最小兜底**：若长期大量附件，可再评估"附件浏览/批量清理"独立页。
4. 既有技术债（V2.14 起延续，未在本轮处理）：巨型 SFC（Workspace 1760 行 / CompassHome 等）、静默 catch、防抖保存无异常处理；`docs/产品白皮书_V2.4.md`、`docs/技术架构与数据模型.md` 命名需随 V2.15 统一刷新。
