# 交付说明 · V3.9.17 项目全景阅读秩序 · 任务账本与树导航

> **发布日期**：2026-10-24
> **版本**：V3.9.17
> **主题**：项目全景单一路径、任务账本三列、项目详情任务软删、策展树空间导航
> **边界**：沿用现有信息架构、六层模型、三卡数据关系、策展树结构与四主题令牌；不推翻现有布局。

---

## 一、本轮结论

本轮在 V3.9.16 的既有方向台布局上继续收口阅读秩序与操作一致性，不新增业务面：

1. **项目全景只保留一条阅读路径**：项目切换与动作 → 项目摘要 → 指标泳道。原先左右争抢的摘要结构退役，项目名、下一步与第 4/5/6 层从属信息按同一阅读顺序进入摘要区。
2. **任务行统一成账本三列**：完成热区 / 标题与线索 / 优先级·成熟度·删除固定在行尾。项目全景、项目详情指标页与任务页共用同一结构，任务删除免二次确认，写软删并进回收站。
3. **策展树补空间导航**：↑↓ 按可见节点顺序移动，← 回父级，→ 进首个子级，Home / End 到首尾；方向键只移动焦点，不改变 Tab 建子级与 Enter 建同级的语义。

本轮不改变六层模型、三卡数据关系、策展树结构或四主题令牌。

## 二、实现结果

### 2.1 项目全景

- 固定为 `.ph-toolbar → .ph-b → .lanes-shell` 的单一路径。
- 项目切换器、进度与项目动作固定在顶部工具带；项目名、下一步、层级脚注顺序进入摘要区。
- 移除 `.ph-r` 左右争抢结构，项目名不再重复出现。
- 四主题实测页首高度稳定为 **103px**；单泳道铺满，多泳道保留可读宽度并在泳道内横向滚动。
- 项目全景多指标场景实测 4 条泳道等分、收容道固定最后、长任务不撑破行、页面级横向溢出为 0。

### 2.2 任务账本

- 任务行统一为三列：完成热区 / 标题与线索 / 优先级·成熟度·删除。
- 项目全景与项目详情指标页、任务页复用同一行内删除语义。
- 删除走软删，免二次确认，可进回收站恢复。
- “从本指标移除”只解绑指标归属，任务本体保留在调度台；删除本体由行尾删除按钮承担，两者不混用。

### 2.3 策展树导航

- `↑` / `↓` 按当前可见节点顺序移动焦点。
- `←` 回到父级，`→` 进入第一个子级。
- `Home` / `End` 跳到首节点 / 末节点。
- 子节点把自身 id 一并上抛，避免选中态与焦点态不同步时导航跳到别处。
- 方向键只移焦点，不触发建支、编辑或拖拽；Tab / Enter 的建支语义保持不变。

### 2.4 无障碍与响应式

- 项目详情中的 `pd-mini`、`pd-check` 提升到 28px。
- 项目全景与项目详情继续保持键盘可达；E2E 新增树空间导航真实浏览器用例。
- M6 响应式覆盖 1440 / 1024 / 800 三档 × 四台面，共 12 组合，无页面级横向溢出，首屏 `<28px` 热区为 0。
- 仍保留两项已知残余风险：**54 处 `outline:none`** 与 **32 处遮罩层**。这两项不能因本轮全绿而写成“无障碍全部通过”。

## 五、下一轮 UI 设计优化方向

项目全景本轮解决了“路径争抢”，但视觉上仍可继续减噪，建议按以下顺序推进：

1. **项目摘要再分层。** 项目名与下一步保持主阅读级，层级脚注和辅助动作进一步退到次级视觉层，避免摘要区仍像一组并列信息。
2. **泳道头部建立统一节奏。** 指标序号、名称、验收标准、进度与详情按钮固定为同一基线；不同指标标题长度不再改变头部视觉重量。
3. **任务账本强化扫描效率。** 任务标题是唯一主信息，线索行只保留归属与必要状态；优先级、成熟度与删除保持行尾固定列，减少每行内部竞争。
4. **项目塔与项目全景共享同一视觉语法。** 两视图继续共享任务账本和状态语言，但项目塔优先“项目推进”，全景优先“指标横向对照”，不强行做成同一张卡。
5. **继续处理无障碍残余。** 优先逐条核验 54 处 `outline:none` 是否有可见替代焦点态，再统一遮罩层的关闭、焦点圈定与焦点回归。
