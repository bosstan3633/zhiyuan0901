## 四、关键设计决策

### 4.1 `Modal.vue` 与 `Drawer.vue` **并列**，不是替换

`Drawer.vue` 挂着**全站 30+ 抽屉宿主**，动它就是全站回归面爆炸。故新壳是**并列的第二个壳**，二者共用同一套外部约定（`open` / `title` / `width` / `@close` + `title-extra` / `footer` 插槽）——对宿主而言换壳是零成本。

三条硬约束（每条都有前车之鉴）：

1. **`useOverlayTarget()` 必须沿用**（R113-N5）：金字塔真全屏时，浮层若 Teleport 到 `body` 就**不可见**。
2. **Esc 走「document 捕获阶段 + `stopPropagation`」**，与 `Drawer.vue` 同机制 —— 否则一次 Esc 关两层。
3. **尺寸走 CSS 变量（`--md-w` / `--md-mh`）而不是内联 `width/height`** —— 内联样式会**压过窄屏媒体查询**，那样 `<768` 的全屏化永远不生效。

### 4.2 收窄"宁松勿猜"

需求③说"按输入指向做范围内全盘检索、保住响应速度"。`scopeSearch` 的落地纪律是：

- **只认字面出现的词**：句子里点名了"资源卡 / 任务卡 / 好奇心卡"或某个台名/分类名才收窄；**不做同义改写、不猜意图**。
- **识别不到就原样返回全库**；**收窄后不足 2 张就放弃收窄** —— 那已经不叫"挑"，叫"没得挑"。
- 收窄结果经 `finish(..., scope)` **回传并显示**（`🎯 范围 资源卡 40/120 张`），让用户看得见"这次只看了多少张"。

为什么不用模型做范围判定：范围判定是**投料前**的决策，用模型判就要先投料（自相矛盾），且会让"每次检索的候选集不可预期"。字面规则可预期、可解释、零成本。

### 4.3 关键词**不进** AI 候选底座

镜像弹窗原本只有 `linkCandidates`（**关键词过滤焊在候选里**）。若直接复用它做 AI 候选，"字面没命中但语义相关"的卡会在投料前就被砍掉 —— **"换个说法也能召回"就失效了**。

故拆成两层：`linkBase`（在册资源卡 + 分类过滤，**不含关键词**）作 AI 候选池；`linkCandidates = linkBase + 关键词` 只影响**可见列表**。`linkShowList` 再把"语义命中"置顶、把"未字面命中的命中卡"补进列表 —— 用户既看到字面结果，也看到 AI 额外找回来的。

### 4.4 星标"仅组内靠前"，不是全局置顶

既有口径是 `markRank`：**置顶(2) > 星标(1) > 普通(0)**（`shared/utils/marksort.ts`）。AI 检索开启后若只按 AI rank 排，会把星标卡挤出组首 —— 与既有口径打架。故排序改为 **`markRank` 优先、AI 命中度次之**，同标记时比较器返回 0，让 `filteredResults` 的既有次序稳定沿用。

用户拍板口径：**"仅组内靠前"** —— 星标卡不会跨组冲到整个结果集最前。

### 4.5 检索历史进 `UIPrefs`，不进 `AppData`

`searchHistory` 放 `uiPrefs`（`zy_ui_v2`）而不是主数据（`zy_data_v2`），理由三条：

1. **它不该被同步/导出**：检索历史是**本机行为痕迹**，跟着数据包走会泄漏"用户在本机搜过什么"；
2. 与 `projRailW`（目录栏宽度）、主题等同类，都是"这台机器上的偏好"；
3. 上限 **20 条**（`SEARCH_HIST_MAX`）并按次数降序只铺 **3 条** —— 检索框下方是**最高频的视觉区**，铺多了会把结果挤下去。

记账点覆盖**两条出口**：`openLinkOrLocate()`（真的用出去了）与 `closeAll()`（关了面板但有结果）—— 否则"打开"与"关闭"会被记成两次。2 字以下不记；同轮换词用 `recordedQ` 幂等。

### 4.6 只投字段与"链接地址"，不抓正文

需求③明确"不需要对卡片背后的链接进行爬取内容"。落地不止是"不抓"，而是**把这条纪律写进系统提示**：

> **这些字段就是你的全部依据**：不许假设、不许脑补、**绝不引用或猜测链接指向的网页内容**——本功能不联网、不抓正文，给你的「链接」只有地址本身。

原因：模型看到 URL 会**自行"回忆"该网站内容**并当成事实（尤其知名站点），用户无法分辨哪句是"读了你的字段"、哪句是"它以为这个网站是啥"。写死不抓，才能让"引用必须来自字段"成为可验证的约束。

## 八、踩坑记录

### 8.1 ★ `vue-tsc --noEmit` 对「模板元素未闭合」**静默放行**

迁移 `.ai-sum`（从右栏表头迁到跨栏汇总）时**吞掉了 `.ai-dual` 的一个 `</div>`**。现象极具误导性：

- `npx vue-tsc --noEmit` → **EXIT=0（全绿）**
- `node scripts/regression.cjs` → **全绿**（都是字符串断言）
- `npm run build` → **`[vite:vue] AiSuggestionDrawer.vue (396:5): Element is missing end tag`**，构建直接失败

**定位方法**（不是猜）：用 `@vue/compiler-sfc` 的 `parse()` 拿 `errors` + `@vue/compiler-dom` 的 `baseParse()` 打印**元素树** —— 一眼看出 `<div class="ai-body">` 的元素区间是 `L396-L531`（延到模板末尾），说明它没被闭合；再看子节点 `<div class="ai-dual">` 吃到 `L517`（本该在 `.ai-sum` 之前闭合）⇒ 定位到缺失的 `</div>`。

**已钉成常驻门禁**（`regression.cjs` R161-⑥）：全站 `.vue` 走 SFC 解析零错误 + 文件数下限。

**实现坑（同一条断言里踩到）**：第一版用 `read(f)` 喂解析器 → **假报错**（`Workspace.vue :: Element is missing end tag`）。原因：`read()` 对 `Workspace.vue` 是**聚合读取**（`WORKSPACE_SRC_FILES` 把 8 个 composable + `workspace.css` 拼在一起），根本不是一个 SFC。⇒ **必须裸 `fs.readFileSync(base + f)` 读单文件**。

### 8.2 宿主 ≤1500 行验收线（04-59）连带 5 条断言同时变红

需求④若把 AI 检索**内联**进 `Workspace.vue`，宿主从 1496 → **1515 行**，越过 04-59 立的 ≤1500 验收线，**连带 `R115-1` / `R140-3` / `R144-6` / `R147-5` / `R151-6` 五条同时变红**。

### 8.3 `workspace.css` 是 `<style scoped>` ⇒ 抽组件不能"只搬模板"

- `.lc-*` 样式（含本轮新加的 `.lc-ai-*`）随组件迁走 —— **scoped 跨不过组件边界**，留在 `workspace.css` 就是死代码。
- `.modal-overlay` / `.modal` / `.modal-header` / `.dr-footer-btn` 这些**壳类也只在 `workspace.css` 里**，且被其余约 10 个弹窗共用 ⇒ **不能搬**。这正是抽出来的 `LinkCardsModal.vue` 必须换到 `Modal.vue` 新壳的原因（顺带把私有 modal 实现的**消费方**减掉一个）。

### 8.4 `grep` 在 emoji 上有编码盲区，判计数必须用 node

排查 `R146-5` 的 emoji 口径时，`grep -c "🤖"` 在 Git Bash 下返回 **0**，而该文件（`GlobalPopups.vue`）实际有 **2** 处。差点据此得出"全站零 `🤖`、我的新代码是唯一违规"的**反向结论**。

⇒ **非 ASCII 字符（emoji 尤其）的计数/定位一律用 node**（`s.split('🤖').length - 1`）。

### 8.5 视觉归档的"非确定性渲染"必须自证，不能当差异

`linear-resource.png` 在 before/after 里 md5 不同，第一反应是"本轮改了资源台"。做法：对 **V3.2.2 同包重复采样 3 次** → `290e7c8a` / `1eff2945` / `1eff2945` ⇒ **两次与 V3.2.1 完全相同**，且两份 PNG 只差 **2 字节** ⇒ 判为渲染抖动（骨架屏→内容的过渡帧/合成差异），不是代码差异。

⇒ **规则：单图 md5 不同**不构成"有改动"的证据**，必须先做同包重复采样**。（与 `perf` 的"读数一字不差要先怀疑测的是同一个包"是同一族纪律的镜像：**一致要自证，差异也要自证**。）

> ★ **2026-09-22 更正（§8.7）**：本条当时的"非确定性渲染"结论**方向对了、归因错了** —— 真正的原因是**视角残留**（滚动位置 + 鼠标 hover），不是渲染本身不确定。修正后同包重采 **24/24 md5 相同、逐像素 0 差异**。判"改成没改"的正确工具是 `scripts/img-diff.cjs`（逐像素 + 包围盒），不是 `md5sum`。

### 8.6 ★★ 键盘快捷键**从未注册**："watch(open) 缺 immediate" + 宿主条件挂载（本轮最重的发现，已修）

**怎么发现的**：收尾核对视觉归档时，发现 AFTER 套里 `apple-dashboard` / `notion-compass` 等**台面图里叠着一条中央弹窗**。口径是"归档图必须能当证据"，于是追下去 —— 根因不在归档脚本，在**产品代码**：

```ts
// Modal.vue（修复前）
watch(() => props.open, async (v) => { … document.addEventListener('keydown', onKey, true) … })
//                                                              ↑ 只有 open 变化时才注册
```

而宿主是 `<AiSuggestionDrawer v-if="aiJob" :job="…">`（`GlobalSettings.vue` / `RecycleBin.vue` / `TaskAddDrawer.vue` 三处同款），组件内 `const open = computed(() => !!props.job)` ⇒ **组件一出生 `open` 就是 `true`**，watch 永远等不到"false → true"那次变化 ⇒ **监听器从未注册**。

**症状的欺骗性**（这是它能活过两轮验收的原因）：

| 关闭方式 | 结果 |
|---|---|
| 点遮罩（`.md-scrim @click.self`） | ✅ 能关（直接 `emit('close')`，不经监听器） |
| 点右上 `×` | ✅ 能关（同上） |
| 按 `Esc` | ❌ **毫无反应** |
| 打开时**焦点自动落到面板** | ❌ 没落（同一 watch 里的 `focus()` 也被跳过） |

- `vue-tsc` / `regression` / **`E2E-23`** 全绿：E2E-23 里**明明写了 `await page.keyboard.press('Escape')`**，却**从不断言结果**（只当"顺手关一下"）⇒ 缺陷被漏过。
- 同一写法在 `AiSuggestionDrawer.vue` 里还有一份（`watch(open, …)` 管 `Cmd/Ctrl+Enter`），所以本轮**新加的那个快捷键也是死的**。

**判据（一次性探针，装仪表记录 document 上的 keydown 捕获监听注册数）**：

| 时刻 | keydown 捕获监听（累计 add / remove） | `.md-panel` 可见 | 焦点 |
|---|---|---|---|
| 修复前·开壳后 | add **+0**（监听没注册 —— 见下方补测表） | true | `gs-btn`（**没**聚焦面板） |
| 修复前·按 Esc | add **+0**、remove **+0** | **true（关不掉）** | — |
| 修复后·开壳后 | add 8 → **10**（+2：Esc 一个、`Cmd/Ctrl+Enter` 一个）；remove 2 | true | **`md-panel`**（打开即聚焦） |
| 修复后·按 Esc | add **10 不变**、remove 2 → **4**（-2：随关闭注销） | **false（真关掉）** | 归还给打开它的元素 |
| 修复后·再开 → 点遮罩 | add 10 → 12、remove 4 → 6 | false | — |

> 「add 不变、remove +2」这一对是本条的关键：**只有注册过才谈得上注销** —— 修复前两个计数纹丝不动，正是"监听从未注册"的铁证。

**修法**：两处 `watch(…, { immediate: true })`（`Modal.vue` + `AiSuggestionDrawer.vue`）。`immediate` 在 `open=false` 挂载时是安全的（分支只做 `removeEventListener`）。

**沉淀成门禁**（不再靠人眼）：
1. `regression.cjs` **R161-⑦**（新）—— `Modal.vue` 的 watch 必带 `immediate` + 必含 `focus()`/`restoreTo.focus()`；
2. `regression.cjs` **R161-6**（加固）—— `Cmd/Ctrl+Enter` 的 watch 同样必带 `immediate`；
3. `e2e.cjs` **E2E-23**（加固）—— 断言 `Esc关闭=true`，不再"按了不管"；
4. `theme-audit.cjs`（加固）—— 每张弹窗图收尾判一次"Esc 关掉了吗"，关不掉就**非零退出**。

### 8.7 归档脚本的"浮层串场"：主题之间**只切 hash 不重载**，一条遗留浮层能盖掉 18 张图

同一批归档里，BEFORE 套（V3.2.1 包）的 `apple/notion/raycast` **四个台面图全部"变脏"**：它们与前一主题的截图 md5 各不相同、体积差 5~26KB —— 第一反应会是"本轮把三个台面都改了"。**实际是**：

- 脚本切主题**不整页重载**（`page.goto(base + hash)` 在同一文档内只是 fragment 导航，Vue 是 SPA，**全局浮层不会随路由消失**）；
- 每轮弹窗图收尾按的那次 `Esc`（正是 §8.6 的缺陷）**关不掉** ⇒ 浮层挂着进下一个主题的四个台面图。

**判据**：`apple-settings.png` 与 `apple-ai-modal.png` **md5 完全相同** —— 若没有遗留，这两张（一张是设置页默认态、一张是设置页+弹窗）不可能逐字节相同。这条"同一主题内两张本应不同的图 md5 相同"就是**串场的指纹**。

**修法（三处工具修正 + 一个新工具）**：
1. `closeOverlays()` —— 先 Esc，不灵则点关闭按钮（两代壳 `.md-close` / `.drawer-close` 都试），**进入每个主题前先清场**，每张弹窗图后判一次 Esc（关不掉即非零退出）。
2. `resetView()` —— 截图前**滚动归零**（含 `window` 与所有内部滚动容器）。
3. 同上一步 —— **鼠标挪到左上角空白**，清掉卡片 hover 态（就是它伪造出了 8,140 px 的"差异"）。
4. **新建 `scripts/img-diff.cjs`** —— 逐像素 diff + 差异包围盒 + 可裁出局部放大；因为本轮已实证**`md5sum` 会双向骗人**：同包重采 md5 不同但**逐像素 0 差异**（纯 PNG 编码抖动），真差异却必须能落到像素与位置。

**为什么必须兜底点按钮**：旧包（V3.2.1）本来就有 §8.6 那个缺陷，不兜底就拿不到一份干净的 before 对照 —— 而"证据必须干净"比"证明旧包有 bug"更重要（旧包的 bug 另在 §8.6 记账）。

**通用教训**：跑视觉对照前先问一句"**这份图里有没有不属于被测对象的东西**"。本轮如果只看"md5 不同 ⇒ 有改动"，会得出完全错误的结论（把工具的视角残留当成产品回归）；三次修正后 before/after 的台面图是 **16/16 逐字节相同**，这才配当"本轮没动台面"的证据。
