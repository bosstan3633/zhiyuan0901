## 一、问题：同一个开关，在方向台上出现了三次

方向台此前长这样（简化）：

```
┌ 方向台 · 主航线与项目全景                        [完整方向树] ┐
├─ 主航线 ────────────────────────────────┐
│                    👁 已完成项目：显示   完整方向树 → │  ← 开关 ①
└────────────────────────────────────────┘
├─ 项目总览 ──────────────────────────────┐
│ 12 项目 · 2 主攻 · 3 已完成  👁 已完成项目：显示  ＋新建 │  ← 开关 ②
└────────────────────────────────────────┘
（完整方向树独立页还有开关 ③）
```

**三个问题：**

1. **同一个偏好，三个开关。** 它们改的是**同一个值**（`UIPrefs.showDoneProjects`），却各自摆了一个入口——看起来像"各自管各自的"，实际上切任意一个，三个地方一起变。
2. **而且它们是三份逐字重复的代码。** 三个组件里各写了一份 `showDone` + `toggleShowDone`，**一字不差**。
3. **两个模块都没说清自己是干什么的。** 主航线叫"主航线"，项目总览叫"项目总览"——用户不知道哪个是用来看的、哪个是用来动手的。R85 已经把**行为**边界立住了（主航线只做一键级预置、管理类导流），但**用户看不见**这个边界。

顺带：项目总览**没有搜索也没有筛选**。项目一多，只能靠眼睛在网格里找。

### D-B · 项目总览检索

- **>12 才出现**（`OV_TOOLS_MIN = 12`，原文）——≤12 个项目一屏看得完，搜索框是噪音；
- 搜索同时匹配**项目名 + 所属战略目标名**（`goalNameOf` 已存在）；
- 状态筛选 `全部 / 进行中 / 停滞 / 已完成`，判定**全部复用 `isProjectStalled` / `isProjectDone`**，不自己写；
- ★ **性能**：这两个函数内部都遍历 `d.tasks` ⇒ 预计算成 `projState` 索引（R83 红线），由 `R86-7` 把守；
- ⚠ **筛选不绕过全局 `showDone` 开关**：开关设为"隐藏已完成"时，筛「已完成」会得到空结果——此时**直接说明原因并给一键「显示已完成」**，而不是偷偷放行。口径只有一套；
- 搜索/筛选是**本地视图态**（组件 `ref`），**不进 `UIPrefs`**：刷新即重置，避免"上次筛了停滞，今天进来以为项目丢了"。

## 附：本轮的两条经验

1. **收敛"多个入口"之前，先收敛"多份实现"。** 本轮若是直接删两个 UI 开关，剩下的那份实现会继续以"两处"或"三处"的形式存在。先抽共享函数，收敛才是真的收敛——**UI 只是表象，实现才是本体**。
2. ⚠ **新坑：`regression.cjs` 的 `stripComments` / `segOf` / `fnBody` 定义在文件中后部（约 1779 行）**，前面的断言调用它们会触发 **TDZ**（`Cannot access 'stripComments' before initialization`）。本轮 `R49-14` / `R57-11` 就因此各红一次。**前面的断言要么不用这些工具，要么把工具定义移到文件顶部。** 已记进技能。
3. **scoped 样式的跨组件坑**：`.mod-role` 定义在 `CompassShell`，**管不到子组件 `LighthousePanel` 的模板**。本项目用 `:deep(.mod-role)` 一份定义覆盖两处（不写两份，避免以后改一处忘另一处）。
