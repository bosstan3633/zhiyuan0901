# 交付说明 · R4-a —— 迁移报告卡与整库回退出口（未升版 V3.7.1 之后）

日期：2026-09-30 · 基线：`25b5a40`（V3.7.1 发版）· 触发：五轮计划盘点结论 —— **R1 数据地基「有原语、无出口」是风险最高、工作量最小的一条，先做它。**

## 一、问题

V3.7.0（R179）落了两个不可逆迁移（hub 分类树 → 两级标签树、台内卡收编入池），配套写了备份、报告、回退三件原语，但**一件都没接到界面上**：

- `zy_cats_migrate_report_v1` 只写不读（`models` 注释还写着「供设置页展示」）；
- `restoreMigrateBackup()` / `readMigrateBackup()` **全库零调用方**（`poolMigration.ts:21-22` 自证）；
- 结果：用户库里那份迁移报告看不见、下载不了、回退不了 —— 一次改数据模型的迁移，出问题时唯一的路是手工改 storage。

## 二、落地明细

1. **迁移报告卡**（新组件 `v2/src/newtab/components/MigrateReportCard.vue`，挂在设置页「标签管理」顶部）：迁移时间 / 一级→父标签数 / 二级→子标签数 / 三四级拍平数 / 打标卡片数 / 新增标签次数 + **逐条映射清单可展开**（`catId · 原路径 → 落库标签 · 去向`）+ 备份时间与备份内卡数。
2. **三个出口**：⬇ 下载迁移前备份（JSON）· ↺ 回退到迁移前（整库覆盖）· ▶ 重新执行迁移。
3. **回退的确认口径按全站红线**：`useConfirm` 报数 —— 备份时间、迁移前资源卡数 vs 当前资源卡数与任务数，明说「迁移之后的改动会一并丢掉」，并提示先下载当前数据。
4. **★回退必须"停得住"**（这条是本轮真正的技术内容）：两个迁移是**幂等落戳**的，`restoreMigrateBackup` 把 `catsMigratedAt`/`boardCardsPooledAt` 清掉之后，**下次启动会原样再迁一遍** —— 回退只活一次刷新，等于没有回退。所以：
   - 新增独立开关键 `K.MIGRATE_OPTOUT`（`zy_migrate_optout`，不进主 JSON、不进导出/备份链）；
   - 回退时 `setMigrateOptOut(true)`，`stores/app.ts` 启动期先 `hasMigrateOptOut()`，为真即**跳过整段池迁移**（含写备份）；
   - 「重新执行迁移」解除开关并刷新，让幂等迁移按同一口径重跑；
   - 卡片在停用态显式挂「迁移已停用（回退态）」徽标，状态可见不是暗箱。
5. **组件化的原因**：这张卡最初直接写进 `GlobalSettings.vue`，被自家增长门禁 **R164-2（GS ≤3,560 行）** 拦红。按该门禁的既有处置方式（R172-T8/T9 就是把记录条与筛选迁成组件后**收紧**上限）**抽成独立组件，不放宽上限**。

## 三、断言与门禁

- 新增 2 条：R4-a 出口三件（读两键 + 出卡 + `restoreMigrateBackup` 不再是零调用方 + 宿主挂载 `<MigrateReportCard />`）、R4-a 回退停得住（`MIGRATE_OPTOUT` 键 + `setMigrateOptOut/hasMigrateOptOut` + `app.ts` 的 `if (!poolOptOut)` 守卫 + UI 双向解除）。
- **E2E 新增 E2E-28**：种迁移前备份与报告 → 设置页出卡（统计含 257、映射清单按钮在位）→ 点回退（确认框出现「整库覆盖」）→ 断言 `zy_migrate_optout` 落、`zy_cats_migrate_report_v1` 清、停用徽标显 → 点重新执行迁移 → 断言开关解除。
- 本轮踩到并修掉的自身错误：① 模板替换时误删「标签树」卡的 `<div class="gs-card">` 开标签 —— 由 **R161-⑥ SFC 结构自检**抓住（`vue-tsc` 不报，这条门禁又一次自证价值）；② 组件化后类名从 `gs-mg-*` 改 `mg-*`，断言与 e2e 选择器各有一处没跟上（`migrateReport.mapping`、`.gs-mg-stats`），当场改正。

## 四、边界（如实）

1. **回退是整库覆盖**，不是"只撤销标签迁移"——备份点之后的所有改动一并丢。确认框已把这句话和两边卡数摆出来；不做增量回退（那需要三方合并，属另一件事）。
2. **备份键本身不被回退清除**，所以可以反复回退/重跑；只有新的迁移发生才会重写它。
3. **「无标签治理视图」不在本轮**：它与轮次 C 的「待打标」筛选是同一个能力，放池面板更顺手，已并入 C 的范围。
4. 真机复核建议：设置 → 标签管理，看这张卡在你真实库上的数字是否与 R179 交付说明记的那份报告一致（一级 7 / 二级 20 / 拍平 3 / 打标 257）。
