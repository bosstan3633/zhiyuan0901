## 一、逐项落地明细

`PoolCardsPanel.vue`（R2-③ 建的 100 行骨架）本轮升成真正的池卡管理面：

1. **控制行四件套**：搜索（原有）+ **＋ 新建卡** + **📥 导入本地文件** + **批量** + 计数（`当前 / 全部 N 张`）。
2. **新建单卡**：轻量浮层（标题必填 / 链接可选 / 标签逗号分隔），`v-if` 不开即零节点（全站浮层纪律）。语义守池不变量——新卡 `workspaceId=CURATION_WS_ID`、`categoryId` 留空（R179 起标签独任组织）、id 走 `uid('rc')`；**绝不再产出台内资源卡**（R1.5 修过的那类违规不在此复现）。浮层底部明写「采集仍走 Ctrl+Shift+J（带网页上下文）」，不抢采集的主入口地位。
3. **本地文件导入入口重落**：R179 把链路 parked 在 `Workspace.vue:673`（注释写明「本地文件导入迁调度台 3张卡」），本轮按既定去向落进池面板控制行。实现**不复制一份**——池面板以 `useWorkspaceImport({ workspaceId: computed(() => CURATION_WS_ID), newCardCatId: () => '' })` 复用同一条链路（一文件一卡、本体入 IndexedDB、不支持类型跳过并汇总、`accept` 串逐字照旧）；Workspace 侧的 `fileImportInput` 与两个绑定撤除（书签那条仍 parked，未动）。
4. **批量**：选择态下点卡=勾选（`picked` 描边）→ 全选本池 → **加标签（只加不减）** / **删除（软删带撤销）**。口径：去标签仍回卡详情，面板里不另立第二套标签编辑；批量删除不弹确认（全站「软删即时可撤销、硬删逐次确认」）。
5. **增量渲染上限**：默认一屏 60 张，滚动到底 `IntersectionObserver`（rootMargin 240px）自动追加 + 手动「加载更多」兜底；`?hl` 定位时先把目标卡纳入渲染范围（否则分页之外滚不到）。**实测**（真库 260 活卡注入扩展页）：首屏 DOM 节点 **3,050 → 1,264（−59%）**、渲染卡数 260 → 60、导航→池面板可见 **449ms → 410ms**、longtask 仍 0。上一轮「当前库容不触红线、上限先量再立」的判停口径，这轮按量到的数字把闸门装上，不等它变慢。
