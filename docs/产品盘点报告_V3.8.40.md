## 一、从内涵与精神出发:产品是什么、守住了什么

### 1.1 产品内核(源自《00_产品事实与表达母版》)

| 层 | 内容 |
|---|---|
| 名称 | 知源调度台 / **Ownway**(Own + Way,走自己的路:数据归自己、判断归自己、节奏归自己) |
| 品类 | **你在浏览器里的个人调度中台**——不是书签管理器、不是笔记、不是待办、不是新标签页美化 |
| 主 Slogan | 万千可调用,自有我方向 |

### 1.3 一个需要警惕的信号

**母版已停更**(§15 自记:"V3.3 → V3.7.1 期间的变更以交付说明与任务书为准")。母版是"最高事实源",但它的版本记录停在 V3.8.0,正文口径停在更早。本批盘点已发现三处"文档/判据指向已不存在之物"(见 §六),母版与实装的漂移是同一类风险的文档版。**建议:要么一次性回正母版,要么正式把它降级为"历史册"并把事实源迁移到代码守卫能覆盖的地方。**


### 3.2 架构强项

1. **单一来源纪律执行到位**:字阶令牌、快捷键清单、分类树索引(`catIndex`)、上限常量(`catTree`)都是"一份定义、多处派生",且有判据把守防第二份出现。
2. **存储边界干净**:主数据 / 界面偏好 / 事件日志 / 附件 / AI 凭证五把钥匙各管各的,凭证天然不进备份链。
3. **加载期归一化层**(B35 `fixTags` 范式):字段缺省/旧结构在 `loadData` 统一兜底,不写迁移戳、幂等。本批刚用它修掉三个老库崩溃。
4. **拆分方法论已验证**:Workspace.vue 五批拆分(3583→1439 行)证明"实现随迁、绑定留宿主 + 断言归位"模式可行,剩余大文件照此办理即可。

## 七、风险与债务清单(按严重度)

### P0-1 · 孤儿代码造成"死 CSS 假绿"(本批刚证实)

`src/newtab/components/dashboard/` 下 **ReviewPanel.vue / DrillCardList.vue / ReviewReportModal.vue 三个组件全库零挂载**(随 W13-D5 退役,产品侧已明文下线),但它们的 class 字面量仍在 `dashboard.css` 与 census 字典里 ⇒ **死 CSS 扫描的 0/0 是假绿**。V3.8.40 只下线了量它们的判据(`RETIRED_DASH_SCENES`),**组件与样式本体未删**。
**风险**:下一批任何人都会继续以为这些样式有宿主;census 字典是历史快照,同类孤儿会越攒越多。

### P0-2 · 老库兼容是"发现一个补一个"的暗线

V3.8.40 在真实老库上连炸三个崩溃(`status` 缺失 ×2 + `question` 字段不存在),根因是**字段改名发生在模型定型之前,类型声明与测试夹具全是新结构,老库不在任何夹具里** ⇒ 静态门禁结构上抓不到。本批补了 `status/priority/title→question/desc→description/done→status/dueAt→dueDate`,但**这是逐案补的,不是系统体检**。下一个缺字段(比如 `order`、`createdAt`、`categoryId`)还会以同样方式炸。
**风险**:每一个使用多年、导过 JSON、手改备份的老用户都是潜在受害者,而他们恰是最忠诚的用户。

### P0-3 · `GlobalSettings.vue` 2,922 行

超验收线 95%,且仍在生长(每个新设置项都往这里塞)。六个子域各有判据分片守着,拆分有成熟模式可抄,是"确定能做完"的债。

### P1 · 文档事实源漂移

母版停更(§1.3);此外 README/手册/白皮书各自有版本锚守着,但**叙事性内容**(产品综述、认知基线)没有守卫,靠人工记得更新。

### P2 · 冷启动感知、商业化准备、Web Store 上架

冷启动 ~800ms(感知优化空间);买断制"规划中"尚无 license 方案;目前只能开发者模式安装,**分发半径 = 会装开发版扩展的人**——这是增长天花板,不是技术债,但属于"产品现状"必须摆上桌的事实。
