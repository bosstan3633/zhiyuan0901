## 一、交付结论

V4.2.5 是云同步热修复版本，修复 V4.2.4 三方合并在没有共同基线、且同一记录两端缺少不同派生字段时，把内部缺失占位符合并进 `Number()` 的问题。修复后不再出现 `Cannot convert a Symbol value to a number`，首次同步可以正常完成合并预览、冲突判断与上传。

## 二、问题与根因

- 现象：同步入口显示 `Cannot convert a Symbol value to a number`，随后顶部同步状态显示断线；再次点击同步时才可能恢复。
- 根因：三方合并器用内部 `Symbol` 表示“字段不存在”。在处理 `createdAt`、`updatedAt`、`callCount` 等派生字段时，旧实现直接执行 `Number(local)` / `Number(remote)`；任意一侧字段缺失时，`Number(Symbol)` 立即抛错。
- 触发条件：首次同步或共同基线尚未建立；同一记录两端字段结构不完全一致，例如一侧有 `createdAt`、另一侧缺失。

## 三、修复内容

- 新增有限数字读取边界：只接受有效数字或数字字符串，不再对缺失占位符或其他类型调用 `Number()`。
- 派生字段合并改为“保留可用值”：一端缺失时使用另一端有效值；两端都有值时，时间字段取安全极值，计数字段取较大值。
- `tagTreeRevision` 归一化也走同一数值边界，避免异常数据再次触发同类转换错误。
- 三方合并的冲突判定、删除 / 修改保护和共同基线逻辑保持不变。
- 新增 V4.2.5 专项回归，覆盖一端缺 `createdAt`、两端缺不同派生字段以及源码直接数值转换负锚。
