### ④ AI 入口图标统一（布局一致 · 大小一致）

**回源码取到的三个真问题**：

1. **大小**：24 处调用点的 `size` 散成 **12 / 13 / 14 / 17** 四档，而同排兄弟动作是 11px 字形——根因是旧徽标**靠 emoji 的 `font-size` 控大小**，在同一个 20×20 盒里实测差 **27%**（"AI 图标看着总比旁边大一圈"）。
2. **不可着色**：emoji 是彩色字形，`color` 无效 ⇒ R156 accent 解禁后无法随主题变化。
3. **描边不可控**：粗细由系统字体决定，Windows / macOS 观感不一致。

**做法**（两件，刻意分开）：

- `ZhiMark.vue` **换骨**：`<span style="font-size:Npx">🤖</span>` → **inline 单色线性 SVG**（`viewBox` + `stroke="currentColor"` + `stroke-width="2"`，尺寸由 `width/height` 属性精确控制）。图形保留 R146~R152 三轮比稿的结论——**"脸"仍是可辨性最高的符号**，只把彩色 emoji 换成单色线性画法。
- 新增 `AiEntryButton.vue`（**全站 AI 入口唯一落点**）：`icon` / `inline` 两态，尺寸**只认 `--icon-sm` / `--icon-lg`**、图标—文案点距唯一值 `5px`。**职责边界：只管徽标与文案的对齐与间距，不接管宿主外框**——背景 / 边框 / hover 仍是各处的角色语义（主行动 / 次级 / 批量），不该被统一掉。

**收敛结果**：**24 处调用点 / 34 处替换 / 15 文件**全量改走 `AiEntryButton`；业务 `.vue` 零直挂 `ZhiMark`、零给徽标写死尺寸。`<ThesisAiBtn>` 自带的 `1px dashed` 虚线框保留（它是"策展台头部主行动"的角色语义，不是 AI 入口的通用形态）。

## 六、性能（medium 档 · 同机零移动 A/B · M14 系各 4 样本）

### 6.1 先记踩到的坑（否则下面的数字不可信）

第一轮 A/B 用的是"`mv` 换 `dist` 目录名"的老办法，结果 R154 与 R155 的读数**一字不差**（M14 / M1 / M2a 连 0.1ms 都相同），据此一度写了"R155 零性能影响"。**这个结论是假的**，真因链：

1. `mv dist dist_old_r154` 时 `dist_old_r154` **已存在** ⇒ `mv` 把 `dist` **整体嵌进去**，成了 `dist_old_r154/dist/`；
2. 磁盘上的 `dist` 随即只剩 **41 文件**（正常 **99 文件 / 37 map / 6.41M**）——缺各视图的 CSS/JS chunk；
3. 包不完整 ⇒ 扩展**整体加载失败**（`ctx.serviceWorkers()` 返 **0**）；
4. `perf.cjs` 抛错，而调用方用 `>/dev/null 2>&1` **把错误吞了**；
5. 于是 `require('.perf-report.json')` 读到的是**上一轮残留报告**——两版自然一模一样。

**决定性证据**：给 `perf.cjs` 加"构建自证"（从 service worker 回读 `chrome.runtime.getManifest().version` 写进报告 `build` 字段）后，立刻暴露"磁盘 `dist` 已是 3.2.0，实测构建却是 3.1.9"。

**留在库里的修复（三条，长期有效）**：

| 改动 | 作用 |
|---|---|
| `perf.cjs` 新增 **`--dist=<绝对目录>`** | 同机 A/B 全程**零移动**，不再有破坏性动作 |
| `perf.cjs` **开跑即删旧报告** | 报告是"本次真跑完了"的证据，不是"上次跑过"的缓存 |
| 报告新增 **`build`** 字段 + `M14b_资源台svg元素数` / `M14c_资源台AI徽标数` | ① 自证测的是哪个包 ② 让 M14 的涨跌**可归因**，而不是"节点多了=变卡了" |

### 6.3 +503 的归因（回源码 + 计量互证，不是"卡变高所以重了"）

- **主因 = 徽标换骨**：`ZhiMark.vue` 从 `<span>🤖</span>`（**1 个元素**）换成 inline SVG（**`<svg>` + 6 个子元素**：天线圆 / 天线杆 / 头 / 双眼 / 嘴）。R154 → R155 的 svg 数 **12 → 95**（+83），恰好等于卡面 AI 徽标数 83 ⇒ **83 × 6 = 498**。
- **余量 5** = 3 处 `inline` 变体入口新增的 `.ai-entry` 包装与其文案 `<span>`（数量 83 → 86 印证）。
- **498 + 5 = 503**，与实测**逐数对上**。这是**有意的结构代价**：换来`currentColor`随主题着色（R156 accent 解禁的前置）、尺寸精确可控、跨平台描边一致。

> **★ 顺手证伪了 04-63 的一处预判**：任务书原写"卡变高 ⇒ 一屏卡数下降，RENDER_STEP 80 是否需同步降"。实测 **M14 卡片数 80 两版完全相同**——变高改变的是**视口内可见张数与滚动长度**，而 M14 数的是**已渲染的卡元素数**。故 R160 **不需要**因本轮去动 `RENDER_STEP`。（节点上涨与卡高无关，是图标换骨。）

### 6.4 本轮性能账

- **结论**：**无观测到的性能劣化**；M14 +503 为图标换骨的确定结构代价，交互指标（M1 / M2a / 帧）与上一版同档。
