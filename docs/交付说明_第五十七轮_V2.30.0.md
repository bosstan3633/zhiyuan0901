## 一、F1 · 策展卡片拖拽根因修复（Bug，根因实锤）

- **根因定位（headless + 有头双环境实证）**：策展中心**原生卡与投射卡模板用的是裸 `draggable` 属性** → Vue 渲染为 `draggable=""`，而 DOM 枚举属性空串是非法值 → 按 auto 处理 → **div 根本不可拖**。dist 产物 `draggable:""` 实锤。旁证闭环：live 源卡/树节点/工作台卡此前都写的 `draggable="true"`（合法）——所以「工作台能拖、源卡能拖，唯独新建卡和镜像投射卡不能拖」，与谭老板反馈逐字吻合。此前的合成 DragEvent 测试绕过了 draggable 检查，造成连续多轮假通过（Playwright 真实鼠标拖拽零 drag 事件即此因）。
- **修复**：两处 `draggable` → `draggable="true"`。现在新建卡、镜像投射卡、未投射源卡全部可拖，与原生分类树、混排网格自由互拖（树节点落卡、卡对卡落位、拖动即物化全链路）。
- **顺手强化**（真实 Chrome 拖拽鲁棒性）：① 全部 dragstart 统一 `effectAllowed='move'`；② 接受拖入的 dragover 统一走 `acceptDragOver`（preventDefault + `dropEffect='move'`，杜绝「不可落」光标）；③ **新增区域级落卡**——拖到当前分类网格任意空白处即移入当前分类（镜像分类下拖未投射源卡 = 物化垫后追加，PENDING 仅收投射卡），不再必须瞄准小卡片；④ 卡片级 `@drop` 补 `.stop` 防止与区域级双落。

## 六、排障记录（3 条，透明留档）

1. **合成事件假通过的教训**：连续三轮策展拖拽的自动化验证用 `new DragEvent()` 派发，绕过了浏览器的 draggable 属性检查——E2E 此后固定先断言 `getAttribute('draggable')==='true'`（E2E-18），再做链路模拟。
2. **E2E-18 首版被「刷新回调度台」白名单重定向**：seed 后 reload `/curation` 被拉回首页致断言全空——改为免 reload 流程（外部写 storage → storage.onChanged 同步运行中的应用 → hash 导航）。
3. **真实拖拽无法在无头环境自动化**：Playwright 鼠标拖拽（headless/headed 均试）不触发 Chromium 原生 DnD 会话（零 drag 事件）——可拖性由属性真值断言兜住，拖拽手势本身列入真机复核。
