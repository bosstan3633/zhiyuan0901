# V4.3.0 交付说明

> 版本：V4.3.0
>
> 日期：2026-11-13
>
> 基线：V4.2.5（`main` / `e4fc9e3` / 标签 `v4.2.5`）

## 一、交付结论

V4.3.0 完成两条主线调整：

1. 今天、本周、本月、本年统一改为 AI 周期复盘。AI 读取当前账号的操作汇总与方向树事实，输出洞察、风险解释和只读导航建议，不再替用户自动归位或绑卡。
2. 移动端采集 PWA 与 PC Inbox 整体退役。产品重新聚焦浏览器扩展内的“采集—调度—策展”，同时保留两代历史采集字段的兼容去重。

## 二、AI 周期复盘

- 四周期共用 `PiAiReview`，不再各自维护一套进度、结果与错误状态。
- 本地事实包由 `periodReview` 统一构建，覆盖：
  - 账号级跨设备操作汇总；
  - 今日战报与周期活跃度；
  - 方向、项目、成功指标与未归档任务；
  - 策展台、论证节点与资源状态。
- AI 输出固定为“洞察、偏离、下一步建议”三类。
- 建议只生成导航动作，不提供采纳写库入口。
- 允许跳转的目标 id 必须来自白名单；无效目标被清除，不产生死链。
- AI 未配置、请求失败、结果解析失败时显示本地事实基线，不伪装成功。

## 三、移动采集与 PC Inbox 退役

- 物理删除移动端 PWA 源码、构建配置、静态资源、移动专用图标和 GitHub Pages 工作流。
- 物理删除 PC Inbox 列表、采集抽屉、角标与数据 composable。
- 调度台“手边的卡”只保留任务、好奇心、资源三池，任务为默认池。
- 旧 `/deck/inbox` 深链统一回到调度台首页。
- 云端请求与性能探针不再访问 `capture_inbox`。
- Supabase `capture_inbox` 表保留为历史备案，供旧账号数据追溯，不再由产品调用。

## 四、历史采集兼容

- 新数据继续读取 `sourceCaptureId`。
- 旧导入数据继续读取 `customFields.captureInboxId` 与 `customFields.capture_inbox_id`。
- 同一 capture id 的旧、新记录在启动、云恢复与导入时合并。
- 合并保留带链接、标签、描述和附件的一方，重复记录软删进回收站。
- 常用夹、任务支持、策展投射、愿景与使命引用同步迁移到保留卡。

## 六、事实边界

- 移动端采集与 PC Inbox 已按产品决定退役，本轮不保留新入口。
- AI 周期复盘未连接真实付费模型做质量评测，自动化只验证输入事实、只读边界、白名单和失败降级。

- 云端历史 `capture_inbox` 数据不会自动删除；产品停止访问后，旧数据只能通过 Supabase 控制台追溯。
- 性能与视觉数据只代表本机桌面 Chromium。
