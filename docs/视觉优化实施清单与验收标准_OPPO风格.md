# 知源整体视觉优化实施清单与验收标准

> 基线：V4.7.6。范围：知源品牌区（画像洞察页）、调度台、方向台、策展台、设置页，以及支撑这些页面的全局视觉基座。目标是贯彻 OPPO 官网“易简、舒适、流畅”的设计气质，同时保持知源作为高频认知调度工具的信息效率。V4.7.6 起主行动色统一为**知源 Logo 蓝**，OPPO 只保留材质、圆角、留白与结构语言。

## 1. 目标与边界

### 目标

- 让用户进入每个页面后，能快速看出当前页面的主要任务、当前位置和下一步操作。
- 让五个台面共享一致的排版、表面层级、圆角、边线、阴影和交互反馈。
- 用留白突出内容重点；让任务、树、时间轴和画布保留适合工作的信息密度。
- 让视觉细节在四套正式主题（光速黑、极简白、纸墨白、知源蓝）下都清晰、协调。
- 保持启动、检索、筛选、滚动、拖拽和弹层操作流畅；视觉改造不能引入可感知的响应退化。

### 实施边界

- 以共享令牌和现有组件为主，先统一规则，再逐台面修整；避免五个页面各自发明一套样式。
- 只使用 `tokens.css` 语义令牌，不在业务组件新增硬编码色值。
- 保留当前四套主题及用户的主题选择。OPPO 风格作为共同的结构与质感语言，`oppo` 主题 ID 保留但界面名改为「知源蓝」；四套主题主行动色统一为 Logo 蓝阶。
- 不改业务数据模型、同步边界和卡片归属规则；交互行为只有在对应工作项明确列出时才调整。
- 不增加运行时依赖、图片背景、大面积模糊或全页动画；路由切换保持即时。

## 2. 全局视觉规则

| 项目 | 实施口径 | 验收标准 |
|---|---|---|
| 页面层级 | 统一为页面底、内容面、浮层三种主要表面；用留白和排版做第一层区分。 | 普通内容不出现多层卡片套卡片；抽屉、菜单、弹窗与页面内容有明确前后关系。 |
| 背景与颜色 | 低饱和中性底色承载长时间阅读；主题强调色集中用于主行动、选中态和少数关键进度。 | 同一视图内主要强调色不泛滥；状态仍可通过文字、图标或形状识别，不只靠颜色区分。 |
| 圆角 | 收敛使用现有圆角阶：大面板、内容卡、控件、标签各有固定映射；胶囊形仅保留给语义确实需要的页签或状态。 | 同层组件圆角一致；页面内不同时出现大量相近但不一致的圆角值。 |
| 边线 | 以低对比发丝线表达分组、列边界和树关系；可交互元素的边界比纯分隔线更清楚。 | 每条线都能说明结构或交互；无意义的重复描边被移除；四主题下边界可辨。 |
| 阴影 | 普通卡片主要靠底色、间距和边线分层；阴影用于抽屉、菜单、弹窗和少量需要抬升的主面板。 | 不为每张卡片叠加阴影；阴影层级不互相竞争；悬停不引起明显跳动或布局位移。 |
| 间距 | 使用现有 4px 基准间距阶；页级留白、模块间距、卡内间距分别固定到有限档位。 | 同类模块间距一致；高频列表不因扩大卡片间距而降低可见信息量。 |
| 文字 | 按页面标题、模块标题、正文、辅助信息、微型标签建立固定字号和字重角色。 | 正文与任务标题在目标分辨率清楚可读；辅助文字与正文层级明确；重要信息不依赖极小字。 |
| 交互态 | 统一默认、悬停、按下、选中、键盘焦点、禁用、加载、成功和错误状态。 | 键盘焦点始终可见；悬停不是识别操作的唯一方式；图标按钮有可读名称和足够点击区域。 |
| 动效 | 只为操作反馈使用短时过渡，建议落在 120–180ms；尊重减少动态效果设置。 | 不增加路由过场；打开、关闭、切换和保存无明显迟滞；连续快速操作不会排队播放装饰动画。 |

## 3. 分模块开发清单与验收标准

### A. 全局框架与视觉基座

**主要位置**：`v2/src/shared/styles/tokens.css`、`v2/src/newtab/App.vue`，以及各页面共用的导航、按钮、表单、抽屉和弹窗样式。

- [ ] 盘点五个目标页面重复出现的页头、分组标题、按钮、输入框、选择器、标签和浮层。
- [ ] 建立页面底、内容面、浮层的表面映射；把现有圆角、间距、边线、阴影和交互色用法映射到语义令牌。
- [ ] 统一顶栏高度、品牌标识、导航选中态、页面内容起始位置和页面级间距。
- [ ] 统一按钮层级：主要行动、次要行动、文本行动、危险行动；图标按钮提供名称、提示和键盘焦点。
- [ ] 核查四套主题的文字、边线、焦点环、悬停态和禁用态，不让主题切换造成组件几何变化。

**验收**

- 四套主题中，顶栏、页面标题、主行动和内容区位置一致，主题差异仅体现在配色与必要的明暗校准。
- 全局色彩和阴影都经语义令牌驱动；新加样式没有硬编码色值。
- 主要操作与次要操作层级明确；键盘操作能看到焦点，悬停、选中、禁用状态可区分。
- 普通内容面板没有重复套壳；浮层与页面内容的层级清晰。

### B. 知源品牌区／画像洞察页

**主要位置**：`v2/src/newtab/views/ProfileInsights.vue`、`ProfileInsights.css`、`v2/src/newtab/components/profile/PiOverview.vue`、`PiTimeline.vue`、`pi-timeline.css`。

- [ ] 梳理页面页头、产品使用状态、个人方向状态、时间轴／热力图切换和时间轴卡片的视觉顺序。
- [ ] 将个人方向和使用数据组织成易扫读的品牌摘要；保留真实指标，减少重复说明和装饰性字段。
- [ ] 明确时间轴为主要浏览区，摘要区与视图切换控制不挤占时间轴首屏空间。
- [ ] 统一时间轴日期锚点、卡片密度、卡片选中态、类型标识和详情抽屉入口。
- [ ] 检查空数据、长标题、标签多、抽屉打开和时间轴筛选等状态。

**验收**

- 1440×900 首屏能看到页面身份、方向／使用摘要、时间轴控制和至少一张时间轴卡片。
- 个人方向是页面可辨识的主线，产品统计是辅助信息；用户能快速分清“我在关注什么”和“我最近做了什么”。
- 时间轴卡片的标题、类型、状态和时间有稳定阅读顺序；点击与双击的视觉反馈明确。
- 摘要区压缩后不隐藏关键指标，也不使说明文字难以阅读。

### C. 调度台

**主要位置**：`v2/src/newtab/views/CompassHome.vue`、`CompassHome.css`、`v2/src/newtab/components/compass/DeckControls.vue`、`HomeResourceFolderGrid.vue`，以及今日行动和卡池视图组件。

- [ ] 固定页面标题、日期、今日三件事、卡片池之间的层级；今日行动成为首要视觉焦点。
- [ ] 统一四类卡池的页签、检索、筛选、排序、分组和视图切换控制条。
- [ ] 对齐今日任务卡的标题、项目／指标、状态、完成操作和辅助操作；长标题换行时保持卡片结构稳定。
- [ ] 统一空卡池、无搜索结果、无常用夹和加载状态的空状态设计。
- [ ] 检查桌面宽度变化时筛选区的折行策略与按钮可达性。

**验收**

- 1440×900 首屏能识别“今日三件事”并看到主要行动内容；卡片池不会抢走主行动的视觉优先级。
- 1440px 宽度下，常用卡池控制项在合理行数内完整显示；1280px 和 1024px 下不重叠、不裁切，窄屏按组折行。
- 四类卡池切换时，控制条的位置和操作语义一致；筛选选中态、清除筛选和空结果状态清楚。
- 任务卡长标题、无项目任务和已完成任务均可读，完成操作可见且不误触旁边的次要动作。

### D. 方向台

**主要位置**：`v2/src/newtab/views/CompassTree.vue`、`CompassTree.css`、`v2/src/newtab/views/useCompassTree.ts`、`v2/src/newtab/components/compass/CompassSpine.vue`、`CompassLayerList.vue`、`CompassPano.vue`、`CompassPanoLane.vue`。

- [ ] 明确愿景、使命、战略目标、项目、成功指标、任务六层结构的视觉层级和层间关系。
- [ ] 用缩进、连接线、分组标题和留白表达结构；减少同一屏内重复的卡片边框与背景块。
- [ ] 分别制定方向节点、项目／指标摘要、任务行的密度规则；任务行突出标题和状态，低频操作收在明确入口中。
- [ ] 统一当前层级、选中节点、筛选中、已完成、未归属任务和空分支的状态表达。
- [ ] 检查树视图、项目全景和任务全景之间的视图工具栏与当前上下文提示。

**验收**

- 用户能在 3 秒内判断当前所在层级，以及当前节点属于哪条方向链。
- 六层的父子关系不依赖颜色；缩进和连接线不会在长树、折叠或横向滚动时断裂或歧义。
- 任务标题、状态、完成热区和所属项目／指标在常用窗口下可扫读；行内操作不会遮挡标题。
- 项目全景与任务全景的筛选、空状态、未归属任务和展开／折叠状态清楚一致。
- 键盘可完成展开、选择、编辑和任务操作；焦点位置始终可见。

### E. 策展台

**主要位置**：`v2/src/newtab/views/Workspace.vue`、`ProjectCuration.vue`、`ProjectCuration.css`、`v2/src/newtab/components/curation/CurationMindMap.vue`、`CurationMindNode.vue`、`v2/src/newtab/components/compass/curation/CurationTreeLayout.vue`、`CurationPyramidLayout.vue`。

- [ ] 统一台身份页头、中心论点、全局操作区、画布工具栏和论证画布的分区关系。
- [ ] 突出“中心论点 → 论证节点 → 资源证据”的视觉路径；节点层级由位置、连接线和信息权重共同表达。
- [ ] 区分可编辑、当前选中、拖拽中、镜像资源、无资源和只读节点状态。
- [ ] 将低频快捷键提示收拢到帮助入口或按需展开区域；保留清楚的键盘操作发现方式。
- [ ] 检查缩放、拖拽、节点增删、资源抽屉、分享和导出等交互状态。

**验收**

- 中心论点一眼可见，画布能看出分支及其证据关系；工具栏不会成为画布内的第二个主视觉。
- 画布节点的标题、描述和操作入口在常用缩放下可读；连接线不会与文本和操作控件混淆。
- 鼠标和键盘均能辨认节点选中状态；拖拽中、落点无效和保存反馈明确。
- 帮助提示不长期占据主要画布高度，快捷键仍可被发现且不只依赖悬停。

### F. 设置页

**主要位置**：`v2/src/newtab/views/GlobalSettings.vue`、`v2/src/newtab/views/settings/GlobalSettings.css`、`v2/src/newtab/views/settings/Settings*.vue`。

- [ ] 统一设置左侧分类导航、页面标题／说明、分组面板、字段说明和操作按钮的层级。
- [ ] 将相关设置组织为可扫描的区块；说明文字靠近对应字段，保存／恢复反馈靠近触发操作。
- [ ] 区分普通设置、数据管理、同步、回收站和重置等高影响区域；危险操作使用独立视觉和确认路径。
- [ ] 检查长设置页、产品更新日志、字段编辑器、主题选择、云同步和窄窗口时的导航表现。

**验收**

- 左侧导航始终能识别当前位置；右侧标题、说明和当前设置项有清楚的阅读顺序。
- 普通页面没有不必要的横向滚动；宽窗口不让正文铺得过宽，窄窗口不遮住导航和主要动作。
- 同一类输入、选择器、复选框和按钮的高度、边线、焦点态一致。
- 重置、删除和恢复等高影响操作容易识别，不与普通保存／编辑操作混在同一视觉层级。

## 5. 全局验收门槛

### 视觉验收

- [ ] 五个目标页面均在四套正式主题下实拍；同一页面的信息结构和布局一致，颜色只按主题令牌变化。
- [ ] 截图覆盖 1440×900；对调度台、方向台、策展画布和设置页额外检查 1280×800 与 1024×768。
- [ ] 页面无文字覆盖、控件遮挡、意外横向滚动、不可见焦点、严重截断或主题对比度问题。
- [ ] 每页只有一个清楚的主视觉和主行动；留白用于分组和阅读，不形成无意义空洞。

### 交互与无障碍验收

- [ ] 主要流程可通过键盘完成；焦点顺序合理，焦点环在四套主题下均清楚。
- [ ] 主要按钮、图标按钮、树节点和拖拽控件具有明确名称、状态和操作反馈。
- [ ] 悬停、选中、禁用、加载、成功、错误、空状态均有明确且一致的表现。
- [ ] 路由切换保持即时；动效不妨碍连续点击、快速检索、拖拽和滚动。

### 性能与工程验收

- [ ] 视觉优化前后比较启动、检索输入、筛选切换、时间轴滚动、树展开、画布拖拽和抽屉开合的体感与现有性能读数。
- [ ] 不新增运行时依赖、大面积模糊、重型背景资源或需要持续重绘的装饰效果。
- [ ] 按仓库规则运行构建、静态回归、主题门禁和键盘可达审计；涉及交互／路由改动时运行 E2E。
- [ ] UI 交付保留四主题实拍；环境缺少截图能力时明确记录“视觉未验证”。
- [ ] 新增视觉行为按仓库要求补充回归断言；不删除或放宽既有断言。

## 6. 每个工作项的完成定义

一个视觉工作项只有同时满足以下条件才可标记完成：

1. 对应页面的主要信息层级和操作路径已按清单实现。
2. 1440×900 基准视口及指定窄窗口没有布局、遮挡或可读性问题。
3. 四套主题都完成实拍走查，颜色、边线、阴影和焦点态符合主题语义。
4. 相关交互、键盘操作及空／错误／加载状态均已验收。
5. 必要的构建、回归、E2E、主题和 a11y 门禁已有真实结果记录。
6. 交付说明列出改动范围、截图位置、验证命令、结果和未验证风险。
