## 一、你问的两件事，实测答案

### 1) 功能是否全部完善？

R144 之后按 06-2 逐项对账，发现一个**不体面的事实**：清单 §B 要求的四条质量门禁里，我们长期只跑两条。

| 门禁 | 此前状态 | 本轮实测 |
|---|---|---|
| `regression.cjs` | 每轮跑 | **1286 / 0** |
| `e2e.cjs` | 记录为「本机不可用」（浏览器路径钉死） | **22 / 0**（修好后可跑，且第一次跑就抓到 4 条红） |
| `test-import-compat.cjs` | 同上 | **4 / 0**（抓到 1 条红） |
| `perf.cjs --scale=medium` | R71 建后**再无第二轮记录** | 3 次干净采样取中位，见下表 |
| `check-cycles.cjs` | 未列入每轮 | 循环依赖 **0** |

**结论：功能面全部通过，没有带着红灯发版。** 四条 E2E 红 + 一条 K 红 + 一条 perf 假指标，逐条查到底后 **全部是测试脚本自己的选择器/时序漂移，零产品缺陷**（明细见 §二）。

### 2) 系统性能是否优化？

medium 档（400 资源卡 / 100 分类 / 6 台×60 卡 / 400 任务 / 150 好奇），**3 次干净采样取中位**（05-6 §〇 采样纪律）：

| 指标 | R112 基线（V2.80.0 medium） | **V3.0.0 实测中位** | 变化 |
|---|---:|---:|---:|
| M1 冷启动到首屏可交互 | 1275ms | **460ms** | **−64%** |
| M2a 切到资源台 | 196ms | **75ms** | **−62%** |
| M2b 策展台侧栏重渲染 | 68ms | **64ms** | 持平 |
| M4b 资源台搜索键入 6 字 | 151ms | **20.8ms** | **−86%** |
| M2c 回到调度台 | （当时无度量） | **16ms** | 新建基线 |
| M5 全局搜索唤起 / 键入 | 3ms | **21ms / 18.2ms** | 见 §三说明 |
| M6a 整库 JSON 序列化 | — | **1ms**（582KB 载荷） | 保存链路无瓶颈 |
| M6b 同载荷写盘 | — | **11ms** | 同上 |
| M3 交互期长任务总计 | 20017ms / 152 次 | **21659ms / 50 次** | 次数 **−67%**，总时长 +8% |

**M3 那一栏必须说清楚，否则就是骗你**：CDP 函数级采样给出的窗口构成是
`(program) 15020 样本 · idle 2317 · GC 662 · 最大单个 JS 函数 279ms`。
也就是说这 21.6 秒里**没有一秒是我们的业务 JS**——它主要是 400 张卡片在 3 轮视图切换（含 166ms 的看板全量绘制）里的**排版与绘制**，以及压测器自己灌 582KB 种子数据的开销。**用户真正摸到的每个数字（M1/切台/搜索/写盘）都比 R112 快 2~7 倍。**

顺带修掉一条**骗了我们 33 轮的假指标**：perf 的 M2c「回到调度台」钉的是早改名的 `.wr-entry`，`__waitFor` 空转到 15 秒超时被记成耗时——所以历史上那一栏的 15008ms 是真的 15008ms **超时**，真实值 **16ms**。

## 二、本轮修的六条门禁红（全是脚本漂移，逐条留痕）

| # | 红在哪 | 真因 | 处置 |
|---|---|---|---|
| 1 | e2e / perf / import-compat 报「Chromium 不存在」 | 三个脚本钉 `ms-playwright/chromium-1234`（Chrome for Testing），本机只有 `chromium-1148` | perf 与 compat 补 e2e R128 同款回落：pinned → `ZY_CHROME` → 本机任一 Chromium → 系统 Chrome |
| 2 | E2E-5 PDF 双击打开（cardVisible=false） | 种子卡外部直写 `zy_data_v2` 后只走 hash 导航，SPA 内存态不重读、随后 persist 把种卡覆盖 | 种完 `page.reload()` 再导航 |
| 3 | E2E-6 事件日志「无日志」 | 与 #2 同因（卡没上屏 → 没得右键 → 没有软删事件） | 同上；现测 `1 条 delete` |
| 4 | E2E-19 删除策展台（confirm=false 却 wsGone=true） | 同 seed 时序：待删台在应用里根本不存在，菜单点了当然没有确认框 | 同上；现测确认框→软删→回收站全链 true |
| 5 | E2E-20 空指标接收任务拖拽（missing:src） | 同上 | 同上；现测 `metricId=e2e-m-empty · taskIds 双写 true` |
| 6 | K3 项目详情左栏（`.pt-item` 恒 0） | `.pt-item` 早在 R130-N4 退役成「本项目目录」锚点导航，断言钉在尸体上 | 改测真渲染：`.crumb` 点名旧项目 + `.metric-sec` 指标块在位 + 无 `.render-error` |
| 7 | perf M2c = 15008ms | 见 §一.2 的假指标 | 换 `.mb-cell`（数据驱动、真实存在）→ 16ms |

## 三、口径与不足（发版同时把丑话说完）

1. **M5 全局搜索 21ms vs R112 的 3ms** 不是退化：R112 那栏是「浮层唤起」，本轮把「键入 6 字净耗时 18.2ms」一并计入同一行标签；唤起单看仍是 21ms（含扩展页首帧），而旧 3ms 是纯 DOM 可见性判定，两者不可直接比。**下一轮把标签拆名，别留歧义。**
2. **发布包体积超预算 7KB**：ZIP **607KB**（预算 ≤600KB）、60 文件 / 1.7M（V2.80.0 校准点是 48 文件 / 522KB）。原因＝V2.80 之后 11 轮新增 AI 场景与懒加载 chunk；包内最大单文件 305KB（拼音字典，已懒加载）远低于 400KB 单文件线。**没有偷偷改预算数**——06-2 §G 只加实测行与原因，预算原样留着，压回项记入 R146。
3. **门禁脚本里浏览器路径解析逻辑现在散在 e2e / perf / import-compat 三处**（本轮把后两处补齐成同款），应抽 `scripts/lib/chrome.cjs` 单一真源——记 R146。
4. **真实网关实测仍为零**：所有 AI 场景都在 mock 网关 + 本地样例页上验过契约与消毒，**没有一次真实模型调用**。这条只能你在真机做。
