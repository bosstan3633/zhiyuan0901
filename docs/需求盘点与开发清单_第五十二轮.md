## 二、B 类修复（根因已定位）

### BUG-1 · 写入记录主计数与副行/详情对不上（用户 #1）

**现象**（截图 1）：主数字 4，副行「任务0 · 好奇0 · 资源3」，4 ≠ 3。

**根因**（`CompassHome.vue:75-104`）：
- 主计数 `logTotal = logRaw.length + todayCalled.length`——事件日志**全类型**计数；
- 副行只按 task/curiosity/resource 三类计数；
- 事件日志里还存在**非三卡事件**（如愿景/使命等 compass 更新、以及 update/status-change 类动作），这类事件进了主计数、副行无处安放 → 必然对不上。

**修复**：统一口径为「**当日三卡事件（新增/删除/恢复/清理）+ 三卡调出**」：
- 主计数 = 副行之和（三卡事件 + 三卡调出），非三卡事件**不计数**；
- 抽屉明细中非三卡事件仍可见（灰显「系统」图标），但无计数权重；
- 同步修正 `logSub` 与 `logTotal` 两个 computed，并加回归断言「主计数口径 = 三卡过滤」。

### BUG-2 · 已完成项目显示/隐藏失效 + 完成口径升级（用户 #10）

**根因**（已实证，五处同错）：「已完成项目」开关实际过滤的是 `status === 'archived'`（**已归档**），不是 `done`（已完成）——
- `CompassTree.vue:47`、`CompassShell.vue:34`（项目总览）、`GlobalPopups.vue:410/492`（搜索项目类型）、`LighthousePanel.vue`（主航线）。
- 用户把项目标为「已完成(done)」后切换开关无任何反应——口径从 R49-C6 落地时即错位。

**修复**：
1. `stores/compass.ts` 新增共享口径 `isProjectDone(p)`：
   `p.status === 'done' || p.status === 'archived' ||（p.tasks>0 且全部 done）`（**派生完成**，见拍板 Q4）；
2. 上述**五处过滤全部改用** `showDone || !isProjectDone(p)`，一处定义、五处消费；
3. 派生完成的纯计算零数据写入（不回写 `p.status`），方向树/主航线/项目总览显示统一的「✓ 已完成」徽标；
4. 回归断言：五处过滤字符串断言升级为 `isProjectDone` 引用断言。

### BUG-3 · 策展中心泄漏进「设置—工作台全景」（用户 #8）

**排查结论**：全景树数据源 `panTree = store.workspaces.map(...)`（`GlobalSettings.vue:1226`），而策展中心**不是** Workspace 实体（`CURATION_WS_ID='zy-curation'` 仅作归属标记），代码层面不应出现 → 泄漏路径需真机复现确认（疑似与用户数据中某张卡的 workspaceId 或导入数据有关）。

**修复**（防御式双保险）：
1. 全景树/分类计数/卡片列表（`panTree/panTotalCats/panCards/gResLive`）显式排除 `workspaceId === CURATION_WS_ID` 的分类与卡片；
2. 全仓排查其他工作台枚举点（按工作台导出 CSV、快捷键映射、书签导入目标、标签统计）一并兜底过滤；
3. 回归断言：全景数据源含 `CURATION_WS_ID` 排除逻辑。

### F7 · 策展中心镜像体系升级（用户 #7，本轮最大项）

现状（R50/R51 已有）：单卡投射→待分类 ✅；分类投射→树内镜像分组（仅改名/移出）✅；整工作台投射→**页面级分区，不入树** ✗；原生卡拖入镜像分组**被拒** ✗。

**四项升级**：

**F7-a 整工作台镜像的分类目录入树**
- 工作台投射后，其**全部分类作为镜像分组节点进入策展树**（📡 前缀，挂在工作台镜像节点或树根，见拍板 Q2 结构）；
- 源工作台新增/删除分类实时反映（派生显示，保住「引用式镜像实时同步」语义）；
- 页面级旧分区移除，统一收进树（内容区只渲染树节点对应视图）。

**F7-b 镜像分组自由增删改 + 拖拽排序**
- 改 = 显示名（displayName，已有）；
- 删 = 移出投射（单组）/整工作台取消投射（联动清组）；
- 增 = 在镜像分组下**新建策展子分类**（策展自有分类，挂在镜像分组下，非改源数据）；
- **拖拽排序**：树内拖拽镜像分组与原生分类互排，顺序持久化（`CurationProjection` 新增可选 `order?: number`；工作台派生组用记录内 `catOrder?: ID[]` 顺序表）；
- 镜像分组内卡片拖入/拖出（见 F7-d）。

**F7-c 单卡镜像直达未分类**
- 已有能力确认保留：单卡投射 → 「待分类」组（`targetCatId` 为空）；
- 补充：工作台内右键菜单文案统一为「📡 镜像到策展中心」，落点提示「未分类」。

**F7-d 全部卡片拖拽语义与工作台一致**
- 镜像卡：跨策展分类/镜像分组拖拽 = 改 `targetCatId`（已有）+ 补「拖回待分类」；
- **原生卡可拖入镜像分组**：新增可选字段 `ResourceCard.curCatId`（仅策展中心消费的策展归属；源工作台仍读 `categoryId`，**源数据零影响**，见拍板 Q3）；拖回策展原生分类 = 清 curCatId 写 categoryId；
- 镜像卡可拖入策展原生分类（targetCatId 指向原生分类 id，与拖入镜像分组同机制）；
- 删除镜像分组时组内卡片回落「待分类」；
- 组内卡片排序统一走既有 `curOrder`（原生卡）/投射数组序（镜像卡）；
- 右键菜单/单击详情/双击开链行为不变（R51-F22 保留）。
