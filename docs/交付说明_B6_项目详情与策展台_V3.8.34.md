## 一、这一批在做什么

B5 把两个首页级页面（调度台 / 方向台）的主次收干净了，B6 转向**两个二级页**：项目详情 `/compass/projects` 与策展台 `/workspace/:id`。六项规范原文已逐条提取核对，不引计划文档旧数字。

### W1 · 金字塔树主角强化

- `.pyramid` 加 `background: color-mix(surface 55%, bg)` + `border: 1px solid var(--border)` + `border-radius: var(--radius-xl)`。台头 `.ws-id-head` 本来就没有底色，于是主从变成"有板 / 无板"的一眼分层。

### W2 · 镜像引用可视化

- `.rc-mirror-badge`：删掉 `opacity: .85` + `filter: saturate(.9)`，改为 `color: var(--text-3)`。原来那两个滤镜是"把颜色压下去"，颜色本身仍随主题偏色；改后是真正中性。补 `cursor: help`（它是溯源标识，不是可点按钮）。
- 三视图 tooltip 统一为「**镜像自原资源卡 · 只读，编辑回源处生效**」。原来三处各写一遍「镜像卡 · 源在资源卡池」——只说了从哪来，没说编辑去哪生效。
- **只读合同未动**：镜像卡写动作仍整组拦截（`<template v-if="!isMirrorView(r)">`），镜像分支只留「打开链接 / 定位到源卡」，单击进只读详情（R106）。判据 W2-3 逐条守这四件事。

### W3 · 台头信息行弱化

- `.wsh-summary`（分类数 / 镜像数 / 更新流水）`fs-sub → caption`，颜色仍 `--text-3`。
- 台名 `.wsh-name` 16px **不动**——那是 R123 既有的页头口径，不属本项；本项只降计数行。
- 「更新」入口的 `title="查看最近更新流水"` 与 `openDrill('recent')` 下钻保持（判据 W3-1 点名守住）。

### W5 · 中心论点层级

- `.tb-title`（常驻论点横幅）与 `.py-root-title`（金字塔论点根）14px / `fs-title` → **`--fs-headline`（17px）**。
- accent 左竖条：`.thesis-banner` 与 `.py-root-card` 各加 `inset 3px 0 0 var(--accent)`。
  **用 box-shadow 内画而不是 `border-left`**：这两处卡面本身已有 accent 描边，再加 border 会让左侧描边变成两倍宽（视觉上像双线）。
- **两处都落，而不是只改金字塔**：`.py-root-card` 只在金字塔视图出现，而用户默认看到的是常驻横幅。只改前者等于"多数时候没生效"。

## 六、本批踩的两个坑

### 1. `rule()` 辅助函数的双重转义

新分片里的 `rule(src, sel)` 内部会转义选择器，调用点却写成 `rule(CSS, '\\.pyramid')` ⇒ 正则变成 `\\.pyramid`，规则永远取不到 ⇒ **整片 13 条里 10 条报"规则缺失"**。

值得记的是它的**表现形式**：不是报"断言失败"，而是报"规则缺失"——后者更像"代码还没写"，容易让人以为是判据本身的问题。**教训：自写的取规则辅助函数，第一次用就要先单测一条**（我验证的方式是单独跑一段 node 比对两种写法的返回值），否则失败会以"数据缺失"的面貌出现，排查方向整个跑偏。

### 2. 负判据扫太宽会把正常值判成违规

初版 `B6-负` 写的是「金字塔相关选择器里不得有 `border-radius: Npx`」，结果 `.py-node-lv`（层级徽标 4px）、`.py-node-count`（计数胶囊 99px）、`.py-node-add`（悬浮钮 6px）全部命中——这三个都是正当的小元素圆角。

**已收窄到只守三张卡片**（`.pyramid` / `.py-node` / `.py-card-chip` / `.py-root-card` / `.py-root-empty`）。教训：**判据失信比没有判据更糟**——一条长期误报的断言，久了就没人看它，而它本来能挡住真问题。

### 附：实拍脚本的一次误伤

临时脚本 `shot_b6.cjs` 最初用 `launchPersistentContext('')`，实测那会复用**本机真实 Chrome profile**：我注入的种子被那份真实库覆盖回用户数据，而脚本还会往用户库里写东西。已改为一次性干净 profile `/tmp/zy-b6-fresh`。

顺带查清一件数据层事实：临时造库时若缺 `hubMigratedAt`，启动会跑 R61 资源台迁移，**把策展台连同其卡一起洗进 `id=zy-curation` 的资源台**（实测注入 `b6-ws`，reload 后 storage 里只剩 `["zy-curation"]`）。补上三个迁移戳即恢复。这是既有行为，不是 bug，但任何"造一份临时库"的场景都得记得。
