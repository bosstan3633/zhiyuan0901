# 需求盘点与开发任务 · 顶栏、自动同步、Inbox 与镜像独立

> **状态**：已实现，待发布；发布前以交付说明和最终门禁实测为准
> **基线**：V4.1.3（`main` / `v4.1.3`，发布提交 `104660d`）
> **目标版本**：V4.2.0
> **判断**：本轮包含镜像数据语义重构，不能只做 UI 隐藏；按 V4.2.0 管理迁移与回归风险。

## 一、需求结论

本轮共 18 项功能，分为六组：

1. **顶栏与云同步感知**：减少右上角常驻内容，加入自动同步设置与每小时同步。
2. **Inbox 唯一转化入口**：Inbox 是唯一可从采集内容转成任务、好奇心、资源的池；转化后离开 Inbox。
3. **卡间关系收口**：好奇心不再做 AI 研判或转化；只允许任务卡和策展节点挂载独立的资源卡镜像。
4. **策展台空间与浮层修复**：隐藏台统一收纳、压缩中心论点区、修复“台数据”菜单裁切。
5. **同步回执可操作**：同步完成后，明细行可查看、删除、恢复或回退，并明确处理结果与后续同步状态。
6. **同步历史可追溯**：每次同步都保留可重新打开的入口；批次和单条记录都可逐层查看并继续处理。

## 三、关键产品口径

### 3.1 自动同步

- **默认关闭**。必须登录云端后才允许打开；退出账号时自动暂停但不删除开关偏好。
- 定时器使用 `chrome.alarms`，建议 `periodInMinutes: 60`。浏览器完全关闭时无法保证后台运行；下次打开浏览器后补跑一次。
- Chromium 定时任务可能因节能或系统负载延迟，产品文案使用“约每小时”，不承诺整点精确执行。
- 第一版自动同步只负责“本机改动上传到云端”，不自动拉回远端新版本。
- 自动同步判断顺序：
  1. 云端为空：上传本机快照。
  2. 本机有改动、云端仍停留在本机基线：自动上传。
  3. 本机无改动、云端 revision 已变化：不上传，标记“云端有新版本”。
  4. 本机有改动、云端也有改动：不上传，标记“待人工选择”。
  5. 网络、登录或数据格式异常：不上传，记录失败原因并转为红色或黄色状态。
- 自动同步与手动同步使用同一把互斥锁，防止两个任务同时覆盖。
- 自动同步结果进入现有同步回执，`trigger` 新增 `auto`；最近实际同步明细仍可打开。
- 因后台不能弹冲突确认框，任何不确定状态都遵循“不覆盖、不猜测、只提示”。

### 3.2 Inbox

- Inbox 只展示未转化记录。已转化记录可继续保存在云端用于幂等和追溯，但不再进入 Inbox 的列表、分组与角标。
- 单击一行打开右侧详情；保留双击打开原始链接、Enter / Space 打开链接的既有快捷操作。
- 行内移除任务 / 好奇 / 资源三枚转化按钮、打开链接和删除按钮，减少重复动作。
- 详情编辑字段：
  - 链接采集：标题、URL、备注、标签。
  - 文本采集：标题、正文、备注、标签。
- 转化后关闭详情，列表即时移除该条，Toast 提供“打开已生成的卡”；不得再出现 Inbox 镜像入口。
- 编辑与转化都采用本机先落状态、远端后补写；失败时不丢用户修改，给出可见重试入口。

### 3.3 好奇心

- 好奇心卡不再提供任何 AI “值不值得转任务”研判。
- 好奇心不再转任务、不归档资源；用户需要先判断时，可自行创建任务或资源，但不能从好奇心一键转化。
- 历史 `convertedAt / convertedTo` 仅用于旧数据兼容和回收站读取，不再出现新的转化动作。
- 以下入口必须一并清理：
  - 好奇心页面头部的批量研判。
  - 卡片、列表、看板、详情中的 AI 研判。
  - 详情中的“转任务”“归档资源”。
  - 全局搜索中的好奇心转化菜单。
  - 洞察页“成熟好奇卡批量转任务”。
  - 项目页与手册中的旧转化说明。
- 现有“好奇心转化率”是否保留为历史指标需审核；建议从当前月报默认视图移除，避免一个不再产生的动作长期显示 0%。

### 3.4 资源卡镜像

当前实现是“引用式镜像”：任务与策展节点只保存源资源卡 id，展示时实时读取真身。这无法满足“删任意一端不影响另一端”。

建议将镜像定义为：

- 在任务或策展节点执行挂载时，从资源真身复制一份独立、只读的资源卡镜像。
- 镜像拥有独立 id、独立挂载记录和独立删除状态。
- 源卡后续编辑默认**不自动传播**到已生成镜像；如需更新，由用户主动重新镜像。
- 删除源卡只影响资源卡池中的真身，不级联已生成镜像。
- 删除某个挂载点的镜像，只移除该镜像与当前挂载关系，不影响源卡，也不影响其他任务或策展节点上的镜像。
- 中心论点 L1 是否算“策展台节点”需审核；建议纳入 L1，保持现有“中心论点关联资源”能力。
- 旧 `SupportLink` 与 `CurationProjection` 需要迁移为镜像挂载记录；迁移必须幂等，并保留旧数据读取回退。

### 3.5 顶栏

建议右侧只保留三类入口：

1. **云同步**：状态灯 + 短状态文本，点击打开同步摘要与动作。
2. **搜索**：保留图标按钮。
3. **更多**：收纳主题、设置、备份提醒等低频入口。

本地保存点：

- 正常态不常驻占位。
- 保存中短暂显示“保存中”，失败时保留红色状态点并提供详情。
- 成功保存无需长时间显示，避免与云同步状态混淆。

隐藏台与溢出台合并为“策展台库”：

- 固定在策展台页签区域末端。
- 菜单分“当前显示”“已隐藏”两组。
- 点击名称进入台；眼睛按钮恢复到顶栏。
- 有隐藏台时显示轻量计数徽标；无隐藏台时是否常显需审核。

### 3.6 策展台密度

- 台身份、中心论点、行动条仍保留三层语义，但压缩为更紧的连续区块。
- 论点区默认不铺开资源 chip 和附件缩略图，只显示“关联资源 N / 附件 N”及详情入口。
- 论点标题保持唯一主标题，不再放大字号；桌面目标高度不超过 96px。
- 在 1440×900 下，页首到画布顶部的纵向占用相对 V4.1.3 至少减少 25%。
- 1024 / 768 / 390 三档不得牺牲标题可读性和操作可达性。

### 3.7 同步回执逐行处理

当前回执只保存记录类型、标题、ID、状态和字段名，无法据此恢复业务对象。实现 F17 时必须先补齐本机私有的动作载荷，再开放行内操作；不能只加按钮。

- 动作载荷只保存在当前设备，不进入云端 manifest、不展示令牌、凭据或附件本体。
- 现有“最近 20 次回执”继续保留；动作载荷与轻量回执分离，避免撑大同步元数据。
- 第一版只支持逐行处理，不提供无确认的批量删除或批量回退。
- 支持操作的业务范围：卡片、策展台 / 节点 / 论证、方向台 / 项目 / 指标、今日三件事、任务与策展资源挂载关系。
- `event`、`stats`、`preference`、系统字段配置等记录默认只读；如需特殊动作，必须单独定义，不能套用普通业务对象的删除 / 恢复。
- 每行动作规则：
  - **新增**：提供“删除本机记录”；二次确认后按对象类型软删除，并在回执中标记“已删除”。
  - **删除**：提供“恢复到本机”；使用本机动作载荷重新创建，保留原对象 ID，`updatedAt` 和当前列表排序时间写为恢复时刻，使记录以最新时间呈现；原 `createdAt` 仅作为内部溯源，不伪造创建历史。
  - **修改**：提供“查看字段差异”；若保存了同步前载荷且当前记录指纹仍与回执一致，允许二次确认后“回退到本次同步前”，否则只读并提示记录已再次变化。
- 恢复卡片或节点时，如原父级、分类或挂载主体已被删除，不得丢弃恢复内容；进入明确的待归类 / 未归档安全位置并提示用户。
- 所有动作先改本机并记入待同步变更，不自动覆盖云端。用户可继续点击云同步提交本次处理结果。
- 每次动作前重新校验当前记录指纹；发现并发变化、载荷过期、数据损坏或类型不支持时停止执行，刷新回执并说明原因。
- 点击回执中的任意数据行可打开单条“记录详情”弹窗，展示记录类型、标题、ID、同步方向、变更状态、变更字段、可用的同步前后值、更新时间、动作状态和可执行动作；不能只把操作藏在一枚没有上下文的按钮里。
- 批次回执弹窗最多再打开一层记录详情；390px 视口将记录详情改为全屏抽屉，避免多层弹窗互相遮挡。
- 每行展示动作状态：`可处理 / 已删除 / 已恢复 / 已回退 / 只读 / 已过期 / 冲突`，避免用户重复操作。
- 动作成功后立即刷新当前列表、分组计数和回执统计；回执中的原始摘要不可篡改，另存动作审计结果。
- “本次同步明细”底部说明由“完全不展示正文”改为“只在本机保存恢复所需的最小私有载荷；不同步正文、附件本体、令牌与凭据到云端”。

### 3.8 同步历史

- 云同步状态面板固定提供“同步历史”入口；设置中心云同步页也提供同一入口，不新增常驻顶栏图标。用户已确认：同步历史放在云同步面板 + 设置中心，不额外占用顶栏。
- 历史列表按同步时间倒序，显示时间、手动 / 自动触发、上传 / 拉回 / 已是最新、新增 / 修改 / 删除数量、修订范围和本次动作处理进度。
- 点击一次同步记录打开该批次的“同步明细”弹窗，可继续按现有分组、搜索和正倒序浏览。
- 点击批次中的任一业务记录，打开单条记录详情弹窗；详情中可执行 F17 定义的删除、恢复、差异查看或安全回退。
- 历史与即时回执复用同一个回执 ID、动作载荷和动作审计，不允许两个入口产生不同状态。
- 动作载荷已过期或已被容量清理时，历史批次仍可查看摘要与字段差异，但操作降级为只读并明确说明原因。
- 历史列表为空时展示说明和“完成一次同步后在这里查看”的空态，不展示一条伪造记录。
- 用户已确认：历史默认保留最近 20 次、最长 30 天；动作载荷过期后仍可查看明细，但不能继续操作。

## 五、验收清单

### 5.1 顶栏与同步

- 1440、1024、768、390 四档视口无横向溢出。
- 1440 桌面右上角常驻控件不超过“云同步 / 搜索 / 更多”三个。
- 云同步主按钮能在一眼内区分绿、黄、红和同步中；完整最近同步时间仍可访问。
- 自动同步开关默认关闭；启用后创建 60 分钟 alarm，重复启用不创建重复 alarm。
- 浏览器关闭期间不宣称已同步；重新打开后按已过时间补跑一次。
- 本机改动 + 云端未变时自动上传；远端已变或双端都变时不得覆盖，状态转为待处理。
- 连续触发、手动与自动并发时只允许一个同步任务执行。

### 5.2 Inbox

- 单击未转化 Inbox 行打开右侧详情；双击、Enter、Space 仍打开原始链接。
- 标题、URL / 正文、备注、标签可编辑并回显；离线编辑不丢。
- 三类转化均从详情发起；转化成功后该记录立即从 Inbox 列表和计数消失。
- 已转化记录不再显示为 Inbox 镜像，也不出现在“任务 / 好奇 / 资源”分组中。
- 删除 Inbox 不影响已生成目标卡；删除目标卡也不恢复 Inbox 记录。
- 不重复创建同 URL 的未转化采集。

### 5.3 好奇心

- 全部用户界面零“转化研判”“研判要不要转”“转任务”“归档资源”入口。
- 全局搜索、洞察页和快捷键不得存在好奇心转化动作。
- 增量代码不得调用 `convertToTask` / `convertToResource`；旧数据读取与导出仍正常。

### 5.4 镜像独立性

至少覆盖以下数据测试：

1. 创建资源真身 → 任务挂镜像 → 删除真身 → 任务镜像仍可打开。
2. 创建资源真身 → 策展节点挂镜像 → 彻底删除真身 → 策展镜像仍可打开。
3. 删除任务上的镜像 → 资源真身仍存在，其他镜像仍存在。
4. 删除策展节点上的镜像 → 资源真身仍存在，任务镜像仍存在。
5. 同一资源挂到两个任务和一个策展节点 → 三个镜像可分别删除。
6. 旧 SupportLink / CurationProjection 数据包可幂等迁移，重复启动不重复生成镜像。

### 5.5 策展台

- 隐藏台入口位置稳定，能进入和恢复全部隐藏台。
- 中心论点区在 1440×900 下高度不超过 96px，页首到画布顶部至少减少 25%。
- 资源、附件、读数与论点详情仍全部可达，信息不因压缩而丢失。
- “台数据”菜单在 1440、1024、768、390 四档视口均完整可见，不裁切、不压住画布后失焦。
- 菜单支持 Esc、点击外部关闭和键盘上下移动。

### 5.6 同步回执逐行处理

- 同步完成后打开回执，每条受支持的业务记录都有可见动作；不再出现“显示可恢复但实际无法恢复”的伪入口。
- 点击回执中的任意数据行会打开单条记录详情，再执行操作；不得要求用户仅凭一行摘要盲目点击动作。
- 新增记录执行删除后立即从当前业务列表与回执有效统计中移除，并标记“已删除”。
- 删除记录执行恢复后，原记录 ID 保持不变，出现在对应业务列表中，`updatedAt` 为恢复时刻并排在最新位置。
- 修改记录可查看字段差异；满足载荷与指纹条件时可回退，否则明确显示“记录已再次变化”或“载荷已过期”。
- 父级已失效的记录恢复后进入待归类 / 未归档安全位置，不丢失正文，也不自动重建整个父级树。
- 系统 / 事件 / 统计 / 偏好记录显示为只读，并说明不能套用普通卡片操作。
- 动作前记录已被其他页面或同步修改时，不执行覆盖，提示刷新后重试。
- 动作只作用于本机，完成后记录为待同步；不会擅自上传覆盖云端。
- 动作载荷不包含附件本体、令牌或凭据，不进入上传快照；清理后旧回执降级为只读并给出原因。
- 回执列表、动作确认、差异详情与结果状态在 1440、1024、768、390 四档视口均可操作且无横向溢出。

### 5.7 同步历史

- 云同步状态面板和设置中心均有“同步历史”入口，两次进入看到同一份历史与状态。
- 历史按同步时间倒序，最多展示保留策略内的记录；每条显示方向、触发方式、时间、三项变化数和修订范围。
- 点击一条历史同步可重新打开该批次完整明细，内容与当时即时回执一致。
- 点击批次内任一数据行可打开单条记录详情并继续执行允许的操作；操作结果同步回写历史列表与批次统计。
- 即时回执与历史回执中的同一记录不会出现“一处已恢复、另一处仍可恢复”的状态分裂。
- 载荷过期、容量清理、记录冲突和系统只读记录都可见且原因清楚。
- 无历史记录时显示空态；加载和操作失败可重试，不清空已有历史。

1. 先定 D1–D13 和版本号。
