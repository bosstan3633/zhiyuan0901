## 2. 关键纠正："统一数据表"的正确打开方式

### 2.1 物理单表 ❌（不推荐）

把 resources/tasks/curiosities 三个数组合并为一张 `cards[]`，每行挂 kind + 二十多个可空列：

- 每行 60%~70% 字段为 null（资源卡没有 projectId/priority，任务卡没有 workspaceId/categoryId…），存储与序列化净增无价值体积；
- TS strict 类型从三个精确接口退化为稀疏大接口，**全链路类型收窄成本爆炸**（所有 UI 都要先按 kind 收窄）；
- 迁移是破坏性的：既有 `zy_data_v2` 数据结构、regression 断言、导出/导入、回收站全要动；
- 收益≈0：物理合并并不会让"转卡/导出/字段管理"更顺——那些是**元数据与逻辑层**的事。

### 2.2 逻辑字段目录 + 公共基底 ✅（推荐形态）

物理存储可完全不动，做三层"逻辑合一"：

```
① CardBase（公共基底，TS 层）   ← 消灭三接口重复声明
   id / kind / title(=好奇的question) / description? / tags[] / customFields
   / pinned / starred? / createdAt / updatedAt / deletedAt? / assets?
② 类型扩展（各卡专有字段，TS 层继承 CardBase）
   resource: linkType·link·workspaceId·categoryId·sourceType·callCount
   task:     projectId?·metricId?·status·priority·dueDate?·estimatedMinutes?·link?·completedAt?·mountedResourceIds·mountedCuriosityIds
   curiosity: sourceUrl?·sourceTitle?·status(四态)·sortOrder?·relatedResourceIds
③ 统一字段目录（Field Catalog，元数据层）  ← 取代 FieldConfig 三分区各自为政
   FieldDef 增加 kinds: CardKind[]（适用哪些卡型），一份目录管理显隐/顺序/类型
```

**为什么这是正确形态**：你的四个诉求——一份管理、一致视觉、顺畅转卡、表格式导出——全部由"①+③"服务，与"物理是否一张表"无关。而现状已经天然长成了 ①②③ 的雏形（FieldConfig+FieldDef+AnyCard+重复公共字段），**演进路径最短、无破坏性迁移**。

**顺手清理**：`UIPrefs.fieldViewCfg`（models:315）grep 全库仅 repository.ts:210 初始化 `{}`，**无任何消费**——是历史遗留的"第二套字段配置"，属死代码，合一时应删除（回归加一条断言防复活）。

## 3. 四个优化抓手（按 ROI 排序）

### 抓手 ① 字段目录合一（中等改动 · 最高收益 · 直接回应设想 6）

**现状痛点**：
- FieldConfig 三份独立分区，设置页三个几乎一样的页面（GlobalSettings.vue:24-66）；
- FieldEditor.vue 里 `ICON_MAP / SYSTEM_KEYS / LOCKED_KEYS / AUTO_KEYS / REQUIRED_KEYS` 五组常量 ×3 卡型，**同一套逻辑重复写了三份**（行 14-30）——这是与 #61 同类的"三份表单"技术债；
- 想加一个"三类卡都显示"的公共字段，现在要进三个页各加一遍。

**目标形态**：
- 数据层：`FieldConfig` 三分区 → 单一目录 `catalog: FieldDef[]`，`FieldDef` 增 `kinds?: ('resource'|'task'|'curiosity')[]`（空 = 全卡型公共字段）+ `scope: 'common'|'type'`；
- 视图层：目录按卡型过滤出"该卡可见字段"，**渲染端零改动**（visibleFields 加一个 kinds 过滤参数即可）；
- 编辑层：FieldEditor 常量表合并为一张总表（key → 图标/分级/锁定），组件仍可按卡型 tab 渲染；新增字段时可选"仅任务卡 / 资源+任务 / 全部"；
- 迁移：migration 惰性归一（公共字段如 title/tags/description/createdAt 自动标记全 kinds；custom_* 老字段按所在分区 backfill kinds），老 key 不变 → **老用户数据无需改写**。
- 复用同一 fieldConfig 的现有消费端：`fields.ts` 的 `visibleFields(cfg, type)` → 改为 `visibleFields(catalog, type)`（kinds 含 type 即返回），两处调用点（Workspace / CompassActions）签名不变。

### 抓手 ② 转卡无损化 + 全向入口（小-中改动 · 设想 7）

**现状缺口**：
- 方向残缺：只有好奇→任务/资源，任务/资源无转出；好奇→任务在任务中心没反查入口；
- 字段有损：`stores/curiosity.ts:63-105` 转卡是"重建新卡"，tags/description/**附件 assets**/customFields/pinned/starred 全部丢弃、customFields 硬置 `{}`、sourceType 丢失——附件是 REQ-048 刚交付的能力，转卡即丢，用户不可接受；
- 语义：源卡软删 + 目标卡带 `mountedCuriosityIds:[源id]`（溯源是对的，保留）。

**目标形态**：统一 `convertCard(source, targetKind, ctx?)`：
- 公共字段**无损搬运**（title↔question 归一映射、description/tags/customFields/assets/pinned/starred 原样带）；
- kind 特有字段按映射表走（curiosity.sourceUrl → resource.link；task.status 与 curiosity.status 需显式状态映射，默认 todo/待探索）；
- 源卡软删、目标卡回指（保溯源）；任务卡获得转出入口（转资源/转好奇），好奇心卡入口保留；
- 有了字段目录后，映射表可由 catalog 按"同名 key"半自动推导，新字段自动支持转卡。

### 抓手 ③ CSV 数据表化（中改动 · 设想 8）

**现状缺口**：`GlobalSettings.vue:838-863` 仅资源卡、仅单个工作台、10 列硬编码（标题/链接/链接类型/标签/分类/描述/置顶/星标/创建/更新时间），不含自定义字段；任务/好奇心无 CSV；与字段目录脱节。

**目标形态**：导出范围可选（全库 / 工作台 / 分类 / 状态筛选）+ 卡型可选（单型 / 三型合并）+ **列 = 字段目录可见字段动态生成**；三型合并导出时加 `kind` 列 + 公共列对齐 + 类型专有列空置。这才是"数据表格式顺畅导出"，可直接喂 Airtable/飞书多维表，与"多维表迁移"愿景同轨。

1. **字段目录合一的迁移**：优先"惰性归一 + 老 key 不变"，避免破坏性改写既有 `zy_data_v2`；老用户 `custom_*` 字段需按原分区 backfill kinds。

4. **回归断言**：统一模型涉及 FieldEditor/GlobalSettings/fields.ts，旧断言 R33-* / 字段相关需同步迁移（沿用 #61 的"断言指到共享实现"打法）。

### 8.2 现状核实（grep 结果）
- `Workspace.vue` 全文 grep `assets|AssetManager|attachment|📎|附件` → **No matches found**：资源卡三视图（card/list/kanban）正面**没有任何附件渲染**。

→ 这是 REQ-048 交付时**漏掉的一环**：上传/预览/硬删都做了，但"卡片正面一眼看到有图有 HTML"未做。属真实产品缺口，不是用户误解。

### 8.3 与 V2.16 字段目录化的天然契合
附件字段 `assets` 已经是 CardBase 公共字段之一（见 4.1）。把它纳入统一字段目录消费链路 `fields.ts → fieldRenderKind → 三视图自动渲染`，正是 V2.16 的首批受益场景：

- **fields.ts 新增 `fieldRenderKind('assets')` 返回 `'assets'`** + `fieldValue` 在导出/详情上下文走附件特殊路径（返回如 "📎 2图 1HTML" 的可读文本）；
- **workspace/views/components 卡片/列表/看板组件**消费该类型：图片显示首张缩略图 + "📎 +N" 徽章；HTML 显示 📄 图标 + 数量；点击走 AssetManager 已有的 `openAsset`（图片弹窗/HTML 新标签）；
- 顺便把**好奇心面板**也接入同一渲染链路，达成"好奇心视图纳入字段目录消费"（拍板 #4）；
- 视觉令牌统一用 `tokens.css`（密度令牌、卡片最小宽），与现有 rc/tc/cc 三视图风格保持一致。
