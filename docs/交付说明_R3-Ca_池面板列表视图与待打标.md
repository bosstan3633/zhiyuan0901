## 二、这一刀补了什么

`PoolCardsPanel.vue` 是资源台退役后池卡的唯一管理面（真库 260 张活卡）。四件事：

1. **列表视图**（`▦ 网格 / ☰ 列表`）：与网格**共用同一份 `rendered`**（`poolCards` 的分页切片），不复制第二条过滤链——两档切换不改变可见集合，只改密度。列表行同样带 `data-rid`，所以 `?hl` 定位高亮、批量勾选、软删撤销在两档里行为一致（`.pcp-card.flash, .pcp-row.flash` 共用同一动画）。视图态存组件内 `ref`，**与任务/好奇面板同口径**，不为池面板单开持久化，也不碰 `wsView.ts`（那是策展台的四值白名单，R84-7 逐字守着）。
2. **「🏷 待打标 N」筛选**：这条不是新功能，是**兑现旧账**——`poolMigration.ts:11` 当初写着「『待分类』子树不迁，其卡片不加标签 = 无标签，走资源卡『待打标』筛选兜住召回」，而这个筛选从来没被实现过。实测真库 260 张里剩 1 张无标签，徽标当场显示「待打标 1」。列表视图里无标签的行显式打 `无标签` 警示牌（不是留白）。
3. **批量反选**：`invertSel()` 只在**当前过滤结果**内取反。不做"反选全池"——那会把看不见的卡卷进批量动作，而批量动作里就有删除，那是静默误删的配方。
4. **右键菜单**：复用 `shared/components/ContextMenu.vue` 单根（好奇面板 R46-1 已定这条纪律），不新写第二套菜单 DOM。四项：打开详情 / 📌 置顶·取消置顶 / 复制链接（**仅有链接的卡出现**）/ 删除（进回收站）。删除直接复用 `removeCard`，所以软删 + 3 秒撤销的既有防呆一步没减。

**★有意偏离记账更新**：看板视图**仍然不做**（资源卡没有状态字段，看板无列可分，这条理由没变）；但列表视图**改了判法**——原先我写"列表与网格信息重叠"，实际差的是密度与标签展开度，一屏 60 行的池卡盘点比 60 张卡片快得多。所以 R2-⑧ 那条"三视图渲染器按两视图收口"的备案，从"不做列表 + 不做看板"更新为"做列表、不做看板"。
