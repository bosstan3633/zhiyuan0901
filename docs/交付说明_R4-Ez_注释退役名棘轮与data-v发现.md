## 一、"注释旧称清账"不能做成"见退役名就改"

现扫 `src` 的注释，含「资源台」的有 **160 处**。绝大多数是**准确的历史出处**，动它们只会把 provenance 抹平：
`// R68-F3：「打开方向台」「打开资源台」退役`、`// R61 资源台转正`、`* V3.7.0（R179）：「📡 镜像到策展台」随资源台退役`、`* 存量库里那枚历史实体的名字仍叫「资源台」`。

真正会误导人的是另一类：**用退役名描述当下的行为，且同一处没写明这是历史**。判据形态定成三条：
① 命中退役名（资源台 / 策展中心 / 主航线 / 项目总览 / CompassShell / LighthousePanel）；
② **本行没有**历史标记词；③ **前两行也没有** ⇒ 才算违规。
按这个口径，160 处里剩 **22 处**，逐条改掉（都是文字，不动代码）：

## 四、★本轮量到一条关于构建的事实：改注释会换 `data-v` 作用域 id

开工前 dist 聚合哈希 `01eb4d55…`；改完这 22 处注释后 `npm run build` 得到 `fb50720b…`。第一反应是"构建不可复现"，于是做了三步因果测试：

1. **同一份源码连打两次** ⇒ 两次都是 `fb50720b…` ⇒ **构建可复现**，差异不是噪声。
2. **把 15 个文件全退回 HEAD 再打** ⇒ 哈希精确回到 `01eb4d55…` ⇒ 差异**确实由这批注释改动引起**。
3. **只退回 `CompassTree.vue` 一个文件** ⇒ CSS chunk 名从 `CompassTree-3EQbmwDk.css` 回到 `CompassTree-Dd6DzFPL.css`；换回我的版本又变回去 ⇒ 定位到机制：**`.vue` 的源码内容参与 scoped 样式的 `data-v-<hash>` 作用域 id 计算**，注释也是源码。

**这条推翻了一个我一直默认的前提**："只改注释不动产物，所以视觉/perf 读数仍代表当前包"。
它在 `.ts` 上成立（esbuild 剥注释），在 `.vue` 上**不成立**。
⇒ 本轮按"src 变了"处理：e2e、theme-audit、perf 全部重跑（第五节）。
反过来也提醒后续几轮：R4-Ew/Ex 那两轮"src 零改动 ⇒ dist 仍代表当前包"的推理仍然成立（它们确实一字未动 src）。

**顺带一条自伤（同形事故第三次）**：做第 2 步因果测试时我**分两次**取备份，第二次取清单时 `cardCols.ts` 已经在第一次单文件测试里被退回 HEAD，于是它不在备份清单里——还原后那 2 处注释静默丢失。
发现靠的是"改完逐条 grep 本轮写入的新词"（22 处复验缺 2 → 当场补回）。
**纪律加严**：因果/回退类测试，备份清单必须在动手前**一次取全**，还原后必须**逐条 grep 本轮写入的每个新词**，不能只看回归绿。

## 六、边界如实

1. **棘轮只盯"注释里的退役台面名"这 6 个词**，且靠标记词表判"是不是历史"。 looseness 是双向的：有人把注释写成带"旧/原/曾"字样就能免检——所以标记词表**在判据体内**，改它必进 diff；但"用词更狡猾"（不出现这 6 个词、改用别的旧称）不在面上。
2. **`data-v` 作用域 id 变了 ⇒ 归档 PNG 与改前不可直接比**（选择器属性变了）。本轮**没有**留"像素不变"的证据：theme-audit 写的是同一目录 `docs/视觉归档/2026-10-04/`，把 R4-Ex 那一批覆盖了。下次做这类"产物变但界面不该变"的轮次，应该 `--tag` 另开一份再跑 `img-diff --batch`，把这条证上。
3. **22 处的判定含人工复核**：分类器给的是候选，最终"这条是不是在描述现状"是我逐条读的。分类器换个人跑可能给出 20 或 25 处——但棘轮锁的是**结果**（现扫为零），后续新增无论谁写都同样要过这条规则。
4. `src` 里仍有 **138 处**注释带"资源台"字样，全部带历史标记（R61/R68/R179/退役/存量库…）。它们不是债，是这项目的年轮；**#118 的尾账到此为止**，再往下就是删历史而不是清误导。
5. #124 的三件里本轮做完 ②③（注释旧称清账 + 过期注释随迁）；①（Airtable 列值统一）已拍板"全站去前缀"，与 #117 的"撤降级"各排一轮 = **#129 / #128**。#127（`raycast-st-manual` 整页跳变）仍待查。
