# 需求清单 · V4.1.0 策展节点附件、画布历史与移动 Inbox

> **日期**：2026-11-04  
> **基线版本**：V4.0.4（`16d0b66`）
> **目标版本**：V4.1.0（已确认）  
> **状态**：V4.1.0 已开发、验证并发布
> **范围**：策展画布 L1 中心论点及 L2–L4 节点；移动端链接/文本采集与桌面 Inbox 池；主快照中的“今日三件事”；普通资源卡、任务卡、好奇心卡的附件不纳入本轮云同步  
> **文档性质**：本文件是实施、验收、回归判据和交付说明的单一需求真源

## 一、目标与边界

### 1.1 本轮目标

1. 让策展节点拥有完整的附件能力：图片、HTML、PDF，并支持文件选择、拖入和剪贴板图片粘贴。
2. 让策展节点附件在登录后默认静默同步至用户自己的 Supabase Storage，实现同账号多设备访问。
3. 让节点附件遵守可恢复的删除语义：节点软删时附件隐藏但保留，彻底删除时再清理本体。
4. 让策展台导出的 HTML 可以离线打开节点附件。
5. 为策展画布提供最多 10 步的撤销/重做，使结构编辑和附件操作可追溯。
6. 让移动端支持链接和文本采集，把采集内容先放入 Inbox 池。
7. 让桌面 Inbox 池与任务卡池、好奇心卡池、资源卡池并列，支持按时间盘点、分组筛选、删除和三卡转化。
8. 让已转化 Inbox 条目成为对应卡片的镜像入口，点击后可打开现有卡片详情。
9. 让“今日三件事”的每日槽位、完成状态、自动推荐日期和静音日期随主快照保持一致，并纳入本机/云端关系判断。

### 1.2 明确不做

- 不把普通资源卡、任务卡、好奇心卡的附件纳入本轮云同步。
- 不做多人实时协作、成员权限、共享链接、协同编辑或附件共享权限管理。
- 不支持多个节点共享同一个附件；附件与节点严格一对一。
- 不把附件 Blob 或 base64 写入主 JSON、云快照中的业务数据。
- 本轮不要求把导出 HTML 中的附件本体重新导回另一套策展台。
- 不新增附件级版本管理、批注或在线预览编辑器。
- 不在 Inbox 内编辑已提交的原始采集内容；转化后在对应卡片详情中编辑。
- 不做移动端直接转化。移动端只负责采集与暂存，三卡转化在桌面 Inbox 池完成。
- 不做语音、拍照、文件或网页正文自动抽取；本轮移动端只支持链接与纯文本。
- 不做 Inbox 批量转化；本轮先完成逐条转化闭环。

### 1.3 已拍板决策

| # | 决策项 | 最终口径 |
|---|---|---|
| 1 | HTML 导出体积 | 按 100MB / 300MB 两级阈值处理，允许单文件自包含或转为 ZIP 包 |
| 2 | 版本号 | **V4.1.0** |
| 3 | 附件上云授权 | **默认静默上传**，不逐次弹窗询问 |
| 4 | 画布历史 | 增加“上一步 / 下一步”，最多保留 10 步，支持快捷键 |
| 5 | 移动采集落点 | 链接和文本统一进入 Inbox 池，不再由设置页临时导入资源卡 |
| 6 | Inbox 转化语义 | 一条采集只能转化一次；转化后保留 Inbox 镜像入口，点击打开对应卡片详情 |
| 7 | 今日三件事云同步 | `dailyFocus`、`focusAutoDate`、`focusMutedDate` 全部纳入云快照与指纹，恢复后逐槽原样一致 |

## 二、节点附件

### 2.1 覆盖节点

- L1：中心论点卡。
- L2–L4：策展画布全部普通节点。
- 节点排序、剪切、粘贴为子级、拖拽换父级时，附件自动跟随节点，不重新上传，不复制为新附件。

### 2.2 类型与限额

| 类型 | 每节点数量上限 | 单文件上限 | 超限行为 |
|---|---:|---:|---|
| 图片 | 9 张 | 10MB / 张 | 第 10 张直接拒绝；超体积文件直接拒绝 |
| HTML | 1 个 | 20MB | 再次上传视为替换，必须先确认 |
| PDF | 1 个 | 50MB | 再次上传视为替换，必须先确认 |

补充规则：

1. 同一节点可同时拥有 9 张图片、1 个 HTML、1 个 PDF。
2. PDF 统一限制为 50MB；存量超过 50MB 的 PDF 仅保留本地，可继续查看，但不上传云端。
3. 上传失败不得阻塞节点标题、说明或其他结构编辑。
4. 节点卡片只显示轻量附件入口和数量，不在画布卡片内直接铺开附件列表。
5. 无附件时不显示空态，不出现“缺证据”或多余分隔线，视觉焦点保持在标题与描述。

### 2.3 上传方式

1. **文件选择**：支持一次选择多张图片；HTML、PDF 单文件选择。
2. **拖入**：支持把图片、HTML、PDF 拖到节点附件抽屉。
3. **剪贴板上传**：
   - 选中节点后，`Ctrl+V` / `⌘+V` 可直接上传剪贴板中的图片。
   - 一次可粘贴多张图片，仍受剩余 9 张限额约束。
   - 只有剪贴板中存在图片时才拦截粘贴；普通文字粘贴不得被阻断。
   - 节点标题或说明处于编辑态时，图片粘贴仍按附件处理；纯文字粘贴保留原文本编辑语义。
   - 画布原有“剪切/粘贴节点为子级”语义必须继续可用，不得与图片粘贴冲突。

### 2.4 命名与反馈

- 粘贴图片使用可读的自动文件名，格式建议为：
  `粘贴图片_YYYY-MM-DD_HHmmss_序号.png`
- 每项附件显示：文件名、类型、体积、上传状态。
- 上传状态至少包含：
  - 仅本机
  - 待上传
  - 已同步
  - 上传失败
- 失败项提供“重试”；批量上传失败时不得丢失成功项。
- 附件总数和体积在抽屉内可核对。

### 2.5 附件操作

- 预览图片。
- 打开或下载 HTML、PDF。
- 删除单个附件。
- 替换 HTML / PDF 前二次确认，并明确旧文件将被移除。
- 删除节点附件属于可撤销操作，必须进入画布历史。

## 三、数据与本地存储

### 3.1 数据模型

1. `Category` 增加可选附件字段：
   - `assets?: AssetMeta[]`
   - 旧数据没有该字段时按空数组处理，零迁移。
2. `AssetMeta` 增加可选云同步字段，仅为策展节点附件使用：
   - `storagePath?: string`
   - `uploadState?: 'local' | 'pending' | 'synced' | 'failed'`
   - `checksum?: string`
   - `uploadedAt?: number`
   - `lastError?: string`
   - `retryCount?: number`
3. 主 JSON 和云快照只保存元数据，不保存 Blob、base64 或临时签名 URL。
4. 本地 Blob 继续存放在 IndexedDB `zy_assets`，键为 `assetId`。
5. 附件本体与节点严格一对一，不建立跨节点引用。
6. `CardBase` 增加可选 `sourceCaptureId?: string`，仅由 Inbox 转化生成的三卡写入，用于幂等去重和跨刷新定位；存量卡不写、零迁移。
7. `capture_inbox` 的采集正文与转化字段独立于主数据快照；主数据只保存转化生成的三卡和 `sourceCaptureId` 映射。

### 3.2 同步队列

1. 新增独立的附件同步队列，以 `assetId` 为幂等键。
2. 上传状态变更不得触发节点内容版本变化。
3. 队列至少记录：
   - 用户、策展台、节点、附件 ID
   - 远端路径
   - 当前状态
   - 重试次数
   - 最近错误
   - 最后尝试时间
4. 应用启动、重新登录、网络恢复时自动补传未完成项。
5. 应用关闭后队列仍需保留，下次启动继续处理。

## 四、Supabase Storage 云同步

### 4.1 存储结构

- 使用私有 Bucket：`curation-assets`。
- 对象路径：
  `userId/workspaceId/nodeId/assetId.ext`
- Bucket 必须为私有，不允许公开读取。
- 仅使用 publishable key + 当前登录用户 access token；`service_role` / secret 严禁进入扩展。

### 4.2 权限边界

RLS 至少满足：

1. 用户只能读写自己 `userId/` 目录下的对象。
2. 未登录用户不能读写任何策展附件。
3. 不同账号即使拿到同一对象的 assetId 也不能访问。
4. 删除、覆盖和下载均经过用户 access token 校验。

Bucket 与 RLS 属于上线前置配置。若 Bucket 不存在或策略未配置，客户端必须显示可诊断错误，但不得影响本地附件使用。

### 4.3 上传策略

1. **本地优先**：先写 IndexedDB，界面立即可用，再异步入队上传。
2. **默认静默上传**：登录后自动上传，不逐次弹窗授权。
3. 设置页提供“策展节点附件云同步”开关，默认开启。
4. 关闭开关后：
   - 新附件仅保存在本机。
   - 已同步附件不自动删除云端副本。
   - 重新开启后补传“仅本机/待上传”的附件。
5. 上传失败按指数退避重试；失败不阻塞本地编辑。
6. PDF 达到 50MB 时建议使用 TUS 或等价的可恢复上传方案，避免弱网反复从头传输。

### 4.4 下载与跨设备

1. 同账号登录后，节点附件抽屉可下载或预览远端附件。
2. 优先读取本地 Blob；本地缺失时按 `storagePath` 下载并回填 IndexedDB。
3. 下载完成后更新本地同步状态。
4. 跨设备不实时推送附件本体；以打开抽屉、预览或主动恢复时按需拉取为准。
5. 附件本体不进入主快照，避免云快照体积膨胀。

### 4.5 文案调整

现设置页“附件本体不进云”需要区分两类数据：

> 普通卡片附件仅保存在本机；策展节点附件在登录后自动保存至你的私有 Supabase Storage。

### 4.6 容量提醒

Supabase 免费项目的 Storage 长期容量通常为 **1GB**，不是 5GB；5GB 多为流量/缓存额度。文档、设置页和帮助文案必须使用准确口径，避免误导。

### 4.7 今日三件事云同步

“今日三件事”不使用附件存储，而是作为 `AppData` 主快照中的结构化业务数据同步。不得只因为云快照当前会深拷贝整个 `AppData` 就默认它已可靠覆盖，必须建立显式契约和专项回归。

同步字段：

| 字段 | 内容 | 同步要求 |
|---|---|---|
| `dailyFocus` | `Record<'YYYY-MM-DD', FocusSlot[]>` | 全部日期、槽位内容、顺序、完成状态和完成时间必须保留 |
| `focusAutoDate` | 最近一次自动推荐已执行的日期 | 必须随快照同步，避免另一设备当天重复自动推荐 |
| `focusMutedDate` | 用户当天选择“不再自动推荐”的日期 | 必须随快照同步，避免另一设备覆盖用户静音决定 |

规则：

1. 上传、下载、冲突检查与关系指纹必须包含上述三个字段。
2. 槽位至少包含 `id`、关联来源、展示标题、`done`、`doneAt`、`auto` 等现有字段；同步时不得裁掉任何槽位字段。
3. 云端恢复必须是原子恢复：三个字段来自同一份快照，不得出现槽位已恢复但自动日期未恢复的混合状态。
4. 同账号设备 A 修改今日槽位内容或完成状态后，设备 B 拉取云端快照，必须得到相同槽位顺序、内容和完成状态。
5. 设备 A 当天已自动推荐或已静音，设备 B 当天不得再次自动写入；除非用户主动执行“换一批”或解除静音。
6. 云端恢复、本机覆盖、云端覆盖和冲突提示都必须把今日三件事变化计入关系判断，不能显示“已同步”却仍存在差异。
7. 普通卡片附件仍不上云；此节只同步“今日三件事”的结构化字段，不引入新的二进制存储。
8. 回归测试必须直接构造两端 `dailyFocus` 差异，验证指纹不同；恢复后逐日、逐槽、逐字段深比较一致，不能只检查数组长度。

## 五、移动端采集与 Inbox 池

### 5.1 移动端采集入口

移动端 PWA 的采集表单支持两种内容类型：

| 类型 | 必填 | 可选 | 规则 |
|---|---|---|---|
| 链接 | 完整 URL | 标题、备注 | 只接受 `http://` 或 `https://` 开头的完整链接 |
| 文本 | 文本正文 | 标题、备注 | 允许纯文本、多行文本和带空白的自然语言 |

交互规则：

1. 表单提供“链接 / 文本”类型切换，默认自动识别输入内容，允许用户手动改选。
2. 链接模式提交前校验 URL；文本模式不要求包含链接。
3. Android 等系统分享的 `link` / `url` 参数进入链接模式。
4. 系统分享的 `text` 参数若本身是单个 URL，则按链接处理；否则进入文本模式。
5. 提交成功后清空当前输入，保留明确的成功回执。
6. 未登录、离线或 token 过期时，内容先写入移动端本地待提交队列；登录或网络恢复后自动补发，不得丢内容。

### 5.2 Inbox 池入口与计数

1. Inbox 池与任务卡池、好奇心卡池、资源卡池并列。
2. 调度台“手边的卡”页签组新增 `Inbox` 页签，与“任务 / 好奇心 / 资源”同排。
3. 卡片池二级页 `/deck/:kind` 的类型切换同步增加 `Inbox`，地址为 `/deck/inbox`。
4. Inbox 页签右上角显示未转化数量徽标；Inbox 二级页右上角保留同一枚数量与状态图标，两处读数同源。
   - 只统计 `未转化`。
   - 不统计已转化、已从 Inbox 删除或已移除的记录。
   - 数字为 0 时不显示红点，但 Inbox 入口仍在。
5. 未登录或云端不可用时，入口仍可见，但显示“未连接 / 去登录”，不得把未知状态伪装成 0。
6. 原有“设置 → 数据管理 → 云同步”的移动采集临时列表与“导入资源池”入口由 Inbox 池承接；设置页只保留 PWA 地址、登录状态与连接说明，不再维护第二套采集列表。

### 5.3 Inbox 列表

Inbox 使用列表视图，不使用卡片网格。每条记录展示：

- 固定名称：`链接采集` 或 `文本采集`。
- 内容摘要：
  - 链接：优先展示标题，其次展示 URL。
  - 文本：展示正文首行或前 80 个字符。
- 采集时间：精确到分钟。
- 当前状态：未转化 / 已转任务卡 / 已转好奇心卡 / 已转资源卡。
- 删除入口。
- 三个转化入口：转为好奇心卡、转为任务卡、转为资源卡。

行交互：

1. 未转化条目点击只选中当前行，不打开右侧详情。
2. 已转化条目点击后，右侧滑出对应卡片现有详情抽屉：
   - 任务卡：`TaskDetailDrawer`
   - 好奇心卡：`CuriosityPanel` 的详情抽屉
   - 资源卡：`ResourceDetailDrawer`
3. Inbox 不复制一套卡片详情组件，必须复用对应卡片的唯一详情实现。
4. 目标卡片已删除或本机尚未同步到目标卡片时，条目仍保留并显示“目标卡暂不可用”，不得因此重新开放转化入口。

### 5.4 分组与排序

分组选择固定为四项：

| 分组 | 范围 |
|---|---|
| 未转化 | 尚未转化为三卡，且未从 Inbox 删除 |
| 转化为任务卡 | `convertedKind = task` |
| 转化为好奇心卡 | `convertedKind = curiosity` |
| 转化为资源卡 | `convertedKind = resource` |

排序规则：

1. 支持“采集时间正序 / 倒序”切换。
2. 默认倒序，最新采集在前。
3. 分组和排序只改变 Inbox 列表视图，不改变采集时间、转化状态或卡片顺序。
4. 每个分组提供独立空态，空态文案要说明当前分组为什么为空。

### 5.5 转化为三卡

每条未转化记录提供三个互斥转化动作：

- 转为好奇心卡。
- 转为任务卡。
- 转为资源卡。

转化规则：

1. 用户点击任一转化动作后，该动作显示进行中状态，防止重复点击。
2. 转化成功后：
   - 对应卡片进入各自卡片池。
   - Inbox 记录保留为镜像入口。
   - 记录写入 `convertedKind`、`convertedCardId`、`convertedAt`。
   - 用户点击的那一种转化动作变为“已转为 X”并高亮。
   - 另外两种转化动作置灰不可点。
3. 一条 Inbox 记录只允许转化一次，不允许再次转成另一类卡。
4. 转化完成后，条目立即退出“未转化”分组、进入对应的“转化为 X”分组，未转化计数同步减一；若用户正停留在“未转化”分组，行离场并给出可跳转的目标分组回执。
5. 转化必须幂等：
   - 重复点击、网络重试、刷新页面都不得生成第二张卡。
   - 卡片需记录可追踪的 `sourceCaptureId`，或在本地建立等价的唯一映射。
6. 卡片创建成功但云端转化状态更新失败时：
   - 本地必须立即保留转化结果，避免生成重复卡。
   - Inbox 进入“转化结果待同步”状态并自动重试。
   - 重试只补写转化标记，不再创建新卡。
7. 转化后卡片进入对应卡片池，Inbox 中的是卡片镜像入口，不是第二张独立卡片。
8. 目标卡片后续被删除时，Inbox 镜像仍可被移除，但不得恢复为未转化状态。

### 5.6 字段映射

转化时按以下最小映射生成卡片；生成后的完整编辑在对应卡片详情完成。

| 来源 | 目标 | 映射 |
|---|---|---|
| 链接 | 任务卡 | 标题优先取采集标题，否则取链接；描述写入备注与链接；默认未归档 |
| 链接 | 好奇心卡 | 问题取采集标题，否则取链接；`sourceUrl` 写链接；`sourceTitle` 写采集标题；备注写描述 |
| 链接 | 资源卡 | 标题优先取采集标题，否则取链接；`linkType=url`；`link` 写链接；备注写描述 |
| 文本 | 任务卡 | 标题取正文首行并截断；描述保留完整正文与备注；默认未归档 |
| 文本 | 好奇心卡 | 问题取正文首行并截断；描述保留完整正文；不伪造 `sourceUrl` |
| 文本 | 资源卡 | 标题取正文首行并截断；描述保留完整正文；链接留空 |

补充：

- 三类转化都不得丢失原始正文。
- 空标题时使用稳定、可辨认的默认标题，不生成空白卡。
- 采集标签为后续能力，本轮可默认为空；不得因无标签阻止转化。

### 5.7 删除 Inbox 条目

1. 每条 Inbox 记录提供删除入口。
2. 删除未转化记录：只从 Inbox 移除该采集，不创建也不删除任何三卡。
3. 删除已转化记录：只移除 Inbox 镜像入口，绝不删除目标卡片。
4. 删除使用软删除字段 `dismissedAt`，列表与计数立即排除。
5. 删除后提供 6 秒撤销，与全站删除回执口径一致。
6. 删除回执必须写清边界：
   - 未转化：`已从 Inbox 删除采集 · 撤销`
   - 已转化：`已从 Inbox 移除镜像入口，卡片仍保留 · 撤销`

### 5.8 数据与云表

1. 扩展 Supabase `capture_inbox`，至少增加：
   - `content_kind: 'link' | 'text'`
   - `text_content: text | null`
   - URL 改为可空；链接类型时必填
   - `converted_at: timestamptz | null`
   - `converted_kind: 'task' | 'curiosity' | 'resource' | null`
   - `converted_card_id: text | null`
   - `dismissed_at: timestamptz | null`
2. 数据库约束至少保证：
   - 链接记录必须有 URL。
   - 文本记录必须有 `text_content`。
   - 两类内容不得同时为空。
   - `converted_kind` 与 `converted_card_id` 必须同时有值或同时为空。
3. 原有“同用户、同 URL、未消费只能一条”的唯一索引需调整为只约束未转化且未删除的链接记录，避免多条文本采集被错误去重。
4. 客户端查询默认过滤 `dismissed_at is null`，分组查询再按 `converted_kind` 过滤。
5. RLS 继续保证每个用户只能读写自己的采集记录；不允许公开读取。
6. Inbox 列表使用最近一次成功拉取的本地缓存；断网时允许查看缓存，转化与删除动作禁用并提示联网后重试。
7. 旧的 `consumed_at` 语义不再承担“导入后消失”；新转化记录必须保留可查询的镜像状态。
8. 存量 `consumed_at` 非空的记录在迁移时置为已删除/已归档并隐藏，不再进入未转化组，也不重建资源卡；避免升级后被重复导入。

## 六、软级联删除与恢复

### 6.1 软删除

1. 删除 L2–L4 任一节点时，整棵子树进入回收站。
2. 节点进入回收站后，其附件立即从以下位置隐藏：
   - 画布
   - 搜索
   - 节点详情
   - 导出与分享预览
3. 附件元数据、本地 Blob 和云端对象暂时保留，确保节点可恢复。
4. 需记录同批级联删除关系，恢复父节点时只恢复“随父级一起删除”的后代。
5. 此前被单独删除的子节点不得因父节点恢复而误恢复。

### 6.2 恢复

- 恢复单节点：恢复其自身及同批级联子树。
- 恢复附件：恢复后附件重新可见，已同步状态保持。
- 恢复不重复上传已有云端对象。

### 6.3 永久删除

以下路径必须统一走硬删除链路：

- 单节点永久删除。
- 清空回收站。
- 删除整个策展台。
- 其他会物理移除策展节点或策展台的数据清理入口。

永久删除时：

1. 删除整棵子树的 IndexedDB Blob。
2. 删除 Supabase Storage 中对应对象。
3. 清理附件元数据和同步队列。
4. 云端删除失败时不得静默忽略；保存待清理记录并重试。
5. 若附件仍被当前状态、撤销栈或重做栈引用，则延迟物理清理。

### 6.4 删除与历史的关系

- 软删除、恢复、永久删除中可逆的结构操作进入画布历史。
- 永久清理本体不属于“可撤销内容变更”，但必须保证引用安全。
- 撤销后重新引用附件时，其本地 Blob 和云端对象应仍存在。

## 七、HTML 导出

### 7.1 输出目标

策展台导出的 HTML 必须：

- 可直接在 `file://` 下离线打开。
- 点击图片可放大预览。
- 点击 PDF 可在新标签打开或下载。
- 点击 HTML 附件可在安全预览层查看，或下载原文件。
- 普通资源卡附件仍只输出名称、类型和大小，不嵌入本体。

### 7.2 生成方式

1. 导出时临时读取节点附件 Blob。
2. 图片、HTML、PDF 转为 data URL 或等价的内嵌数据，写入导出产物。
3. 业务快照只保存附件元数据；内嵌数据只在生成导出文件时临时构造，不回写主数据。
4. HTML 附件不得直接在主分享页执行：
   - 使用 `sandbox` iframe 预览。
   - 提供“下载原文件”入口。
   - 明示“附件内容来源自负”。
5. 导出前显示：
   - 附件数量
   - 附件总体积
   - 预计导出体积
   - 将要采用的单文件或 ZIP 模式

### 7.3 体积分级

| 节点附件总量 | 导出行为 |
|---:|---|
| ≤ 100MB | 生成自包含单文件 HTML |
| 100MB–300MB | 强提醒预计体积与浏览器压力，用户确认后继续生成单文件 HTML |
| > 300MB | 改为“HTML + attachments/ 附件目录”的 ZIP 包 |

补充：

- 单文件 HTML 必须尽量减少重复编码和额外复制。
- 生成过程应有进行中状态，避免长任务造成页面无响应。
- ZIP 模式下，HTML 内使用相对路径引用 `attachments/`，保证解压后离线可打开。
- 若浏览器内存不足以生成单文件，应允许直接降级为 ZIP。

## 八、画布撤销与重做

### 8.1 入口

- 在策展画布顶部工具栏新增“上一步 / 下一步”按钮。
- 位置靠近“金字塔 / 树状”模式切换，属于高频操作区。
- 按钮在不可用时置灰。
- 悬停显示具体动作，例如：
  - “撤销：移动节点「AI 应用场景」”
  - “重做：添加 3 张图片”

### 8.2 快捷键

| 操作 | macOS | Windows / Linux |
|---|---|---|
| 撤销 | `⌘+Z` | `Ctrl+Z` |
| 重做 | `⌘+Shift+Z` | `Ctrl+Shift+Z` |
| 重做备用键 | — | `Ctrl+Y` |

焦点规则：

1. 焦点在策展画布且不在文本输入态时，快捷键驱动画布历史。
2. 焦点在标题、说明等文本输入框时，优先保留浏览器原生文本撤销。
3. 焦点不在策展画布时，沿用现有全局撤销语义，不抢占其他模块的 `Ctrl/Cmd+Z`。

### 8.3 历史上限与生命周期

- 最多保留 10 个可撤销状态。
- 最多保留 10 个可重做状态。
- 撤销后执行新操作，立即清空重做栈。
- 历史按策展台独立保存；同一会话内切换策展台再返回，历史仍保留。
- 刷新、关闭应用、重新打开后历史清空。
- 历史不写入主 JSON、不进入云快照、不在设备间同步。

以下情况必须清空当前策展台历史：

- 云端快照恢复。
- 策展成果重新导入。
- 清空数据或永久删除数据。
- 策展台被删除。

### 8.4 计入历史

| 类别 | 操作 |
|---|---|
| 节点结构 | 新建、重命名、修改说明、删除、恢复 |
| 节点层级 | 拖拽改变父级、层级位置、剪切、粘贴为子级、复制 |
| 同级顺序 | 左右箭头移动同层级位置 |
| 资源关系 | 关联资源、取消关联资源 |
| 中心论点 | 修改标题、说明 |
| 节点附件 | 添加、删除、替换图片 / HTML / PDF |

合并规则：

- 一次完整操作只记一步。
- 拖拽以松手落点为结束。
- 标题和说明以 Enter 或失焦确认结束。
- 一次粘贴或一次批量选择上传视为一步。
- 上传进度、云同步状态、重试结果不单独产生历史。

### 8.5 不计入历史

- 缩放、平移。
- 金字塔 / 树状模式切换。
- 展开层级、折叠层级。
- 搜索、筛选、高亮。
- 选中节点、打开详情、全屏。
- 开关抽屉、上传进度变化、同步状态变化。

### 8.6 历史快照与附件安全

1. 历史只记录结构、字段和附件元数据引用，不保存附件二进制。
2. 只要附件仍被以下任一位置引用，本地 Blob 和云端对象不得物理删除：
   - 当前数据状态
   - 撤销栈
   - 重做栈
   - 回收站中的可恢复节点
3. 上传中的附件被撤销时：
   - 能取消上传则取消。
   - 不能取消则等待上传完成后进入孤儿清理候选。
4. 附件真正不再被任何状态引用后，才进入延迟清理队列。

| P8 | HTML 导出 | 附件嵌入、sandbox 预览、体积分级、ZIP 模式 | P1 |
| P9 | 验收与发布 | 回归分片、双设备测试、今日三件事云恢复专项、断网测试、构建、版本号、changelog、交付说明、安装包 | P0–P8 |

### 10.1 建议开发顺序

1. 先完成 P0，一次性把附件数据、Inbox 文本字段、转化状态和旧数据兼容边界定下来。
2. P4–P5 是移动采集主链路，可在不依赖策展附件云同步的情况下先行完成并独立验收。
3. P1–P3 完成策展节点附件从本地到云端的闭环。
4. P6 与 P7 共用附件引用保护，建议连续实施。
5. P8 放在附件本地读取链路稳定之后，避免导出先行造成数据契约反复。
6. P9 最后统一做回归、版本和发布。

## 十一、技术风险与约束

| 风险 | 影响 | 应对 |
|---|---|---|
| 云快照误带 Blob/base64 | 主快照膨胀、同步失败 | 严格只存元数据；增加负锚回归 |
| Bucket 或 RLS 未配置 | 上传全部失败 | 本地仍可用；错误可诊断；上线前检查清单 |
| 免费容量认知错误 | 用户误判附件容量 | 明确标为 1GB 长期容量，5GB 非长期附件额度 |
| 大数据量 HTML 导出 | 内存峰值、标签页卡死 | 100/300MB 分级、确认提示、ZIP 降级 |
| HTML 附件脚本风险 | 在主页面执行不可信脚本 | sandbox iframe + 下载，不直接注入主文档 |
| 全局撤销冲突 | 画布撤销抢占其他模块 | 仅在画布焦点且非文本输入态接管 |
| 附件引用被过早清理 | 撤销后附件打不开 | 当前状态、撤销栈、重做栈和回收站联合计数 |
| 云端删除失败产生孤儿 | Storage 长期泄漏 | 待清理队列 + 自动重试 |
| 普通卡片附件边界漂移 | 用户误以为全部附件都上云 | 设置页和帮助文档明确两类附件口径 |
| 50MB PDF 弱网传输 | 上传耗时和失败率高 | 可恢复上传、指数退避、失败重试 |
| `capture_inbox.url` 仍为必填 | 纯文本采集无法落库 | 改为可空；用约束保证 URL 与文本至少一项存在 |
| 原 URL 唯一索引误伤文本 | 多条文本被判定重复 | 唯一索引只约束未转化、未删除的链接记录 |
| 卡片创建成功但转化状态回写失败 | 刷新后重复生成卡 | 本地保留转化映射；`sourceCaptureId` 幂等；只补写状态不重建卡片 |
| 已转化目标卡在其他设备暂未同步 | Inbox 详情打不开 | 保留镜像并显示“目标卡暂不可用”，禁止重新转化 |
| 用户误以为删除 Inbox 等于删除卡片 | 误删数据 | 删除文案明确“只移除镜像入口，卡片仍保留” |
| 设置页旧导入列表与 Inbox 双入口 | 两套状态互相漂移 | 由 Inbox 唯一承接，旧列表退役 |
