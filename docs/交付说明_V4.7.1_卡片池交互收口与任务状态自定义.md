## 二、逐项落地

### 2.1 好奇心详情单宿主

- **根因**：首页、设置页与旧二级池各挂一个 `CuriosityPanel`，KeepAlive 下多个实例同时订阅 `onOpenDrawer`；访问过设置页或旧 `/deck/curiosity` 后，一次点击会打开多个相同抽屉。
- **修复**：`CuriosityPanel` 增加 `detailsHost: 'home' | 'settings' | 'deck'`，在 `onOpenDrawer` 的 `curio` 分支入口先做路由匹配；非当前宿主直接让路，不打开抽屉、不清 query、不记热度。
- **路由真名**：调度台首页是 `route.name === 'home'`；`/compass` 是方向台且 `name` 才是 `compass`。设置页匹配 `settings`，旧二级池匹配 `/deck` 前缀。
- **守卫**：`152-v471-curio-single-host.cjs` 六条（CURIO471-1…6）。

### 2.2 三卡池左侧折叠统一

- 任务卡：`TaskCalendarView.vue` 折叠后显示 `.cal-rail-toggle`，46px 常驻窄轨。
- 选题卡：`TopicManagerPanel.vue` 折叠后显示 `.topic-rail-toggle`，与任务卡同构。
- 好奇心卡：`CuriosityWorkbench.vue` 折叠后显示 `.cw-rail-toggle`，不再把展开按钮放到顶部右侧。
- 三处折叠只改视图状态，不清空搜索、项目 / 状态筛选、视图模式或排序。

### 2.3 「进入卡片池」入口退役

- `CompassHome.vue` 页头删除「进入卡片池 →」整块操作区与 `hand-head-actions`。
- 资源页「查看全部 / 全部」改由 `HomeResourceFolderGrid.openAll()` 直接打开总夹抽屉。
- `/deck/task|topic|curiosity|resource` 与 `/deck/inbox` 路由保留兼容重定向；`CompassDeckView.vue` 只做旧深链对照，不再有首页入口。
- 守卫：`153-v471-pool-collapse-entry.cjs` 四条（POOL471-1…4）。

### 2.4 任务控制栏与按项目分组

- 第一行：搜索、项目、状态、快速筛选。
- 第二行：排序、分组、月历 / 看板、月历显示已完成、清空筛选。
- 快速筛选下拉固定五项并带计数：全部 / 未挂项目 / 未落图 / 未归档 / 主攻项目；不恢复「已逾期」。
- 按项目分组时，每个项目组头是按钮，维护 `aria-expanded`；栏头提供「全部折叠 / 全部展开」。
- 默认仍为全部项目、全部状态、最新入池在前；未落图任务优先显示。
- 守卫：`154-v471-task-toolbar-group.cjs` 七条（TASK154-1…7）。

### 2.5 资源系统夹与全部资源抽屉

- `HomeResourceFolderGrid.vue` 拆为两区：
  - **系统夹**：全部资源卡、今日采集，68px 紧凑强调卡，左色条 + 强调底；
  - **我的常用夹**：自建夹独立标题、管理 / 新建入口与空态。
- `PoolCardsPanel` 新增 `hideFolderEntry`；一级「全部资源卡」抽屉传入该开关，移除顶部重复「常用夹 N」入口。
- 单卡「加入常用夹」、批量选择、批量打标、镜像与右键菜单全部保留，未复制第二套实现。
- 守卫：`155-v471-resource-folders.cjs` 五条（RES471-1…5）。

### 2.6 策展台双栏拖拽

- `UIPrefs.wsConsoleSplit` 保存整数百分比，默认 62，钳制 32–72。
- 分隔条 `role="separator"`：Pointer 拖拽、方向键每次 ±2%、Home / End 到边界、双击复位 62%、持久化 `saveUIPrefs`。
- 布局由 CSS 变量驱动：左栏最小 320px、右栏最小 340px，并以 `100% - 352px` 封顶防溢出；≤900px 自动上下堆叠并隐藏分隔条。
- 比例只进本机界面偏好，不进入业务云同步。
- 守卫：`157-v471-workspace-split.cjs` 九条（WSPLIT157-1…9）。

### 2.7 任务状态自定义

- **数据契约**：新增 `TaskStatusBucket`、`TaskStatusDef`、`TaskCard.statusId?` 与 `AppData.taskStatuses`；旧 `TaskCard.status` 保留为兼容语义桶。
- **默认三档**：待开始 / 进行中 / 已完成；只有 `task-done` 标记 `terminal`。
- **统一工具**：`shared/utils/taskStatus.ts` 提供排序、取状态、按 id 写入、完成切换与入库归一化；悬空 `statusId`、重复 id、非法颜色、零 / 多完成态都在入库边界收敛。
- **设置入口**：`TaskStatusEditor.vue` 支持改名、改色、排序、新增、删除迁移、语义桶与完成态；完成态有且只有一个。
- **消费面**：任务详情状态菜单、看板列、月历标签与颜色、任务池状态筛选、项目全貌、旧 `/deck/task` 兼容页共用同一套定义。
- **颜色边界**：自定义颜色只作识别色；文字继续使用主题色，保证四主题对比度。
- **同步**：`taskStatus` 记录类型进入云同步 manifest、计数、回执与三方合并；合并结果统一归一化。
- 守卫：`151-v471-task-status.cjs`（10 条）与 `158-v471-task-status-ui.cjs`（7 条）。

### 2.8 安排历程主模块

- `PlanScheduleHistory.vue` 重设计为纵向时间轴：
  - 当前计划 chip；
  - 安排次数与最近安排时间；
  - 每次安排的节点、改期链、操作时间与来源标签；
  - 最新一条强调；
  - 单条删除 + 撤销；
  - 超过 5 条显示全部 / 收起；
  - 空态明确说明从本版本开始记录。
- 任务详情：安排历程位于首屏，先于项目 / 指标；日期编辑收入主模块；「设为今日重点」降为次级链接；新增「取消排期」。
- 选题详情：同构重排，安排历程在成果出口之前；日期与状态收在同一编辑行。
- 删除只写事件墓碑，不改当前计划日期。
- 守卫：`156-v471-plan-history-hero.cjs` 七条（HIST156-1…7）。
