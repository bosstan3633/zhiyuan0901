## 二、F38 落地明细

**用户可见行为**：仪表盘页头右侧多一枚 `👁 高亮可交互`，点开之后这一屏**每一个能点的地方**都被 accent 虚线圈出（热力格 / KPI / 规则行 / 下钻卡 / chip / 各按钮），再点关闭。

- `GlobalSettings.vue`：页头工具条按钮 + 面板根 `:class="{ 'dz-hl': dzHl }"`；状态**持久化在 `UIPrefs.dzHl`**（`saveUIPrefs`，跨会话记住，默认关）——不是会话态，因为"我这块界面看不懂能点哪"是反复发生的需求，不该每次回来重新开。
- `dashboard.css`：`.dz-hl :is(...)` 一组选择器覆盖原生可交互元素（`button/a/input/select/textarea/[role=button]/[tabindex]`）+ 仪表盘里用 div 挂 `@click` 的那批类名。**用 `outline` 不用 `border`**：圈出来不该把版面挤动一像素；颜色只取 `var(--accent)`（四主题各自取色，零硬编码）。
- 未来日的热力格是 `disabled button`——它不是交互点，给**虚点**（dotted）表示"看得见但点不动"，与"漏圈"区分开。

**判据是硬核的**：theme-audit 新增 `dz-hl` 场景（第 8 个仪表盘场景，四主题共 **64 → 68 图**），量的是「圈出数 == 面板内全部可点元素数」，差一个即红。首轮就抓到 313/406 —— 一量发现差额 93 个全是 disabled 的未来格（按设计走虚点），**是判据写错不是代码写漏**；改成"可点数排除 disabled + 禁用数另计"后四主题 **313/313、314/314 全中**。场景量完当场把开关关回去，免得后面所有截图都带着虚线。
