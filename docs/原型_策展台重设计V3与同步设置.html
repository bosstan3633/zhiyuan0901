⇄ Airtable 同步
单向同步：知源 → Airtable。以知源卡片字段为准，自动在目标表创建缺失字段。 同步范围涵盖调度台好奇心卡、方向台任务卡、资源台资源卡，以及你新建的每个策展台。
🔗 连接配置 仅本机存储，不经过任何中间服务
获取方式
新建表
申请 PAT
令牌需要 3 个 scope：data.records:read、 data.records:write、schema.bases:write（自动建字段用）。 另外，建字段要求账号是该 Base 的 Creator —— 若提示 403，说明你是 Editor，需要在 Airtable 里手动先建好列。

知源字段Airtable 列名类型表内状态说明
自动建字段规则：同步前先 GET /meta/bases/{base}/tables 读现有 schema， 按列名比对；缺失的列用 POST /meta/.../fields 创建。 已存在的列不改名不改类型（避免破坏你在 Airtable 里的视图与公式）—— 只有类型冲突时才提示你手工处理。 公式 / 汇总 / 查找列是 Airtable 的计算列，API 建不了也写不了，知源不会去碰。

每 3 小时自动轮询
用 chrome.alarms 唤醒，在 Service Worker 里跑，不占用页面主线程；实测不卡 UI 才建议开
空闲时补推
切换页面或静置 30 秒后，若有待推送则静默补一次（5 秒内完成）
为什么默认不开轮询：MV3 Service Worker 空闲 30 秒就会被浏览器回收，3 小时轮询未必每次都能跑完； 且每次轮询要消耗 API 配额。所以默认手动 —— 你按快捷键即可，零延迟零风险。 先跑一段时间手动，确认不影响流畅度后再打开 3 小时轮询。
