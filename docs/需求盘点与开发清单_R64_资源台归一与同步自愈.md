## 二、Airtable 同步 Bug 排查结论（用户报：删除 Airtable 记录后再同步报 422）

**现象**：`Airtable 422: Record ID recAOGukf8MpdYphQ does not exist in this table`，之后同步一直失败。

**根因**（airtable.ts:324-341 实证）：
1. 本地 `airtableMap` 持久保存 recordId；用户在 Airtable 端手删记录后映射过期。
2. 同步时 `map[row.key]?.recordId || remote.get(row.key)` **map 优先**，拿已删 id 发批量 PATCH。
3. Airtable 批量 PATCH 中任一 id 不存在 → **整批 422** → runSync 抛错中止，游标不推进 → 该卡 `updatedAt > cursor` 每轮重试，永远撞墙，后续卡也全被堵死。

**修复方案（三管齐下）**：
- **R1 远端索引优先**：`remote.get(row.key) || map[row.key]?.recordId`——远端实测存在的 id 才可信，map 仅兜底。
- **R2 422/404 自愈降级**：批量 PATCH 失败且错误含记录不存在语义时，该批**逐条重试**；单条仍报不存在 → 转 POST 重建，新 recordId 写回 map。用户无需任何手工干预即自动恢复。
- **R3 批隔离**：单条重建失败不再拖垮整轮同步（错误记 log，其余卡继续推）。

## 五、验收路径（真机）

1. 加载 dist → 调度台：方向状态显示「N 战略目标 / M 项目推进中」；三件事无提示条、纵向紧凑。
2. 制造一次同步失败（改错 Table ID 同步一次再改回）→ chip「同步出错」→ 点击直落设置同步分区 → 日志见具体原因 → 立即同步恢复后错误清除。
3. 在 Airtable 手删几条记录 → 立即同步 → 自动重建、无 422、映射写回。
4. 镜像一张卡到策展台 → 同步 → Airtable 中出现两条独立记录（资源台/策展台各一条，所属工作台列不同）。
5. 资源台：原工具库/JS工作/教育AI/内容工程/策展 的分类树出现在资源台根下同名根分类内，导航仅剩 调度台/方向台/资源台 + 用户新建台；Ctrl+Shift+J 默认落资源台。
6. 策展台：卡片视图默认树状嵌套分组，卡面见路径徽标；金字塔有连线、点空态可弹窗创建中心论点、hero 已删、指标单行。
