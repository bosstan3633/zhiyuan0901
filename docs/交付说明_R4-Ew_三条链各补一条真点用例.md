## 二、三条用例：每条都真点、都核库或核形状

- **E2E-40（①采集保存链路）**：本地 `http.createServer` 起一个宿主页 → `worker.evaluate` 发 `chrome.tabs.sendMessage(tab, {type:'zy-open-capture'})` 唤起浮层 → 等 `#__zy_cap_ws__` 就绪 → 读台下拉**默认选中值**与**选中项的可见文本** → 填标题 → **真点 `#__zy_cap_save__`** → 核三件：回执 toast 命中 `/已入台/`、落库那张卡 `workspaceId === 'zy-curation'`、`categoryId` 留空（进池即未归档，R4-Ep 的口径）。事后删探针卡、关服务。
- **E2E-41（②hover 动作区）**：故意**自己种两张探针卡**（词面不靠库里现成的卡——E2E-38 的教训：锚点随库变化会搜不到，那一屏就退化成"什么都没测"）→ ⌘K 搜探针词 → 核三枚钮 title 齐（星标 / 删除 / 打开链接）→ 先确认**探针行本身不是选中行**，再测它 `.gp-ri-actions` 的 opacity：hover 前 `=== 0`、hover 后 `> 0.9` → 点星标后**回读 storage** 得 `starred === true`，再点一次回读得 `false`（真写库 + 真复原，不是只看 DOM 类名翻转）。
- **E2E-42（③下钻抽屉）**：`.mb-cell` 逐格点 i=0/2/3/4，每格核**标题对得上** + 有行或有空态 + 说明行（`.md-tip`）在 + WCE/WRR 两格带计数行（`.md-head-count`），并按**每格自己的动作面形状**判：前三格 = 每行一支「定位 ›」（`.md-go` 数 = 行数），未归档 = 每行两支归档下拉（`.md-select` 数 = 行数 × 2）。

第 2 格（推进项目）**没重复开**：它和战略目标都走 `openCell('dhi')`，抽屉标题同为「战略目标 / 推进项目 · 明细」，是同一种形态，再点一次只是把同一段渲染测两遍。

## 五、本轮被机制抓住的四处（都是测试脚本自己错，不是产品）+ 一起**没人报**的还原事故

1. **MV3 的 http 宿主页里没有 `chrome.storage`**。第一版在采集用例里写 `capPage.evaluate((t) => chrome.storage.local.get(...))`，当场 `Cannot read properties of undefined (reading 'local')`。浮层自己是通过消息与扩展侧通信的，测试要取库必须**回扩展页**。
   这条不只固化成判据（R4-Ew② 的负锚），**经过本身也写进了脚本**：`e2e.cjs` 里那次取库的上方压着三行记账注释，注释原样带着那串错写法。于是多了一条要防的事——判据若读原文就会被自己的注释打红，所以它读 `codeOnly()`；W6 就是把 `codeOnly()` 摘掉来证明这层依赖成立。
2. **宿主页端口不能写死**。改成 `listen(0, '127.0.0.1', r)` 现取、用完关；theme-audit / perf 也是同一手法各自起，写死会互相撞。
3. **`.drawer, [class*="drawer"]` 会先命中遮罩** `.drawer-overlay`（无文本），标题永远读不到 ⇒ 下钻的「题在」恒假。改成只读 `.drawer-title`。
4. **探针行不等于选中行**。⌘K 面板的默认 `.selected` 落在别的行上，第一版把探针行当成"选中态样本"去测，hover 前 opacity 读出 1，判成"动作区一直可见"——那是测错了对象，不是产品有问题。改成先核探针行**未选中**，再测它自己的 opacity。

**★还原事故（这轮唯一"没人报"的一次，靠自己盯 sha 才抓住）**：我把 `98-r4-gates.cjs` 的备份取在**改尺子之前**，跑完 W7b 用那份备份还原 ⇒ **① 的 `codeOnly()` 被一起抹掉了**，而回归照样 **1,632/0**——两种读法当下都是绿的，任何门禁都报不出来。
发现和纠正的过程：还原后 `grep` 那一行的实际内容，看见是 `fs.readFileSync` 而不是我刚写进去的 `codeOnly(...)`。
纪律（这是 [[feedback-negative-assertion-discipline]] 里 R4-Dm 那条"备份必须当场命名 + 逐字节校验"的**第二次同形事故**，教训要加严）：**探针开始前取的备份，只能用于"本轮未改动前"的状态；本轮后续又改了同一文件时，必须重新取备份或改用 `git stash`之外的显式重放**，且还原完必须**逐条 grep 本轮写入的关键符号**（本轮是 `codeOnly`）确认它们还在，而不是只看回归绿不绿。

## 七、边界如实

1. **WCE / WRR 两格本轮走的是空态**（行=0）。形状判据 `r.loc === r.rows` 在 `rows === 0` 时被短路 ⇒ 这两格证到的是"抽屉 + 标题 + 说明行 + 计数行 + 空态"，**没证到"有行时每行挂定位"**；有行的形态由战略目标（2 行 / 2 定位）与未归档（1 行 / 2 下拉）两处真实覆盖。要在有数据态下补，得给 WCE/WRR 种事件夹具。
2. **命中性仍未证**。星标钮是点 handler 不是点坐标——`.gp-ri-actions` 在面板里被 tab 条挡住（E2E-38 早就写明，本轮照做）。所以"真机鼠标能不能点到"这件事本轮依旧只由 theme-audit 的像素侧兜，而 theme-audit 的 hover 取景**没有扩**（挂 #125）。
3. **普查对这三条面的覆盖是"两种缺失"**（别混着说）：① 采集浮层的**类名在册**（R4-En 起浮层页被包进普查），但**"点保存之后"的画面没有场景拍过**——所以第四票对"保存链路"这件事是零贡献；② 下钻抽屉整族 `md-*` **不在册**（2026-10-03 那份 831 token 里 `md-row` / `md-tip` / `md-select` / `md-go` 一个都没有），因为**没有场景把抽屉拍开过** ⇒ 这批规则的 CSS 只有静态三票在兜。本轮补的是运行时断言，不是像素证据；若某个类只在未拍到的状态下由 JS 拼出来，静态票 + 活体探针仍可能同时看漏（R4-Ev 边界①原样还在）。
4. **未归档没真归档**。只数了每行两支 `md-select` 控件在位，没做一次"选项目 → 选指标"的写库往返。
5. **采集落库只核了两件**（`workspaceId=zy-curation`、`categoryId` 留空）+ toast 文案。标题之外的字段搬运（描述 / 标签 / 链接 / 附件）是 E2E-38 那条转化链在管，不重叠。
6. 本轮**没动 theme-audit**，所以 `ai-modal-narrow` / `dz-report` / `ov-capture` 三族不可复现场景一个都没消解——那是 #125 的活；#117 popup 白屏、#114① 唤起阻塞的设计取舍仍等拍板。
