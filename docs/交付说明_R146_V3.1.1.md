## 一、回退契约九条（审计条目 1/5/6/7 收口）

产品承诺是"删除可恢复、操作有痕"，但审计发现**九条路径的兑现程度参差不齐**：有的没确认、有的确认了不报数、有的报了假账。本轮把它们拉成同一口径：**动手前报数 → 动手后 3 秒可撤销 → 回执点名是哪一条**。

| # | 位置 | 之前 | 现在 |
|---|---|---|---|
| ① | 方向树删目标/项目/指标 | 四视图各写一遍 `splice`，**无确认无撤销**，删错即整棵子树物理消失 | `shared/utils/compassCrud.ts` 真源：`compassNodeCounts` 报数（"其下 2 项目 / 5 指标 / 14 任务"）→ 确认 → 快照摘除 → toast 撤销**按原序号插回**；父已被删时如实返回 false 并点名，不静默造悬挂数据 |
| ② | 删成功指标 | 三处入口三套文案 | `removeMetricWithConfirm` 一处真源：确认里明说"N 个任务将转为未关联指标（任务本体不删）"，撤销连任务归属一起回填 |
| ③ | 删任务 | 五路入口口径不一（R141 已统一，本轮补检索浮层） | 检索结果行 🗑 改走 `softDeleteTaskToTrash`——**同时摘 `metric.taskIds`**，不再留脏引用（R141 双向不变量补齐） |
| ④ | 「删除策展台」**同名两实现** | 台签右键=静默 `archived=true`+卡搬家；⚙ 菜单=硬删台+卡软删。同名不同命 | 拆成两个具名动作：**📦 归档此台（卡移至待分类）** / **🗑 删除策展台（确认里报出"其中 N 张资源卡与全部分类将移入回收站"，删后 3 秒整台撤销）** |
| ⑤ | 回收站永久删除 | 直接删，无确认 | 必过 `useConfirm('永久删除')`，回执点名对象与类型：`🗑 已永久删除资源卡「待永久删除的卡」· 不可恢复` |
| ⑥ | 回收站批量恢复 | 每条各弹一次 toast，互相顶掉只剩最后一条 | 一次动作**一条账**：`♻ 已恢复 N 项（资源卡分区）` |
| ⑦ | Toast 本身 | **一条覆盖上一条**——批量操作的回执被物理截断 | 队列化：最多叠 3 条、同文案合并 `×N`、各条独立计时与独立撤销（`TOAST_DURATION=3000` 不破 REQ-030） |
| ⑧ | 设置「清除缓存」 | **假回执**：只说"已清除"，其实只清了个变量 | 点名清了什么：`✓ 缓存已清：12 篇网页正文 · 30 篇梳理抽读正文（卡片数据未动）`，读不到东西时如实说"没有需要清理的缓存" |
| ⑨ | 回收站入口 | 埋在「设置 → 重置与回滚 → 危险操作区」里 | 常驻设置页左栏「数据」组（导航项支持路由出口，深链 `?page=recycle` 不落空白面板） |

**冒烟实证**（`/tmp/zy_r146_smoke.cjs` U1~U4/U8/U9）：删指标 2 任务摘归属一条不删 → 撤销回原位并双回填；删台 3 卡+1 分类全软删、撤销后 3 卡复活；归档 3 卡搬它台待分类、零软删；toast 状态层与 DOM 双口径都是 3 条上限、`甲一条×2` 合并成立；永久删除确认框点名对象。

## 二、「知」镂空徽标：全站 AI 入口换脸（你点名的第一件事）

**做了什么**：新增 `src/shared/components/ZhiMark.vue`——一枚**缺口圆环里嵌描边「知」字**的纯 CSS 徽标，静止时是入口图标，`:spin` 时转起来（1.1s 一圈，`prefers-reduced-motion` 降到 4s）。全站 **13 个文件、约 30 处** AI 入口的 🤖 全部换成它。

**为什么是这个形状**：AI 入口的本质是"这里可以让它替你想一想"，不是一个机器人按钮。缺口圆环借了加载指示器的语言——**同一个图形同时回答"能点"和"正在跑"两件事**，这正好补上审计里"五处 AI 入口点了没反应"的缺口（本轮已给 资源详情×2 / 任务录入 / 卡 hover 优化 / 找佐证 补上互斥锁 + 转圈）。

**边界（说清楚，别一概而论）**：卡片正文里的 `🤖 中心论点 / 🤖 步骤清单 / 🤖 行动方案`、以及存库的 `🤖 深度洞察` 卡标题**保留机器人**——那是"AI 出品"的**溯源标记**，写在数据里、跟正则替换绑定，不是入口图标。改它会让历史卡的整段替换逻辑失配，属于为了好看砸掉正确性。断言 R146-5 用"全部 .vue 零 🤖"把这条边界钉死（.ts 里的数据前缀不受限）。

**设计细节备案**：试过纯 `transparent` 填充 + 0.5px 描边的真镂空，12px 下整个看不见；渲染四档对比后定为 **22% 淡填充 + 0.85px 描边**，小字号才立得住。

## 四、全局检索浮层两刀（你实测的截图）

### 1) 类型 tab 被 emoji 劈成两行
`🔍 搜全部` 在窄窗里逐字换行成"搜全/部"。根因不是宽度不够，是 **emoji 图标 + `flex-shrink` 默认为 1 + 无 `white-space` 约束**，标签被压到最小内容宽后从字间断开。
**改**：七枚 tab 全部去掉图标前缀（计数徽标已足够区分类型），`.gp-type-tab` 锁 `white-space: nowrap; flex-shrink: 0`，容器改 `flex-wrap: wrap`——**宁可整枚换到第二行，也不把词劈成两截**。
**验**：冒烟 U4a 量七枚 tab 的 `getBoundingClientRect().height` 与 `top` 全等（等高同排 = 没有一枚内部换行）。

### 2) 「AI 理解」点了就一直等
**真因**（不是网络慢，是设计留的坑）：
- 走的是**非流式** `chat()`，`maxTokens: 900`——模型一个字没吐之前，UI 只能挂着一句"… 理解中"；
- **无超时**：网关不回，就永远不回；
- **不可取消**：`if (aiBusy.value) return` 让第二次点击变成"没反应"，改词、关浮层也不中止，请求悬在那儿；
- 投料偏大：20 条命中 × 每条 60 字摘要，首字延迟直接吃这个规模。

**改**（`rerankSearch` 一处 + 浮层一处）：
1. `chat()` → **`chatStream()`**，`maxTokens 900 → 420`，投料 `20 → 14` 条、摘要 `60 → 40` 字；
2. **早停**：每次增量都试着解析，JSON 一闭合（`order` 已是数组）立刻 `abort()`——**不等模型把废话说完**；
3. **30 秒硬超时** + 外部 `signal` 可中止，错误文案点名（"30 秒无响应——换轻量模型"）；
4. 浮层侧：tab 上**每秒跳秒数、流式回字后追加"已回 N 字"**、徽标转起来；**跑动中再点一次=取消**（回执"已取消 AI 理解（未采用任何结果）"）；**改词/关浮层静默中止**（不打扰）；**同词同批命中走缓存**（≤12 条 LRU，清除后再点秒回）；
5. 精选组标题点名投料与耗时：`从 3 条命中里挑 3 条 · 13ms`——亚秒说毫秒，不把 13ms 报成"1s"。

**实测**（mock 网关故意在 JSON 之后继续拖 2.4 秒废话）：**13ms 落地**，尾巴被掐断；慢速路径下"理解中 0s · 已回 36 字"可见、取消回执到位、缓存 52ms 秒回。零写库不变（R136-1 的 `aiRerankRun` 段无 persist 断言继续把守）。

## 七、备案：本轮踩到的坑（都是测试侧，产品零错）

1. **`eval(STORE)` 在 `page.evaluate` 里不可用**——函数被序列化进页面，Node 侧闭包变量不存在。改为 `addInitScript` 注入 `window.__zyStore()`。
2. **toast 计数被离场动画骗过**：`<TransitionGroup>` 在 leave 动画期间旧节点仍在 DOM，60ms 时读到 4 条。改判两口径：状态层 `toastState.items.length === 3` 立刻读，DOM 等 700ms 后读。
3. **"理解中"抓不到，是因为它 13ms 就没了**：早停生效后快于任何轮询节奏。断言改成"要么看得见进度回显，要么快到不需要（<300ms）"——这才是用户真正要的性质，不是"必须看到转圈"。
4. **mock 网关原本不支持 SSE**，`chatStream` 全部走回退分支，早停路径根本没被覆盖。给 `/tmp/zy_mock_llm.cjs` 补了流式分支 + "JSON 之后继续拖 2.4s 废话尾巴"，早停才有证据；再加关键词「慢」触发挤牙膏模式，才测得出"跑动中取消"。
5. **U1 首跑红是测试数据错**：造任务时只写了 `metric.taskIds` 没写 `t.metricId`，摘归属当然是 0 条——产品行为正确，补上 `metricId` 后 2/2。
6. **`sed` 式批量替换又险胜一次**：给 RDD 补 `:disabled` 时写出重复属性，靠 typecheck + build 抓到（承 R139/R144 教训：字符级批量替换后必过 typecheck+build）。

## 八、请你真机复核的 6 个点（headless 测不了"味道"）

1. **删除报数的口气**：删一个有 14 个任务的战略目标，确认文案里的数字对不对、读起来慌不慌；删完 3 秒内点撤销，节点是否**回到原位**（不是跑到末尾）。
2. **「知」在小字号下的辨识度**：12~13px 时能不能一眼认出是"知"、是否显得比原来的机器人更"轻"；深色/浅色四主题下描边是否都立得住。
3. **AI 理解的等待感**：接你自己的网关（真实模型）跑一次搜索重排，看秒数回显是否让你愿意等、取消是否顺手；与改前"点了没反应"比，是不是解决了你说的那个问题。
4. **指标行/任务行的「知」是否显眼**：项目详情页里每个指标、每个任务都挂了一枚，会不会太吵？（若吵，第二刀把任务级收进 ⋯ 菜单）
5. **toast 叠 3 条**：批量恢复 20 条时是否读得清；`×N` 合并是否自然。
6. **归档 vs 删除**：台签右键菜单里两个动作的文案，能否让你不看说明就选对。
