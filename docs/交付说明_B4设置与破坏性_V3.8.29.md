### S2「组标题」一项的处理（如实说明）

规范原文写「表单组 caption 标题」。实际核对：**导航分组标题已是 caption 档**（`.gs-nav-group-title`，11px/700），设置页里没有"表单组"这一层结构；`.gs-card-title` 是**区块名**（16px/600），压到 caption 会让八区难扫读。
本批因此**不动卡片标题**——不是漏做，是判断「压到 11px 与『八区可扫读』冲突」，且无用户拍板。若要压，等于把设置页做成一整片小字，需要你点头。

> **★2026-10-18 更正（V3.8.30）**：上面那句「`.gs-card-title` 是区块名（16px/600）」**数字写错了，实测是 13px/600**（`var(--fs-body)`）。16 是在没有回源码复核的情况下凭观感写的，它让当时的判断显得比实际更激进。用户随后拍板「统一压小」，已在 V3.8.30 压到 caption 档（11px/700/正字距），三层组标题合并为同一套标签排印，详见 `docs/交付说明_S2组标题统一_V3.8.30.md`。教训：**凡要写进交付物、会被下一轮当依据的数字，当场 grep 一遍，不靠转述**。

## 三、顺带修掉的真缺陷

**① 设置页有两处空态是 B2 的漏网**
`G3`（空态唯一实现）在 V3.8.27 收口了 10 处，但 `GlobalSettings.vue` 里「该标签下暂无卡片」与「暂无同步记录」两处仍用旧裸类 `gs-ev-empty` 且带自己的样式。已改走 `EmptyState`（`size="inline"`）并删掉那条旧规则。
**为什么门禁没拦住**：`13-components.cjs` 的 `G3-4` 只钉 `<EmptyState` 的使用条数下限（≥12），没有反向清点"还有哪些旧类残留"。这类"下限式棘轮"天然只防后退、不防遗漏。

**② `theme-audit` 三个覆盖缺陷（本批新增一个场景才暴露）**
| 缺陷 | 现象 | 处置 |
|---|---|---|
| 主题下拉不在 `closeOverlays` 的识别范围内 | 展开态跨主题泄漏：raycast 的 `st-airtable` 截图里挂着一块打开的主题菜单；下一主题的 `act` 再点一次等于关掉 ⇒ `dz-theme-menu` 在 raycast/notion **交替判 0** | `closeOverlays` 补「点同一个按钮收回」，`act` 侧加幂等保护 |
| 池面板判据锚在 `.pcp-card / .pcp-empty` | 资源卡池的视图模式（网格/列表）**持久化**：上次 run 停在列表时两者都不存在 ⇒ `paneOn` 假红，且**只在每个 run 的第一个主题复现** | 判据锚补 `.pcp` 容器（语义本就是"面板在不在"），并幂等切回网格保证截图同构 |
| 池面板懒挂载 + 500ms 盲等 | 首个主题量到"面板还没进 DOM" | 改 `waitFor(.pcp, attached)`，超时才退回盲等；判据一条没放松 |

这三个都属于"工具只有在被换一种方式使用时才暴露假设"——与 B3 撞到的两个同源。

**③ PAT 回填是安全语义问题，不只是体验问题**
原先 `type=password` 给人的错觉是"密钥没暴露"，但 DOM `value` 一直是明文，选中即复制、截图工具/录屏/DevTools 都能拿到。B4 的改法让**页面里根本没有那个明文**。
