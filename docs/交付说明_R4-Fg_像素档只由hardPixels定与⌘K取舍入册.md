## 一、A 案：变化档只由 hardPixels 定，带宽只报不判

```js
if (r.hardPixels > 0) return { 档: 'changed', rows }
return { 档: 'jitter', rows, 带宽超阈: rows > JITTER_BAND_ROWS }
```

**为什么改**（R4-Fd/Fe/Ff 十对同构建连采的数据）：光栅层非确定性会产出「幅度 ≤7/255、摊在几百行上」的差，而 `scene-state` 逐点全同 ⇒ 旧规则（带宽 >8 行也算变化）下**同一份产物两跑每对必红 1–3 张**，像素 A/B 就当不了门禁。

**没动的部分要说清**：`HARD=6`/`TOL=6` 这条腿**一个字没改**——它才是防"整片调淡"的闸（R4-Ex④ 随迁时把这个分工写进标题）。A 案砍掉的只是"带宽单独定变化"这条腿。

**买到什么、没买到什么**（落地后第一次实测：改前基线 vs 新 dist 全量 104 张）：

```
⇒ 成对 104 张：0 差 97，抖动 6，有变化 1
    notion-dashboard.png    6 px  差异带高 611 行  单通道最大差 6  带宽超阈(>8 行，A 案计入抖动；要严用 --strict)
✗ raycast-dz-entry.png      变化像素 3  …  单通道最大差 7
    └ 归因：非位移、非单侧色偏（幅度 7）⇒ 要人看 … DOM 态：一致 ⇒ 差异只在光栅层
```

- **买到的**：`notion-dashboard` 这一类（6 个像素摊在 611 行、幅度 6）从"红"落到抖动档，**并且照样把带宽报出来**、附上"要严用 `--strict`"——不是静默放宽。
- **没买到的**：`raycast-dz-entry` 有 3 个像素幅度 7 > HARD 6，**A 案不动 HARD 所以它仍红**。今天 10 对里这类每对约 0–1 张。要再降只剩 B 案（HARD 6→8），代价是放过 7–8/255 的令牌色差（四主题走查里那是有意义的最小单位）——**这条本轮没做**，写在 #132 的收口记录里备用。

## 二、⌘K 那一帧：拍板结论落到用户读得到的地方

手册「全局检索」章节新增一条：

> **唤起那一帧的取舍（明写在这是为了让它不是暗病）**：面板遮罩用毛玻璃（`backdrop-filter: blur(20px)`）+ 自动聚焦输入框，实测唤起后会有一帧约 **100ms 的渲染阻塞**——发生在面板打开之后、不影响你开始打字与检索。本项目的拍板是**保留毛玻璃、接受这一帧**：它是四主题观感的一部分，而省掉它要动的是遮罩合成分支，代价是观感一致性。

判据 **R4-Fg②** 钉住这句话的三个语义片段（现象 / 结论 / 不影响打字），锚的是片段不是整句——**改文案不必重指，但少一个语义就红**。

★**一条取景覆盖面的实话（本轮新量到，别让它成为暗账）**：这条 li 在手册页**折叠下方**，`st-manual` 截图是视口档（1440×900、`scrollY=0`），所以像素 A/B 对这次产品改动报 **0 差**。⇒ 用户可见文档的正文改动靠的是**源码锚**（R120-5 / R4-Fg②），不是视觉门禁；如果希望视觉门禁也能看到手册正文改动，得给 `st-manual` 加分节滚动场景（未做，成本是每主题多几张图）。

## 三、判据与随迁

  ★这条锚第一轮就红在我自己手上：注释锚用 `codeOnly` 读会被剥掉 ⇒ 判据恒红。同一轮里 R4-Fg② 的负锚也因"旗标名写在字符串里"红过一次（见 R4-Fe 第五节）——**两种读法各管一件事，别混成一个 read**。

## 五、边界如实

1. **A 案不是"噪声变小了"**，是"带宽这条腿不再单独定变化"。光栅层非确定性一点没少，只是不再每对都红；`--strict` 与「带宽超阈」标记都留着，要严随时能切回去。

3. **手册那条 li 视觉门禁看不到**（折叠下方）。它的证据面是源码锚 + 真机阅读，不是截图。
