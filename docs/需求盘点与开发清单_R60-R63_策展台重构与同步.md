## 二、⚠️ 关键发现：取消灯塔会让 DHI 分母失效（必须同轮处理）

这是本次盘点最重要的发现，你的两条需求实际是**同一件事**：

```ts
// newtab/stores/compass.ts:159-172
const pinnedProjects = projects.filter(p => p.pinnedToLighthouse)   // ← 分母来自"投射"
const dhiPct = pinnedProjects.length ? Math.round((activeProjects / pinnedProjects.length) * 100) : -1
```

**DHI = 在轨项目数 ÷ 已投射灯塔的项目数**。删掉 `pinnedToLighthouse` 字段，分母直接归零，DHI 会永久显示「—」。

**好消息是有现成替代**：产品里同时存在两套语义重叠的开关——

| 开关 | 字段 | 现状 |
|---|---|---|
| 投射灯塔（你要删的） | `pinnedToLighthouse` | DHI 分母、首页灯塔区、主航线 📡 |
| **主攻** | `isFocused` | `focusedProjects`（compass.ts:68-70）+ `toggleFocusProject`，**语义完全覆盖投射** |

所以：**删投射、保留主攻，DHI 分母改用 `focusedProjects`**，语义还更准（"我认定的重心项目，有多少真在推进"）。

## 三、DHI 计算规则优化方案

### 现状问题（4 条）

1. **分母依赖投射**（上节），投射一删就失效。
2. **窗口口径不一致**：`dhiDays = week ? 14 : …`（:160），而 WCE/WRR 的 `days = week ? 7 : …`（:150）。同一周期档下 DHI 看 14 天、其他指标看 7 天，用户无法理解。
3. **在轨判定过松**：「有 doing 任务」即算在轨（:166）。一个项目挂了 1 个 doing 任务后放半年，仍算 100% 在轨——**只反映"有没有"，不反映"是否在推进"**。
4. **空态无引导**：无投射项目时显示「—」（:171），用户不知道该去哪设置。

### 建议新口径

```
DHI（方向契合度）= 在轨主攻项目数 ÷ 主攻项目数 × 100%

在轨判定（满足任一）：
  ① 窗口内有任务完成（completedAt 在窗口内）
  ② 有 doing 任务 且 该任务 updatedAt 在窗口内      ← 新增：防"挂着不动"
  ③ 项目下任务已全部完成（保留 R55 修复：做完即掉分不合理）

窗口：日 = 今日 / 周 = 近 7 天（与 WCE、WRR 统一）/ 累计 = 全部
档位：清晰 ≥75% / 关注 ≥40% / 模糊 >0 / 未启动 = 0
空态：无主攻项目时显示「未设主攻」+ 跳转方向台设定（不再显示「—」）
```

**改动点**：`compass.ts:155-172`（计算）、`:203`（副标题 `${dirs.length}方向·${focused.length}主攻·${active}在轨`）、`:214`（公式文案）。

### 可选增强（需你拍板，默认不做）

**投入契合度**：现有 DHI 只衡量"在不在轨"，衡量不了"方向对不对"。可增加子指标——

```
方向投入分布 = 窗口内完成任务中，归属主攻项目的比例
```

避免出现「主攻项目都在轨，但 80% 精力花在非主攻的杂事上，DHI 却显示 100%」。
如采纳，作为 DHI 下钻抽屉里的第二行展示，不改变主数字。

## 五、模块 B：金字塔挂载类型限制

**规则**：L2–L4 节点内**只允许挂资源卡**（`kind === 'resource'`），任务卡与好奇心卡不得挂入。

**实现**：三处加校验，统一收敛到一个判定函数 `canMountInNode(card, node)`：

| 入口 | 位置 | 校验 |
|---|---|---|
| 拖拽挂卡 | 策展台 drop 处理 | 非 resource → 拒绝并提示"金字塔节点只挂载资源卡" |
| 节点内新建卡 | 「＋在此节点新建卡」 | 新建卡默认 resource，不提供类型切换 |
| 从资源台镜像 | 镜像分类 | 资源台内只有资源卡，天然满足 |

**连带影响**：`CurationCenter.vue:204 mixedCardsOf` 目前混排"原生 + 投射 + live"三类，重构后需确认三者是否都收敛为 resource（任务/好奇本就不该出现在此链路）。若历史上存在误挂数据，需加一条启动期迁移：把非 resource 卡从策展台节点摘出，回落到资源台/原归属。

## 八、模块 E：Airtable 单向同步（按你的确认落地）

**已确认前提**：你是该 Base 的 Creator → `schema.bases:write` 可用 → **自动建字段可落地**。

| 项 | 方案 |
|---|---|
| 方向 | **单向**：知源 → Airtable |
| 字段 | 以知源为准，缺失自动创建；**已存在的列不改名不改类型**（避免破坏你的视图与公式）；formula/rollup/lookup 计算列不碰 |
| 同步范围 | 调度台好奇心卡、方向台任务卡、资源台资源卡、各策展台（镜像 + 台内）+ 主题卡 |
| 区分方式 | `卡片类型`（资源/任务/好奇心）+ `所属工作台`（资源台/策展台名/调度台/方向台），另加 `金字塔层级路径`、`层级`、`是否中心论点` |
| 触发 | **手动为主**（设置按钮 / 首页卡片 / 浏览器快捷键）；3 小时轮询开关默认关闭 |
| 状态展示 | 调度台首页右上角常驻卡片：上次同步时间 / 已同步数 / 待推送 / 耗时·调用数 |
| 删除 | 软删同步 → 置「已删除」勾选，**不物理删** |

**技术约束（已核实）**：
- 自动建字段：`POST /v0/meta/bases/{baseId}/tables/{tableId}/fields`，scope 需 `data.records:read` + `data.records:write` + `schema.bases:write`
- 限流 5 req/s / base，每批 ≤10 条，429 退避 30s；**Free 版每月仅 1000 次调用，需 Team 及以上**
- PAT 明文存 `chrome.storage.local`（零云端立场，随设备不跨端）
- manifest 已声明 `<all_urls>`，**无需新增权限**

**快捷键（Chrome 硬限制）**：MV3 无 API 可在扩展内改快捷键，唯一途径是跳 `chrome://extensions/shortcuts`；每个扩展最多 4 个默认键（**已被 调度台/采集/搜索/好奇 占满**）。
→ 新增 `sync-airtable` 命令**不配默认键**（沿用项目现有模式，见 `manifest.ts` open-settings/open-compass 等），设置页用 `chrome.commands.getAll()` 读取实际分配值回显。设置页已有 `shortcuts` 分区与 `shortcutsUrl`（`GlobalSettings.vue:495-535`, `:752`），**加一行即可**。

## 十二补、决策 A 带来的重要简化：R61 几乎零数据迁移

原方案 A 要求「所有卡的真身迁往资源台」，风险最高。改为决策 A 后：

| 现有实体 | 重构后 | 数据动作 |
|---|---|---|
| 策展中心（虚拟台 `zy-curation`） | **资源台** | 其原生卡原地成为资源台资源，**零迁移** |
| 各工作台 `Workspace` | **策展台** | 台内卡原地不动，语义天然就是「台内新建卡」，**零迁移** |
| `curationProjections`（现：工作台 → 策展中心） | **资源台 → 策展台** | 方向反转；现有记录可在迁移时**直接清理**（源卡本就留在自己的策展台里，不需要镜像到资源台），无数据丢失 |

**结论**：R61 从「高风险全量迁移」降级为「概念重命名 + 镜像方向反转 + 层级放开」，迁移风险大幅下降；但仍保留「迁移前自动备份下载」的既有约定。
