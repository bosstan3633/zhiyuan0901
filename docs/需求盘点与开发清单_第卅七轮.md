## 一、REQ-042 搜索抽屉升级（从只读预览 → 可编辑）

### 现状核查（第卅六轮交付物）

| 项 | 第卅六轮 ResourceDetailDrawer | 缺口 |
|---|---|---|
| 容器 | 自绘 `.rdd-*` 遮罩 + 抽屉（Teleport body） | 与 ProjectDetailDrawer 的共享 Drawer.vue 两套皮肤，体感不一致 |
| 编辑 | ❌ 只读预览（无任何 input/select） | 改工作台/分类必须跳工作台 |
| 删除 | ❌ 无 | 破坏性动作无处安放 |

### 落地清单

| # | 改动 | 文件 |
|---|---|---|
| 1 | 容器换共享 `Drawer.vue`（open/title/footer 插槽 + Esc 关闭） | `ResourceDetailDrawer.vue` |
| 2 | 完整编辑表单：标题/链接类型/链接/工作台 select/分类 select/TagPicker/注解/挂载任务/时间戳 | 同上 |
| 3 | 工作台切换 → 分类联动重置（REQ-005 口径）；保存检测跨台迁移并 Toast | 同上 |
| 4 | 删除 = 软删 + 撤销（按 id 定位当前树） | 同上 |
| 5 | 打开走统一通道 `toOpenableUrl` + `recordResourceOpen` | 同上 |
| 6 | 保留抽屉总线（kind='res'）+ 定位高亮 | 同上 |

### 调研结论：第三方页就地抽屉不可行

1. `content/search-overlay.ts` 注入第三方 DOM，Vanilla JS，无 Vue 上下文
2. newtab bundle 不在 `web_accessible_resources`（manifest 仅暴露 popup + assets）
3. iframe 方案引入权限/样式/通信新坑，性价比极低
4. 现有链路（sendMessage → background → zy-route → App.vue → 抽屉总线）已实现"切回工作台 + 落地展开 + 高亮"
