## 二、拆分机制（为什么历史断言能一处不改）

本批沿用项目已有的**聚合读层**（`v2/scripts/regression/helpers.cjs` 的 `COMPONENT_AGGREGATES` 表 + `CONTENT_SRC_FILES`
+ GlobalSettings 的 `settings/` 目录聚合）：宿主迁走样式或子域后，历史判据从宿主路径读取时，`read()` 仍返回
「宿主 + 拆出成员」的完整源码——**结构优化只改物理位置，不改判据语义**。

- `PREPEND_AGGREGATES`：`repository.ts` 的 `legacy-normalize.ts` 需排在宿主正文**之前**，否则 P0-2 的 `slice(indexOf(...), indexOf(...))`
  会起点大于终点、切出空串。
- `CONTENT_SRC_FILES`：content 三文件（search / capture / query）按「采集域在宿主之前、搜索域在纯函数域之前」的
  原始先后拼接，保证 `fnBody(head, next)` 的先后关系不破。
- 少数确需改判据的，逐条**随迁带备案**（判据标题写明「★R181 随迁带备案」+ 理由）：`10-foundations`（`zy-locate-workspace`
  网页端锚迁到 `overlay-capture.ts`）、`98b-r4-visual`（R4-Fb① 负锚豁免）、`98-r4-gates`（R4-Dm 表、R4-Eq changelog 分片计数）、
  `95-R161-R166`、`40-v2.47-v2.59`、`97-r3-rounds`、`02-w8-compass`、`04-w12-restore`、`07-w13-profile`、`80-R120-R143`、
  `70-perf112`、`12-w17-profile`、`06-compass-v3822`、`20-req39-64`、`100-p0-gates`、`11-p0-strings`、`102-g09-experience` 等。
- 入口矩阵（`entry-matrix.cjs`）：`shared/ai/jobs/registry.ts` 的 hosts 随域逻辑下沉更新（`useGlobalPopupsSearch` / `useGlobalPopupsCapture`、
  `useGlobalSettingsPanels`、`useCompassTree`、`useGlobalSettings`、`useProfileInsightsTags`、`useCompassHome` 等）。
- 老库体检夹具（`shared/storage/__fixtures__/legacy-fixture-run.cjs`）：尾锚从 `//repository.ts` 改 `//legacy-normalize.ts`（该函数现为文件末导出）。
