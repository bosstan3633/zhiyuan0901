设计说明（模型与边界）

1. 子任务模型（按你的倾向定稿）：内嵌内容，非独立卡

  • TaskCard.subtasks: [{ id, title, done, note? }]——子任务是这张卡自己的字段（像说明/标签一样），不是 TaskCard 实体：不进任务池、不占指标 taskIds、不参与看板拖拽/周报计数/回收站，天然不违反「卡间零挂载」（零引用，非关系记录）。
  • 与现状差异：R144-a 的 parentId 软层级把子任务做成独立卡（平铺+↳ 记号）。本方案把「拆解采纳」的去向从建卡改为写入本卡子任务清单；任务调度模块（列表/看板/分组）不再出现游离子卡，父卡自带「1/2」进度角标 + 就地展开清单。
  • ⚠ 存量迁移（待拍板 D5）：现库中 parentId 子卡 → 建议启动期幂等折叠进父卡 subtasks（title+done 平移，原子卡软删进回收站并带说明，可撤销）；无父可折的升为普通任务。
  • 连带退役：详情头「↳ 父名/⤴ 升顶层」徽标、删父升顶层、子不陪葬等语义随独立卡模型一并简化——子任务生命周期完全跟随父卡。

2. AI 三入口（任务详情标题行工具组，各自三态）

  • 补全（新）：按标题+现状补齐缺项——验收标准写入说明、建议标签、建议归属项目/指标、估时；勾选采纳才写库。
  • 拆解（改造）：评审抽屉双通道去向——「✓ 采纳为子任务清单」=写 subtasks；「📝 步骤写进详情」=纯文本进说明（R139 secondary 原样）。
  • 找资源（新）：盘点资源卡→推荐→勾选采纳=写 SupportLink { taskId, subId?, resourceId }；子任务行可挂自己的 🧭 支持（subId 定位）。
  • 三态共用一枚 chip：「🤖 最近：补全 · MM-DD HH:mm」；跑中仅该钮转圈+互斥。

3. 资源支持（关联表，红线不动）

  • 双向显示=反查：任务详情「资源支持」区（点行=打开资源链接+计热度）；资源详情「支持的任务」区（只读，解绑入口留任务侧）。
  • 解绑只删记录，绝不动卡本体；任一端软删→显示过滤，物删→purge；撤销窗口随卡回挂。

4. 待拍板

  • D5 存量 parentId 子卡折叠迁移（推荐：折叠+回收站可撤）。
  • D6 子任务完成是否影响成熟度/周报（推荐：本轮都不接，子任务纯执行工具；要接单独拍）。
  • D7 好奇卡 fromCuriosityId：已拍板删除（好奇零关联，转化即出路）。
