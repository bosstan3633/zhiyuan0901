## 一、#130 归因：那 368 个像素是**字形渲染模式**不同，不是内容变了

R4-Fc 收口时像素 A/B 报「0 差 99 / 抖动 4 / 变化 1」，唯一那张 `notion-deck-pool-list.png`：变化像素 368、单通道最大差 7、差异带高 262 行、包围盒 `184,491,389,512`。裁出来两枚标签胶囊文字完全一样，只是背景整片暗了约 4–7/255。

三步把它钉死：

1. **活体探针**（`/tmp/zy_fd_probe.cjs`，同页连采四次同一区域）：区域像素哈希四次全同、`.pcp-row` 行数 60 不变、首行 y=361.297、动画数 0 ⇒ 简化流程里复现不出来，且**列表几何落在小数像素上**（行高 36.797）。
2. **位移抵消测试**：把 B 平移 ±1/±2px 十种方向重数差异 —— `0,0` 就是最小值 368，平移 1px 反而涨到 1,395–2,259 ⇒ **几何完全对齐**，排除"整片挪了位置"。
3. **色偏统计**：372 个差异像素里，一侧 `|R−B|>3` 全中（376 个，平均 4.98），另一侧**一个都没有**（0 个，平均 2.94）⇒ 两侧用了不同的文字抗锯齿模式：**LCD 子像素 vs 灰度**。Chromium 在图层被提升期间会退回灰度，所以同一份产物两跑可能一边一种。

处置：取景侧加 `--disable-lcd-text` 钉成灰度。**与 R4-Ex 撤掉的那三条渲染路径旗标的区别是这条有实测成因**（那三条是猜，量下来没消抖反而让 st-manual 整页不同）。验证两条：
- 钉完连采两跑（notion 单主题）：**0 差 25 / 抖动 1 / 变化 0**；
- 钉完的图与**本来就是灰度**的历史归档逐张比：`notion-deck-pool-list` **0 差** ⇒ 旗标没有改变常见形态，只是把例外堵死（历史基线不必重拍）。

## 二、顺手量到并钉掉的第二条轴：光标在闪

钉灰度后重拍全量，`notion-ov-search` 从"变化"名单里消失，但另一对里露出同族新形态：**62 px、只有 1 行、幅度 30、色偏只在一侧**（`422,186–483,186`）。那是搜索框**光标在闪**，截图赶上"亮/灭"两个相位——光标闪烁不是 CSS animation，calm 那条 `animation/transition:none` 管不到它。
处置：calm 的 style 里补 `caret-color:transparent !important`。静照里本来就不存在"正在闪"这件事，与关动画同类，**产品一行没动**。

## 三、#127 定性完成：`st-manual` 的"整页跳变"是**整片挪 1px**

同构建两跑全量成对判（钉完两条轴之后）报出 `linear-st-manual.png`：变化像素 **93,410**、差异带高 842 行、包围盒 `0,58,1439,899` —— 与 R4-Ex 记的 raycast 那次（93,912 / 842 行 / `0,58–1439,899`）同形。这次由 `--why` 直接判出来：

> 几何位移：把 B 平移 `0,-1` 后变化像素 **93,410 → 1,440** ⇒ 整片挪位置，不是内容变

即**手册页在 y=58 以下整体下移 1px**。R4-Ex 当时只能记"偶发、成因未定"，现在定性完成；**没做完的是点名是谁多占了那 1px**：活体探针同页重进 6 次几何完全稳定（`mn-head` y=48/h=52、文档高 23,376.16、字体 loaded）⇒ 单靠重进页面复现不出来，需要完整会话态。做法已写进 #127：给 st-manual 场景加一条"y≈58 那条线上元素的 rect 记账"，两跑对比即可点到元素。

## 四、把归因收进尺子：`img-diff --batch … --why`

原先这三步是我手写的 /tmp 探针（位移抵消、色偏、幅度），**收进 img-diff**，红的时候直接告诉你它红在哪一类：

| 归因档 | 判据（实测分界写死在代码里） | 处置方向 |
|---|---|---|
| 几何位移 | 非零平移能把变化像素压到 `0,0` 的 **20% 以下** | 取景/布局相位，先怀疑取整 |
| 渲染模式差 | 色偏只在一侧 **且幅度 ≤12** | 取景侧 `--disable-lcd-text` |
| 瞬时态差 | 色偏只在一侧但幅度更大 | 取景侧 calm（如 `caret-color`） |
| 要人看 | 都不成立 ⇒ 明写"要人看"并给 `--crop` 坐标 | **不许把归因不明的图判成噪声放过去** |

★**两条自伤当场被自己的尺子抓住**，都记下来：
1. 第一版 `--why` 我自己抄了一遍逐像素循环 —— **R4-Ex③ 的 `getImageData === 1` 锚当场红**。改法不是放宽那条，而是让位移抵消**把平移后的图再喂给同一把 DIFF_FN**（色偏/幅度/行数由 DIFF_FN 顺手算好），调用点从 2 个变 3 个，R4-Ex③ 随之**随迁带备案**（它守的是"算式只有一份"，那由 `getImageData === 1` 钉死）。
2. 第一版分类用**差异行数**分档，于是把 pool-list（只有 2 行：胶囊上下各一条边线）读成了"瞬时态"。改成按**幅度**分档（≤12 vs ≥30），两族各自归位。教训与 #119 同一条：**判据形态必须和缺陷形态同构**，行数不是这两族的区分量。
3. 还有一条纪律性发现：`--only=notion` 的**单主题连采**与全量跑**不可互比**——dz-*/settings 那批场景差 9,676–205,668 px（会话顺序影响画面）。部分跑只能与部分跑比，**别把部分跑的产物写进基线目录**（本轮所有 `--tag=` 都写在独立目录，测完删）。

## 七、边界如实

1. **`--disable-lcd-text` 是取景侧的旗标，不是产品的开关**。用户真机上仍是系统/浏览器的默认文字渲染（多半是 LCD 子像素），本轮**没有**验证"产品在哪种 AA 模式下更好看"——那是另一个问题，别把这条读成性能或观感决策。
2. **#127 只到定性**：1px 整片位移已证实，**元素未点名**。所以它仍挂着，且本轮没为它加棘轮。
3. **#131 是钉完两条轴之后才露出来的**（`apple-st-tags` 38 px / 1 行 / 幅度 69 / 两侧都无色偏）——`--why` 老实判成"要人看"，没有替我猜一个成因。
4. **归因分档的阈值是在这台 Mac、这一份 Chromium 上量的**（20% / ≤12 / ≥30）。换机器要重量，做法同 R4-Ex 那条边界：连采两跑看分布，别照抄数字。
5. **`--why` 不改判定只加解释**：一张"整片挪 1px"的图仍然让 `img-diff` 非零退出（R4-Fd③ 钉着），要不要放过由人拍板——这是设计，不是遗漏。
6. **基线目录被本轮重拍过一次**（`docs/视觉归档/2026-10-04/`）。此前那批未钉光标的归档与它比较时，`ov-search` 一类会报"瞬时态差"；`--why` 会这么告诉你，但**别拿它当内容回归**。
