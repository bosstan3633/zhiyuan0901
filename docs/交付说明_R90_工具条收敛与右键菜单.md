## 二、改动明细

### T1 · R8-① 常驻教学文案改「?」气泡

`Workspace.vue` 页头右端摘要里常驻着 `· 可镜像到策展台`——它是 04-18 那句「卡片在此存储为真身 · 📡 单卡 / 📤 分类可镜像到各策展台 · 源数据零影响」的残留。

- 该文案从摘要中移除，收进台名右侧一枚 `?` 的 `title`（文案常量 `HUB_HELP_TEXT`，**一字未改**）。
- 用原生 `title` 而非自绘气泡：页头高度已锁 `max-height:40px`（R84 约束），自绘气泡会撑破或需 Teleport。

> **不常驻 ≠ 删除。** 回归断言 `R90-2` 逐字校验四段文案（卡片在此存储为真身 / 📡 单卡 / 📤 分类 / 源数据零影响）仍在。

### T2 · R8-② 主 CTA「＋新建」前置

改前顺序：`视图 Tab ｜ 搜索 ｜ 筛选 ｜ [批量] ｜ ＋新建 ｜ ⚙`，且 `.toolbar-search` 带 `margin-left:auto` 把搜索之后所有元素一起推到右端——**主 CTA 是视线最后扫到的东西**。

改后：`视图 Tab ｜ ＋新建 ｜ [spacer] ｜ 搜索 ｜ 筛选 ｜ [批量] ｜ ⚙`。

- 新增 `.toolbar-spacer { flex: 1; }`，`.toolbar-search` 去掉 `margin-left:auto`，右推职责移交 spacer。
- 与 R88 的分级**不冲突**：一级仍五件，只是主 CTA 从右端移到左区。批量中的「✓ 完成批量」仍留在一级（退出通道不能断）。

### T3 · R8-③ 资源台 fallback 定位语降为 tooltip

`wsHeadDesc` 一个 computed 里混着**两种性质完全不同**的内容，一刀切会把 R84 刚立起来的台身份抹掉，故拆成两态：

| computed | 内容 | 呈现 |
|---|---|---|
| `wsHeadDescOwn` | 用户自写的台描述 | **仍内联**（`· {{ wsHeadDescOwn }}`）——这是身份，不是提示 |
| `wsHeadDescFallback` | 资源台无描述时的回落定位语「资源卡唯一存储 · 镜像源头」 | 降为 `ⓘ` + `title` |

### T4 · R10 右键菜单补 编辑 / 星标 / 镜像

`openResCtx` 非镜像分支新增三项（**三项能力本就存在，本轮只是接线**）：

| 新增项 | 调用 | 说明 |
|---|---|---|
| `✏️ 编辑详情` | `openResource(r)` | 此前右键只有"打开链接"，**要改内容得先单击卡进详情** |
| `⭐ 星标` / `☆ 取消星标` | `toggleStar(r)` | hover 动作条早就有 ⭐，右键一直没有 |
| `📡 镜像到策展台` | `openMirrorCard(r)` | **带 `isHub` 门控**——策展台的卡源头就是资源台，再往外推没有意义 |

镜像分支（只读引用）不动：R89 已收敛为 `打开 / 复制 / 🎯 定位源 / ✕ 移出镜像`。

**顺带修掉一个既有缺陷**：`Icon.vue` 的图标表里没有 `edit` / `star` / `share` 三个键，而 `Icon` 的实现是 `ICONS[props.name] || ICONS.compass` —— 既有的 `icon: 'star'`（"设为中心论点"）一直**静默显示成罗盘**。本轮补齐三键，并让中心论点改用 `target`（靶心，更贴"中心"语义，也避让星标）。

### T5 · R17 抽屉下拉注入「🗂 资源台（真身）」

`ResourceEditForm.vue` 的 `wsOptions = computed(() => store.workspaces)`，而 `store.workspaces` **显式排除资源台**（`stores/app.ts:18` `w.id !== CURATION_WS_ID`）。后果（与 04-18 原文逐字一致）：

1. 在资源台打开一张真身卡的详情，`v-model` 的值在选项列表里**不存在** ⇒ 下拉显示空白；
2. 随手改选并保存 ⇒ 卡片 `workspaceId` 被改写 ⇒ **真身静默迁去策展台**；
3. 而 `curationProjections` 里指向它的镜像仍留在原地。

修法：`model.workspaceId === CURATION_WS_ID` 时在下拉**首位注入**「🗂 资源台（真身）」。

> ⚠ **不改 `store.workspaces` 本体**——那是全局口径：`GlobalSettings` 的搬家目标台、`overlay` 的台计数都不该混入资源台。此处只是表单层的局部补救。

## 七、补交付：两项欠账的修复（同一版本 V2.59.0 内，零产品代码改动）

> 产品行为零变更，故**不升版本号**；改动只落在回归脚本与对外文档。

### 7.1 版本断言改为「版本锚」动态基准

`regression.cjs` 顶部新增单一锚点：

```js
const VER_ANCHOR_LITERAL = "version: '2.59.0'";   // ← 升版只改这一行
const CUR_VER  = (VER_ANCHOR_LITERAL.match(/'([\d.]+)'/) || ['', ''])[1];
const CUR_VTAG = 'V' + CUR_VER;
```

各轮断言的判据全部改用锚点派生值：`m.includes(VER_ANCHOR_LITERAL)` /
`pkg.includes('"version": "' + CUR_VER + '"')` / `mp.includes(CUR_VTAG)` /
`reg.includes(VER_ANCHOR_LITERAL)`。

| 项 | 数量 |
|---|---|
| 判据动态化 | **78 处**（m 20 / reg 16 / pkg 20 / mp 20 / 独立 2） |
| 断言描述去掉硬编码版本号 | **20 处**（含 `R36-20` 与 5 条仍写旧版本号的旧描述） |

**效果验证（关键）**：把 `manifest.ts` 临时改成 `2.60.0` ⇒ **21 条版本断言立即变红**；改回 ⇒ 934 全绿。
证明这些断言是真的在守"五处同步"，而不是恒真地躺在那里。

### 7.2 顺带还原被全局替换污染的**历史轮次标注**

排查时发现污染面远大于断言本身——`regression.cjs` 里的轮次标题（`console.log('【第八十七轮 · V2.56.0：…】')` 与 `// ===== 第X轮 · V…` 注释）也被一路抬高，例如 R87（真实 V2.56.0）显示成 V2.59.0。

用两个**独立于被修对象**的证据源还原：

| 证据源 | 覆盖 | 条数 |
|---|---|---|
| `git log` 提交主题（正则 `V(\d\.\d+\.\d+) 第…轮（R(\d+)）`） | R64–R90（R72/R73 由母版变更记录补齐） | 27 |
| `docs/交付说明_第五X轮_V*.md` 文件名 | 早期轮次（git 主题未写版本） | 27 |

结果：**轮次标题还原 34 条**（git 映射 23 + 文件名 8 + 注释式 11 中的可还原部分），
R70→V2.39.0、R77→V2.46.0、R87→V2.56.0、R89→V2.58.0 等全部回到真实版本；
**无据可查的 0 条**（若有则会删掉错误版本号——显示错的比不显示更糟）。
