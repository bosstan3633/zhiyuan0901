## 一、为什么这轮不动产品，只修尺子

R4-Et 立了一条刹车：`fnBody` 的起点/终点标记找不到就记账，判据要求账本为空。但那条闸**只覆盖 `fnBody` 的 14 处**，同一种失效形状在 `segOf` 的 **69 处**调用上一字未设防——而 `segOf` 才是主力（`CTX90` / `OPEN_LINK_FN` / `RES_CARD_IFACE` / `WS_TPL` / `FIELDS` … 都是它切的）。

还有一个只有扩到 `segOf` 才暴露的问题：**闸不能装在分片里**。`fnBody` 的 14 处全在 helpers 模块加载期求值，所以 R4-Et② 放在 98 分片里判"账本为空"是有效的；而 `segOf` 的绝大多数调用写在**判据体内**（`const fn = segOf(...)`），谁没被跑到谁就不记账 ⇒ 任何分片里判空只覆盖到那一刻之前。所以这一轮把收口挪到 `regression.cjs`：**全部跑完之后再判，且直接影响退出码**。

## 三、判据 +2（1627 → 1629）

- **R4-Eu①（闸在位）**：`regression.cjs` 必须有行首语句 `const misses = [...new Set(getSliceMisses())];` 与 `process.exit(fail || misses.length ? 1 : 0);`，并**负锚** `process.exit(fail ? 1 : 0);`（退回旧写法就等于把漂移放掉）；helpers 侧四条失败路径（fnBody/segOf × 起点/终点）都要记账；现场 `getSliceMisses()` 为空。
- **R4-Eu②（形状锚）**：漂移闸只抓"标记找不到"，**抓不到"标记还在但落点错了"**——起点在文件里重复出现、或终点被换成一个存在却很晚的串，切片会静默撑大而不记任何账。所以再钉一层形状：三段 helpers 级切片必须还是那一段代码的量级（`CTX90` < 4,000、`OPEN_LINK_FN` < 2,500、`RES_CARD_IFACE` < 3,000，实测 1,458 / 1,032 / 1,329，放了一倍余量），承重内容要在（`icon: 'star'`、`if (meta.kind === 'image')`、`kind: 'resource'`），**区外的东西不得进来**（`openMirrorDetail`、`previewName`、第二个 `export interface`）。

1. 形状锚只覆盖 helpers 里那三段（有常量可引）。分片体内自算的（`parseQuery` / `fixLink` / R80-6 input）本轮只靠漂移闸兜——要扩到它们得先把这些切片提成常量，那是另一件事。
