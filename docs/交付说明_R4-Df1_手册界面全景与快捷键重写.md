## 一、为什么先动这三章

盘点结果：`manual-data.ts` 24 节里约 1/3 需要重投，但**危险程度极不均匀**——
大部分章节是"用词旧了"，读者还能猜对；只有三章是**照着做会走进死路**：

| 章 | 它教用户做什么 | 实际情况 |
| --- | --- | --- |
| `basic-1` 界面全景 | 「顶部导航：调度台 / 方向台 / **资源台** / 策展台」；「方向台（指标条 / **主航线** / **项目总览**）」；「**项目调度**（两列，R67 重排）」 | 顶栏只有三样；指标条在调度台；主航线与项目总览随 R3-B1 被方向树整条接替；项目调度卡 R2-② 已退役 |

| `mid-3` 项目总览与项目详情 | 「方向台 · 项目总览（满宽三列卡 + 置顶分组 + 拖拽排序）」 | 那一屏不存在；置顶/排序/进入详情都在方向树卡头上做 |

顺带把 `basic-3` / `basic-4` 的**章节标题**也改了（「策展台与**资源台**操作」「今日三件事与**项目调度**」）——
正文改对了而目录还在骗人，等于没改。

## 二、★断言钉住了错句子，比没有断言更坏

本轮 6 条重指（`R45-13` / `R63-15` / `R63-16` / `R66-7` / `R67-9` / `R127-7`）的共同点是：
**它们逐字钉的锚点本身就是已失效的事实**。例如：

- `R45-13` 要求手册必须含「方向台（指标条 / 主航线 / 项目总览）」——那句现在是一句假话；
- `R63-15` 要求含「资源台：资源卡真身的唯一居所」（旧台面时代的章标题）与「5 指标卡」（辅助条自 R98 起 5→3、R123 又退役主题格）；
- `R63-16` 要求含两条「项目调度」面板的中缝比例（模块已退役）；
- `R67-9` 要求含「常亮高亮」（指已退役的策展主题格）；
- `R127-7` 要求手册写「**默认列表视图**」，而 `TaskManagerPanel.vue:49` 的默认值是 `card` —— 手册自 R127 起一直教错。

**这种断言的实际效果是：每次有人想把手册改对，先撞一次红；久了就没人改。**
本轮一律按「钉当下真形状 + 旧措辞转负判据不许回流」重指，每条都写了为什么原判据守的东西已经不存在、
能力搬去了哪、新判据为何不更松。**没有一条是悄悄放宽的**：六条的重指都新增了负判据。

## 三、新增 4 条：把手册与代码之间最容易漂的三件事钉成可核对

1. ★**手册命令表必须等于 manifest 真值**——不硬编码条数，从 `manifest.ts` 现算"无 `suggested_key` 的命令"，
   每条的 description 都必须在手册里实名出现。将来加/删命令，这条会自动要求同步手册。
   （`ref-1` 反复漂移的根因就是手抄一份命令清单。）
2. **应用内切台键位口径写对**（1/2/3 起），并把旧那句「从 1 起按导航顺序计数」转负判据。
3. **退役结构不许作为现役功能写回**：资源台台面 / 主航线 / 项目总览 / 项目调度面板 / 今日记录四格 /
   策展主题格 六件各自点名，同时要求手册**明说它们去哪了**（只删不说＝用户按旧记忆找而手册沉默）。
4. ★**章节标题本身不许带退役物**——这条是当场抓到我自己的：我重写完正文，回头截图才发现目录里
   还挂着「项目总览与项目详情」。判据要求 24 个标题逐个不含六个禁词。
