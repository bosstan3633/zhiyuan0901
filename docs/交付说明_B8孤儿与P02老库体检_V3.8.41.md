## 一、本批最重要的结论：一次差点造成不可逆损失的错误

**我按孤儿探测器的输出删了 6 个"零挂载"文件，回归当场 46 条红。**

真相是：这 6 个文件里有 4 个是 **W13-D5（2026-10-16 用户拍板）「复盘能力四段常驻」明文要求"组件文件保留待复用，同 CatPicker 先例"** 的，`W13-T7a` 判据正逐条读其中一份的本体。**那不是"清理陈旧断言"，是把一次用户拍板当成死代码删掉。**

根因不是判断慢，是**尺子的输出被当成了删除许可**。据此立三条规矩（写进 `orphan-check.cjs` 头注）：

1. 脚本 `exit 1` 只是"该看一眼"，**不是"可以删"**；
2. 删任何文件前先 grep `scripts/regression/`，看有没有判据在**读它的本体**（读注释不算，读 `includes` 才算）；
3. "保留待复用"必须在脚本的 `RETAINED` 名册里**明文登记** —— 只写在组件文件头的注释里不算登记（它不会跟着 git diff 走评审）。

**处置**：六个文件全部恢复；四条理由登记进名册（另两个经查是 `ReviewPanel` 的**动态 import 下游**，本就有真入边，不该进名册）；`B8-3` 立四条负锚防复发。

## 二、P0-1：孤儿探测器（`scripts/orphan-check.cjs`）

### 为什么立这把尺子
盘点报告曾用 **grep 文件名**数引用，得出"三个组件全库零挂载"。那个结论**本身错了一个**：`DrillCardList.vue` 被 `DayDetail.vue` 真实 import（今日战报在用）。注释、备案句、字符串里都会出现文件名，而真 import 只有三种形态。

### 口径
- 节点 = `src` 下全部 `.vue/.ts/.js`（`.d.ts` 除外）；边 = 静态 import / export-from / dynamic import / `defineAsyncComponent`
- 入口 = 构建入口 + 由图的传递闭包自然算出，**不手工列白名单**
- `--json` 输出机器可读；退出码 `0`=无孤儿 `1`=有孤儿 `2`=自身错误

### 尺子自己也踩了两个坑（都已修正并立判据）
1. **解析规则必须与真实构建一致**：`@` 别名指向 `src`（第一版错指其父目录）；扩展名顺序照抄 Vite 的 `resolve.extensions`（`.ts` 必须在 `.vue` 前）。第一版把 `.vue` 排最前 → **误报 102 个**。
2. **尺子要能自证有效**：判据 `B8-2b` 真在 `src` 里造一个无人 import 的 `.vue`，要求脚本 `exit 1` 并点名它，跑完删掉。只改字符串不真建文件，测的是想象力。

**当前结果**：`✓ 无孤儿文件（201 个节点 / 1046 条 import 边）`，保留名册 4 条（CatPicker + W13-D5 一族）。

## 四、P0-2：老库字段系统体检

### 结构性决定：归一化必须是单一真源，不挂在读路径上

V3.8.40 已在 `loadData` 里加了四条归一化（实测有效）。但盘点复查发现一个缺口：

> **设置页「导入数据」走 `mergeImport`，它把导入的卡直接塞进 `d.resources/tasks/curiosities`，从不经过 `loadData`。**

而归一化写在 `loadData` 里 = 只能治"启动读老库"，**治不了"导入老库"** —— 而导入恰恰是老库的主要来源。
⇒ 抽成导出函数 `normalizeLegacyCards(data)`，`loadData` 与 `mergeImport` 调同一份。

> **纪律：归一化必须挂在"数据入库的那一层"，不能挂在"某条读路径上"** —— 挂在读路径上，每新增一个读入口就漏一个；而入库层是唯一的。

### 本批补齐的 6 处缺口

| # | 字段 | 不补的后果 |
|---|---|---|
| 1 | `linkType` + 旧字段 `url` | **不崩**。`toOpenableUrl` 走 url 分支 ⇒ 本地文件卡被当网页打开；`linkStateOf` 判不出 incomplete ⇒「⚠ 待补全路径」永不出现 |
| 2 | `kind` | **不崩**。缺 kind 的卡**从所有 kind 视角里消失**：筛选看不到、三卡统计少算、导出丢列 |
| 3 | `id` | **不崩**。id 是关联的锚；`mergeById` 用它做 key，会把多张无 id 卡**折叠成一张（静默丢卡）** |
| 4 | `title` | **不崩**。空标题在卡面/⌘K/导出/回收站里是一处空白可点区域，用户以为数据丢了 |
| 5 | 策展台 `order`/`archived`/`name` | **不崩**。`a.order - b.order` 里 NaN 参与比较 ⇒ 台序错乱且每次载入都可能不同 |
| 6 | 分类 `order`/`name` | 同上 |

第 1 条的性质与其他五条不同：**它不会崩**，所以任何"点开就炸"的实拍都抓不到它 —— 是一次纯静态盘点才发现的**行为缺陷**。

## 五、本批抓到的两个真缺陷（都是"读源码看不出来"的）

### 缺陷 1：兜底排在映射之前 ⇒ 用户的完成记录被静默清零
原顺序是 `fixCurioStatus`（缺 status 兜成 `todo`）→ `fixCurioLegacyFields`（`done`→`status`）。
轮到第二段时 `status` 已非 undefined，`done` **永远读不到** ⇒ 老库里每张 `done:true` 的已完成好奇卡，导入后都被改成"待探索"。**不报错，只是用户的完成记录凭空清零。**
⇒ 已改为映射在前、兜底在后；并立判据 `X-3` 钉住这条顺序。

### 缺陷 2：`url` 映射顺手写死 `linkType='url'` ⇒ 形状推断永远轮不到
第一版写成 `c.link = c.url; c.linkType = 'url'`，导致后面按形状推断的代码形同虚设：
`D:\资料\讲义.pdf` 与 `obsidian://…` 都被标成网页链接。
⇒ 改为只搬字段、让推断器统一判。

**两段逻辑各自都对，合在一起是错的** —— 只有把真实旧结构喂进去看输出才会现形。

## 八、本批沉淀的纪律

1. **★★「孤儿」与「该删」之间隔着人的判断** —— 尺子的输出不是删除许可，删前必查有没有判据在读它的本体。
2. **★★★「保留待复用」必须登记在门禁脚本里**，写在组件文件头不算（它不跟着 git diff 走评审）。
3. **★★★归一化必须挂在入库层，不是读路径** —— 挂在读路径上，每新增一个读入口就漏一个。
4. **★★兜底必须排在映射之后** —— 否则兜底会吃掉映射的输入（`done` 被 `todo` 顶掉）。
5. **★★★自建提取器连错七次都是"代码对、判据红"** —— 终局解法是**别自建，用现成转译器**。
6. **★★诊断脚本自己会被 shell 转义误导** —— 据此误判过源码是全角引号，改完判据仍红，比判据本身错更费一轮。锚点一律先 grep 实际文案。
7. **★「测量出错」与「被测物出错」长得很像**（第七次记）：夹具跑出 `status:"todo"` 与 `linkType:"url"` 时，看不出是"读数错"还是"代码错" —— 必须人工核对每个读数的含义。
8. **★★★「独立重算」本身也会错，而且错在"偷偷加了生成器没有的过滤"** —— 本轮独立重算得 52,289 而生成器 52,297，差 8 行；查证是生成器的 `walk()` 既不过滤 `.d.ts` 也不过滤 `__fixtures__/`，而我"凭直觉"排掉了它们。差值看起来像"生成器过期"，实际是"我算错了"。⇒ **独立重算必须照抄被校验方的过滤逻辑，一个字都不优化** —— **一个比被校验对象更聪明的校验器，校验的是另一个东西**。（与第 5 条同源：凡自建校验工具，第一步都是证明它与被校验物同口径。）
9. **★★门禁的"严格"必须有成本意识** —— `dead-css-scan` 的新鲜度闸只看 mtime，于是**改一句更新日志文案也要逼人重跑 6 分钟实拍**。这不是严，是**把纪律变成负担**；负担足够重时人会绕过纪律（改用 `--census` 硬绕），那才是真风险。⇒ 精确化为「只有可能产出 DOM class 的改动才顶旧普查」：豁免名单限死两个纯文案数据文件且**豁免是自检出来的**（文件里一出现 class 关键词或 CSS import，下次照常拦），豁免时**必须打印文件名与理由**（静默放行等于偷偷开闸），任何可能间接产出 class 的文件一律不豁免。**口径边界写进头注：宁可多拦（多跑 6 分钟），不可错放（错放就是一份假绿清单）。**
10. **★悬停浮层不能脱离宿主单独存活** —— 那段 `.dz-ov-tip` 的注释里还留着"让键盘用户 Tab 进去也能看到"，可它挂靠的整行已经没了，**这句善意从来没有机会执行给任何人**。这类残留不是错误、只是一段永远不会被执行的正确代码，最难发现。宿主判死时必须连浮层一起判。

### 新增门禁 B8-6 · 文档不能是唯一不带门禁的产物

**这才是本段真正的产出**：代码有 39 个分片在守着，**文档是本项目体系里唯一完全裸奔的一类产物**。给它补三条判据（`25-b8-orphan.cjs`，已做**三处反向注入验证**：改回旧读数 / 塞不存在的键 / 改旧版本行 ⇒ 三条如期变红，还原回绿）：

- `B8-6a` 架构总览不得含已退役口径（104 图 / 180 文件 / 24 声明 / 26 调用点 / 1,675 / 六主题 / 虚构备份键），且必须给出当期读数 —— **不写死具体数字**（会随版本变），而是禁旧值 + 逼它给出当期值。
- `B8-6b` 存储段里每个 `zy_*` 字面量都必须能在 `keys.ts` 里查到，且该段必须指向 `keys.ts` 常量。
- `B8-6c` 架构总览版本行必须等于 `manifest.ts` 现行版本，且必须存在一份「本轮改了哪几类」的差异账 —— **否则下一个人只能全盘不信或全盘信，两种都危险**。

### ★★★顺带抓到一个真缺陷：提示污染了数据面（`W13-7` / `R4-Et①` / `R4-Ev①` 三条同时假红）

- **症状像判据坏了**（三条历史判据同时红，且都指向同一个我没动过的文件），**真因却是被测物的输出面被我的话搅了**。这属「测量出错」那一族：判据红是信号，不是结论。
- 处置：提示改走 **stderr**，与错误路径一致；并给 `B8-4c` 补一条负锚 —— **`--json` 的 stdout 必须是纯 JSON**（判据里 `JSON.parse(r.stdout)` 失败即红）。
