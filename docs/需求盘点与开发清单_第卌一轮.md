## 三、问题清单（核心修复 → 计划项 → 技术债）

### REQ-054 详情面板附件端到端修复 🔴 最高优先级

**问题（V2.16.0 疏漏）**：
1. 详情抽屉标题旁无附件徽章（用户期望"外面看一眼就知道挂了几张图几个 HTML"）
2. 详情抽屉附件 section 头也无徽章（V2.16 我只在卡片正面三视图接了 AssetBadge，详情抽屉完全没接）
3. 端到端验证缺失——我自己都没真正跑过「上传 → list 渲染 → 预览 → HTML 新标签 → 删除 → 徽章同步」全链路

**方案**：
- **三处详情抽屉标题旁加徽章**：`<ResourceEditForm>` / `<CuriosityPanel>` 详情 / `<CompassActions>` 任务详情
- **三处附件 section 头加徽章**：与标题旁同步（数据共享）
- **响应式链路核验**：上传 → AssetManager emit → onXxxAssetsChange → store.update → Object.assign → persist → 详情抽屉 list 与徽章同步更新
- **HTML 新标签打开核验**：`chrome.tabs.create` 在新 MV3 扩展中是否仍需 `tabs` 权限？若缺则补 manifest
- **交付前强制端到端验证**（吸取 V2.16 教训）：用 chrome 加载 dist，三卡型 × 详情面板，**每条流走一遍**，截图入交付说明

**改动文件**：
- `v2/src/newtab/components/ResourceEditForm.vue` — 标题行加 `<AssetBadge>`（标题右上）
- `v2/src/newtab/components/compass/CuriosityPanel.vue` — 详情 `<Drawer>` 标题旁加 `<AssetBadge>` + 附件 section 头也加
- `v2/src/newtab/views/CompassActions.vue` — 任务详情 `.ts-head` 区加 `<AssetBadge>`
- 验证需要时不需改业务逻辑（链路已完整）

### REQ-055 资源卡 CSV 导出动态列对齐字段目录

**现状**（需 grep 确认导出位置）：可能为固定字段导出

**目标**：CSV 导出列读 `visibleFields(fieldConfig, 'resource')`，自动跟随字段管理（显示/隐藏/重命名/顺序）
- 系统字段全导出
- 自定义字段按可见性过滤
- 列顺序 = fieldDef.order
- 列标题 = fieldDef.label（资源 title 中文如"所属工作台"）

**改动文件**：
- CSV 导出所在位置（grep 后定）
- 复用 `visibleFields` from `shared/utils/fields`

### REQ-056 AssetManager/AssetBadge 双份图片 viewer 抽公共组件

**问题**：两个组件各自内嵌一份 `Teleport` + 弹窗 UI + Esc 关闭 + 图片渲染，代码双份 ~60 行

**方案**：抽 `shared/components/AssetPreview.vue`
- props: `open: boolean; url: string; name: string`
- emit: `close`
- 内含 Teleport + 弹窗 UI（继承 am-viewer 样式） + Esc/点击外部关闭 + 图片渲染
- AssetManager 的 `viewerOpen/viewerUrl/viewerName/revokeViewer/closeViewer/openAsset` 内部状态 → 全部删除，统一调 AssetPreview
- AssetBadge 的弹层列表 + 图片预览 → 同样调 AssetPreview

**改动文件**：
- `v2/src/shared/components/AssetPreview.vue` — 新建
- `v2/src/shared/components/AssetManager.vue` — 改用 AssetPreview
- `v2/src/shared/components/AssetBadge.vue` — 改用 AssetPreview

### REQ-057 静默 catch 收敛（巨型 SFC 本轮不拆）

**问题**：`} catch { /* noop */ }` 与 `console.error` 静默吃错的模式不利于诊断

**目标**：本轮只做"最小改动"——
- 全库 grep 静默 catch 模式
- 区分"安全容错"（如 IndexedDB 不可用时降级）vs"业务吞错"（如 store.update 失败却无提示）
- 业务吞错位置加 `showToast` 提示 + console.error 保留

**改动范围**：约 10-15 处 catch 块，每处 1-2 行改动，不拆 SFC
