## 一、为什么是这一刀

`Workspace.vue` 是全仓最大单文件（R71 登记时 2597 行，本轮动工时 **3583 行**），资源台与策展台合体后持续膨胀。但它同时被 **204 行**回归断言以字符串 includes 盯着——拆分的真实成本不是搬代码，是**断言归位**。因此刀口由「断言纠缠度 × 耦合度」决定：

| 候选域 | 断言纠缠 | 耦合度 | 判定 |
|---|---|---|---|
| **导入三链路**（数据包/书签/本地文件，~220 行连续块） | 13 行 | 低（依赖全部可注入） | ✅ 第一刀 |
| 下钻抽屉 | 7 | 高（8+ 视图态依赖） | 第二批 |
| 批量管理 | 3 | 中（状态散布三处） | 第三批 |
| 镜像域 | **32** | 中 | 倒数第二批 |
| 分类树 + 拖拽 | 多 | 极高（dragState 贯穿） | 最后一批 |

## 二、拆分模式（本轮确立，后续批次沿用）

**实现随迁，绑定留宿主**：

- 实现逐字迁入 `src/newtab/composables/useWorkspaceImport.ts`（数据包导入 R70 净化链路 / 书签解析-勾选-确认 / 本地文件一文件一卡 + putAsset）；
- Workspace.vue 以解构保持**全部原标识符**（`importModalOpen`/`handleBoardImport`/`bkFolders`/…）——**模板零改动**（三个 file input、导入弹窗、文件夹勾选弹窗原样），`fileImport`/`@change` 入口面不变；
- 依赖以 ctx 注入：`{ d, workspaceId, newCardCatId, persist }`（`newCardCatId` 为函数声明，提升安全；`showToast` 等全局单据直接 import）；
- 进口随迁：`guessAssetKind/assetMimeOf/stripExt/ASSET_KIND_MB/safeDecodeText/sanitizeCategoryTree*/putAsset` 迁出宿主进口；`getAssetBlob` 留守（`openImageAsset` 仍在宿主）。
