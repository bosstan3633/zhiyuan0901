## A1 · 标签体检：先补账，再改判据（P0）

**现象**：抽屉「知 · 标签体系体检」跑完显示"模型没有给出可采纳的建议"，其他 AI 场景正常。

**代码里能确证的真因**：`src/shared/ai/govern.ts:56-92` 的 `parse` 是**全站唯一没有消毒账的 run 型场景**——两类动作共 4 条静默 `return`，丢了几行、为什么丢，界面上一个字都不报；这个 job 也没有 `audit()`（R147-c 那套账目要求漏了它）。所以现在**无法区分**"模型没答"和"模型答了我们全丢了"。

**三条最可能的具体原因（按概率排，都要在补账后一次看清）**：
1. **名称对不上**：模型爱写 `#产品开发与演示`、带空格或全角括号，而判据是 `usedTags.has(from)` 精确匹配（`govern.ts:73-75`）→ 全丢。你的树有 92 个分类、路径长，命中这条的概率最高。
2. **键名不认**：契约要 `merges` / `rehome`；模型给 `merge` / `moves` / 中文键 → `bag.merges` 为空。
3. 它**诚实回答**"没有可合并的"（保守判据本来就容易得出这个结论）。

**修法**
1. **补账**：`drop = { noKey, notInUse, notInTree, selfMerge }` + `audit()`，空态点名真因（例：「模型给了 6 行：5 行标签名对不上库（示例 `#项目运营`）、1 行目标不在树上」），不再演"没有建议"。
2. **名称归一化**：剥 `#`、去首尾空格、全角转半角、`父/子` 与叶子名双口径先归一再比——**复用 R129-B4 的 `cardHasTag` 口径，不再造第二套**。
3. **契约加固**：`tagGovernSystem` 明写"标签名原样回填，不要加 #、不要翻译、不要改层级写法"，并给一条示例行。
4. 归一后仍 0 行时，抽屉给**「看模型原文」折叠**（复用 R144 的 `rawText` 通道），让契约问题一眼可判。

**验收**：冒烟造三种答法（带 `#` 前缀 / 键名写成 `merge` / 真没建议），断言三者账目文案各不相同；新增断言反向钉"体检必须带 audit()"。

## A3 · AI 检索结果的交互（P0，先复现再改）

**代码里能确证的三条偏差**：
1. **Ctrl+单击 全站没有**——只有 Ctrl+Enter（`GlobalPopups.vue:1088`）。鼠标侧 AI 行（`:46`）与主行（`:75`）都只绑 `@click`，所以"和一般检索一致"字面成立，但**用鼠标无法只定位**。
2. **双击未定义**——面板行上没有 `@dblclick`，双击=两次单击，资源卡会**连开两个 tab**。你 R150 原话是"点击和双击的交互方式保持一致"，这条当时没落。
3. **同一张卡渲染两次**——AI 组与主组各一份，`flatList` 里 id 重复，而 `syncIndexFromId()` 用 `findIndex` 永远命中第一条（AI 组那条）：你鼠标停在主组那行、按 Enter 执行的是 AI 那行。同卡所以结果一样，但**高亮会跳**，观感就是"没按约定走"。

**推荐收口（一条改动解决三条）**：**AI 命中不再单列一组**，改成在主列表命中行上挂「✦ AI 命中 · 理由」徽标并按命中序置顶，列表里每张卡**只有一行**；组标题保留「挑出 M 条 · 投料 N/总数 · 耗时」这笔账（R150 的"没看全要写出来"一字不动）。

**开工前需要你补一个事实**：鼠标侧的手势矩阵按哪套？我打算按这个落，你不吭声我就照做——
**单击 = Enter = 打开链接；双击 = Ctrl+单击 = Ctrl+Enter = 只定位到卡片所在处。**

**验收**：6 格手势逐条实测（开了几个 tab、路由落到哪、选中高亮是否落在你眼睛看到的那行）；断言"AI 命中的行与主列表行走同一函数、同一 title 文案"。

## A5 · 流畅度：先归因，再动刀（P0）

**账先摆明**：R151 三采样 M2a 71→117、M13 阻塞 322→502、M1 468→501，我当时写的是"未归因、待观察"。你手感确认变钝 → 这条从观察升级为必做，**且第一刀必须是归因，不是改代码**。

**已经排除的**：✦ SVG 图标本身（A/B 实测：删掉小星 M2a 反而 149ms，差值在同机带宽内）。

**已经定位的一半**：M3c 那 6~9s 长任务 = **交互后 Blink 侧的非 JS 时间**（零交互静置 20s 出 **0 条**长任务；窗口三采样 21.6s 里 `(idle)13.4s + (program)7.5s`，业务 JS 不足 0.4s）。**方向是布局/绘制，不是算得慢**——所以刀要砍在"少节点、少重排"上。

**三条确定性嫌疑，按改动成本排序**
1. **每张卡一个 AI 组件实例（最便宜、最该先做）**：`CardAiEntry` / `TaskAiMenu` / `ThesisAiBtn` / `EvidenceMenuItem` 都在 `<script setup>` 里调 `defineAsyncComponent(...)` —— `<script setup>` 顶层就是 setup 函数体，于是 **258 张卡 = 258 份异步组件定义 + 每实例 3 个 ref**。修法：提到模块作用域单例（新建 `lazyAiDrawer.ts` 导出一个，四个组件 import 它）。一处改，全站受益，且能 A/B 量出来。
2. **动作条节点变多**：R151 给列表/看板每行又加一枚入口；`.rr-actions` 在 flex 行里参与测量。修法：列表动作条改 `position:absolute`（看板已经是）+ 卡片网格 `content-visibility:auto` / `contain-intrinsic-size`。
3. **首屏渲染量本身**：258 卡 × 6 列 + 92 分类树 + 每卡标签/徽标/成熟度。修法：卡片网格虚拟化或分页 60 张滚动加载——**改动面最大，单独一批做**，且要先有 1、2 的实测数据才知道值不值。

**门禁补齐**：新增 **M14「资源台首屏节点数 + 布局耗时」**（现在所有指标都只量交互，渲染量没人看，这正是这轮漏掉的那块）。

**采样纪律不变**：三采样串行独占取中位；**归因跑要跑在你自己的库上**（当前 perf 用的是合成种子，258 卡/92 分类这个规模没测过）——需要你把 `导出数据` 的 JSON 给我一份，或允许 dev server 直连你的 storage 快照。
