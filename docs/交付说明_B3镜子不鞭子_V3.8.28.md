## 三、顺带修掉的真缺陷

**① 方向台「项目」与「指标」不是同一把尺子（两份账）**

`treeStats` 里 `projects` 走 `visibleProjectsOf(dir)`（受「已完成项目：显示/隐藏」影响），而 `metrics` 走 `dir.projects.reduce(...)`（**含已隐藏的已完成项目**）。于是隐藏已完成后会出现「项目 3 · 指标 20」，而树上从第 4 层数下去只有 12 个指标。

- **为什么门禁没拦住**：`R49-15` 只断言 `treeStats` 这个 computed 存在、`C1` 之前也没有任何判据比对两个数的口径；而骨架条第 5 层复用同一个 `treeStats.metrics`，两个数字一起错，互相印证"看起来是对的"。
- **处置**：`metrics += vis.reduce((s, p) => s + p.metrics.length, 0)`，与 `projects/focused/stalled` 同源；`C1-4` 钉正锚 + 负锚（旧的 `dir.projects.reduce(` 零命中）。

**② 画像页 KPI 的红绿染色从来没被检查过**

计划文档 §1.1 写 A2「✅ 基本落地（`PiHero.vue` 11 处 title，全文件无 danger/success/trend 红绿绑定）」——**这句只核对了 `PiHero.vue`**。真正的红绿在 `pi-timeline.css`：`.pi-chip.ok/.bad/.up`、`.wk-badge.up/.down`、`.m-badge.up/.down`、`.one-insight.ok/.warn`、`.pi-tag.ok/.warn` 共 9 条规则。

- **为什么门禁没拦住**：A2 的判据面只落在 `PiHero.vue` 一个文件；`theme-contrast` 查的是"对比度够不够"，红绿本身是达标的，不在它的语义里。
- **处置**：全数中性化 + `A2-1/2/4` 三条判据覆盖 CSS 侧。**这是本批最大的一块真活，不是"补判据"。**

**③ 一次差点做错的自我纠正（记在这里，避免下轮重犯）**

M2 降噪时我先把 `mb-k/mb-v/mb-denom` 一并降到 `text-3`，回归立刻打红 `R153-4`——那条判据记着一次真机体检：「这一行的小字曾量到 3.14:1，低于 AA，所以 `cf-pct` / `mb-denom` 从 `text-3` 抬到 `text-2`」。我又把它们调暗，等于把无障碍缺陷请回来。
**降噪只能降字号与间距，不能降对比度**——这条已写进 `MetricBar.vue` 的注释与交付说明，`mb-denom` 也放弃下压到 9px。

**④ 四主题走查工具本身有两个覆盖缺陷（本批要截图才暴露）**

- **`VIEWS` 里没有 `profile`**：画像洞察是一级页面，却一直只以「下钻 / 复盘 / 报告」等浮层形式出现在 `MODAL_VIEWS` 里，**页面本身的四主题截图从来没被拍过**。A2 改的正是这一页 —— 等于"改了没证据"。已补 `{ id: 'profile', hash: '#/profile' }`。
- **`--scenes` 过滤必然假红**：收尾的图数校验一律用 `VIEWS.length / MODAL_VIEWS.length / DRAWER_VIEWS.length / DASH_SCENES.length` 的**全量长度**算"应有"，过滤后拍到的必然更少，于是 `EXIT=1` 报「图数 32 ≠ 应有 112」——明明 32 张全成功。已改用 `pick` 之后的实际镜头数，并在报错文案里标注"本次带 `--scenes` 过滤"。
- **为什么没早发现**：这两个缺陷都在"跑全量、没人过滤"的路径上；只有本批为了只拍三页去用 `--scenes`，才把第二个撞出来。**又一次印证：工具只有在被换一种方式使用时才暴露它的假设。**
