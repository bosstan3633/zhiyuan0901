## 二、节点附件边界

| 类型 | 每节点上限 | 单文件上限 | 超限语义 |
|---|---:|---:|---|
| 图片 | 9 张 | 10MB / 张 | 第 10 张拒绝；超体积拒绝 |
| HTML | 1 个 | 20MB | 再次上传为替换，需确认 |
| PDF | 1 个 | 50MB | 再次上传为替换，需确认 |

补充口径：

1. 附件与节点严格一对一；节点排序、剪切、拖拽换父级时附件跟随，不复制、不共享。
2. 普通资源卡、任务卡、好奇心卡的附件仍仅存本机，不进入本轮附件 Storage 同步。
3. 主 JSON 和云快照只保存附件元数据，不写 Blob 或 base64。
4. 当前上传为单次 Storage POST；失败后保留本地并允许重试，不宣称已实现 TUS 可恢复上传。

## 三、Supabase 配置与上线动作

上线前必须在目标 Supabase 项目的 SQL Editor 执行更新后的：

```text
v2/supabase/schema.sql
```

该脚本采用幂等增量写法，会补齐：

1. 私有 Bucket `curation-assets`。
2. 仅允许 `auth.uid()` 访问自身目录的 Storage RLS。
3. `capture_inbox` 的文本字段、三类转化字段、删除字段和链接唯一索引。
4. 主快照相关表的现行约束。

安全边界：

- 只使用 publishable key；`secret` / `service_role` 严禁进入扩展。
- Bucket 必须保持私有，不创建公开分享链接。
- AI 凭据仍不上云。
- 跨账号附件隔离依赖上述 RLS，不能只靠前端路径拼接。

## 四、删除与导出语义

| 操作 | 本地 Blob | Storage 对象 | 界面 |
|---|---|---|---|
| 节点软删 | 保留 | 保留 | 节点和附件立即隐藏 |
| 同批恢复 | 保留 | 保留 | 节点和附件重新可见 |
| 节点彻底删除 | 删除 | 删除；失败进入待清理重试 | 不再可见 |
| 分享 HTML | 只读嵌入 | 不改变 | 图片可预览，HTML 隔离预览，PDF 打开或下载 |

分享导出的体积口径：

1. 附件总量 ≤100MB：默认生成自包含 HTML。
2. 100–300MB：强提醒，用户确认后继续。
3. >300MB：改为“HTML + attachments 目录”的 ZIP 包。
