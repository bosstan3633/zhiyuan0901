## 二、A1 · Hero 主次归位

**病灶：主次正好反过来。** 改前的主角（使命主线）被裹进一个 `surface-2 + border` 的**药丸盒**里、只分到 1 份宽；副带（KPI 读数）却裸着占 3 份宽，数字还 13px/700 比使命文本 12px/400 更重。于是首眼落在数字上，读到的是仪表盘，不是画像。

三件修法：

| # | 修法 | 判据 |
|---|---|---|
| ① | **药丸盒退役**：底色 `background: none` + `border: 0` 零残留，改用 `box-shadow: inset 3px 0 0 var(--accent)` 画左缘竖条（inset 内画不占宽度、不撑盒） | A1-1 |
| ② | **使命文本抬档**：`fs-sub/400 → fs-body/600`，标签降 `fs-caption/600 + var(--tracking-sm)`，使命正文同时 `color: var(--text)` | A1-1 / A1-3 |
| ③ | **权重反转**：`1:3 → 1:2`（使命 `flex: 1 1 300px` / KPI 带 `flex: 2 1 420px`） | A1-1 |

**降噪只动字重不动对比度**（AA 护栏 R153-4）：`.hero-kpi .v` 由 700 降 600，但颜色仍是原来的 `var(--text)`，**没有借"降噪"之名把对比度一起降掉**。实拍四主题逐项复核：读数色 linear `rgba(255,255,255,.92)` / apple `rgba(0,0,0,.9)` / notion `rgba(35,31,25,.9)`，与改前一致。

空态同步走无药丸盒路径（`.hcb-empty`），使命行超宽时 `text-overflow: ellipsis` + `max-width: 56vw` 回落（A1-4 / A1-5）。

## 四、★★ 本轮踩到的最隐蔽的一个坑：模板注释里的反引号

**这是本批最值得记录的一条**，因为它的症状欺骗性极强。

### 现象

PiYear 段头新增的 `.pi-mod-acts` 徽标，实拍四主题全部报「全年右缘：**缺失**」——DOM 里 `document.querySelectorAll('.pi-mod-acts').length === 3`（缺 PiYear 那一个）。

### 排查链路（每一步都被"看起来对"骗过）

| 步骤 | 结果 | 是否真相 |
|---|---|---|
| 读源码 | `'pi-mod-acts' in s == True` | 源码确实在 |
| `vue-tsc --noEmit` | 0 错 | 绿 |
| `vite build` | 成功 | 绿 |
| `@vue/compiler-sfc` 单文件编译 | `编译结果含 pi-mod-acts: true` | **绿但是假象** |
| 读 `dist` chunk 的 `__name:"PiYear"` 段 | 只有 `pi-mod-t` 接 `ins-year`，中间空的 | 红 |
| 查 sourcemap `sourcesContent` | PiYear 源码含新节点（6,895 字节） | 红（源码在、代码不在） |

### 真因

**段头注释里写了带反引号的类名**（形如 `` 的 `.m-badge` 反引号 ``），而下面节点自身的 `:title` 又含模板字符串反引号。Vue 的 template 解析按 **HTML 注释规则**走，注释一旦被判成未正常闭合，**后面整段模板（含本枚徽标与整个 `pi-mod-b` 段体）被静默降级成注释文本丢弃**。

编译输出里能直接看到证据——注释变成了 `_createCommentVNode`，注释文本里**裹进了后面整段模板的源码**：

```js
_createCommentVNode(" ★A3（V3.8.35）：...不与格内读数重复。 */\n      <div class=\"pi-mod-acts\">\n ...")
```

### 为什么所有既有门禁都绿

- **回归判据读的是源码**（`read(file).includes(...)`），不是产物 ⇒ `A3-5` 那种判据天然发现不了；
- `vue-tsc` 只查 TS 不查 template 结构；
- `vite build` 不校验 template 完整性，丢了节点照样成功。

**只有实拍 DOM 才看得出段头右缘空着。**

### 修法与新增闸

1. 模板区注释一律不写反引号，更不要把 `title` 的模板字符串搬进注释（已把这条写在坑现场）。
2. **新增判据 A3-8：产物级校验**——不走 `read()`，改走 `@vue/compiler-sfc` **真编译 template**，断言四段的段头 / 段身 / 右缘三个容器都进入了编译输出。这条是本轮最有价值的产出：它堵住了"读源码发现不了"这个判据体系盲区。

### 两条排查纪律（本次绕了一圈才学到）

① **只清 `dist` 不够**，须一并 `rm -rf node_modules/.vite`——否则 vite 会拿旧的转换产物骗你；
② 产物里 class 常量被 vite 提取为 `_hoisted_N` / 单字母名（`Pa` / `Na` / `_a`…），**直接搜 class 字面量必有盲区**，要搜就搜 hoisted 常量的**定义表**。
