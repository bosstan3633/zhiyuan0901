## 二、已确认的产品语义

### 1. 资源卡常用夹

- 常用夹不是新卡片，不复制资源卡，不改变资源卡分类。
- 常用夹数量不限，每个常用夹内卡片数量不限。
- 同一张资源卡可以同时进入多个常用夹。
- 同一常用夹内自动去重。
- 成员是**独立快照镜像关系**：
  - 加入、移出只改变文件夹与卡片的关联。
  - 不修改资源卡标题、正文、标签、置顶、星标、归属、生命周期或策展关系。
  - 不更新资源卡本身的 `updatedAt`。
  - 从常用夹移出卡片、删除常用夹，都不删除资源卡。
- 文件夹内直接展示成员，并直接提供“添加卡片”和逐条“移出”；不要求进入第二层成员明细。
- 源卡删除后，已有镜像快照仍保存；常用夹内可继续查看标题与原始链接，一键打开时使用快照地址。
- 常用夹镜像与任务资源镜像、策展节点资源镜像属于同一生命周期体系：删除源卡不级联删除镜像，移出或删除镜像也不影响源卡、其他常用夹或策展台镜像。

### 2. 策展台资源批量打开

- 只收录当前策展台内实际关联的资源镜像，不把资源池全量导入。
- 原链按可打开的 URL 去重；无链接、失效附件和重复地址跳过。
- 一键打开超过 15 条时先确认，避免误开大量标签页。
- 只打开链接并记录打开次数，不修改资源卡、策展节点或镜像关系。

### 3. 策展台图片附件

- 应用内和导出 HTML 都只增强图片附件的浏览，不改变附件本体、排序或数据。
- 同一节点的多张图片才能前后切换；图库不跨节点混合。
- 缩放只作用于当前图片；切换图片或重新打开时回到“适应窗口”。
- 放大后支持拖动查看；缩小到适应尺寸后不出现无意义的大面积空白。
- “全屏”统一定义为**铺满当前浏览器视口的沉浸式覆盖层**，不依赖系统原生 Fullscreen API：
  - 浏览器兼容更稳定。
  - 导出 HTML 可以由纯 HTML/CSS 实现同一体验。
  - 关闭全屏后回到图库普通状态，不关闭当前图片。

### 4. 导出 HTML

- 继续不注入可执行脚本、不依赖外部字体 / 样式 / 网络资源。
- 继续支持阅读版、树状版、中心论点附件、节点附件、单图、多图、移动端和打印。
- 中心论点关联卡、中心论点附件与节点附件链接继续保持可点击。
- 新增的放大、缩小、重置、全屏全部由图库内控件完成。
- 图库关闭、打印时不显示控制条和暗色遮罩。

### 5. 今日三件事复制

固定模板：

```text
推进[[项目名]]项目，任务内容，助力【指标名】指标落实到位
```

用户示例：

```text
推进[[MOC-内容生成工作]]项目，进一步完善 Obsidian 知识库的架构和用法，形成经验沉淀，助力【skill 地图集完成 3 个可复用技能模块】指标落实到位
```

规则：

- 每个今日计划槽位都有复制入口。
- 任务、有效项目、有效成功指标三者任一缺失时，复制按钮禁用并说明原因。
- 不生成缺项目或指标的半截句。
- 模板之外不自动追加“任务”“项目成功指标”等旧措辞。

### 6. 使用手册

- 重写目标：用户能在 5 分钟内知道“东西放在哪、一件事怎么完成”，而不是读产品历史。
- 以“流程 + 判断点 + 结果”为主：
  - 采集后往哪里去。
  - 三种卡怎么选。
  - 任务如何进入今日三件事。
  - 资源卡如何进入常用夹和资源镜像。
  - 策展台如何从论点到证据再到导出。
  - 云同步如何判断绿 / 黄 / 红。
- 流程图使用产品内统一的 HTML/CSS 流程块，不新增外部流程图服务或运行时依赖。
- 应用内手册与“下载分享版”继续共用 `manual-data.ts` 单一数据源，不允许两套正文。
- 手册版本同步为 V4.2.2。

## 五、数据与兼容

```ts
export interface ResourceFolder {
  id: ID
  name: string
  order: number
  createdAt: number
  updatedAt: number
}

export interface ResourceFolderMirror {
  id: ID
  folderId: ID
  resourceId: ID
  order: number
  addedAt: number
  snapshot?: ResourceCard
}

export interface AppData {
  // ...
  resourceFolders?: ResourceFolder[]
  resourceFolderMirrors?: ResourceFolderMirror[]
}
```

- `resourceFolders` 缺省为 `[]`。
- `resourceFolderMirrors` 缺省为 `[]`；分组与成员分表，同一资源卡可进入多个常用夹。
- 每个成员在加入时保存独立 `snapshot`，并纳入附件索引、软删兼容与附件清理。
- 同一常用夹内按 `folderId + resourceId` 去重；同一资源卡可镜像到不同常用夹。
- V4.2.2 不做成员拖拽排序、自定义封面或文件夹嵌套。
- 云同步新增业务记录类型 `resourceFolder` 与 `resourceFolderMirror`。
- 常用夹的添加、移出、改名、排序、删除同步；抽屉宽度、当前选中夹、搜索词留在本机。
- 同步回执与历史中可显示“新增常用夹 / 修改成员 / 重命名 / 删除常用夹”。
- 导入、导出、恢复、回收站和数据包都必须识别新字段。

## 六、本轮不做

- 不让常用夹改变资源卡生命周期。
- 不增加资源卡 → 任务卡的反向挂载。
- 不改变“只有任务卡和策展节点可以挂资源镜像”的边界。
- 不在 V4.2.2 做图片裁剪、旋转、批注或格式转换。
- 不为导出 HTML 引入 JavaScript、外部 CDN、字体或运行时。
- 不用系统原生 Fullscreen API 作为唯一方案。
- 不改今日三件事的推荐、完成、复制昨日和导出 CSV 逻辑。
- 不编造 V4.2.2 尚未完成的功能或性能数据。

## 八、验收矩阵

### 功能

- 可连续创建超过 3 个常用夹，无数量上限。
- 每个常用夹可容纳任意数量资源卡，同一张卡可进入多个夹。
- 文件夹内直接添加、逐条移出，无需进入成员详情。
- 一键打开只打开可用原链，并说明跳过与重复数量。
- 策展台可一键打开全台去重后的可用原链，超过 15 条先确认。
- 应用内图片可放大、缩小、重置、拖动和全屏。
- 导出 HTML 的同一图库具备同等能力，且无脚本、离线可用。
- 今日复制精确生成新模板；缺项目或指标禁用。
- 手册以流程为主，应用内与下载版正文一致。

### 数据安全

- 常用夹增删不改变资源卡内容、标签、生命周期和策展关系。
- 删除常用夹或移出成员不删除资源卡。
- 普通卡片附件、AI 凭据和界面布局不进入云同步。
- 旧数据导入不丢卡、不报错，不产生同名重复夹。

## 十、已确认口径

1. 常用夹数量不限、每夹成员不限；成员变化作为独立业务镜像同步，但不更新资源卡本身的修改时间。
