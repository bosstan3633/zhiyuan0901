## 一、你拍的三个板，逐条落地

| 你的选择 | 落地 |
|---|---|
| **合并成一枚「知 AI 检索」** | 旧「AI 理解」（`rerankSearch` / `rerankSystem` / `rerankReady`）整体退场删除，浮层类型条上只剩一枚钮。它不是改名字：旧的只能重排**字面已经命中的前 14 条**，卡面上没那几个字就永远召不回；新的候选直接是**库内三类卡** |
| **只读：打开 / 定位，同现有手势** | AI 行走的就是主列表那套 `pickRow` + 同一句 title 文案 + 同一个 hover 选中；零写库（冒烟量过：跑前跑后整库 JSON 一字不差） |
| **先粗筛再精排 + 显式全库兜底** | 本地按相关度打分取一批投料（eco 80 / std 180 / deep 320 张），旁边一枚「全库分批扫」把没看全的那部分补齐 |

## 二、这一刀真正难的地方：把"没看全"这件事说出来

自然语言检索最容易骗人的形态，是明明只扫了一成就说"库里没有"。所以账目全部摊开：

- 组标题一句话：**「挑出 M 条 · 投料 180/202 张 · 34ms」**——分子是这次真投给模型看的张数，分母是当前类型下可检索的卡数。
- `scanned < total` 时右边出现 **「全库分批扫」**，tooltip 先把代价说清：`本次只看了相关性最高的 180 张；全库共 202 张，分批扫约 2 次请求、会慢`。
- 分批扫跑动中钮上报 **`检索中 3s · 已扫 120/202 张 · 已命中 3 · 已回 12 字`**；跑完标题变 **「挑出 6 条 · 投料 202/202 张 · 7.2s · 2 批」**。
- 单次投料**没有中间进度**，就不假装有：那句话改说「库内 202 张里挑」。
- 模型点名但不在候选集里的 id 计入 **「消毒：2 条 id 不在候选内」**（R147 同一口径）。
- 把握度 <0.55 或干脆没给理由的行挂 **「低置信」** 徽标——不藏掉，判定权在你。
- 分批扫**够 16 条就止损**，不为已经够用的结果继续烧钱；也不进同词缓存（慢路径的结果不该被"秒回"冒领）。

## 三、手势能一致，是因为把手势收口回了同一处

`allResults`（面板内三类卡的统一行模型）→ AI 结果按 id 回查这张表 → 行的数据结构、`pickRow`、`openLinkOrLocate`、`locateOnly`（Ctrl+Enter 只定位）全部是原来那一份，**没有第二条实现**。顺带修掉一个一直存在的错位：

> 旧「AI 理解」组渲染在主列表**之上**，却不在键盘扁平列表 `flatList` 里——于是按方向键时"选中的行"和"眼睛看到的行"差着 AI 那几条（R60-1 同型 BUG，一直没人撞到）。本轮把 AI 组按渲染顺序排进 `flatList` 最前，冒烟实测：按 ArrowUp 回到第一行，选中的确实是 AI 组第一行。

## 四、冒烟撞出来的两个真 BUG（都不是断言先写的）

1. **跑动态把秒数渲染成 `[object Object]`**——computed 里插值写成 `${aiSecs}s` 漏了 `.value`。这是冒烟第一版抓到的，产品代码修的。
2. **「全库分批扫」必挂在第二批**：分批共用一把 `AbortController`，而批内的 JSON 闭合早停会 `ac.abort()`——第一批拿完结果把那把刀按下去了，第二批一开局就拿到已 abort 的 signal 直接失败。改成**每批各持一把中止器**（外部取消靠 `aborters.forEach(a => a.abort())` 广播）。这条现在有正面锚点（断言 R150-4 钉 `aborters` 与 `finally { aborters.delete(ac) }`）。

另外 R146 的老教训再次生效：mock 网关 34ms 就答完，"跑动态"窗口根本不存在，第一版冒烟把它当失败——按 R146 口径改成**"要么看得见进度，要么快到不需要"**，测取消与批进度则改用带「慢」关键词的慢网关夹具。

## 六、入口 chunk 口径（本轮再收紧一次）

量法仍是 **newtab 入口 chunk 的静态导入闭包**（3 个文件）。本轮把清单分成两类，避免"全 0"这句话含糊：

- **AI 实现与场景字面量 16 项：全 0** —— `chat/completions` / `zy_ai_v1` / `autoReport` / `openJob` / `withReport` / `检索参谋` / `semanticSearchSystem` / `rerank` / `batchG` / `thesisDraftSystem` / `flattenTaskTree` / `可被反驳` / `资源调度参谋` / `做结构性体检` / `AiRow` / `searchLines`。
- 入口 chunk 里**允许且只允许**出现三类名字：UI 文案（`AI 检索`）、CSS 类名（`gp-ai-more`）、以及 `import('@/shared/ai/select')` 的**解构名**（`semanticSearch`）和懒 chunk 的 CSS 路径（`AiSuggestionDrawer` / `TaskAiMenu`）。逐条查过上下文，均非 AI 代码本体。
- GP 源码里**连 `import type` 都不写向 AI 目录**：契约形状在 GP 内做同形声明（12 行），换来的是那条守卫不需要任何豁免说明。

## 八、真机请你复核的 5 点

1. **写一句自然语言**（不是关键词）点「知 AI 检索」——它挑出来的 3~8 条，是不是你真想要的那几张？没挑中是你的说法问题还是它的问题？
2. **"投料 180/202 张"这句话看得懂吗？**会不会你以为它扫了全库？「全库分批扫」这颗钮的出现时机与措辞够不够明白？
3. **低置信徽标**（模型自报把握低或没给理由）你觉得该露出来还是干脆别显示？
4. **切到「任务卡 / 好奇心」tab 再点检索**——只在那一类里找，符合预期吗？还是你希望 tab 只管主列表、AI 永远跨三类找？
5. **一次调用 34ms、全库两批 7.2s**（mock）——换成你的真实网关后，"等得起"的边界在哪，要不要给分批扫也上托盘？
