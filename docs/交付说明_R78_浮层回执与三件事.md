## 一、为什么：浮层在别人的地盘上，每一秒占有屏幕都要付代价

浮层是**唯一运行在用户真实工作环境里的界面**。它浮在别人（或用户正在读）的网页上，因此它有两笔"债务"是本轮要还的：

**债务一 · 保存回执太重（A3）**

采集一张资源卡或一条任务，成功后会弹出一整屏确认块，5 秒后才自动消失，或在屏幕上一直等到你按 `Esc`。问题是——**这个块什么也不让你决定**：信息你已经填完，动作已经完成，它只是告诉你"成功了"。用户的真实动作是"继续读刚才那篇文章"，却被一整块面板挡住。

**债务二 · 搜到了却排不进去（A7）**

`Ctrl+K` 搜到一条任务，浮层能做的只有"打开链接"或"定位"。但用户此刻真正的念头常常是「**这条我今天要干**」。此前必须：先记住 → 切到新标签页 → 打开方向台 → 找到三件事 → 点空位 → 搜索 → 选中。七步。而任务就在眼前。

本轮把这两步压到 **零切换**。

## 二、关键约束（三条，决定了实现方式）

### 2.1 键位：`Ctrl+Enter` 已被占用

`onSearchKeydown` 里 `Ctrl+Enter` 是 **「定位并打开详情抽屉」**（REQ-045 固化的交互）。A7 需求原文写的 `→` / `Ctrl+Enter` 只能取 **`→`（ArrowRight）**。

而 `→` 在搜索框里本就是"光标右移"。⇒ **只在光标已在输入框末尾**（右移本就无意义）时才截获，其余情况一律放行，不抢编辑键位。

### 2.2 上限：newtab 侧其实没有硬上限

`CompassHome.vue` 的 `selectTaskForSlot()` 直接 `list.push(slot)`，**3 上限只在 `openPicker()` 入口拦**。直接调函数能突破 3（`shared/models` 的注释写着"每天最多 3 个"）。

⇒ 本轮**在浮层侧实现真正的硬上限**，newtab 侧**不在本轮范围**（避免范围膨胀，已登记遗留，见 §八）。

### 2.3 跨上下文合并：整体覆盖写 + 1500ms 缓存

```ts
async function saveData(d) { await chrome.storage.local.set({ [DATA_KEY]: d }) }   // 整体覆盖写
async function getData() { if (dataCache && Date.now() - dataCacheAt < 1500) return dataCache ... }
```

浮层若"读缓存快照 → 改 → 整体覆盖"，期间 newtab 的写入会被**整体吃掉（lost update）**。
⇒ **对策**：A7 写入一律 `await loadData()` **绕过缓存**取最新快照，改完立即 `saveData(d)` 并**同步 `dataCache`**，把竞态窗口压到"读—改—写"一次往返内。整体事务化重构风险/收益不划算，不在本轮。

## 三、交付内容

### 3.1 A3 · 保存回执轻量化

| 项 | 改前 | 改后 |
|---|---|---|
| 资源卡保存成功 | 整屏确认块 + `5s` 自动关闭 | 一行 toast `✓ 已入台 · Enter 打开看板` + `2.5s` |
| 任务保存成功 | 整屏确认块 + `5s` 自动关闭 | 一行 toast `✓ 任务已保存 · Enter 打开{项目/方向台}` + `2.5s` |
| 重复卡确认（"该页面已收录"） | 整屏 | **维持整屏**（需求明文要求） |

**实现要点**——整屏块消失后，原先挂在按钮上的「Enter 打开看板」没有了落点：

```ts
let savedOpenBoard: (() => void) | null = null   // 模块级，替代已被移除的 __zy_saved_open__ 按钮
function showSaved(toastMsg: string, openAction: (() => void) | null) {
  savedState = true
  closeOverlay()
  savedOpenBoard = openAction ? () => { try { openAction() } catch {}; clearSavedState() } : null
  showToast(toastMsg, 2500)
  document.addEventListener('keydown', onSavedKeydown, true)
  savedTimer = setTimeout(clearSavedState, 2500)
}
function clearSavedState() { savedState = false; savedOpenBoard = null; /* 清定时器 + 解绑监听 */ }
```

- `openOverlay()` 开头调 `clearSavedState()`——新浮层一开，上一次的回执态即作废；
- `closeOverlay()` 同步清 `savedOpenBoard` 与 `pendingReplaceSlot`；
- 任务保存的落点按 `projectId` 分流：有 → `/compass/projects?p=<id>`；无 → `/?hl=<taskId>`。

### 3.2 A7 · 搜索浮层 → 今日三件事

**① 入口只给任务卡**

渲染分支带守卫 `g.type === 'task'`：

```ts
const inFocus = todayFocusSourceIds.has(String(item.id || ''))
const focusHtml = g.type === 'task'
  ? '<span class="zy-ri-focus' + (inFocus ? ' on' : '') + '" data-focus-id="…">'
    + (inFocus ? '✓ 已入选' : '→ 三件事') + '</span>'
  : ''
```

按钮默认隐藏，hover 或该行为当前选中行时显形（与既有 🗑 删除按钮同一节奏）；**已入选恒显并置灰**，点击不再写库、直接定位。

**② ≤3 槽硬上限 · 两段式替换**

```
第 1 次触发（已满）  → toast「今日三件事已满 3/3 · 再按一次替换第 1 件」，不写库，置 pendingReplaceSlot = 0
第 2 次触发          → 真正替换第 1 件，清 pendingReplaceSlot
```

两段式是为了**防误替换**——三件事是当天最贵的三个位置，一次误触就顶掉一件不该顶的。中间态存模块级 `pendingReplaceSlot`，关闭浮层即清空（`closeOverlay`）。

**③ 去重**

`todayFocusSourceIds` 由 `dailyFocus[todayKey]`（本地时区 `YYYY-MM-DD`，与 `CompassHome.dateStr` 同口径）派生，每次渲染前 `refreshTodayFocus()` 对齐一次，写入后再对齐一次。
已入选 → `showToast('该任务已在今日三件事中')` + `focusLocateTask(item)`，**不写库**。

**④ 定位分流**

```ts
const route = t?.projectId ? '/compass/projects?p=' + t.projectId : '/?hl=' + id
```

挂了项目/指标 → 项目详情；否则 → 调度台任务调度模块高亮（沿用既有 `?hl=` 链路，不碰 `tabs.query` hash）。

**⑤ 写入同构**

写入的槽位与 `CompassHome.selectTaskForSlot()` **结构完全一致**，保证调度台三件事卡片能直接识别：

```ts
{ id: uid('focus'), sourceType: 'task', sourceId: taskId,
  text: t.title, done: t.status === 'done', doneAt: t.completedAt }
```

**无数据模型改动、无迁移、无新增存储键。**

## 八、遗留

| 项 | 说明 | 建议 |
|---|---|---|
| newtab 侧无硬上限 | `CompassHome.selectTaskForSlot()` 无 3 上限校验（只在 `openPicker` 入口拦） | 下轮补：把上限校验下沉到 `selectTaskForSlot`，两入口口径统一 |
