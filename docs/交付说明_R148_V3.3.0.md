## 二、性能改了什么（以及没改什么）

### 1) 热度统计拆独立键 `zy_stats_v1`（最大的一笔）

**实测病根**：单击一张卡看详情 → `recordResourceOpen` 改 `callCount/lastCalledAt/stats.*` → `store.persist()` 把**整库**（medium 档 ≈600KB）重新序列化并写盘。你每看一张卡，都付一次全库写的账。

**改**：`shared/storage/hotStats.ts` 新键只装 `{cards:{id:[次数,最近打开]}, stats}`；13 处"只改热度"的入口（资源台单击/双击/搜索打开/关联卡/北极星下钻/任务与好奇面板行…）改走 `store.persistHot()`。三条口径写死在文件头：

1. **主树仍是唯一消费口径**——视图读法一字未改，本键只是落盘通道 + 重启后的权威值；
2. **启动期一次 `get` 同时取两键**——拆键不能变成多一次启动 IO；
3. **任何整库写入（saveData / saveDataNow / 外部合并 / 导入）都同步刷新本键**——所以"旧热度盖住刚导入的新热度"这类岔路不存在；回滚（重置初始状态）连本键一起 `clearHot()`，否则旧 stats 下次启动会覆盖回来。

**迁移**：老数据无此键 → 首次启动以主树落一次并打 `hotStatsSplitAt` 戳，幂等；导出 JSON 仍带统计（导出走主树，天然完整），导入拆回——`test-import-compat` 4/0 是这条的验收。

### 2) 派生缓存的记忆层（`getMutationSeq`）

`taskMaturity(task)` 等直接写在模板上（任务面板 11 处行位 + 方向树 + 项目页 + 详情抽屉），每行每次渲染都新建一个 `{score,grade,label,reasons[]}`；`metricMaturity` 还要把其下任务全扫一遍。

**改**：repository 加**内存脏计数**（每次 persist 意图同步 +1，不等写盘成功），maturity 引擎按 `seq + 日粒度 + 实体自身字段指纹` 记忆；`tagUsage` 从"按标签树每个节点各扫全库"改成**一次遍历建表**（路径+叶子双口径与"排除回收站软删卡"逐字保留，R130-1 已备案改写并加等价性说明）。

> 顺手堵掉一条现存隐患：原先派生缓存若用 `dataVersion` 判失效，**它只在写盘成功后自增**，防抖窗口内会读到旧索引。

### 3) KeepAlive 补齐四个重计算页

`/settings`、`/recycle`、`/compass/projects`、`/compass/tree` 此前**每次进都全量重挂载**（设置页 3500+ 行，挂载即算 `lcCards`/`gFlat`/标签用量）。四页补显式实例名并入缓存（子路由在 CompassShell 内套自己的 keep-alive）。E2E 22/0 复跑确认没有"缓存导致状态串台"。

### 4) 实测之后判定**不做**的：面板增量渲染

M1 冷启动 433-515ms **已经包含** 400 任务面板的挂载，M11/M12 单次切台阻塞只有 50-69ms——给任务/好奇面板再加一层增量渲染，收益不覆盖它引入的定位（`?hl=`）与拖拽风险。**判停写进断言 R148-7**，不是忘了做。

## 三、AI 任务后台化（你附截图点名的那条）

**病根不是交互是架构**：抽屉就是任务本体，`props.job` 一换即 `abort()`。所以手滑点到别的诊断，正在跑的多批归架直接蒸发；再点同一个功能又从头开始。

**改**：新增 `shared/ai/runner.ts` 任务注册表——

- **按 `jobKey` 幂等**：在跑 → attach 看进度；跑完 → 看结果 +「↻ 重新运行」；没有 → 起一个。18 个场景工厂各配稳定 key（卡片级用 `rec:<id>`、`opt:<id>` 这种带锚点的，避免跨卡串结果）。
- **关抽屉不杀任务**：只有「⏹ 停止」才中止。设置页顶部新增 **AI 任务托盘**：列出在跑/排队/跑完的每一份，带秒数与投料，点「展开」回到结果。
- **并发上限 2**，超了排队并写明"排队中（同时最多 2 个）"，不偷偷并行打满你的网关。
- **投料账搬进任务**（R147-b 同一口径），托盘里就能看到"跑动中 12s · 投料 594 字 · 1 次请求"。

**报告自动落卡（按你选的"只新增类"）**：深度诊断跑完自动存一张「🧠 深度诊断 · 日期」到**资源台 › 待分类**，打「AI 报告·待审阅」标签，抽屉里点名落点。边界写死在 `shared/ai/reports.ts`：只 `unshift` 一张新卡、绝不 `splice`/改既有卡（断言反向锁死）。

> **一条要你知道的取舍**：周回顾 / 成果文稿 / 深度洞察这三个的"采纳"本来就是"存一张卡"，若也自动落卡，用户再点采纳就会**落两张**。所以本轮只给诊断接了自动落卡，其余三个先享受"attach 不重跑"。若你要它们也自动落，我把它们改成"只读报告 + 自动落卡"、撤掉采纳按钮——一句话的事，但不肯替你决定。

**首版踩的坑（已修+备案）**：`openJob` 把新任务直接标成 `running`，而 `execute()` 的守卫是"已在跑就返回"——**任务被自己的守卫挡住，永远 0 秒**。改成先入队、由 execute 提升。

## 四、改后实测（同档同法，3 次采样）

| 指标 | 改前 | 改后 | 判读 |
|---|---|---|---|
| **M7 单击卡片 → 主键重写次数** | 1 次 | **0 次** | 拆键达成 |
| M7 同步成本 | 5.3ms | 4.4-5.2ms | 持平（本来就不在同步段） |
| M8 点置顶 同步 | 28-36ms | 22.8-28.4ms | −20% |
| **M9 进设置页（二次）** | 101ms | **70-79ms** | −25%（keep-alive 生效） |
| M9 进设置页（冷挂） | 190ms | 162-246ms | 噪声带内 |
| M11/M12 单次切台阻塞 | 70 / 50ms | 67-69 / 0-51ms | 持平 |
| M1 冷启动 | 433-490ms | 486-515ms | 同码不同轮 420~515ms，噪声带内 |
| **M3c 窗口三长任务总计** | 8996-9135ms | **8989-9142ms（未动）** | **未收口，见下** |

**M3c 这条我不糊弄**：改前改后一模一样，说明那 9 秒（约 16 个 ~1 秒长任务）**不在本轮改的任何链路上**。已排除的：单次切台（M11 67ms）、单击卡片（M7 block 0）、面板挂载（M1 已含）、写盘（M6b 11ms）。**下一轮第一个动作就是给它做窗口内 CDP 定向采样**，不猜、也不拿"其他指标变好了"糊过去。

**新增的 M13（来回切台 4 次）**：墙钟 2670ms，主线程阻塞仅 401ms，最大单任务 65ms。也就是说"切换不够丝滑"的体感里，**约 1/6 是主线程阻塞，其余是渲染/合成与等待**——这条给了下一轮一个明确的靶子：把每次切换的墙钟 310-450ms 压到 150ms 以内。
