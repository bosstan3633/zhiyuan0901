## 二、交付内容

### D1 P0-1 分类树结构校验与递归防护（最高优先级）

**病根**：`Workspace.vue` / `GlobalSettings.vue` 两条导入路径只查 `version`，不校验环 / 深度 / 孤儿父节点；而 `mergeById` 的 `{...existing, ...incoming}` 会覆盖 `parentId`，因此**一条构造过的 JSON 就能造出环**。环一旦入库，5 处无 `visited` 保护的递归/循环会在渲染路径上无限展开——`levelOf` 的 `while(cur)` 直接**冻结标签页**，`catAggCount` 在模板中被调用使资源台/策展台**打不开**，坏数据又删不掉，只能清空扩展数据（全部陪葬）。

**修复（双保险）**：

1. **入口净化**——新增 `v2/src/shared/utils/catTree.ts`：
   - `MAX_CAT_LEVEL = 4` / `MAX_CAT_NODES = 5000` **单一来源**（此前 4 这个上限散落在多处各写各的）；
   - `sanitizeCategoryTree()`：迭代至稳定——成环节点、孤儿父节点、超过 4 级的节点一律**提为根节点**（只修结构、不删数据）；节点数超上限直接拒绝该包；
   - `catTreeFixNote()`：把修复量（环 N 个 / 孤儿 N 个 / 超深 N 个）作为可读文案回传。
2. **运行期兜底**——所有递归与上行走链补 `visited`：
   - `CurationCenter.vue`：`levelOf` / `subtreeHeight` / `deepDescendantIds` / `nodeCount`；
   - `Workspace.vue`：`descendantIds` / `drillCatRows` / `groups` / `kanbanCategories.pathOf` / `sidebarCats.pushTree` / `selectSidebarCat` / `treeCatOptions.push` / `pyDepthOf` / `pyramidLevels.walk` / `pyLayout` / `pyHeightOf` 共 11 处。
3. **顺带修复审计点名的静默丢失**——`Workspace.vue:1679 pyLayout` 原先只从 `!parentId` 下钻，环内节点会静默消失；现补 `placed` Set + 补漏遍历，**环内节点不再丢失**。
4. **导入侧接线**——全量导入（`GlobalSettings.mergeImport`）与策展台数据包导入（`Workspace.handleBoardImport`）均先净化；toast 追加「分类树已自动修复（环 N 个…）」；超上限则明确拒绝并提示。

### D2 P1-1 导出与备份剥离 Airtable 明文凭证

`exportAll` 原先展开整个 `AppData`，`airtableSync.pat`（PAT 明文）**无剥离**直接写盘；`GlobalSettings:1614` 的导入前自动备份同样。产品本身鼓励「导出即带走 / 分享数据包」——等于把令牌一起送出去。

**修复**：`exportAll` / 按台导出 / 导入前自动备份三处统一 `const { airtableSync, ...safe } = d` 后再写盘。

### D3 P1-2 全局搜索漏过滤资源台本体

`GlobalPopups.vue:577` 结果集只 `filter(!w.archived)`，而计数与类型树都有 `w.id !== CURATION_WS_ID`——同一个界面两套口径。**修复**：结果集补 `&& w.id !== CURATION_WS_ID`，三处对齐。

### D4 P1-3 任务采集浮层监听器泄漏 → 重复写数据

`overlay-impl.ts:1245` 的 `onTcKey` 是局部闭包，每次唤起都 `document.addEventListener` 且全文无对应移除；`closeOverlay` 只清 `innerHTML`。结果：第 N 次唤起后 `Ctrl+Enter` 会触发 N 个监听器，**一次保存写入 N 条重复任务**。

**修复**：改为模块级 `activeTcSave` 指针 + 模块级 `onTcKeydown` 在 document 上**只注册一次**；`closeOverlay` 置 `activeTcSave = null`。

### D5 P1-4 双向引用两处不同步

1. `CuriosityPanel.vue` 指标下拉仅 `disabled`，清空项目时不重置 `convertMetId` → 会造出「有指标无项目」的非法任务。**修复**：项目下拉加 `@change` 复位指标。**数据层再加一道兜底**：`curiosity.ts convertToTask` 里 `const safeMetricId = projectId ? metricId : undefined`。
2. `curiosity.ts convertToTask` **不写 `metric.taskIds`**（全项目唯一漏双写的路径）。**修复**：补写 `metric.taskIds.push(task.id)`。

### D6 P1-5 多窗口快捷键定位错窗口

`background/index.ts` 5 处 `tabs.find(t => t.id != null)` 不限 `windowId` → 多窗口时可能定位到别的窗口的标签页。**修复**：优先同 `windowId`，找不到再全局回退。
