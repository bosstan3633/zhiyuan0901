# 交付说明 · R3-B2 —— 方向树：同目标内拖拽排序 + 置顶回归（未升版）

日期：2026-09-30 · 基线：`40d8bb1`（R3-B1 方向台树即首屏）· 触发：B1 交付时我报了一处溢出项（置顶与手动排序随主航线右键菜单退役、无替代入口），用户拍板 **「不退，保留手动拖拽排序和置顶（在同一个战略目标下）」**。

## 一、口径

两项能力落回方向树，**不回到右键菜单形态**：

- **拖拽排序**：卡头动作组里多一枚 `⠿` 手柄（hover 才显，零常驻占位），`draggable` 起拖 → 同目标的另一张卡头是落点 → 落位后按"当前所见序"逐位重写 `order` 并落库。
- **置顶**：▾ 折叠菜单加一项 `📌 置顶到本目标前排 / ☆ 取消置顶`，卡头出现 📌 徽标。
- **只在同一战略目标内**：`dragProj.dirId !== 目标 dirId` 直接不接。跨目标改归属是另一件事（走项目详情），不做顺手支持。

## 二、两个设计决定（都是为了让"拖了就是拖了"）

**1. 排序键 = 主攻 → 置顶 → order，而不是把 order 当唯一真源。**
`pinned` 不写进 order 语义里，它只是"钉在非主攻组最前"的快捷方式（置顶时把 `order` 压到该组最小值 −1，保证组内也稳定）。这样 R59-T3 那条「主攻项目置前」的既有产品口径一字未改，`🚀` 卡永远在前排。

**2. 落位时清掉被拖卡的 `pinned`。**
如果不清：你把一张 📌 卡拖到第 3 位，排序键立刻把它弹回前排——**看着就像"这张卡拖不动"**。拖拽的语义是"用位置说话"，所以落完即解除钉住。反过来，从主攻组拖出去不会解除 `isFocused`（主攻是产品级状态，最多 2 个、直通调度台速览，不该被一次拖拽顺手改掉）。

**3. 落位指示用 `inset box-shadow`，不用 border。**
`.tp-head.drop-on { box-shadow: inset 0 2px 0 0 var(--accent); }` —— 指示态不许把版面挤动一像素（与 R3-B′ 折叠态那条 `outline 不用 border` 的纪律同源）。这条也写进了断言（判 `.drop-on` 不得走 border）。

## 三、断言与 E2E

- **新增 2 条**（`99-recent.cjs`【R3-B2】）：★拖拽只在同目标且所见即所得（手柄 draggable + dragover 同目标非自身才给指示 + drop 重写 order + 落完清 pin + 指示不落 border）、★排序键口径（`isFocused → pinned → order` 三元比较式逐字核 + 置顶压 order + 徽标 + 两态文案 + 落库）。
- **重指 5 条**（都是 B1 里刚写成"退役"的那批，随拍板改回"回归树内"，逐条带 ★R3-B2 备案）：R49-18 置顶、R49-19 手动排序、R99-4 置顶与排序去向、R121-6 ▾ 菜单四项→五项、R3-B1「退役不悬空」（把 `function togglePin`/`function moveProject` 从"零命中"清单里摘出去——它们以 `toggleProjectPin`/`onProjDrop` 的形态回来了，留在清单里就是假装没发生）。
- **E2E 新增 E2E-29**：真实事件序列跑通「拖第 1 张到第 2 张 → DOM 顺序翻转 + `order` 落库（策展=1 / 回填=0）→ ▾ 菜单置顶第二张 → 它跳到前排且 📌 徽标在位 + `pinned` 落库」。
  ★踩到一条通用时序坑：**Vue 的 class 绑定在下一个 tick 才落到 DOM**，`dispatchEvent('dragover')` 后同步读 `classList.contains('drop-on')` 必假（首轮 E2E-29 就红在这里，而拖拽本身其实已经生效）。等一拍（80ms）再量才是真的在量渲染。
