## 五、边界如实

1. **反漂闸只覆盖四个数字**（规模、债务条数、时效行、差异账在不在）。卡上其余几十项——性能表、体积、文档数、AI 入口数——**仍在闸外**，它们靠"评审前重跑"保证，判据管不了（管了就得每次回归都跑 perf + theme-audit，不可接受）。
2. **§2.3 性能表是今天这一跑的读数**，同机不同天仍会漂（采样纪律不变），所以那一节写明了日期与种子规模；换种子或换机器都要重量。
3. **ZIP 没重算**：重打包是外向动作，按约定等 R5 收口一起做 ⇒ 卡上那行是"待复核"，不是数字。
4. `00` / `03` 只替换了失真数字与退役红线名，**没重排结构**。模式 B/C（模型只能对话 / 只能看 repo）现在还用得上吗？值得下次连这个问题一起拍板。
5. 判据读的是仓库根 `评审交接包/` 这个路径。**将来包改名或搬走，R4-Ey① 会红**（响亮方向），处置是同步改判据里的路径，而不是删判据。
6. 透视卡里那两条"低成本验证项"换成了当前为真的两条（popup 白屏 #117 / 索引反漂闸 R163-1）。**#117 仍是待拍板的产品取舍**，不是本轮能替用户决定的。
