## 二、沉淀资产（下轮直接复用的规矩）

1. **能收口在一处，就不要让 N 个宿主各写一遍**。R148 的"宿主传 job-key"是错的设计——13 个入口里 12 个漏绑。本轮把判据搬进抽屉，漏绑的可能性归零，且新增场景只要工厂带 key 就自动继承全部行为。
2. **"撤掉一个按钮"必须同时回答"那结果去哪了"**。撤采纳的前提是自动落卡 + 回执点名落到哪张台 + 兜底路径（宿主没绑 key 时自己结算）。只删按钮不接住产出，比旧版更糟。
3. **异步中止要有轮次所有权**。任何"取消后立刻重发"的结构（rerun、重试、换参数重跑）都要有一个 attempt/epoch 令牌，否则晚到的 rejection 会误杀新一轮。这条已经用 A/B 验证成一条断言（R149-4）。
4. **每个终态都要有画面**。running/done/error 之外，用户主动的"停止"也是一个终态（stopped），必须有一句话解释它作废了什么、下一步能干什么。
5. **自动落卡要防重复堆积**。同一天重跑刷新同一张，不然报告型场景会把资源台待分类变成日志目录。
6. **门禁的可用性本身也是被测对象**。"要设一个环境变量才跑得动"的门禁等于没有门禁；浏览器回落在 e2e 与 perf 两边必须同口径。
7. **测量口径改严时，先把旧结论自己推翻一遍**。本轮把入口字面量从"单文件"改成"静态闭包"后，R148 的"14 项全 0"就不再成立（`zy_stats_v1` 本在启动链），如实写进交付说明 §六 而不是维持旧说法。
