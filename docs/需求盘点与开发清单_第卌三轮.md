## 二、问题根因初判

### 2.1 BUG-1：新建任务 Ctrl+Enter 保存不更新列表（🔴 待复现确认根因）

**现状代码**（`v2/src/newtab/views/CompassActions.vue`）：

- `createNewTask()`（L396-418）创建 `title='新任务'` 占位任务，`d.value.tasks.unshift(task)` 入库，`openTaskSidebar(task)` 打开抽屉
- `saveTaskTitle()`（L697-704）：
  ```ts
  function saveTaskTitle() {
    if (!selectedTask.value) return
    const val = taskTitleDraft.value.trim()
    if (!val) { showToast('标题不能为空'); return }
    selectedTask.value.title = val          // ⚠️ 直接改原始对象属性
    selectedTask.value.updatedAt = Date.now()
    store.persist()
    showToast('✓ 已保存')
  }
  ```
- `selectedTask = ref<TaskCard | null>` 持原始 task 对象引用（**非 store reactive Proxy**）
- 模板用 `{{ task.title }}`（v-for 渲染时 task 是 store reactive Proxy 子代理）

**根因初判**：`selectedTask.value.title = val` 直接改原始对象属性，**绕过 store reactive Proxy 的 `set` trap → 不触发 `trigger` → 模板不更新**。

**矛盾点**：用户描述"再次从列表点开抽屉编辑就能保存显示"——按此根因，第二次也该不更新。**因此根因可能另有他处**（如：第一次 createNewTask 后 `nextTick` 自动 focus 全选，用户键入文字后未失焦就按 Ctrl+Enter，v-model 同步但某些时序导致 drawer 提前关闭？），需 E2E 复现确认。

**修复预案**（任选其一，先复现再敲定）：
- **方案 A**：saveTaskTitle 改为通过 store 找任务再赋值
  ```ts
  const t = d.value.tasks.find(x => x.id === selectedTask.value!.id)
  if (t) { t.title = val; t.updatedAt = Date.now() }
  selectedTask.value.title = val  // 编辑态同步
  store.persist()
  ```
- **方案 B**：openTaskSidebar 时 selectedTask 指向 store Proxy 元素
  ```ts
  selectedTask.value = d.value.tasks.find(x => x.id === task.id) || task
  ```
- **方案 C**（叠加）：Ctrl+Enter 改为先失焦（避免 v-model 时序问题）再 saveTaskTitleAndClose

### 2.2 BUG-2：批量管理下双复选框（✅ 根因已锁死）

**现状代码**（L1005 / L1027 / L1042，三处任务行模板）：

```html
<div v-if="batchMode" class="batch-check" :class="{checked: selectedTaskIds.has(task.id)}" 
     @click.stop="toggleSelect(task.id)">{{ selectedTaskIds.has(task.id)?'✓':'' }}</div>
<span v-else class="t-drag">⋮⋮</span>
<div class="check-sm" :class="{done: task.status==='done'}" 
     @click.stop="cycleTaskStatus(task.id)">{{ task.status==='done'?'✓':task.status==='doing'?'◐':'' }}</div>
```

**根因**：`batchMode=true` 时一行同时渲染：
- `batch-check`（批量勾选 = 选中 selectedTaskIds）
- `check-sm`（状态切换 = todo/doing/done）

**修复预案**：batchMode 下隐藏 `check-sm`（状态切换走抽屉），保留 batch-check；同时把空 `check-sm` 位置的左侧 padding 收齐以保持行高不变。

### 2.3 需求 R-1：任务卡删除入口（现状：仅抽屉有）

**现状**：
- 抽屉底部已有 `🗑 删除任务` 按钮（L1344，调用 `deleteTask`）
- 右键菜单有"删除"（L828）
- 卡片行**无直接删除按钮**（hover 也不显）

**方案**：任务行 hover 时右侧出现 `🗑` 删除按钮（`@click.stop="deleteTask(task.id)"`），与右键菜单、抽屉三入口并存；删除走 `deleteTask(taskId)` 走软删（`deletedAt = Date.now()`，回收站可恢复）。

### 2.5 需求 R-3：今日三件事卡片紧凑化

**现状**（图3）：三列卡片纵向过高（~140px），任务标题只占一两行，视觉空旷。

**根因初判**：`v2/src/newtab/views/CompassActions.vue` 今日三件事卡片的 CSS `min-height` / `padding` 偏大；行高未做紧凑处理。

**方案**：
- 取消 `min-height`，让卡片高度随内容自适应
- 缩小 `padding`（如 `20px` → `14px`）
- 标题字体略增（`14px` → `15px`），行高从 `1.5` → `1.4` 增强紧凑感
- 卡片底部"未关联"标签区从 14px 缩到 12px
- 保持三列布局不变

### 2.7 需求 R-5：北极星指标与周/月/累计周期关联

**现状**（`NorthStarPanel.vue`）：
- `period = ref<'week' | 'month' | 'all'>`（L17）
- 头部三按钮：周/月/累计（L260-263）
- WCE：`3项激活 本周+7`（已带周期）
- WRR：`126次打开 本周38次`（已带周期）
- DHHI：`1方向·0已投射·0在轨`（**无周期标签**）
- 模块分组 / 链接卡片 / 未归档任务：均**无周期标签**

**根因**：`newtab/stores/compass.ts` 中 `northStarMetrics(period)` 返回 DHHI/WCE/WRR 三项；模块分组、链接卡片、未归档任务是 `NorthStarPanel.vue` 内部从 store 直接取，无 period 维度。

**期望**：用户原话"知源北极星的指标数，要跟周/月/累计时间统计周期关联起来"——可能含义：

**A. 严格解读**（所有指标都按周期统计）：模块分组、链接卡片这种**纯计数**与时间无关，无法分周期；建议明确哪些指标**不参与周期**（保持原状）+ 哪些**参与周期**（WCE/WRR 已有，DHHI 待补）

**B. 宽松解读**（仅在每个指标下补周期副标）：即使数字无变化，也在副标加"本周/本月/累计"提示

**澄清待确认**（见 §三-2）：严格 vs 宽松？
