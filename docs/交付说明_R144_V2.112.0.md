- 入口：策展台中心论点横幅（有论点/无论点两态都在位），Workspace 压在 1500 行的验收线**净增 0 行**——按钮、评审抽屉、AI 懒栈与自带样式全收进新组件 `ThesisAiBtn.vue`。
- 投料 `projectDeckThesis`：本台卡群全量台账（分类归属/描述现状/标签/打开次数）＋愿景使命锚＋**按需补读正文**（描述<10 字且 http(s)，复用 R143 `reviseSnips` 会话缓存与 `SNIP_CAP` 档位，抓过的零重抓，进度实时回显）。
- 契约 `thesisDraftSystem`：论点必须是**一句可被反驳的判断**（≤30 字，不许文件名式、不许口号），why 必须点名证据卡，parts=2~4 支 MECE 分论点各带收卡定义与佐证 cardIds；卡群支撑不起时要求如实说「支撑不起」。
- parse 消毒：论点≤40 字、支≤5 且同名去重、**cardIds 只认本台活卡且一卡只归一支**（幻觉 id 与跨支重复卡直接丢，冒烟实测 4 张幻觉/重复 id 只剩 3 张真卡）；`ensureThesisCard` 建/取本台唯一主题卡。
- **主采纳=只写中心论点卡**（🤖 块整段替换、重复采纳不堆积），分类与卡片归属一律不动；**「🗂 分论点建成分类并归架」是显式次通道**（同名分类复用、顶层 ≤12 封顶）。右上角可换执笔专家（换后自动重跑）。

## 三、数据与兼容性

唯一模型变更 = `TaskCard.parentId?: ID`（可选，零迁移、零消毒脚本）：老数据无此字段即全部顶层；父卡被硬删/换指标导致指针悬空时，`flattenTaskTree` 与 `parentTitleOf` 双端各自兜底（子按顶层出、记号不显示），**不会有任何卡从视图里消失**。G1 主采纳不动分类不动卡归属；G2 只写 status 与走既有转化通道；G3 只新增镜像投影记录；G4 只新增一张卡。AI 侧纪律不变：密钥独立键 `zy_ai_v1` 不进数据链、建议只活内存态、勾选采纳才落库、全手动触发零轮询、入口 chunk 零 AI。

## 四、真机复核点位

1. **论点味道**：G1 采纳写进主题卡的论点，是不是你敢署名的判断（还是复读卡名）；不满意直接不勾该行重跑或换专家。
2. **骨架落地**：「🗂 分论点建成分类并归架」的归架抽查 5 张——一卡一支是否合你的直觉。
3. **研判尺度**：G2 一轮里 convert 的比例（多于一半就是它在讨好你），以及被搁置的卡事后想不想得起来。
4. **佐证准度**：G3 推荐的卡里有没有「主题词相同但论证方向不同」的硬凑。
5. **文稿可用性**：G4 下载下来的 .md 是否能不改直接发；证据不足时是否真的敢说不足。
6. **软层级手感**：真实拆解跑一次，看方向树缩进与 ⤴ 的位置是否顺手；父任务删掉后子任务的去向是否符合预期。
