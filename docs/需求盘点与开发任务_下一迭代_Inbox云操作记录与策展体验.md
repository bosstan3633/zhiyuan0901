# 下一迭代需求盘点与开发任务：Inbox、账号操作记录与策展体验

日期：2026-11-05

产品基线：V4.1.1（`4897d51`，已发布）

交付状态：**V4.1.2 已完成开发并通过发布门禁，线上 Supabase 迁移已执行**。真实双设备与双账号运行验收边界以交付说明为准。

发布版本：V4.1.2。

文档性质：本轮功能优化清单、交互口径、开发任务、数据方案与验收边界的单一真源。

## 一、本轮目标

本轮不扩展多人协作等产品边界，集中完成四类优化：

1. **Inbox 体验闭环**：角标轻量化、未转化内容可开详情、详情内可转化、支持一键清空。
2. **账号级操作记录**：同一账号下不同设备的卡片操作能够合并、上云、互相可见，并成为“今日战报”的统一数据源。
3. **云同步明细可下钻**：本机基线和云端修订中的具体记录可以继续打开右侧详情，查看记录背后的事实。
4. **策展体验收口**：多图附件可连续浏览、页面设置菜单退役、画布操作日志可回滚、方向树任务状态视觉统一。

## 二、优先级

| 优先级 | 范围 | 说明 |
|---|---|---|
| P0 | Inbox 未转化详情与转化、账号级事件合并、同步记录详情 | 影响核心闭环和跨设备数据可信度 |
| P0 | Inbox 一键清空、空角标隐藏 | 用户已明确反馈，且属于高频入口 |
| P1 | 策展多图切换、页面设置退役、画布日志回滚 | 直接影响策展台日常操作 |
| P1 | 方向树项目/指标/任务视觉 | 提升全局可读性，不改业务模型 |
| P2 | 回归、四主题实拍、文档、构建、出包 | 所有 P0/P1 完成并通过门禁后执行 |

## 三、现状核对

以下能力已经在 V4.1.1 存在，本轮不重复重写，只纳入回归验收：

1. 移动端已经使用单一采集输入区，链接和文本共用同一提交按钮；成功后已有回执并聚焦输入框。
2. 调度台“手边的卡”已经将 Inbox 放在第一位并默认显示。
3. 中心论点模块已经可展示关联资源卡和节点附件缩略图。
4. 策展节点下部已经有独立附件行，可上传、删除和点击预览图片、PDF、HTML。
5. 策展画布已经有最多 10 步的上一步/下一步。
6. 方向树项目已有进度条，成功指标已有百分比文本。

本轮需要补齐或修正：

1. Inbox 的 0 角标仍显示，非零角标仍使用红色。
2. 未转化 Inbox 行不能打开详情，只有已转化行可以打开目标卡。
3. Inbox 只有逐条删除，没有一键清空。
4. 事件日志会在云恢复时整体替换，上传时也可能被另一台设备的快照覆盖；事件 ID 还没有设备级唯一性保障。
5. 同步明细抽屉内的记录目前只做就地展开，没有二级右侧记录详情。
6. 策展附件预览一次只接收一个附件，没有同节点多图左右切换。
7. 策展台仍保留完整“页面设置”齿轮菜单。
8. 画布历史项只有动作名和快照，没有时间、ID、日志视图和点击回滚。
9. 成功指标只有百分比文本，没有进度条；任务状态在金字塔和树状中视觉区分不足。

## 四、功能优化清单

### F01 Inbox 角标重设计

#### 交互

1. 覆盖四处角标：
   - 调度台“手边的卡”Inbox 页签。
   - Inbox 列标题计数。
   - 二级 Inbox 页标题计数。
   - 手边卡二级页签 Inbox 计数。
2. 数字为 `0` 时不渲染角标，不留空胶囊。
3. 数字为正数时使用轻量强调色胶囊：`--accent-light` 背景、`--accent-ink` 文字。
4. 不使用红色，不与错误、危险、删除语义混淆。
5. 超过 `99` 显示 `99+`。
6. 离线且仅展示缓存时，可保留弱化边框或灰点表达“缓存态”，但不再显示红色。

#### 验收

- 0 条未转化记录时，四处角标完全消失。
- 1、9、99、100 条时宽度稳定，不挤压页签。
- 四套主题下对比度通过 theme-contrast 门禁。

### F02 未转化 Inbox 也作为完整 Inbox 卡

#### 列表

1. 每一条 Inbox 采集都以卡片形态展示，不再只有已转化记录可交互。
2. 卡片至少展示：
   - 标题或正文首行。
   - 采集时间。
   - 链接/文本来源标记。
   - 未转化/已转化状态。
   - 目标卡镜像状态（已转化时）。
3. 点击卡片主体打开右侧详情。

#### 未转化详情抽屉

抽屉展示：

- 采集类型：链接/文本。
- 原始链接或完整正文。
- 可选标题、备注、标签。
- 采集时间。
- 未转化状态。
- 删除按钮。
- 转化为任务卡、好奇心卡、资源卡三个动作。

转化成功后：

- 当前抽屉切换为“已转化为 X 卡”状态。
- 另外两类转化入口立即置灰。
- 提供“打开目标卡”按钮。
- Inbox 当前行更新为对应卡片的镜像入口。
- 目标卡进入对应卡片池。

#### 已转化详情抽屉

- 展示 Inbox 镜像信息和目标卡状态。
- 可直接打开任务卡、好奇心卡或资源卡详情。
- 删除 Inbox 只移除镜像入口，不删除目标卡。

#### 数据口径

- 三条转化动作共用同一套 `useInbox.convert()`，避免列表、详情抽屉、首页快捷动作各写一份。
- 已转化状态以云端 `converted_kind + converted_card_id` 为最终真源。
- 本地先建卡、云端状态补写失败时，继续使用现有待补写队列，不重复创建目标卡。

### F03 Inbox 一键清空

#### 交互

1. 二级 Inbox 顶部工具栏新增“清空 Inbox”按钮。
2. 池子为空时按钮禁用或隐藏。
3. 点击后二次确认，明确写出：
   - 会清除未转化采集。
   - 会移除已转化记录在 Inbox 中的镜像入口。
   - **不会删除已经进入任务卡池、好奇心卡池、资源卡池的目标卡。**
4. 清空成功后显示撤销入口，建议保留 5 秒。
5. 离线时只允许查看，不执行批量清空。

#### 实现口径

- 不物理删除记录，使用 `dismissed_at` 批量软删除，保证可撤销。
- 清空范围默认是整个 Inbox 池，而不是当前分组。
- 撤销只恢复本次被清除的 Inbox 记录 ID，不影响已入池目标卡。
- 若未来需要“清空当前分组”，另设入口，不与本次“一键清空”混淆。

### F04 移动端统一采集验收

当前代码已经满足单一输入区。本轮不重写交互，只补回归和文案一致性：

1. 页面不出现“链接/文本”分段切换。
2. 一个输入区可输入纯 URL、短句、多行文本、带 URL 的说明文字。
3. 纯 URL 自动识别为链接采集，其余保存为文本采集。
4. 提交成功后明确显示“已提交到 Inbox”，并提供“继续采集”。
5. 离线时显示“已暂存，联网并登录后自动同步”，不得冒充已经到达云端。

### F05 账号级操作记录同步

#### 目标

同一账号下，A 设备产生的卡片操作记录在 B 设备可见；今日战报对账号下所有设备的记录统一汇总。

#### 本轮“操作记录”的范围

本轮账号级操作记录指现有卡片事件体系：

- 新增。
- 删除。
- 恢复。
- 永久清理。
- 任务/好奇心状态变更。
- 卡片被调出。

不把每一次页面点击、搜索、打开菜单都写成操作记录；这些属于行为埋点，不在本轮范围。

#### 数据策略

采用“账号级事件表为主、本机缓存为辅”：

1. 新增 Supabase `account_events` 表，作为账号级操作记录真源。
2. 本地 `zy_event_log` 继续作为离线可用缓存，不再以云快照中的事件数组作为唯一真源。
3. 事件 ID 改为设备级全局唯一：
   - 稳定设备 ID。
   - 时间戳。
   - 本地序号或随机片段。
4. 设备可离线写本地日志；联网后按事件 ID 幂等上传。
5. 拉取时按事件 ID 去重，再按时间合并进本地缓存。
6. 旧版本云快照中的 `eventLog` 保留一次性迁移入口；迁移成功后不重复导入。
7. 云快照的同步指纹不再因为不同设备各自持有不同事件窗口而制造假冲突。

#### 完整性与容量

- 服务端保留账号完整事件，不在 5000 条处截断。
- 本地仍可只缓存最近 5000 条，但“全部记录”和指定日期战报通过账号事件查询补足。
- 今日战报优先读取账号事件表；离线时回退本机缓存。
- 网络失败不影响本地继续记录，下次联网补传。

#### 验收

- A 设备新增任务、完成任务后，B 设备同步一次即可在今日战报看到两条事件。
- A、B 同时产生事件，不因云快照冲突互相覆盖。
- 同一事件重复上传、重复拉取不会产生重复记录。
- 今日战报不再只统计当前设备。
- 5000 条本地缓存回卷后，云端仍保留更早事件，指定日期仍可查询。

### F06 本机基线与云端修订的记录级详情

现有同步明细抽屉保留，并增加“二级记录详情”：

1. 点击 manifest 中任意具体记录，从右侧再打开记录详情抽屉，而不是只做行内展开。
2. 业务记录详情展示：
   - 类型。
   - 标题。
   - 稳定 ID。
   - 更新时间。
   - 删除/有效状态。
   - 内容摘要指纹。
   - 所属修订。
   - 与本机/云端的差异状态。
   - 关联的最近操作事件。
3. 事件记录详情展示：
   - 动作。
   - 卡种。
   - 卡标题。
   - 事件时间。
   - 来源设备。
   - 状态变更前后值。
   - 事件 ID。
4. 不展示完整 JSON、附件 Blob、令牌、刷新凭据。
5. 本机基线与云端当前使用同一记录详情组件，只切换数据来源标签。

### F07 策展附件多图连续浏览

1. 点击某个节点的图片缩略图时，传入该节点完整图片列表。
2. 预览弹窗支持左右箭头切换上一张/下一张。
3. 支持键盘 `←`、`→`。
4. 显示当前位置，如 `2 / 9`。
5. 只有一张图片时隐藏左右箭头。
6. 首尾循环切换；Esc 关闭。
7. 仅图片参与轮播；PDF、HTML 仍按单文件预览。
8. 中心论点卡和 L2-L4 节点共用同一图集预览逻辑。

### F08 策展台“页面设置”退役

1. 删除策展台工具条上的齿轮“页面设置”入口及整个下拉菜单。
2. 保留必要能力，但不再集中挂在“页面设置”下：
   - 重命名、隐藏、删除策展台继续由顶栏台签右键菜单承接。
   - “导入 JSON 备份”并入现有“导入”下拉菜单。
   - “导出 JSON 备份”移入台签右键菜单。
   - “清理本台镜像卡”移入台签右键菜单，并保留二次确认。
3. 描述与图标编辑不再通过设置菜单进入：
   - 默认随台名区域的轻量编辑入口保留。
   - 若用户后续明确要求连描述/图标编辑一并删除，再单独移除。
4. 不因为删除设置菜单而丢失导入、导出、清理镜像和删除台四项能力。

### F09 画布操作日志与状态回滚

#### 历史项

将现有 `HistoryEntry` 扩展为：

- `id`
- `label`
- `timestamp`
- `before`
- `after`

继续沿用最多 10 步的会话内历史。

#### 操作日志入口

1. 画布工具条在“上一步/下一步”旁新增“操作记录”。
2. 点击后从右侧打开日志抽屉。
3. 日志按时间倒序展示，最新在上。
4. 每条展示动作名称、时间和“回滚到此状态”动作。

#### 回滚语义

1. 点击某条日志，确认后恢复到该条记录完成后的画布状态。
2. 回滚本身作为一条新的可撤销操作写入历史，避免误操作后无法返回。
3. 回滚后清除 redo 栈，符合普通编辑历史语义。
4. 当前会话最多保留 10 步；刷新页面后清空，这是与现有上限一致的默认口径。
5. 若后续要求跨刷新持久化，另立 IndexedDB 存储与迁移任务。

#### 覆盖范围

覆盖当前画布结构操作：

- 创建/删除节点。
- 修改标题/说明。
- 同级排序/拖拽移动。
- 关联/解除资源。
- 上传/删除附件。
- 设置/取消中心论点。

### F10 方向树项目、指标与任务视觉统一

金字塔和树状两个布局使用同一套状态语义：

1. 项目：
   - 保留进度条。
   - 保留完成数/总数与百分比。
2. 成功指标：
   - 增加进度条。
   - 保留完成数/总数与百分比。
   - 无任务时继续显示“缺任务”。
3. 任务：
   - 已完成：中性灰底、弱化文字和状态点。
   - 待开始：浅蓝底，低强调。
   - 进行中：浅蓝底，增加强调色左边线或更明显的状态点。
   - 停滞：保留 warning 语义。
4. 不写死蓝色，统一使用四主题语义令牌。
5. 金字塔和树状布局在同等状态下视觉含义一致。

## 五、数据库与数据流

### 5.1 `account_events`

建议字段：

| 字段 | 说明 |
|---|---|
| `id text` | 设备级全局唯一事件 ID |
| `user_id uuid` | 账号 |
| `device_id text` | 来源设备 |
| `event_ts timestamptz` | 实际操作时间 |
| `action text` | create/delete/restore/purge/status/call |
| `card_kind text` | resource/task/curiosity/system |
| `card_id text` | 目标卡 ID，可为空 |
| `title_snapshot text` | 事件发生时的标题快照 |
| `to_state text` | 状态变更目标值，可为空 |
| `payload jsonb` | 必要补充字段，不保存完整业务快照 |
| `created_at timestamptz` | 云端接收时间 |

约束与索引：

- `primary key (user_id, id)`。
- `index (user_id, event_ts desc)`。
- RLS 仅允许 `auth.uid() = user_id`。
- `anon` 无读写权限。

### 5.2 同步关系

1. 本地卡片操作先写 `zy_event_log`。
2. 事件上传队列按 ID 幂等写 `account_events`。
3. 同步检查/打开今日战报时，按时间游标拉取新增事件。
4. 云端事件合并到本地缓存后，今日战报、全量记录、同步记录详情共用。
5. 旧云快照中的 `eventLog` 作为一次迁移源，不继续作为长期真源。

### 5.3 Inbox 清空

- 不新增表。
- 继续使用 `capture_inbox.dismissed_at`。
- 新增批量软删除和批量恢复能力，避免逐条请求。

### 5.4 策展画布历史

- 不新增数据库表。
- 使用当前会话内快照栈。
- 附件只保存元数据引用，历史回滚不能清理仍被其他历史快照引用的 Blob。

## 九、风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 事件 ID 当前可能碰撞 | 双设备按 ID 合并会误去重 | 先完成设备级 ID，再做事件表合并 |
| 旧快照事件被覆盖 | 历史记录无法恢复 | 首次上线时从现存云快照迁移；迁移后停用快照事件作为真源 |
| 批量清空误删 Inbox 镜像 | 用户担心目标卡被删 | 确认文案写清，撤销机制保留，目标卡不受影响 |
| 页面设置删除导致能力失踪 | 导入、导出、删除台无可达入口 | 先迁移入口，再从 DOM 和样式中删除设置菜单 |
| 附件历史回滚引用 Blob | 回滚后附件无法预览 | 历史快照保留附件元数据；物理清理先检查全部历史引用 |
| 四主题下浅蓝状态对比不足 | 可读性下降 | 使用语义令牌并通过 theme-contrast 门禁 |
