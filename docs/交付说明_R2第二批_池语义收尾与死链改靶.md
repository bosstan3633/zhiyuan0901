## 二、★本轮定位到但**故意不在本轮修**的既存缺陷：全站 `persistHot()` 空转

`shared/storage/hotStats.ts` 的 `store()` 把 `chrome.storage.local.set` **摘成裸函数引用**返回，调用时丢了 `StorageArea` 接收者 → Chrome 抛 `TypeError: Illegal invocation: Function must be called on an object of type StorageArea`，而调用点全包在静默 catch 里 ⇒ **每一次 `persistHot()` 都在空转**：R148-P0b 热度拆键的小载荷快通道从未生效、R173-T2 的 `immediate=true` 页隐藏补写同样是死的、「调出」事件只能等下一次整库保存才被 `takeEventLogPatch` 顺带带出。

**证据**：`/tmp/zy_detached_set.cjs` 在扩展页实测——裸调 `set({...})` 报 Illegal invocation 且键未写入，`chrome.storage.local.set({...})` 正常写入。

**为什么另轮修**：把接收者绑回（`set.call(area, o)`）后本机门禁**不能全绿**——`E2E-5 双击卡片打开本地 PDF 的 file:// 通道`转红（同一构建、只回退这一处即复绿，A/B 各跑两轮实证）。机理：单击开抽屉时新增的那次真实存储写插在双击与 `window.open` 之间，弹窗时序/用户激活被吃掉，headless 下 file:// 新标签不再出现。这是**修复引出的二阶问题**，需要单独一轮：先定「开抽屉要不要记调出」的产品口径（或把记调出挪到 rAF 之后 / 让 file 通道不依赖弹窗激活），再随该轮一起验真机。**本轮如实保留缺陷，不夹带半修。**
