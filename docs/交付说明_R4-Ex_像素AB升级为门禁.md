## 一、结论先说：像素 A/B 现在可以当门禁，规则是「三档」

每张图落到三档之一：**0 差** / **抖动**（边线取整，不算变化）/ **变化**（真改动）。用法固定两条命令：

```
node scripts/theme-audit.cjs --tag=X-before --freeze-at=<同一个日子>     # 改前构建
node scripts/theme-audit.cjs --tag=X-after  --freeze-at=<同一个日子>     # 改后构建
node scripts/img-diff.cjs --batch docs/视觉归档/X-before docs/视觉归档/X-after
```

退出码 0 ⇒ 本次构建**无可归因的视觉变化**；非 0 ⇒ 逐张点名并给变化包围盒（直接是坐标，不用再目视找）。
这条替代了此前的做法："像素 A/B 只能当参考，归因前必须先跑一次同构建对照"（R4-Et 记的方法账）——现在同构建对照就是尺子本身的一档。

## 三、试过又撤掉的一条路（记下来免得重走）

给 chromium 加 `--disable-skia-runtime-opts` / `--disable-partial-raster` / `--disable-gpu-shader-disk-cache`，想从渲染路径消掉边线抖动。实测：**抖动没消掉**（连采仍有 3–7 张落在边线带上），反而让 `raycast-st-manual` 整页不同。⇒ 已撤，注释留在 launch 参数那里说明别再走。

## 四、噪声地板为什么必须是形状判据，而不是数值放宽

抖动档要**同时**满足两条：① 每个差异像素的**单通道**差 ≤6；② 差异包围盒**高度 ≤8 行**。

- 为什么必须有 ②：一整个面板被均匀调淡 5/通道 也满足 ①，但那是真变化——它不可能只落在 8 行以内的带里。只靠数值阈值，等于把门禁改成"看不见小改动"。
- 实测两档之间有余量：抖动 3–6/通道、带高 4–6 行；真变化（那串 URL）232/通道、带高 13 行。
- 判据 R4-Ex④ 把 `TOL=6 / HARD=6 / JITTER_BAND_ROWS=8` 三个常量与 `classify` 的两条条件一起钉死（X6 放宽带高、X7 摘掉带高条件都会红）。
- **如实一条下限**：整片均匀 ≤6/通道 且落在 8 行以内的改动会被判成抖动放过——约 2.4% 的色差，肉眼不可辨，但这是明确的盲区。

## 五、`img-diff --batch`：把整归档判下来

- **一次起浏览器**判 104 对（此前逐张 = 104 次冷启动，"同构建连采该有多少噪声"这件事因此根本没法当门禁跑，只能靠一次性脚本量一次）。
- **两侧张数不齐即红**——少一张图不是"没差异"。
- 逐张算式只有 `DIFF_FN` 一份，批量与单对共用同一把尺子；判据 R4-Ex③ 用 `getImageData` 只许出现一次来钉这件事（#119 那把"两把尺子"的账在这里不重犯）。
- `--strict` 连抖动都不许有（要严格对照时用）。

## 八、边界如实

1. **抖动档有分辨率下限**（第四节那条 2.4% 色差），不是"像素级全对"。
2. **`HARD/TOL/带高` 是在这台 Mac、这一份 Chromium 上量的**。换机器要重量——做法就是连采两次跑 `--batch`，看抖动档的数值分布再定，不要照抄这三个数。
3. **`--batch` 没接进回归自动执行**：一次 theme-audit 是 6 分 15 秒，接进判据会让回归不可跑。接法是使用纪律（第一节那两条命令）+ 判据钉尺子在位（③④）；实跑由收口时手动做，本轮做了四跑三对。
4. **早于本轮的归档不能再当 A/B 基线**：`*-ov-capture` 那 4 张与钉框前必然差（画面里那串 URL 换了）。要用 2026-10-04 之后新拍的。
5. `raycast-st-manual` 整页跳变成因未定（新挂账）。
6. **#120 就此清空**（孤儿 CSS 两批 R4-Et/R4-Ev + 切片闸 R4-Eu + 视觉可复现本轮）。仍等拍板：#117 popup 白屏、#114① ⌘K 唤起 ~100ms 的 `backdrop-filter`+focus 取舍、R5 升版收口（真机复核在前）。
