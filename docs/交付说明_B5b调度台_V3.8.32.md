## 三、四件值得单独说

### ① 半透明在这套界面里一直是"禁用"的意思

三件事的空槽原来整格压到 55% 不透明度。这个写法在别处一直用于"不可用"（禁用按钮、失效行），于是"今天还差一件事没排"被读成了"这个位置坏了"。**虚线已经足够表达"这里还空着"**，不需要再叠一层半透明——两层都在说"空"，但只有虚线说的是"空着且可填"。

改后：虚边取 accent、文字取 accent、hover 才给淡底。空格仍是空格，但它是**能被点的主行动**。

M3 原文另外两条，实测已经是现状、本批没动：日期行与计数行本来就在 `--fs-sub`；「全屏三分栏内子任务 4 行定高内滚」这一条描述的是 P5 之后已退役的卡内子任务视口（现在子任务在卡片下方的全貌区），不再适用。

### ② 三条历史判据钉的是类名，其中两条靠注释续命

把入口从 `mb-act cta` 降为 `mb-act` 之后，`R56-3/R66`、`R120-6`、`R113-1` 三条同时红。看实现才发现：

- 三条都钉在**类名字符串** `mb-act cta` 上——而它们真正要守的是"右槽只有一个入口"和"入口的依赖先于使用点"；
- `R56-3/R66` 与 `R120-6` 还各要 `seg.includes('📈 复盘')`，可是**当前代码里根本没有这个标签**（按钮写的是「今日战报」）——那四个字一直活在右槽上方的一段 HTML 注释里。判据是被注释喂绿的。

处置：三条全部重指到**使用点**（`@click="openReview"` / `class="mb-act"` / 入口可见标签），并在判据描述里写明"类名不是契约，使用点才是"；同时把"复盘"那句改成按现状断言的"今日战报"。

**教训与 B3 的 `st-warn` 同形**：正锚钉实现细节（类名、属性顺序），实现一改就假红；而假绿更隐蔽——注释里提一嘴就够。写判据时该问的是"我在守哪句话"，然后把锚点放到那句话的**承重位置**上。

### ③ 规范说"Tab 下划线"，代码是"深色实心胶囊"——本批不改

M5 原文的现状段写"三卡共用下划线 Tab"，方案段写"Tab 下划线统一 accent 当前态"。但代码里是胶囊（R120-TB4），且 V3.8.18 的 R175 已按原型把选中态改成**深色实心胶囊**（`text` 前景反转 `bg`），并有判据 `R120-9` 守着。

两者冲突时取**更晚的拍板**：规范文档是 2026-10-16 的，R175 是其后按原型做的对齐。所以本批只落实 M5 的实质（同构：外框圆角 / 卡内单元 / 卡头 / 空态），Tab 形态不动，并在判据描述与计划文档里备案——**不是漏做，是判断后不做**。

### ④ 新分片自己先红了一次：正则转义层数写错，`pick` 拿回空串

`M5-2` 第一版用 `new RegExp('^\\.' + sel + ' \\{...')` 的动态拼接取规则体，判断结果三家全是 `?`（规则没取到）。原因是转义层数：字符串里写了四层反斜杠，运行时成了 `^\\.x`——即"反斜杠 + 任意字符 + x"，永远匹配不上；而 `bad.push(n + '=' + (match || ['?']))` 的兜底把"没取到"变成了一句无害的 `tm=?`，**判据红了，但红得没有信息**。

改法：不用动态正则，按行首 `\n.tm-card {` 定位再截到行内第一个 `}`。同时把兜底从 `'?'` 改成显式的「规则缺失」——**判据的自述必须能指出哪里坏了**，否则下一个人只会看到一堆问号。
