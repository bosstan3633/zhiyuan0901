## 四、技术要点

- **REQ-054 关键设计**：`Drawer` 容器层抽象（`#title-extra` 具名插槽 + `.drawer-title-extra` flex 工具类）一次定义三处复用，避免每处详情重复接 AssetBadge 模板与样式；section 头徽章采用「左标题 + 右徽章」flex 布局（`.detail-sec-head / .ts-label-row / .ref-label-row` 三处同名同构），CSS 三处同步以保视觉一致。
- **REQ-054 端到端验证机制（吸取 V2.16 教训）**：
  - 旧教训：V2.16 仅断言"模板含 AssetBadge 字符串"就算完成，但详情面板实际未呈现——因扩展页面 hidden input 不可被 Playwright 驱动，且 R39 断言选择器未命中子级（`.ts-title-assets / .ref-title-assets` 计数 0 是 grep 路径问题非真问题）。
  - 新做法：注入式验证（IDB put Blob + chrome.storage.local set assets）+ 真实 Chrome 加载 dist 人工目检关键截图；本轮三处详情（好奇/任务/资源）截图均显示右上角与 section 头双徽章真实呈现，且 AssetManager list/preview/HTML 新标签打开/删除全链路在真机可用。
  - **残余自动化边界**：文件选择器 click → 真实 OS 文件选择对话框在 Playwright 下无解，需用户手动走一次完整上传流程（清单见 §附 验证清单）。
- **REQ-055 关键设计**：`visibleFields` 只导可见字段会丢失系统数据基线（默认配置仅 4 字段 visible），故选 `allFields` + 系统字段无条件 + 自定义按 visible 过滤的双轨；`resCsvValue` 把系统字段键（title/link/description/sourceType/tags/createdAt/assets）映射为人类可读值，自定义字段从 `customFields[key]` 取值，附件列渲染为「N 图 · M HTML」文本摘要（与 fieldValue assets 同规则）保持一致性。
- **REQ-056 收敛判定**：`am-viewer* / ab-viewer*` 类名在 `AssetManager.vue / AssetBadge.vue` 宿主中全部清零（断言 R41-7b 全库扫描），仅保留 `AssetPreview.vue` 的 `ap-viewer*`；样式继承原 am-viewer（92vw max、1080px max、92vh max、12px radius、0.72 黑遮罩）。
- **REQ-057 收敛原则**：用户主动操作（删除附件、硬删回收站）失败必须可见；自动容错（background 降级、content 边界、解析兜底、IDB 打开失败）保留——避免"全员 toast"噪音与"自动恢复误报"。

## 八、V2.17.1 热修（用户真机反馈驱动，真实上传链路双重根因）

用户以截图反馈：附件字段在表单里存在，但**选完文件后附件没有出现在表单/卡片里**。定位出两个叠加根因，均已修复并经真机端到端 6 项 ALL PASS：

### 根因 ① 上传入口时序 Bug（onFilesChange 100% 静默失败）
- `AssetManager.onFilesChange` 旧代码：`const files = input.files; input.value = ''; if (!files.length) return`——**设置 `input.value=''` 会重置整个 FileList**，先存的引用同步变空，导致每次真实上传在选择文件后立即静默 return。
- 修复：`const files = Array.from(input.files || [])` **先快照再清空**（断言 R41-9 锁死顺序）。
- 为什么 V2.17.0 没发现：注入式验证直接写 IndexedDB + storage，完全绕过此链路。

### 根因 ② reactive Proxy 泄漏入存储（卡片正面徽章永不渲染）
- 真实链路中 `ResourceEditForm.onAssetsChange` 执行 `store.data.resources[idx] = { ...props.model }`，展开出的 `assets` 属性是 **Vue reactive Proxy 数组**；persist 直传该树给 `chrome.storage.set`，chrome 的序列化把 Proxy 数组降级为**类数组对象 `{"0":…}`**——读回后 `assets.length` 为 undefined → 卡片正面 `v-if="r.assets?.length"` 永假 → **AssetBadge 永不渲染**（用户看到的"卡片上没有显示"）。
- 修复：`saveData` / `saveDataNow` 入存储前统一 `JSON.parse(JSON.stringify(cache))` 纯净清洗（断言 R41-10 锁死 ≥2 处），保证入存储永远是 plain 结构。
- 为什么 V2.17.0 没发现：注入式验证写入的是纯数组，不经过 reactive 展开。

### 端到端验证升级（V2.17.1 起真实链路可自动化）
- 新脚本 `C:\Users\win\Desktop\zy_e2e_v2_17_1\e2e_v2_17_1.mjs`：OS 文件对话框虽不可驱动，但用 **DataTransfer 构造 File 赋给 `input.files` + dispatch change 事件**，走的是产品真实 `onFilesChange → putAsset → emit → persist` 全链路（非注入绕行）。
- 6 项断言 ALL PASS：V1 详情上传入口可见 / V2 真实 change 链路 2 chip 渲染 / V3 Toast「已上传 2 个附件」/ V4 storage 中 assets 为真数组 image+html / V5 IDB Blob 本体 ×2 / **V6 卡片正面徽章 `🖼 1 🧾 1` 渲染**（截图 `v17_1_01_upload_chips.png`、`v17_1_02_card_badge.png` 目检通过）。
- 上一节"残余自动化验证边界"中"建议人工走一次上传"在 V2.17.1 已由脚本代偿，用户仍可在真实 Chrome 快速点一次确认体验。
