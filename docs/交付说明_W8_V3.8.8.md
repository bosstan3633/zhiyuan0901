# 交付说明 · W8 / V3.8.8 —— 方向台视觉焦点契约

> **日期**：2026-10-12
> **一句话**：**给方向台一个主角。** 愿景升为本页唯一 22px display 级主体；六层思维链第一次在字阶上真的分层；主攻项目升为次级焦点。
> **性质**：视觉层级调整（CSS 为主）。**数据模型、存储、六层结构、AI 边界一律未动。**

## 一、这轮从哪来：一次读码诊断

用户问「方向台的重点与视觉焦点应该是什么，现状是否满足」。读码（不读文档）得到三个事实：

| 元素 | 实测字号 | 问题 |
|---|---|---|
| 页头面包屑「方向台」 | **16px 字面量** | **全页最大字，却只是导航标签** |
| 「六层思维链」区块标题 | `--fs-caption` **11px** | 真内容标题比导航**小 45%** ⇒ **层级倒置** |
| 第1层 愿景 | 14px 字面量 /700 | |
| 第2层 使命 | 13px /500 | |
| **第3~6层** 战略目标/项目/指标/任务 | **全部 13px** | **六层里四层完全同字号** |
| `--fs-display` / `--fs-headline` 使用 | **0 / 0** | |

结论：方向台**结构清楚但没有焦点**，且六层思维链——产品最核心的结构——**在字阶上是平的**，层级只能靠发丝缩进辨认。

> ★**这不是孤例**：V3.8.7 在热力图修掉的「指标 17px > 区块标题 15px」是**同一种病**（层级倒置）。两轮下来确认是**通病**，故本轮除方向台外，顺手在 W8-3 立了「内容标题必须大于面包屑」的判据防复发。

## 二、改了什么

用户审核对照原型后拍板：**① 主角＝愿景（A 案）② 攻坚项目 17px（A 案）**。

| # | 对象 | 现状 | 改后 | 落点 |
|---|---|---|---|---|
| 1 | 第1层 **愿景** | 14px 字面量 | **`--fs-display` 22px + `shadow-lg` 重框**（全页唯一主角） | `.tl-text` / `.tree-level-card.hero` / L1 卡加 `hero` 类 |
| 2 | 六层字阶 | 第2~6层全 13px | 使命 **17** / 战略目标 **15** / 攻坚项目 **17** / 指标·任务 保持 **13** | `.tl-text.sub` / `.tct-name .node-title` / `.tp-title .node-title` |
| 3 | 「六层思维链」标题 | **11px** caption | **17px** `--fs-headline` | `.lt-title` |
| 4 | **主攻项目** | accent-28% 边框 + 🚀 | **accent 边框 + `accent-light` 底色 + 标题转 `accent-ink`** | `.tree-project-branch.is-focused` |
| 5 | 面包屑「方向台」 | 16px | **16px 不动**（见下） | — |

### ★第 5 条与 R123 的冲突，以及为什么改法换了

原型原案是「面包屑 16px → 13px」。但施工时撞上 **R51-6 / R123-10 两条判据**钉着 **R123 轮定案：「工作台 / 项目详情 / 方向台三页页头标题统一 16px」**——那是**跨页一致性**决策。

已就此问用户拍板：**保三页一致，标题升到 17px**。于是修法从「降面包屑」换成「**抬内容标题**」：

```
层级变成：愿景 22 › 区块标题 17 › 面包屑 16 › 正文 13   （单调递减，倒置同样消除）
```

好处：**R51-6 / R123-10 两条判据不需要随迁**，跨页一致性零破坏。

### 取舍备案：字阶不是单调递减

`使命 17 → 战略目标 15 → 攻坚项目 17` 有一段**起伏**。这是**用户拍板的 A 案**：攻坚项目是「当前在做的事」，比它所属的战略目标更该被看见。代价是扫读时略跳——**这是有意取舍，不是失误**，W8-2 的判据里明确写了「不许被后人当 bug 修正成单调递减」。
