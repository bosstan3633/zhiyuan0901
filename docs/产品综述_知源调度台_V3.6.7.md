## 卷首 · 一页读懂

**一句话**：知源调度台，是你在浏览器里的个人调度中台。

**一段话**：它是一套接管浏览器新标签页的 Chrome/Edge 扩展（MV3），把你每天使用的链接、本地文件、Obsidian 笔记、AI 聊天金句、零星念头统一收纳为可被你自己指挥的卡片，并以"愿景 → 使命 → 战略目标 → 项目 → 成功指标 → 任务"六层目标与行动结构承接你的方向。它 100% 本地运行、零账号、零云端、零订阅，让每一个被见过的信息都具备在正确时刻被召回的能力。

**一页话**：AI 让"生成答案"变得前所未有地廉价，于是个人认知的真正瓶颈不再是"能不能创造"，而是"能不能把散落各处的产出，在正确的时刻重新调度回来"。知源不生产内容——它经营你的**认知周转率**。它不是书签插件，不是笔记软件，不是待办清单，也不是新标签页美化工具；它是横在所有工具之上的一层**调度层**：信息洪流中的控制中心。它也不是催人更忙的效率工具，而是帮助你**围绕自己的目标**开展工作——英文名 Ownway（走自己的路）说的就是这件事。

## 第一章 · 它是什么：从一句话到全景

### 1.1 三层递进的定义

- **品类层**（回答"这是什么"）：你在浏览器里的个人调度中台。
- **能力层**（回答"它怎么工作"）：看见方向，留下好奇，调用所需，策展成果。
- **立场层**（回答"它信什么"）：万千可调用，自有我方向。

三层分工明确：主口号强调主体性，解释句交代工作过程，场景文案落到具体情境——避免每一句都重复宏大理念。

### 1.2 中文名释义

> **知源，是知道自己为何出发，也知道所用信息从何而来。**
> **调度，是围绕自己的问题，让合适的信息、工具与材料参与行动。**

"知源"是品牌寓意，不表示产品自动保证信息真实或替用户完成判断——判断永远属于用户。

### 1.3 英文名释义 · Ownway：走自己的路

**Ownway = Own（自己的）+ Way（道路、方式）。**

它表达的是"走自己的路"，也把知源的三重归属写进了名字：

- **数据归自己**——100% 本地存储，无账号、无云端，导出即迁移；
- **判断归自己**——AI 只建议、不决策，方向永远用户定；
- **节奏归自己**——度量是镜子不是鞭子，不做 KPI 逼宫与红点轰炸。

Ownway 不是催人更忙的效率工具，而是帮助用户**围绕自身目标**开展工作。它与中文名互为表里：知源回答"从哪出发、用什么出发"，Ownway 回答"走谁的路"——答案是同一句：**万千可调用，自有我方向**。名字本身就是产品立场的陈述。

### 1.4 产品形态：一个总指挥，四张台面

知源接管新标签页，把"打开浏览器"这个每天发生几十次的动作，变成回到自己指挥台的动作。全站由三横一纵构成：

```
┌─────────────────────────────────────────────────────────────┐
│  全局调度层（纵切所有页面）：Ctrl+K 搜索 · 快速采集 · 好奇心采集  │
│  · 任务采集 · 浮层系统 · 全局快捷键 · 全局撤销                  │
├──────────┬──────────┬──────────┬────────────────────────────┤
│  调度台   │  方向台   │  资源台   │  策展台 ×N（用户自建）       │
│  今天     │  主航线   │  资源卡   │  金字塔策展空间              │
│  从哪出发 │  与项目   │  唯一居所 │  镜像引用 · 中心论点         │
├──────────┴──────────┴──────────┴────────────────────────────┤
│  数据与信任层：本地单根 JSON · 软删回收站 · 全量导出 · 生命周期   │
│  · AI 认知协作者层（横切四台：补全/拆解/找资源/检索/复盘……）     │
└─────────────────────────────────────────────────────────────┘
```

心智画面是**外部万千，内有主线**——一条属于用户的行动路径：沿途留下好奇，接入所需工具与材料，并形成阶段成果。

### 1.5 它不是什么

| 不做 | 原因 |
|---|---|
| ❌ 不做云同步 | 同步 = 把你的数据上别人的服务器。这是功能立场，不是能力缺陷 |
| ❌ 不做 AI 替你决策 | AI 是你的部队，知源是你的指挥台；你不该被任何一个 AI 工具替代判断 |
| ❌ 不做"第二大脑" | 不抢 Notion/Obsidian 的市场——它们仍是最好的写作工具，知源只调度"素材"那一层 |
| ❌ 不做社交/协作 | 单一用户的认知工具，不引入他人数据、他人算法、他人权限 |
| ❌ 不做跟踪分析 | 没有用户画像、没有使用画像、没有广告位 |

一句话：**知源不与任何工具争"更能装"，它只做"更能调"。**

## 第二章 · 为什么要有它：这个时代的问题

### 2.1 AI 改变了什么：瓶颈的位移

AI 让"生成答案"的速度比"找到自己产出"的速度快一千倍。当产出不再稀缺，稀缺的是**调度**：你三个月前做过的分析、上周问过 AI 的金句、昨天冒出的念头，能否在需要的那一秒回到你手边？AI 时代的个人认知瓶颈，从"能不能创造"位移到了"能不能召回"。

### 2.2 三大时代病根

| 病根 | 日常的痛 |
|---|---|
| **工具碎片化** | 每几秒切一次 Tab，节奏全断；写一份报告要在 N 个 Chat 窗口、文件夹、标签页之间跳来跳去 |
| **资源失血症** | 做过的事找不到——三个月前的分析搜不到、记不清、没办法再调出上下文；看到好东西存了，读完就没有下游了 |
| **数据被绑架** | 核心稿件存在某个云的某个数据库里，换工具或涨价时只能被迫迁移；今天的服务免费、明天的数据定价、后天的服务停服 |

### 2.3 为什么现有工具治不了

- **浏览器书签**：只存不找；层级深了等于没有。
- **AI 对话框收藏**：内容锁在对话里，与你的资源库隔离。
- **"稍后读"应用**：读完就没有下游了。
- **Notion**：库越建越重、找回越来越慢——它擅长深度写作与数据库，不擅长三秒进出。
- **Obsidian**：本地双链笔记的优秀，但它是写作环境而非调度环境（且知源与它互补：收录并直达 `obsidian://` 链接）。
- **Flomo / Raindrop / Eagle**：各自收藏某一类东西（念头 / 链接 / 素材），但缺方向、缺策展、缺"调度"这一层。
- **Raycast / LaunchBar**：同频"三秒召回"，但它们是系统级命令面板，没有方向、没有策展、没有北极星。
- **Momentum 等新标签页美化**：卖"好看"，知源卖"调度"——好看只是副产品。

### 2.4 货架理论：自造一个品类

> 类目的力量：**书架的位置决定商品的价格。** 选错货架的茅台，只能按散酒论斤卖。

知源不挤进"书签/笔记/待办"任何一个旧货架，而是自造一个新货架：**信息洪流中的控制中心——AI 时代知识工作者的个人资源调度台**。通用工具比知源"更能装"，知源比通用工具"更能调"——它不抢你的写作、不抢你的协作、不抢你的云，只做一件事：让你见过的每一个信息，都具备在正确时刻被召回的能力。

## 第三章 · 给谁用：目标用户

### 3.1 以工作方式识别，而非以职业标签定义

知源的首要用户不以职业名称或使用工具数量单独定义，而以**工作方式**识别：

- 主要在浏览器中接触信息与开展工作；
- 需要独立决定研究什么、投入什么、如何交付；
- 同时使用多个信息来源和工具（典型如 5 个以上日常 AI 工具，场景横跨十几个网页）；
- 希望将探索与行动连接，并形成自己的成果表达。

### 3.2 首选人群与延展人群

**首选**：AI 重度使用的"独立深度研究者 / 咨询顾问"——产出高度碎片化（研究/报告/答疑/客户交付）、独立工作者（不依赖团队协作流程）、对数据主权敏感。

**延展**：创作者、终身学习者、深度播客主等同类型用户，同样适用，优先级稍后。

**这是一个市场进入假设，不是已经证明的付费排序。**

### 3.3 明确不为谁设计

- 想"存一堆链接就不看"的人——知源的价值在调度与召回，不在囤积；
- 已有完整 Notion/Obsidian 工作流且满意的人；
- 强依赖多人实时协作、自动云同步或自动化执行的人；
- 换电脑无所谓反正有云同步的人——知源反其道而行：你的数据只属于你的机器。

### 3.4 一天的样子（虚构演示场景）

> 以下为说明产品用法而构拟的演示场景，非真实用户案例。

早晨打开浏览器，新标签页就是**调度台**：方向状态四指标告诉你战略目标与推进项目的最新状态，今日三件事已经排好（AI 可以给推荐，但写进哪三格由你定）。工作中刷到一篇好文章，`Ctrl+Shift+J` 五秒收录入台；冒出一个与当前任务无关的疑问，`Ctrl+Shift+I` 先留下，不打断手头的事。下午写报告需要上周那份分析，`Ctrl+K` 拼音首字母三秒召回，双击直达。周五下午，打开**知源仪表盘**：年度热力图上每个格子都是一天的痕迹，复盘两栏摆出本周与上周的对比，AI 按金字塔原理续写洞察与建议——数字是产品给的，判断是你下的。

## 第四章 · 核心功能模块全景

### 4.1 四大台面

**调度台（`/`，默认首页）——今天从哪里出发**
方向状态四指标（战略目标数·推进项目数 / WCE 好奇探索 / WRR 资源复用 / 未归档任务，日·周·累计三档可下钻）+ 今日三件事（≤3 槽锁定当日最重要行动，可 AI 推荐、复制昨日、导出 CSV）+ 项目调度（任务树默认折叠，左右可拖分栏）+ 好奇心培育 + 主攻速览。刷新固定回此页——它是你的"今日出发点"。

**方向台（`/compass`）——看主线，管项目**
主航线（愿景/使命锚点条 + 目标卡 + 主攻聚焦条，读为主）、项目总览（管为主，>12 项目自动启用搜索与状态筛选）、任务调度（全域任务管理三视图）；另有项目详情展板与完整方向树（六层全展开、全节点原位编辑、停滞检测）。主攻（最多 2 个）被显式分配注意力，直通调度台速览。

**资源台（`/workspace/zy-curation`）——资源卡唯一真身居所**
卡片/列表/看板三视图 + 分类树（≤4 级，默认根节点"全部分类"）+ 排序/筛选/搜索（支持 `#标签` 直筛、调用最多排序、待补全路径筛选）+ 批量管理 + 导入（书签 HTML / 本地文件一文件一张附件卡）。所有策展台中的资源卡都是这里的镜像引用，源数据零影响。

**策展台 ×N（`/workspace/:id`）——围绕主题取舍、分层与表达**
金字塔居中树布局（层级可折叠）+ 节点双入口（关联资源卡=逐张镜像 / 新建台内卡）+ 中心论点（一次策展的灵魂，已设论点默认金字塔视图）+ 卡片跨节点拖拽 + 金字塔真全屏。策展 = 围绕主题进行取舍、分层与表达，形成可回看、可理解的成果。

### 4.2 三类卡片：信息的三个基本粒子

| 卡片 | 是什么 | 关键字段 | 生命周期特征 |
|---|---|---|---|
| **资源卡** | 收藏的网页、本地文件、Obsidian 笔记——高信度资产 | 标题、链接（URL/本地路径/obsidian://）、分类、标签、描述、注解、自定义字段、附件、调用计数 | 有热度（callCount/lastVisits），可进生命周期（活跃/冷却/归档） |
| **任务卡** | 可执行的行动项，挂载在项目→成功指标下 | 标题、所属项目+指标（双挂）、优先级、状态、子任务清单、链接、备注 | 未挂指标即"未归档任务"，可在北极星下钻中级联归档 |
| **好奇心卡** | 一闪而过的疑问和灵感 | 问题原文、状态（待探索/探索中/已求证/已搁置）、来源链接+来源标题 | 可转化为任务卡或资源卡（转化即离场，可撤销） |

三类卡片均支持**置顶**与**星标**双标记，排序权重统一为：置顶 > 星标 > 命中度。**卡间零挂载**是一条结构性红线：三卡互不持有对方 id，跨卡关联走独立的记录型关联表——这保证了任何一张卡都可以被独立删除、迁移、导出而不留悬挂引用。

### 4.3 六层目标与行动结构

```
愿景（Why）→ 使命（How）→ 战略目标 → 攻坚项目 → 成功指标 → 任务
```

知源引擎·方向树的核心结构，每一层都可原位编辑、可增删。任务可挂指标，未挂即"未归档任务"。这六层让"今天做的这件小事"与"我想成为什么样的人"之间有了可追溯的链路——**今天的行动有来处，做过的事形成表达**。

### 4.4 全局调度层：三秒召回的骨架

- **全局搜索（`Ctrl+K`）**：任意网页浮层 + 新标签页内均可调出；标题/标签/分类/项目名/自定义字段值/link 全命中；拼音与首字母匹配；`#标签` 交集直筛、`@项目` 收窄；双击直达；空态给"近期最常用 + 最近调出"。这是对已收录条目的检索，不是全盘全文检索（边界明示）。
- **快速采集（`Ctrl+Shift+J`）**：任意网页数秒收录入台，自动预填标题/URL/选中文本。
- **好奇心采集（`Ctrl+Shift+I`）**：念头速记，选中文本自动填入并附带来源，可转任务卡或资源卡。
- **快捷键体系**：系统级 6 个命令项（chrome.commands 可自定义），应用内 Alt+1/2/3 直达方向台/资源台/策展台；`Ctrl+Enter` 保存并关闭；Esc 逐层关闭；`?` 唤出快捷键速查。**主干道全部键盘化**——高频低摩擦是硬原则。

### 4.5 AI 认知协作者层：AI 是部队，知源是指挥台

知源的 AI 不是聊天窗口，而是贯穿方向台/资源台/策展台/任务台的**能力层**（当前 24 个已注册能力入口，由入口注册表单一真源与双向对账门禁把守）：

- **单卡三入口**：任务卡的补全 / 拆解步骤 / 找资源支持；资源卡的补全 / 关联任务；好奇心卡的研判。
- **对照式评审范式**：所有 AI 建议统一进中央弹窗——左栏是当前形态，右栏是补全后完整形态，行级对照、可就地编辑（编辑即自动勾选）、逐条采纳。执笔角色可切换、可下一次性指令（优先级高于角色，但破不了数据契约）。
- **全局能力**：AI 检索（对全库字段整体梳理，不抓链接正文）、AI 建议面板（跨台镜像发现/主题漂移检测/沉睡资源唤醒）、今日三件事推荐、AI 复盘文本报告。
- **四条铁律**：
  1. **密钥只在本机**——直连用户自配的模型服务，无知源云端中转；
  2. **启动零 AI 负担**——AI 栈全部懒加载，不用 AI 的用户零成本；
  3. **建议须勾选采纳才落库**——AI 永远不静默改你的数据；
  4. **只补缺不覆盖**——已填字段给建议默认不勾；体系外新词默认不落；数字越界（如复盘续写超出事实白名单）整段弃用。

### 4.6 知源仪表盘与复盘：度量是镜子，不是鞭子

V3.6.5 起，知源仪表盘完成 R3 重构：**概览带**（5 张指标卡随选中日时间绑定）+ **年度热力图**（12 月块 × 366 格，六档语义图例，禁裸色阶）+ **日详情**（四列可下钻 + 库容变化 + 当日流水）+ **复盘两栏**（四范围等长环比 + KPI 对账 + 8 条偏离规则皆可下钻）+ **全量记录抽屉**（三维筛选 + CSV 导出）+ **导出三件套**（CSV / Markdown / PNG，取当前主题令牌自绘）。AI 复盘是金字塔原理的四段文本报告——结论 → 支撑论据 → 洞察 → 建议：规则给事实、专家只续写判断。另有运行错误留痕（免 F12 提供堆栈）与数据体检卡（脏数据检测 + 一键修复）。V3.6.7 仪表盘焦点化：概览带压缩一半（188→94px）、热力图摘要四卡压单行指标条、六档色阶低两档拉距（Lab 实算 ΔL*≥5 落成断言），并按日快照落盘——热力图不再随事件日志滚动淘汰而褪色。

### 4.7 数据与信任体系

- **删除一律软删**：任何删除只写 `deletedAt`，回收站可单条恢复或永久删除（含附件清理）。
- **全局撤销**：9 秒窗口内 `Ctrl+Z` 可撤，批量回执与 AI 采纳回执自动入栈；AI 采纳前自动压整库快照。
- **导入导出**：JSON 全量导出（含界面偏好段）/ 按台导出 / 策展台数据包 / CSV（UTF-8 BOM）/ Markdown；书签 HTML 导入；本地文件一文件一卡；导入前自动备份；并集合并（按 id）；导入含分类树结构校验（成环/孤儿/超 4 级自动提根）。**导出与备份一律剥离 Airtable 凭证**——分享数据包不带出令牌。
- **Airtable 单向同步**：用户自备 Personal Access Token、手动触发，推送到用户自己的 Base；**只出不回，绝不回写本地**。这是"用户主动触发的导出式推送"，不等同于云同步——对外表述纪律如此，产品实现亦如此。
- **附件**：图片/HTML/PDF 挂卡，IndexedDB 本地存储，单文件 ≤20MB；双击下载+打开；孤儿附件可检测清理。
- **落盘状态可见**：顶栏状态点实时呈现 saving/saved/error——"存没存上，用户必须看得见"是产品原则。
- **数据体检**：设置内一键检测并修复脏数据（如中心论点重复卡）。

## 第五章 · 它是如何解决用户问题的

### 5.1 六个核心动作：最小可用闭环

| # | 动作 | 触发方式 | 时间量级 |
|---|---|---|---|
| 1 | **快速采集** | `Ctrl+Shift+J` 任意网页 | 5 秒 |
| 2 | **三秒搜索** | `Ctrl+K` 全场景 | 3 秒 |
| 3 | **追想法念头** | 好奇心采集 `Ctrl+Shift+I` | 10 秒 |
| 4 | **一键直跳** | 双击搜索结果 | 0 思考 |
| 5 | **方向管理** | 知源引擎（愿景/使命/方向/项目/指标/任务） | 锚定主攻方向 |
| 6 | **完整导出** | 设置 → 导出全部数据 | 一份 JSON |

前四个动作治"工具碎片化"与"资源失血症"——收得进、看得见、找得到；第五个动作治"忙碌与方向脱节"；第六个动作治"数据被绑架"——带得走。

### 5.2 功能价值五字诀

**收得进 · 看得见 · 找得到 · 信得过 · 带得走。**

采集浮层把"存"降到 5 秒；三视图与指标条把"看"变成一眼；拼音首字母把"找"压到 3 秒；本地存储+软删+撤销+落盘可见把"信"落到实处；全量导出把"带"变成一份文件。五字诀环环对应第二章的三大病根。

### 5.3 从好奇到成果：五步转化链

> 好奇 → 求证 → 项目 → 指标 → 任务，五步各有去处。

"稍后读"应用读完就没有下游了；知源的好奇心卡是整条链的起点——先留下（不打断当前工作），回看时选择是否投入探索（转任务/转资源，转化即离场且可撤销），进入项目与指标后与方向对齐，最终形成可策展、可表达的成果。**核心动词只有五个：收录、归位、调出、复用、校准**——不发明新词，不堆叠隐喻。

### 5.4 方向状态四指标：事实呈现，不做 KPI 逼宫

**战略目标数**（副行：推进项目数）/ **WCE 好奇探索**（含转化）/ **WRR 资源复用** / **未归档任务（N/M）**，日/周/累计三档，四格均可下钻。设计立场：指标呈现事实，不做红点轰炸，不打焦虑——**度量是镜子不是鞭子**。

## 第六章 · 产品背后的精神

### 6.1 认知主权与数据主权

订阅制 + 云服务 + 算法推荐这套组合，是数据主权的反向路径。知源坚持走反向的路：数据只存在你自己的电脑里，没有账号、没有 token、没有用户标识，导出 = 一份 JSON 文件，迁移成本 = 0。**换工具从来不需要导出你的智慧。**本地保存不等于自动备份，产品会明确提醒你定期备份——诚实高于漂亮话。

### 6.2 人的主体性

AI 让答案变得廉价，但**判断不可外包**。知源的 AI 层有一条贯穿始终的纪律：AI 只建议、人采纳；AI 只补缺、不覆盖；AI 只续写洞察、不编造数字；方向永远用户定，产品只呈现关系。"不做 AI 替你决策"写在第一条反原则里。

### 6.3 克制的哲学

- **少开入口，不是少做功能**——一级界面只留高频动作，长尾收进右键与面板；
- **新功能先过"三步以内"门槛**——不为功能完整牺牲低摩擦；
- **不做复杂笔记**——写作交给专业工具，知源不抢；
- **主色稀缺**——强调色只用于主行动与当前态；
- **不制造焦虑**——指标是镜子，完成态是安静收束而非庆祝烟花；
- **交互三戒**——原生 prompt/confirm 全面禁用、路由切换零动画、删除可撤销。

### 6.4 六条产品原则

1. **调度优先**：一切功能最终服务"正确时刻召回"；
2. **高频低摩擦**：主干道快捷键化，常用动作 ≤3 步；
3. **写入可感知**：存没存上，用户必须看得见；
4. **关系可追溯**：卡与项目/方向/来源的链路点得回去；
5. **状态可见不焦虑**：呈现事实，不做红点轰炸与 KPI 逼宫；
6. **用户拥有控制权**：数据可导出、操作可撤销、无暗锁。

### 6.5 美是核心生产力

视觉基准为 Linear 结构语言（近黑画布、发丝线、克制装饰、键盘优先），六套主题（默认深空薰衣草）全部走语义令牌体系，文本对比度有硬性门禁（≥4.5:1），每个新界面在全部主题下逐一走查。美不是装饰——**美是让用户愿意每天回来的生产力**。

### 6.6 工程精神：可信是产品的一部分

知源把工程纪律当作产品精神的外延：**每周一轮、轮轮交付留痕**；回归断言只增不减（当前 1528 项），每个新功能同步追加断言；断言必须做**活性验证**（破坏它必须变红，"红不了 ≠ 守住了"）；性能每轮必测、劣化必须归因（不许带病发版）；文档失真被视为与代码 bug 同级的问题（"书面口径与代码实装不一致 = 坏账"）。这个仓库的设计目标之一就是：**换一个环境，由任意智能体接手后，仅凭本仓库即可继续迭代。**

### 6.7 产品哲学一句话

> **写每行代码时自问——这个功能让用户更自由地思考，还是让用户更像机器的奴隶？如果是后者，删除它。**

## 第七章 · 技术底盘速览：它为什么做得到

| 维度 | 选型与事实 |
|---|---|
| 架构 | MV3 四端：新标签页主应用（Vue 3.5 + TypeScript strict + Vite 5 + Pinia）· Content Script 浮层（纯 Vanilla JS + Shadow DOM，不引入 Vue 运行时）· Service Worker（命令/注入/单例定位）· Popup 降级弹窗 |
| 存储 | 主数据 `chrome.storage.local` 单根 JSON（300ms 防抖合并写，主 JSON 绝不存 base64）+ 附件 IndexedDB 库；热度键独立小载荷写盘（进台写盘载荷 276KB → 9.9KB） |
| 性能 | 视图切换 <40ms 红线（perf.cjs A/B 基准台 + perf-census DOM/长任务普查）；真库受控 A/B：冷启动 −23.1%、冷挂资源台阻塞 −32.3%、切看板 −29.3%（V3.6.1）；看板列视口驱动窗口化后同批最小 33.3ms（V3.6.6+） |
| 质量门禁 | vue-tsc 0 错误 + 回归断言 1528 项全绿（helpers + 11 时代分片 + 编排 runner，单片 ≤900 行）+ E2E 25 项 + 导入兼容 + 主题对比度硬判据 + 六主题视觉走查 68 图 + 入口注册表双向对账 + 依赖锁自证 + 代码索引防漂移 |
| 数据红线 | 卡间零挂载；删除一律软删；stats.lastVisits 只经统一入口更新；渲染 computed 禁原地 sort；样式只用语义令牌 |
| 交付包 | 93 文件 / 约 1.7M / ZIP 620,309B（预算 600KB，超 5,909B 按证据挂账：不减功能、不假装通过） |

技术底盘的每一个"较真"，最终都兑换成用户可感知的东西：快（三秒召回）、稳（1528 项断言守着每一次改动）、可信（数据永远在你手里）。

## 第八章 · 演变历程：从工具到调度台

知源的成长分三个阶段，方向从未变过，内涵逐步加深：

**第一阶段 · 工具成型（V2.1~V2.20）**：统一卡片模型与字段目录、附件体系（IndexedDB）、回收站、双标记体系、事件日志与知源仪表盘雏形、三系统页（任务管理/项目策展/仪表盘）——先做一个"收得进、找得到"的好工具。

**第二阶段 · 台面归一与调度深化（V2.20~V2.85）**：品牌内涵重构（"以好奇过滤信息，以调度致用于己"）；台面体系归一（资源台成为资源卡唯一真身居所、用户自建台定名策展台）；金字塔策展与镜像引用上线；Airtable 单向同步；生产反馈三批+体验梳理十项；资源生命周期引擎；Workspace 五批纯拆分与性能治理（视图切换全 <40ms）。

**第三阶段 · AI 协作者层与信任层（V3.0~V3.6.7）**：AI 认知协作者层贯穿四台（24 个能力入口、对照式评审范式、角色与一次性指令）；信任层（全局撤销/AI 采纳快照/落盘状态点/存储键字典）；性能收口（入口 chunk −45%、拼音字典退役、ZIP 预算内）；三卡详情重设计与"卡间零挂载"红线确立；子任务、资源支持关联、今日三件事 AI 推荐；知源仪表盘 R3（年度热力图 + 复盘两栏 + AI 文本报告）；性能主线四刀收口（量具修正/看板窗口化/开详情拆账/检索定位）；V3.6.7（R174）仪表盘焦点化 + 按日快照落盘 + 回归分片 + ZIP 减重。

> 完整逐轮明细见 `docs/交付说明_R*.md`（编号即轮次，当前至 R173-T）。

## 第九章 · 边界与未来

### 9.1 明确不做（本期）

知源云同步 / 自动云端备份 / 团队协作 / 移动端 / 复杂长文编辑 / AI 自动决策 / 使用追踪与画像 / KPI 压迫式管理。

### 9.2 下阶段候选方向

按"先调度闭环可信 → 再习惯养成 → 再商业化"排序：资源生命周期深化（防库无限膨胀）→ 模板与角色方案包（新手激活杠杆）→ 复用度量增强 → 商业化能力（买断授权、本地校验）→ 生态协同（Obsidian 深链增强、本地 AI 工具链接入规范）。

### 9.3 商业化现状

免费使用，本地分发，开发者模式安装。商业化方向为**买断制**（规划中）——不承诺具体价格与时间，不把买断制写成已开放销售权益。
