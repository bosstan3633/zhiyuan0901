设计说明（为什么这么做）

0. 需求与红线怎么兼容

  • R165-B 红线「卡间零挂载」= 卡对象互不持有对方 id。本提案不恢复 R162 退役的 TaskCard.mountedResourceIds 字段，改用独立关联表 SupportLink { id, taskId, resourceId, from: ai|manual, why, createdAt }。
  • 先例同构：策展台镜像 CurationProjection[]（记录型实体，mergeByIdArr 按 id 并集合并，红线明文豁免）。关联表走同一模式，红线一字不改。
  • 双向显示=反查索引（一次建表，catIndex 同法）：任务侧列资源、资源侧列任务；两端卡都零新增字段。
  • 好奇卡按拍板零关联：fromCuriosityId 一并删除（转化溯源由 link=sourceUrl + 描述文字承担）。

1. 拆解双通道（已有，R139）

  • 「拆解步骤」评审抽屉里两枚去向钮：采纳=建子任务（primary）/「📝 步骤写入任务详情」（secondary）。本原型不重复发明，只展示两通道并存。

2. 子任务 = 第 7 层？

  • 数据层已支持（R144-a parentId 软层级，无新层实体、零迁移）；完成状态不联动、删父升顶层、⤴ 手动升级——语义都已在线上。
  • 缺的只是呈现：现状子任务在列表/看板平铺散着，仅一枚「↳」记号。本原型给出「详情内嵌分组（可折叠）+ 清单视图缩进归组」两处的目标态。

3. 找资源支持（新）

  • 入口=任务详情标题行主上下文动作（AI 三态同方案 A）；子任务同款入口（任务同构）。评审抽屉勾选采纳 → 写关联表；AI 不自动关联（决策边界不变）。
  • 投料：任务标题+说明+标签 本地预筛资源候选（top ~40，排除已关联），LLM 只排序+给一句判词（找佐证 buildEvidenceJob 同法）。
  • 任务侧点关联资源行=直接打开资源链接（recordResourceOpen 计热度）；行尾 ⧉ 语义另需看详情时走资源详情抽屉。
  • 解绑=删关联记录，绝不动资源卡本体（软删红线不碰）。
  • 删除卫生：任一端进回收站 → 显示过滤；物理删除 → purge 记录（metric.taskIds 同法）。撤销窗口内随卡恢复。

4. 难度与批次建议（详见聊天盘点）

  • 关联表+AI job+两向 UI ≈ 20 文件触点，一轮可做；风险=M14 渲染量（关联区计数徽标默认折叠）与合并语义回归用例。
