**为什么是 11px 而不是 12px**：规范 S2 原文写「表单组 caption 标题」，`caption` 在本项目字阶表里就是 11px。压到 12px 是"介于两档之间"的自造值——比规范大一档、比原来小一档，谁都不满足。

## 三、三件值得单独说

### ① 上一版我说错了一个数字，这版更正

B4 交付说明 §「S2 组标题一项的处理」里写「`.gs-card-title` 是**区块名**（16px/600）」。**实测是 13px/600**（`var(--fs-body)`）——16 是我在没有回源码的情况下凭观感写的。这个错让当时的判断偏向了"不能压，因为 16 压到 11 太狠"；实际是 13 压到 11，只差两档，压下去的代价比我说的小得多。

**教训**：这卡上一直写着"引用型数字必然失真"，通常用来防"引用别人的旧数字"；这次失真的是**我自己刚看过代码后的转述**。结论不变但理由变了——凡是要写进交付物、会被下一轮当依据的数字，当场 `grep` 一遍，不靠记忆。

### ② 压小之后层级靠什么成立

原来 13px/600 与正文 13px 同字号，**只能靠字重区分**；八张卡连排时，卡头和正文糊成一片。压到 11px 后，层级由三点差同时成立：

- **字号**：11 对 13（卡头比内容小一档，是"标签"不是"标题"）
- **字重**：700 对 400
- **字距**：正字距 `0.04em` 对 0（小字加正字距是本项目的既有约定）

颜色**没有下调**（仍是 `--text`，危险区仍 `--danger`）——这是 B3 定下的纪律：降噪只能动字号与间距，不能降对比度。11px 与 13px 的 AA 门槛同为 4.5:1，字号变化不改变合规要求。

### ③ `theme-audit` 不带 `--tag` 会把半成品写进日期目录，一次毒三条判据

第一次跑截图时没带 `--tag`，工具按默认值写到 `docs/视觉归档/2026-10-18/`（24 张 + 一份 **24 场景 / 282 token** 的普查）。而 `dead-css-scan` 与两条普查判据会**自动挑最新的归档目录**当字典——字典从「104 场景 / 831 token」缩到 282 token，大量规则瞬间"没见过"，判死与祖先断的账一起变，`W13-7` / `R4-Et③` / `R4-Ev①` 三条同时红。

处置：目录改名 `B-3830-title`（批量命名不带日期，不参与"最新"竞争），复查死 CSS 回到 3,804 / 0 / 0，三条判据原样通过。

**这类坑的共同形状**：产物本身没错，错在它**进了某条判据的自动选取范围**。上个月踩过一次（`2026-10-17` 只有 8 张图无普查），这次换成"有图有普查但场景少"。判断依据不是"文件对不对"，而是"谁会自动读到它"。
