## 二 · ★搬移脚本连踩四个坑

这四个坑**症状完全一致**：`vue-tsc` 绿、`build` 绿、判据全绿，只有结构知道。

### ① 锚点行是**开标签**不是闭合行

宿主那行是 `<SettingsExportPanel v-if="activePage === 'export'" ref="exportRef"` —— props 与 `/>` 在**下一行**。接线插在"它后面"就是**插进标签属性区**：

```
error TS2345: Argument of type '{ ref: string; '<!': string; 快捷键设置: string; … }'
              is not assignable to …        ← 注释被当成 props
error TS2367: 'export' and 'shortcuts' have no overlap   ← 后续门控全部串成字符串比较
```

**解法**：从开标签往下找第一个含 `/>` 的行，插在它**之后**；并在搬后自检里加一条「接线必须落在 `<script setup>` 之前」。

### ② 两个锚同区

模板接线与 import 都锚在 `import SettingsExportPanel from …` 那一行 ⇒ **模板接线整块落进 import 列表中间**，正好夹在两个 import 之间。`vue-tsc` 与 `build` 全绿（import 区出现标签文本是合法的 TS）。

**解法**：两锚**分区** —— 模板区锚 `<SettingsExportPanel v-if=`（模板内唯一）、import 区锚 `import SettingsExportPanel from`（脚本内唯一），且各自断言**不唯一即抛错**。

### ③ 组件多套了一层 `gs-panel` 外壳

原文两个面板**各自**自带外壳且段内配平（332~371 段 `<div` 18 / `</div>` 18，差 0）。我多加一层 ⇒ 模板多一个 `</div>` ⇒ **Vue 模板容错把多余闭合标签静默忽略**，编译过、判据绿，只剩缩进错乱。

**解法**：脚本先自检原文配平（`<div` 数 == `</div>` 数），再据此决定是否补外壳；生成后断言 `depth == 起点深度`。

### ④ 注释插错面板

`unshift` 把 R49-I2 段注释放在守门**之前**，顶掉了守门要认的开标签 ⇒ 守门立刻假红「tplWsKeys 起点不是 shortcuts 门控」。

**解法**：任何"往段首插一行"的动作都必须排在守门之后。注释本身是有价值的历史证据（V3.7.0 R179 资源台退役 ⇒ 策展台顺延到 3 号位），随面板迁进子域、放第二个面板顶部。

### 一条通用纪律（第四批已在记忆里，本批再次兑现）

> **判据与脚本自己必须先被验证**：锚点先 `grep` 实际形态、脚本先 `--dry` 再 `--gen-only` 再全量、生成后逐条自检（宿主零残留 · 接线在 `<script setup>` 之前 · 段内 div 配平 · 宿主私有符号逐个点名）。

配套两条：
- **`--gen-only`**（先写组件、vue-tsc 验过再改宿主）—— 上一批建立，本批全程沿用，**宿主零残留返工**。
- **宿主私有符号逐个点名 + 先剥注释** —— 大正则 `!/activePage|wsDisplayNameOf\(/` 命中了只说"有残留"，不说是哪一个；本批正是靠它发现 `wsDisplayNameOf` 漏配。而加上 `wsDisplayName`（前缀）又是负锚加码，`includes` 逐字包含 ⇒ 误报（纪律 18）。
