## 二、逐项勘验结论（源码为准，2026-09-16）

### A · 分类口径统一（① ②）

**现状**
- 采集浮层 `src/content/overlay-impl.ts:1311`（及切台面重算 `:1397`）：
  `treeCatLabels(d.categories.filter(c => c.workspaceId === defaultWs.id))` —— **只过滤 workspaceId，未过滤 `deletedAt`**。
- 数据获取 `getData()`（`:60-71`）：300s TTL 缓存 + `chrome.storage.onChanged` 命中即回写缓存 ⇒ 唤起时数据基本最新；但**浮层 DOM 是单次构建快照**，浮层开着时在资源台增删分类不会重绘。
- `treeCatLabels`（`:1703-1716`）**无防环**（自引用节点会整条消失），与资源台口径不一致。
- 资源台侧同功能口径是**对的**：`views/Workspace.vue:980` `wsCats` 含 `&& !c.deletedAt`。
- 批量移动 `composables/useWorkspaceBatch.ts:90`：
  `moveCatOptions = treeCatOptions(d.categories.filter(c => c.workspaceId === moveWsId))` —— **同样缺 `!deletedAt`**（但走 `buildCatIndex` + `seenOpt` 防环，抗重复更强）。
- 第三处（勘验附带发现）：`components/GlobalPopups.vue:1027` `capCategories` 同样无 `deletedAt` 过滤。

**结论**：截图里「产品设计 / 效率工具 / 事业策展台」各重复 3 次，根因在**数据层存在已软删分类（幽灵项）与同名历史记录**，而非渲染重复（`treeCatLabels` 输入→输出是 1:1）。
**修法**：三处统一走一个「当前台面有效分类树」纯函数（过滤 `deletedAt` + 防环 + 统一父子 label 口径）；浮层打开期间订阅一次变更重绘。

### B · 定位与高亮统一（⑤ ⑥）

**现状（机制齐全，但入口分散、语义偏浅）**
- 消费端 4 处：`Workspace.vue:1426`（资源卡 `[data-rid]`）· `components/compass/CuriosityPanel.vue:37`（好奇卡 `[data-czid]`）· `components/compass/TaskManagerPanel.vue:508`（任务卡 `[data-tid]`）· `CompassTree.vue`。高亮 = `scrollIntoView` + `.flash` class，**2000ms**，消费后 `router.replace` 清 query。
- 生产端 **3 份重复实现**：`CompassHome.vue:128 locateRec` · `GlobalSettings.vue:1284 openStatCard` · `GlobalPopups.vue:880 openItem`（另有 `:788 runFlatLocator`）。
- **真 bug（错配）**：`openStatCard` 对任务卡跳 `/` + `hl` —— 而任务卡消费者住在**方向台** `TaskManagerPanel`，调度台无消费者 ⇒ 跳过去**不定位、不高亮**。（⑨ 搬迁后此路径自洽。）
- 语义偏差：`openStatCard` 只切台+高亮，**不进详情**；`openItem`（搜索）资源卡**有链接时直接外开浏览器**（与「定位到资源台位置并高亮」的诉求相反）。

**结论**：① 3 份生产端收敛为单一 `locateCard(kind, id, opts)`；② 语义从「切台+高亮」升级为「切台 → 切到该卡所在容器（资源卡=所在分类 / 任务卡=所在项目与指标组 / 好奇卡=清单）→ 滚动 → 高亮」；③ 搜索点击默认改为「定位」，外开链接降级为行内显式按钮或修饰键。
**⚠ 关键新约束（R112/R116 引入）**：资源台卡片/列表/看板已改**增量渲染**（`RENDER_STEP=80` / `KANBAN_COL_STEP=20`）——目标卡可能不在已渲染集里，`scrollIntoView` 找不到节点，定位**静默失败**。定位前必须先把该卡纳入渲染集（扩展 limit 或切到所在分类后按需追加）。**这是本轮最容易踩的坑，必须进断言。**

### C · 结构重构与调度台整合（⑧ ⑨ ⑩）

**现状**
- 调度台 `/` = `views/CompassHome.vue`：今日三件事 + 项目调度 + 底部好奇心培育（R105-B4 折叠摘要，`curioCollapsed` 默认 true，`:568`）。
- 方向台 `/compass` = `views/CompassShell.vue`（489 行）三块：主航线 `LighthousePanel`（`:256`）+ **项目总览内联块**（`:260-344`，无独立组件）+ 任务调度 `TaskManagerPanel`（`:347-349`）。
- `TaskManagerPanel.vue`（1073 行）**无 props / 无 emit / 无 inject**（已核实 0 匹配），依赖只有 `useAppStore` + `useCompass()` ⇒ **搬迁成本低**。但内部 `route.query.hl` watcher（`:508`）与调度台上好奇卡的 hl 消费者**同页冲突**，需设计 hl 分派（如 `?hl=` 配 `?kind=`）。
- **三件事 bug 路径已确认**：`todayFocusList`（`:145`）= `dailyFocus[日期].slice(0,3)`，**长度不恒为 3**；`focusFull = length >= 3`（`:150`）。当 3 条记录中 1 条的 `sourceId` 失配或任务已软删 → `todayTaskForSlot` 返回 null（`:159`）→ 卡片 `v-if` 不渲染；而 `focusFull` 仍为 true → 空卡入口（`:805`）也不渲染 ⇒ **该格成黑洞，无入口**。截图现象完全吻合。
- **当日新增标记：当前无任何实现**（全库无 NEW badge），仅有 `todayIn` 计数（`:53`）。
- `ProjectCuration.vue`（870 行）**一个文件含两态**：无 `?p` = 项目选择网格（`:427-442`），有 `?p` = 单项目展板。

**结论**：方向台重构 = 删项目总览内联块 + 删任务调度 → 首页直接落「主航线 + 项目详情（一级，默认第一个项目）」；需为「多项目切换」保留轻量入口（否则删掉总览后无路切项目）。

### D · 字段配置真实生效（⑦）

**现状**：配置读写链路**是通的**（`models/index.ts:353 fieldConfig` ↔ `GlobalSettings.vue:1068` ↔ `FieldEditor.vue:79` ↔ `shared/utils/fields.ts:12 visibleFields`）。断点在**取值口径分裂**：
- 任务卡 `TaskManagerPanel.vue:651-664`：状态 / 标题 / 项目 / 指标 / 日期 **全部硬编码**；`tListFields`（`:429`）只吃「扩展行」，且 `slice(0,4)`、还把 `description` 排除。
- 好奇卡 `CuriosityPanel.vue:452-469`：`question / status / createdAt` 硬编码（注释自认「骨架不参与字段流」）；`sourceUrl` 默认隐藏且**卡片上根本没渲染**。
- 资源卡（`Workspace.vue:352 / 406 / 412`）**基本受控**，残留硬编码：分类徽标（`:364`）、`callCount`（`:411`）。

**结论**：把「骨架字段」也交给 `visibleFields(kind)` 判定后再渲染；`FieldEditor` 对不可隐藏的骨架字段显式标注「锁定」；扩展字段行数上限（4 / 3）放开或可配。

### E · 生命周期阈值可配（③）

**现状**：`shared/utils/lifecycle.ts:33-35` 硬编码 `COOLING_MS = 30d` / `ARCHIVE_MS = 90d` / `NEW_GRACE_MS = 14d`，注释明确「本期固定 30/90 天，不做设置页配置」；`lifecycleState`（`:52-64`）统一判定，面板文案（`LifecyclePanel.vue:131`）也写死 30/90。
模型侧：`CardBase` 已有 `lifecycleArchived`（R110）与 `snoozedUntil`（R113-T9）——但后者是**一次性绝对时间戳**，语义「忽略 30 天」，**不能**表达「这张卡冷却是 60 天」⇒ **per-card 阈值必须新增字段**。

**结论**：新增可选字段 `coolingDays? / archiveDays?`（可选 = 零迁移）；`lifecycleState` 内回落 `card.coolingDays ?? 30`；`LifecyclePanel` 每张卡加内联输入（填天数 → 自动重算 + 显示「自定义」标识）。
