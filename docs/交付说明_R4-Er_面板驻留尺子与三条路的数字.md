# 交付说明 · R4-Er · 给 ⌘K 的驻留立一把尺子（#114 的③，量完决定不动链路）

**日期**：2026-10-02 · 基线 V3.7.1（`65129f1` R4-Eq）· **未升版**
**来源**：#114 的第三件「结果表 ~1.3MB 派生串驻留」。开工前先量了一次——**那个 1.3MB 是估的**
（按字符数 ×2 算出来的），本仓库此前所有 perf 指标都是墙钟与长任务，没有一条读得出
"面板关掉之后到底还占着多少"。所以这一轮的交付是**尺子 + 数字 + 三条路的取舍**，不顺手改检索链路。

---

## 一、M15 是什么口径

`scripts/perf.cjs` 新增 **M15**：在**新文档**里 GC 后取堆用量作稳定态基线，点开一次 ⌘K（必须真的渲染出
`.gp-result-item`，等 2.2s 让懒加载 chunk 与空闲回调落定）再关掉、再 GC，取第二次——

| 指标 | 含义 |
|---|---|
| `M15_面板关着仍驻留(KB)` | 关掉面板后被永久占住的那份（结果表按数据缓存，R4-Pa 那条拆层 ⇒ 它不随面板释放） |
| `M15_开面板瞬时(KB)` | 开着时的堆差（含 DOM/vnode），**与上一条没有必然大小关系**（见第四节） |
| `M15_每卡驻留(B)` | 前者 ÷ **结果集行数**（资源+任务+好奇+策展台+项目，与面板真实建行同口径） |
| `M15_稳定态基线KB` | 一起报，否则跨次运行的堆漂移会被读成"驻留涨了" |

采不到就作废并显式记 `M15_采样失败`（面板没关掉 / 堆差为负 / 行数为零）——**宁可不报也不报假数**。

## 二、量到的数

```
大合成库（perf --scale=large，1,540 资源 + 700 任务 + 300 好奇 + 8 台 + 36 项目 = 2,584 行）
  M15_面板关着仍驻留 = 7,165KB   开面板瞬时 = 7,857KB   每卡 = 2,839B   稳定态基线 = 18,181KB
同尺子小库（439 行）  关着仍驻留 = 2,072KB → 两点定斜率 ≈ 2.4KB/行、固定项 ≈ 1.0MB
真库规模（用户库 260 张活卡的真实标题，合成同构库）  关着仍驻留 ≈ 1,979KB
```

再把每卡的 2.4KB 拆开（三组对照，都不改代码）：

| 对照 | 每卡驻留 | 说明 |
|---|---|---|
| 富内容（标题+描述+2 标签+链接） | 2,064 B | 基线 |
| 薄内容（去描述/标签/链接） | 1,277 B | **差 786 B ⇒ 派生串与 link/badges 附属物的份额** |
| 纯 ASCII 标题库 vs 中文标题库 | 差 79 B | 拼音字典**不在**驻留里（它按中文查询才进，且 M15 不键入） |
| 按字符数 ×2 直接算四份派生串（bl/nb/nt/tl） | ≈ 411 B | 与 786B 同一量级，差的是 link 截断串/badges 数组/字符串对象头 |

⇒ **R4-Pa 记的「~1.3MB 派生串」方向对、量级偏低**：真库里关着面板占住约 2.0MB，其中派生串约三分之一；
大头是"给整库每一行都建一个 17 字段对象"这件事本身。

## 三、三条路的数字（以及为什么这轮一条都不走）

| 方案 | 可省 | 代价 | 结论 |
|---|---|---|---|
| A. 关掉面板就释放结果表缓存 | ≈ 全部（关着 0） | 每次重开都要重建：R4-Pa 实测满库开 100ms vs 缓存后 48ms ⇒ **每次开都付回那 ~50ms**，而 ⌘K 是每天几十次的动作 | 不做：拿高频响应换空闲时的内存，方向反了 |
| B. 显示字段（badges/link/ws/cat）挪到"按屏算"，行对象只留匹配字段 | ≈ 每卡 300B 上下（≈ 10%） | 动的是全站断言最密的 `GlobalPopups.vue`（R117/R131-C2/R152/R161/R4-Pa/R4-Dk/R4-Dm 的锚点都在这条链上） | 暂不做：10% 的驻留换一次高风险随迁，不划算 |
| C. 去掉 `bl`（只留归一化串 `nb`） | 每卡 ≈ 190B | **不是零成本**：`bl` 那一路是"原文子串"通道，去掉后 `normKey` 的 NFKC 合成会在边界上丢召回（实测推理：数据里 `cafe\u0301`（分解形式）能被 `bl.includes('cafe')` 命中，而 `nb` 合成成 `café` 后不含裸 `cafe`） | 不做，除非带一套边界词召回电池并且你同意"分解形式变音符"这类数据不再被裸词召回到 |

**这轮真正的交付**是：以后任何人动 A/B/C 都有 M15 可读、有每卡口径可比，而不是拿估算数争论。

## 四、这一轮我自己犯的两次错，都是被机制抓住的

1. **给尺子加了臆造的不变式。** 我一开始把「开着 ≥ 关着」写成采样作废条件——小库实测直接打脸：
   关着 2,072KB > 开着 1,782KB（关掉面板时缓存与派生表留下、DOM 与 vnode 释放，两者没有必然大小关系）。
   已撤掉这条假闸，并在判据里加了**负锚**：`if (!closedOk || h1 < h0 || hOpen ...)` 这种写法一出现就红
   （**拿臆造的不变式当门禁条件，会把真样本判成假数，比不设闸更坏**）。
2. **撞出一个既有判据基建的洞。** 我给 M15 写了两段块注释，而 `perf.cjs` 里有
   `chrome.tabs.query({ url: 'http://127.0.0.1:' + port + '/*' })`——回归的注释剥离器**不跳字符串**，
   于是那个字符串里的 `/*` 被当成块注释起点，一路吞到后面的 `*/`：`codeOnly` 从 65,465B 只剩 **26,398B**，
   R4-Pa 那条「perf 必须量应用内 ⌘K」的正锚**全红**（改行注释即恢复，变异探针 R3 现在专门复现这条）。
   危险的不是这次报红的方向，而是**负判据在这种文件上会静默通过**。现扫 src 已有 8 个文件在字符串里含 `/*`
   （manifest.ts 5 处、overlay-impl.ts、GlobalPopups.vue、PoolCardsPanel、`useDashboardReport.ts` 的
   `'@/shared/ai/*'`——那正是入口字面量判据的锚点串、letter-data.ts、AssetManager、keys.ts 的 `'src/**'`）。
   立案 **#119：先修尺子再动手**，改完要重跑 1,621 条并逐条复核翻转（负锚变红=过去是假绿）。

## 七、边界如实

- M15 是**记录型指标**，不设阈值：CDP 堆读数本机噪声在 ±300KB 量级（拼音那档实测过），拿它当红线会假红；
  它的用法是"改前改后各读一次、每卡口径可比"。
- 「开着瞬时」这一档我没找到稳的语义（关面板前后两个读数都含未回收的中间态），所以只并列报出不作判定，
  也不要拿它做门禁。
- 三组对照（富/薄/ASCII）都是在**合成同构库**上量的，绝对值不等于你的真库；真库规模的 2.0MB 是"260 张活卡标题 + 同构合成"下的读数。
- #114 还剩两件：唤起那 ~100ms 里的 `backdrop-filter blur(20px)`+`focus()`（要动是设计取舍，等你拍板）、
  键入档读数稳定性（同码散布 1.1–1.2×，目前只能读最小值）。
- #117（popup 降级弹窗白屏）等拍板；#119（剥离器不跳字符串）建议排在下一次动 `GlobalPopups.vue` 或 `manifest.ts` 之前。
