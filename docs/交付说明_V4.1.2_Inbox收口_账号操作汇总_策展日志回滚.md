## 二、P0 修复说明

### 2.1 跨设备删除附件又被旧设备拉回

**根因**：云端恢复对普通卡片保留本机与远端成员并集，以兼容旧附件；同一策略误用于策展节点后，B 设备已经删除的附件会被 A 设备本机旧成员重新补回。

**修复**：

1. 普通卡片继续使用兼容并集。
2. 策展节点与 L1 中心论点以远端成员表为准，本机只能补状态，不能补成员。
3. 远端已不存在的附件进入失效集合，同时清理本机 IndexedDB Blob 与远端 Storage 对象。
4. 增加 `V412-9` 回归，覆盖 owner 彻底删除后的本机清理。

### 2.2 剪贴板图片无法粘贴到节点

**根因**：部分浏览器在 `paste` 事件中只暴露 HTML 或异步 Clipboard API，单一 `clipboardData.files` 读取会误判为空。

**修复**：

1. 优先读取 `paste` 事件中的 image files。
2. 非文本编辑区在图片为空时补读 Clipboard API。
3. 再兜底解析 HTML 中的 data URL 图片。
4. 普通文字粘贴不拦截；节点内标题 / 说明编辑框保持原生粘贴。

### 2.3 Inbox 转化入口无响应

**根因**：历史祖先元素上的 `aria-disabled` 污染了内部原生按钮，导致点击被浏览器视为不可用。

**修复**：Inbox 行改为普通 `article`，转化、删除、详情分别使用独立原生按钮，并补齐处理中、成功、失败和另外两类入口置灰状态。

## 三、数据与云同步

### 3.1 新增账号事件表

`v2/supabase/schema.sql` 新增 `public.account_events`：

- 主键：`(user_id, id)`，保证不同设备重复上传幂等。
- 设备：`device_id` 记录来源设备。
- 时间：`event_ts` 保存实际操作时间，`created_at` 保存云端接收时间。
- 内容：只保存动作、卡种、卡 ID、标题快照、目标态和必要 payload。
- 索引：按账号与事件时间倒序；按账号与云端接收时间。
- RLS：仅 `authenticated` 且 `auth.uid() = user_id` 可读写；`anon` 全部撤销。

部署脚本为幂等 SQL，可重复执行。

**当前部署状态**：已在线上项目 `zhiyuan-prod-sg` 成功执行两版迁移：

1. `20261105075004_add_account_events_and_capture_inbox_limits_v4_1_2`
2. `20261105075035_harden_sync_functions_and_rls_v4_1_2`

已核验 `account_events` 表、主键、索引、RLS 策略、`capture_inbox` 约束与 `curation-assets` 私有 Storage 策略均已生效。Supabase 安全扫描已清零函数搜索路径与 RLS 初始化性能告警；剩余一项非阻断建议是开启 Auth 的泄露密码保护。性能建议中的三条“未使用索引”为新表/新索引尚未积累查询，不作为删除依据。真实双账号运行态隔离与双设备网络同步仍待人工验收。

### 3.2 事件合并边界

- 本地继续保留最近 5,000 条事件缓存。
- 云端事件表不因本地窗口回卷而丢失更早记录。
- 旧云快照中的 `eventLog` 保留一次性迁移入口。
- 同步清单与今日战报共用同一份去重后事件序列。
- 本机离线仍可记录；联网后按事件 ID 补传。

### 3.3 数据兼容

- V4.1.1 升到 V4.1.2 不需要本地迁移脚本。
- 普通卡片附件仍只保存在本机。
- 策展节点附件继续进入用户私有 Supabase Storage。
- AI 凭据仍不上云。
- “今日三件事”继续随主数据快照同步。
