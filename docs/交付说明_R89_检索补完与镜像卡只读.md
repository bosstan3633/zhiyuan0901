## 一、要解决的问题

本版修的是三处"**看得见、用不了**"：

1. **自定义字段能显示，却搜不到。** 你在「设置 · 卡片字段设计」里加的自定义字段，值就印在卡片上，但搜索框对它一无所知。
2. **星标能点、能显示，却没法"只看星标"。** `⭐` 在三视图都能切换、看板卡上还会亮出来，唯独筛选里没有它。
3. **镜像卡上摆着四个点不动的按钮。** 镜像卡是别处资源的**只读投影**，却跟普通卡一样摆着 `📌 ⭐ 📂 🗑`——四个点下去，四个都只弹一句"镜像卡为引用，请到资源台操作"。而 `🗑` 更离谱：它写着"删除"，实际执行的是 `removeMirror`（**把投影移出本台，源卡毫发无损**）。

## 三、改了什么

### T1 · R6：搜索判据

抽 `parseQuery` + `matchCard` 一份（**只有一处使用，故留在组件内**，符合"≥2 处才抽共享"）：

| 能力 | 实现 |
|---|---|
| 范围扩到自定义字段 | `Object.values(r.customFields \|\| {})` 逐个 `String(v)` 比对 |
| `#标签` 直筛 | `parseQuery` 把 `#a #b 关键词` 拆成 `{ tags, kw }`；`matchCard` 中 **tags 全部命中才算**（交集） |
| 边界 | 单个 `#`（长度 1）**不算标签**，回落为普通词——避免刚敲下 `#` 就把列表筛空 |
| 用法提示 | 搜索框 `title` 补一行：`#标签 可按标签直筛（多个取交集，如 #前端 #待读）` |

> **为什么多个标签取交集**："直筛"是收窄不是扩大。`#前端 #待读` 的直觉是"前端**且**待读"，不是"前端**或**待读"。

### T2 · W5：`starred` 星标筛选

四处同步（同一份白名单 / 谓词 / 标签 / 下拉，避免漏一处）：

```
FILTER_KEYS       += 'starred'
FILTER_PREDICATES += starred: (r) => !!r.starred
FILTER_LABELS     += starred: '⭐ 星标'      ← 生效值徽标自动沿用（R88 的 filterSummary）
筛选气泡下拉      += <option value="starred">⭐ 星标</option>
```

### T3 · W4：镜像卡只读三件套

三视图（卡片 `.rc-action` / 列表 `.rr-action` / 看板 `.kc-action`）：

| 动作 | 条件 | 行为 |
|---|---|---|
| `↗ 打开` | 无条件 | 保持既有 |
| `📌` `⭐` `📂` `🗑` | 包进 `<template v-if="!isMirrorView(r)">` | 只给真身卡 |
| `🎯 定位源` | `v-if="isMirrorView(r)"` | `locateMirrorSource(r)` |
| `✕ 移出镜像` | `v-if="isMirrorView(r)"` | `removeMirror(r)`，复用 `.delete` 红色样式 |

**实现选择**：用包裹 `<template>` 而非拆两套动作条——后者会断开 `R79-2/3/5`（七动作顺序）与 `R82-1/2`（📋 位置）的判据链，需多改 4 条断言。效果等价，改动更小。

## 六、建议手测（3 分钟）

1. **自定义字段搜索**：设置 → 卡片字段设计，加一个自定义字段（如「来源」）并给某张卡填值；回资源台搜这个值，应能搜到（**改前搜不到**）
2. **`#标签` 直筛**：给 A 卡打 `前端`+`待读`、B 卡只打 `前端`；搜 `#前端 #待读` 应只剩 A；搜 `#前端` 应 A、B 都在
3. **单个 `#`**：只输入 `#`，列表不应被筛空（回落为普通词）
4. **星标筛选**：给两张卡点 ⭐；筛选气泡 → 按状态 →「⭐ 星标」，应只剩这两张；且「筛选」按钮上出现「⭐ 星标」徽标
5. **镜像卡动作条**：在任一策展台找一张 📡 镜像卡，hover 后应只有 `↗ 🎯 ✕` 三个（**改前有七个，其中四个点不动**）
6. **🎯 定位源**：点它应跳到资源台并高亮源卡
7. **✕ 移出镜像**：点它该投影从本台消失，**去资源台确认源卡还在**
8. **普通卡不受影响**：hover 一张原生卡，七个动作照旧（含 📡 / 📋）

## 八、本轮的经验：改结构前先看断言会不会被"搬家"绊倒

W4 有两种做法：

- **A. 拆两套动作条**（原生卡一套七动作 / 镜像卡一套三动作）——最直白，但会让"原生卡七动作"这条字符串链断开，`R79-2/3/5` 与 `R82-1/2` 五条断言全部要重写。
- **B. 用包裹 `<template>` 把写动作圈起来**，镜像专属两动作 `v-else`——效果完全一样，改动面小一半。

选了 B，但即便如此仍有 **3 条断言**因"门控位置搬家"变红（`R73-7` / `R79-8` / `R82-1`）。

**教训**：`v-if` 从"挂在元素上"移到"挂在包裹层"是**语义等价**的，但**基于字符串的静态断言看不见等价性**。动这类结构前，先 grep 断言里有没有那串 `v-if`，能预判就能少跑一轮。
