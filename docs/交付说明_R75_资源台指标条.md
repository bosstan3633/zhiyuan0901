## 一、为什么是"资源台指标条"

指标条（`ws-metrics`）自 **R62** 建立以来一直是**策展台专属**——整个块被 `v-if="!isHub"` 包住。这意味着：

**资源台顶部一格指标都没有。** 而资源台恰恰是全部资源卡的真身居所、镜像源头，是三张台面里数据量最大的一张。用户在策展台能一眼看到卡片总数 / 附件数 / 最近更新，切到资源台却什么都看不到。

这不是"要不要加"的问题，而是"当初写 `v-if="!isHub"` 时把两个身份混为一谈"留下的缺口。R73/R74 完成资源台收敛（两入口合一 + 删旧组件）之后，这个缺口成为资源台最显眼的信息空白。

**为什么不直接复用 5 格？** 5 格里的🏛 策展主题格与🔀 来源构成格对资源台不成立：

- **论点**是策展台的概念（每台一张中心论点、金字塔 L1 根），资源台不设论点；
- **来源构成**（台内 vs 镜像）描述的是"这一台里有多少是从资源台镜像过来的"，在资源台自身恒为「本地全量 / 镜像 0」。

⇒ 按台身份分流：**资源台 3 格 / 策展台 5 格，各取所需**。这也是 `04-20` 立项时拍板的口径（"补 3 格，但独立立项，别让 R16 范围膨胀"）。

### 2.2 卡片总数格的补充口径（`hubCountHint`）

新增一个 computed，三行逻辑：

```ts
const hubCountHint = computed(() =>
  metrics.value.mirrored > 0
    ? `⚠ 镜像 ${metrics.value.mirrored} 条待清理`
    : `分类 ${metrics.value.categoryCount} · 待分类 ${uncategorizedCount.value}`
)
```

### 2.3 样式（一行）

```css
/* R75（R18）：资源台 3 格版——论点格与来源构成格对 hub 无意义；只加修饰类，不改 5 格本体 */
.ws-metrics.hub3 { grid-template-columns: repeat(3, 1fr); }
```

只加修饰类，**`.ws-metrics` 本体（5 列）一字未动** ⇒ 策展台布局零风险。

## 三、一处需要裁决的实现偏离

`04-20` R18 原文写的是「📊 卡片总数（含"**台内 / 镜像**"提示）」。实现时勘验发现该口径在资源台不成立：

- `boardCardsOf(d, wsId)` 的镜像分支取 `p.targetWsId === wsId`；
- **单向挂载红线** ⇒ 不存在指向资源台的投射 ⇒ 资源台的 `metrics.mirrored` **恒为 0**；
- 照搬会让资源台常驻一行「台内 12 · 镜像 0」的噪声提示。

**本轮处理**：改为结构口径「分类 N · 待分类 M」（数据源 `metrics.categoryCount` + 组件内已有的 `uncategorizedCount`，**同样无需新计算**）；同时保留异常暴露——若历史脏数据导致 `mirrored > 0`，hint 自动切换为「⚠ 镜像 N 条待清理」。

- **未偏离拍板核心**：3 格 · 卡片总数 / 附件数量 / 最近更新 · 全部可点击下钻。
- **偏离仅限 hint 文案**。若坚持「台内 / 镜像」字面文案，改回只需替换 `hubCountHint` 一个 computed（一处、三行）。
