## 三、B2：任务树默认折叠（**不选抽屉**）

提案给了两个方案：**默认折叠** / **改为点击任务后滑出的右侧抽屉**。本轮选前者：

| 维度 | 默认折叠（选） | 右侧抽屉 |
|---|---|---|
| 新增组件 | **0** | 抽屉 + 遮罩 + 焦点管理 |
| 任务编辑入口 | 复用现有点一下即 `drawerRef?.open(t)` | **引入第二套入口**（重复） |
| 收益点 | 首屏信息密度下降 ✅ | 同样 ✅ |
| 回退成本 | `ref(false)` → `ref(true)` **一行** | 拆组件 |

**实现要点：**

```ts
const curTreeOpen = ref(false)
const curColsStyle = computed(() =>
  curTreeOpen.value ? `minmax(0, ${curSplit.value}%) 8px 1fr` : '1fr')
```

- 卡头按钮 **带任务数**：`任务树 {{ projTasks.length }} ▾/▴` —— 折叠时也知道下面压着多少；
- `.cur-split` 与 `.cur-col-r` 包 `<template v-if="curTreeOpen">` —— **用 `v-if` 而非 `v-show`**，
  折叠时真的不渲染，首屏的**信息密度与渲染成本双降**（`v-show` 只降视觉重量）；
- `collapsedGroups` 是组件级 `ref<Set>`，重建不丢。

### ★ 为什么不持久化

写进 `UIPrefs` 就变成「**记住上次**」，与「**默认折叠**」直接矛盾——第二天打开浏览器，
首屏又变成昨天那副沉重的样子。它管的是**首屏**，不是"上次看到哪"。

同一会话内**切换项目不重置**：用户已经表达要看，切个项目不该收回去。
这条由 `R94-8` 否定断言把守。

## 四、B3：三件事全完成的安静完成态

```ts
const focusAllDone = computed(() =>
  todayFocusList.value.length > 0 && todayFocusList.value.every(s => s.done))
```

**`length > 0` 这一半不是多余的** —— `Array.every` 对空数组恒返回 `true`，
去掉它就成了"一件都没排 = 今天已经完成"，是本类需求最经典的陷阱（`R94-5` 把守）。

**视觉**：

```css
.card.focus.all-done .today-cards { filter: saturate(.5); }
.card.focus.all-done .tc-num     { color: var(--text-3); }
.td-done { margin-top: 8px; font-size: 11.5px; color: var(--text-3); text-align: center; letter-spacing: .3px; }
```

- **不用庆祝动画、不用红色、不用进度百分比** —— 提案原文与产品原则（状态可见但不焦虑）都要求"安静"；
- **卡头不去饱和**（复制昨日 / 导出 / 日期导航）—— 那是操作区，褪色会影响可用性；
- 全部走既有 tokens 变量，零硬编码色。
