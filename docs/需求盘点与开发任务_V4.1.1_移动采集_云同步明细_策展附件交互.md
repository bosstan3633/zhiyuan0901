# V4.1.1 需求盘点与开发任务

日期：2026-11-05

基线：V4.1.0（`6599020`，`main` / `v4.1.0` 同点）

目标版本：**V4.1.1（小范围优化升级）**

开发分支：`codex/v4.1.1`
文档性质：本轮功能清单、开发任务、验收判据和发布范围的单一真源

## 一、版本目标

V4.1.1 不扩展产品边界，重点完成三类工作：

1. 修复已经影响实际使用的数据与交互 bug：图片粘贴、附件跨设备删除、Inbox 转化。
2. 收紧高频入口和交互路径：移动采集、云同步明细、中心论点卡、节点附件、Inbox。
3. 为方向树策展模式增加独立浏览器快捷键入口，并让默认落点符合用户预期。

本轮继续保持：

- 本地优先、手动云同步。
- 普通卡片附件不上云。
- 策展节点附件继续使用私有 `curation-assets` Storage。
- 不引入多人实时协作、共享权限或附件公开链接。

## 二、优先级

| 优先级 | 范围 | 说明 |
|---|---|---|
| P0 | 图片粘贴、跨设备附件删除、Inbox 转化 | 直接影响已有数据和核心闭环，先复现、先修复、先加回归 |
| P1 | 移动统一采集、云同步明细、中心论点卡、节点附件行、快捷键 | 用户高频可见和可操作的入口 |
| P2 | Inbox 首页置顶与快捷动作、样式收口、文档与发布 | 在 P0/P1 稳定后完成 |

## 三、功能清单

### R1 移动端统一采集栏

#### 交互

1. 删除“链接 / 文本”类型切换。
2. 只保留一个主输入区，用户可输入或粘贴链接、短句、多行文本。
3. 可选保留“标题”“备注”作为补充信息，不与主输入争夺视觉焦点。
4. 点击“提交到 Inbox”后自动判断采集类型：
   - 输入内容去除首尾空白后，整体是合法的 `http://` 或 `https://` URL：记为链接采集。
   - 其余内容：记为文本采集，原始换行和正文不得丢失。
5. 继续使用 `capture_inbox.content_kind` 落库，不新增数据库字段。
6. 离线、token 过期或网络失败时进入现有本地待同步队列。

#### 成功反馈

1. 提交成功后显示明确的成功状态，不只依赖短暂 Toast。
2. 成功状态至少包含：
   - “已提交到 Inbox”
   - 本次识别类型：链接采集 / 文本采集
   - “继续采集”按钮
3. 成功后清空主输入、标题和备注。
4. 输入区恢复到可立即继续输入的状态；点击“继续采集”后自动聚焦主输入。
5. 离线暂存时改为明确提示“已暂存，联网并登录后自动同步”，不得显示成已经到达云端。
6. 连续提交多次时，每次都有独立、可辨认的成功回执。

#### 验收

- 同一输入区可以提交 URL 和任意多行文本。
- 纯 URL 被识别为链接；包含解释文字的 URL 文本按文本保存，正文不丢失。
- 成功后清空输入并明确提示可继续提交。
- 离线队列恢复网络后仍能补发。

### R2 云同步基线与云端修订明细

#### 入口

1. 云同步页的“本机同步基线”和“云端当前修订”改为可点击项。
2. 点击任一项，从右侧打开同步明细抽屉。
3. 抽屉提供两个页签：

#### 本机基线明细

至少展示：

- 修订号。
- 最近上传、下载、检查时间。
- 内容指纹。
- 业务数据总量与分类数量。
- 记录级清单：类型、ID、标题/名称、更新时间、删除状态。
- 待上传附件、上传失败附件、待清理远端附件数量。

- 显示“基线明细尚未建立，本轮成功同步后生成”。

#### 云端当前明细

至少展示：

- 记录级清单：类型、ID、标题/名称、更新时间。

#### 差异视图

1. 本机基线与云端当前可生成记录级差异：
   - 新增
   - 删除
   - 内容变化
2. 差异按卡片/分类/事件/偏好分组，不用整库 JSON 直接糊给用户。
3. 没有差异时显示“本机基线与云端当前记录一致”。
4. 指纹只用于总体判断，记录级差异必须回到 manifest 计算。

1. 在 `CloudMeta` 附近新增轻量 `SyncManifest`，只保存同步身份信息和记录摘要。
2. 不保存第二份完整业务快照，不保存附件本体。
3. 成功上传、成功拉回和首次建立基线时写入 manifest。
4. 云端当前 manifest 在检查或打开抽屉时按需读取，并可缓存最近一次成功结果。

#### 验收

- 两张修订卡均可点击并打开右侧明细。
- 明细不是只有总数，能看到实际记录行。

### R6 图片粘贴 bug

#### 根因

当前节点 keydown 在检测到 `Ctrl/⌘+V` 后立即 `preventDefault()`，浏览器不会再派发包含图片文件的 `paste` 事件。后续读取 `ClipboardEvent.clipboardData` 的上传逻辑因此收不到图片，只进入“粘贴节点为子级”的旧链路，并提示“剪贴板为空”。

#### 修复口径

1. 统一由 `paste` 事件判断剪贴板内容，不再在 keydown 阶段提前吞掉 `Ctrl/⌘+V`。
2. 粘贴优先级：
   - 剪贴板含图片文件：上传到当前选中节点。
   - 无图片文件，但存在画布内部剪切节点：执行“粘贴为子级”。
   - 焦点在标题/说明输入框且剪贴板是文本：保留浏览器原生文本粘贴。
   - 画布外：不拦截。
3. 图片上传后继续走本地 IndexedDB 与云端异步入队。
4. 一次粘贴多张图片仍受 9 张上限约束。

#### 验收

- 从截图工具复制图片，选中节点后 `Ctrl/⌘+V` 能直接出现附件。
- 复制图片后再剪切节点，粘贴时优先处理图片，节点不会被意外移动。
- 标题编辑状态下粘贴文字仍进入输入框。
- 原有节点剪切/粘贴为子级继续可用。

### R7 跨设备附件删除不同步 bug

#### 根因

云端恢复时，代码会把“远端存在的附件”和“本机存在的附件”做并集，用于保留普通卡附件本体。这条并集规则同时误伤了策展分类节点与 L1 论点卡：B 删除附件并上传后，A 拉回云端快照时又把自己旧有的附件元数据补回，导致附件重新出现。

#### 修复口径

1. 普通卡片附件继续沿用“本机附件 + 远端元数据”的兼容策略。
2. 策展分类节点和 L1 论点卡改为：
   - 远端附件列表是唯一成员真源。
   - 本机只允许为远端已存在且 ID 相同的附件补充本地状态。
   - 远端不存在的附件不得从本地旧列表回填。
3. 拉回后本机多出的策展附件 Blob 进入孤儿清理候选，确认不再被历史或回收站引用后删除。
4. 远端对象删除使用持久队列；失败后继续重试，不得因为画布历史仍引用而永久丢失删除任务。
5. 节点软删仍只隐藏附件，不立即删远端对象；节点彻底删除才物理清理。

#### 验收

- A、B 同账号。
- A 上传附件并同步。
- B 拉回后能看到附件。
- B 删除附件并同步。
- A 再拉回后，附件元数据与缩略图均消失。
- Storage 中对应对象最终被清理。
- 普通卡片附件的既有本机兼容行为不回退。

### R9 Inbox 池入口、列表与转化修复

#### 手边的卡

1. 页签顺序改为：
   - Inbox
   - 任务
   - 好奇心
   - 资源
2. 默认选中 Inbox。
3. Inbox 角标显示“已进入 Inbox 且未转化”的数量；数量为 0 时显示弱化角标。

   - 采集时间。
   - 链接采集 / 文本采集标签。
5. 首页预览行提供快捷入口：
   - 转为任务卡。
   - 转为好奇心卡。
   - 转为资源卡。
   - 删除。
6. 更多信息或已转化镜像点击进入二级 Inbox。

#### Inbox 二级页

1. 每行显示标题明细，不再只显示固定的“链接采集 / 文本采集”。
2. 固定名称作为类型标签，标题/正文首行作为主标题。
3. 每行继续提供删除与三种转化入口。
4. 转化成功后：
   - 自动切换到对应转化分组，或原行原位进入已转化态。
   - 滚动并高亮该镜像行，显示持续可见的成功回执。
   - 用户点击的转化按钮保持高亮。
   - 另外两个转化按钮立即置灰。
5. 转换后的卡片必须进入对应卡池，Inbox 只保留镜像入口。
6. 删除已转化 Inbox 条目只移除镜像，不删除目标卡。
7. 所有不可执行状态必须有可见原因，不允许按钮点击后静默 `return`。

#### 转化 bug 修复

1. 复现并修正 `connected / online / converting` 提前返回导致的无反馈。
2. 点击转化后立即进入“转化中”状态；网络超时要有上限并显示错误。
3. 本地卡片创建成功后，即使云端转化状态回写失败，也保留已转化状态与重试队列。
4. 避免同一条采集生成第二张卡；继续使用 `sourceCaptureId` 幂等。
5. 转化后不依赖刷新页面才更新 UI。

#### 验收

- 首页默认看到 Inbox，且角标数量正确。
- 首页与二级页均能看到标题和操作入口。
- 点击任一转化入口后，目标卡进入正确卡池。
- 当前页面不刷新即显示已转化镜像。
- 另外两个入口置灰，删除镜像不删目标卡。
- 网络失败有明确提示，恢复后可重试且不重复建卡。

## 五、数据与兼容

### 不新增数据库表

本轮复用现有结构：

- `cloud_snapshots`：继续保存主快照和修订号。
- `capture_inbox`：继续保存链接/文本、转化和删除状态。
- `curation-assets`：继续保存策展节点附件本体。

预计无需新增 Supabase SQL 迁移。

### 本地新增数据

新增同步 manifest 属于本机辅助信息，放在现有云端 meta 存储中：

- 不进入主 JSON。
- 不进入云快照业务数据。
- 不包含附件 Blob 或凭据。
- 可随时重建，不参与核心数据恢复。

### 旧数据兼容

- 没有 manifest 的旧账号首次打开明细时显示“待建立”。
- `capture_inbox` 既有 `content_kind` 保持不变，新移动端只改变录入方式。
- 普通卡片附件恢复逻辑不得因本轮修复而改变。
