## 三、说明（3 条）

1. **卡 DOM 15 节点目标重估**：该目标定于 R155 富卡拍板之前；R155 已拍板「摘要 2 行 + 启用字段 3 个」、R158 已拍板「一档 hover = AI 徽标/移动/删除 + 断链补全 + ⋯ 出口」，卡面信息密度为主动选择。实测 ~34 节点/卡与任务书基线一致，按任务书「与 R155 富卡（卡变高）合并测定」条款，改以 **M14 全屏节点总量（1647）** 为跟踪口径写入 06-2。
2. **E2E-16 伪通过修正（本轮实测发现）**：原用例「页面内 `runtime.sendMessage` 自收」**本就是空转**（MV3 同帧不收自身消息）——旧版只是靠 GP 静态挂载时面板 DOM 恒在（关闭态非 display:none）蒙混过关；GP 改按需挂载后暴露。已改走真实生产路径：**SW → `tabs.sendMessage(tabId)` → App 收 → `gpOpen` 冷挂载 GP → 面板打开**（同时覆盖懒挂载首启链路）。
3. **包体文件数 65→88 的解释**：按需挂载把原入口内的大模块拆成独立小 chunk（GP/抽屉/Airtable/迁移器等），文件数上升属**结构代价**，总体积与 ZIP 双双下降。
