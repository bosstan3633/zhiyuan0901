# 交付说明 · R73（V2.42.0）资源台收敛（R16）

**发版日期**：2026-09-11 ｜ **版本**：V2.42.0 ｜ **基线**：V2.41.0（R72 → 本轮待 commit）

> 本轮为**入口收敛版**：把资源台的两套界面（顶栏「资源台」页签 / 工作区里的资源台本体）**合成一套**，让"资源卡真身唯一居所"这句话在实现层也成立。**零数据模型破坏性改动、零存储格式改动**——用户看到的资源台功能只增不减（新增页头、镜像推送、空白落卡），且旧入口组件退役后**保留代码可一行回退**。

## 一、为什么这一轮是「资源台收敛」

R16 立项时的原始判断是"资源台有两个界面，需要收敛"。但真正动工前，先做了一轮**只读等价性审计（S1，零代码改动）**，结论如下：

**`CurationCenter.vue` 在 `v2/src/` 内仅 3 处引用**——`router.ts` 的动态 import、`App.vue` 的 KeepAlive include、文件自身。这意味着：

| 路线 | 做法 | 代价 |
|---|---|---|
| 甲：删文件 | 删除 `CurationCenter.vue` + 重写 58 条引用它的断言 | 断言大面积改写，回归风险高 |
| **乙：摘路由（本轮采纳）** | 只改路由重定向，**文件保留** | 58 条断言**原样通过**，回归**只增不减**，一行可回退 |

用户拍板走**路线乙**（`04-23` §十二 Q4）。事实也证明如此——改完源码后跑回归，**恰好 7 条失败**（正是那 7 条"资源台在旧组件里"的断言），其余 51 条因文件保留而原样通过。

## 二、交付内容

### 2.1 路由收敛（S5b）——两入口合一

`src/newtab/router.ts`：

```ts
{
  path: '/curation',
  name: 'curation',
  redirect: to => ({ path: '/workspace/' + CURATION_WS_ID, query: to.query }),
  meta: { title: '知源调度台 · 资源台' }
}
```

- 顶栏「资源台」页签（`/curation`）→ **重定向**到资源台本体（`/workspace/zy-curation`）；
- **查询参数透传**（`query: to.query`）——`?hl=` 定位高亮不丢；
- `App.vue` 的 `activeTab` 认 `CURATION_WS_ID`（`:74`），顶栏高亮正确；
- `App.vue` 的 KeepAlive include 去掉 `CurationCenterView`（`:484`），改 `CompassHomeView,WorkspaceView,CompassShell`。

**构建级证据**：`vite build` 产物中**已无 CurationCenter 独立 chunk**——该文件从路由不可达，被 tree-shaking 彻底剔除。

### 2.2 旧入口退役但保留（S5c）

`CurationCenter.vue` 文件头加 `@deprecated R73` 大段注释（说明保留原因、死代码提示、指向 `04-23`），**文件不删**。这是路线乙的核心：可一行路由回退，回归项数只增不减。

### 2.3 资源台补页头（S5a / Q2）

`Workspace.vue` 模板补 hub 页头——补上 R64-F13 删除 hero 大标题后留下的空档：

```
资源台 · 资源卡唯一存储 · 镜像源头
📡 单卡 / 📤 分类 可镜像到各策展台 · 源数据零影响
```

### 2.4 导入按场景分流（S2）

`Workspace.vue` 导入弹窗改 **mode-aware**：

| 场景 | 提供通道 |
|---|---|
| 资源台（hub） | **书签 HTML** + **本地文件**（书签文件夹勾选弹窗） |
| 策展台 | **策展台数据包 JSON** |

新增：`makeHubResource` / `parseBookmarksHtml` / `handleBookmarkImport` / `ensureBookmarkCategory` / `confirmBookmarkImport` / `handleFileImport` + 3 个隐藏 input（`bookmarkInput` / `fileImportInput` / `boardImportInput`）。书签规则不变：根文件夹白名单（`BK_ROOT_NAMES`）→ 前 2 级建分类、第 3 级+转标签（`segs.slice(2)`）。

### 2.5 镜像推送入口（S3）——补齐 L3

| 入口 | 位置 | 作用 |
|---|---|---|
| 📡 | 资源卡卡面动作条 | 把**单卡**镜像到指定策展台 |
| 📤 | 分类树节点 | 把**整分类**（含直属子分类与卡）镜像到指定策展台 |

均以 `v-if="isHub && !isMirrorView(r)"` / `v-if="isHub && !isMirrorCat(sc.cat)"` 门控——**只在 hub 且非镜像物出现**。底层 5 个投射 API 此前已在 hub 使用，本轮只补"选目标台"推送 UI（`mirrorPushModal`）。

### 2.6 区域级落卡（S4）——补齐 L5（唯一需新写的功能）

hub 此前**完全没有**"拖入空白分区落卡"能力，本轮新写：

- `acceptDragOver` / `clearDragState` / `catKeyToCatId` / `onAreaDragOver` / `onAreaDrop` / `reorderMixed`；
- `.card-grid` 绑定 `@dragover="onAreaDragOver($event, g.key)" @drop="onAreaDrop($event, g.key)"`，卡片绑 `@dragend="clearDragState"`。

### 2.7 聚合哨兵不污染数据层（S4a）

新增 `newCardCatId()`——新建卡 / 文件导入 / 空白区落卡统一经它回落，聚合哨兵（`all`）不写进分类归属。为避免与 hub 既有 `filterBy` 的 `'all'` 字面量撞名，**保留字面量、只补函数**：

```ts
function newCardCatId(): string {
  const c = activeCategory.value
  return (c && c !== 'uncat' && c !== 'all') ? c : ''
}
```
