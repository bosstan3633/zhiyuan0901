## 一、为什么有这一轮

上一轮（R94）交付时我给出的结论是：

> 「P1 24 项已交付 21 项，剩 **1 项 `G7`**（`cardCols` 纳入导出偏好包）。要我接着开吗？」

**动工前勘验，这个结论被证伪了。**

| 证据 | 内容 |
|---|---|
| 代码 | `GlobalSettings.vue:1637` 注释即 `// R72-G7：界面偏好包补齐「卡片视图列数」` |
| 追溯 | `git log -S "R72-G7"` ⇒ 引入于 commit `7420ea3`「V2.42.0（R72 + R73）」 |
| 断言 | `R72-9 G7 界面偏好包补齐列数：导入侧按白名单归一后落库` —— **长期全绿** |
| 导出侧 | `exportAll()` 走 `loadUIPrefs()` 整段并入 `uiPrefs`（`R66-3` 把守）⇒ `cardCols` 本就随行 |

⇒ **`G7` 早在 R72 / V2.42.0 就已交付**。而 `04-20` 总览写着「G1–G6 已交付；**G7 待排期**」。

这与 R91 清偿的「任务中心顶部」是**同一类坏账**——**书面口径与代码实装不一致**。
但这次更严重：它不是清单里孤零零的一行字，而是**我在 R93、R94 两份交付说明与母版变更记录里一路向下传递的错误结论**。

⇒ 本轮不写新功能，做三件事：**① P1 全量对账（逐条拿证据）· ② 修正清单与已发出的错误表述 · ③ 补断言把守往返闭环**。

## 五、补的 2 条断言（969 → 971）

`G7` 的**往返闭环**此前分散在两条历史断言里——`R66-3` 守「导出整段并入 uiPrefs」、
`R72-9` 守「导入白名单归一」，**没有任何一条从"列数偏好"的角度把往返串起来**。
这正是"能力已交付却被认为没交付"的土壤。

| ID | 断言 |
|---|---|
| `R95-1` ★ | `cardCols` **往返闭环**：`exportAll` 并入 `loadUIPrefs()` 整段（`{ ...safeData, uiPrefs }`）＋ 导入侧 `sanitizeCardCols(ui.cardCols)` → `saveUIPrefs({ cardCols: cols })` |
| `R95-2` | 三模块键同源：`sanitizeCardCols` 的键集合取自 `CARD_COLS_DEFAULT`（**不手写键数组**）⇒ 新增模块键时自动跟随，不会漏归一 |

**活性验证**：撤掉 `GlobalSettings.vue` 导入侧那两行
⇒ **`R72-9` 与 `R95-1` 双双变红**（969 通过 / 2 失败）；还原 ⇒ **971 全绿**。

> 承接 R92 教训（技能 §五·补二十）：**全绿只能证明代码当前符合断言，只有活性验证能证明断言会拦住回归。**
