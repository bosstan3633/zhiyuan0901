## 三、顺带修掉的真缺陷

### 3.1 镜像「误报成功」

**病根**：`hub.ts` 的 `projectCardToBoard` 对**已存在**的投射记录会顺手更新 `targetCatId` 并**返回已有 id**，调用方拿到的 id 与新建成功完全一样 ⇒ 无法区分「新建」与「本来就有」⇒ 重复镜像也弹「已镜像到…」。

**为什么门禁没拦住**：既有判据只钉「镜像写入发生」，没钉「写入是新建还是已存在」——这是**判据的盲区**，不是回归失败。

**修法**：拆出 `projectCardToBoardEx`，返回 `{ id, created }`；弹窗汇总只按 `created` 说真话（新增 N / 移出 M / 没有改动）。

### 3.2 镜像与置顶「双计」与「覆盖回去」

- **双计**：`ResourceDetailDrawer.openFromId` 打开时**自己已经记过一次调用**。若「开链接失败 → 回落开抽屉」路径先自己记一次、再让抽屉记一次，就记了两回。修法：`openResourceLink` 改为**先判定可打开性、确认可打开才记账**，失败分支零记账。
- **覆盖回去**：抽屉的 `editing` 是源卡深拷贝，`save()` 用整份 `editing` 覆盖库内记录 ⇒ 只改库内对象不同步 `editing.pinned`，用户随后点「保存」会把置顶状态覆盖回去。修法：`togglePinOf` 同时更新库内记录与传入的编辑草稿。

### 3.3 孤儿检查在 Windows 上长期误报

`orphan-check.cjs` 的名册键统一正斜杠后，8 个早已登记保留的文件长期被误报孤儿（B8-2a 一直红）。本批修了 Windows 路径分隔符 bug，并补齐 `shared/utils/index.ts` 的保留登记。
