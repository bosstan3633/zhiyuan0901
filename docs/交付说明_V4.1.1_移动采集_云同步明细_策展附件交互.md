## 二、P0 缺陷根因与修复

### 2.1 剪贴板图片无法粘贴到节点

**根因**：节点在 `keydown` 阶段检测到 `Ctrl/⌘+V` 后立即 `preventDefault()`，浏览器不再派发包含图片文件的 `paste` 事件，后续附件上传逻辑收不到图片，只进入旧的“粘贴节点为子级”路径并提示“剪贴板为空”。

**修复**：

1. 不再在 `keydown` 阶段提前吞掉粘贴事件，统一由 `paste` 事件读取 `clipboardData`。
2. 有图片文件时优先上传到当前选中节点。
3. 没有图片时，才处理画布内部剪切的节点。
4. 焦点位于标题或说明输入框时，文本粘贴保持浏览器原生行为。
5. 多图粘贴继续受每节点 9 张图片上限约束。

### 2.2 B 设备删除附件后 A 设备重新出现

**根因**：云端恢复时把“远端附件”和“本机旧附件”做并集，用来兼容普通卡片附件。该规则误用于策展分类节点和 L1 论点卡，导致 B 已删除的附件在 A 拉回时被本机旧列表重新补回。

**修复**：

1. 普通卡片继续保留本机与远端的兼容合并策略。
2. 策展分类节点和 L1 论点卡的附件成员列表改为远端权威。
3. 本机只能为远端已存在且 ID 相同的附件补充本地状态，不得回填远端已删除的附件。
4. 失效本机 Blob 进入后置清理，不影响远端删除队列。

### 2.3 Inbox 点击转化无反应

**根因**：祖先 `v-pressable` 的 `aria-disabled` 状态污染了内部转化按钮，浏览器把所有子按钮视为不可用，点击事件无法完成转化。

**修复**：Inbox 行改为普通 `article`，转化、删除和详情使用独立原生按钮；转化过程补齐处理中、成功、失败和置灰状态，成功后立即显示目标卡镜像，不依赖刷新。

## 三、数据、云同步与兼容边界

本轮**没有新增 Supabase 表或 SQL schema 迁移**：

- 移动采集继续使用现有 `capture_inbox`。
- 策展节点附件继续使用现有私有 `curation-assets` Storage。
- 同步明细使用本机轻量 `SyncManifest`，只保存同步身份和记录摘要，不复制完整快照，不保存 Blob、base64、签名字典或凭据。
- 普通资源卡、任务卡、好奇心卡的附件仍仅保存在本机。
- AI 凭据仍不上云。
- “今日三件事”的结构化字段继续随主快照同步。

旧数据兼容：

- V4.1.0 本机数据升级到 V4.1.1 不需要迁移脚本。
- 没有同步 manifest 的旧账号首次打开明细时显示“待建立”，完成一次成功同步后生成。
- 已转化 Inbox 项继续保持幂等，不重复创建第二张目标卡。
