## 四、关键设计决策（为什么是这些值，不是拍脑袋）

### 4.1 accent 亮度有一个**硬上限**：L ≤ 0.183

全站有 **10+ 处** `background: var(--accent); color: #fff`（`.ai-btn.primary` / `.mini-btn.primary` / `.cz-filter.active` / `.nd-btn` / `.ts-status-chip.active` / `.re-btn` …）。白字要满足 WCAG AA 4.5:1，要求 accent 的相对亮度 ≤ `1.05/4.5 − 0.05 = 0.183`。

同时 accent 还承担"当前态文字色"（`color: var(--accent)`），太暗会在深底上看不见 ⇒ **下界约 0.14**。

**accent 的可用亮度窗口是 [0.14, 0.183]，非常窄。** 这是"蓝色系配白字"的固有约束，也是为什么不能随手挑一个漂亮的亮蓝 —— 实测四主题最终落在 **0.139 ~ 0.177**，全部命中窗口且 4.5:1 有余量（4.70 / 4.85 / 4.92 / 5.55）。

### 4.2 「跟随系统」不引入第五套 CSS 主题块

设计选择：`ui.theme = 'auto'` 在**落 `data-theme` 之前**解析成具体主题（系统深 → `linear`，浅 → `apple`），而不是新增 `[data-theme='auto']` + `@media (prefers-color-scheme)`。理由三条：

1. `tokens.css` 只需维护四套**真实**主题块，auto 不是第五种观感；
2. 任何读 `documentElement.dataset.theme` 的地方（`theme-audit` / `e2e` / 调试）拿到的都是**确定值**，不会出现"截图里是 auto"这种不可判定的状态；
3. UI 选中态（`ui.theme='auto'`）与实际生效主题**解耦**，两者各自正确。

配套：`stores/app.ts#applyTheme` 在 `auto` 模式下注册 `matchMedia('change')` 监听、切到固定主题即解除 —— 否则「跟随系统」只在切换那一刻生效，**刷新后系统改配色页面不会跟着变**。监听在 `init()` 里也调一次，保证冷启动（`main.ts` 只负责落属性）不会漏注册。

### 4.3 顺带修掉的两处过期口径

| 问题 | 事实 | 处理 |
|---|---|---|
| `--text-3` 在浅色最深层底上不足 3:1 | apple `#E9ECEF` 上 2.96 / notion `#E9E6DF` 上 2.74 | **提亮 `--surface-3`**（`#EAEAEF` / `#EEEAE3`）而不是压暗文本 —— 保住了 text-3 与 text-2 的档位区分 |
| `stores/app.ts` 的 `theme` computed 默认值 | 仍写 `'green'`（R53-D 早已退役该主题） | 校正为 `'linear'` |

3. **视觉归档 16 图**：`docs/视觉归档/` 按 `.gitignore` 不入库（派生件，一条命令可重放）。
4. **真机手点复测**：需在浏览器实际加载解压包，肉眼确认四主题观感差异（尤其 linear vs raycast 的纯黑对比）。

## 八、踩坑记录

1. **notion `--surface-3` 与 `--surface-2` 曾一度撞车**：为把 text-3 拉过 3:1 而提亮 `--surface-3` 时，初值 `#F0EDE7` 与 `--surface-2` `#F1EFEA` 几乎同色 ⇒ **层级塌陷**。改为重排两层（`#F2F0EB` / `#EEEAE3`）+ 加深 text-3 到 `.52` 才同时满足"对比度达标"与"四层可辨"。教训：**改浅色主题的层级色必须同时校验相邻两层差**，不能只盯对比度。
2. **`--accent-light` 上的对比度不是"改坏了"**：暗主题 3.28/3.40 是既有事实（R153-4 已记账），不是本轮引入。核查方式是先算 `#5E6AD2` on `rgba(94,106,210,.16)` 的旧值 —— 同为 ~3.3:1。
3. **heredoc 写 JS 会被 shell 抢先展开**（`${...}` 触发 `Bad substitution`）：设计期脚本改用文件写入，不用 `cat <<'EOF'`。
