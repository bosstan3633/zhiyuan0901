## 三、设计决策

### 3.1 目录化形态（方案 C：类型单源 + 分区数据保留 + 自定义共享同步）

**纠正过的方向**：不做物理单表、不做 FieldConfig 物理合并（order/visible 须按卡型独立，合并即退化）。落地形态：

1. **系统字段单源目录** `FIELD_CATALOG`（新增 `v2/src/shared/models/catalog.ts`）：
   - 每条 `CatalogField` = `FieldDef` + `{ scope: 'base' | 'type'; kinds: CardKind[]; locked?; required?; system?; auto? }`
   - `base` scope = 公共字段（description/tags/pinned/**assets**/createdAt 等 → 转卡全搬清单 + 卡片通用渲染都以此为准）
   - `type` scope = 型专属字段（resource: link/linkType/sourceType/workspaceId/categoryId/callCount；task: status/priority/projectId/metricId/dueDate/mountedResourceIds/mountedCuriosityIds；curiosity: question/sourceUrl/status/shelf）
   - 锁定/必填/系统/自动/图标 全由目录推导，**删除 FieldEditor.vue 手写 3 份的五组常量（ICON_MAP/SYSTEM_KEYS/AUTO_KEYS/LOCKED_KEYS/REQUIRED_KEYS，行 14-30）**
2. **数据层 FieldConfig 分区结构不动**（{resource,task,curiosity} 三数组，各自 order/visible）→ **零迁移**。仅 `defaults.ts` 每型补 `assets` 系统 def。
3. **兜底机制**：`fields.ts visibleFields/allFields` 改为「分区数据 ∪ 目录兜底」——老用户分区缺目录 base 字段时自动尾插默认可见。效果：**新增公共系统字段 = 只改 catalog + defaults，三处界面与三视图自动生效**。
4. **自定义字段共享同步**：仍存各自分区，但增删改走统一函数 `syncCustomField`——新增时勾选适用卡型（默认全选），同名 key+label 写入被勾选型的分区；重命名/删除跨型同步。key 全局唯一 → 转卡时 customFields 原样搬、label 有效。
5. **转卡注入**：目标型分区若缺源卡带的自定义 def → convert 时自动补入（保 label 显示）。

### 3.2 CardBase 公共基底（REQ-049 子项）

- `models/index.ts` 新增 `interface CardBase { id; kind; description?; tags?; pinned?; assets?: AssetMeta[]; customFields; createdAt; updatedAt; deletedAt? }`
- `ResourceCard / TaskCard / CuriosityCard extends CardBase`（kind 收窄字面量；title/question 留在各型——资源/任务 title 必填、好奇 question）
- 破坏面由 vue-tsc 全量兜底；各 store `add()` 字面量不变（继承兼容）

### 3.3 转卡状态映射（显式，REQ-050）

| 好奇 status | → 任务 | → 资源 |
|---|---|---|
| todo 待探索 | todo 待开始 | （资源卡无 status 概念，不映射） |
| doing 探索中 | doing 进行中 | （同上） |
| done 已求证 | done 已完成 | （同上） |
| shelf 已搁置 | todo 待开始（Toast 提示：已搁置→待开始） | （同上） |

### 3.4 附件正面展示（REQ-051）

- 视觉：卡片正面底部一行 chips，按 kind 分组——图片 `🖼 n` / HTML `📄 n`，n=数量（满足"明确展示挂了几图几 HTML"）。点击徽章 → 弹出文件列表（名称/大小/类型），点单个文件：图片 objectURL 大图预览（Teleport body，复用 AssetManager 同款弹窗）；HTML `chrome.tabs.create` 新标签打开。缩略图为增强项，开工时按用户视觉意见定（见 §十 待确认）。
- 渲染链路：`fieldConfig 该型分区含 assets def（visible）` → `fieldRenderKind('assets')` → 三视图/面板统一渲染 `<AssetBadge>`，点击 `stopPropagation` 不触发行开交互。
- 列表/CSV 兜底：`fieldValue(card,'assets')` 返回"2 图 · 1 HTML"摘要文本。

## 五、验收清单

1. FieldEditor 界面三卡型 tab 行为与现版一致（显隐/排序/重命名/新增/删除），锁定与必填规则不变
2. 在资源 tab 新增自定义字段（适用三型）→ 任务/好奇 tab 立即可见；跨型同步改名/删除生效
3. 老数据（无 assets def）加载后三视图自动出现附件字段（兜底生效），无需重置
4. 好奇卡含 tags/描述/附件/自定义 → 转任务/转资源后全部保留且可编辑；shelf 状态转任务有文案提示
5. 好奇→任务/资源 转卡：tags/描述/附件/自定义字段/钉选 全保留且可编辑；shelf→任务 有 Toast 提示；三视图与详情**无任何「任务/资源转出」入口**（单向唯一）
6. 资源/任务卡正面：图片附件显示 `🖼 n`、HTML 显示 `📄 n`；点击出列表，图片可大图预览、HTML 新标签打开
7. 好奇心面板接入字段目录：按 fieldConfig.curiosity 显隐/排序渲染，附件徽章同链路
8. 卡片正面的徽章点击不触发卡片打开/双击行为
9. 全库检索无 `fieldViewCfg`（model/defaults/代码/回归）
10. vue-tsc 0 错误；regression.cjs 全绿（含 R40-*）；dist 干净重建；版本五处 2.16.0
11. 资源卡 CSV 导出不受影响（列仍含新增公共字段时按原 10 列逻辑回归验证）

## 七、风险与边界

- **转卡单向、无环**：任务/资源永不退化回好奇 → 不存在「任务转出后挂载关系」问题。好奇→任务/资源 后源卡软删（现有行为）；目标任务卡 `mountedCuriosityIds=[源 id]` 回指保持现状。任务/资源卡界面**不出现任何转出入口**。
- **FieldEditor 重写**有回归风险 → 施工后对照现版逐项手测（验收 1）。
- **好奇面板接入目录**牵动渲染结构，施工先看 CuriosityPanel 现有字段区再最小侵入改。
- **附件 Blob 不动**：转卡/展示均只搬 AssetMeta 引用，IndexedDB `zy_assets` 零变更。
- 资源卡 CSV 导出本次**不动**（抓手指 ③ 留 V2.17），仅回归防回归。
