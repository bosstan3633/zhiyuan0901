## 二、做了什么

### 2.1 动作条第七动作 `📋`（三视图一致）

```
↗ 打开 · 📌 置顶 · ⭐ 星标 · 📂 移动分类 · 📡 镜像（仅资源台真身）· 📋 挂载（非镜像）· 🗑 删除
```

- 卡片 `.rc-action.mount` / 列表 `.rr-action.mount` / 看板 `.kc-action.mount`，条件同为 `v-if="!isMirrorView(r)"`；
- 📡 的条件维持 `isHub && !isMirrorView(r)` **不动**（`R79-8` 把守）；
- 已挂载时加 `.on`：**强调色 + 淡底**（与 ⭐ 的金色区分），`title` 报「已挂载 N 个任务 · 点击管理」。

> **此处有一处未拍板、由任务书定的取舍**：动作条图标**不随已挂载态变化**（恒 `📋`）。
> 理由：动作条上的 `✓` 通常读作"完成"，与"挂载"语义混淆；`.on` 高亮与既有 `⭐` 同款（图标不变、仅高亮），不增加图标词汇。`✓` 出现在**选择器内**，已满足 R4 原文"已挂载显示 ✓ 可取消"。

### 2.2 右键菜单双入口

非镜像分支在「移动分类」之后新增一项（`icon: 'clipboard'`）：已挂载时报「挂载到任务（已挂 N）」，否则「挂载到任务…」。**镜像分支的四项不变。**

### 2.3 选择器弹窗（复用 📂 的 `modal-overlay` 骨架）

```
┌─ 挂载「<资源标题 16 字>…」到任务 ────────── ✕ ─┐
│ 🔍 搜索任务…                                    │
│ ✓ 完成 Q3 复盘              项目·年度规划        │
│ ＋ 整理客户访谈纪要          项目·客户洞察        │
│ ＋ 写周报                                       │
│ …（最多 50 条）                                  │
│ 单向挂载 · 点条目即生效            [✓ 完成]      │
└────────────────────────────────────────────────┘
```

- 数据源：未软删 → 关键词过滤（标题 `includes`，不区分大小写）→ **已挂载优先** → `updatedAt` 倒序 → 上限 50；
- 每行 `✓ / ＋` **点一下即挂载、再点一下取消**，立即 `persist()`，**无需确认**——与任务侧挂载 UI 完全对称，一次可挂多个任务；
- 底部「完成」只负责关闭（并给一句 `✓ 已挂载 N 个任务`）。

### 2.4 写入（单向挂载红线的落点）

```ts
function toggleMountTask(t: TaskCard) {
  const rid = mountTarget?.id
  if (!rid) return
  const arr = t.mountedResourceIds || []
  // 整体替换而非 push —— 直接改数组元素的部分路径不触发响应式
  t.mountedResourceIds = arr.includes(rid) ? arr.filter(x => x !== rid) : [...arr, rid]
  t.updatedAt = Date.now()
  store.persist()
}
/** 反查：该资源被多少个未软删任务挂载（不新增反向字段） */
function mountedTaskCount(r: ResourceCard): number {
  return d.value.tasks.filter(t => !t.deletedAt && (t.mountedResourceIds || []).includes(r.id)).length
}
```

**红线自检**：整个写入函数只碰 `TaskCard`，除取 `id` 外**不读不写 `ResourceCard` 的任何字段**。资源卡要知道"被哪些任务挂着"一律**反查** `d.tasks`（与 `ResourceEditForm.vue:52` 同款）。反查同一份数据 ⇒ 任务侧与资源卡侧计数**天然同步，无缓存副本**，不需要同步逻辑。
