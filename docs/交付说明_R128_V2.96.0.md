## 一、四项交付明细

### A1 · 跨上下文写入合并下沉到仓库（原：只在新标签页手工接线）

**缺陷**：`storage.onChanged → mergeExternalData` 的合并保护**只挂在 `newtab/stores/app.ts`**。popup 与 content 浮层各自「读—改—整树写」`zy_data_v2`，没有任何并发合并：浮层采集一张卡的瞬间，看板侧的未落盘修改会被整树覆盖（静默丢改）；`UIPrefs` 同样是整对象覆盖写，A 上下文改主题会被 B 上下文改列数**回退成自己的旧值**。

**实现**：
1. `shared/storage/repository.ts` 新增 `attachStorageSync()`（幂等，`syncAttached` 守卫），在 `loadData()` 内自动注册——**凡走仓库的上下文（newtab / popup / options / content）一份接线全覆盖**：数据键非本页写入 → `mergeExternalData` → 通知订阅者；UI 键走逐键合并。
2. 新增 `uiSelfWritten` 记账 + `mergeExternalUIPrefs()`：只接受本上下文没写过的键；我方写过的键在外部回声落地前保持本地值（外部值 == 我方值即解除保护，此后跟随外部）→ 多窗口偏好不再互相回退。
3. `app.ts` 删除自挂的 `chrome.storage.onChanged` 监听（避免同一外部写入被两处各合并一次 → 双 `saveData` 写环）；`isSelfWrite` 内容指纹短路语义不变（R34-22 仍守）。
4. **content 浮层数据链路整体改走仓库**：`loadData/saveData` → `repoLoadData/repoSaveNow`，自挂的 `onChanged` 刷新与「300s TTL 手工缓存」退役（新鲜度由仓库统一保活，且共享 `flushCardEvents` 的 WCE 口径与 JSON 纯净清洗）。popup 侧无需改动（R70 已走仓库，本轮起自动受保护）。

### A2 · 迁移「先判后落戳」+ 备份触发条件收窄（原：不可重试 + 误清现役镜像）

**缺陷**：`migrateHubMerge()` 把 `d.hubMergedAt = Date.now()` 写在两个 guard **之前**——资源台缺失/被归档时直接 `return false`，但戳已落 → 合并被**永久跳过**，用户后来取消归档资源台也不会补合并。同时 `app.ts` 的「迁移前自动备份下载」判据是 `!hubMergedAt`，资源台归档期间**每次启动都下载一份备份**。另 `migrateHubStructure()` ④ 步无条件 `d.curationProjections = []`，会把 R61 之后的**现役镜像**（资源台→策展台）一起抹掉（先导旧备份再升级 → 标记被重置 → 迁移重跑 → 用户镜像清单清零）。

**实现**：`hubMergedAt` 只在「确实无事可做」（无 boards）或「合并完成」两种终态落戳；新增导出 `hubMergeWorkPending(d)` 供调用方判断是否真要备份；④ 步收窄为「只清旧方向」——保留 `kind==='card'` 且 `targetWsId !== CURATION_WS_ID` 的现役投射（与启动期 `scrubHubMirrorMarkers` 同一口径）。

### A3 · 永久删除口径合一 + 转卡共享附件保命（原：三套实现、四类副作用）

**缺陷**：硬删逻辑存在**三套**（回收站逐项删、回收站「清空当前分区」、设置页「清空回收站」），且设置页那套只 `filter` 数组 → ① IndexedDB 附件 **Blob 全量泄漏成孤儿**（主 JSON 只存 `AssetMeta` 引用，数组删了本体永远留在库里）；② 任务卡脱离 `compass…metrics[].taskIds`（指标进度虚高、抽屉显示已删任务）；③ 指向已删卡的 `curationProjections` 悬空累积；④ 分类硬删与其他两套口径不一致。更严重的是**转卡共享本体**：REQ-050「转卡无损」是 `AssetMeta` **引用拷贝**（两张卡可指向同一个 assetId），而任一侧硬删都无条件 `deleteAsset(id)` → 另一侧附件**当场变死链**。

**实现**：新增 `shared/storage/purge.ts` 统一引擎——
- `purgeCardsCompletely(d, targets)`：四类副作用一处收口（本体清理 / `metric.taskIds` 摘除 / 数组移除 / `pruneDanglingProjections` 悬空投射剪枝），返回 `{ cards, assetsPurged, assetsShared, assetsFailed, projectionsPruned }`；
- **引用计数保命**：`keep` = 存活卡（含回收站软删卡，软删可恢复故其本体必须留）assets 并集，被引用者计入 `assetsShared` 不删，两侧引用者都硬删后才真正回收；
- `recycledCardsOf(d)`：全量口径（三类软删卡 + 软删分类），`RecycleBin.purgeAll` 与 `GlobalSettings.emptyRecycleBin` 共用；
- `deleteAssetIfOrphan(id, selfCardId)`：卡内删附件走此路径（排除所在卡自身后仍被引用 → 只摘引用不删本体）。`AssetManager` 新增 `owner-id` prop，三处宿主（`ResourceEditForm` / `TaskDetailDrawer` / `CuriosityPanel`）接入；文档替换旧附件同样改为判引用；
- 附件失效单条清理（`useWsAssetHygiene.onDrillCleanupAsset`）引用摘除**覆盖三类卡**（此前只扫 `resources` → 任务/好奇侧残留死链）；
- 用户可见反馈：删除失败/共享保留均按计数提示，设置页清空回收站改异步并报告「永久删除 N 项 · 清理 M 个附件本体 · K 个共享附件保留」。

### A4 · 浮层注入面收口（转义 + 链接协议统一口径）

**缺陷**：`content/overlay-impl.ts` 的结果行 `innerHTML` 直接把 `item.link.text` / `item.link.type` / badge / icon 裸插值——**链接文本可来自导入的 JSON 或页面采集**，是全站唯一未转义的 `innerHTML` 注入点；且浮层自行实现的 `toFileUrl` **旁路**了 R70-14 的伪协议黑名单（`javascript:` / `data:` 录入或导入后点击即执行脚本）。`TaskManagerPanel.toOpenableLinkUrl` 同样「其余协议原样放行」。

**实现**：结果行/热行图标/采集面板 `<option value>`（id 可来自导入）全部 `escapeHtml`；打开链接改走 `shared/utils/link.toOpenableUrl`（本地文件缺路径 → toast 引导去资源台补全；协议不被允许 → 明确提示），删除重复的本地 `toFileUrl`；调度面板补 `javascript|data|vbscript|blob` 黑名单拦截。

**范围说明**：原计划的 **Shadow DOM 样式/事件隔离已延后到批次 D**——浮层内有 54 处 `document.getElementById/querySelector`、`document.activeElement` 判定与事件重定向行为，属跨上下文架构改造，放进 P0 数据安全批次风险不对称。
