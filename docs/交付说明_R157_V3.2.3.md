## 八、踩坑记录

1. **断言脚本的"失败通道"也要被负向用例覆盖**：首版 `capsCheck`/`entryRegion` 的 `bad()` 推模块级 `errors`，而 `accounting` 返回局部 `errs` —— 主流程看似全绿、负向自检拿到空壳恒不红。修法：`let sink = []`，`accounting` 进场先 `sink = errs`。**若无负向自检，这个 bug 会静默把整个能力对账架空。**
2. **键型证据正则被三元冒号骗**：`chain.ts:86` 的 `bag.steps : bag.items` 让「步骤条」误判为已接（`\bsteps\s*:` 把 `.prop` 后的三元冒号也当对象键）。修法：键型证据统一加 `(^|[^.\w'"])` 守卫。
3. **实现侧统一挂载的字段，证据要认实现函数**：`autoReport`/`resave` 由 `withReport()` 统一挂——裸词对账漏掉 deliver（恰是文档没记的那处）。证据正则须写 `(\bautoReport\b|withReport\s*\()`。
4. **vue-tsc 对类型字段的把关是真实的**：caps 表加了 `rawText` 但接口漏声明，regression 全绿而 vue-tsc 红——两套门禁互补的又一次实证。
5. **node 不认 Git Bash 的 `/d/...` 路径**：`--out=/d/...` 落盘直接 ENOENT 退出 1；传 Windows 形式 `D:/...`。
