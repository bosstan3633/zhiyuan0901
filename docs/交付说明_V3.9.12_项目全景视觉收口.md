## 一、本轮交付

### 1. 项目全景的视觉层级收口

- 项目切换从一排常驻项目卡收成一个紧凑切换器；当前项目名只在摘要中出现一次。
- 「下一步」成为摘要主句，进度、完成数与主行动并排；导入模板、AI 建议指标、AI 诊断收进「⋯」。
- 第 4 / 5 / 6 层层级从属降为摘要脚注，不再独占第二块水平带。
- 无归属任务收容道改用独立 `lane-orphan` 命名空间，不再复用 `.lane` 影响子泳道宽度。

### 2. 横向泳道宽度与密度

- 单指标时泳道铺到 **920px**，不再停在左侧约六成宽度；多指标仍保持可横向滚动的泳道列。
- 泳道区取消固定 320px 空底，高度随任务量收缩；任务由嵌套小卡退成行式，保留指标主色轨、连接轨与状态。
- 任务完成框、更多、删除、等级与详情等交互热区保持至少 28px。

### 3. 页首与双导航收口

- 项目全景下页头动作与读数并排；战略骨架隐藏重复说明徽标与零断链行。
- 四主题实测页首两层（页头 + 战略骨架）高度由约 250px 压到 **155px**。
- 项目全景不显示项目塔左栏，避免两套项目导航同时出现；回项目塔仍由摘要动作区的明确出口承担。

### 4. 验收场景与回归

- `theme-audit.cjs` 新增 `compass-pano` 场景，四主题均验证：
  - 项目切换器、当前项目、摘要、下一步在位；
  - 单泳道宽 920px；
  - 页首两层高度 ≤250px（实测 155px）；
  - 最小热区 ≥28px；
  - 页面横向溢出 0px。
- 静态回归继续守换主体、回项目塔、任务详情、指标详情、加任务、挂指标与删除指标的两跳接线。

## 四、边界与遗留

- **项目全景的第一轮视觉收口已完成**，但不宣称“所有信息都已最优”：多项目、多指标、长任务标题下的横向滚动与列宽分配仍需真实夹具持续验证。

## 五、UI 设计层面的优化方案

### 1. 视觉层级：每个信息只保留一个“发声点”

- 项目名只在摘要出现一次；切换器只表达“换主体”，不重复项目名。
- 下一步是摘要唯一的主句；进度与动作是次句；第 4 / 5 / 6 层只做脚注。
- 低频动作统一进「⋯」，常驻只留项目切换、回项目塔、＋指标与更多。

### 2. 容器纪律：用线和留白分组，不用层层套框

- 每加一层容器，优先检查能否用发丝线、主色轨、缩进与留白替代边框、底色与阴影。
- 泳道只保留一条外边界；指标头、任务行与收容道不再各自叠卡。
- 单泳道铺开，多泳道横向滚动；不为“填满宽度”把任务行拉成超长文本。

### 3. 颜色纪律：一项目一主色轨，状态色只表达状态

- 每个项目一条主色轨；指标进度、连接轨与任务分支点复用同一色。
- 成熟度等级只做小徽标；完成 / 进行中 / 风险只做状态色，不把等级色涂到标题。
- 暗色与亮色主题都用同一套语义层级，不用“换主题就改布局”掩盖信息问题。

### 4. 动效纪律：只给空间关系变化

- 项目塔 ↔ 项目全景切换保留轻量淡入与 8px 上浮，说明“同一份数据的第二种投影”。
- 抽屉与菜单只用短时进入 / 退出；不做与阅读无关的漂浮、弹跳或持续呼吸。
- `prefers-reduced-motion` 下彻底取消位移，而不是缩短成看不见的动画。

### 5. 下一阶段方向台的 UI 优化顺序

1. **多项目 / 多指标真实夹具**：验证 3–6 根泳道的列宽、横向滚动与任务标题换行，避免只在单泳道样本上过绿。
2. **项目塔与项目全景共用同一把视觉尺子**：项目摘要、指标头、任务行三级的字号、行距、热区和颜色口径继续对齐。
3. **全站键盘与读屏**：把项目全景已使用的原生按钮、焦点环与 Esc 边界推广到其余可点击元素。
4. **页首读数继续减法**：只保留“现在要判断的”，其余计数按需展开，避免全局读数再次压过项目摘要。
5. **长任务与大项目密度档**：为 20+ 任务、10+ 指标提供紧凑 / 标准两档，不靠无限滚动解决。
