## 三、BUG-1 根因与修复（重点）

**复现路径**（真机 E2E，playwright-core + MV3 dist）：
`全域任务管理 → ＋新建任务 → 标题 fill"复现标题ABC-9527" → Ctrl+Enter → 断言列表首条`
→ 修复前列表首条 = **"新任务"**（保存不更新）；修复后 = **"复现标题ABC-9527"** ✓

**根因**：`createNewTask()` 先构造普通对象 `task` 再 `d.value.tasks.unshift(task)`，随后
`openTaskSidebar(task)` 把**原始对象**赋给 `selectedTask`（ref 持原对象，**非 store reactive Proxy**）。
`saveTaskTitle()` 执行 `selectedTask.value.title = val` 直接改原对象属性——**绕过 Proxy 的 `set` trap → 不触发 `trigger` → 模板 v-for 不响应更新**。
数据其实已随 `store.persist()` 入库（persist 序列化时经 Proxy 读到新值），所以**第二次从列表点开（此时 v-for 项是 Proxy）再保存就"正常"**——与用户描述的"二次编辑才展示"完全吻合。

**修复**（`CompassActions.vue`，R43-9 防回归）：
1. `openTaskSidebar`：`selectedTask.value = d.value.tasks.find(x => x.id === task.id) || task`（取 store Proxy 引用，抽屉内一切赋值走响应式）
2. `saveTaskTitle` 兜底：先 `find` store 内元素再写入，`selectedTask.value` 同步指向它

## 四、技术要点

### 4.1 BUG-2 双复选框（最小侵入修复）
- 根因：`batchMode` 时任务行同时渲染 `batch-check`（批量勾选）与 `check-sm`（状态切换）。
- 修复：`mgr-body` 容器绑定 `:class="{batch: batchMode}"`，CSS `.mgr-body.batch .check-sm { display:none }` —— **模板零改动、看板不受影响**。

### 4.2 任务中心迭代
- **R-1 删除**：三处任务行（分组/置顶/普通）`t-del` 按钮，样式仿 `t-pin`/`t-star`（opacity 0 → hover 显现），悬停变红警示；点击 `deleteTask`（软删 → 回收站可恢复）。
- **R-2 总数**：`totalTaskCount = 未删除任务总数`（不随筛选变）+ `clearTaskFilter()` 清 filterBy/searchQuery。

### 4.3 北极星指标迭代（`compass.ts` + `NorthStarPanel.vue`）
- **R-4 未归档 N/M**：`{{ unarchivedTasks.length }}/{{ totalTasks }}`（如 3/128），抽屉行为保留。
- **R-5 严格周期联动**：
  - **DHI**："在轨"活跃窗口随周期：周=近 14 天（沿用历史口径）/ 月=近 30 天 / 累计=全部（`dhiDays`）
  - **WCE**：副标 `本周+7 / 本月+N / 累计+N`（累计档原无数字，本轮补齐）
  - **WRR**：副标 周=`本周N次`（`stats.wrr.thisWeekUsage`）；月/累计=`累计N次`（`stats.wrr.totalCumulativeUsage`）
  - **不分期标注**：模块分组/链接卡片 `全量 · 不分期`，未归档 `未挂指标 · 不分期`
- ⚠️ **数据模型限制**：打开次数仅有「累计(callCount) + 本周(lastVisits，跨周重置)」，**无月级历史** → 月档暂以累计口径呈现，月独立统计需模型扩展（建议后续 V2.19 采集 monthlyUsage）。
