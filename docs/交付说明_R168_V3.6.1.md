# 交付说明 · R168 · V3.6.1

**主题**：性能全面盘点（重点：工作台切换 / 全局检索）→ 三刀落地
**量具**：新增 `v2/scripts/perf-census.cjs`（DOM 账 + 逐动作长任务账），与既有 `perf.cjs --real`（真实路径耗时）互补
**数据**：真库 = `zhiyuan_backup_2026-09-21.json`（资源 380 · 任务 74 · 好奇 27 · 台 50 · 分类 234）

---

## 一、先立口径：为什么这轮的结论不看"耗时中位数"

R167 在同一台机器上连采三批 A/B，散布 2.81×~5.28×，慢样本在新旧两侧随机出现 ⇒ **本机当下的 ms 不适合当判据**。
所以这轮的盘点表按两个**不受 CPU 噪声影响**的量来下结论：

1. **DOM 节点账**（一次动作插入多少节点）；
2. **长任务清单**（PerformanceObserver 抓到几个、各多少 ms）。

配套新规已写进 06-2 §B：**散布 >2 且重采两次仍 >2 ⇒ 改用「同批最小值」，并只把结构量按字面读**。
★ 踩坑一并记账：census 第一版把长任务观察器装在动作**之后**，于是报"无长任务"——那是探针的错，不是应用的。
现在观察器在动作之前装好，脚本注释里留了这条反面教材。

## 二、盘点结论（V3.6.0 原状，真库逐项实测）

| 动作 | 阻塞合计 | DOM 增量 | 判定 |
|---|---|---|---|
| **切到看板视图** | **488ms**（146/82/198/62） | **+3520 节点** · svg 169 | ★全站最慢的一次交互 |
| 冷挂资源台（卡片首屏 32 卡） | 283ms（193/90） | +774 节点（**卡片自身 688**） | 次高 |
| 再进同一台（keep-alive） | 58ms | +770 节点（DOM 重新插入） | keep-alive 已生效，收益有限 |
| 冷挂策展台（空台） | 56ms | −970 节点 | 正常 |
| 单击卡片开详情 | 0ms | +4 节点 | **即时——代价是抽屉常驻** |
| 全局检索唤起 / 键入 6 字 | 0ms（R7 27ms / 20ms） | — | **不是瓶颈，本轮不动**（见 §四） |

三条根因（都落到具体代码，不是"感觉慢"）：

1. **看板的"增量渲染"名存实亡**：`KANBAN_COL_STEP = 20`，而资源台有 33 个分类列 ⇒ `20 × 33 = 660 ≥ 全量 380 卡`，
   等于整台卡一次挂满。原来那句注释只写了"每列初始 20 张"，没人把它和列数相乘。
2. **常驻浮层**：`Workspace.vue` 的内联资源抽屉开着与否都在 DOM 里（**168 节点，其中 88 个是分类下拉的 `<option>`**），
   加上 8 副 modal 壳共 163 节点 ⇒ 每次进台面白摊 ~331 节点；抽屉还是 `transform: translateX(100%)` 移出视口，
   **布局照算**，不是真省。
3. **AI 徽标每枚一整棵形状树**：`ZhiMark` 每次渲染 = 1 个 `<svg>` + 6 个形状 = **7 个节点**；
   资源台首屏 32 张卡各一枚 ⇒ 光徽标 224 节点，约占该次挂载增量（774）的 **29%**。

## 三、三刀落地（V3.6.1）

| # | 改动 | 落点 | 效果（真库实测，同一量具） |
|---|---|---|---|
| ① | 看板首屏每列 **20 → 6 张**（滚动/「显示更多 N 张」机制一字未改，不新增代码路径；`count` 仍恒为全量长度） | `useResourceView.ts` | 看板 DOM 增量 **+3520 → +1937**（−45%）· svg 169 → 106 |
| ② | 九副浮层全部 **`v-if` 化**（点开才挂、关掉即卸）；抽屉进出场改走 `<Transition name="dr">` + `prefers-reduced-motion` | `Workspace.vue` · `workspace.css` | 常驻抽屉/modal **→ 0 节点**；资源台首屏 option **178 → 24** |
| ③ | 徽标图形搬进 **`<symbol id="zy-ai-mark">` 全站只挂一次**（App 根），`ZhiMark` 退化为 `<use>` ⇒ **7 节点/枚 → 2** | `ZhiMarkSymbol.vue`（新）· `ZhiMark.vue` · `App.vue` | 卡片内节点 **688 → 528**；资源台首屏总 DOM **1551 → 1059（−32%）** |

**没有变慢的东西**：视觉一字未变（徽标仍是同一套描边/眼睛实心/currentColor，靠外层 svg 的呈现属性继承）；
`prefers-reduced-motion` 下抽屉过渡自动关；看板与抽屉的续载机制未动。

**代价要如实说（并已实测否掉一个假代价）**：抽屉改为"点开才挂"，直觉上会把成本挪到单击那一下——
普查阶段确实记到一个 235ms 长任务落在这一步，我当时把它写成了代价。**受控 A/B 复测：R3 单击开详情
同步 0.5ms、阻塞 0ms**，那 235ms 是上一步（切回卡片视图）没跑完的尾巴串进结算窗口所致（普查的观察器
虽在动作前清空，但每步只等 1.8~3s）。⇒ 真实情况是：成本从"每次进台面都付"变成"只在真点开时付"，
而那一次仍是亚毫秒同步、无长任务。原话留在文档里、结论改在这里，是为了记下"我一度写错了什么"。
若后续仍觉得开详情慢，下一刀是分类下拉（88 个 `<option>`）换成"点开才展开的自绘选择器"。

## 三b、本轮明确不做的事

- **全局检索不再压**：真库实测唤起 33ms / 键入 6 字 42.4ms（V3.6.0 下界），已在无感区间；再动收益 <10ms 且有回归风险。本轮只是"顺带快了"（键入 −46%，来自台面响应式依赖变少），不是专门做的。
- **keep-alive 不加名单**：三主视图 + 设置 + 回收站已在缓存内（`App.vue` 的 `include` 自 R65-F7 起就在），二次进台面的开销是 DOM 重新插入而非重算；再要动就得改路由层，收益/风险不成比例。
- **卡片视图 RENDER_STEP=32 不再降**：降到 24 会让首屏不满一屏（1440×900 下 5 列 × 4 行），滚动即触底反而更烦。

## 四、受控 A/B（V3.6.0 基线 → V3.6.1 · 真库 `--real` · 交错 3 轮 · 取每步最小值）

基线包由 `git worktree add ~/r167-base v3.6.0` + node_modules junction 现建并现场构建，两侧 `manifest.version`
由 perf 自打（3.6.0 / 3.6.1），不靠"我记得我构建过"。

**先说读数前提**：本机散布仍 >2 倍（R1 基线三样本 1723/835/745 = 2.3×，新版 2137/1567/573 = 3.7×），
按 06-2 §B 新规**只用「同批最小值」＝无噪声下界**下结论；ms 的百分比是"下界对下界"，不是统计结论。
结构量（R6 节点账）三轮各自完全相同，可照字面读。

| 指标（3 轮最小值） | B = V3.6.0 | A = V3.6.1 | 变化 |
|---|---|---|---|
| R1 冷启动→首页可交互 | 745.5 ms | **573.5 ms** | **−23.1%** |
| R2 冷挂资源台·主线程阻塞 | 844 ms | **571 ms** | **−32.3%** |
| R2 冷挂资源台·最大单任务 | 568 ms | **402 ms** | **−29.2%** |
| R4 视图切换·卡片 | 103 ms | 91.2 ms | −11.5% |
| R4 视图切换·**看板** | 266 ms | **188 ms** | **−29.3%** |
| R6 真库首屏可见节点 | 1116 | **954** | **−14.5%**（三轮 1116/1116/1116 vs 954/954/954，完全可复现） |
| R7 全局检索·唤起 | 33 ms | 33 ms | 0（本来就不是瓶颈） |
| R7 全局检索·键入 6 字 | 42.4 ms | 22.9 ms | −46% |
| R3 单击开详情·同步 / 阻塞 | 0.2 ms / 0 ms | 0.5 ms / **0 ms** | **无可测代价**（见下） |
| R5 滚动最差帧 | 67 ms | 80 ms | 噪声主导（同批 A 有 297ms 的脏样本），不下结论 |

**"开详情会不会变慢"这条已被实测否掉**：普查阶段曾记到一个 235ms 长任务落在"单击开详情"那一步，
当时我在 §三 里把它写成"代价"。受控 A/B 复测 R3 = 同步 0.5ms / 阻塞 0ms，说明那 235ms 是**上一步
（切回卡片视图）还没跑完的尾巴串进来的**——普查的观察器虽在动作前清空，但结算窗口只有 1.8s。
⇒ 结论修正为：**把成本从"每次进台面"挪到"点开那一次"，而那一次本身仍是亚毫秒级同步 + 无长任务**。
普查脚本已加注释提醒：跨步串场要在解读前先排除。

## 附：本轮新增量具 `v2/scripts/perf-census.cjs`

```
node scripts/perf-census.cjs --real=<知源导出JSON> [--dist=<扩展包>] [--steps=deck,kanban,drawer,search]
```
