## 一、一句话

### 2.3 「导 N」双口径的界面欠账收口（本轮补做）

**欠账的来龙去脉**：手册「新增/导入双口径（V2.21.3 起）」白纸黑字写着「导入的卡单独显示**「导 Y」**并继承原创建时间——不会把导入错记成今天新建」；判据 `R48-5` 也确实钉住了数据层（`todayImportCount` / `weekImportCount`）。但**界面那一半一直挂着**——`changelog-data.ts` 的 V3.8.22 条目里自己写着「已知欠账（登记待接）：今日/本周「导 N」计数仍在数据层，界面徽标尚未接回」。

**为什么不是 bug 而是欠账**：两枚 computed 一直在算，只是**没有任何消费者**。这类东西最容易被当成「已经做了」。

**本轮补法**：徽标挂在**今日段的段头右缘**（`pi-mod-acts`），不在 `strip4` 里——

- 放 `strip4` 会挤掉一格既有读数，并打破「恰四枚读数格」的定版断言（W13-F8 / A2-6「段内语义格恰好 14 处」）；
- 「导 N」本就是「今日入台」这枚读数的**口径拆分**，不是第五个读数。段头是「这枚读数的补充说明」的位置；
- 0 时不渲染（没有导入就别占一格宽度）。

新增判据 `V3.9.6-1` / `V3.9.6-2`（`12-w17-profile.cjs`），后者带**负锚**：不许把 `importedAt >= gStartOfToday` 换成 `createdAt`（换了就等于把导入错记成今天新建，正是手册明文承诺不做的）。

## 三、本轮抓到的真缺陷（工具侧）

### 3.1 E2E-4 守的是一条已被产品废弃的跳页链路

**症状**：全量 E2E **43 通过 / 1 失败**。

**病根**：`E2E-4` 期望「未归档」跳到**任务二级页**并预选状态筛选；而 W17-C01 已把它改成**就地只读明细弹窗**（原地不改路由 / 只读 / Esc 可关 / 焦点回归）。W17 批重指了 **16** 条回归分片，**唯独漏了 E2E**——这条断言不在 16 片里，于是它一直守着一条产品明确废弃的行为。

**修法**：重写为断言新契约（弹窗开 / URL 不变 / 明细行不可点 / Esc 可关 / 焦点回归触发器）。

★**这条值得记的不是「漏了一条断言」，而是「分片制的覆盖边界之外的东西会静默腐烂」**：W17 批重指了 16 片回归，E2E 不在那个集合里，于是它按自己的旧理解活着。⇒ **判据体系的「只增不减」守的是断言条数，守不住「断言守的是当前产品」。**

### 3.2 `theme-audit` 的 `pickData()` 取了**空库**备份

**症状**：实拍判据 44 个 ✗，11 个需要数据前置的场景全部拿到空态。

**病根**：默认备份选择取「Downloads 下按文件名排序的**最后一份** `zhiyuan_backup_*.json`」= `zhiyuan_backup_2026-10-20.json`，实测那份是**空库**（资源 0 / 任务 0 / 好奇 0 / 分类 0）。⇒ 图片数直接少 12 张。

**修法**：改为**按内容挑而非按文件名挑**——遍历所有候选备份，选**数据量最大**的那份（实测 `zhiyuan_backup_2026-10-19.json` 有 386 资源 / 76 任务 / 30 好奇 / 50 工作台 / 245 分类 = 737 条）。

★**与 census 那次是同一族病**：**文件名顺序表达的是时间，数据量表达的是前置是否成立**。判据工具的「自动选数据源」比「手工指定」更危险——它每次都绿，但绿的是上一次的数据。

### 3.3 `theme-audit` 的网页 ⌘K 搜索锚点被空格截断

**症状**：四主题各 4 项 `ov-search` 判据红。

**病根**：旧代码把标题的**去空格**版本再切片（`(2) X 上的…` → `(2)X…`），而内容侧搜索用的是 `blob.includes(kw)` 走**原标题** ⇒ 永远匹配不上。判据自己把自己的锚点改坏了。

**修法**：改用连续的中英文数字段 `[\p{L}\p{N}]{2,}`。

### 3.4 抽屉落位判据被**固定等待**误伤（假红）

**症状**：2026-10-21 全量走查里 `apple/drawer-resource` 报「点了 `.res-card` 但 `.ref-form` 没出现 —— 抽屉没开」。

**病根**：抽屉落位用**固定 1200ms** 等待。慢机日（进场动效 + `onTaskRowClick` 260ms 单击去抖 + 首帧懒挂载）不够，于是判红。但同一镜头随后 `resetView` 复读时是开着的、截图也对（`开=是`）——**抽屉确实开了，只是时钟不够**。

**修法**：改成**轮询等真终态**（最多 6s，每 150ms 轮询一次 `.open` 可见性）。真没开还是判红（终态仍由 `opened` 决定），只是不再被机器的快慢误伤。

★**这与 R170 备案的「等不够就判死」是同一族病**：固定等待 = 拿机器的快慢当判据。
