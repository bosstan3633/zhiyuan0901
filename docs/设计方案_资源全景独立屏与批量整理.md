> 第卌四轮 · 2026-09-03 · 状态：**待拍板，未动工**
> 修订动因：谭老板指出仪表盘首屏过载、树状三级占空间不协调；真实需求 = **一目了然的全景 + 批量选中卡片跨工作台/分类拖拽移动**。
> 本篇**替代**《需求盘点与开发清单_第卌四轮.md》中的 F2.4（知源全景树状三级），其余功能点不变。

## 0. 设计判断（回应"你觉得呢？"）

你的直觉是对的，两个问题都成立：

1. **仪表盘首屏塞不下全景**。仪表盘的职责是"看状态"（指标+记录），全景的职责是"做整理"（浏览+移动），两种心智任务混在一屏必然臃肿。**拆开是正确方向**：仪表盘 = 默认第一屏，资源全景 = 第二屏。
2. **树状三级不适合批量移动**。树状展开是"阅读型"布局，层级深、行距密，拖拽跨越折叠层级的命中率差、占屏高度失控。批量整理的正确形态是**双栏（Master-Detail）**——邮件客户端、Finder 列视图、后台管理验证了几十年的成熟模式。

### 交互设计（扁平化操作核心）

- **左栏 = 全景计数树**：工作台（卡数）→ 分类（卡数），一级可折叠。**默认全收起，只看数字**——这就是"一目了然有多少工作台、每分类多少卡"；不需要逐卡展示时屏幕永远清爽。
- **右栏 = 当前分类的卡片列表**：复选框 + 标题 + 类型图标 + 🔥打开次数；顶部面包屑（工作台/分类）+「全选本分类」。
- **批量移动两条路**（都给，拖拽为主）：
  1. **拖拽**：选中若干行 → 拖到左栏任意分类节点（高亮虚线"投放至此"）→ 松手完成跨工作台/分类移动；
  2. **按钮兜底**：「移动到 ▾」下拉（工作台 → 分类两级菜单），不习惯拖拽时用。
- **单击详情 / 双击打开**：沿用全产品统一卡片交互。
- **移动 = 改 `workspaceId`+`categoryId`**（+updatedAt），零新数据模型；移动后左栏计数即时刷新；跨工作台移动若有挂载/归档关系只挪卡片本身，不动任务挂载（单向挂载红线不受影响）。
- 复用 V2.18.1 已有的批量多选基建（batchMode 复选框），本次只加"跨分类移动"动作与 DnD 投放。

### 为什么这是最优解（设计规范角度）

- **一屏一主题**（产品既有规范）：仪表盘管状态、资源全景管整理，互不挤压。
- **Master-Detail 是管理页原生形态**：设置页里回收站、字段管理都是"左导航+右内容"心智，资源全景融入自然，风格协调。
- **操作路径最扁**：现状跨工作台移动一张卡 = 进工作台A → 找卡 → 剪切/重录 → 进工作台B → 粘贴（5+ 步）；新方案 = 勾选 → 拖放（2 步），且支持 N 张并行动。

## 2. 备选方案（供对比）

### 方案 B：独立全屏路由 `/panorama`（像回收站，不进设置页）

- 同样的双栏，但独占整屏，空间最大，可加搜索/筛选/排序复杂功能。
- 入口：仪表盘"总卡片"卡下钻 + 首页顶部。
- 优点：沉浸、未来扩展空间大；缺点：多一层入口跳转，且"整理"属于低频管理动作，放设置页语义更贴。

### 方案 C：看板式（分类为列，跨列拖拽）

- Trello 心智，拖拽最直觉；但 19 个分类横向滚动很长、批量多选跨列拖拽手重、纵向空间浪费，不推荐作为主方案。

## 3. 仪表盘首屏同步瘦身

知源全景撤出后，仪表盘（默认首屏）最终为：

1. 核心指标 5 卡（总卡片/资源/任务/好奇/链接卡片）
2. 动态条（今日 +N/−N · 本周 · 累计删除）
3. 操作记录时间线（三维筛选）
4. CSV 按筛选导出

版块数从 6 → 4，首屏恢复协调；"总卡片"卡下钻直达资源全景第二屏。

## 6. V3.1 补充（用户追问两点：设置页整体布局 + 工作台内批量移动去留）

### 6.1 设置页导航重组：3 组 12 项 → 5 组 14 项（一项不减）

现状（截图核实）：`卡片字段(3) / 数据管理(4) / 其他(5)`。加入仪表盘与资源全景后，重组为五组，语义边界对齐"这块管什么"：

| 组 | 项 | 说明 |
|---|---|---|
| **总览** | 📊 知源仪表盘 | **默认首屏**（进入设置即达，导航第一位） |
| **整理** | 🗺 资源全景 | 第二屏，双栏批量整理 |
| **卡片与字段** | 📇 资源卡 / ✅ 任务卡 / 💡 好奇心卡 / 🏷 标签管理 | **标签管理从"数据管理"上移**——它服务卡片呈现，与三卡同组 |
| **数据** | ⬇ 导入数据 / ⬆ 导出数据 / 🔄 重置与回滚 | 纯数据进出与兜底（仪表盘内 CSV 导出为快捷入口，此处保留完整导出） |
| **系统** | 🔌 扩展设置 / ⌨ 快捷键设置 / 📖 使用手册 / ✉️ 一封信 / ℹ 关于 | 不动 |

要点：①高频动线（看状态→做整理）置顶两屏；②12 项原功能一项不删，仅重排分组；③实现成本 ≈0.25 天（纯 navGroups 数组 + dashboard/panorama 两个新 key）。

### 6.2 工作台内批量移动：**保留**（推荐）

| 维度 | 分析 |
|---|---|
| 心智场景不同 | 工作台内 = **顺手归位**：浏览/采集时发现错位卡，就地勾选移到同工作台其它分类，几秒完成；全景 = **专项大盘整理**：跨工作台批量挪移。高频微调不应被迫跳设置页 |
| 成本为零 | V2.18.1 batchMode 多选基建与全景共享同一套代码，保留无额外维护成本，删除反而要花工时拆 |
| 交互统一 | 两处均为「勾选 → 移动到▾」同一模式，认知一致；全景多出拖拽通道与跨工作台范围 |

**备选 B（不推荐）**：移除工作台内批量移动只留全景——省一处 UI，损顺手整理动线，且删除也要花工时。

**可选增强（+0.25 天，可不做）**：工作台批量条加「在资源全景中打开」入口，跳转全景并自动定位当前工作台/分类，两处动线闭环。

总工作量 ≈6 → **6.25 天**（导航重组 +0.25；保留批量移动 ±0）。

## 7. V3.2 线框图定稿（2026-09-03 深夜，用户拍板命名与范围）

**命名与范围修正**：总览组两项 = **知源仪表盘**（默认首屏）+ **工作台全景**（第二屏）。原「资源全景」更名「**工作台全景**」——它只呈现**资源工作台**（自定义工作台，如 JS工作/教育资讯/内容工程/工具库），**不含知源罗盘、知源引擎**。

### 7.1 知源仪表盘（默认首屏）三段式

1. **核心指标 5 卡**：总卡片 628（含今日 +N 小标）/ 📇资源 / ✅任务 / 💡好奇 / 🔗链接卡片（跨全部工作台口径）；各卡点击下钻明细抽屉。
2. **动态条**：今日 +5/−2 · 本周 +23/−6 · 累计删除 41 ＋ 右侧「⬇ 导出 CSV（按筛选）」按钮——这是"操作是否保存了"的即时确认器。
3. **操作记录时间线**：类型（全部/资源/任务/好奇）× 动作（全部/新增/删除）× 时间范围 三维筛选；每行 = 时间 + 增/删徽标 + 类型 + 标题 + 详情▸，点击行展开（归属/链接/标签/附件/摘要）；含恢复与永久删除事件（事件日志）；分页滚动，日志 5000 条滚动淘汰。

### 7.2 工作台全景（第二屏）双栏 Master-Detail

- **左栏 · 全景计数树**（宽 ~210px）：工作台（卡数）→ 分类（卡数），**默认全收起**只看数字；当前分类蓝色高亮；**拖拽悬停目标绿色虚线高亮**。
- **右栏 · 卡片列表**：面包屑「教育资讯 / 政策解读 · 38 张」＋ ☐全选本分类 ＋「移动到▾」；行 = 复选框 + 标题 + 来源/日期副标；滚动加载。
- **批量操作条**（勾选后浮现）：「已选 N 张 · 移动到▾ · 取消」，随选随显。
- **双通道**：①拖拽——勾选后拖到左栏目标分类，虚线高亮松手即移动（跨工作台=改 workspaceId/categoryId，零新模型）；②按钮——「移动到▾」工作台/分类级联下拉兜底。
- 单击详情 / 双击打开，与全产品交互统一。
