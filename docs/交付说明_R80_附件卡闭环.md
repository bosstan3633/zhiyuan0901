## 一、问题：本地文件导入在造"哑卡"

```ts
// 改前（Workspace.vue:2445）
files.forEach(f => d.value.resources.unshift(
  makeHubResource(f.name.replace(/\.[^.]+$/, ''), 'file', f.name, catId)))
//                                                        ↑ 只存文件名，没有本体、没有附件
```

「报告.pdf」被当成链接存进卡里。`toOpenableUrl('file', '报告.pdf')` 因为不是完整路径**直接返回空**，双击只得到一句「未设置链接」。

**用户既打不开，也修不好**——他不知道"补全完整路径"是什么意思，更不知道该补成什么样。这是 04-18 §261 原文描述的哑卡：卡片上无标记、无筛选器，导入 50 个文件得到 50 张废卡。

同时 `handleFileImport` 的注释里明写着「R13 将改写为『每文件一张带附件的卡』，此处先保持迁移前口径」——这笔债从 R73 迁移时挂到现在。

## 三、交付内容

### 3.1 R13 · 每文件一张带附件的卡

```
输入：用户多选文件
对每个文件 f：
  1. kind = guessAssetKind(f.name, f.type)
  2. kind === null            → skipped[]，不建卡
  3. 体积 > ASSET_KIND_MB[kind] → skipped[]，不建卡
  4. putAsset(id, f) 失败      → skipped[]，不建卡
  5. 否则 → 建卡（每卡 assets 恰 1 项）
建卡字段：
  title      = stripExt(f.name)
  linkType   = 'file'
  link       = 'zy-asset://<assetId>'
  assets     = [meta]
  categoryId = newCardCatId()      // 聚合/待分类视图回落 ''（R73-S4a 口径）
收尾：
  ✓ 已导入 N 个文件（共 X MB）
  ⚠ 已跳过 M 个不支持的文件：a.zip、b.docx…   ← 仅 M>0 时出现（最多列 3 个）
```

- **图片 / HTML / PDF 一律一文件一卡**（Q10 拍板）。「多图一卡」作为**能力**保留（详情里可追加至 ≤9 张），**不改变导入语义**。
- `<input>` 的 `accept` 由裸 `multiple` 补为 `image/*,.png,…,.html,.htm,.pdf,application/pdf,text/html`——选文件时就能筛掉不支持的，不用等导入后才被告知。

### 3.2 类型判定抽为共享工具（关键决策）

`guessKind` 原本是 `AssetManager.vue` 的**局部函数**。导入侧要用同一套判定，若在 `Workspace.vue` 再写一份，两处口径必然漂移（一个认 `.jpeg` 一个不认）。

⇒ 抽出 **`shared/utils/assetKind.ts`**：

| 导出 | 用途 |
|---|---|
| `guessAssetKind(name, mime)` | 类型判定（mime 优先，扩展名兜底） |
| `ASSET_KIND_MB` | 体积上限 `{ image: 10, html: 20, pdf: 100 }` |
| `assetMimeOf(kind, fallback)` | mime 兜底 |
| `stripExt(name)` | 去扩展名（建卡标题） |

`AssetManager` 改为 `import` + `const guessKind = guessAssetKind`（局部名不变，其余代码零改动）；`IMG_MAX_MB` / `PDF_MAX_MB` 改由 `ASSET_KIND_MB` 供值（**数值不变**：10 / 100）。

**判定只有一份实现。**

### 3.3 R14 收尾 · 图片附件卡就地预览

```ts
if (!meta)                                   { showToast('⚠ 卡片指向的附件不存在或已失效，请重新上传'); return }
if (meta.kind === 'image')                   { void openImageAsset(meta); return }   // ← 新增
if (meta.kind === 'html' || meta.kind === 'pdf') { openHtmlAsset(meta); return }
```

`openImageAsset`：`getAssetBlob` → `URL.createObjectURL` → `AssetPreview` 单图模式弹窗（`:open/:url/:name/@close`）；blob URL 在下次打开前 revoke（与 `AssetBadge` 同款写法，不泄漏）。

### 3.4 R1 遗留 · 资源卡标签默认可见

- `defaults.ts`：`resource` 组 `tags.visible: false` → **`true`**
- `repository.ts`：**一次性幂等迁移**（新标记 `AppData.tagsVisibleMigratedAt`）——老数据启动时把 `resource` 组 tags 置为可见，只跑一次

**只改 resource 组**（R1 的落点是资源卡；task / curiosity / thesis 组维持原状）。

⚠ **取舍**：若用户此前**主动**关掉过标签，本次会被重新打开。判断依据——R1 是 P0 且标签是资源卡核心元数据，"不知道能开"的概率远高于"主动关掉"。**回退只需在设置里再关一次**。
