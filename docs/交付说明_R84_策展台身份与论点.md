## 一、问题：你在哪个台？这个台想说什么？——两件事页面上都答不上来

策展台（含资源台）此前的首屏长这样：

```
┌──────────────────────────────────────────────────┐
│ ▦ 卡片  ☰ 列表  ▤ 看板  ⬡ 金字塔    排序 ▾  …      │  ← 直接就是工具条
├──────────────────────────────────────────────────┤
│ 指标条：🏛 论点 · 卡 12 · 镜像 3 · …                │  ← 论点挤在第一格里
│ 📁 分类一                                          │
│   ┌────┐ ┌────┐ ┌────┐                            │
│   │ 卡 │ │ 卡 │ │ 卡 │                            │
└──────────────────────────────────────────────────┘
```

**两个"我是谁"的问题，页面一个都没回答：**

1. **这是哪个台？** `workspace.name` 与 `workspace.desc` 在模板里**零出现**（`name` 仅在导出文件名里用了一次）。用户侧栏点了"读书笔记"进来，整个页面没有任何一处告诉他"你在读书笔记"。**资源台有一段 R73 补的、写死的页头；策展台连那段都没有。**
2. **这个台想说什么？** 中心论点只出现在**指标条第一格**（一个 10px 的小格）和**金字塔 L1 根节点**。而默认视图是**卡片视图** ⇒ **绝大多数时候，论点等于不存在**。

W2 ② 还藏着第三个事实：`viewMode = ref('card')` 是**纯内存**的，切个台、重开一次就回卡片。原文写的"用户切过视图后记忆其选择"**从来就没实现过**。

W1 与 W2 落在同一个文件、同一条纵向动线（页头 → 论点 → 视图），故**合成一轮**改完。

### 2.2 两个必须知道的前置事实

**① `UIPrefs.viewMode` 是个死字段，不能复用。**
`models/index.ts:419` 声明了 `viewMode: 'list'|'kanban'|'card'`，`repository.ts:407` 给了默认值 `'card'`，但**全代码库零读取、零写入**。而且它是**全局**的（不按台），类型里也**没有 `'pyramid'`**。
⇒ 本轮另建 `UIPrefs.wsViewMode?: Record<string, …>`（**按台 id 记忆**，与 `cardCols` 同构），**死字段一行未动**（动了会打乱未来可能的清理，且两者语义不同）。

**② 金字塔页签对所有台可见**（`:100` 无 `v-if`），资源台也能进金字塔。
⇒ W2 ② 的规则对 hub 与策展台**一视同仁**：无偏好时 `thesisCard ? 'pyramid' : 'card'`。

### 2.3 一处未拍板、由任务书定的取舍（W1）

**资源台那段写死的文案怎么办？** 若统一走 `workspace.desc`，而资源台的 `desc` 通常为空 ⇒ 按"描述为空不占位"就会**丢掉**「资源卡唯一存储 · 镜像源头」这句教学文案（那是 R16 收敛时特意补的）。

**定：hub 且描述为空时，回落 R73 原文案。** 普通策展台"为空不占位"严格生效；资源台回落保住教学信息，**零信息损失**；右端摘要 hub 时追加「· 可镜像到策展台」，同样保住原 hub-hint。

### W1 · 台身份页头（一行 ≤40px，所有台都渲染）

- **图标** `workspace.icon`；为空则回落 `📦`（资源台）/ `🗂`（策展台）——**不给空位**；
- **台名** `workspace.name`，**19px**：沿用 R51-F11「页头标题统一放大」的既有规范（三个主页面 + 项目详情 / 方向树 crumb 同款），不另起字号；
- **描述** `workspace.desc`，单行省略，`title` 挂全文兜底；**为空则不占位**（`v-if` 而非三元，避免渲染一个空 `·`）；hub 为空时回落 R73 文案；
- **右端结构摘要** `N 个分类`，hub 追加「· 可镜像到策展台」，策展台有镜像时追加「· 镜像 N 条」；
- 高度：原 `.ws-hub-head` 是 `padding: 18px 0 14px`（约 **60px**），现 `min-height: 34px; max-height: 40px; padding: 6px 0 8px` ⇒ 实测 **37px**（19px 行高 ≈23px + padding 14px）。**资源台让出约 23px，策展台新增一行换来台名/描述首次可见。**

> ⚠ 字段名是 **`desc`**，不是 `description`——第一轮按 `description` 写会直接 `TS2339`。

### W2 ① · 论点横幅（卡片视图顶部，两态）

- **已设立** → `🏛 [中心论点] <标题>` + 右端「查看金字塔 →」（切金字塔视图）；点标题直接打开论点卡详情；
- **未设立** → 一行**轻引导**：「尚未设立中心论点 —— 右键台内卡片可设立（设立后即成为金字塔 L1 根）」。灰底、无按钮、不弹窗；
- **只在卡片视图出现**（`v-if="viewMode==='card'"`）——金字塔视图本身 L1 根就是论点，**不重复**。

### W2 ② · 视图偏好按台持久化

新增 `shared/utils/wsView.ts`，**与 `cardCols.ts` 完全同构**（读 / 写 / 归一 / 导入 sanitize）：

```ts
export const WS_VIEW_MODES = ['card', 'list', 'kanban', 'pyramid'] as const
export type WsViewMode = typeof WS_VIEW_MODES[number]
export function readWsView(ui: UIPrefs | undefined | null, wsId: string): WsViewMode | null
export function writeWsView(ui: UIPrefs | undefined | null, wsId: string, mode: WsViewMode): void
export function sanitizeWsView(raw: unknown): Record<string, WsViewMode>
```

- `UIPrefs.wsViewMode?: Record<string, WsViewMode>`，**按台 id** 存（与 `cardCols` / `sortPrefs` / `taHeights` 同为 `zy_ui_v2` 界面偏好，不进主数据）；
- **初始化优先级**：① 该台已存偏好 → 用它；② 无偏好 → `thesisCard ? 'pyramid' : 'card'`；
- **切视图即写偏好**，同步更新内存态 `ui` 对象（`cardCols` 同款处理，避免读回旧值）；
- **切台时重算**：`watch(workspaceId, () => nextTick(applyWsView))`——A 台的金字塔不会串到 B 台；
- `sanitizeWsView` 供全量导入使用（`GlobalSettings.vue`），只认四个白名单值，其余丢弃。

**⚠ 行为变更，已评估**：仅影响"从未切过视图 **且** 已设立论点"的台。旧用户升级后 `wsViewMode` 为空 ⇒ 有论点的台首屏变金字塔；用户一旦手动切过，偏好即生效，**不会再被自动切走**。

## 附：本轮的两条经验

1. **字段名以模型为准，不以直觉为准。** `workspace.description` 看起来天经地义，实际模型里是 **`desc`**。改数据结构相关代码前先 `Read` 模型定义，比事后等 `TS2339` 便宜。
2. **起新字号前先查既有规范。** R51-F11 早就把"页头标题统一 19px"写成了规范（且三个主页面都在用），本轮却自作主张起了 14.5px。**断言能拦住，但更好的做法是先 grep 一遍同类元素。** 已记进技能 §五。
