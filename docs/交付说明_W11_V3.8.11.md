## 四、判断口径的三处修正（判据改了，但守的行为没变）

### 4.1 收敛类判据不能钉「全文件唯一触发点」

R3-B′ 原口径「设主攻/添加指标/进详情/删除各自全文件只剩一处触发点」。W11 按原型给卡头加了 `＋指标` 快捷钮与零指标空态引导，全文件计数直接红。

**收窄为**「`.tw-menu` 块内每项恰好一处 + 父组件 `@监听` 恰好一处」。收敛的本意是**同一动作不许两条路**，语境性出口（常驻快捷 / 空态引导）与菜单项语义不同，不算重复。`pin` 本就有意双路（卡头钮 + 菜单），判据改为切到菜单块内再计数。

### 4.2 负锚要钉作用域，不能钉字符串

- R57-9 负锚 `repeat(3, 1fr)` 全站扫 → 误伤 `CompassSpine` 的六层三列网格与看板 `.kanban-board`；收窄到 `CT_W11` 才对。
- R59-3 负锚 `is-focused` 撞上我自己写的注释；`codeOnly` 不剥 `/* */` 块注释。

### 4.3 判据锚局部变量名 = 给自己埋漂移

R91-5 原锚 `query: { p: proj.id, from: 'tree' }`，改接线后形参成 `pid` 就红。改为正则 `p: [\w.]+, from: 'tree'` —— **锚路由与语义值，不锚变量名**。

## 十一、第二批追出的三条真问题（本轮最值钱）

### ① 「门禁缓存存 tail」让判据静默恒红 —— 一条从没人怀疑过的故障模式
`R4-Ev①`（死 CSS 棘轮）红了两轮，我一直判为"环境缺口"。真因：`regression-eb.cjs` 的 `.gate-cache.json` **只存 stdout 末 3 行**，而该判据要 `JSON.parse(--json 全文)` ⇒ 永远失败 ⇒ 恒红。
**处置**：GATES 项加 `{full: true}` 标志位，该门禁全文入缓存。
**这类故障不抛异常，只表现成"某条判据一直红"，最容易被归因成环境问题。**

### ② 一条判据可能从来没真正执行过
`once("deleteNode\\('proj'", t)` 的 `\(` 转义丢失 → 正则未闭合分组 → `new RegExp` 抛异常。它前面只要有子句为 false 就永远不触发，**这条"守删除入口收敛"的判据自诞生起就是装饰品**。
暴露它的是我改判据时让某个前段子句顺序变了。
**处置**：修正为 `deleteNode\\('proj\\'`。**规则：改判据后要把该 check 的 fn 单独取出来执行一次，不能只看整片红绿。**

### ③ 负锚被自己的纪律注释命中
W11-11 负锚"六组件不得出现 `font-size: var(--fs-display)`"红 —— 因为六个组件头部都写着「★全组件不得出现 font-size: var(--fs-display)」这句纪律注释，它自己含被判定的字面量。
**处置**：负锚走 `codeOnly()` + 改钉"用法"（`var(--fs-hero)` 在注释里是裸词不命中）+ "tokens.css 里没有 `--fs-hero` 定义"双保险。
