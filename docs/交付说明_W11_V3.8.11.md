## 三、★★ 追出来的四处能力真丢（不是判据问题，是实现问题）

红判据里混着两类问题，分界线是：**模板里还有没有调用点**。以下四处改了实现、没动判据：

| 能力 | 判据 | 现象 | 处置 |
|---|---|---|---|
| 任务行 ✕ 解绑 | R141-1 | `unbindTask` 函数在，`CompassLane` 无挂载点 | 补 `.tk-unbind` 钮 + 两层 emit 透传（hover 才显形，误触成本高） |
| 指标级 ＋加任务 | R32-14 / R33-13b | 只在 `orphanMetric` 分支有，断链之外无常规出口 | 补 `.mc-add` 常驻钮 |
| 任务层 AI 入口 | R135-4 六入口之一 | Lane 里完全没有 | 补 `.mc-ai` ✦ 钮 → `aiChain('tasks', mid)` |
| 进项目详情**页** | R54-5 / R91-5 | 改写菜单时换成了 `openPano`（抽屉）＝**能力降级**（详情页有面包屑/头部加任务/⋯菜单） | 补 `gotoDetail` emit → `router.push('/compass/projects', { p, from: 'tree' })` |

**另有一处语义错配**：`@edit-title="emit('addMetric', proj.id)"` ⇒ 点指标名会**新建指标**而不是改名。改为与树内 `contenteditable` 同源的就地改名三件套（`editTitle / saveTitle / cancelTitle`），四层节点改名手感一致。

## 四、判断口径的三处修正（判据改了，但守的行为没变）

### 4.1 收敛类判据不能钉「全文件唯一触发点」

R3-B′ 原口径「设主攻/添加指标/进详情/删除各自全文件只剩一处触发点」。W11 按原型给卡头加了 `＋指标` 快捷钮与零指标空态引导，全文件计数直接红。

**收窄为**「`.tw-menu` 块内每项恰好一处 + 父组件 `@监听` 恰好一处」。收敛的本意是**同一动作不许两条路**，语境性出口（常驻快捷 / 空态引导）与菜单项语义不同，不算重复。`pin` 本就有意双路（卡头钮 + 菜单），判据改为切到菜单块内再计数。

### 4.2 负锚要钉作用域，不能钉字符串

- R57-9 负锚 `repeat(3, 1fr)` 全站扫 → 误伤 `CompassSpine` 的六层三列网格与看板 `.kanban-board`；收窄到 `CT_W11` 才对。
- R59-3 负锚 `is-focused` 撞上我自己写的注释；`codeOnly` 不剥 `/* */` 块注释。

### 4.3 判据锚局部变量名 = 给自己埋漂移

R91-5 原锚 `query: { p: proj.id, from: 'tree' }`，改接线后形参成 `pid` 就红。改为正则 `p: [\w.]+, from: 'tree'` —— **锚路由与语义值，不锚变量名**。

## 五、门禁机制的两条新认识

1. **`dead-css-scan.cjs` 直跑不需要 Chromium**（`node scripts/dead-css-scan.cjs --json` 即出 JSON）。V3.8.7 时误以为它要浏览器链，导致 R4-Ev① 挂了三个版本。本轮靠它坐实「判死 13 + 祖先断 2 全在 CompassTree」（`.task-item` / `.task-check` / `.task-text` / `.task-meta` / `.task-actions` / `.empty-sub` 六族 15 条 R3-B2 遗留），清账后 **R4-Ev① 首次打绿**。
   - 同批**不删** `.metric-*`（投影弹窗仍用）与 `.proj-toggle` / `.toggle`（R4-Ev① 的活体票载体，删了那条判据会假红）。

2. **R4-Ey① 是「每次 src 变动都要还的债」**：src 一动 → `gen-code-index.cjs` → 透视卡 §2.1/§2.2 数字失效。本轮因此同步了两次（45,977 → 45,965 → 45,977）。**引用型数字不是一次性维护。**
