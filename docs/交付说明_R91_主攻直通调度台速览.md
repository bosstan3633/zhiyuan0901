## 一、这轮清偿的是什么

两处白纸黑字、但**零实现**的承诺：

| 出处 | 原文 |
|---|---|
| `v2/src/shared/models/index.ts:65` | `是否主攻项目（最多2个，同步至任务中心顶部）` |
| `v2/src/newtab/manual-data.ts:229` | `🎯 主攻（最多 2 个）**直通调度台速览**；14 天无推进自动亮 ⚠ 停滞。` |

**为什么它和其余 9 项 P1 性质不同**：那 9 项是"排期里还没做"，用户不会去找；这两项是**已经对外承诺**，用户读手册会去找一个不存在的东西——**找到就发现被骗了一次**。自 R85 提出后一直未拍板，本轮优先清偿。

### 1.1 勘验：两处承诺其实指向同一处

- `focusedProjects`（`stores/compass.ts:92`）是现成 computed：`allProjects().filter(p => p.isFocused && p.status !== 'archived')`。
- 它的**唯一消费方**是 `LighthousePanel.vue:153` 的主攻聚焦条（R85 加的，在**方向台** `/compass`）。
- **调度台 `/`（`CompassHome.vue`）零消费。**
- 「任务中心」是 **R49 已退役的旧页**（`/tasks` 路由已删，回归有 `check('旧任务中心路由已退役', …)` 把守）；`goToTask` 现在 `router.push('/')` 并提示"已跳转任务中心"——**"任务中心"这个叫法在用户侧已经等价于调度台首页**。

⇒ 「同步至任务中心顶部」与「直通调度台速览」是**同一件事**，落点就是 `CompassHome.vue` 顶部。

### 1.2 顺带发现：手册还承诺了"停滞"，同样没兑现

`isProjectStalled`（14 天无推进）在 store 里早就导出，被用于 R83 主航线项目胶囊与 R86 项目总览状态筛选，**但方向台的主攻聚焦条没用它**（只显示 🎯 + 名字 + 进度）。故「14 天无推进自动亮 ⚠ 停滞」在主攻这个语境下**同样是空头支票**——本轮在调度台速览条上兑现。

## 二、改动明细

### T1 · 调度台主攻速览条（`.ch-focus-strip`）

`CompassHome.vue` 新增一行，**插在 `MetricBar` 之后、`#dispatch-split` 之前**：

```
page-head        面包屑「调度台 · 今天，从哪里出发」
MetricBar        方向状态四格 + 操作记录四格
.ch-focus-strip  ← 本轮新增：🎯 主攻 ｜ 项目名 · 43% · ⚠ 停滞 · 待办 N
split            左：今日三件事 ｜ 右：项目调度
```

> 首页面包屑原文是「**今天，从哪里出发**」——**主攻正是这个问题的答案**。放在 MetricBar 之下、split 之上，正是"速览"的位置。

内容构成：

| 元素 | 说明 |
|---|---|
| `🎯 主攻` | 标签，用 `var(--accent)` |
| 项目胶囊 | `名字 · 进度% · ⚠ 停滞 · 待办 N`；**点击直达项目详情** |
| `去方向台 ›` | 右端导流回管理视角 |
| 空态 | `🎯 尚无主攻项目 —— 去方向台指定（最多 2 个）`，**整行可点** |

**与方向台聚焦条的分工（不是重复）**：方向台那条在**目标卡上下文里**，是"管"的视角（hover 能就地切换主攻）；调度台这条在**"今天从哪出发"的语境里**，故多了**停滞警示**与**待办数**——直接回答"今天该推哪个"。

### T2 · 预计算索引（R83 性能红线）

`projectProgress` / `isProjectStalled` / `isProjectDone` / `projectTasksOf` 内部**都要遍历 `d.tasks`**，在模板里对每个主攻各调一次就是 O(主攻数 × 任务数) 每次重渲染 ⇒ 预计算成 `focusMeta` 索引（与 R83 的 `projMeta`、R86 的 `projState` 同款），由 `R91-3` **否定断言**把守。主攻上限 2 个，成本可忽略，但红线不因"量小"而破例。

### T3 · 模型注释放齐

`models/index.ts:65` 的「同步至任务中心顶部」指向一个 **R49 已退役的页面**。若实现后注释仍指向它，会继续误导后来者 ⇒ 改为「直通调度台速览」并**注明原指向已退役**（保留沿革，便于追溯）。

## 五、本轮踩到的坑（已入技能）

**`projectTasksOf` 收 id，其余三个收对象——同一个 store 里签名不对称。**

```ts
projectProgress(p: Project)      // 收对象
isProjectStalled(p: Project)     // 收对象
isProjectDone(p: Project)        // 收对象
projectTasksOf(projectId: string) // ★ 收 id 字符串
```

按对称性直觉写成 `projectTasksOf(p)` ⇒ `vue-tsc` 报 **TS2345: Argument of type 'Project' is not assignable to parameter of type 'string'**。已改为 `projectTasksOf(p.id)`。
