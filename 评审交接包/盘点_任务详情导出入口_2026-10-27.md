# 盘点：任务详情“导出”入口

> 日期：2026-10-27
> 结论：导出属于 V3.9.22 的发布能力；当前工作树中没有导出，是未提交回退，不是其他分支或版本差异。

---

## 一、核查范围

- 当前分支与发布提交：`main` / `049139c`
- 当前分支父提交：`6d2b0cf`
- 本地分支：`main`、`backup-mac-20260908`、`codex/perf-feature-integration`、`codex/perf-r181`、`codex/unified-perf-feature`、`codex/unified-roadmap`
- 本地工作树：当前目录、`/private/tmp/zy_head`、`/private/tmp/zy_r181_snapshot`、三个 Codex managed worktree
- 相关文件：`TaskDetailDrawer.vue`、`ExportMenu.vue`、`taskExport.ts`、`109-shared-export.cjs`

---

## 二、事实

| 位置 | 任务详情导出 | 说明 |
|---|---:|---|
| V3.9.22 发布提交 `049139c` | 有 | `TaskDetailDrawer.vue` 新增导出入口、`exportTask()` 与 `.ts-export` 样式 |
| V3.9.22 父提交 `6d2b0cf` | 无 | 与当前工作树里的详情组件完全一致 |
| 当前工作树 / 暂存区 | 无 | 暂存区删除详情组件 16 行，并删除 `shared/utils/taskExport.ts`、`109-shared-export.cjs` |
| 其他本地分支 | 分两类 | `codex/unified-*` 含导出；`backup-mac-20260908` 与 `codex/perf-*` 基于发布线之外的旧快照，含该文件但无导出 |
| 当前工作树其他详情入口 | 无替代实现 | 全仓已无 `taskExport` / `buildTaskExportDocument` 引用 |

### 分支与工作树核对

- `main` = `049139c`：发布提交，含导出。
- `github/main` / `codex/unified-roadmap` / `codex/unified-perf-feature` = `c14db08`：合并发布线，含导出。
- `codex/perf-feature-integration` / `codex/perf-r181` = `d8d259b`：R181 性能分支，基于发布线之前的快照，不含导出。
- `backup-mac-20260908` = `a14a3da`：较早的本机备份分支，不含导出。
- `/private/tmp/zy_head` 与当前分支同为 `049139c`；当前主工作树的详情文件与父提交 `6d2b0cf` 字节一致。

因此“本地所有分支都有导出”这一旧判断不成立；正确答案是：**所有位于 V3.9.22 发布提交及其后续合并线上的分支都有导出；发布线之前的备份 / 性能快照没有导出。截图不是来自另立实现，当前主工作树没有导出仍是未提交回退。**

### 发布提交中的导出能力

- 入口：任务标题行右侧“导出”。
- 格式：Markdown、HTML。
- 实现：`buildTaskExportDocument()` + `taskExportMarkdown()` / `taskExportHtml()`。
- 边界：附件只导出名称、类型、大小等元数据，不读取附件 Blob。
- 回归：`109-shared-export.cjs`，覆盖链接协议、附件边界、HTML 自包含、Markdown 转义和文件名安全化。

### 当前工作树的回退范围

暂存区同时包含 V3.9.22 发布前的设置页导出结构和当前导出结构的反向变更：

- `TaskDetailDrawer.vue`：移除导出入口与逻辑。
- `ExportMenu.vue`：移除 `align` 参数与自包含样式，菜单回退到依赖外部样式。
- `cardExport.ts`、`taskExport.ts`：删除。
- `109-shared-export.cjs`：删除。
- `SettingsExportPanel.vue` / `SettingsImportPanel.vue` 被改为 `SettingsDataManagement.vue`。

因此这不是“截图来自别的分支”，而是**当前索引整体回退到了 V3.9.22 发布前的结构**。详情组件与父提交逐字节一致，是判断这条结论的关键证据。

---

## 三、对设计的影响

1. 原型继续保留任务导出，不能因为当前工作树没有按钮而删掉需求。
2. 导出仍作为独立动作放在任务详情右侧，不并入 AI 工具组。
3. 开发时应以发布提交 `049139c` 为基线，先恢复被回退的导出能力和对应回归，再叠加本轮布局与信息顺序调整。
4. 不建议直接使用当前暂存区作为新功能开发基线，否则会把 V3.9.22 的导出能力再次带回旧结构。

---

## 四、建议确认

开发前先由仓库负责人确认当前暂存区这套回退是否仍需保留。如果它是临时测试或未完成的重构，应先把任务导出与共享导出回归恢复到工作树；如果确有“下线任务导出”的产品决定，应单独记录决定并同步删除原型中的导出入口。
