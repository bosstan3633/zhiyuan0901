## L1 · 架构骨架

### 1.1 五个运行入口

| 入口 | 角色 | 关键事实 |
|---|---|---|
| **newtab**（主应用） | 全部页面 | 路由级懒加载 + KeepAlive 缓存四大主视图；单页应用 |
| **background**（Service Worker） | 命令监听 / 浮层注入 / 单例定位 / 路由中转 | MV3 SW，**会被随时回收**，故所有状态必须落 storage |
| **content script** | 任意网页的搜索 / 采集 / 好奇浮层 | 拆两层：常驻**信号层**约 2.9KB + 按需拉取**重型实现**（Shadow DOM，纯 Vanilla，**不引 Vue**） |
| **popup** | `chrome://` 等不可注入页的降级采集 | 降级路径 |
| **options** | 设置页入口 | — |

### 1.2 数据层（三层存储）

| 层 | 载体 | 内容 | 关键约束 |
|---|---|---|---|
| 主数据 | `chrome.storage.local` 单根 JSON（键 `zy_data_v2`） | 全部业务数据 | 已申请 `unlimitedStorage`；**真实库约 582KB**；写入 300ms 防抖 + JSON 纯净清洗 |
| 附件本体 | IndexedDB（库 `zy_assets`） | 图片 / HTML / PDF 的 Blob | **Blob 绝不进主 JSON**；单文件 ≤20MB |
| 辅助键 | `chrome.storage.local` 其余键 | UI 偏好 / 事件日志 / 热度统计 / 错误日志 / AI 配置等 | R159 起有**存储键字典**（`shared/storage/keys.ts`）作为唯一字面量出处，门禁「裸键名即红」 |

**并发写语义**：多窗口 / 浮层并发是真实场景。外部写入到达时 —— 本地无未落盘修改则整树替换；**有**则走 `mergeExternalData`：卡片按 `id + updatedAt` **LWW 合并**（平手取本地，保护输入中的表单），其余段"本页动过留本页"。自身写入回环由 writeId 指纹抑制。

### 1.3 领域模型（三卡 + 六层）

- **三张卡**：`ResourceCard`（资源）/ `TaskCard`（任务）/ `CuriosityCard`（好奇）
- **六层结构**：愿景 → 使命 → 战略目标（Direction）→ 项目（Project）→ 成功指标（Metric）→ 任务
- **策展台**（`Workspace` 实体）：金字塔策展空间，可**镜像**资源台的卡（引用式呈现，源数据零影响）
- **镜像投射**：`CurationProjection[]` 记录「哪张源卡被投到哪个策展台」

### 1.4 关键红线（违反即返工 —— 这是理解本项目的**必要前提**）

1. **卡间零挂载**（R165）：三卡互不持有对方 id（R162 退任务↔资源、R165 退任务↔好奇与好奇↔资源、R166 退 `fromCuriosityId` 溯源引用）；**记录型关联不受限**——`CurationProjection`（资源台→策展台镜像）与 `SupportLink`（任务→资源「支持」记录，R166 定案 5）是独立表里的记录，卡对象本身互不持有 id，与六层归属（projectId/metricId）同理属豁免项；任务**父子软层级已在 R166 退役**（`parentId` 删除，子任务改为父卡内嵌 `subtasks` 字段，不进任务池/指标/看板/周报）。
2. **删除一律软删**（`deletedAt` → 回收站）；策展台删除也软删卡片，恢复时孤卡回落。
3. **排序 computed 禁止原地 `.sort()`**（会污染源数组），拖拽序回写持久化字段。
4. **样式只用令牌**（`tokens.css`），禁硬编码色值；新 UI 必须过四主题走查。
5. **版本号唯一来源** `manifest.ts`，静态同步 6 处；`vue-tsc --noEmit` 必须 0 错误。
6. **每轮交付必须追加回归断言**（`regression.cjs` 只增不减）；被新拍板覆盖的旧断言**重指而非删除**。

### 1.5 渲染与性能策略（现状）

- KeepAlive 缓存四主视图（切台免重挂载）
- **增量渲染**：`RENDER_STEP`（R160 由 80 降为 32）—— 一次只渲染视口内若干张卡，滚动续载
- `content-visibility` 屏外跳过
- 分类树**索引层**（`catIndex.ts`）：一次建表替代 37 处 O(n) 全表扫描
- 记忆化：成熟度 / 字段 / 日期格式
- **虚拟滚动：未引入**（2026-09-13 拍板「先做重算削减，暂不引入」，以增量渲染替代）

## L3 · 债务、决策史与已知争议

### 3.1 已确立的架构决策（ADR 摘要 —— **请勿重复建议已被否决的方向**）

| # | 决策 | 取舍理由 | 复审条件 |
|---|---|---|---|
| 01 | **本地优先，不做云同步** | 目标用户对数据主权敏感；同步 = 数据上他人服务器 | 出现强付费的团队场景需求 |
| 02 | **单根 JSON 而非多键 / SQLite** | 个人级数据量；导出即迁移、导入即并集 | **若破性能预算再评估分域存储**（已列为下阶段首选项） |
| 03 | **附件走 IndexedDB，主数据不含 Blob** | 附件大（≤20MB）、主数据要轻要可 diff | — |
| 04 | **搜索 = 内存过滤 + 拼音按需，不建倒排索引** | 个人库千级为主，省索引维护复杂度 | 5000+ 卡场景触发再建 |
| 05 | **删除一律软删 + 回收站** | "信得过"是产品信任底座 | — |
| 06 | **并发写 = 卡片级 LWW 合并而非锁** | 多窗口是真实场景；合并复杂度换数据完整性 | — |
| 07 | **网页浮层纯 Vanilla，不引 Vue 运行时** | 注入体积与启动速度敏感；**代价是逻辑双写** | — |
| 08 | **资源台归一**（原「策展中心」转正为唯一资源卡存储源） | 台面命名混乱、存储源头分散 | — |
| 09 | **Airtable 单向同步**（只出不回，用户自备凭证） | 数据主权零成本 | — |
| 10 | **DHI 方向契合度退役** | 百分比可解释性差、用户难以据此行动 | — |

> **两处已实测确认的具体缺陷**（列在此处是为了给评审模型一个"低成本验证项"，用它检验材料与仓库是否一致）：
> 1. **`newtab/App.vue:344` 文案括号不匹配** —— `showToast(\`⛔ 数据保存失败（${tag}${sz}，请清理或导出后重试\`, act)`，外层 `（` 无闭合 `）`；且 `sz` 本身是条件拼接的（含自己的 `（）`），故配额超限时文案为"…失败（配额超限（已达 582 KB），请清理…"，正常时则缺右括号。
> 2. **`shared/storage/keys.ts` 概念边界被稀释** —— 该文件自称"存储键字典·全站唯一真源"，但 `K.ASSETS_DB`（`zy_assets`）实为 **IndexedDB 库名**、`K.ASSET_PACK`（`zy_asset_pack`）实为**导出包类型标识**，二者都不是 `chrome.storage` 键。把非存储键放进"存储键唯一真源"，会让"裸键名即红"这条门禁的语义边界变模糊。

### 3.3 项目自己的血泪教训（**这些是理解本项目"为什么这么做"的钥匙**）

1. **「断言全绿」≠「断言在守门」** —— 断言可能因为判据写错而恒真。项目现在的规矩是：凡 ★ 断言必须做**活性验证**（注入探针 → 期望变红 → 撤除 → 回绿）。曾实证：某否定断言正则用 `[^)]*` 穿不过函数右括号，导致长期漏检。
2. **「收尾结论下轮先证伪」** —— 曾出现"清单说 G7 待排期，实际代码三年前就交付了"的坏账，且该错误结论被多份文档一路传递。现在要求：**任何"已交付/待开发"的结论，下一轮先证伪再采信**。
3. **文档失真比代码腐烂更危险** —— 曾出现"技术架构文档否认 IndexedDB 附件层的存在"（该层早已上线）。现在要求：文档里的落点行号必须**回源码实核**，凡未证实者不写入。
4. **引用型数字必然失真** —— 项目已把这条写进纪律："任何引用型数字都可能在下一轮失真，使用时须重新核对"。
5. **性能数字必须同机 A/B** —— 跨时间比数字等于自欺（同包两次读数可差 24%）。

### 3.4 已知争议点（**给评审模型的引导，不预设结论**）

以下几处是项目**内部尚未形成共识**或**明知是问题但没找到解法**的地方，建议外部视角优先审视：

1. **单根 JSON 是否该分域** —— ADR-02 说"破预算再评估"，但真实库 582KB 离"可感区间"还远；项目自评"**越晚做越贵**"。
2. **巨型文件拆分的收益是否真实** —— 拆了 `Workspace.vue`，但总量没降、最大的换了名字。**拆分的正确性判据是什么？**
3. **虚拟滚动 vs 增量渲染** —— 拍板选了后者（不破坏拖拽/分组/选中结构）。在 2000+ 卡场景下这个选择是否仍然成立？
4. **浮层逻辑双写**（网页浮层 Vanilla + 应用内 Vue 各一份）—— 一致性靠断言守门，但**维护成本随功能增长**。
5. **AI 能力边界** —— 产品边界写着"不做 AI 替用户决策"，但已有 22 个 AI 入口（含"全方位优化""提炼论点骨架""找佐证"）。**边界是否需要重新定义？**
6. **文档体系的规模** —— `docs/` 300+ 份交付说明 + `文档中心/` 110 份规范。**维护成本 vs 认知收益**的平衡点在哪？
7. **门禁脚本单文件 666KB / 4,617 行**（`regression.cjs`）—— 可维护性与"只增不减"纪律的冲突。
8. **`content script` 在 `all_frames` 下注入所有页面** —— 性能与隐私观感的取舍。
