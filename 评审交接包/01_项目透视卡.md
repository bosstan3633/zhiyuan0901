## L0 · 一页纸

| 项 | 内容 |
|---|---|
| **产品名** | 知源调度台（英文 **Ownway**） |
| **形态** | Chrome MV3 扩展，**接管新标签页**（`chrome_url_overrides.newtab`） |
| **品类** | 「你在浏览器里的个人调度中台」——明确**不是**书签管理器 / 笔记软件 / 待办清单 / 新标签页美化工具 |
| **主 Slogan** | 万千可调用，自有我方向 |
| **目标用户** | 以浏览器为主要工作入口的独立知识工作者（独立顾问 / 研究型创作者 / 多项目并行者） |
| **核心价值** | 看见方向 · 留下好奇 · 调用所需 · 策展成果 |
| **信任底座** | 本地优先：无账号、无知源云端、无用户标识、无使用追踪。**唯一出网行为** = 用户自备 Token 手动触发的 Airtable 单向推送（只出不回）。★AI 密钥只活在 `chrome.storage` 的 `zy_ai_v1` 一个键里，不进导出/备份/合并链路，内容侧浮层永不持钥（所有 AI 调用发生在 newtab 侧） |

| **技术栈** | Vue 3.5（`<script setup>`）+ TypeScript strict · Vite 5 + @crxjs（MV3）· Pinia · Vue Router（hash）· UnoCSS + CSS 变量令牌 · 无 UI 框架 |

## L1 · 架构骨架

### 1.1 五个运行入口

| 入口 | 角色 | 关键事实 |
|---|---|---|
| **newtab**（主应用） | 全部页面 | 路由级懒加载 + KeepAlive 缓存主视图；单页应用 |
| **background**（Service Worker） | 命令监听 / 浮层注入 / 单例定位 / 路由中转 | MV3 SW，**会被随时回收**，故所有状态必须落 storage。★`chrome.*` 注入晚于 Playwright 的 `serviceworker` 事件，任何门禁脚本对 SW 求值必须走 `scripts/browser.cjs` 的 `swReady(worker)` |
| **content script** | 任意网页的搜索 / 采集 / 好奇浮层 | 拆两层：常驻**信号层** + 按需拉取**重型实现**（纯 Vanilla，**不引 Vue**）。★浮层目前注入在宿主页**普通 DOM**（Shadow DOM 隔离仍挂账），因此它读得到 `zy_ui_v2` 却**没有 `chrome.storage`**（MV3 的 http 页里根本没有）——所有跨上下文读写走消息 |
| ~~popup~~ **已退役**（R4-Fb） | 曾承诺 `chrome://` 等不可注入页的降级采集 | 该入口**从未进过构建**（dist 里仍引 `./main.ts`、manifest 无 `default_popup`）⇒ 打开是空白窗口；现由「进应用开对应面板」替代，`src/popup/` 三文件已删 |
| **options** | 设置页入口 | — |

### 1.2 数据层（三层存储）

| 层 | 载体 | 内容 | 关键约束 |
|---|---|---|---|
| 主数据 | `chrome.storage.local` 单根 JSON（键 `zy_data_v2`） | 全部业务数据 | 已申请 `unlimitedStorage`；**真实库 ≈333KB**（2026-10-04 实测：备份文件 413KB、`zy_data_v2` 主数据 287,439 字符；381 资源卡 / 76 任务 / 29 好奇）· perf 合成载荷 1,103KB；写入 300ms 防抖 + JSON 纯净清洗（Vue Proxy 过不了结构化克隆，见 R2-⑦） |
| 附件本体 | IndexedDB（库 `zy_assets`） | 图片 / HTML / PDF 的 Blob | **Blob 绝不进主 JSON**；单文件 ≤20MB |
| 辅助键 | `chrome.storage.local` 其余键 | UI 偏好 / 事件日志 / 热度统计（`zy_stats_v1`，R148 拆键）/ 错误日志 / AI 配置（`zy_ai_v1`）等 | R159 起有**存储键字典**（`shared/storage/keys.ts`）作为唯一字面量出处，门禁「裸键名即红」；★R164 把"名字像存储键但实则不是"的标识**拆出去**了：`IDB_NAMES`（IndexedDB 库名）与 `EXPORT_MARKERS`（导出包类型标识）不再混在 `K` 里 |

**并发写语义**：多窗口 / 浮层并发是真实场景。外部写入到达时 —— 本地无未落盘修改则整树替换；**有**则走 `mergeExternalData`：卡片按 `id + updatedAt` **LWW 合并**（平手取本地，保护输入中的表单），其余段"本页动过留本页"。自身写入回环由 writeId 指纹抑制。

### 1.3 领域模型（三卡 + 六层）

- **三张卡**：`ResourceCard`（资源）/ `TaskCard`（任务）/ `CuriosityCard`（好奇）
- **六层结构**：愿景 → 使命 → 战略目标（Direction）→ 项目（Project）→ 成功指标（Metric）→ 任务
- **策展台**（`Workspace` 实体）：金字塔策展空间。**资源卡真身统一入池**（R179），策展台经 `CurationProjection` **投射引用**拉取；★"把卡镜像到别的台"这个**推送入口已随资源台退役整域删除**（09-23 版描述的那条路径不复存在）
- **池**（`zy-curation`）：不是台面，是资源卡的唯一真身所在。★那枚 workspace **实体仍活在 `d.workspaces` 原始数组里**（getter 过滤掉），所以"按实体找池"的写法全是巧合——显示名单源在 `shared/utils/wsName.ts`（`POOL_DISPLAY_NAME='资源卡池'`），可选台列表另有 `selectableWsOptions` / `boardWsOptions` 两个口径（池显式排第一 vs 显式排除池）

### 1.4 关键红线（违反即返工 —— 这是理解本项目的**必要前提**）

1. **卡间零挂载**（R162/R165/R166）：三卡互不持有对方 id；**记录型关联不受限**——`CurationProjection`（池→策展台投射）与 `SupportLink`（任务→资源「支持」记录）是独立表里的记录，与六层归属（`projectId`/`metricId`）同理属豁免项；任务**父子软层级已退役**（`parentId` 删除，子任务改为父卡内嵌 `subtasks`，不进任务池/指标/看板/周报）。
2. **删除一律软删**（`deletedAt` → 回收站）；策展台删除也软删卡片，恢复时孤卡回落。
3. **排序 computed 禁止原地 `.sort()`**（会污染源数组），拖拽序回写持久化字段。
4. **样式只用令牌**（`tokens.css`），禁硬编码色值；新 UI 必须过四主题走查（`theme-audit.cjs` 的 104 张图 + 对比度门禁）。
5. **版本号唯一来源** `manifest.ts`，静态同步 **7 处**（09-23 版是 6 处）；`vue-tsc --noEmit` 必须 0 错误。
6. **每轮交付必须追加回归断言**（只增不减）；被新拍板覆盖的旧断言**重指而非删除**，且重指要写备案。
7. ★**AI 三条硬约束**：密钥只在 `zy_ai_v1`；内容侧不持钥、所有 AI 调用发生在 newtab；**入口 chunk 里不许出现任何 AI 字面量**（`entry-literals.cjs` 双向扫源码闭包与产物，15 项全 0 才过）。

### 1.5 渲染与性能策略（现状）

- KeepAlive 缓存主视图（切台免重挂载）+ 隐藏视图停摆
- **增量渲染**：`RENDER_STEP`（R160 由 80 降为 32）+ 滚动到底自动追加 + 手动「加载更多」兜底
- `content-visibility` 屏外跳过
- 分类树**索引层**（`catIndex.ts`）：一次建表替代全表扫描
- 模板内函数改预计算表（R148-P1b）；`nowTick` 与整库 computed 解耦（B7）
- 记忆化：成熟度 / 字段 / 日期格式
- ⌘K 检索：两层打分（原文子串通道 + 拼音通道），派生串在**首次唤起后驻留**（M15 量过：关着面板仍占 ~7.2MB / 每卡 ~2,839B，其中派生串只占约三分之一，大头是"给整库每行建一个 17 字段对象"）
- **虚拟滚动：未引入**（2026-09-13 拍板「先做重算削减，暂不引入」，以增量渲染替代）

> ★**`perf.cjs` 至今没有进每轮自动门禁**——它一次 1′27″，且必须**串行独占**（并发跑互相抢主线程整批作废）。现状是"收口轮手动跑 + 判据钉指标在位（M5c/M5d/M15 等）"，09-23 版提的"纳入每轮门禁"这条**没做**，但原因从"没人做"变成了"有意的取舍"。
> **采样纪律不变**：同机同包两次 M1 可差 24%，M3 类四次可差近 5 倍 ⇒ 任何跨时间比较都不可信，必须同机 A/B 交替（`perf.cjs --dist=<包>`），并报出每次采样值。

### 3.3 项目自己的血泪教训（**这些是理解本项目"为什么这么做"的钥匙**）

1. **「断言全绿」≠「断言在守门」** —— 断言可能因判据写错而恒真。规矩是：凡 ★ 断言必须做**活性验证**（注入探针 → 期望变红 → 撤除 → 回绿）。已成型的具体口径：锚点要落在**被计算/被比较的那个表达式**上（不是用例标题、不是明细里的同名串）；要么锚"行首可执行语句"，要么直接实跑量具；闸要装在**全部跑完之后**的收口处。
2. **「收尾结论下轮先证伪」** —— 曾出现"清单说待排期，实际三年前就交付了"的坏账并被多份文档传递。现在要求：任何"已交付/待开发"的结论，下一轮先证伪再采信。**本卡这次重写就是这条纪律的执行结果**（见文末差异账）。
3. **文档失真比代码腐烂更危险** —— 曾出现"架构文档否认 IndexedDB 附件层的存在"（早已上线）。现在要求：文档里的落点行号必须回源码实核，凡未证实者不写入。
4. **引用型数字必然失真** —— 已写进纪律。09-23 版当时标「实测确认」的那 12 项，本次逐条重测后**过半已变**（文末差异账逐条列了）。
5. **性能数字必须同机 A/B** —— 跨时间比数字等于自欺（同包两次读数可差 24%）。
6. ★**像素比较也要有噪声地板，而且地板必须是形状判据**（R4-Ex）—— 同构建连采会差在 1–6 行高的边线上（单通道 ≤6），拿"逐字节相同"当判据必然假红；但只放宽数值又会把"整片调淡"看成噪声。做法：抖动 = 单通道 ≤6 **且** 差异带高 ≤8 行，两条缺一即算变化。
7. ★**"负判据被吞"比"正判据被吞"危险得多**（#119 / R4-Es）—— 剥注释的工具不跳字符串时，`'file:///*'` 会把后面 32 行真 manifest 吞掉：正锚吞了会红（响亮），**负锚吞了是静默永久绿**。同类形状还有"切片起点标记漂了 ⇒ 切片变空串 ⇒ 负判据永远绿"。

### 3.4 已知争议点（**给评审模型的引导，不预设结论**）

以下几处是项目**内部尚未形成共识**或**明知是问题但没找到解法**的地方，建议外部视角优先审视：

1. **单根 JSON 是否该分域** —— ADR-02 说"破预算再评估"，本轮 M6b=25ms / 载荷 1,103KB ⇒ 项目的 A1 判据判"未触发"。但真实库只有 ≈333KB（本轮实测），离可感区间还远，项目自评"**越晚做越贵**"。这个自评和判据的口径一致吗？

3. **虚拟滚动 vs 增量渲染** —— 拍板选了后者（不破坏拖拽/分组/选中结构）。在 2,584 行结果集（M15 那档）下这个选择还成立吗？
4. **浮层逻辑双写**（网页浮层 Vanilla + 应用内 Vue 各一份）—— 一致性靠断言守门，但维护成本随功能增长。★新的加重项：浮层页**没有 `chrome.storage`**，测试与产品都得绕。

8. **`content script` 在 `all_frames` 下注入所有页面** —— 性能与隐私观感的取舍。
9. ★**"每轮加断言、只增不减"这条纪律的长期成本** —— 现在 1,650 条、14 个分片、每轮跑 25 秒，且**新断言必须配活性变异自证**。这条线什么时候会变成负债？项目目前的答案是"上限靠加分片而不是放宽"，但没有回答"断言总量该不该有上限"。
