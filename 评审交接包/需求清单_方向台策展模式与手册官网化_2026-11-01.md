## 迭代一 · F1 方向台「策展模式」（全景只读视图 + 导出）

### 1.1 需求原意与核心动机（用户原话归纳）

- 在**方向台界面**提供一种「策展模式」，类似策展台的结构化呈现：把整棵方向树用**金字塔或树状结构**完整画出来；
- 页面可**上下滑动**，从愿景→使命→战略目标→项目（进展）→成功指标→任务（完成情况）全部呈现，**一览全局**；
- **点击具体内容 → 右侧滑出详情，只可阅读、不可编辑**；
- **导出 Markdown + HTML**，内容里的链接可点击；
- **一键折叠 / 全部展开**；
- 动机两点：① 全景式看见自己的方向树（自上而下）；② 导出后可**分享给别人，也可以喂给 AI**——AI 通过阅读导出文件更好地理解用户当前状态。

### 1.2 现状实测（V3.9.31 代码实读）

| 事实 | 依据 |
|---|---|
| 方向台已有两种视图形态与切换机制 | `views/useCompassTree.ts` `viewMode = ref<'tower' \| 'pano'>('tower')` + 左栏 `.navside` 切换按钮（W11-3 判据在守） |
| 策展台的金字塔/树状渲染器与罗盘数据**不通用** | `CurationMindMap.vue` props 为 `nodes: Category[]`（强绑分类树与资源卡），强行复用需改造数据层，得不偿失 |
| 全树导出基建可直接继承 | `taskExport.ts` / `projectExport.ts`（V3.9.31）+ `cardExport.ts`（escape/主题/文件名/链接安全）+ `link.ts` `toOpenableRawLink` |
| 只读详情无现成载体 | 现有 TaskDetailDrawer / MetricDetailDrawer / ProjectDetailDrawer 均为可编辑抽屉 |
| 折叠/展开交互有先例 | 方向塔 `expandAllNodes/collapseAllNodes`；策展树层级折叠（R98） |
| 组件行数帽 | W11-12：方向台组件 ≤400 行（新视图必须拆件） |
| 六层只读聚合口径已统一 | `compassMeta.ts`（tasksOfProject/tasksOfMetric 双路并集 + taskIds 轨道序） |

### 1.3 需求定义（拍板建议已内嵌，见 §1.5）

**D1 落位**：方向台**第三种视图模式**（与「项目塔 / 项目全景」并列），左栏视图切换扩为三态；非独立二级页（贴合「在方向台这个界面提供」）。
**D2 布局**：双布局可切换——**树状**（默认：自上而下六层纵向，支持上下滑动通览）与**金字塔**（愿景居顶逐层收窄的塔形总览）；布局切换交互语言复用策展台（`setLayout('tree' | 'pyramid')` 同款分段控件）。
**D3 内容呈现（六层全量，只读）**：
- 愿景 / 使命：原文卡（塔顶）；
- 战略目标：名称 + 期限 + 项目数/任务数读数；
- 项目：名称、进度（N/M · %）、主攻标记、状态（active/paused/done/archived）、停滞警示；
- 成功指标：验收标准、目标日、进度、⚠ 缺任务警示（挂 0 任务）；
- 任务：状态（待开始/进行中/已完成）、优先级、成熟度、链接、完成时间；
- 断链警示口径与方向台一致（空指标/停滞 14 天+）。
**D4 只读详情**：点击任一节点 → 右侧滑出**只读详情抽屉**（六种形态同一抽屉内分区呈现），底部「去方向台编辑 ›」导流回工作面；**不修改现有可编辑抽屉**。
**D5 折叠/展开**：每层节点可折叠；页头提供「全部展开」与「一键折叠至目标层」双动作。
**D6 导出**：页头「⤓ 导出」（ExportMenu，MD/HTML 双选）→ 新建 `shared/utils/compassExport.ts`（与 taskExport/projectExport 同构的单一生成器）：
- 范围：**全树一次导出**（愿景/使命原文 → 目标 → 项目 → 指标 → 任务），含状态、进度、优先级、验收标准、目标日、任务链接；
- MD 为标准语法（链接 `[标题](url)`，可直接投喂 AI 作上下文）；HTML 自包含单文件、沿用当前主题、链接可点击（`safeExportLink` 口径，不可用显式标注）；
- 导出说明段落写明「数据来源：知源本机数据 · 导出时间」。
**D7 只读红线**：策展模式全程**零写库**（不触发 persist 的任何路径）；与知源树同哲学——同一份数据的第二种长相。

### 1.4 验收判据方向（交付时落 regression 分片）

1. 三态切换锚（tower/pano/curation）+ 左栏三按钮常驻（双向可达，W11-3 同口径）；
2. 只读性负锚：策展模式组件内零 `persist()` / 零编辑调用；
3. 六层完整性：视图节点数与 compassMeta 聚合一致（投影完整性断言）；
4. 折叠/全展开双动作在位；
5. 导出：MD/HTML 双格式生成器存在、链接真 href、HTML 主题跟随、两处不另立第二实现；
6. 新组件行数 ≤400（W11-12 同帽，超了拆件）。

## 迭代二 · F2 产品操作手册官网化重写

### 2.1 需求原意

参考自家产品官网（feishu 站点，已抓取全文）围绕产品介绍所做的**可视化叙事风格**，以同样的风格**重新撰写产品操作手册**（产品内 `/manual` 使用手册）。

### 2.2 官网风格拆解（抓取实文的风格骨架，作为重写规范）

| 官网语汇 | 手册化转译 |
|---|---|
| 眉题（WHAT IS OWNWAY / HOW IT WORKS / WHY IT HELPS / TRUST & FAQ）+ 大标题 + 一句副题 | 每篇/每节以「英文眉题 + 中文大标题 + 一句白话副题」开节 |
| 「遇到的问题 → 知源怎么接住 → 带来的结果」三段式价值卡 | 操作节配「你在哪里卡住 → 手册教你这样做 → 做完后你能看见什么」三段卡 |
| STEP 01–04 流程卡（轻量闭环：收录→归位→调出→复用→校准） | 操作流程一律 STEP 编号卡，每步一句话+入口位置 |
| 真实产品截图 + 图注（点击可放大） | 每篇至少 1 张真实界面截图（复用库内 `宣传片/shots/` 实拍图 9 张），配一行图注 |
| 信任段（本地存储 / AI 只给建议 / 指标不制造焦虑）+ FAQ | 手册收尾篇做「信任与边界 + FAQ」 |
| 克制排版、白底、发丝线 | 全部 tokens.css 令牌，六主题走查，禁氛围渐变 |

### 2.3 现状实测

- 手册为**篇→节**两级富文本：`manual-data.ts`（`{ id, title, html }`，现约 quick×3 / basic×4 / mid×3+ 等篇节）+ `ManualPage.vue`（左侧滚动目录 + IntersectionObserver 双向联动 + 分享版 HTML 下载）；
- 框架质量好（滚动目录/联动/下载），**重写 = 内容重构 + 官网化组件样式**，不动目录联动机制；
- 手册有回归锚（R46-10 / R50-7 钉「好奇心卡/任务卡/单击明细行」等字面）——重写时旧锚按「重指而非删除」处置。

### 2.4 需求定义

**M1 篇目重构（五篇提案）**：
1. **认识知源**（WHAT：它是什么/给谁用/四价值——收录·对齐·调用·策展）；
2. **收录与三卡**（三键采集、资源/任务/好奇心卡、卡池管理）；
3. **方向与行动**（六层思维链、今日三件事、项目与指标推进）；
4. **调用与策展**（Ctrl+K 全局搜索、策展台组织成果、导出分享）；
5. **信任与 FAQ**（本地存储/AI 只给建议/指标不制造焦虑 + 常见问题 + 快捷键附录）。
**M2 官网化组件样式**：眉题、大标题+副题、三段式价值卡、STEP 卡、截图框注、FAQ 手风琴——全部走令牌。
**M3 内容事实源**：以母版/PRD 口径为准；沿用 02-13 红线（不打焦虑、不承诺「掌控/永不迷失/效率翻倍」）。
**M4 截图**：优先复用 `宣传片/shots/` 已入库实拍图；缺的界面（策展模式等新功能）标注占位待补。
**M5 分享版 HTML 下载保留**，样式随新风格走。

### 2.5 验收判据方向

1. 五篇结构锚 + 每篇眉题/三段卡/STEP 卡至少各一；
2. 截图引用路径在库（`宣传片/shots/`）；
3. 旧手册锚重指备案；违禁词负锚（不出现「掌控」「永不迷失」「效率翻倍」）；
4. 分享版 HTML 导出可用且含新样式。
