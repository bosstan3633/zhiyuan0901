## F1 · 任务详情 → 所属项目全景直达入口（P0 · 功能）

**反馈原文**：任务详情选好项目和成功指标后，需要入口点击后直接进入方向台、定位到该项目全景图，让我知道这个项目还有哪些其他指标和相关任务。

**现状实测**：
- 任务详情抽屉 `v2/src/newtab/components/compass/TaskDetailDrawer.vue`：项目/指标为紧凑双字段（V3.9.26 收口形态，见用户截图红框），字段本身只承担选择，无任何跳转出口；
- 方向台 `/compass` 的「项目全景」= `CompassPano.vue` 横向泳道视图（单项目、指标为列、任务为卡），由左栏 `viewMode`（tower/pano）切换、`CompassPanoSwitch` 选台；
- `CompassTree.vue` 目前**不读取任何 URL 定位参数**（grep `route.query` 零命中）——深链管道需新建；
- 全局已有单卡定位先例可参照：`/deck/:kind` 深链 `hl/hk` 定位单卡。

**需求定义**：
1. 任务详情抽屉项目/指标字段行尾新增「全景」Icon 按钮（`Icon` 组件 + tooltip「查看项目全景：该项目的全部指标与任务」）；
2. 仅当任务已挂项目时可用；未挂项目置灰，tooltip 说明「先选择所属项目后可查看全景」；
3. 点击 → 路由跳转 `/compass?view=pano&proj=<projectId>&hlTask=<taskId>`（参数名开发轮定稿）；
4. 方向台接收参数后：自动切**项目全景**视图 → 选中该项目 → 滚动定位到当前任务所在指标泳道 → 该任务行高亮闪烁约 3 秒（复用展板 `taskFlashId` 既有机制形态）；
5. 浏览器返回键可回到原页面（常规路由跳转天然支持，不另设返回逻辑）。

**验收判据建议**：
- 新增回归分片：① 按钮仅在已挂项目任务可用（未挂置灰）；② 参数解析缺省安全——非法/已删 projId 回落项目塔视图，缺参数不报错；③ 高亮走现有 flash 锚点，不新造第二套闪烁；
- 四主题 + 1024/800 断点截图走查。

**边界与非目标**：不改变字段下拉选择交互；到达全景后不自动展开任何编辑态；不跨到项目详情展板（`/compass/projects`）。

## F2 · 项目全景「切换项目」下拉溢出视口（P0 · 缺陷修复）

**反馈原文**：项目全景切换项目时，项目列表溢出了屏幕，是 bug。

**现状实测（根因已定位）**：`v2/src/newtab/components/compass/CompassPanoSwitch.vue` 下拉面板样式：
`position: absolute; right: 0; top: calc(100% + 5px); width: min(420px, calc(100vw - 32px)); max-height: 320px; overflow-y: auto;`
——而触发按钮位于画布**左上角（贴视口左缘）**，`right: 0` 锚定使 420px 宽面板整体向**左**溢出视口，项目行被截断不可读（用户截图 2026-10-31 实拍，红框即溢出区域）。

**需求定义**：
1. 水平锚定做**视口钳制**：按钮贴左缘时面板左对齐（`left: 0`）、贴右缘时右对齐——全景场景按钮恒在画布左侧，可直接改 `left: 0` 并以注释说明依据；
2. 垂直方向同样钳制视口底缘（按钮贴近底部时改为向上展开），杜绝纵向截断复发；
3. 面板内项目行完整可读：名称 + 指标/任务读数不再被视口截断。

**验收判据建议**：断言面板定位含钳制锚点；窄断点（1024/800）+ 四主题截图走查；**同类排查**——`ProjectCuration.vue` 自带的「切换项目」下拉同款场景一并检查，同病同修（不同修则备注理由）。

**边界**：不改面板交互逻辑（选中/返回行为不变）。

## F3 · 调度台「最近调出」→ 按频率与时间的 Top 10（P1 · 功能）

**反馈原文**：调度台右下角「最近调出」模块，需要按照频率和时间，呈现排名前十的卡片内容。

**现状实测**：`v2/src/newtab/views/useCompassHome.ts:589-596`——`recentResources` = 未删且有过调出的资源卡，**按 `lastCalledAt` 降序取 6 条**；行 meta = 相对时间 + 打开 N 次；头部 chip「本周 N 次」（wrr 周戳口径）与「全部」入口。

**拍板口径**：频率优先 · 全窗口 Top 10。

**需求定义**：
1. 排序改为：`callCount` 降序 → 同频按 `lastCalledAt` 降序；取前 **10** 条；
2. 行内两个信息都在：打开 N 次（主）+ 最近调出时间（辅）——频率优先时时间仍可读；
3. 模块标题与排序语义对齐：「最近调出」名不副实，建议更名**「常调 Top 10」**（终名开发轮随文案定稿，同步手册与 tooltip 口径）；
4. 头部「本周 N 次」chip（口径不变：本周一 0 点起被打开过的资源卡）与「全部」入口保留。

**验收判据建议**：断言排序表达式锚点（callCount 优先于 lastCalledAt）与 `slice(0, 10)`；空态文案同步；R187 系调度台右栏读数相关旧锚如受影响按「重指而非删除」处置。

**边界**：**仅资源卡**——调出计次物理上只存在于资源卡（`stats` 只经 `recordResourceOpen` 更新，红线 #3），任务卡/好奇心卡无「调出」概念，不引入。

## F4 · 方向台任务跨指标拖拽（P1 · 功能）

**反馈原文**：任务需要能跨指标的拖拽移动，调整位置和其归属。

**现状实测**：
- **已有同款能力**：项目详情展板树（`/compass/projects`，`v2/src/newtab/views/useProjectCurationDnd.ts`）支持指标/任务拖拽——指标内 t/b/in 三档落点、跨指标投放改归属（**双写归属口径** G1，R55-17 字符串锚把守：「树任务双写归属」「任务已转为未归类」）；
- **缺口**：方向台项目塔 `CompassTower.vue` 任务行只有 toggle / grade / openDetail / unbind，无拖拽；项目全景 `CompassPano.vue` 泳道任务卡同样无拖拽。

**拍板口径**：同项目内跨指标 + 指标内排序；**不做跨项目拖拽**。

**需求定义**：
1. 项目全景泳道：任务卡可拖拽——跨泳道投放 = 改该任务 `metricId`（**复用展板双写归属口径**，不另立第二套写法）；泳道内上下 = 调 `order`；
2. 项目塔任务行：同口径拖拽建议同轮带上（塔是同一数据的纵向形态，分开做会出两套行为）；若工作量裁决拆轮，塔侧移入下一轮并在此备注；
3. 拖拽视觉：落点指示线（复用展板 `dropOn` t/b 形态）、投放后泳道归属轨道与进度即时刷新；
4. 越界防护：拖到**其他项目**的泳道/舱时拒绝投放并 toast 说明（跨项目非本轮范围）；拖到「未归类」区按展板既有语义转未归类。

**验收判据建议**：R55-17 双写口径锚点在塔/全景落位后依旧全绿；新增断言——① 跨泳道 drop 改 `metricId` 且 `updatedAt`/persist 正确；② 同泳道重排只改 `order` 不触归属；③ 跨项目投放被拒绝；④ 渲染 computed 无原地 `.sort()`（红线 #4）。

**边界**：不做多选拖拽；不动任务父子软层级；全景只呈现挂指标任务，未挂指标任务不经此路径管理。

## F5 · 项目导出：全景 + 详情弹窗（P1 · 功能）

**反馈原文**：项目全景，乃至项目弹窗详情页，均需要提供导出功能，将项目整体情况导出为 markdown 或 html，结构化呈现，含链接的地方一并导出且可点击打开。

**现状实测**：
- **可复用基建**：任务详情 MD/HTML 导出（V3.9.22）——`v2/src/shared/utils/taskExport.ts` + `cardExport.ts`（`escapeHtml/escapeMarkdown`、`exportDateStamp`、`readExportTheme` 主题跟随、`safeExportFileName`、`safeExportLink`）+ `link.ts`（`toOpenableRawLink` 链接可点击、不可用标注）；今日战报导出同款先例；
- **缺口**：`ProjectDetailDrawer.vue`（项目弹窗详情页）**无任何导出**（grep 零命中）；项目全景页头亦无。

**拍板口径**：两处落点（全景页头 + 详情弹窗），MD + HTML 双格式。

**需求定义**：
1. **入口**：① 项目全景页头行动区（用户截图红框位：与进度 / ＋指标 / ⋯ 同行）；② 项目详情弹窗标题栏（与任务详情导出按钮位式一致，V3.9.26 口径）；
2. **导出内容（结构化）**：
   - 项目头：项目名、所属战略目标链、主攻标记、下一步主句、进度（N/M 任务 · %）、断链警示；
   - 指标 ×N：名称、验收标准、期限、进度、⚠ 缺任务警示；
   - 任务 ×N（按指标分组）：标题、优先级、状态、子任务清单（含完成态）、任务链接（可点击）、说明；
   - 支撑资源：经 `SupportLink` 关联的资源卡标题 + 链接（可点击；链接不可用时按 `safeExportLink` 口径标注，不静默丢）；
3. **格式**：Markdown 为标准语法（链接 `[标题](url)`）；HTML 自包含单文件、沿用当前主题（`readExportTheme`）；附件**不嵌入本体**，只留清单信息（与任务详情导出口径一致）；
4. 新建 `v2/src/shared/utils/projectExport.ts`（与 taskExport 平行归置），两处入口共用同一生成器，杜绝两份导出实现漂移。

**验收判据建议**：沿用 taskExport 断言模式——① 导出物含项目/指标/任务三级结构锚点；② 链接为真实可点 href（`toOpenableRawLink` 口径）；③ HTML 主题跟随；④ 文件名规范（`safeExportFileName` + `exportDateStamp`）；⑤ 两处入口调用同一生成器（防漂移断言）。

**边界**：不做 PDF/图片导出；不含 Airtable/策展台数据；`obsidian://` 与 `file://` 链接按既有 `toOpenableRawLink` 口径处理，不另立标准。
