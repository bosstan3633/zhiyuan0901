## 0. 一句话结论

六项反馈不是六个孤立改版，而是三条主线：

1. **先止血**：项目 AI 诊断在无“判词行”的 job 上直接读 `__verdict`，属于确定性空指针，必须先修。
2. **把“计划执行日期”从单字段升级为可追溯的安排历程**：任务、选题、好奇心都要能回答“这张卡被安排过几次、每次安排到哪天、什么时候安排的”，并能手动删减某个时间点。
3. **把四类卡片的管理面收回一级卡片池**：`/deck/*` 二级页退役，任务/选题/好奇心统一为“左侧列表 + 右侧日历/看板”，资源卡用“全部资源卡”默认文件夹 + 右侧大抽屉承接原二级页全部能力。

另外两项是独立的信息架构优化：

- **项目弹窗**从“概览 + 指标 + 任务”三页签拆解，改成一棵可上下滚动的项目全貌树：项目 → 成功指标 → 任务 / 选题。
- **策展台页头**把“论据卡 / 佐证附件”从中心论点中移出，与分享、台数据、打开全部资源、检索一起组成右侧全局功能模块；分享成果置顶右上，低频动作缩小。

## 4. 功能详情

### F0 · 项目 AI 诊断空指针修复（P0）

**用户原话**：项目模块，点击 AI 诊断，直接报错，是 bug，需要修复。日志见附件。

**报错事实**：

```text
Cannot read properties of undefined (reading '__verdict')
at AiSuggestionDrawer.vue
```

**根因（已定位，不是猜测）**：

- `v2/src/newtab/components/AiSuggestionDrawer.vue:198`：

```ts
watch(shown, (v) => {
  if (v.length && !verdictPick.value) {
    verdictPick.value = (v[0].data as { __verdict?: string }).__verdict || ''
  }
})
```

- 项目诊断 job 在 `v2/src/shared/ai/projectDiagnose.ts` 的 `parse()` 中只产出：

```ts
rows.push({ key: 'adv:' + rows.length, badge: `建议 ...`, main: s })
```

这些行**没有 `data` 字段**，`v[0].data` 为 `undefined`，再读 `.__verdict` 即抛错。

**修复口径**：

1. 先找**第一条真正带 `__verdict` 的行**，而不是无条件取 `v[0]`；
2. 所有读取都做可选链兜底；
3. 每次 `run(job)` 开始时重置 `verdictPick` / `verdictTitle`，避免上一个判决 job 的选择残留到下一个 job；
4. 不改项目诊断的规则引擎、不自动重跑、不改变“采纳后生成报告”的流程。

**验收**：

- 在“画像洞察 → 主攻项目 → 项目弹窗 → AI 诊断”入口点击，AI 抽屉正常打开、正常流式输出；
- 0 条建议、1 条建议、5 条建议三种返回都不报错；
- 项目没有指标 / 没有任务时也不报错；
- 原有的好奇心判决卡、资源卡补全等带 `__verdict` 的 job 行为不变；
- 再次点击 AI 诊断不残留上一次的判词选择。

**边界**：只修空指针与状态重置，不重做诊断 UI、不改模型提示词。

### F1 · 任务卡池：从“排期表”升级为“任务工作面”（P1）

#### F1-1 缺口筛选：未挂项目 / 未落图

**用户原话**：需要快速筛出没有挂载任何项目的任务；需要快速筛出没有挂载任何任务计划时间的任务，也就是没有落图到日历视图里的任务。

**现状**：

- `v2/src/newtab/views/useCompassHome.ts:949-1007` 的快捷筛选是：
  - `unscheduled`：`!task.dueDate`
  - `unarchived`：`!task.projectId || !task.metricId`
  - `focus`：属于主攻项目
  - `overdue`：`status !== 'done' && dueDate < today`
- “未归档”把“未挂项目”和“缺指标”混在一起，用户无法只筛前者；
- “未排期”判定就是 `!task.dueDate`，与“未落图”同义，不应再加一枚重复筛选。

**目标筛选组（推荐定稿）**：

| 筛选 | 判定 | 计数口径 | 用户用途 |
|---|---|---|---|
| 全部 | 未删除且未进入生命周期归档 | 全部活任务 | 总览 |
| **未挂项目** | `!task.projectId` | 与左列表同源 | 先把任务挂到项目 |
| **未落图** | `!task.dueDate` | 与左列表同源 | 还没安排计划执行日期；由“未排期”更名而来，判定不变 |
| **未归档** | `!task.projectId \|\| !task.metricId` | 与左列表同源 | 保留现状，不拆不改 |
| **主攻项目** | 有项目且项目 `isFocused` | 与左列表同源 | 聚焦当前重心 |
| ~~已逾期~~ | — | — | **入口退役**；不再用“计划日期早于今天”推导逾期 |

**交互要求**：

1. 筛选是“单选取快捷条件”，与上方“项目 / 状态 / 搜索”是交集关系；
2. 五个计数与左侧清单、右侧日历使用同一份 `liveTasks`，不允许两套过滤函数；
3. 点击“未挂项目”后，左侧清单只显示这些任务；每条任务行直接提供“去归位”入口；
4. 点击“未落图”后，左侧清单只显示没有计划日期的任务；把任务拖到日历即从该筛选结果中消失；
5. 筛选状态写入 URL（如 `?tab=task&quick=noProject`），刷新/返回可恢复；
6. 空态文案说明“当前没有缺项目的任务”或“当前没有未落图任务”，不显示空白列表。
7. 任务卡上的项目占位文案、归位提示统一由“未归档”改为“未挂项目”；“未归档”只保留为旧筛选名，不再用于卡片上的归属状态文案。

**边界**：

- 不把“已完成”任务从计数中偷偷排除；是否看已完成由“状态筛选”决定；
- 不再新增“缺标签 / 缺优先级”等筛选，本轮只解决项目归属与计划时间两条主线；不新增“待补指标”。

#### F1-2 任务详情：计划执行历程

**用户原话**：任务详情页需要提供模块记录任务被安排的时间历程；可能今天安排、明天又安排、后天又安排；允许手动删减某些时间点。

**现状**：

- `TaskDetailDrawer.vue:276-281` 只更新 `selectedTask.dueDate`；
- `TaskDetailDrawer.vue:393-405` 已有“计划执行”区块，但没有历史；
- 多条写入路径直接改 `dueDate`（日历拖拽、快捷菜单、今日三件事、AI 推荐、任务/选题管理器等），如果只在详情里记录，会漏掉大部分安排动作。

**数据口径**：

- 采用**独立安排事件表**，不把历史数组塞进每张卡：

```ts
export interface PlanScheduleEvent {
  id: ID
  cardId: ID
  cardKind: 'task' | 'topic' | 'curiosity'
  /** 这次安排动作发生的时间 */
  at: number
  /** 被安排到哪一天，YYYY-MM-DD */
  date: string
  /** 安排前是哪一天，可为空 */
  fromDate?: string
  /** 来源：详情、日历、快捷菜单、今日重点、AI 采纳、导入 */
  source: 'detail' | 'calendar' | 'focus' | 'quick' | 'ai-adopt' | 'import'
  /** 用户手动删除该时间点时的墓碑；UI 过滤掉，同步时不会被并回来 */
  removedAt?: number
}
```

- 新增 `AppData.planScheduleEvents?: PlanScheduleEvent[]`；
- 只有“用户主动把日期写成非空值，且与当前日期不同”才新增事件；
- 若用户只是重复确认同一日期，默认不新增；若后续希望保留“再次确认”痕迹，可在入口加 `force` 开关，但本轮不做，避免历史被重复确认刷屏；
- 清空日期不新增事件；
- 手动删除只写 `removedAt`，**不改当前 `dueDate`**；
- 不伪造旧卡历史；旧卡只显示“当前计划”。
- 卡片软删时事件保留；从回收站恢复卡片后，历史随卡片回来；物理清理仍按回收站现有策略。

**为什么用独立表**：现有云同步的 `threeWayMerge` 对顶层记录数组按 `id` 合并，对卡片内数组的删除容易产生“删了又被另一台并回来”的冲突。独立事件表 + `removedAt` 墓碑可以让“删某个时间点”跨设备稳定生效，也避免每张卡都背一条历史数组。

**详情页 UI（任务 / 选题共用组件）**：

```text
计划执行
[ 2026-11-20 ]   [设为今日重点]
当前计划：11/20（周四）

安排历程（5）                          [显示全部]
11/19 21:30  安排到 11/20    详情设置   ×
11/18 09:12  从 11/19 改到 11/20  日历拖拽  ×
11/17 20:40  从 11/18 改到 11/19  今日重点  ×
...
```

**交互要求**：

1. 最新安排排在最上面；
2. 每行同时显示“安排动作时间”和“被安排到的日期”，避免用户把两者混为一谈；
3. 来源用轻量标签区分“详情 / 日历 / 今日重点 / AI 采纳”；
4. 删除按钮只删除该条历史，二次确认或 3 秒撤销二选一；推荐**3 秒撤销**，因为历史不是高风险数据；
5. 历史为空时显示“从本次升级后开始记录；当前计划为 11/20”，不显示假数据；
6. 历史超过 20 条时默认显示最近 5 条 + “显示全部”，避免详情页被历史淹没；
7. 历史模块只读展示，不允许编辑某条历史的日期；要改日期就重新安排，产生新事件。
8. “删除某条历史”不等于“取消当前计划”：前者只清理记录，后者要用日期输入清空当前 `dueDate`，两个动作不要合并成一个按钮。

**验收**：

- 任务从“未落图”拖到 11/20 → 历史新增一条；
- 再从 11/20 拖到 11/21 → 再新增一条，`fromDate=11/20`；
- 同一天重复确认 11/21 → 不新增重复事件；
- 清空日期 → 不新增“取消”事件，当前计划变为未落图；
- 删除某条历史 → 当前计划不变，刷新后该条仍不显示；
- 云同步后删除墓碑不被另一台设备并回来；
- 任务、选题、好奇心三种卡都用同一个历史组件与同一套取数。

### F7 · 全局搜索新增“任务”页签 → 项目全景定位（P1）

**用户原话**：全局搜索框还需要增加一个 tab 页，搜任务；搜索选中任务后，直接定位到任务所在项目全景里。

**现状**：

- 存在两套全局搜索入口，当前都只有“任务卡”，没有“任务”：
  - 应用内：`GlobalPopups.vue` + `useGlobalPopups.ts`（类型 `all/res/task/curio/topic/ws/proj`），顶栏放大镜与 `Ctrl/⌘+K` 呼出；
  - 网页浮层：`overlay-search.ts` + `overlay-query.ts`，网页内快捷键呼出；
- 任务结果点击后：
  - 应用内 `useGlobalPopupsRows.ts` 的 `openItem` / `locateOnly` → `/deck/task?hl=<taskId>`；
  - 网页浮层 `overlay-query.ts` 的 `openSearchResult` → `/?hl=<taskId>`（调度台任务卡）；
  - “加入今日三件事”的定位 → `/compass/projects?p=<projectId>`（项目详情）；
- 项目全景深链已经存在：`useCompassTree.ts:467-481` 监听 `pano=1&proj=&m=&task=`，调用 `onListLocate` 切全景、滚动、闪烁。

**目标**：

1. 新增页签 **“任务”**（与现有“任务卡”区分）；推荐标签：
   - `任务卡`：管理卡片，落到任务卡池；
   - `任务`：按项目语境搜索，落到项目全景；
2. 应用内 `GlobalPopups` 与网页浮层 `overlay-search.ts` 都要新增同一页签与同一结果口径；不允许只改其中一套；
3. 搜索字段：任务标题、说明、标签、项目名、成功指标名、状态、计划日期；
4. 结果行显示：
   - 任务标题；
   - 项目 › 成功指标；
   - 状态 + 计划日期；
   - 未挂项目的任务带“未挂项目”徽标；
5. 选中结果：
   - 有项目：`/compass?pano=1&proj=<projectId>&m=<metricId>&task=<taskId>`；
   - 无项目：打开一级任务页并展开任务详情，toast 说明“任务未挂项目，先归位后可从项目全景查看”；
   - 项目/指标引用失效：回落任务详情并提示；
6. 结果可按项目分组；默认按任务最近更新/匹配度排序；
7. 键盘：↑↓ 选择、Enter 打开、Ctrl/Cmd+Enter 仅定位（沿用现有语义）；
8. Tab 循环、`typeLabel()`、计数缓存、清空 chip 都要同步新类型。

**验收**：

- 顶栏放大镜与网页浮层分别搜索一个已挂项目任务，选中后应用切到方向台项目全景，定位到对应指标与任务并高亮；
- 浏览器返回能回到搜索前页面；
- 未挂项目任务有明确回落，不白屏；
- 项目已删除/归档/指标失效时不报错；
- 旧“任务卡”页签行为不变；
- 搜索 200+ 任务时输入无明显卡顿（沿用现有前端过滤与计数缓存）。

**边界**：

- 不把“任务卡”页签删掉；本轮是新增专用落点；
- 不改项目全景本身的布局；
- 不改变 `onListLocate` 的定位与闪烁实现，只复用。

## 5. 数据与状态设计

### 5.1 F8 · 计划安排事件与唯一写入入口

```ts
export interface PlanScheduleEvent {
  id: ID
  cardId: ID
  cardKind: 'task' | 'topic' | 'curiosity'
  at: number
  date: string
  fromDate?: string
  source: 'detail' | 'calendar' | 'focus' | 'quick' | 'ai-adopt' | 'import'
  removedAt?: number
}
```

**唯一写入入口**：

```ts
scheduleCardDate(d, card, date, {
  source: 'detail' | 'calendar' | 'focus' | 'quick' | 'ai-adopt' | 'import',
  at?: number,
})
```

所有现有直接写 `task.dueDate` / `topic.dueDate` 的地方都必须改走这个入口，至少包括：

- `TaskDetailDrawer.vue`
- `TopicDetailDrawer.vue`
- `TaskCalendarView.vue`
- `TaskManagerPanel.vue`
- `useTaskManagerPanel.ts`
- `TopicManagerPanel.vue`
- `useCompassHome.ts`
- `focusSlots.ts`
- `focusSuggest.ts`
- `overlay-search.ts` 的“加入今日三件事”
- `overlay-query.ts` 的任务定位（如涉及日期）
- 后续新增的任何写日期入口，也必须走同一函数（由静态负锚守住）

**系统自动写入**：

- `focusSuggest.ts` 每日自动推荐首次写日期，属于系统安排；
- 推荐不写 `PlanScheduleEvent`，或写 `source='import'` 但默认不展示；本轮选择**不写**；
- 用户点“采纳”或“设为今日重点”时，才写 `source='ai-adopt' / 'focus'`。
- `syncFocusTasksToSchedule()` 同时服务自动推荐与手动“今日重点”，改造时必须加 `source: 'auto' | 'focus'` 参数：`auto` 只写 `dueDate` 不记事件，`focus` 才记事件；`addManualFocus()` / `addManualTopicFocus()` 调用时显式传 `focus`。

### 5.2 筛选与视图状态

一级卡片池 URL 建议统一：

```text
/?tab=task|topic|curiosity|resource
&view=list|calendar|kanban
&quick=all|noProject|noMetric|noPlan|focus
&group=none|project|status
&sort=created|unplanned
&hl=<cardId>&open=1
```

- 刷新、返回、从全局搜索跳入都能恢复；
- 不使用多份组件内 ref 互相覆盖；
- 旧 `/deck/*` 参数映射到以上参数。

### 5.3 项目全貌树取数

新增唯一取数函数：

```ts
buildProjectTree(d, projectId): {
  project, direction,
  metrics: Array<{
    metric,
    tasks: TaskCard[],
    topics: TopicCard[],
  }>,
  orphanTasks: TaskCard[],
  orphanTopics: TopicCard[],
}
```

要求：

- 任务按 `metric.taskIds` 与 `task.metricId` 双写口径合并，去重；
- 选题按 `metric.topicIds` 与 `topic.metricId` 双写口径合并，去重；

- 弹窗、项目导出、后续项目全景尽量共用同一取数，避免三处口径漂移。
