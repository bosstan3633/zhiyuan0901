# 资源卡「常用夹」需求与实现方案

审核稿 V1.2 · 2026-11-11

## 1. 需求定义

恢复“把用户自选资源卡收成常用文件夹、一键打开其中全部原始链接”的能力。结合当前产品命名，界面统一称为**常用夹**，并在首次出现时注明“原常用文件夹”。

它不是新的卡片分类，也不是复制资源卡，而是一组可持久保存的启动关系：

- 常用夹数量不限。
- 每个常用夹不限资源卡数量。
- 同一张资源卡可同时进入多个常用夹。
- 同一常用夹内自动去重。
- 文件夹成员按**引用式镜像关系**处理：加入、移出只改变文件夹与卡片的关联，不修改资源卡在资源池中的任何状态。
- 删除常用夹、从常用夹移出卡片，都不会删除资源卡。
- 常用夹不改变资源卡的标题、内容、标签、置顶、星标、归属、生命周期或策展关系。

## 2. 为什么复用现有“批量打开”而不是另起一套

当前资源池已经具备：

- 批量模式、全选、反选。
- 有链接卡片过滤。
- 超过 15 张先确认。
- 统一通过 `useResourceOpen` 记录调出并打开链接。

这次需要补上的不是打开链路，而是把一次性的临时勾选升级为可命名、可保存、可跨设备复用的关系数据。

## 3. 核心用户路径

### 3.1 从资源池批量创建

1. 进入“调度台 → 资源卡”。
2. 点击“批量”。
3. 勾选若干资源卡。
4. 点击“加入常用夹”。
5. 选择一个或多个目标常用夹；选择器内始终可以直接新建，不设数量上限。
6. 确认后显示“新增 X 张，跳过 Y 张已在夹内”。

### 3.2 从已有常用夹补充

1. 点击资源池控制行的“常用夹 2”。
2. 当前常用夹直接在右侧抽屉中展示成员列表。
3. 点击该常用夹内的“添加卡片”。
4. 在选择器中搜索并勾选资源卡。
5. 确认添加；成员数量与列表在当前常用夹内立即更新。

### 3.3 一键打开

1. 在常用夹列表中点“一键打开”。
2. 只保留有可打开链接、且未永久失效的卡片。
3. 无可用链接或已回收卡片跳过，并在回执中说明数量。
4. 超过 15 张沿用现有确认规则。
5. 实际产品复用 `useResourceOpen` 逐张打开，不另造链接判断逻辑。

### 3.4 文件夹内直接管理

- 常用夹列表中的每一个文件夹直接显示成员列表，不要求进入二级成员明细。
- 支持重命名、添加卡片、逐条移出卡片、删除常用夹。
- 每个成员行提供“移出”；点击后只删除该镜像关系，资源卡仍在资源池。
- 删除前明确提示“只删除分组，不删除资源卡”。
- 移出卡片后即时更新计数；可提供撤销回执。

## 4. 信息架构与入口

### 资源池控制行

在批量按钮附近增加：

`[文件夹图标] 常用夹 2`

- 0 个时显示“常用夹”。
- 有数据时显示当前常用夹数量。
- 数量不限，抽屉内始终可以继续新建。
- 按钮不占用资源卡行尾，避免资源行动作继续拥挤。

### 右侧抽屉

使用 520px 右侧抽屉：

- 每个文件夹卡片内直接展示成员列表、添加卡片、一键打开、重命名和删除。
- 成员列表超过可视高度时在文件夹卡片内部滚动，不跳转二级明细。
- 宽度约 520px；390px 视口改为全屏抽屉。

### 批量加入选择器

中央小弹窗，不做第二层抽屉：

- 显示本次将加入的卡片数。
- 可选择任意数量的目标常用夹。
- 可多选目标。
- 已包含的卡片显示“已含 N 张”。
- 选择器内提供内联新建，不设置常用夹数量上限。

### 单卡快捷入口

资源卡行不新增常驻按钮。保留两处低干扰入口：

- 批量模式下统一“加入常用夹”。
- 资源卡右键菜单增加“加入常用夹”。
- 资源卡详情抽屉增加“加入常用夹”。

## 5. 数据模型

新增业务关系实体，不修改 `ResourceCard`：

```ts
export interface ResourceFolder {
  id: ID
  name: string
  cardIds: ID[]
  order: number
  createdAt: number
  updatedAt: number
}

export interface AppData {
  // ...
  resourceFolders?: ResourceFolder[]
}
```

约束：

- 常用夹数量不设硬上限。
- `name` 去首尾空格，1–20 字，组间不可重名。
- `cardIds` 使用 `Set` 去重，建议保持添加顺序。
- 只允许引用资源池卡：`workspaceId === CURATION_WS_ID`。
- 软删除资源卡保留引用；打开时跳过并显示已回收。
- 永久删除后做一次懒清理；清理只删引用，不反向影响资源卡。
- 导入旧数据、旧云快照、包导入、默认数据均补 `resourceFolders: []`。
- V1 不支持拖拽排序；成员按添加顺序展示。
- 文件夹成员是独立引用关系；不能在加入/移出过程中调用 `store.persist()` 以外的资源卡字段更新，也不得改写源卡的 `updatedAt`。

## 7. 云同步

常用夹属于用户业务数据，必须进入云同步，而不是 `UIPrefs`。

同步范围：

- 上传：常用夹新增、改名、增删成员、调整顺序、删除。
- 拉回：同上。
- 不进入云端：抽屉宽度、列表/网格、搜索词、筛选状态。

清单与回执：

- `SyncManifestRecordType` 增加 `resourceFolder`。
- 回执分组可显示为“资源卡 / 常用夹”。
- 单独改名时字段差异显示 `name`。
- 成员变化时显示“成员”或 `cardIds`。

冲突策略：

- 以单个 `ResourceFolder` 为冲突粒度。
- `updatedAt` 较新者胜出。
- 删除记录同样带 `updatedAt`，避免旧设备把已删文件夹重新并回。
- 多端同时改同一文件夹时，在同步历史中保留可查看、可安全回退的动作记录。

## 8. 一键打开边界

- 无可用链接：按钮不消失，但禁用并提示原因。
- 部分有链接：打开可用数量，回执写清跳过数量。
- 同一常用夹出现相同 URL：打开时按 URL 去重，并说明跳过重复链接。
- 已回收/已永久删除卡片：跳过，不阻塞其他卡。
- 超过 15 张：弹出确认。
- 浏览器拦截：提示检查弹窗权限；打开循环中不得插入异步等待，避免丢失用户手势。

## 9. 性能目标

- 常用夹入口打开 P95 ≤ 600ms。
- 20 个常用夹、每组 300 张时，抽屉首屏 P95 ≤ 800ms。
- 批量加入 100 张到任意数量常用夹 ≤ 200ms，不含落盘。
- 搜索资源选择器键入 P95 ≤ 100ms。
- 打开操作不在主线程做重复全量数组扫描；成员集合预先建立索引。

## 10. 验收清单

- [ ] 可持续创建超过 3 个常用夹，不出现数量上限。
- [ ] 每个常用夹可添加任意数量资源卡。
- [ ] 同一张卡可以同时加入多个常用夹。
- [ ] 同一常用夹内重复加入会跳过，计数正确。
- [ ] 在常用夹内直接添加、移出成员，无需进入成员明细。
- [ ] 加入或移出常用夹不改变资源卡的内容、标签、置顶、星标、归属和生命周期。
- [ ] 重命名后列表与详情同步更新，空名/重名被拦截。
- [ ] 移出成员只删关系，不删资源卡。
- [ ] 删除常用夹只删分组，不删资源卡。
- [ ] 一键打开只处理可打开卡片。
- [ ] 无链接、已回收、重复 URL 均有回执说明。
- [ ] 超过 15 张出现二次确认。
- [ ] 批量加入支持多目标常用夹。
- [ ] 右键菜单与资源详情均可加入常用夹。
- [ ] 常用夹进入云同步，布局与抽屉状态不进云端。
- [ ] 导入旧数据自动补空数组，不报错。
- [ ] 1440、1280、1024、768、390 五档无横向溢出。
- [ ] 四主题对比度与现有产品一致。

## 11. 开发任务拆分

### P0 · 数据与持久化

1. 定义 `ResourceFolder` 与 `AppData.resourceFolders`。
2. 补默认值、迁移、导入/导出、存储合并。
3. 建立纯函数 CRUD：create / rename / addCards / removeCard / delete / prune。
4. 完成数量、重名、有效性、去重校验。

### P0 · 资源池交互

1. 控制行加入“常用夹 N”。
2. 实现 520px 右侧抽屉，每个文件夹内直接显示成员列表。
3. 实现新建、重命名、删除、文件夹内添加与逐条移出。
4. 批量栏加入“加入常用夹”。
5. 实现多目标选择弹窗与内联新建。
6. 右键菜单和资源详情补入口。

### P0 · 一键打开

1. 复用 `useResourceOpen` 与 `toOpenableUrl`。
2. 实现可用性统计、重复 URL 去重、跳过回执。
3. 实现 >15 张确认。
4. 补浏览器拦截提示。

### P1 · 云同步

1. 快照自动包含新业务段。
2. 清单与回执增加 `resourceFolder`。
3. 同步动作支持文件夹添加、改名、删除和成员恢复。
4. 补冲突与删除 tombstone 规则。

### P1 · 质量

1. 单元：CRUD、上限、重名、去重、软删引用。
2. 回归：控制行、批量栏、选择器、抽屉、右键菜单。
3. E2E：创建、批量加入、多目标、一键打开、删除不删卡。
4. 性能：3×300 卡首屏与键入。
5. 视觉：四主题、五档响应式、抽屉 390px。
6. 文档：产品基线、更新日志、使用手册、同步回执文案。

## 12. 明确不做

- 不做真实操作系统文件夹。
- 不复制资源卡。
- 不把常用夹映射为标签或策展台。
- 不让常用夹改变卡片生命周期。
- 不提供无限文件夹层级。
- V1 不做成员拖拽排序与自定义封面。

## 13. 建议审核结论

建议批准进入开发。推荐先做 P0 数据与资源池闭环，再接入云同步；原型中的“打开全部”为演示态，不会真的批量打开外链。
