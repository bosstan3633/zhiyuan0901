# 需求梳理 · 方向台层级标签与任务详情优化

> 日期：2026-10-27
> 基线：V3.9.22 发布提交 `049139c`（当前工作树含未提交回退）
> 产物：`原型_方向台层级标签与任务详情优化_审核稿_V2.html`
> 配套：`盘点_任务详情导出入口_2026-10-27.md`
> 性质：需求澄清 + 高保真交互原型；本轮不改生产代码，不新增数据字段。

---

## 一、需求目标

用户在方向台看到的标题有六层结构，但当前只有战略目标前有一枚很小的编号标签，项目标题与指标标题前没有同类说明。用户需要从上下文推断“这是什么层级的标题”，识别成本高。

任务详情当前把“状态 / 徽标”“AI 三入口”“导出”都塞进抽屉标题区；项目与指标又落在正文底部。用户打开任务后，先看到的是拥挤的操作，而不是“这个任务属于哪里、接下来能做什么”。

本需求要解决两件事：

1. **方向台任何一层标题，都能被标签直接说明层级。**
2. **任务详情先讲清任务与归属，再提供 AI 与导出；所有打开任务详情的模块同步受益。**

V2 根据评审继续收敛方向台首屏：移除战略骨架与项目塔之间单独占宽的“当前主攻”条，避免与下方项目行的“主攻”徽标、“只看我”筛选重复表达同一信息。

## 二、现状证据

| 观察 | 代码事实 | 结论 |
|---|---|---|
| 战略目标标签过弱 | `CompassTree.vue` 的 `.dir-badge` 使用 `--fs-micro`（9px）、透明底、普通边框 | 视觉重量接近注释，无法承担“标题类型说明” |
| 项目 / 指标没有同级标签 | `CompassTower.vue` 的项目标题直接从序号与 `h3` 开始；`CompassLane.vue` 的指标标题也从指标名开始 | 用户只能靠卡片结构与字号猜层级 |
| 战略目标标签同时承担筛选 | `.dir-badge` 点击会切换 `dirFilter`，行尾另有“只看我” | 标签一旦加粗，会与行尾筛选动作形成双入口、双语义 |
| 任务详情标题区承载过多 | V3.9.22 发布提交的 `TaskDetailDrawer.vue` 在 `#title` 放标题、状态徽标与导出，`#title-extra` 放三枚 AI 入口 | 520px 抽屉内同时出现标题、状态、AI、导出，容易拥挤 |
| 项目 / 指标位于正文底部 | `TaskDetailDrawer.vue` 的 `ds-props2` 排在说明、子任务、资源支持之后 | 归属是任务的上下文，应在用户开始编辑前出现 |
| 详情页是共享组件 | `TaskDetailDrawer.vue` 被方向台、项目详情、指标详情、任务调度、今日三件事、画像洞察等宿主复用 | 只改共享组件即可同步全部入口，禁止各宿主各做一套 |

> **导出入口盘点结论**：不是版本差异。V3.9.22 发布提交 `049139c` 在 `TaskDetailDrawer.vue` 中新增了任务导出（Markdown / HTML）、`ExportMenu` 接线与 `.ts-export` 样式，同一提交还新增了 `shared/utils/taskExport.ts`。当前工作树的暂存区却把这 16 行以及整个 `taskExport.ts`、对应回归 `109-shared-export.cjs` 删除了；工作树中的 `TaskDetailDrawer.vue` 与 V3.9.22 的父提交 `6d2b0cf` 完全一致。换言之，**导出属于 V3.9.22，工作树的“没有导出”是未提交回退**。本原型以发布提交为设计基线保留导出，建议在开发前先恢复该能力，不能因为当前工作树看不到按钮而漏做。

## 三、需求澄清与设计裁定

### 3.1 层级标签

**做什么**

- 在战略目标标题前保留并强化“战略目标”标签。
- 在项目标题前新增“项目”标签。
- 在成功指标标题前新增“指标”标签。
- 三者采用同一“层级签”组件：层级号 + 图标 + 中文类型名。
- 战略目标使用强调色淡底与左侧实轨，成为分组层级签；项目与指标使用中性底 + 强发丝线，形成清楚的同族关系。

**不做什么**

- 不把标签做成徽章墙或第二套导航。
- 不改变六层结构、排序、折叠与筛选口径。
- 不用新的颜色语义；只使用现有 `accent / surface / text / border` 令牌。

**关键裁定：标签只说明层级，不再兼任筛选。**

当前战略目标标签点击会筛选，行尾又有“只看我”。标签强化后继续可点，会让用户无法判断它是“说明”还是“动作”。因此：

- 层级签统一为静态标签（`span`，不可聚焦）。
- “只看我 / 正在只看”继续作为唯一筛选入口留在行尾。
- 这样既满足识别，也避免两个入口做同一件事。

**术语**

- 产品六层结构中的正式名称是“成功指标”。
- 标题前空间有限，界面可见标签统一为“指标”，`title / aria-label` 写明“第 5 层 · 成功指标”。
- 正文、筛选、AI 文案继续使用“成功指标”，不改词库。

### 3.2 任务详情信息顺序

调整后的顺序固定为：

1. 任务标题与完成态。
2. 状态、成熟度、子任务数等轻量读数。
3. **项目 / 指标归属。**
4. AI 协作与导出。
5. 说明、子任务、资源支持。
6. 优先级、链接、标签、时间、附件。

理由：

- 归属是阅读任务前必须知道的上下文，不能滚到底部才看见。
- AI 与导出是“看完任务后要做的事”，应排在归属之后，且不能与标题争夺注意力。
- 说明与子任务是正文，不与顶部动作混排。

### 3.3 顶部操作布局

**AI 三项收敛为一组**

- “补全 / 拆解 / 找支持”放进同一枚低强调的 segmented group，组前有“AI 协作”说明。
- 不再让三枚按钮各自使用实心强调色；悬停或聚焦时才出现 accent。
- 三项仍是独立按钮，不改变现有 AI 能力、互斥锁与采纳流程。

**导出独立**

- 导出放在动作行最右侧，与 AI 组之间用弹性留白分开。
- 默认是 ghost 按钮，点击展开格式菜单。
- 原型演示 Markdown / HTML / CSV 三种格式；若现网只有一种格式，开发时删除菜单、保留单按钮即可，不改本布局。

**窄屏**

- 抽屉默认宽 560px（现为 520px），宽屏更从容。
- 520px 以下时项目 / 指标改为上下排列。
- 360–440px 视口下动作行自动换行：AI 组独占一行，导出位于右上或下行末尾。
- 不缩小字号换空间。

### 3.4 “同步到所有任务详情”的落实方式

所有入口继续复用唯一的 `TaskDetailDrawer.vue`，不复制模板。本轮需要同步验证的宿主：

| 宿主 | 打开入口 | 同步方式 |
|---|---|---|
| 方向台 | 项目塔 / 项目全景任务标题 | 共享组件，自动同步 |
| 项目详情 | 任务行 | 共享组件，自动同步 |
| 指标详情 | 任务行 | 共享组件，自动同步 |
| 任务调度 | 卡片 / 列表 / 看板菜单 | 共享组件，自动同步 |
| 今日三件事 | 任务行 | 共享组件，自动同步 |
| 画像洞察 | 任务明细行 | 共享组件，自动同步 |
| 全局入口 | 深链 / 搜索结果 | 共享组件，自动同步 |

原型右上“评审”面板内提供入口矩阵，用于逐项验收“同一详情、不同宿主”。

## 四、交互与验收

### 4.1 方向台

- 战略骨架与项目塔之间不保留“当前主攻”独立模块；主攻信息继续由战略目标的“主攻”状态、项目行“主攻”徽标与行尾“只看我”承载。
- 战略目标、项目、指标三处标签同屏可见，且一眼能区分。
- 标签不可点击，不进入 Tab 顺序；行尾“只看我”仍可操作。
- 项目与指标折叠展开后，标签位置保持稳定。
- 1440 / 1024 / 520 / 390 四档无横向溢出。

### 4.2 任务详情

- 打开任意任务，项目与指标在标题下方首屏可见。
- 项目切换后指标清空，指标选项随项目变化。
- AI 三项位于同一组，运行中有统一忙碌态；不会因三枚按钮各自抢色而拥挤。
- 导出有独立入口与明确菜单；点击后回执。
- 说明、子任务、资源支持仍在首屏后连续可读。
- `Esc` 先关菜单，再关抽屉；`Ctrl/⌘ + Enter` 保存并关闭。
- 520 / 390 两档下标题、归属、操作不重叠，不缩字。

### 4.3 视觉规范

- 令牌：颜色 / 字号 / 间距 / 圆角全部取 `tokens.css`，不新增色值。
- 字阶：战略目标与项目 17px，指标 15px，正文 13px；同屏层级不超过三档。
- accent：只用于战略目标层级签、当前状态、AI 悬停与主行动；不让三枚 AI 按钮同时实心。
- 热区：所有按钮 ≥28px；图标按钮有可读 `aria-label`。
- 四主题：`linear / raycast / apple / notion` 均需走查。
