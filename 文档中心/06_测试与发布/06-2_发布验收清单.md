- [ ] `node scripts/perf.cjs --scale=medium` → 记录并与历史基线**同档**对比
      ★ **基线必须标测量机器（R154 实测教训）**：同一份 V3.1.8 代码，Mac 记的 M1=491ms / M2a=87ms，
      Windows 本机 A/B 实测 **M1=1221.7ms / M2a=345ms**——差 2.5~4 倍。跨机比数字会把"环境差异"误读成"性能回归"。
      规则：① 每轮记录**机器标识**；② 判回归只跟**同机上一轮**比；③ 换机器时先跑一次当轮代码的
      `git stash` A/B（旧版 vs 新版同机同档），拿到差再下结论。R154 即按此法判定"无劣化"。
      （**性能项须独占机器多次采样取中位**，见 `05-6` §〇 采样纪律）
      ★ **M14（R153 新增）＝资源台首屏渲染量**：可见节点数 / 卡片数 / 最差帧 / 掉帧数。此前所有指标只量交互耗时，
      首屏画得更重这件事没人守（R152 真库探针证明用户说的"卡"不在 JS：冷挂 626ms 里阻塞仅 106~173ms）。
      V3.1.8 基线：2724 可见节点 / 80 卡 · 最差帧 26ms · 掉帧 0/30（medium 档）。
      V3.0.0 基线（3 次干净中位）：M1 460 · M2a 75 · M2b 64 · M4b 20.8 · M2c 回调度台 16 ·
      M6a 序列化 1ms / M6b 写盘 11ms（582KB 载荷）· M3 21659ms/50 次（窗口内 `(program)` 占 15.0s，
      最大单个 JS 函数 279ms——长任务总量主要是 400 卡的排版绘制与压测器灌数据，非业务 JS）
      ★ **归因跑（R151 新增，指标异常时先跑这一条再谈改代码）**：`node scripts/perf.cjs --scale=medium --profile --idle-control`
      ——`--profile` 现在**额外**单采一段窗口三 CPU 谱（写 `.prof-window3.json`），`--idle-control` 在同库同页**零交互静置 20s** 出 M3d。
      规矩：**任何"看着像噪声"的指标，先用静置对照判它是不是环境自己抖**。M3c（窗口三 6~9s）据此定案：静置 **0 条**长任务
      ⇒ 由交互触发；窗口三 21.6s 采样 = `(idle) 13.4s + (program) 7.5s + GC 0.2s`，落到业务 JS **不足 0.4s**
      ⇒ **是交互后 Blink 侧非 JS 时间**（与 V3.0.0 基线那句"主要是排版绘制"对上），不是知源算得慢；
      JS 采样器到此问不出更多，下一刀换 **trace 分类**（layout / paint / 存储 IPC）。

- [ ] **★ 为什么这次是改预算而不是压产物（R154 用户拍板）**：600KB 是 **V2.80（48 文件）** 时代的口径，此后四轮（V3.0.0 607 → V3.1.2 620 → V3.1.9 637）单调爬升，**每轮都在"告警但无人处理"**——一个长期红着的门禁等于没有门禁。上调到 **660KB** 的依据：V3.1.9 实测 637KB + 约 3.5% 余量；生产包 1.7M/2M 与单文件 305KB/400KB 两条**不动**。
      同时把这条写清：**上调不是"这轮没问题"，是"承认门禁口径过期"**。压回路径照旧记账、不许因为预算抬高就忘掉：
      ① 拼音字典（305KB，占 ZIP 近半）分段或换更紧编码——最大单项，砍一半可直接回到 600KB 以下；
      ② 手册全文（约 280KB 两块 chunk）折叠加载或外置 JSON。
      下次 ZIP 逼近 660KB 时，**先做①，不再抬预算**。
