## 〇、一句话结论

> **竖版不是把横版裁一刀，而是重新编排。**
> 本片是 16:9 界面主导的演示片，横版里「界面 + 抽屉 + 右栏」三栏同屏；直接居中裁成 9:16 会把
> 调度台首屏切成一条窄缝、把抽屉整段切掉、把字幕切出安全区。
> 因此竖版走**「单主体裁切 + 重排」**：每个镜头只保留一个视觉主体，重新叠字幕、重排节奏、独立配旁白。

---

## 一、为什么不能直接裁

横版成片的画面构成决定了直接裁切的三个硬伤：

| 硬伤 | 具体表现 | 直接裁 9:16 的后果 |
|---|---|---|
| **多栏同屏** | 调度台首屏 = 主栏（今日三件事 + 手边的卡）+ 右栏（今天的状态 / 最近调出 / 好奇心培育），1920 宽内容铺满 | 居中裁 608 宽 → 主栏被切成两半，右栏整段丢失，「今天的状态」等读数全部出画 |
| **右侧抽屉** | 镜头 3 的任务详情抽屉占右侧 620px，是「任务挂在项目+指标」的**唯一证据画面** | 裁右侧抽屉 = 母本镜头 3 的核心证据消失；裁左侧 = 调度台首屏消失 |
| **底部字幕 + 贴底主线** | 字幕底边距画面下沿约 180px，主线走在底缘 y≈1044 | 竖版安全区（上下各留 200px）会把字幕压出画面，主线被切掉 |

**结论：竖版必须重新出片，不能由横版机械裁切得到。**

## 二、竖版技术规格

| 项 | 规格 | 说明 |
|---|---|---|
| 分辨率 | **1080 × 1920**（9:16） | 主流竖版投放规格 |
| 帧率 | 30 fps（与横版一致） | 便于同源素材复用 |
| 时长 | **45 秒**（不是 60 秒） | 见下方「为什么缩到 45 秒」 |
| 安全区 | 上下各留 **240px**（顶 240 / 底 240），左右各留 **60px** | 规避平台 UI 遮挡：抖音底部文案区、Instagram 顶部标题区 |
| 字幕位置 | 底部 **y = 1440**（即距底 480px），字号 52px | 位于安全区内，不被平台 UI 压住 |
| 品类字幕条 | 与横版同一套渲染规则，仅位置改为 y = 1360 | 保持视觉语言一致 |
| 尾帧 CTA | 品牌尾帧重排为**竖向三段式**（Logo → Slogan → CTA），CTA 不加二维码 | 无商店入口，二维码暂不可放（底稿 §6.2 缺口 6） |
| 音频 | **独立配音**：语速由 3.87 字/秒提到约 4.6 字/秒，删减长句 | 见 §四 |
| 编码 | H.264 High@4.1 / AAC 192k / faststart | 与横版一致 |

### 为什么缩到 45 秒

- 竖版的核心消费场景是**信息流快速滑过**，60 秒在竖屏里完播率显著低于横版；
- 母本旁白全稿 232 字，横版 60 秒是 3.87 字/秒（已接近母本标注的 3.3 字/秒上限）。竖版再塞 232 字就要提到 5.2 字/秒，**会破坏母本要求的"平静、清醒、有探索欲"的语感**；
- 因此竖版走**减法**：旁白压到约 205 字、删掉一处过渡性表述，其余信息点全部保留。

### 单主体裁切的具体做法

| 镜头 | 横版原图 | 竖版裁切框（源像素） | 处理 |
|---|---|---|---|
| 调度台「今日三件事」 | 01-dashboard.png 1920×1080 | x=276..1296, y=140..680 | 取主栏「今日三件事」区，缩放至 1080 宽 |
| 抽屉「项目 / 指标」 | 02-drawer-task.png 1920×1080 | x=1408..1920, y=540..640 | 只留「项目 / 指标」两行，2× 放大后锐化 |

| 策展台论证树 | 03-curation.png 1920×1080 | x=720..1230, y=300..900 | 裁 L1–L3 论证主干 |

> 浮层类画面（采集 / 好奇心 / 搜索）**不需要裁**——它们本身就是居中浮层，在 9:16 里反而更好看。
> 这也是竖版重构收益最大的地方：横版 3 个浮层各占 3.3 秒，竖版可以把最想讲的两个各给 6–7 秒。

## 五、声音设计（竖版）

- **00:00–00:08** 环境杂讯渐强，痛点处戛然静音（同横版，保留母本的声音转折）；
- **00:08 起** 极简电子配乐淡入，音量比横版 **+2dB**（竖版外放场景更多、环境噪声更大）；
- 旁白比横版 **+1.5dB**（竖版多为手机外放，字幕与口播需压过环境音）；
- 母本「无激昂鼓点、无史诗感」的约束不变。

## 七、生成与验收

**生成方式**：复用本片的现成资产，不需重新拍摄——
- 真实界面源图：`宣传片/shots/*.png`（9 张，1920×1080 深空薰衣草实拍）
- 抽象动效源：`宣传片/gen/*.mp4`（6 段，H2.3 生成）
- 配音：重新走 TTS（换声线或换语速参数），母本文字已按 §四 改写
- 配乐：`宣传片/music/music_main.mp3`（可直接复用）

**验收清单**：
1. 时长 45.000s，1080×1920，30fps；
2. 字幕全部位于安全区（y ∈ [1440, 1600]），平台 UI 不遮挡；
3. 每个镜头只有一个视觉主体，**无"半截界面"**（禁止出现被裁一半的抽屉或被切两半的三件事列表）；
4. 旁白语速 ≤ 4.6 字/秒，无赶读；
5. 尾帧无二维码、无商店安装承诺；
6. 红线自查同横版（见横版交付包中的红线自查表）。

## 八、本方案未做的事（诚实边界）

- **未产出竖版成片文件**：本次交付的是方案说明，不是成片。按 §七 生成方式执行即可落地，所需资产全部就位。

- **尾帧 CTA 口径不变**：仍按母本原定「免费使用 · 本地安装」。当前产品为开发者模式安装、无商店入口，**二维码在真实入口确认前不添加**。
