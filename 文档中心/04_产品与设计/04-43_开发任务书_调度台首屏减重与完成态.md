## 一、需求原文

**B2 · 项目调度面板偏重，是首屏第二重**（`04-16:130-134`）
> **现状**：项目调度通栏卡片，内部左右分栏：左侧强调框（战略目标 + 项目名大字 + 期限/进度 + 2×2 四指标），
> 右侧按成功指标分组的任务树（含关联/删除/新建）。复杂度接近一个独立页面，**视觉重量仅次于三件事**。
> **方案**：**默认只显示左侧摘要**（项目 + 进度 + 四指标）；右侧任务树**默认折叠**或改为**点击任务后滑出的右侧抽屉**。
> **收益**：首屏信息密度下降，焦点更集中。**成本**：中。

**B3 · 三件事缺少"完成"的安静正反馈**（`04-16:136-139`）
> **现状**：勾选 = 任务置完成，但页面没有"今天三件都做完了"的收束感。产品原则要求"状态可见但不焦虑"
> —— **不等于没有反馈**。
> **方案**：三件全完成时给卡片区一个**安静的完成态**（整块轻微去饱和 + 一行"今日三件事 · 已完成"），
> **不用庆祝动画、不用红色、不用进度百分比**。**成本**：小。

## 二、只读勘验结论

### 2.1 B2 前提**成立**（此前担心的"已过时"是误判）

提案写"左右分栏 / 右侧任务树"。代码里 R51-F10 确实把**页面级**布局改成了上下联动
（`.split { flex-direction: column }`，三件事在上、项目调度在下），
但**项目调度卡片内部**仍是左右分栏，B2 描述的正是这一层：

```
.card.curation
└ .cur-cols  :style="{ gridTemplateColumns: curColsStyle }"   ← 三列：l / split / r
  ├ .cur-col-l   战略目标 + 项目名大字 + 期限 + 项目进度% + 4 指标卡（= 提案说的"左侧摘要"）
  ├ .cur-split   拖拽调宽（30%–75%，持久化 UIPrefs.curSplit）
  └ .cur-col-r   .cur-groups —— 按成功指标分组的任务树
                  每组：▸ 折叠 / 🔗 关联已有任务 / 🗑 删除指标 / ＋ 新建任务
                  每任务：状态点 + 标题 + 状态 + ⨯ 去关联 + 🗑 删除
```

⇒ **"视觉重量仅次于三件事"属实**，`curColsStyle = minmax(0, ${curSplit}%) 8px 1fr`（默认左列 38%）。

### 2.2 B3 前提**成立**：全完成确实没有任何收束

勾选完第三件后页面与勾选前**视觉上无差别** ⇒ 收束感缺失属实。

### 2.3 既有断言无冲突

## 三、改动清单

### T1 · B2：任务树默认折叠（选"默认折叠"，不选"右侧抽屉"）

提案给了两个方案。**选"默认折叠"**，理由：
- "改为点击任务后滑出的右侧抽屉"要新建抽屉组件 + 遮罩 + 焦点管理，**成本中且会引入第二套任务编辑入口**
  （现有点一下即 `drawerRef?.open(t)` 开任务详情，再套一层抽屉是重复）；
- "默认折叠"复用既有结构，风险低、回退只是一行 `ref(false) → ref(true)`，
  且**收益点（首屏信息密度下降）完全一致**。

**script**：

```ts
/** R94（B2）：项目调度任务树默认折叠——提案原文「默认只显示左侧摘要」。
 *  ⚠ 不持久化：写进 UIPrefs 就变成"记住上次"，与"默认折叠"矛盾；每次进首页都是干净首屏。
 *     同一会话内切换项目**不重置**（用户已表达要看，切项目不该收回去）。 */
const curTreeOpen = ref(false)
const curColsStyle = computed(() =>
  curTreeOpen.value ? `minmax(0, ${curSplit.value}%) 8px 1fr` : '1fr')
```

**模板**：

1. 卡头（`curProject` 存在时）加切换按钮，带任务数：

```html
<button v-if="curProject" class="mini-btn" :title="curTreeOpen ? '收起任务树' : '展开任务树'"
  @click="curTreeOpen = !curTreeOpen">
  <Icon name="branch" :size="13" />任务树 {{ projTasks.length }} <span class="cur-tree-caret">{{ curTreeOpen ? '▴' : '▾' }}</span>
</button>
```

2. `.cur-split` 与 `.cur-col-r` 包 `v-if="curTreeOpen"`（**用 `v-if` 而非 `v-show`**：
   折叠时真的不渲染，首屏的信息密度与渲染成本**双降**；`v-show` 只降视觉重量）。
   `collapsedGroups` 是组件级 `ref<Set>`，重建不丢。

**样式**：折叠时 `.cur-cols` 已由 `curColsStyle` 变 `1fr`；补一条让左列在单列时铺满即可（grid 默认行为，无需额外样式）。

### T2 · B3：三件事全完成的安静完成态

**script**：

```ts
/** R94（B3）：三件事全完成——**安静**的完成态。
 *  判据：至少有一件（空列表不算"完成"），且全部 done。 */
const focusAllDone = computed(() =>
  todayFocusList.value.length > 0 && todayFocusList.value.every(s => s.done))
```

**模板**：

1. `<div class="card focus">` → `<div class="card focus" :class="{ 'all-done': focusAllDone }">`
2. `.today-cards` 之后加一行（在 `.today-body` 内）：

```html
<!-- R94（B3）：全完成的**安静**收束——一行中性小字 + 整块轻微去饱和。
     不用庆祝动画、不用红色、不用进度百分比（产品原则：状态可见但不焦虑）。 -->
<div v-if="focusAllDone" class="td-done">✓ 今日三件事 · 已完成</div>
```

**样式**（全部 tokens 变量、零硬编码色）：

```css
/* R94（B3）三件事全完成：安静完成态——整块轻微去饱和 + 一行中性小字 */
.card.focus.all-done .today-cards { filter: saturate(.5); }
.card.focus.all-done .tc-num { color: var(--text-3); }
.td-done { margin-top: 8px; font-size: 11.5px; color: var(--text-3); text-align: center; letter-spacing: .3px; }
```

> 卡头（复制昨日 / 导出 / 日期导航）**不去饱和** —— 它们是操作区，褪色会影响可用性。
