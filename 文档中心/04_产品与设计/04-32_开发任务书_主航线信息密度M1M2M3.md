## 三、设计

### 3.1 M1 · 愿景/使命压成一行锚点条

```
┌──────────────────────────────────────────────────────────────────┐
│ 愿景  让每一位规划师在家长面前…（单行省略）   │ 使命 ……  │ 进入方向树 › │
└──────────────────────────────────────────────────────────────────┘
         ↑ 整条可点，进完整方向树（愿景 1.2fr ／ 使命 1fr，维持原比例）
```

- 高度 `≤44px`（`min-height: 44px` + 单行 `nowrap/ellipsis`），**12px** 字号；
- 愿景段 `flex: 1.2`、使命段 `flex: 1`（沿用原 `.mr-vm-row` 的 `1.2fr 1fr`，改动前后重心一致）；
- tier 标签（愿景 / 使命）保留——它们是这段的**语义锚**，去掉后两条引文分不出谁是谁；
- 「进入方向树 ›」**由每张卡各一个收敛为右端一个**（原文"右端保留"）；
- 空态文案沿用「尚未设定愿景 / 尚未设定使命」。

**收益**：两块卡（≈85px，含 head + 两行 clamp + padding）→ 一条 44px，**首屏让出约 40px 给战略目标网格**；网格本身是 `auto-fill minmax(340px,1fr)`，让出的空间直接变成**多看到一行目标卡**。

### 3.2 M2 · 目标头补期限 / 主攻 / 进度 tooltip

```
目标  三年内建成…   中期 · 项目 3（主攻 1） · 45%ⓘ
```

- 期限 `dir.term` → `远期 / 中期 / 近期`，**未设则不显示**（原文验收要点）；
- 主攻数：`projectsOf(di).filter(p => p.isFocused).length`——**只在 >0 时显示**（写"主攻 0"是噪音）；
- 进度 `45%` 后的 `ⓘ` 是 **`title` tooltip**，说明口径：
  > *各项目进度的算术平均；项目有任务时 = 已完成任务 / 全部任务，无任务时取项目手动进度*
  （与 `projectProgress` 的实现逐字对应，不另造说法）；
- 项目数与主攻数合并为一段「项目 3（主攻 1）」，避免头部碎成一地。

### 3.3 M3 · 项目小卡由一行名字改两行

```
┌──────────────────┐
│ 🎯 客户洞察   停滞 │   ← 行 1：主攻标记 + 名字 + 停滞标记
│ ▓▓▓▓░░░  43% · 3/7│   ← 行 2：迷你进度条 + 百分比 · 完成数/总数
└──────────────────┘
```

- **主攻**沿用 R60 口径用 **`🎯`**（不引入 `★`，避免与既有 `⭐` 星标语义打架）；原 `.chip-proj.accent` 强调色边框**保留**；
- **停滞**用 `isProjectStalled(p)`，显示「停滞」文字标（不只是变色——颜色对色弱用户不可见）；
- **进度**调 `projectProgress(p)`，输出 `pct% · done/total`；
- **已完成**用 `isProjectDone(p)` → `opacity: .55`（对齐 `.archived`）；
- 宽度 `min-width: 150px; max-width: 210px`，两行后高度增加，`CHIP_LIMIT = 6` **保持不变**（>6 仍折「更多 N」）。

### 3.4 ★ 性能：进度与状态必须预计算，不能在模板里调函数

R71 确立了"模板方法调用消除"。`projectProgress` / `isProjectStalled` 内部都要遍历 `d.tasks`；
若在模板里对每个 chip 调一次，就是 **O(项目数 × 任务数) 每次重渲染**。

故加一个 computed 索引：

```ts
const projMeta = computed(() => {
  const m = new Map<string, { pct: number; done: number; total: number; stall: boolean; finished: boolean }>()
  for (const p of allProjects()) {
    const pr = projectProgress(p)
    m.set(p.id, { pct: pr.pct, done: pr.done, total: pr.total, stall: isProjectStalled(p), finished: isProjectDone(p) })
  }
  return m
})
```

模板一律 `projMeta.get(p.id)`，与 `goalPct` 复用同一份口径。

## 八、风险与回滚

| 风险 | 处置 |
|---|---|
| M1 压成一行后长愿景被引号截断 | 单行 `ellipsis` + `title` 全文兜底；愿景本就是"锚点"不是"阅读区"，完整内容在方向树里 |
| M3 小卡变高，6 个 chip 可能撑高模块 | 模块是 `auto-fill` 网格，高度自适应；若实测过高，`CHIP_LIMIT` 由 6 降到 4（**留作手测后的微调，本轮不动**） |
| `projMeta` 遍历全部项目（含隐藏的已完成） | 与 `goalPct` 一样的量级，且是 computed；已完成项目仍可能被展开显示，不能只算可见的 |
| 停滞判定 `isProjectStalled` 有 14 天窗口 | 复用既有口径，**不改判据**（改了会与主航线/项目总览不一致） |

**回滚**：纯展示层改动，无数据写入；`git revert` 单个提交即可。
