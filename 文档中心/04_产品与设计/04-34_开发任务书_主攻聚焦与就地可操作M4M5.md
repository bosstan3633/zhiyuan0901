## 二、勘验（读源码为准）

### 2.1 三条需求本身的现状

| M4 聚焦条 | 主攻只在**各目标卡内的 chip** 上有 🎯 标记；**跨目标的主攻一览零存在** | ❌ 未做 |

### 2.2 ★ 三条勘验挖出来的既有问题（本轮必须先修，否则 M5 会放大它们）

**① 主攻「最多 2 个」是既定规则，但两处出口只有一处校验。**

三个地方都白纸黑字写了上限 2：

| 出处 | 原文 |
|---|---|
| `models/index.ts:65` | `/** 是否主攻项目（最多2个，同步至任务中心顶部） */` |
| `manual-data.ts:229` | `🎯 主攻（最多 2 个）直通调度台速览` |
| `ProjectCuration.vue:209` | `if (focused.length >= 2) { showToast('主攻项目最多 2 个…'); return }` |

但 `stores/compass.ts:72` 的 `toggleFocusProject()` **直接翻转、零校验**：

```ts
function toggleFocusProject(projectId: string) {
  const p = projectById(projectId)
  if (p) { p.isFocused = !p.isFocused; store.persist() }   // ← 无上限
}
```

⇒ **完整方向树（`CompassTree.vue:589` 用这个 store 方法）可以设出 3 个、4 个主攻**，违反模型与手册。
**M5 要在主航线加「🎯 设为主攻」按钮 ⇒ 不先修就是给这个漏洞再加一个入口。**

**② `focusedProjects` computed 已存在，但零消费。**
`stores/compass.ts:68` 定义了（含 `status !== 'archived'` 过滤），全代码库**只有定义与导出，无任何消费方**（Grep 实测）。
⇒ 模型注释承诺的「同步至任务中心顶部」、手册承诺的「直通调度台速览」，**目前都没兑现**。

**③ 新建项目四处出口，字段已经不一致。**

| 出口 | `pinned` | `order` | 名字来源 |
|---|---|---|---|
| `CompassShell.vue:102`（项目总览） | `pinned: false` ✅ | `order: dir.projects.length` ✅ | 用户输入 |
| `CompassTree.vue:182`（方向树） | **缺失** ❌ | **缺失** ❌ | 硬编码「新攻坚项目」 |
| `ProjectCuration.vue:248`（项目策展页） | **缺失** ❌ | ✅ `length` | 用户输入 |
| M5 待加（主航线） | — | — | 用户输入 |

`order` 缺失 ⇒ 在 `LighthousePanel.chipsOf` 的排序里走 `a.order ?? 999` ⇒ **方向树建的项目永远排在最后**。
**M5 要加第四处新建入口 ⇒ 不先抽共享函数就是制造第四份不一致。**

> ⚠ **勘验遗漏，如实记录**：写任务书时按 `newProject|addProject|新建项目` 三个关键词 grep，**漏掉了 `ProjectCuration.confirmCreateProject`**（函数名与文案都不含这几个词）。是**动工改到第三处调用方时才发现的**。
> 教训：找"同一件事的多个出口"时，**关键词要取"写入动作本身"**（此处是 `dir.projects.push`），而不是入口名——入口名各写各的，写入动作却只有一种写法。已补进技能 §五·补四。

### 2.3 一处需要说清的张力：M5 的写操作 vs D-A 的"主航线读为主"

`04-20` §2.2 的 **D-A** 写着：「主航线 = 看主线（读为主）；项目总览 = 管项目（写为主）」。
M5 却要在主航线加写操作（新建项目、设主攻）——**看起来冲突**。

**定：M5 只做"一键级轻量预置"，管理类操作仍导流出去。**

| 动作 | 性质 | 与 D-A 的关系 |
|---|---|---|
| `＋ 新建项目` | 只录一个名字，就地创建 | 轻量预置；复杂编辑仍去项目总览 |
| `🎯 设为主攻` | 一个开关 | **属于"看主线"**——主攻就是注意力的显式分配，不算"管项目" |
| `⋯` | 跳方向树并定位该目标 | **把重操作导流出去**，正合 D-A |

⇒ **不新增任何"管理类"能力**（改名 / 删除 / 设期限 / 归档一律不在主航线做）。

### 2.4 一处范围收窄（M5 第三项）

原文「目标卡 hover `⋯`」**未定义动作集**。本轮定为 **「在方向树中打开并定位」**（复用既有 `zy-locate-goal` 定位机制 + `openTree()`）——
**不造第二套目标操作菜单**（`CompassTree.vue` 已有完整的目标级操作：改名 / 添加 / 删除）。目标管理菜单若要做，应随 D-A 一起独立立项。

## 三、设计

### 3.1 T0-A · 主攻上限校验下沉（前置修复）

`stores/compass.ts`：

```ts
/** 主攻上限——models/index.ts:65「最多2个」与手册 manual-data.ts:229 同一口径 */
export const FOCUS_PROJECT_LIMIT = 2

function toggleFocusProject(projectId: string): { ok: boolean; msg: string } {
  const p = projectById(projectId)
  if (!p) return { ok: false, msg: '项目不存在' }
  if (!p.isFocused) {
    const others = allProjects().filter(x => x.isFocused && x.id !== p.id)
    if (others.length >= FOCUS_PROJECT_LIMIT) {
      return { ok: false, msg: `主攻项目最多 ${FOCUS_PROJECT_LIMIT} 个，请先取消其他主攻` }
    }
  }
  p.isFocused = !p.isFocused
  store.persist()
  return { ok: true, msg: p.isFocused ? '🎯 已设为主攻' : '已取消主攻' }
}
```

- **返回结构化结果，由调用方 toast**（store 不直接弹 toast——它是数据层，不该碰 UI）；
- 三处调用方各自 `showToast(res.msg)`：**`CompassTree:589`**（原本无提示，现在补上）、**`ProjectCuration:206`**（改为调 store，删掉本地那一份校验）、**M5 新加的 chip hover 按钮**；
- `ProjectCuration` 原 toast 文案「🎯 已设为主攻，同步今日行动」保留——把 store 的 msg 作为兜底，成功后仍用原文案（**不丢"同步今日行动"这个信息**）。

### 3.2 T0-B · `addProjectToDir` 共享函数（前置修复）

`stores/compass.ts`：

```ts
/** 新建项目（三处出口共用：项目总览 / 方向树 / 主航线）——字段以 CompassShell 既有口径为准 */
function addProjectToDir(dirId: string, name: string): Project | null {
  const dir = d.value.compass.directions.find(x => x.id === dirId)
  if (!dir) return null
  const proj: Project = {
    id: uid('proj'), name, isFocused: false, pinned: false,
    progress: 0, status: 'active', order: dir.projects.length, metrics: []
  }
  dir.projects.push(proj)
  store.persist()
  return proj
}
```

- `CompassShell.confirmCreate` / `CompassTree.addProject` / `ProjectCuration.confirmCreateProject` / **M5 的 `＋`** —— **四处**改调它；
- ⚠ `CompassTree` 的硬编码名「新攻坚项目」**保留**（那是方向树的既有行为，改名属范围外）；
- `pinned` / `order` 的补齐会**改变方向树新建项目的排序**（从永远最后 → 按创建顺序）。这是**修 bug**，不是行为破坏。

### 3.3 M4 · 主攻聚焦条（锚点条之下，一行 ≤40px）

```
┌────────────────────────────────────────────────────────────────┐
│ 🎯 主攻  [🎯 客户洞察 67%]  [🎯 产品重构 12%]                    │  ← ≤40px
└────────────────────────────────────────────────────────────────┘
   无主攻时：🎯 尚无主攻项目 —— 在项目小卡上点「🎯」即可指定（最多 2 个）
```

- 数据源：**既有的 `focusedProjects`**（已过滤 `archived`）——不用另写一份；
- 每项：名字 + `pct%`，点击 `openProject(p)` 进详情；**沿用 `projMeta` 索引**（R83 性能红线，不在模板调 `projectProgress`）；
- **受 `showDone` 开关节制**？——**否**。主攻是注意力分配，已完成的主攻项目也应能一眼看到并从聚焦条取消掉；已完成项 `opacity: .55`（对齐 `.chip-proj.done` 既有口径）；
- 无主攻 → 一行轻引导（灰字、无按钮），**文案带上"最多 2 个"**（把规则说给用户听，而不是等他被拒才知道）。

### 3.4 M5 · 就地可操作

**① 目标卡底 `＋ 新建项目`**（预选该目标）
点 `＋` → 卡底出现内联输入框（`v-focus` 自动聚焦）→ 回车创建 → Esc / 空内容失焦取消。
**不弹窗**——弹窗是"管理"，内联输入是"预置"，且省掉一次跨组件通信（`openCreate` 弹窗在父组件 `CompassShell`）。

**② 项目小卡 hover 两动作**

```
┌──────────────────────┐
│ 🎯 客户洞察      ⟶ 🎯 │  ← hover 时右端浮出
│ ▓▓▓▓▓▓░ 67% · 2/3    │
└──────────────────────┘
   🎯 = 设为主攻/取消主攻（toggle，走 T0-A 的 store）
   ›  = 进详情（与整卡点击等价，给"怕点错"的用户一个明确的入口）
```

- 用 `.cp-acts` 绝对定位在 chip 内，**hover 才显示**（`opacity` 过渡），不占常态空间；
- `@click.stop` —— **不能冒泡到 chip 的 `@click="openProject(p)"`**，否则点 🎯 会顺带跳详情页。

**③ 目标卡 hover `⋯`** = 「在方向树中打开并定位」：`openTree()` 后派发 `zy-locate-goal`（复用 R51-F15 既有机制，`LighthousePanel` 自己也监听这个事件）。

## 八、风险与回滚

| 风险 | 处置 |
|---|---|
| T0-A 让方向树"设第 3 个主攻"失败 ⇒ 存量已超 2 个的用户怎么办 | **不阻断**：超限时只拒绝**新增**，取消与查看一律正常；存量 3 个不受影响（不强制裁剪，避免丢用户的注意力分配） |
| T0-B 补齐 `order` 后，方向树新建项目的位置会变（从最后 → 按创建顺序） | 这是**修 bug**；已在 §3.2 记录 |
| M4 聚焦条让首屏又变高（R83 M1 才让出 40px） | 一行 ≤40px；且**主攻上限 2** ⇒ 聚焦条常态很窄，横向排得下 |
| M5 hover 动作挤占 chip 空间（chip 宽 168px） | 只在 hover 显示（`opacity` 过渡），常态零占位；`🎯` 与 `›` 各约 18px |
| 聚焦条与目标卡内的 🎯 chip 重复 | **不重复**：卡内是"某目标下的主攻"，聚焦条是"跨目标一览 + 直达入口"；且上限 2 ⇒ 聚焦条极短 |

**回滚**：`git revert` 单个提交即可。T0-A / T0-B 是纯逻辑收敛（无数据形态变更），M4 / M5 是纯展示 + 既有能力的入口，**无数据残留**。
