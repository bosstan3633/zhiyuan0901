## 二、现状勘验（读源码为准）

### 2.1 A3 · 整屏确认块

| 位置 | 场景 | 本轮 |
|---|---|---|
| `:1164` 附近 | **重复卡确认**（"该页面已收录"） | **维持现状**（A3 明文要求） |
| `:1185` 附近 | 资源卡保存成功 | → 改一行 toast |
| `:1304` 附近 | 任务保存成功 | → 改一行 toast |

- 自动关闭定时器：`savedTimer = setTimeout(..., 5000)`（两处）⇒ 改 **2500**
- 文案："按 Esc 关闭 · 5 秒后自动关闭" ⇒ 随整屏块一起移除
- `showToast(msg, duration = 2000)` 已存在（`:296`），toast 样式 `.zy-toast` 已具备 ⇒ **无需新增组件**

### 2.2 A7 · 数据结构与既有能力

`FocusSlot`（`shared/models/index.ts:270-279`）：`id` / `sourceType` / `sourceId` / `text` / `done` / `doneAt`
`DailyFocus = Record<string, FocusSlot[]>`（`:282`），**注释已写明"每天最多 3 个"**。

⚠ **既有缺陷**：`CompassHome.vue:170-184` 的 `selectTaskForSlot()` **没有 3 上限校验**——上限只在 `openPicker()` 入口拦（`:165`）。直接写 `dailyFocus[key].push(slot)` 会突破 3。⇒ **本轮在浮层侧实现真正的硬上限**，newtab 侧不在本轮范围（见 §七）。

### 2.3 键位冲突（重要）

`onSearchKeydown`（`:828`）中 **`Ctrl+Enter` 已被"定位并打开详情抽屉"占用**。
⇒ A7 的 `→` / `Ctrl+Enter` 只取 **`→`（ArrowRight）**，不改既有 Ctrl+Enter 语义。

### 2.4 跨上下文合并（A7 ③）的真实风险

```ts
async function saveData(d: any) { await chrome.storage.local.set({ [DATA_KEY]: d }) }   // 整体覆盖写
async function getData() { if (dataCache && Date.now() - dataCacheAt < 1500) return dataCache ... }  // 1500ms 缓存
```

浮层"读快照 → 改 → 整体覆盖"，若期间 newtab 也在写 ⇒ **newtab 的改动被整体覆盖（lost update）**。
**本轮对策**：A7 写入一律 `await loadData()` **绕过缓存取最新**，改完立即 `saveData(d)` 并**同步更新 `dataCache`**，把竞态窗口压到"读—改—写"一次往返内；不做整体重构（风险/收益不划算）。
