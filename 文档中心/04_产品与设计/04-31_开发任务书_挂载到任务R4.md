### 2.2 一个容易被忽略的事实：镜像卡与真身同 id

`hub.ts:139` `mirrors.push({ ...src, categoryId: …, __mirrorProjId: p.id })` —— 镜像卡是**真身的拷贝，`id` 相同**。
这意味着"从镜像卡挂载"在写入上等价于"从真身挂载"，语义是安全的。

但产品负责人本轮拍板：**镜像卡不给入口**。理由与 R61/R79 一脉相承——镜像卡在策展台是**只读引用**（动作条只有 `↗ 🎯 ✕`），任何"写"动作一律回落资源台真身卡。**口径一致性优先于此处的功能增益。**

### 4.1 动作条新顺序（七动作）

```
↗ 打开 · 📌 置顶 · ⭐ 星标 · 📂 移动分类 · 📡 镜像（仅资源台真身）· 📋 挂载（非镜像）· 🗑 删除
```

- `📡` 条件维持 `isHub && !isMirrorView(r)`（**不动**，`R79-8` 把守）；
- `📋` 条件 `!isMirrorView(r)` —— 资源台真身卡与**策展台原生卡**都有，镜像卡都没有。

### 4.2 选择器内容

```
┌─ 挂载「<资源标题 20 字>…」到任务 ────────── ✕ ─┐
│ 🔍 搜索任务…                                    │
│ ── 最近任务 ─────────────────────────────────   │
│ ✓ 完成 Q3 复盘          项目·年度规划           │
│ ＋ 整理客户访谈纪要      项目·客户洞察           │
│ ＋ 写周报                                       │
│ …（最多 50 条）                                  │
│ ─────────────────────────────────────────────  │
│                          [取消] [✓ 完成]        │
└────────────────────────────────────────────────┘
```

- 数据源：`d.value.tasks.filter(t => !t.deletedAt)`；
- 排序：**已挂载优先** → `updatedAt` 倒序（"最近"）；上限 50 条（性能，与既有列表策略一致）；
- 关键词过滤：标题 `includes`（不区分大小写），与任务侧 `mountSearchR` 同款；
- 项目名取 `d.value.projects` 反查，无项目则留空；
- 每行点一下即 `toggleMountTask(t)`，**立即 `persist()`**，无需确认。

### 4.3 写入（单向挂载红线的落点）

```ts
function toggleMountTask(t: TaskCard) {
  const rid = mountTarget?.id
  if (!rid) return
  const arr = t.mountedResourceIds || []
  // 整体替换而非 push —— 直接改数组元素在部分路径下不触发响应式
  t.mountedResourceIds = arr.includes(rid) ? arr.filter(x => x !== rid) : [...arr, rid]
  t.updatedAt = Date.now()
  store.persist()
}
```

**红线自检**：整个函数只碰 `TaskCard`，**不读不写 `ResourceCard` 的任何字段**（除取 `id`）。资源卡侧要"知道被哪些任务挂了"一律**反查**：

```ts
const mountedTaskCount = (r: ResourceCard) =>
  d.value.tasks.filter(t => !t.deletedAt && (t.mountedResourceIds || []).includes(r.id)).length
```

（与 `ResourceEditForm.vue:52` 同一写法，**已验证可行**，无需新字段。）
