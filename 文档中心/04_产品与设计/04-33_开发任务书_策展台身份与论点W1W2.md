### 2.2 两个必须知道的前置事实

**① `UIPrefs.viewMode` 是个死字段，不要复用。**
`models/index.ts:419` 声明了 `viewMode: 'list'|'kanban'|'card'`，`repository.ts:407` 给了默认值 `'card'`，但**全代码库零读取、零写入**。且它是**全局**的（不按台），类型里也**没有 `'pyramid'`**。
⇒ 本轮另加 `UIPrefs.wsViewMode?: Record<string, …>`（**按台 id 记忆**，与 `cardCols` 同构），**不动这个死字段**（动了会影响未来可能的清理，且语义不同）。

**② 金字塔页签对所有台可见**（`:100` 无 `v-if`），资源台也能进金字塔。
⇒ W2 ② 的规则对 hub 与策展台**一视同仁**：无偏好时 `thesisCard ? 'pyramid' : 'card'`。

### 2.3 一处未拍板、由本任务书定的取舍（W1）

**资源台 R73 那段写死的文案怎么办？**
若统一走 `workspace.description`，而资源台的 `description` 通常为空 ⇒ 按"描述为空不占位"就会**丢掉**「资源卡唯一存储 · 镜像源头」这句教学文案。

**定：hub 且 `description` 为空时，回落显示 R73 原有文案。**
- 对普通策展台，"描述为空不占位"**严格生效**（不显示描述段）；
- 对资源台，回落保住了 R73 的教学信息，**零信息损失**；
- 右端摘要 hub 时追加「· 可镜像到策展台」，同样保住原 hub-hint 的提示。

## 三、设计

### 3.1 W1 · 台身份页头（一行 ≤40px）

```
┌────────────────────────────────────────────────────────────────────┐
│ 📦 资源台 · 资源卡唯一存储 · 镜像源头        12 张卡 · 3 个分类 · 可镜像到策展台 │
└────────────────────────────────────────────────────────────────────┘
   ↑ workspace.icon（空则不显示）  ↑ name      ↑ description（空则不占位）
```

- **图标** `workspace.icon`（`WS_ICONS` 里的 emoji）；为空则不渲染该 span（不留空位）；**资源台无图标时回落 📦**；
- **台名** `workspace.name`（加粗，与描述区分）；
- **描述** `workspace.description`，单行省略；**为空则不占位**（原文验收要点）；hub 且为空时回落 R73 文案（见 §2.3）；
- **右端结构摘要** `N 张卡 · M 个分类`，hub 追加 `· 可镜像到策展台`；
- 高度 `≤40px`（`min-height: 34px`，`max-height: 40px`），与指标条之间不留额外空白。

**替换关系**：`.ws-hub-head`（`v-if="isHub"`）→ `.ws-id-head`（**所有台**）。R73 的镜像教学文案进回落与摘要，**不丢**。

### 3.2 W2 ① · 论点横幅（卡片视图顶部）

```
┌────────────────────────────────────────────────┐
│ 🏛 中心论点：让选择发生在看见之后      查看金字塔 → │
└────────────────────────────────────────────────┘
   未设立时：🏛 尚未设立中心论点 —— 右键台内卡片可设立（轻引导，非阻断）
```

- 位置：**卡片视图顶部**（`v-if="viewMode==='card'"`），在分类分组之前；
- 已设立 → 显示 `🏛 中心论点：<标题>`（点击打开论点卡详情）+ 右端「查看金字塔 →」（切 `viewMode='pyramid'`）；
- 未设立 → 一行**轻引导**（灰字、无按钮、不弹窗），文案沿用指标条里已有的那句「右键台内卡片可设立」；
- 金字塔视图本身就有 L1 根节点 ⇒ **不在金字塔视图重复显示**（`viewMode==='card'` 已排除）。

### 3.3 W2 ② · 默认视图 + 按台持久化

新增 `shared/utils/wsView.ts`，**与 `cardCols.ts` 完全同构**（读 / 写 / 归一 / 导入 sanitize）：

```ts
export const WS_VIEW_MODES = ['card', 'list', 'kanban', 'pyramid'] as const
export type WsViewMode = typeof WS_VIEW_MODES[number]
export function readWsView(ui: UIPrefs | undefined | null, wsId: string): WsViewMode | null
export function writeWsView(ui: UIPrefs | undefined | null, wsId: string, mode: WsViewMode): void
export function sanitizeWsView(raw: unknown): Record<string, WsViewMode>
```

- `UIPrefs.wsViewMode?: Record<string, WsViewMode>`（models 加字段，与 `cardCols` 同款）；
- **初始化优先级**：① 该台已存偏好 → 用它；② 无偏好 → `thesisCard ? 'pyramid' : 'card'`；
- **切视图即写偏好**（按 `workspaceId`），同会话内同步更新内存态 `ui` 对象（避免读回旧值，`cardCols` 同款处理）；
- **切台时重算**（`watch(workspaceId)`）——不同台各有自己的偏好；
- `sanitizeWsView` 供全量导入导出使用（只认四个白名单值，其余丢弃）。

⚠ **行为变更，已评估**：仅影响"从未切过视图 **且** 已设立论点"的台；用户一旦手动切过，偏好即生效，**不会再被自动切走**。旧用户升级后 `wsViewMode` 为空 ⇒ 有论点的台首屏变金字塔，无变化需求的台仍是卡片。

## 八、风险与回滚

| 风险 | 处置 |
|---|---|
| W2② 改默认视图，用户可能困惑"怎么变树了" | 横幅右端常驻「查看金字塔 →」，且**手动切过一次即永久记忆**；未设论点的台行为零变化 |
| 切台时偏好未重算 ⇒ A 台的金字塔串到 B 台 | `watch(workspaceId)` 显式重算，并由 `R84-7` 把守 |
| 导入的 `wsViewMode` 含非法值 | `sanitizeWsView` 白名单过滤（与 `sanitizeCardCols` 同款），非法丢弃 |
| W1 页头让首屏又变高 | ≤40px；原 hub 页头本来就在占位，策展台是**新增**一行——但换来台名/描述首次可见（W1 的目的） |

**回滚**：`wsViewMode` 是可选偏好字段，删掉后自动回落默认逻辑；页头与横幅是纯展示。**`git revert` 单个提交即可，无数据残留**。
