## 〇、需求原文与目标

> 好奇心培育和任务调度模块，以及资源台，呈现好奇心卡，任务卡，资源卡的地方，在卡片视图状态下，提供横向 4 个卡片，5 个卡片，6 个卡片，7 个卡片的布局选择，卡片大小自适应。

拆成三条可验收的规格：

| # | 规格 | 判定 |
|---|---|---|
| S1 | **出现位置**：只在「卡片视图」下出现 | 列表 / 看板 / 金字塔视图下控件不存在 |
| S2 | **四档可选**：4 / 5 / 6 / 7 列，互斥单选 | 四档唯一白名单，无第五档 |
| S3 | **卡片大小自适应** | 列数变化 → 卡片宽度随之变化；窗口变窄 → 自动降列，卡片不被压到不可读 |

**设计意图**：「一行放几张」随屏幕宽度、数据密度、当下任务（浏览 vs 精读）而变，是**偏好**，不该由样式表替用户决定。因此本轮不是"加一个控件"，而是**把列数从样式常量提升为可持久化的用户偏好**。

### G6 · 网格公式（"卡片大小自适应"的落点）

四套网格模板统一改为：

```css
grid-template-columns: repeat(auto-fill,
  minmax(max(<最小卡宽>, calc((100% - (var(--grid-cols, N) - 1) * <卡间距>) / var(--grid-cols, N))), 1fr));
```

| 模块 | 最小卡宽 | 卡间距 | `--grid-cols` 缺省 |
|---|---|---|---|
| 好奇心培育 | `200px` | `12px` | `4` |
| 任务调度 | `240px` | `12px` | `5` |
| 资源台（旧入口） | `240px` | `10px` | `5` |
| 资源台 / 策展台 | `var(--card-min-w)` | `var(--card-gap)` | `5` |

**`--grid-cols` 由宿主以行内自定义属性下发**（`.cz-grid` / `.tm-grid` / `.page` / `.ws-page`），CSS 侧只读变量——列数不进样式表、不散落模板。

## 三、数据结构影响

```ts
// shared/models/index.ts · UIPrefs
/** R72-1：卡片视图横向列数偏好（模块键 curio/task/res → 4~7 列；缺省取各模块默认值） */
cardCols?: Record<string, number>
```

- **落点**：`chrome.storage.local` 的独立偏好键 `zy_ui_v2`（`UI_KEY`），**不进** `zy_data_v2` 主数据根，**不参与**跨设备同步，但**随全量导出包的 `uiPrefs` 段迁移**（G7）。
- **兼容性**：可选字段，**老数据零迁移**——缺失即取默认值。
- **不引入反向字段**：不改任何卡片实体，不触碰 `mountedResourceIds` 单向挂载红线。

## 四、网格公式原理与算例

`minmax(max(<最小卡宽>, <均分宽>), 1fr)` 的语义是：**每列至少要有「均分宽」那么宽；实在放不下时退到「最小卡宽」**。而 `auto-fill` 会在容器里塞进尽可能多的列——由于「均分宽」本身是从容器宽度算出来的，**恰好只能塞进 N 列**；一旦容器窄到「均分宽 < 最小卡宽」，就自动退成更少列。**这就是"卡片大小自适应"的数学表达**。

以任务调度（最小 240px / 间距 12px）为例：

| 容器宽 | 目标 N | 均分宽 = (W − (N−1)×12) / N | `max()` 取值 | `auto-fill` 实际列数 |
|---|---|---|---|---|
| 1392px（方向台满宽） | 5 | (1392 − 48) / 5 = **268.8** | 268.8 | **5** ✔ |
| 1000px | 5 | (1000 − 48) / 5 = 190.4 | 240（退到最小卡宽） | **4**（4×240+3×12 = 996 ≤ 1000；5 列需 1248 > 1000）✔ |
| 900px | 7 | (900 − 72) / 7 = 118.3 | 240 | **3** ✔ |

> 取整误差可能造成边界处 ±1 列，属正常（浏览器按子像素计算）。这正是"自适应"而非"硬指定"的表现。

## 五、默认值口径与升级影响

**口径：各模块默认列数 = 改造前的等效列数**，保证升级后视觉零变化。

| 模块 | 改造前 | 等效列数 | 默认值 |
|---|---|---|---|
| 好奇心培育 | `repeat(4, 1fr)` | 4（写死） | **4** |
| 任务调度 | `auto-fill minmax(240px, 1fr)` | 方向台 1440px 页宽下 ≈ 5 | **5** |
| 资源台 / 策展台 | `auto-fill minmax(260px, 1fr)` | 同口径 ≈ 5 | **5** |

**升级影响**：老用户首次打开看到的列数与升级前一致；四档选择器提供的是**新增自由度**，不是**新的默认**。若产品侧希望"默认更宽松"，只需改 `CARD_COLS_DEFAULT` 一行。

## 八、风险与回滚

| 风险 | 评估 | 处置 |
|---|---|---|
| `calc()` 内 `var()` 作除数不被支持 | 低——Chrome 79+ 支持 `calc(100% / var(--n))`，本产品为 Chrome MV3 扩展 | `--grid-cols` 均带**字面缺省值**（如 `var(--grid-cols, 5)`），变量缺失时退化为改造前等效列数 |
| 容器极窄时列数塌到 1~2 列 | 中——属"自适应"预期行为 | 最小卡宽作为下限（200/240/`--card-min-w`），卡面不被压到不可读 |
| `CurationCenter.vue` 与 `Workspace.vue` 键冲突 | 低——两者**共用 `res` 是刻意设计**（同一台面同一偏好） | `R16` 收敛后自动合并，无迁移 |
| 工具条变长挤压搜索框 | 低——四处工具条均 `flex-wrap: wrap` | 窄屏时选择器换行，不遮挡 |
| 回滚 | — | 单点回滚：删 `cardCols` 使用处即可；**已写入 `zy_ui_v2.cardCols` 的偏好对旧版无害**（未知字段被忽略） |
