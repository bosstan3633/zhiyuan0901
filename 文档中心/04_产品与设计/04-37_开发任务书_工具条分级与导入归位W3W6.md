## 一、只读勘验结论（动工前）

### 1.1 工具条现状：一级已经堆了 11 个控件

`Workspace.vue:97-147` 的 `.ws-toolbar` 当前一级顺序为：

```
① 视图 Tab ×4（卡片/列表/看板/金字塔）
② 排序 select（5 档，R87 加的「调用最多」）
③ 排序方向按钮（仅 recent/visited 时出现）
④ 筛选 select（8 档 2 组，R87 扩的）
⑤ 密度 select（舒适/紧凑）
⑥ 列数 ColsPicker（R72 加，仅卡片视图）
⑦ 搜索框（margin-left:auto）
⑧ ☑ 批量管理
⑨ ⬇ 导入（primary 主色）
⑩ ＋ 新建（ghost 次色）
⑪ ⚙（设置菜单）
```

**这正是 W3 写这条需求时的画面**：②③④⑤⑥ 五个控件是"改看法"的，⑧⑨ 是低频管理动作，它们和 ①⑦⑩⑪ 这四个"每次都用的"平铺在同一行，主次不分。R72 加了列数、R87 把筛选扩到 8 档之后，这一行更挤了——**W3 的必要性是被动工本身推高的**。

### 1.2 两根现成的钉子（不要新造轮子）

| 已有 | 位置 | 本轮怎么用 |
|---|---|---|
| `.settings-menu`（⚙ 菜单） | `:86`，`position: fixed; top:54px; right:28px`，`display:none` + `.open` | W6 把「导入」「批量管理」挂进去 |
| `closeSettingsMenu` + `document.addEventListener('click', ...)` | `:1948` onMounted | 筛选气泡复用同一套"点外部关闭"机制，加一个 `closeFilterPop` |

### 1.3 定位方式：**改用相对定位**（相对既有 fixed 是改进）

`.settings-menu` 用 `position: fixed` 是 R64 之前的遗留——注释写"避免被 hero 圆角裁剪"。**hero 已在 R64-F13 删除**，且勘验确认 `.ws-page`（`:2932`）与 `.ws-toolbar`（`:2999`）**都没有 `overflow: hidden`**（只有 `.ws-content:3069` 有 `overflow-y:auto`，工具条不在其中）⇒ 气泡用 **`position: relative` 容器 + `position: absolute` 气泡**即可，且**会跟随触发按钮**——比写死 `right: 28px` 更健壮（筛选按钮的宽度会随"生效值徽标"变化，fixed 定位算不准）。

### 1.4 批量管理不能简单收进 ⚙

`.batch-bar` 浮动栏（`:435`）的条件是 `batchMode && selectedIds.size` —— **开了批量模式但一张卡都没选时，浮动栏不出现**。此时工具条上的「✓ 完成批量」是**唯一退出通道**。

⇒ 对策：**批量模式激活时，工具条临时出现「✓ 完成批量」**（进入仍走 ⚙），退出永远可见。

### 1.5 主色稀缺：一级只留一个主按钮

移除 ⑨（primary 的导入）后一级将没有主色按钮。按"主色稀缺"规矩，把唯一主动作 **「＋ 新建」由 `ghost` 升为 `primary`**（R8 也主张"主 CTA『＋新建』前置"，此处只做主色、不改顺序）。

| 5 | 「＋ 新建」由 `hero-btn ghost` 改 `hero-btn primary` |

### T2 · W3-②：「筛选」气泡

`.filter-pop` 内四行 + 一个重置：

| 行 | 控件 | 备注 |
|---|---|---|
| 排序 | `<select v-model="sortBy">` + 方向按钮 | 方向按钮沿用 `v-if="sortBy==='recent' \|\| sortBy==='visited'"` |
| 筛选 | `<select v-model="filterBy">` | 8 档 2 组，原样搬 |
| 密度 | `<select v-model="density">` | 舒适/紧凑 |
| 列数 | `<ColsPicker v-model="resCols" label="列数">` | **仅卡片视图**（沿用 `v-if="viewMode==='card'"`） |
| 底 | 「重置全部」 | 排序→manual、筛选→all、密度→cozy、列数→默认、并清空搜索 |

- `@click.stop` 阻止冒泡到 document
- 关闭：`document.addEventListener('click', closeFilterPop)`（与 `closeSettingsMenu` 同处 onMounted 注册）
- **互斥**：打开筛选气泡时关掉 ⚙ 菜单，反之亦然

### T3 · W3-③：生效值徽标

`filterSummary: string[]`（computed）收集**非默认值**：

| 项 | 默认 | 非默认时显示 |
|---|---|---|
| 排序 | `manual` | `SORT_LABELS[sortBy]` |
| 筛选 | `all` | `FILTER_LABELS[filterBy]` |
| 密度 | `cozy` | `紧凑` |
| 列数 | `CARD_COLS_DEFAULT.res`（5） | `N 列`（仅卡片视图计） |

- 按钮上**最多显示 2 个 chip**，超出显示 `+N`
- `title` 给出全部生效值（徽标挤不下时的兜底）
- **全默认时无徽标**（纯「🔣 筛选」灰字，不喧哗）

### T4 · W6：导入收进 ⚙ 并消歧义

| # | 内容 |
|---|---|
| 1 | ⚙ 菜单新增「⬇ 导入」项，文案 **mode-aware**：`isHub ? '⬇ 导入资源' : '⬇ 导入数据包'` —— W6 的痛点是**同名不同义**（策展台的"导入"是导入数据包，资源台的"导入"是导入资源），改名要从根上消歧义 |
| 2 | ⚙ 菜单新增「☑ 批量管理」项（仅 `!batchMode` 时显示） |
| 3 | 导入弹窗标题本身已是 mode-aware（R73-S2），文案不动 |
