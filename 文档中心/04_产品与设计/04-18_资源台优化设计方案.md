## 一、核心判断

> **资源台是"真身台"，但它是四个台面里卡片信息最薄的一个——镜像台（策展台）比真身台看得更全。**
> 这与主航线的"清单 vs 路线"是同一类病：**该是主场的台面，反而最不像主场。**

资源台的定位是「资源卡唯一存储 · 镜像源头」（页头自述），也是产品闭环 **入台 → 归位 → 调出 → 复用** 中"复用"的家。但：

- 它**看不见复用**（不显示调用次数 / 最近调用）；
- 它**做不了复用**（没有"挂载到任务"入口）；
- 它**找不到复用目标**（不能按调用热度排序、不能按标签筛）。

## 二、三个代码级反差

### 反差 1 · 信息倒挂：真身台卡片 < 镜像台卡片

| 卡片字段 | 资源台 `.cur-card` | 策展台 `.res-card` |
|---|:---:|:---:|
| 标题 | ✓ | ✓ |
| 链接 | ✓（纯文本） | ✓（带 linkType 图标 🔗/📁/📝） |
| 描述 | ✓（2 行截断） | ✓ |
| **标签** | **✗** | ✓ `#tag` chips |
| **附件** | **✗** | ✓ `AssetBadge` |
| **调用次数** | **✗** | ✓ `🔥 N` |
| **来源类型** | **✗** | ✓ |
| **创建时间** | **✗** | ✓ |
| 自定义字段 | ✓（chips） | ✓（按字段池） |
| 置顶 | ✓ | ✓ |
| **星标 ⭐** | **✗** | ✓ |
| **移动分类 📂** | **✗**（只能拖拽或批量移动） | ✓ |
| **右键菜单** | **✗** | ✓（打开/编辑/置顶/星标/移动/删除） |
| **字段池生效** | **✗** | ✓ |

> 证据：`CurationCenter.vue:1053-1072`（原生卡模板只有 title/link/description/customFields/tools）；`Workspace.vue:194-210`（策展台卡片含 tags/assets/callCount/sourceType/createdAt）。

### 反差 2 · 字段池在真身台失效

全局设置里的「字段设计」（`fieldConfig`）驱动卡片显示哪些字段、什么顺序。**它在策展台、任务、好奇心都生效，唯独资源台不生效**：

- 生效：`Workspace.vue:748` `visibleFields(d.value.fieldConfig,'resource')`；`TaskManagerPanel.vue:411`（task）；`CompassHome.vue:310`（task）；`CuriosityPanel.vue:374`（curiosity）
- **不生效**：`CurationCenter.vue` —— 全文件 grep `fieldConfig` **0 命中**，卡片字段为硬编码

> 用户花时间配了字段，结果在自己资源最多、最该定制的真身台上不生效。

### 反差 3 · 计数不自洽：同一屏三个数

| 位置 | 口径 | 代码 |
|---|---|---|
| 左树「全部分类」徽标 | **只算原生卡** `nativeCards.length` | `:979` |
| 左树「未分类」徽标 | **只算原生卡** `cardsIn('').length` | `:984` |
| 左树命名分类徽标 | **原生 + 投射 + 未投射源镜像**（并向上聚合子级）`nodeCount(c)` | `:1006`/`:1025` |
| 右侧视图（全部分类） | **全台混排**（原生 + 全部投射） | `mixedCardsOf(ALL_CAT)` |
| 看板列计数 | `mixedCardsOf(col.key).length` —— **不含子分类** | `:1145` |

结果：同一个节点，左树徽标、看板列头、右侧实际卡数**三者可以互不相等**。计数是"我有什么"的唯一度量，不一致会直接损伤信任。

## 三、方案（R 系列）

> 每条格式：**问题 → 方案 → 理由 → 成本 → 优先级**。

### R1 【P0】资源台卡片对齐策展台卡片（补齐信息）

- **问题**：真身卡不显示标签、附件、调用次数、来源、创建时间、星标；hover 动作条只有 `↗ 📌 📡 🗑`。
- **方案**：资源台卡片补齐以下要素，**样式语言复用策展台 `.rc-*`**：
  - 头部：`📌 置顶` · `📡 镜像标记` · 标题
  - 中部：链接（带 linkType 图标）· 描述 · **`#标签` chips** · **`AssetBadge` 附件**
  - 底部（新增 footer 行）：`📁 所在分类` · **`🔥 调用 N 次`** · `双击打开链接` 提示
  - hover 动作条：`↗ 打开` · `📌 置顶` · **`⭐ 星标`** · **`📂 移动分类`** · `📡 镜像` · `🗑 删除`
- **理由**：真身台的信息量必须 **≥** 镜像台。当前是倒挂的。
- **成本**：中（模板 + CSS；数据全在 `ResourceCard` 上，零模型改动）。
- **优先级**：**P0**。

### R2 【P0】接入全局字段池 `fieldConfig`

- **问题**：资源台硬编码卡片字段，全局设置「字段设计」在此失效（反差 2）。
- **方案**：卡片字段改由 `visibleFields(d.value.fieldConfig, 'resource')` 驱动，与策展台同源；`customFields` 不再单独渲染 chips（并入字段池统一表达），避免两套并存。
- **理由**：用户配置必须处处生效；同时消除"资源台一套、策展台一套"的双实现。
- **成本**：中（需处理"字段池未含 tags/assets 时的兜底"——`repository.ts:96-105` 已有自动补 `tags`/`assets` 定义的迁移逻辑，可直接复用）。
- **优先级**：**P0**。

### R3 【P0】统一计数口径

- **问题**：左树「全部分类」/「未分类」只算原生卡；命名分类算混排；看板列不含子级。三个数不一致（反差 3）。
- **方案**：
  1. 「全部分类」徽标改为**全台混排总数**（原生 + 投射，与右侧视图一致）；
  2. 「未分类」徽标改为**该区混排总数**（原生 + 投射）；
  3. 命名分类统一 `nodeCount`，并在 `title` 注明「含子分类」；
  4. 看板列计数改为与左树同口径（含子级聚合），或列头明写「仅直属 N」。
- **理由**：同一屏幕上同一节点不允许出现两个数。
- **成本**：小（`nodeCountMap` 已预计算，只需替换两个模板表达式 + 一处看板计数）。
- **优先级**：**P0**。

### R4 【P0】新增「挂载到任务」（补上"复用"闭环）

- **问题**：资源台是"复用"的家，但卡片动作里**没有挂载入口**。全代码库中 `mountedResourceIds` 的写入**只发生在 `TaskDetailDrawer.vue`**（任务侧）。用户想"把这张卡用到我正在做的事上"，必须先跳到任务里再找资源。
- **方案**：卡片 hover 动作条 + 右键菜单加 `📋 挂载到任务…`：
  - 弹出轻量选择器：搜索 + 「最近任务」列表；
  - 选中即在 `task.mountedResourceIds` 追加（去重）；
  - 已挂载的任务显示 `✓`，可再次点击取消。
- **理由**：产品核心场景是"在其他网页界面调度已有卡片推进当前的事"。**资源台是资源侧唯一的"出口"，必须能发起挂载。**
- **红线校验**：单向挂载红线约束的是**数据方向**（只有 Task 持有 `mountedResourceIds`，资源卡不反向持有）。本方案**写入的仍是 `task.mountedResourceIds`**，未新增反向字段，**不违反红线**。
- **成本**：中（新增选择器组件 + 写入逻辑；需按规则 7 补回归断言）。
- **优先级**：**P0**。

### R5 【P1】排序与筛选

- **问题**：排序**写死**为 `pinned > curOrder > createdAt`（`:186`），无排序控件；筛选**只有搜索**。
- **方案**：
  - **排序**：`手动排序（默认） / 最近调用 / 调用最多 / 最近创建` —— 后三项直接用 `lastCalledAt` / `callCount` / `createdAt`；
  - **筛选**（与搜索并列的轻量下拉）：`全部 / 有链接 / 本地文件 / ⚠待补全路径 / 有附件 / 未挂载任务`。
- **理由**：资源台的价值是"**调得出**"，不是"存得下"。热度排序让"我常用的那几张"浮上来。
- **成本**：中（排序小；"未挂载任务"筛选需扫 `tasks`，建议用 `Set` 预建索引）。
- **优先级**：**P1**。

### R6 【P1】搜索覆盖标签与自定义字段

- **问题**：`searchHit`（`:341-347`）只匹配 `title + link + description`；**标签可编辑却不可搜、不可筛**。
- **方案**：搜索范围扩展到 `tags` 与 `customFields` 的值；支持 `#标签` 语法直筛标签。
- **理由**：标签是用户自己建的检索维度，搜不到等于白建。
- **成本**：小。**优先级**：**P1**。

### R7 【P1】「待补全路径」显性化

- **问题**：本地文件导入写入的 `link` 是**文件名本身**（`CurationCenter.vue:679` `makeResource(f.name..., 'file', f.name, ...)`）。而 `toOpenableUrl`（`link.ts:17-22`）对"仅文件名"**返回空**，双击只会弹一句 **"ℹ 该卡未设置链接"（文案也不准确——链接是设了的，只是不完整）**。卡片上**没有任何标记**，也没有筛选器，用户无法找到并批量补全。
- **方案**：
  1. 卡片对 `linkType==='file' && !isFullPath(link)` 显示 `⚠ 待补全` 徽标（复用 `ResourceEditForm.vue:71-73` 的 `isFullPath`）；
  2. 配合 R5 的「⚠待补全路径」筛选，形成 **导入 → 筛出 → 批量补全** 的收尾闭环；
  3. 双击时的 toast 文案改为「⚠ 该本地文件仅有文件名，请在详情中补全完整路径」。
- **理由**：本地文件导入是产品明确承诺的能力，但没有收尾路径——导入完就是"哑卡"。
- **成本**：小。**优先级**：**P1**。

### R8 【P1】工具条收敛（一页一主角）

- **问题**：页头一行塞了 7 个元素（面包屑 + 3 视图 Tab + 搜索 + 批量 + 导入 + **常驻虚线提示胶囊** + 新建卡片）；主 CTA「＋ 新建卡片」被挤到最右。
- **方案**：
  - 常驻提示条（"卡片在此存储为真身 · 📡 单卡/📤 分类可镜像到各策展台 · 源数据零影响"）改为**「?」气泡**或首次进入引导，不常驻；
  - 「＋ 新建卡片」提到搜索框左侧（主 CTA 前置）；
  - 面包屑副标题「资源卡唯一存储 · 镜像源头」降为 tooltip（它是定位语，不是每屏必读）。
- **理由**：一页只允许一个主角；工具条是"工具"，不该抢占"内容"的注意力。
- **成本**：小。**优先级**：**P1**。

### R9 【P2】补齐星标 ⭐

- **问题**：`starred` 字段在模型中存在（`models/index.ts:117`），策展台有 ⭐ 动作，**资源台完全没有**。
- **方案**：卡片动作条加 ⭐；筛选加「只看星标」。
- **成本**：小。**优先级**：**P2**。

### R10 【P2】右键菜单

- **问题**：策展台有 `openResCtx` 右键菜单（打开/编辑/置顶/星标/移动/删除），资源台没有。
- **方案**：对齐策展台，并加入 `📋 挂载到任务`（R4）。
- **理由**：高频操作不应只在 hover 时出现（hover 动作条在小卡上容易误触）。
- **成本**：中。**优先级**：**P2**。

### R11 【P2】数据一致性：`callCount` 与 WRR 口径对齐

- **问题**：抽屉里的「↗ 打开链接」按钮调用 `openCard(editingResource)`，而 `editingResource` 是**深拷贝副本**（`:430` `JSON.parse(JSON.stringify(r))`）。`recordResourceOpen` 会把 `stats.wrr` / `lastVisits` 加一，但 `callCount` 只加在**副本**上；若用户不点"保存"就关闭，**卡片的 `callCount` 永不落库**——于是 `callCount` 与 `stats.wrr.thisWeekUsage` 长期不一致。
- **方案**：抽屉打开链接时直接对 store 中的真实对象计数（或保存时合并 `callCount`）。
- **理由**：复用度量（WRR）是产品核心指标，其输入不得漂移。
- **成本**：小。**优先级**：**P2**。

### R12 【P2】网格末尾内联「＋ 新建卡片」

- **问题**：策展台网格末尾有 `rc-add-card`（内联"＋ 新建资源卡"），资源台只有工具条按钮。
- **方案**：资源台网格末尾加同款内联新建卡。
- **理由**：与策展台一致；在浏览位置直接新建，减少视线跳跃。
- **成本**：小。**优先级**：**P2**。

## 五-B、附件体系补充需求（2026-09-11 追加）

### 需求原文（用户拍板）

1. **本地文件导入升级**：支持 HTML / PDF / 图片等**批量导入**，**每个文件关联一张资源卡**；文件以**附件形式**上传到卡片上；交互方式与此前一致，**能通过浏览器打开**。
2. **卡片附件入口**：有附件的卡片在卡面呈现**明显图标**；点击图标 —— **只有 1 个附件 → 直接打开**；**多个附件 → 先弹附件列表，再按用户点击打开对应附件**。

### 现状核实（关键：需求 2 已实现 90%，需求 1 是"改一条链路"）

**附件体系已完备**（无需新建）：

| 层 | 实现 | 说明 |
|---|---|---|
| 数据 | `AssetMeta { id, kind: 'image'｜'html'｜'pdf', name, size, mime, createdAt }` | `models/index.ts:25-33`；挂 `CardBase.assets?` |
| 存储 | IndexedDB `zy_assets`（key=assetId, value=Blob） | `shared/storage/assets.ts`；**主 JSON 只存 meta，Blob 永不进 JSON**（性能红线） |
| 上传 | `AssetManager.vue` `guessKind()` + `putAsset()` | 图片 ≤9 张/卡（单张 ≤10MB）· HTML **单卡唯一** ≤20MB · PDF **单卡唯一** ≤100MB；同类重复上传 = 替换 |
| 卡面徽标 | `AssetBadge.vue` | `🖼 n` / `🧾 n` 分组计数，`@click.stop` 不触发宿主卡片单击 |
| 打开通道 | `openHtmlAsset()`（`utils/htmlAsset.ts`） | 图片 → `AssetPreview` 弹窗（多图左右切换）；HTML/PDF → 落盘 `下载目录/知源附件/` 后 `file://` 打开（Chrome 内置 PDF viewer 渲染）；失败降级 blob |

**需求 2 的差距只有两点**（改 `AssetBadge.vue`，成本极小）：

| # | 现状 | 需求 | 改动 |
|---|---|---|---|
| a | `openList()` **恒弹列表**，1 个附件也要多点一次 | 1 个 → 直接打开 | `openList()` 改为 `list.length === 1 ? openAsset(list[0]) : listOpen = true` |
| b | 徽标只分两档：`🖼 n` 与 `🧾 n`，**PDF 被算进 🧾**（而条目图标是 `📕`，自相矛盾） | 三类各自可见 | 拆为 `🖼 n` / `📕 n` / `🧾 n` 三档徽标 |

**需求 1 的差距是"导入链路走错了"**（改 `CurationCenter.vue`）：

- 现状 `handleFileImport`（`:675-684`）：`makeResource(f.name.replace(/\.[^.]+$/,''), 'file', f.name, newCardCatId())` —— **`link` 写的是文件名本身**，附件**根本没上传**，`assets` 为空。
- 后果链：`toOpenableUrl('file', '报告.pdf')` → 仅文件名 → **返回空**（`link.ts:17-22`）→ 双击只弹「ℹ 该卡未设置链接」（文案也不准确）→ 卡片上无标记、无筛选器 → 用户**无法找到也无法修复**。即 04-18 §三 R7 所指的"哑卡"。
- **且**：`openCard()` 首行（`:377-379`）主动拒绝打开附件卡 —— `if (r.linkType==='file' && /^zy-asset:\/\//i.test(r.link)) { showToast('ℹ 附件卡请到源策展台打开'); return }`。**资源台是附件本体的家，却拒绝打开自己的附件**，与"能通过浏览器打开"直接冲突。

### 方案（R13–R15）

#### R13 【P0】本地文件导入 → 改为"每文件一张带附件的资源卡"

- **方案**：`handleFileImport` 重写为：
  1. 对每个文件调 `guessKind(f.name, f.type)`（复用 `AssetManager` 的判定，扩展名兜底 mime）；
  2. **支持**（image/html/pdf）→ `putAsset(uid('at'), f)` → 生成 `AssetMeta` → 建卡：
     `title = 去扩展名文件名` · `linkType = 'file'` · `link = 'zy-asset://<assetId>'` · `assets = [meta]` · `categoryId = newCardCatId()`
  3. **不支持**（其它类型）→ **跳过并汇总提示**（`已跳过 N 个不支持的文件：a.zip、b.docx`），**不再生成哑卡**。
- **理由**：让导入**一次到位**——文件真身进 IndexedDB，卡片直接可打开；同时**从源头消灭哑卡**。
- **注意**：因 HTML/PDF 是**单卡唯一**，而本方案是"一文件一卡"，**每个文档卡恰好 1 个附件**，天然满足上限约束。
- **拍板补充（Q7）**：不支持的类型（zip/docx/xlsx/mp4）→ **跳过 + 末尾汇总一句**（`已跳过 N 个不支持的文件：a.zip、b.docx`），**不生成哑卡**。
- **拍板补充（Q10 已确认 = 一图一卡）**：图片与 HTML/PDF **一律"一文件一张卡"**，每卡挂 1 个附件；「多图一卡」作为**能力**保留（详情里可继续追加图片至 ≤9 张），**不改变导入语义**。完整规格见 §五-D。
- **成本**：小。**优先级**：**P0**。

#### R14 【P0】资源台开放附件卡打开

- **方案**：`openCard()` 首行的"附件卡请到源策展台打开"分支改为：
  - 卡有 `assets` 且 `link` 为 `zy-asset://` → **就地打开**（图片走 `AssetPreview`，HTML/PDF 走 `openHtmlAsset`）；
  - 无附件且 `link` 为 `zy-asset://`（本体缺失的遗留卡）→ 提示「⚠ 附件本体缺失，请在详情中重新上传」。
- **理由**：真身台必须能打开真身。当前分支是历史遗留的"资源台只当仓库"思路，与新定位冲突。
- **成本**：小。**优先级**：**P0**。

#### R15 【P1】附件入口的"明显化"与计数修正

- **方案**：
  1. `AssetBadge` 徽标由两档拆为**三档**：`🖼 n` / `📕 n` / `🧾 n`（修正 PDF 被计入 🧾 的口径错误）；
  2. 有附件的卡片在**卡片左下角**（或标题右侧）呈现徽标，并给徽标一个**低饱和底色**（`var(--surface-3)` + `1px var(--border)`），保证"明显"但不抢主色；
  3. 单击徽标：**1 个附件 → 直接打开**；**多个 → 弹附件列表**（列表内每行显示 图标 / 文件名 / 大小 / 打开方式提示）。
- **理由**：附件是"卡里装着东西"的唯一信号，必须一眼可见、一击可达。
- **成本**：小。**优先级**：**P1**。

> **需求边界（须拍板，见 §五-C Q6）**：HTML/PDF 是**单卡唯一**。若用户希望"一张卡放多个 PDF"，需先放开 `AssetManager` 的单卡唯一约束——这会影响"重复上传=替换"的既有语义与回归断言，**不在本轮默认范围内**。

### R16 【P0·结构性】资源台当前有**两个入口、两套界面**

- **问题（代码核实）**：资源台本体是 `kind='resource'` 的 Workspace 实体（`isHubWs` = `w.kind==='resource' || w.id===CURATION_WS_ID`）。但：

| 入口 | 路由 | 渲染组件 | 视图 | 排序 | 筛选 | 密度 | 字段池 | 附件徽标 | 右键菜单 | 指标条 |
|---|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 顶栏「资源台」 | `/curation` | `CurationCenter.vue` | 3 | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ |
| 全局设置 →「定位源卡」 | `/workspace/zy-curation` | **`Workspace.vue`（`isHub=true`）** | **4** | **✓** | **✓** | **✓** | **✓** | **✓** | **✓** | ✗ |

  - 证据：`GlobalSettings.vue:1494` `jumpMirrorSource()` → `router.push('/workspace/' + CURATION_WS_ID + '?hl=' + src.id)`；`Workspace.vue:610` `isHub = isHubWs(workspace)`，而 `isHub` **只**用于隐藏 5 指标条（`:23` `v-if="!isHub"`）——其余能力全部保留。
- **结论（R16 勘验后修正 · 2026-09-11）**：`Workspace.vue` 的 `isHub` 分支**能力更全**（字段池、附件徽标、右键菜单、排序/筛选/密度、4 视图），这一点成立。但**"只是路由没指过去"的判断不完整**——
  - `CurationCenter.vue:66` 的 `isMirror = (c) => !!c.curFrom`，而 `curationMigration.ts:93` `migrateHubStructure()` **步骤③已剥离**资源台分类的 `curFrom`（注释原文："镜像方向反转后溯源失效"），**步骤④又清空 `curationProjections`** ⇒ `isMirror()` **恒为 `false`**。
  - 因此 `CurationCenter.vue` 中依赖 `curFrom` 的一整条链路（`mixedCardsOf` 的 `curFrom` 分支 / `live:` 源卡 / `LIVE_BASE` / `onLiveDrop` / `.mirror-node` / `moveProjectionTo`）**全是旧方向死代码**；它相对 hub 分支**真正独有的活能力只有 3 组**：书签 HTML 导入、本地文件导入、资源台侧镜像到策展台（📡/📤）。
  - **性质重判**：R16 不是"改一条路由"，而是 **删死代码（约 40% 篇幅）+ 迁移 3 组活能力 + 重写约 50 条回归断言**。详细勘验、能力差集、断言 A/B/C 分组处置见 **`04-22_开发任务书_资源台收敛R16.md`**。

- **理由**：两套界面是"信息倒挂"的**根本原因**——同一个台面，从不同入口进去看到不同能力，用户无法建立稳定预期。
- **连带影响**：**R0 不再需要**（R1/R2 由"抽共享组件"降级为"删重复实现"）；R13/R14/R15 的改动点落在 `Workspace.vue` 的 `isHub` 分支。
- **成本**：中（迁移两个入口 + 废弃 1503 行；迁移期需保证 `/workspace/zy-curation` 旧链接与 `?hl=` 高亮不失效）。
- **优先级**：**P0（前置，须最先做）**。

### R17 【P1】资源台卡片的「策展台」下拉不含资源台（真身会静默迁走）

- **问题**：`ResourceEditForm.vue:48` `wsOptions = computed(() => store.workspaces)`，而 `store.workspaces` **排除 hub**（`stores/app.ts:18` `w.id !== CURATION_WS_ID`）。于是在资源台打开一张真身卡的详情，「策展台」下拉**没有匹配当前值的选项 → 显示空白**；用户一旦改选并保存，卡片 `workspaceId` 被改写，**静默离开资源台**（真身迁移到策展台），而 `curationProjections` 里的镜像仍指向它。
- **方案**：当 `model.workspaceId === CURATION_WS_ID` 时，在下拉**首位注入一个"资源台（真身）"选项**并默认选中；或在该场景下把字段设为只读、显示"资源台"。
- **理由**：真身归属不该被一个"看不到当前值"的下拉悄悄改掉。
- **成本**：小。**优先级**：**P1**。

### R13 最终规格（本地文件导入）

```
输入：用户多选文件（accept: image/*,.html,.htm,.pdf + 其它）
对每个文件 f：
  1. kind = guessKind(f.name, f.type)          // 复用 AssetManager 的判定（扩展名兜底 mime）
  2. kind === null        → 计入 skipped[]，不建卡
  3. kind === 'image'     → putAsset → 建卡（assets=[meta]）   // 一图一卡
  4. kind === 'html'      → putAsset → 建卡（assets=[meta]）   // 单卡唯一，天然满足
  5. kind === 'pdf'       → putAsset → 建卡（assets=[meta]）   // 单卡唯一，天然满足
建卡字段：
  title      = 去扩展名的文件名
  linkType   = 'file'
  link       = 'zy-asset://<assetId>'
  assets     = [meta]
  categoryId = newCardCatId()                  // 当前视图分类；聚合/待分类视图落「未分类」
收尾：
  ✓ 已导入 N 个文件（共 X MB）
  ⚠ 已跳过 M 个不支持的文件：a.zip、b.docx   ← 仅在 M > 0 时出现
```

> **边界**：一图一卡意味着导入 20 张图会生成 20 张卡。若用户后续需要"图集卡"，可在任一张卡的详情里继续追加图片（≤9 张）——**能力已具备，不需要导入期的特殊分组**。

## 七、一句话总结

> **资源台是"真身台"，它必须先是"主场"，再是"仓库"。**
> 把镜像台有的信息补回真身台（R1）、让用户配的字段在这里也生效（R2）、让计数只出现一个数（R3）、让"复用"在这里能发起（R4）——用户打开资源台，第一眼该看见的是**"我常用的东西，以及它能被用到哪件事上"**，而不是一张张只有标题的卡片。
