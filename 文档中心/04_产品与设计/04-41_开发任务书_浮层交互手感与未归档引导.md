## 一、三项需求原文

| ID | 原文（`04-16`） |
|---|---|
| **D1** | 浮层唤起后 `setTimeout(focus, 50)`，有"前几个字符丢失"风险 → 改同步 `focus()` 或 `requestAnimationFrame`。成本：极小 |
| **D2** | `Esc` 语义单一：直接关浮层，搜索框有内容时误关会丢失查询 → 两段式：**有内容先清空，空再关闭**。成本：小 |
| **E1** | "未归档"治理入口深，而动线断点正是"采集后不归位" → 采集/搜索浮层保存后，若该卡未挂项目/指标，回执带一行轻引导「未归档 · 去归位」。成本：小 |

## 二、只读勘验结论

### 2.1 D1：不是一处，是**四处**同一个 `setTimeout(…, 50)`

| 行 | 场景 | 代码 |
|---|---|---|
| 361 | 搜索浮层输入框 | `setTimeout(() => input?.focus(), 50)` |
| 1203 | 资源卡采集（聚焦标题并全选） | `setTimeout(() => { titleInput.focus(); titleInput.select() }, 50)` |
| 1395 | 任务卡采集（有选区聚焦描述，否则标题） | `setTimeout(() => { (hasSel ? descInput : titleInput).focus() }, 50)` |
| 1477 | 好奇心采集（聚焦并把光标移到末尾） | `setTimeout(() => { textarea?.focus(); …setSelectionRange(…) }, 50)` |

- 四处都在 `root.appendChild(panel)` **之后**，元素已在 DOM 中；`openOverlay()` 里 `root.className = '… open'` 已先执行（`.open{display:block}`）⇒ **同步 `focus()` 完全可行**，50ms 是历史遗留的"等入场动画"。
- 代价：唤起后立刻打字，前 ~50ms 的按键会被宿主页面吃掉（D1 原文的风险描述）。

### 2.2 D2：Esc 入口只有两处，且**没有全局监听**

- `onSearchKeydown`（搜索 input 的 keydown）：`e.key === 'Escape'` → `closeOverlay()`（`:975`）。
- `onSavedKeydown`（保存回执态）：Escape → 关闭（`:1334`）——回执态不是输入框场景，**不在 D2 范围**。
- **无 document 级 Escape 监听**（`openOverlay()` 只挂 scrim 的 click）⇒ 焦点离开输入框后 Esc 无效。这解释了"为什么 Esc 有时没反应"，但**不本轮改**（改监听层级会牵动宿主页面快捷键，属 D5 范畴）。
- ⚠ **另有一个 `Esc` 按钮** `#__zy_esc__`（`:346`，点击 → `closeOverlay()`）。它是**显式点击意图**，与"反射性按键"性质不同 ⇒ **按钮保持直接关闭**，只把**按键**改两段式。二者语义不同是有意的，写进注释免得后人"统一"掉。

### 2.3 E1：「归位」对两类卡含义不同，但判据都现成

| 卡类型 | 归位 = | 判据（现成） |
|---|---|---|
| 资源卡 | 放进某个分类 | 采集面板「分类」下拉 `<option value="">📥 待分类</option>` 是**默认项**（`:1181`）⇒ `catSelect.value === ''` 即"落在待分类 = 未归档" |
| 任务卡 | 挂到某个项目 | `projSel.value`（`:1411` `projectId: projSel.value \|\| undefined`）⇒ 空即未归档 |

> E1 原文写"未挂项目/指标"，落到两类卡上就是：**资源卡看分类、任务卡看项目**。指标（`metricId`）依附于项目，项目为空时指标必然为空 ⇒ 只判项目即可，不必判两个。

### 2.4 ★ 顺带发现：任务回执的落点**文案指错了页面**

`:1423-1424`：

```ts
const tcRoute = task.projectId ? '/compass/projects?p=' + task.projectId : '/?hl=' + task.id
showSaved('✓ 任务已保存 · Enter 打开' + (task.projectId ? '项目' : '方向台'), …)
```

- 无项目时路由是 `/?hl=<id>` —— **`/` 是调度台**（`CompassHome.vue`），**不是方向台**（`/compass`）。
- 回执却写「打开**方向台**」⇒ 用户按 Enter 会落到调度台，与文案不符。

这与 R91 刚清偿的「任务中心顶部」（注释指向已退役页面）是**同一类坏账**：**文案指向的页面与实际落点不一致**。本轮一并修（一行文案，零风险）。

## 三、改动清单

### T1 · D1：四处 `setTimeout(…, 50)` → 统一走 `focusWhenReady()`

新增一个共享 helper（**一个口径、多个出口**——四处写法不同但语义相同，必须抽一处）：

```ts
/**
 * R92（D1）：浮层唤起后的聚焦——**不再 setTimeout(…, 50)**。
 *
 * 原实现延迟 50ms 是为了等面板入场动画，代价是"唤起后立刻打字"的前几个字符
 * 会丢（焦点还没落到输入框，按键被宿主页面吃掉）。面板此时已在 DOM 中
 * （root.appendChild 先于本调用，且 .open 已置），同步 focus 即可生效。
 *
 * 仍保留一帧兜底：宿主页面若在同步阶段抢回焦点，下一帧再争一次
 * （rAF ≈16ms，远小于原 50ms）。正常情况下兜底不触发。
 */
function focusWhenReady(el: HTMLElement | null, opts?: { select?: boolean; toEnd?: boolean }) {
  if (!el) return
  const doFocus = () => {
    el.focus()
    if (opts?.select && typeof (el as HTMLInputElement).select === 'function') (el as HTMLInputElement).select()
    if (opts?.toEnd && typeof (el as HTMLTextAreaElement).setSelectionRange === 'function') {
      const n = (el as HTMLTextAreaElement).value.length
      ;(el as HTMLTextAreaElement).setSelectionRange(n, n)
    }
  }
  doFocus()
  requestAnimationFrame(() => { if (document.activeElement !== el) doFocus() })
}
```

四处替换：

| 行 | 改为 |
|---|---|
| 361 | `focusWhenReady(input)` |
| 1203 | `focusWhenReady(titleInput, { select: true })` |
| 1395 | `focusWhenReady(hasSel ? descInput : titleInput)` |
| 1477 | `focusWhenReady(textarea, { toEnd: !selection })` |

> ⚠ 1477 原本 `setSelectionRange` 只在 `!selection` 时执行 —— 有选区时 `textarea` 已被填入选区文本，光标应停在开头让用户检查。**这个条件必须保留**，不要无脑加 `toEnd`。

### T2 · D2：搜索框 Esc 两段式

`onSearchKeydown` 的 Escape 分支改为：

```ts
} else if (e.key === 'Escape') {
  // R92（D2）：两段式——有内容先清空，空再关闭（误按 Esc 不再丢失查询）
  const input = document.getElementById('__zy_si__') as HTMLInputElement | null
  if (input && input.value) {
    e.preventDefault(); e.stopPropagation()
    input.value = ''
    searchSelIndex = 0; searchSelId = ''
    renderTypeTabs(); runSearch('')
  } else {
    closeOverlay()
  }
}
```

- **按钮 `#__zy_esc__` 保持 `closeOverlay()` 不变**（显式点击 = 明确要关），并在其上补 `title="关闭（Esc）"` 说明。
- 注释写明"为何键与按钮不同"——否则后人会当成 bug"统一"掉。

### T3 · E1：未归档轻引导

**资源卡**（`saveCapture`）：

```ts
const filed = !!catSelect.value          // R92（E1）：空 = 落在「待分类」= 未归档
…
showSaved(filed ? '✓ 已入台 · Enter 打开看板' : '✓ 已入台 · 未归档 · Enter 去归位', () => { … })
```

**任务卡**（`saveTc`）：

```ts
const filed = !!projSel.value            // R92（E1）：未挂项目 = 未归档
const tcRoute = task.projectId ? '/compass/projects?p=' + task.projectId : '/?hl=' + task.id
showSaved(
  filed ? '✓ 任务已保存 · Enter 打开项目' : '✓ 任务已保存 · 未归档 · Enter 去归位',
```

> **动作不变，只换措辞**：Enter 的落点本来就是"定位到这张卡"，未归档时这句提示只是**告诉用户为什么要去那儿**（去把它归位）。不新增路由、不新增写入。
