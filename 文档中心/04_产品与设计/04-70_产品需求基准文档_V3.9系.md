## 一、产品前提与一句话定位

**前提**：用户是长时间基于浏览器做信息获取、信息论证、信息处理的知识工作者。

**一句话**：知源（Ownway）是一个 Chrome 浏览器扩展（MV3，接管新标签页），是知识工作者在信息处理过程中的**个人认知调度中枢**——100% 本地运行，零账号零云端。

**两条生命线**（验收优先级按此排序）：
1. **性能、响应速度、稳定性是第一生命线**——全局检索、快捷操作必须快，慢等于没有。
2. **UI 设计、交互、外观是第二生命线**——"看见"是产品灵魂：看见任务、看见项目、看见方向树、看见策展台，所有的看见都要符合阅读的审美。

## 二、核心抽象：三卡是一切起点

产品里只有三种出发卡，**卡片产生的主场景是浏览器内的信息获取与处理过程，通过快捷键完成捕获**：

| 卡型 | 是什么 | 归宿 |
|---|---|---|
| **资源卡** `ResourceCard` | 有出处的事实资产（网页 / 文件 / Obsidian / 附件） | 资源卡池（隐藏实体 `CURATION_WS_ID`） |
| **任务卡** `TaskCard` | 可执行事项，需要投入时间精力去行动、被跟进、被闭环 | 任务卡池 |
| **好奇心卡** `CuriosityCard` | 一闪而过的念头 / 问题 | 好奇心卡池（全局池，不归属任何台） |

**数据形态**：三类卡 = 三张数据表，捕获后统一沉淀到卡片池管理。捕获不是目的，**后续的使用才是产品精髓**：让卡片在需要的时候能被快速调用、被论证、被展示。

**第四类对象**：策展台内的「论证节点卡」`ArgumentCard`——只服务于策展叙事，**不属于三卡池**，随台存亡。

## 三、使用的两个方向（产品的价值双引擎）

卡片的使用分两方面，对应产品的两大价值闭环：

### 方向 A · 解决问题（从自己的问题到他人的问题，助力专业能力变现）

三个动词，构成"解决问题"的完整链路：

| 动词 | 定义 | 产品承接 |
|---|---|---|
| **被调用** | 池里的三类卡，在需要时能快速找到 | 全局检索（关键词/拼音/AI 自然语言匹配，最高频）；任务卡、好奇心卡的跟进闭环中，AI 对资源池做支撑卡匹配；策展台按主题节点关联资源卡 |
| **被论证** | 在职场商务活动中快速调出权威数据、官方文件并直达原文 | 资源卡快速采集 + AI 自动打标签 + 全局检索 / AI 辅助检索 |
| **被展示** | 围绕重复的问题给出解决方案，并分享给他人实现商业价值 | 策展台：顶部指标数据（卡数 / 核心论点卡 / 附件列表 / 分享为 HTML）+ 思维导图策展（金字塔架构 = 树状向下；树状架构 = 全部向右）；节点挂资源卡；**分享的 HTML 能打开节点下资源卡的链接** |

方向 A 的商业闭环：**解决问题 → 解决重复问题 → 把解决方案分享出去**。

### 方向 B · 明确赛道（知道为什么做、往哪里走，成就自己）

方法论链路：**任务卡 → 方向树 → 今日三件事**。

1. **任务卡**：用户快捷写入与采集，沉淀到任务卡池统一管理。
2. **方向树**（个人赛道澄清与管理的方法论）：
   - 从个人的愿景、使命、战略目标出发；
   - 围绕战略目标构建项目；
   - 把项目拆成可衡量的成功指标；
   - 把任务挂到「项目的某个成功指标」下——明确这条任务在推进哪个项目的哪个指标；
   - 由此，任务执行有目的，目的背后是一整条个人发展方向。
   - **方向树两大作用**：① 全景展现个人赛道与航线（看见当下的状态、方向、位置）；② 全景呈现项目图（看见当前聚焦的事件集，明确努力方向与成功目标，有的放矢）。
3. **今日三件事**：每天从任务池选出三件要执行的任务——每日有核心标的，每件任务都挂在人生方向上，行动持续在轨道上，不偏航、不做漫无目的的努力。

## 四、产品架构

### 4.1 技术形态

Chrome / Edge / Brave MV3 扩展，三层壳：

| 层 | 职责 |
|---|---|
| `background/` Service Worker | 快捷键命令、浮层注入、单例定位、消息路由 |
| `content/` 网页浮层 | 在任意网页上唤起搜索 / 采集 / 好奇 / 任务四浮层（Shadow DOM，Vanilla JS） |
| `newtab/` 主应用 | Vue 3 + TS(strict) + Vite + Pinia + hash 路由；接管新标签页的全部主界面 |

数据：100% 本地（`chrome.storage.local` 主 JSON + IndexedDB 存附件二进制）；Airtable 为可选单向同步出口。

### 4.2 页面地图（路由即信息架构）

| 路由 | 页面 | 角色 |
|---|---|---|
| `/` | **调度台** | 今天的行动出发点：今日三件事、主攻速览、手边卡 |
| `/deck/:kind` | **卡片池二级页**（task / curiosity / resource） | 三卡各自的集中管理面 |
| `/compass` | **方向台** | 方向树即首屏：战略目标 → 项目 → 指标 → 任务；项目塔 / 项目全景双视图 |
| `/compass/projects` | 项目总览 | 全部项目的检索与管理 |
| `/workspace/:id` | **策展台** | 主题策展：指标头 + 金字塔 / 树状思维导图 + 节点挂卡 + 分享 HTML |
| `/profile` | **画像洞察** | 使用路径深度洞察：热力图、今日/本周/月度/年度洞察、指标驾驶舱 |
| `/settings` | 设置中心 | 数据 / 字段 / 标签 / Airtable / 快捷键 / 主题 / AI 设置 |
| `/recycle` | 回收站 | 软删恢复 |
| `/manual` | 使用手册 | 内置手册与更新日志 |

### 4.3 功能模块清单

| 模块 | 核心职责 |
|---|---|
| **捕获层** | 全局快捷键三件套；网页浮层采集（资源 / 任务 / 好奇）；书签与 Markdown 导入 |
| **卡片池** | 三卡三张表统一管理；批量操作、打标、置顶、软删回收 |
| **全局检索** | ⌘K：关键词 / 拼音 / 归一化 / 多词 AND 模糊检索 + AI 自然语言匹配；检索结果直达详情、链接、定位 |
| **方向台（方向树）** | 愿景 / 使命 / 战略目标 / 项目 / 成功指标 / 任务 六层链；项目下一步；项目塔与项目全景 |
| **今日三件事** | 每日从任务池选三件；与主攻项目、方向树挂钩；AI 推荐排序 |
| **策展台** | 主题策展空间 ×N；金字塔 / 树状双架构；节点关联资源卡；顶部指标（卡数 / 核心论点 / 附件）；分享为自包含 HTML（可打开节点下资源卡链接） |
| **AI 赋能层** | 见第六章 |
| **画像洞察** | 年度热力图；今日 / 本周 / 月度 / 年度洞察；指标数据驾驶舱 |
| **数据与同步** | 全量导入 / 导出；Airtable 同步；本地备份 |
| **系统支撑** | 设置中心、AI 设置、更新日志、使用手册、回收站 |

## 五、数据关系（一张图）

```
                    ┌──────────────┐
                    │  愿景 / 使命  │ ← linkedResourceIds / linkedCuriosityIds（单向关联）
                    └──────┬───────┘
                           │
                    ┌──────┴───────┐
                    │ 战略目标 Direction │── projects[]
                    └──────┬───────┘
                           │
                    ┌──────┴───────┐
                    │ 项目 Project  │── isFocused 主攻 · nextStep 下一步 · metrics[] · order/pinned
                    └──────┬───────┘
                           │
                    ┌──────┴───────┐
                    │ 成功指标 Metric │── taskIds[]（任务挂指标的第一路径）
                    └──────┬───────┘
                           │
   ┌─────────────┐   ┌─────┴──────┐   ┌──────────────┐
   │  资源卡池    │   │  任务卡池   │   │  好奇心卡池   │
   │ ResourceCard │   │  TaskCard  │   │ CuriosityCard│
   └──────┬──────┘   └─────┬──────┘   └──────┬───────┘
          │                │                  │
          │   归属路径：task.projectId / task.metricId / metric.taskIds（三路并集，按 id 去重）
          │                │
   ┌──────┴──────┐         │
   │  策展台 ×N   │ 镜像投射 │（引用式呈现，源数据零影响；节点还可关联资源卡）
   │ 金字塔/树状  │◄────────┘
   │ 论证节点卡   │── 分享为 HTML（节点下的资源卡链接可打开）
   └─────────────┘

   今日三件事：每日从任务卡池选出 3 条，挂回主攻项目与方向树。
   画像洞察：以事件日志 + 按日快照聚合，纯读取零写入。
```

**红线**：
1. **三卡互不持有对方 id**（卡间零挂载）。明文豁免的两条记录型关联：`CurationProjection`（资源→策展台镜像）、`SupportLink`（任务→资源"支持"记录）——独立表记录，卡对象本身不挂对方。
2. 任务归属唯一口径：`projectId` / `task.metricId` / `metric.taskIds` 三路并集，按 id 去重（任一视图不得出现"总数对、明细少"）。
3. 删除一律软删（`deletedAt`），回收站可逆。

## 六、AI 赋能清单（六类）

| # | 对象 | AI 做什么 |
|---|---|---|
| 1 | 卡片管理 | 结合方向树信息构建**收敛的标签体系**，并据此给卡片打标（标签不许发散） |
| 2 | 任务卡 | 结合任务内容与其所在项目：子任务拆解、字段补全、匹配资源卡池里的支撑卡 |
| 3 | 资源卡 | 结合卡内容补全字段，从既有标签体系里选标打标 |
| 4 | 项目 | 成功指标拆解建议、当前项目情况诊断 |
| 5 | 今日三件事 | 结合方向树与主攻项目情况，推荐今日三条任务 |
| 6 | 使用路径洞察 | 今日 / 本周 / 月度 / 年度洞察 |

AI 红线：本地规则先行、AI 续写受限（不许改动已计算的数字）；启动零 AI 调用、打开页面零写入。

## 七、非功能需求

| 维度 | 要求 |
|---|---|
| **性能（第一生命线）** | 全局检索与快捷操作瞬时响应；附件二进制只进 IndexedDB，主 JSON 绝不存 base64；增量渲染与按需加载 |
| **视觉与交互（第二生命线）** | "看见"是灵魂：四主题（深空薰衣草 / 光速黑 / 极简白 / 纸墨白）WCAG 对比度门禁全绿；方向树、策展台、项目、任务的呈现必须符合阅读审美 |
| **稳定性** | 全量门禁：静态回归 2,023+ 断言只增不减、E2E 44+ 真点真写库、四主题 100 图实拍、死样式 / 孤儿 / 循环依赖零容忍 |
| **数据安全** | 100% 本地；软删 + 回收站；导入前先校验、合并后净化（中心论点重复等） |
| **隐私** | 零账号零云端；Airtable 同步为用户显式配置的可选项 |

## 八、验收基准（后续开发的检查口径）

每个迭代批次交付时必须同时满足：

1. **过本文档**：新需求先回答"它服务三卡的哪个动词 / 哪个方向"，过不了的不做。
2. **过门禁**：`vue-tsc` 0 错、静态回归 0 失败、E2E 0 失败、四主题实拍与对比度全绿、ZIP ≤ 900KB。
3. **过文档回填**：架构总览、认知基线、交付说明三处数字与实测同源，不许引用旧文档数字。

**评审三问**（沿用 04-6）：
① 砍掉它，"捕获 → 调用/论证/展示"或"任务 → 方向树 → 三件事"这两条闭环会坏吗？
② 能否用现有能力组合实现，而不是新增模块？
③ 失败态（空数据 / 并发写 / 老库兼容）想清楚了吗？
