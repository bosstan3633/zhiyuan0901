## 二、产品定位的精神内核——UI 的价值锚

### 2.1 从定位到 UI 的推导链

产品一句话本质（认知基线 §〇 / 04-70 同源）：

> **知源调度台（Ownway）= 你在浏览器里的个人认知调度中枢。它不生产智能，而是组织智能——让你见过的每一个信息，都具备在正确时刻被召回、被论证、被展示的能力。**

两条生命线（04-70 §一原文）给出了 UI 的优先级与分量：

> 「1. 性能、响应速度、稳定性是第一生命线——慢等于没有。2. **UI 设计、交互、外观是第二生命线——"看见"是产品灵魂**：看见任务、看见项目、看见方向树、看见策展台，所有的看见都要符合阅读的审美。」

**推导链**：UI 在这个产品里不是「包装」，而是**产品价值的一半交付面**——产品的核心承诺「三秒进出」「今日三件事挂在方向上」「成果可策展分享」，全部要靠 UI「被看见」才成立。**性能决定产品能不能用，UI 决定产品的价值能不能被感知。**

### 2.2 六条价值支柱（UI 的价值观基础）

从品牌手册（01-1/01-2/01-3）、04-70 PRD、认知基线中提炼，每条附原文锚点：

| # | 价值支柱 | 原文锚点 | 一句话内涵 |
|---|---|---|---|
| V1 | **调度致用** | 主 slogan「万千可调用，自有我方向」；判词「通用工具比知源更能装，知源比通用工具更能调」 | 收藏不是目的，正确时刻的召回才是；三秒进出是硬承诺 |
| V2 | **看见是灵魂** | 04-70 两条生命线；「符合阅读的审美」 | 每个台面必须让它的核心对象一眼被看见，且经得起阅读 |
| V3 | **外部万千，内有主线** | 01-3 视觉主题；心智画面「一条属于用户的行动路径」 | 不是仓库、不是驾驶舱，是行动路径；主线永远可见 |
| V4 | **镜子不鞭子** | R03；品牌个性「清醒而不冷漠，可靠而不僵硬」 | 呈现不评价、不制造管理压力、不打焦虑 |
| V5 | **主权与可信** | 01-4「用户是 owner」；本地优先七不原则 | 无账号无追踪，一切状态可见、一切数据可带走 |
| V6 | **专业工具感** | 键盘优先传统（v-pressable / 24 组快捷键）；「AI 是部队，知源是指挥台」 | 独立知识工作者的指挥台，键盘优先、克制冷静 |

### 2.3 价值 → UI 原则映射表（本文核心）

每条价值推出一条 UI 总则、一组「必须」与一组「禁止」。**任何新 UI 提案先过这张表：说不出守护哪条价值的样式不加，违反禁止项的设计不批。**

| 价值 | UI 总则 | 必须体现 | 明令禁止 |
|---|---|---|---|
| V1 调度致用 | **效率即美学** | 视图切换 <40ms；态切换 ≤150ms；路由零动画；`Ctrl+K` 全场景可达；操作路径最短 | 装饰性动画、庆祝弹窗/撒彩带、呼吸类常驻动画、任何为好看加的等待 |
| V2 看见是灵魂 | **每屏一个主角** | 每个工作面唯一 display 级主体（22px 全页唯一）；一屏字阶 ≤3 级；行高与字号成对；数字 tabular-nums | 层级倒置、双主角抢焦、把「仪表盘感」带回台面 |
| V3 内有主线 | **主线可见，路径成序** | 调度台以「今日三件事」开屏；方向台战略骨架单行状态带 + 项目塔主角；策展台金字塔/导图为画布主角 | 文件柜/书架/文件夹隐喻；「信息汇入搜索框」隐喻；空白被视为失败（空白是保留选择权） |
| V4 镜子不鞭子 | **中性读数，边界用色** | 状态读数默认中性 + 口径 tooltip；红=全站最稀缺色，只属破坏性；空态三段式（不羞辱）；完成态安静收束 | 评价式措辞（「落后了」「才完成 1 个」）；KPI 压迫排版；用红色催办 |
| V5 主权与可信 | **状态透明，静谧可信** | 保存状态点常在且 ≥28px 命中盒；导出入口可达；四主题同一结构语言；对比度门禁全绿 | 云端/订阅暗示元素；通知轰炸；追踪类 UI（「猜你喜欢」） |
| V6 专业工具感 | **键盘优先，令牌纪律** | 一切可点击面 Tab 可达 + Enter/Space 触发（v-pressable）；热区 ≥28px；焦点环 2px；系统图标一律 Icon 组件（103 个线性 SVG） | 只能鼠标点的界面；emoji 当系统图标；硬编码色值/字号；样式绕开 tokens.css |

### 2.4 台面价值审计（四价值 ↔ 台面，逐一对位）

「四价值 ↔ 四页面一一对应，改版不许错位」（认知基线 §1.5）。逐台面审计现状：

| 台面 | 路由 | 承载价值 | 唯一主角（现状） | 审计结论 |
|---|---|---|---|---|
| 调度台 | `/` | 留下好奇 + 今日行动 | 今日三件事（恒三槽） | ✅ 对位；V6 原型主张进一步「案头化」，待拍板（O-15） |
| 方向台 | `/compass` | 看见方向 | 项目塔（战略骨架 V3.9.15 起默认折叠） | ✅ 对位 |
| 策展台 | `/workspace/:id` | 策展成果 | 金字塔 / 思维导图画布 | ✅ 对位；顶部已收成一行（V3.9.10） |

## 三、设计规范（价值锚定版）

### 3.0 规范架构

```
价值层（§2.3 六支柱，不随版本变）
   ↓ 推导
条文层（本节，随版本演进，演进须注明所护价值）
   ↓ 落地
令牌层（tokens.css 唯一真源，数值以它为准）
   ↓ 守护
门禁层（regression / theme-contrast / 四主题实拍 / M6 / a11y-tab-audit）
```

### 3.1 色彩与主题

| 条文 | 规范 | 所护价值 |
|---|---|---|
| C-1 表面阶梯 | 层级只由四级表面（`--bg → --surface → --surface-2 → --surface-3`）+ 1px 发丝线承载；阴影只留给悬浮弹层 | V2、V6 |
| C-2 accent 纪律 | 每主题唯一 accent，只用于：主行动、当前态、选中环、焦点环；一处界面同时最多一个 accent 实心面 | V2、V6 |
| C-3 状态色语义 | ok/warn/danger 低饱和；**红是全站最稀缺色，只属破坏性操作**；镜面读数默认中性色 + 口径 tooltip | V4 |
| C-4 对比度门禁 | `--text/--bg ≥ 4.5`、`--text-3 ≥ 3.0`、白字/accent ≥ 4.5（theme-contrast 常驻） | V5 |
| C-5 文本四档 | 文本层级只用 4 档透明度令牌，不另设灰阶 | V2、V6 |
| C-6 禁项 | 硬编码色值（豁免：主题样例板、导出/分享纸样的固定配色）；氛围渐变、聚光卡片 | V6 |

### 3.2 字阶与排版

| 条文 | 规范 | 所护价值 |

| T-1 九级一档一职 | micro 9 / tiny 10 / caption 11 / sub 12 / body 13 / title 15 / headline 17 / display 22（+34 级预留）；一屏 ≤3 级、display 全页唯一 | V2 |
| T-2 六层字阶契约 | 愿景 22 › 使命 17 › 项目 17 › 目标 15 › 指标/任务 13；**项目>目标是有意取舍，不许当 bug 修** | V2、V3 |

### 3.3 间距与圆角（★本节含两笔新裁定）

| 条文 | 规范 | 所护价值 |
|---|---|---|
| S-1 间距七档 | `--sp-1..7` = 4/8/12/16/24/32/48；页面边距 sp-6/7、区块间隔 sp-5/6、同组内聚 4–8、组间 12–16；**禁止全体等距** | V2、V3 |
| S-2 ★gap 阶化 | `gap` 只允许取七档 sp 值（或 0）；现存 14 种散值（8/6/10/5/7/9/…）收敛至七档（见 O-02） | V6 |
| S-3 圆角六档 + 胶囊裁定 | xs4 / sm8 / md10 / 12 / lg14 / xl18；同族同圆角、嵌套外大内小。**★新裁定：新增 `--radius-full`（999px）令牌，胶囊形态合法化但限定用途**——只用于筛选胶囊、状态 chip、页签（tab）三类；卡面/按钮/输入框禁用胶囊 | V6、V2 |
| S-4 行语言双轨 | 「可点击列表行」全站只允许两种形态（见 3.4-B），各自用令牌，不出现第三种 | V6、V2 |

### 3.4 组件规范（★收口空白的增量）

**A. 按钮系统（现状：30+ 前缀并行——gs-btn / mini-btn / ai-btn / dz-btn / gp-btn / rb-btn / pi-btn / pcp-btn / hero-btn / icon-btn 等各写各的）**

| 阶 | 用途 | 视觉 | 一屏配额 |
|---|---|---|---|
| primary | 主行动（全屏唯一） | accent 实心 + 白字 | 1 |
| secondary | 常规动作 | surface-2 底 + 发丝线 | ≤3 |
| ghost | 低频/工具位 | 透明底 + hover surface | 不限 |
| danger | 破坏性 | danger 色，须二次确认或可撤销 | 按需 |

统一为 `<ZButton>` 组件（或先立 `btn` 基类 CSS），icon 按钮统一 `icon-btn`（28px 热区）。迁移路径见 O-05：**新代码一律用新系统，旧前缀按页面逐批迁移，dead-css-scan 钉住不回流。**

**B. 列表行系统（现状三种规格并行：`pcp-row` 7px 10px / `rb-item` 12px 14px / `dz-row` 发丝线无卡面）**

| 形态 | 适用 | 规格 |
|---|---|---|
| 卡面行 | 卡池、回收站等「对象管理」列表 | surface 底 + 发丝线 + radius-sm + 内距 `--card-pad-*` + 行距 `--card-gap` |
| 发丝线行 | 下钻明细、抽屉内清单等「阅读型」列表 | 无卡面，1px 分隔线 + 8px 纵距 + gap 12 |

**C. 既有契约维持不变**：EmptyState 三档四段式（全站唯一实现）、Toast（右上 320px / 2.4s / 撤销 6s）、Drawer 全局抽屉栈（Esc 只关最上层）、Modal/ConfirmDialog、徽章族 4px 圆角小胶囊、AiEntryButton 统一 AI 入口。

### 3.5 动效

三档时长（120/150/250ms）× 三套曲线（ease-out-soft / emphasis / spring）；**交互三戒**：路由零动画、态切换 ≤150ms、呼吸常驻动画禁止；成功回弹全站至多 1 处；`prefers-reduced-motion` 全局尊重（现存 7 处已接）。（所护价值：V1）

### 3.6 密度与断点（★本节含一笔新裁定）

| 条文 | 规范 |
|---|---|
| D-1 ★密度裁定 | 现状：`data-density` 4 令牌零消费、开关空转。**二选一，不允许维持现状**：(a) 接通——卡面行/卡面间隙改读 `--card-pad-*/--card-gap`，compact 档真实生效；(b) 退役——删令牌与快捷面板入口，对用户诚实。建议 (a)，工作量小且行系统统一（O-03/O-06）后自然达成 |

## 四、优化方案（15 项 · 三批）

> 每项格式：问题（证据）→ 方案 → 验收判据。全部遵循仓库纪律：断言只增不减、判据重指不删、四主题逐一走查、每轮落交付说明。

### P0 批 · 规范收口（违反已立规范的纪律债，1–2 轮可清）

**O-01 圆角纪律收口**（证据：99px/999px 胶囊字面量 **119 处**实测，tokens.css 头注明言「99px 胶囊退役」仍大量在用；非阶值 5/6/7/9px 共约 200 处）
方案：按 S-3 裁定新增 `--radius-full`；筛选胶囊/状态 chip/页签三类替换为令牌，其余胶囊逐处改 lg/sm；非阶值就近归入 6 档。
判据：`grep -rE 'border-radius:\s*(99|999)px'` 归零（或仅剩令牌定义处）；dead-css-scan 无新增死样式；四主题实拍无回归。

**O-02 间距纪律收口**（证据：`gap:` 字面量 14 种取值，8px×131 / 6px×94 / 10px×65 / 5px×56 / 7px×33 / 9px×26…；`--sp-*` 仅 91 处）
方案：按 S-2 七档收敛，5→4、6→8、7→8、9→8、10→12（视觉就近归档，逐页走查防错位）。
判据：gap 字面量种类 ≤7 档枚举集合；M6 三档实拍像素级对账（吸取 V3.8.42「像素 A/B 假绿」教训——新旧图必须真是两张）。

**O-03 密度系统裁定**（证据：`--card-pad-vert/horz`、`--card-gap`、`--card-min-w` 四令牌在 tokens.css 之外**零消费**；开关入口仍在快捷面板，点了无反应）
方案：按 D-1 裁定执行（建议接通：行系统统一后行距/内距改读密度令牌）。
判据：切换 compact/cozy 后至少卡面行距与池列表肉眼可变；或入口删除 + 回归断言更新（重指不删）。

**O-04 字号残留收口**（证据：字面量约 100 处，集中在图标位 14/16px 与 18–38px 大标题）
方案：图标位改 `--icon-*`；大标题归 display/headline；逐处确认不破坏 T-1「display 全页唯一」。
判据：字面量字号清零（豁免名单白名单化）；焦点契约断言不红。

### P1 批 · 结构统一（组件债，3–5 轮）

**O-05 按钮组件统一**（证据：30+ 按钮类前缀并行，gs-btn×40 / mini-btn×38 / ai-btn×21 / dz-btn×20…）
方案：立四阶按钮契约（3.4-A），新代码一律新系统；按台面逐批迁移（建议顺序：回收站 → 卡片池 → 设置 → 方向台 → 全局弹窗）。
判据：新增 `regression` 分片断言「新按钮类出现后旧前缀不得再增长」（棘轮）；每批迁移四主题实拍。

**O-06 列表行统一**（证据：`pcp-row` / `rb-item` / `dz-row` 三种行规格并存）
方案：按 3.4-B 双轨制统一——卡面行一个基类、发丝线行一个基类，三处实例收编。
判据：行规格种类 = 2；密度令牌在行组件中真实消费（与 O-03 联动）。

**O-07 死资产清理**（证据：UnoCSS 接入构建但 0 处使用且 shortcuts 残留退役绿 accent `rgba(58,107,76,…)`；workspace.css `.res-card` 全套无渲染点；App.vue 三个 `.topbar-inner.align-*` 类定义完全相同）
方案：UnoCSS 移除或激活（二选一拍板）；死样式删除（跑 gen-code-index + dead-css-scan 确认）；重复类合并。
判据：构建产物不含 uno 虚拟模块（或 shortcuts 更新为现行 accent）；dead-css-scan 0 新增。

**O-08 `outline:none` 54 处复核**（证据：V3.9.16 交付说明自认残余风险）
方案：逐处确认有等效焦点样式（自绘 ring 或 focus-visible 覆盖）；无等效的补齐或移除 outline:none。
判据：键盘走查脚本（Tab 遍历）在四主题下焦点可见率 100%。
