## 二、方向 ① · 资源生命周期

### 2.1 三态模型

| 状态 | 判定条件 | 视觉 | 默认视图 |
|---|---|---|---|
| 🔥 **活跃** | `lastCalledAt >= now - 30d` **或** `createdAt >= now - 14d` | 无特殊标记（正常） | ✅ 显示 |
| 🧊 **冷却** | 不活跃，且 `lastCalledAt >= now - 90d` | 卡片右上角 🧊 微标（不抢占注意力） | ✅ 显示 |
| 📦 **归档** | 不活跃，且 `lastCalledAt < now - 90d`，或用户手动归档 | 仅在归档区可见 | ❌ 隐藏 |

**关键设计原则**：
- 三态是**计算属性**（纯读 `lastCalledAt` / `createdAt`），不落存储——零数据模型变更
- **归档**是唯一需要写入的操作：卡片加 `lifecycleArchived: true` 标记（可逆）
- 新卡有 14 天宽限期（创建即活跃，避免"刚收录就被标冷却"的负面体验）
- 未曾调用过的卡（`callCount = 0`）按 `createdAt` 计算年龄

### 2.3 交互规则

| 操作 | 行为 |
|---|---|
| 单击冷却卡「归档」 | 该卡 `lifecycleArchived = true`（从默认视图消失，进入归档区） |
| 「📦 归档全部冷却卡」 | 批量归档（确认框报数），逐条设 `lifecycleArchived` |
| 归档区「↩️ 恢复」 | 清除 `lifecycleArchived`（回到冷却态，重进默认视图） |
| 归档区卡片双击 | 照常打开链接（归档≠删除，只是"眼不见"） |
| 全局搜索 | 归档卡**默认不出现**；搜索结果底部有"另有 N 张归档卡匹配——点击查看" |
| 冷却卡「忽略 30d」 | 临时重置 `lastCalledAt = now`（延后 30 天再评估，不改变调用计数） |

### 2.4 数据模型影响

| 变更 | 类型 | 说明 |
|---|---|---|
| `lifecycleArchived?: boolean` | ResourceCard 可选字段 | 归档标记（可逆）；**零迁移**（缺省 = false） |
| 其余 | 无 | 三态纯计算，不落存储 |

### 2.5 明确不做（本期）

不做：自动归档（仅手动/批量手动）、归档区独立路由、归档卡独立搜索入口、生命周期报表导出。

## 三、方向 ③ · 调度画像周报

（与上一版设计一致，此处仅列要点——完整设计见交互原型）

- **四段式**：调度总览（4 大数字+环比）/ 方向活跃度（条形图）/ 资源调用 TOP 5 / 好奇心转化漏斗
- **💡 洞察**：规则引擎自动生成（非 AI），5 条规则覆盖高频场景
- **入口**：调度台页头「📊 周报」按钮 → 全屏浮层
- **周期**：本周 / 上周切换
- **数据源**：`zy_event_log` + `d.tasks` + `d.curiosities` + `stats.lastVisits` —— 纯读取零写入

## 六、需拍板的决策点

1. **冷却/归档阈值**：默认 30 天/90 天，是否需要用户可配（设置页加滑块）？——建议本期固定默认值，后续加配置
2. **归档区搜索**：归档卡从默认搜索消失后在底部给一行提示——这个体验是否 OK？还是归档卡要有独立搜索入口？
3. **资源台 vs 策展台**：生命周期仅作用于**资源台**（真身居所）——策展台镜像卡不参与（镜像跟随源卡状态）。确认？

## 七、硬性规则

版本六处同步；样式只用令牌；断言追加与活性验证；构建前清 dist；`lifecycleArchived` 为可选字段零迁移。
