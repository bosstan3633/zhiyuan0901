## 一、核心判断

> **策展台把"操作台"做得很全，却把"论点"藏了起来。**
> 产品定义"策展台 = 中心论点 + 金字塔"（`isThesis` / 金字塔视图 / L1 根），但用户进入策展台，首屏看到的是 **5 个统计格 + 12 个工具条控件 + 一张张卡片**——看不到"我的论点是什么、我的结构长什么样"。

这个判断由三个代码级观察支撑：

| # | 观察 | 证据 |
|---|---|---|
| **1** | **台身份缺失** | `workspace.name` / `workspace.description` 在模板中零出现（R64-F13 删 hero 后未留替代）；描述只能经 ⚙ 菜单查看 |
| **2** | **论点被降级为"一格指标"** | 中心论点在首屏只以「🏛 策展主题」一格出现，且只显示标题（`.mc-value.thesis` 单行截断）；真正的论点视图（金字塔）是 4 个 Tab 里的**第 4 个**，且 `viewMode` 默认 `'card'` |
| **3** | **工具条是控件墙** | 12 个控件平铺一行，主 CTA（＋新建）被夹在中间；窄窗口必然换行（`.ws-toolbar` 无 `flex-wrap`） |

## 二、方案（C 系列）

> 每条格式：**问题 → 方案 → 理由 → 成本 → 优先级**。

### C1 【P0】补一行"台身份"页头

- **问题**：进入策展台看不到"这是哪个台、它是干什么的"。台名只在顶栏台签（可被滚动/截断）；`workspace.description` 不可见。
- **方案**：加**一行极简页头**（不恢复 hero）：
  ```
  🎯 产品方法论         这一台收的是"如何做产品决策"的素材与方法           3 分类 · 24 卡 · 2 镜像
  ```
  高度 ≤ 40px；图标 + 台名（15px/500）+ 描述（12px 次级色，单行省略）+ 右端结构摘要。描述为空时不占位。
- **理由**：R64-F13 删 hero 是为了省空间，但"省掉身份"不等于"省空间"。一行即可。
- **成本**：小。**优先级**：**P0**。

### C2 【P0】把"中心论点"提到首屏

- **问题**：中心论点是策展台的 L1 根（`isThesis`，每台最多一张），但首屏只在指标条第 1 格显示标题；金字塔视图默认不可见。
- **方案**（两步，可任选或叠加）：
  1. **卡片视图顶部加一条论点横幅**：`🏛 中心论点：<标题>  → 查看金字塔`；未设立时显示轻引导 `🏛 点击设立中心论点`（复用 `openThesisCreate`）；
  2. **已设中心论点时，`viewMode` 默认 = `pyramid`**（当前硬编码 `'card'`，`Workspace.vue:790`）；用户切过视图后记忆其选择。
- **理由**：策展台的差异化能力就是"论点 + 结构"。不把论点放首屏，策展台和资源台在观感上就没有区别。
- **成本**：小。**优先级**：**P0**。

### C3 【P1】工具条分级：12 → 一级 4 + 二级气泡

- **问题**：4 视图 Tab + 排序 + 排序方向 + 筛选 + 密度 + 搜索 + 批量 + 导入 + 新建 + ⚙ = **12 个控件**平铺；主 CTA 被夹在中间。
- **方案**：
  - **一级常驻**：`视图 Tab ｜ 搜索 ｜ ＋新建 ｜ ⚙`；
  - **二级收进「筛选」气泡**：排序（+方向）· 按类型筛选 · 密度档位 —— 三者都是"设置一次就不再动"的低频项，用「⚙筛选」按钮承载，气泡内显示当前生效值（如 `筛选：本地文件`）作为徽标；
  - 「⬇ 导入」并入 ⚙（见 C6）。
- **理由**：一页一主角（04-10）。工具条越宽，内容越靠后。
- **成本**：中（模板 + 气泡组件 + 偏好回显）。**优先级**：**P1**。

### C4 【P1】镜像卡的 hover 动作条对齐右键菜单（消除"可点击但不可用"）

- **问题**：`.res-card-actions`（`Workspace.vue:188-193`：📌置顶 / ⭐星标 / 📂移动 / 🗑删除）对**所有卡**渲染，**无 `isMirrorView` 判断**；但三个 handler 内部都会拒绝镜像卡并弹提示：
  - `togglePin`（`:1068`）→ `'📡 镜像卡为引用——置顶请在资源台操作'`
  - `toggleStar`（`:1076`）→ `'📡 镜像卡为引用——星标请在资源台操作'`
  - `openMoveOne`（`:1657`）→ `'📡 镜像卡为引用——移动落点请直接拖拽…'`
  - `deleteResource`（`:1058`）→ 转 `removeMirror`（这条是对的）
  而右键菜单 `openResCtx`（`:1098-1105`）对镜像卡**正确**给出只读语义（打开 / 复制 / 定位到资源台 / 移出镜像）。
- **后果**：同一张卡，hover 与右键是**两套语义**；hover 给出的动作点了才知道不行。
- **方案**：镜像卡的 hover 动作条替换为镜像语义三件套：`↗ 打开` · `🎯 定位源` · `✕ 移出镜像`（复用 `locateMirrorSource` / `removeMirror`），与右键菜单完全对齐。
- **理由**：**界面上出现的动作，必须都是能生效的动作。**
- **成本**：小。**优先级**：**P1**。

### C5 【P1】排序补「调用最多」，筛选补「星标 / 有附件」

- **问题**：
  - 卡片 footer **已经显示** `🔥{{ r.callCount }}`（`:208`），但 `sortBy` 只有 `manual / recent（最近添加）/ visited（最近访问）/ title`（`:76-81`）——**看得到热度，排不了序**；
  - `filterBy` 只有 linkType（`all / url / file / obsidian`，`:84-89`）——**没有"只看星标""只看有附件"**。
- **方案**：
  - `sortBy` 增加 `hot`（调用最多，用 `callCount`）——与 `visited`（`lastCalledAt`）互补：一个看"多常调"，一个看"最近调"；
  - `filterBy` 增加 `starred`（只看星标）与 `hasAssets`（只看有附件）。
- **理由**：数据都在卡上，显示了却不能用，是"假可用"。
- **成本**：小。**优先级**：**P1**。

### C6 【P1】「⬇ 导入」改名，避免与资源台同名不同义

- **问题**：策展台「⬇ 导入」**只导 JSON 数据包**（R65-F4 起书签/本地文件导入已移交资源台，弹窗标题才写明"导入策展台数据包"）；资源台「⬇ 导入」导**书签 / 本地文件**。**同名按钮，行为完全不同。**
- **方案**：按钮改名为「⬇ 导入数据包」；或直接收进 ⚙ 菜单（它是极低频操作）。
- **理由**：同名不同义是跨台面的一致性硬伤。
- **成本**：极小。**优先级**：**P1**。

### C7 【P2】金字塔视图加层级折叠

- **问题**：`.py-board` 列宽 `minmax(170px, 250px)`、`width: fit-content`，`.pyramid` 仅 `overflow-x: auto`。台一大（分类多），金字塔**只能横向滚动**，且所有层级一次全展开。
- **方案**：顶部加层级开关 `仅 L2 / 到 L3 / 全部`（默认按分类数自适应）；折叠时只渲染到指定深度，连线同步。
- **理由**：金字塔的价值是"看清结构"，横向滚动会让人失去全局。
- **成本**：中。**优先级**：**P2**。

### C8 【P2】指标条瘦身：把"元信息"移出

- **问题**：5 格中，`🕐 最近更新`（什么时候动过）与 `🔀 来源构成`（台内/镜像）偏**元信息/结构性说明**，不是策展主体每天要看的东西；而它们与 C1 的页头摘要、📊 卡片总数的 hint 表达重复（`📊 卡片总数` 的 hint 已经是"台内 N · 镜像 N"，与 `🔀 来源构成` 同义）。
- **方案**：
  - 「🕐 最近更新」移入 **C1 页头右端摘要**；
  - 「🔀 来源构成」并入「📊 卡片总数」（其 hint 已含同信息），指标条由 5 格收敛为 **3 格**：`🏛 策展主题 · 📊 卡片总数 · 📎 附件数量`。
- **理由**：指标条只留"策展主体"，元信息归页头。
- **成本**：小。**优先级**：**P2**。

### C9 【P2】分组标题补"含子分类 N"，消除双重表达歧义

- **问题**：左树选分类后，内容区仍按分类**递归分组**（`resourceGroups` 的 `walk` + `depth` 缩进 + 可折叠标题）。这是"第八轮：点击父分类 = 聚合显示本级 + 全部子分类"的有意设计，**不是缺陷**；但左树与分组标题对同一层级表达两次，且分组标题的 `· N` 只是**直属**卡数（`count: direct.length`），与左树的**聚合**计数（`sc.aggCount`）口径不同 → 同一个分类，左树显示 12、分组标题显示 3，用户会以为漏卡。
- **方案**：分组标题在有子分类时补一句 `含子分类`，或直接显示 `3 + 子级 9`。**不改结构**。
- **理由**：两处计数口径不同必须写明，否则看起来像 bug。
- **成本**：极小。**优先级**：**P2**。

### C10 【P2】搜索范围统一为 title + link + description + tags

- **问题（对称缺陷）**：
  - 策展台 `filteredResources`（`:839-842`）搜索 `title + description + tags`，**不含 link**；
  - 资源台 `searchHit`（`CurationCenter.vue:341-347`）搜索 `title + link + description`，**不含 tags**。
  - **两台范围互补但不重合，各自都不完整。**
- **方案**：统一为 `title + link + description + tags`（`customFields` 值可选）。
- **理由**：同一产品内"搜索"必须是一件事。
- **成本**：极小。**优先级**：**P2**。

## 五、一句话总结

> **策展台不缺能力，缺的是"让论点站在前面"。**
> 它已经有四个台面里最全的操作能力（4 视图 / 排序 / 筛选 / 密度 / 字段池 / 右键菜单 / 指标下钻 / 金字塔）——把这些收进一级、二级两层，再把"我是哪个台"（页头）和"我的论点是什么"（论点横幅 / 金字塔）提到首屏，策展台就从"一个很好用的卡片管理器"变回"**一个策展的地方**"。
