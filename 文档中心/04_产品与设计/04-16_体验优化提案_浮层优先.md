## 卷首 · 三句话结论（修订）

1. **产品的主界面其实是"网页浮层"，但设计资产与品牌表达都押在了"产品内的页面"上——这个错位依然成立。**
2. **浮层目前是"另一个产品"**：绿色 + 暖白 + **0 处主题感知**。用户在"光速黑"下打开浮层，看到的是暖白绿——**它不跟随你的主题**。
3. **"推进当前的事"缺少闭环动作**：浮层只能"收"和"找"，**不能"挂到我在做的这件事上"**；而"今日三件事"这个核心纪律，在新标签页之外没有任何入口。

> **修订说明**：v1 对调度台的批评（B1）基于错误前提，**已整体降级**（见 B1'）。调度台的首屏结构实际上已经做对了。

## 二、优化提案

> 每条格式：**问题 → 方案 → 收益 → 成本 → 优先级**。P0 = 建议本轮/下轮；P1 = 一个季度内；P2 = 择机。

### A 组 · 浮层（产品主界面）— 最高优先

#### A1 【P0】浮层接入用户当前主题，终结"两个产品"

- **问题**：`overlay-impl.ts:76-202` 全部硬编码：强调色 `#0E7A4E`（绿）、面板底 `#FDFDFC`、次级底 `#F7F5F0`、文字 `#1A1D23`；顶部还有一条绿色渐变装饰条（`:91`）。构建产物中 `#0E7A4E` 出现 14 次。**浮层内 grep `theme|dark|data-theme` = 0 命中**——用户在"光速黑"（珊瑚红）或"极简白"下打开浮层，看到的永远是同一个暖白绿。
- **方案**：建立**浮层语义令牌**，**从用户当前主题映射**（不是固定某个品牌色）：
  ```
  --zy-ol-surface    linear/raycast → 深色 #141516 ；apple/notion → 浅色 #FDFDFC
  --zy-ol-surface-2  对应 surface 阶梯的下一档
  --zy-ol-border     深 #23252A / 浅 #E8E5DE
  --zy-ol-text       深 #F7F8F8 / 浅 #1A1D23
  --zy-ol-text-2     深 #8A8F98 / 浅 #5C6370
  --zy-ol-accent     取当前主题 accent（linear #5E6AD2 / raycast 珊瑚红 / apple 蓝 / notion 蓝）
  ```
  - 判定顺序：**优先跟随宿主页面的 `prefers-color-scheme`**（浮层出现在别人的网页上，跟随宿主最不扎眼）；再回落到知源主题（读 `zy_ui_v2.theme`）。
  - 移除顶部绿色渐变装饰条（`:91`）——Linear 规范明确禁止装饰性铺色。
- **收益**：用户在任意网页上看到的浮层，第一次"是知源"，且与主应用同色系。
- **成本**：中（改 CSS 变量 + 主题读取，不动逻辑）。
- **备注**：v1 提的"统一为薰衣草蓝"**已撤回**——正确做法是**跟随用户主题**。

#### A2 【P0】全屏 20px 模糊，违背"不打断当前页面"

- **问题**：`:80` 居中模式为 `background:rgba(245,243,238,.72); backdrop-filter:blur(20px) saturate(1.4)`。**20px 模糊 + 0.72 不透明**让页面几乎完全消失。而承诺是"5 秒入台、不打断心流"。
- **方案**：改为**轻 scrim**：`rgba(0,0,0,.18)`、`blur ≤ 6px` 或**完全不 blur**，只做轻微压暗，让页面内容仍可辨。
- **收益**：保住"不打断"的体感；扫一眼浮层还能看见原文。
- **成本**：极小（一行 CSS）。**附带**：轻 scrim 后需加强浮层自身阴影与 1px 边框，避免与页面内容糊在一起。

#### A3 【P0】保存后的"大块确认页"，与 5 秒承诺矛盾

- **问题**：`:190-197` 保存后整块替换为 `padding:56px 24px 48px` 的居中确认视图（52px 圆形对勾 + 标题 + 两行提示 + 两按钮）；`:1152` 5 秒后自动关闭。用户为存一张卡被"奖励"了一整屏确认。
- **方案**：保存后**收窄为一行轻量回执**（复用已有 `.zy-toast`）：`✓ 已入台 · Enter 打开看板`；自动消失 **5s → 2.5s**。重复卡确认视图（`showDupConfirm`）属必要打断，维持现状。
- **收益**：入台尾部摩擦显著下降。**成本**：小。

#### A4 【P1】三种采集面板位置不统一

- **问题**：资源采集在**右上角**（`:90` corner 模式，400×600，`padding:10px 10px 14px`）；任务采集与好奇心采集在**居中**（R66-F1）。同类动作两种落点；且右上角远离视线与选区。
- **方案**：**统一居中 640px**（与搜索一致），形成"知源浮层永远从屏幕中央出现"的预期。后续可增强为**锚定选区下方**。
- **成本**：小。**备注**：400×600 侧窗是"对标 Obsidian Web Clipper"，但那个形态服务于长表单；知源采集只有 4 个字段，不需要 600px 高度。

#### A5 【P1】类型 Tab 与搜索框内 chip 重复表达同一状态

- **问题**：`:105-110` 常驻一行类型 Tab；`:101-104` 搜索框内又有同义 chip。两套控件表达同一个 `searchType`。
- **方案**：二选一。推荐**保留 chip**，Tab 行改为"有输入时才出现的轻量提示行"。
- **成本**：小。

#### A6 【P1】结果图标 6 种颜色，违反"主色稀缺"

- **问题**：`:117-122` 图标底色 6 种（资源蓝/任务完成绿/进行黄/待办灰/好奇黄/策展台紫），`:127-135` 徽标 8 种配色。
- **方案**：**类型用图标/形状区分**，颜色只保留"当前选中态"一个强调色；状态徽标收敛为「中性 / 强调 / 警示」三档。
- **注意**：**不要动主应用里好奇心卡的状态色**（待探索/探索中/已搁置）——那是**语义色**，是合理且必要的区分。
- **成本**：小。

#### A7 【P0】浮层缺少"推进当前的事"的闭环动作（全篇最重要）

- **问题**：核心场景是"用调出来的卡片推进当前的事"，但 `Ctrl+K` 找到卡片后**唯一动作是"打开"**。用户无法把"找到的东西"与"我正在做的事"连接起来。采集浮层同样只能"存入台面 + 分类"（`:993-1007`），不能"加入今日三件事"。
- **方案**：给结果行与采集面板各加一个**次级动作**：
  1. 搜索结果行：`→` 或 `Ctrl+Enter` = **「加入今日三件事」**（复用 dailyFocus 与 ≤3 槽纪律）；槽满时提示"今日三件事已满，替换第 N 件？"。
  2. 采集浮层底部：主按钮旁加次级按钮「**存入并加入今日三件事**」。
- **收益**：把"采集 → 归位 → 调出 → 复用 → 校准"的闭环，**第一次在浮层内闭合**。
- **成本**：中（需写 dailyFocus；资源卡如何进槽需产品定义 → 见 §四 Q1）。
- **兼容**：截图中三件事已是首屏第一块，浮层内新增入口与它**同源同义**，不引入第二套语义。

#### A8 【P2】搜索无输入态缺"最近调出"

- **问题**：`:635+` 无输入态是"快捷操作 + 热度 Top（按调用排序）"，但高频场景常是"**我昨天刚看过的那份文件**"。
- **方案**：无输入态分两段：**最近调出（近 7 天）** / **最常调出（Top 8）**。数据源 `stats.lastVisits` + `lastCalledAt` 已有。**成本**：小。

#### A9 【P2】搜索缺少按项目/标签过滤

- **问题**：只有类型 Tab，没有"只看某个项目/标签"。而"推进当前的事"往往等于"只看跟这个项目有关的"。
- **方案**：支持 `@项目名` / `#标签` 前缀过滤，或结果区"按项目分组"。**成本**：中。

### B 组 · 调度台 · 今日三件事（**已按实际界面修订**）

> **先说结论：调度台的首屏结构已经做对了。** 实际界面为：页头 → **方向状态（紧凑单行细条）** → **今日三件事（通栏 + 强调色光晕边框）** → 项目调度（通栏）→ 好奇心培育（通栏）。三件事是首屏第一块视觉主角，v1 的批评不成立。

#### B1' 【P2】方向状态条与三件事的次序（可选微调）

- **现状**：方向状态细条在三件事**之上**。它确实很紧凑（单行），但"每天做好三件事"的主张下，更彻底的做法是把三件事提到**最顶**，方向状态下沉到三件事下方或右侧。
- **方案（可选）**：① 保持现状（现状已可接受）；② 三件事置顶、方向状态下沉一行；③ 方向状态收为页头右端的一行摘要。
- **成本**：小（模板换序）。**优先级**：P2——**不建议为它单独开一轮**，可与其它改动顺带。
- **附带**：操作记录四格（⬇7 ⬆3 ↗8 ✎8）挂在方向状态条右端（`CompassHome.vue:648-653`）。它与方向状态同级但语义更轻，若做 B1' 可一并移入页头。

#### B2 【P1】项目调度面板偏重，是首屏第二重

- **现状**：项目调度通栏卡片，内部左右分栏：左侧强调框（战略目标 + 项目名大字 + 期限/进度 + 2×2 四指标），右侧按成功指标分组的任务树（含关联/删除/新建）。复杂度接近一个独立页面，视觉重量仅次于三件事。
- **方案**：**默认只显示左侧摘要**（项目 + 进度 + 四指标）；右侧任务树**默认折叠**或改为**点击任务后滑出的右侧抽屉**。
- **收益**：首屏信息密度下降，焦点更集中。**成本**：中。

#### B3 【P1】三件事缺少"完成"的安静正反馈

- **现状**：勾选 = 任务置完成，但页面没有"今天三件都做完了"的收束感。产品原则要求"状态可见但不焦虑"——**不等于没有反馈**。
- **方案**：三件全完成时给卡片区一个**安静的完成态**（整块轻微去饱和 + 一行"今日三件事 · 已完成"），**不用庆祝动画、不用红色、不用进度百分比**。**成本**：小。

#### B4 【P2】好奇心培育与当日焦点的关系弱

- **现状**：好奇心培育在页面底部（截图中为四张状态色卡片 + 筛选 chips），与"三件事"的当日关系弱（好奇是长期探索，三件事是今日承诺）。
- **方案**：保持位置但**降低视觉权重**（默认折叠/半高），调度台首屏只留"激活好奇 N 条"一行摘要 + 入口。**成本**：小。

### C 组 · 视觉系统一致性

#### C1 【P0】浮层是唯一未接入设计系统的表面（见 A1）

#### C2 【P1】"主色稀缺"需要在浮层同样成立

- **现状**：主应用遵守"强调色只用于主操作/焦点/链接"（截图中体现得很好：强调色只出现在三件事卡边框、项目调度强调框、编号、当前状态点）。浮层却把绿色用在了顶部装饰条、主按钮、chip、选中态、图标底色、徽标——**处处是绿**。
- **方案**：浮层统一后，强调色只保留三处：**主按钮 / 焦点环 / 当前选中行**（与主应用同规矩）。**成本**：随 A1 一并完成。

#### C3 【P2】浮层字号阶梯与主应用不一致

- **现状**：主应用 `--fs-body:13.5px / --fs-sub:12px / --fs-caption:10.5px`；浮层用 17/14/12.5/11/10.5px——两套阶梯。
- **方案**：浮层复用主应用字号令牌（搜索框可保留 16-17px 输入态放大）。**成本**：小。

### A7 实现说明（按拍板结果细化）

**动作一 · 加入今日三件事**
- 入口：搜索浮层**切到"任务卡"类型**后，结果行提供「加入三件事」次级动作（`→` 或 `Ctrl+Enter`）。
- 写入：content script 直写 `zy_data_v2.dailyFocus[todayKey]`（浮层是纯 Vanilla，不经 Pinia）。
- 必须处理：① **≤3 槽硬上限**（满则提示"今日三件事已满，替换第 N 件？"）；② **去重**（已入选的任务置灰或提示）；③ **跨上下文合并**——R70 已实现 `dailyFocus` 槽级合并（`repository.ts:304`），但浮层直写仍需确认不会与 newtab 的 300ms 防抖互相覆盖。

**动作二 · 定位到任务卡所在位置**
- 复用现有定位链路（`zy-locate-workspace` / `?hl=<cardId>`）。
- 落点建议：任务**有 `projectId`** → 定位到项目详情并高亮该任务；**无 `projectId`（未归档）** → 定位到方向台任务调度模块并高亮。
