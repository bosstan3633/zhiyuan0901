## 一、动工前勘验结论（2026-09-12，代码已核实）

| 项 | 勘验事实 | 方案 |
|---|---|---|
| M6 | `.mgc-projects` 是 `flex-wrap` 行，「更多 N」展开后全量 chip 撑高目标卡；`.mr-goals-grid` 无 `align-items`（默认 stretch）⇒ 同排邻卡被拉伸变形 | `.mr-goals-grid` 加 `align-items: start`——展开只长自己这张卡（提案「卡内独立一行 + align-self:start」的落地形态；chips 本就 flex-wrap 自动成行） |
| M8 | 主航线无筛选；项目总览已有 `ovFilter`（D-B，`>12` 门控 + projState 预计算）；`goalPct` 直算 `dir.projects`（不受视图影响） | `ovFilter` 留在 CompassShell 持有，**v-model 传入 LighthousePanel**（一处切换两处生效）；`projectsOf` 叠加状态筛选（计数/芯片/主攻数跟随所见 = D-B「所见即所数」口径）；门控与 D-B 同口径（`toolsGate` prop 单一来源）——**偏离登记**：M8 原文未写门控，不设门控会造成「主航线有控件、总览没控件却跟着变少」的分裂 |
| D-D | 方向台页头只有面包屑 + 显隐开关 + 方向树按钮，无读数 | `.page-head` 面包屑后加 `.mainline-summary`：`X 目标 · Y 项目 · Z 主攻 · W 停滞`（项目/主攻/停滞随 showDone，停滞复用 projState 预计算） |
| D-E | `onProjDrop` 跨区 = toast 拦截（`:189`）；且 `onProjDragOver` 对跨区目标**不 preventDefault** ⇒ drop 事件根本不会在跨区目标上触发（双重锁死） | 跨区分支改为**自动切换 `pinned` 后插入目标区序列**（拖入置顶区=置顶，拖回=取消）；`onProjDragOver` 只拦同卡（跨区给 drag-over 高亮）——不改这条 D-E 永远触发不了 |

## 二、实现要点

1. **M6**：`.mr-goals-grid { align-items: start }` 一行 CSS（零 JS 改动）。
2. **M8**：LighthousePanel `defineProps<{ ovFilter?; toolsGate? }>` + `emit('update:ovFilter')`；`projectsOf` 三分支（stalled/done/active，复用 projMeta）；空态区分「暂无项目」vs「无符合当前筛选的项目」（`rawVisibleCount`）；`.mr-tools` 加 `.mr-filter` select（四档，观感对齐 `.ov-filter`）。CompassShell：`<LighthousePanel v-model:ov-filter="ovFilter" :tools-gate="showOverviewTools" />`。
3. **D-D**：`focusCount` / `stalledCount` computed + 页头摘要行（tabular-nums）。
4. **D-E**：跨区分支翻 `proj.pinned` → 拖拽卡 splice 进目标区 → order 全量规整回写 → toast 说明自动切换；dragover 放行跨区高亮。

## 三、数据结构影响

**零改动、零迁移**。M8 筛选是既有本地视图态 `ovFilter` 的跨组件复用（不进 UIPrefs，维持 D-B 拍板）。
