## 一、只读勘验结论（动工前）

### 1.1 现状：排序

`Workspace.vue:1033` `sortBy` 四档：`manual` / `recent`（最近添加） / `visited`（最近访问） / `title`（标题 A-Z）。
对照 R5 规格 `手动（默认）/最近调用/调用最多/最近创建`：

| R5 规格 | 现有 | 结论 |
|---|---|---|
| 手动（默认） | `manual` | ✅ 已有 |
| 最近调用 | `visited`（`lastCalledAt`） | ✅ 已有 |
| **调用最多** | — | ❌ **缺**，需 `callCount` 降序 |
| 最近创建 | `recent`（`createdAt`） | ✅ 已有（文案写作「最近添加」，与模型 `createdAt` 一致，保留） |

> `callCount` 在 `shared/models/index.ts:142`（资源卡为**必填** `callCount: number`），卡片/列表/看板三视图 footer 已有 `🔥{{ r.callCount }}` 展示 —— **数据早已在维护，只是没有排序出口**。

### 1.2 现状：筛选

`Workspace.vue:1036` `filterBy` 四档：`all` / `url` / `file` / `obsidian`，**全部按 `linkType` 判**（`:1080` `r.linkType === filterBy.value`）。
R5 的新四档（有链接 / ⚠待补全路径 / 有附件 / 未挂载任务）是**语义谓词**，与 `linkType` 不同维度 ⇒ 不能塞进同一个 `===` 判定，须改为**谓词表**。

### 1.3 现状：待补全路径（R7）

- `isFullPath()` **只存在于** `ResourceEditForm.vue:71`（本地私有函数），是唯一的"是否完整路径"判据 —— 卡片视图、列表、看板、筛选**都没有**。
- ⚠ **既有缺陷**：`isFullPath` 不认 `zy-asset://`。R80（R13）之后，本地文件导入生成的卡 `linkType='file'` 且 `link='zy-asset://<id>'`（内部附件引用，**故意**不暴露本机路径），`isFullPath` 判为 `false` ⇒ 编辑抽屉里会误报「⚠ 当前仅存文件名，双击打开前请补全完整路径」。**本轮抽共享时一并修掉**。
- 双击打开无链接卡时 `openResourceLink`（`:1228`）toast 一律是「请先补全链接（本地文件需完整路径…）」，对 **URL 类型但链接为空** 的卡同样适用这句 —— 文案不准（R7 原文「双击 toast 文案改准」）。

### 1.4 现状：未挂载任务的反查（单向挂载红线）

R4 立下的红线：资源卡**不得新增反向字段**。`mountedTaskCount(r)`（`:2016`）已是 `d.tasks.filter(...)` 反查实现，但它是 **O(tasks)** 且**每张卡调一次** ⇒ 若直接用于筛选将是 O(卡数 × 任务数)，触 R83 立下的性能红线。
⇒ 本轮新增 **`mountedResIds` 反查索引**（一次遍历 tasks 建 `Set`），筛选走 `Set.has`。

### 1.5 现状：落点"hub 分支"已无区分必要

R5 原文落点写「hub 分支工具条」——这是在 **R16 资源台收敛之前**的语境（当时担心改错文件）。收敛后资源台与策展台**同为 `Workspace.vue` 同一组件同一工具条**，卡片同源 ⇒ 新增的排序/筛选档位**两台同时生效**，不做 `isHub` 分支开关。（`isHub` 仍用于 📡 镜像入口等真有差异处。）

## 二、改动清单

### T0 · 抽链接三态判据（`shared/utils/link.ts`）

| # | 内容 |
|---|---|
| 1 | 新增 `isZyAssetLink(link?: string): boolean` —— `^zy-asset:\/\//i` |
| 2 | 新增 `isFullPath(link: string): boolean` —— `^([a-zA-Z]:[\\/]\|file:\/\/\|\\/)`（自 `ResourceEditForm.vue:71` 原样迁出） |
| 3 | 新增 `linkStateOf(linkType, link): 'none' \| 'ok' \| 'incomplete'`：空链接 → `none`；`zy-asset://` → `ok`（附件引用由 `openResourceLink` 走预览通道，**不是待补全**）；`file` 型且非完整路径 → `incomplete`；其余 → `ok` |
| 4 | `ResourceEditForm.vue` 本地 `isFullPath` **退役**，改 `linkStateOf(model.linkType, model.link) === 'incomplete'` ⇒ 顺带修掉 1.3 的误报缺陷 |

> **为什么是三态而不是布尔**：`有链接` 筛选项要的是「有/没有」，`⚠待补全` 要的是「有但不完整」，两个筛选项共用一份判据，布尔表达不了。

### T1 · 排序补「调用最多」（R5-①）

| # | 内容 |
|---|---|
| 1 | `applySort` 增 `hot` 分支：`(b.callCount\|\|0) - (a.callCount\|\|0)`，同热度按 `lastCalledAt` 降序兜底 |
| 2 | 下拉 `<option value="hot">调用最多</option>`，置于「最近访问」之后 |
| 3 | 排序方向按钮（`.sort-dir-btn`）**仍只对 `recent`/`visited` 出现** —— 热度与标题无方向语义 |
| 4 | 新增 `SORT_BY_KEYS` 白名单，读偏好时校验（`sortPrefs.res.by` 是历史持久化字段，防止未来退役档位后卡死） |

### T2 · 筛选扩到 8 档（R5-②）

下拉用 `<optgroup>` 分两组，旧四档值不变（兼容已持久化偏好）：

| 组 | 值 | 判据 |
|---|---|---|
| 类型 | `all` | 全部（默认） |
| 类型 | `url` / `file` / `obsidian` | `r.linkType === <值>`（**保留既有**） |
| 状态 | `hasLink` | `linkStateOf(r) !== 'none'` |
| 状态 | `brokenPath` | `linkStateOf(r) === 'incomplete'` |
| 状态 | `hasAssets` | `(r.assets?.length \|\| 0) > 0` |
| 状态 | `unmounted` | `!mountedResIds.value.has(r.id)`（**反查索引**，单向挂载红线） |

- 新增 `FILTER_KEYS` 白名单。
- `filterBy` **不进 UIPrefs**（与既有行为一致）：筛选是临时视图态，持久化会造成"打开发现卡少了"的困惑。排序沿用既有 `sortPrefs.res` 持久化。

### T3 · ⚠待补全徽标（R7-①）

三视图各一处（R79 立的"三视图动作条推平"原则同样适用于状态徽标）：

| 视图 | 位置 | class |
|---|---|---|
| 卡片 | `.rc-footer`，`🔥{{ callCount }}` 之前 | `.rc-broken` |
| 列表 | `.rr-assets` 之后 | `.rr-broken` |
| 看板 | `.kc-card-footer` 首项 | `.kc-broken` |

- 条件：`linkStateOf(r.linkType, r.link) === 'incomplete'`（封装为 `isBrokenPath(r)`）
- 文案 `⚠ 待补全`，`title` = 「仅存文件名，双击无法打开 —— 点击补全完整路径」
- 点击 `@click.stop="fixLink(r)"`
- 样式一律 tokens：`color: var(--warning)` + `background: var(--surface-2)` + `border: 1px solid var(--warning)`；**与 `.rc-calls` 同形**（10px / 99px 圆角）

### T4 · 一键补全（R7-②）

| # | 内容 |
|---|---|
| 1 | `ResourceEditForm.vue` 用 `defineExpose({ focusLink })` 暴露聚焦方法（`nextTick` 后 `.ref-link-input` 聚焦并全选） |
| 2 | `Workspace.vue` 新增 `fixLink(r)`：镜像卡 → `📡 镜像卡为引用——补全路径请到资源台`（与 📌⭐🗑 同款只读拦截）；否则 `openResource(r)` + `nextTick` 聚焦链接输入 |
| 3 | 抽屉里 `linkStateOf==='incomplete'` 时那条 ⚠ 提示（`.ref-warn`）正是用户要填的地方 ⇒ 一键到位 |

### T5 · 双击 toast 文案改准（R7-③）

`openResourceLink` 的兜底 toast 由一句改为**按三态分流**：

| 态 | 文案 |
|---|---|
| `none` | `⚠ 该卡还没填链接 —— 点卡片右上角 ↗ 或进入详情补一个` |
| `incomplete` | `⚠ 仅存文件名，需补全完整路径（如 D:\docs\file.pdf）` |
| 其他（有链接但打不开，如伪协议） | `⚠ 该链接无法打开（协议不受支持）` |

> 注意 `recordResourceOpen` 仍在最前面执行 —— 计数口径不动（`🔥 调用 N 次` 照常递增，与 R11 待办互不干扰）。

### T6 · 空态感知筛选

卡片视图 `EmptyState`：当 `filterBy !== 'all'` 或搜索有词时，文案改「当前筛选/搜索没有匹配的资源卡」并给 `清除筛选` 动作（`filterBy='all'` + `searchQuery=''`）。

### 不做（边界声明）

- **不做** `starred` 星标筛选（属 `W5` 策展台条目，留给后续批次）
- **不做** 搜索扩到 `customFields`（属 `R6`）
- **不做** 工具条分级 / 生效值徽标（属 `W3`）
- **不动** `sortPrefs.res` 的既有持久化结构，只加白名单校验
