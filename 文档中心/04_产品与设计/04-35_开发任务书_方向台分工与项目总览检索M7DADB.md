### 2.2 ★ 顺带发现：三处开关是**三份逐字重复**的实现

| 出口 | 位置 | 内容 |

```ts
// 三处一字不差
const showDone = computed(() => store.ui?.showDoneProjects !== false)
function toggleShowDone() {
  const next = !showDone.value
  if (store.ui) store.ui.showDoneProjects = next

```

M7 要动这三处 ⇒ 按 §五·补四（≥2 处出口就抽共享函数），**先抽再改**，否则收敛完还是三份或两份。

## 三、设计

### 3.1 T0 · 抽 `showDone` / `toggleShowDone` 到 store

`stores/compass.ts`：

```ts
/** 已完成项目显隐（三处模块共用：主航线 / 项目总览 / 完整方向树；口径 isProjectDone，R52-BUG-2） */
const showDone = computed(() => store.ui?.showDoneProjects !== false)
function toggleShowDone() {
  const next = !showDone.value
  if (store.ui) store.ui.showDoneProjects = next
  saveUIPrefs({ showDoneProjects: next })
}
```

- 三处组件删掉本地实现，改从 `useCompass()` 解构；
- ⚠ `saveUIPrefs` 需 import 到 store（当前 store 已 import `getDataVersion` from repository，同文件追加）；
- **行为零变化**——这是纯收敛。

### 3.2 M7 · 开关收敛到方向台页头一处

```
改前：                                  改后：
┌ 主航线 ─────────────────┐            ┌ 方向台 · 主航线与项目全景    👁 已完成项目：显示  [完整方向树] ┐  ← 页头一处
│ 👁 已完成项目：显示  完整方向树 → │            ┌ 主航线（看主线）────────────────┐
└────────────────────────┘            │                      完整方向树 → │  ← 开关移除，入口保留
┌ 项目总览 ──────────────┐            └──────────────────────────────────┘
│ N 项目 · N 主攻  👁 已完成…  ＋新建 │            ┌ 项目总览（管项目）──────────────┐
└───────────────────────┘            │ N 项目 · N 主攻 · N 已完成  ＋ 新建项目 │  ← 开关移除
```

- **保留**：`CompassTree.vue:443` 方向树独立页那一处（原文明确要求；它是独立页，用户可能只在那儿活动）；
- **保留**：主航线 `.mr-tool accent`（「完整方向树 →」）——那不是开关，是导航入口；
- 页头开关沿用 `.ov-toggle` 的既有样式（改名为语义更通用的 `.done-toggle`，三处不再各写一份）；
- ⚠ **页头是全局的**：用户开着"隐藏"时，主航线与项目总览同时变——这正是"收敛"的意义（一个开关管整页），不是 bug。

### 3.3 D-A · 分工显式化

R85 已把**行为**边界立住（主航线只做一键级预置、管理类导流出去）。D-A 缺的是**让用户也知道**。

落地为**两个语义标签**（各模块头一个，小胶囊，与既有 `.mr-tier` 同款观感）：

| 模块 | 标签 | 位置 |
|---|---|---|
| 主航线 | `看主线` | `.mr-tools` 左侧（开关移除后空出的位置附近） |
| 项目总览 | `管项目` | `.ov-head` 的 `.ds` 之前 |

**不做**任何新的写能力、不改任何交互——D-A 是**表达**条目，不是功能条目。

### 3.4 D-B · 项目总览搜索与状态筛选

```
┌ 项目总览（管项目）────────────────────────────────────────┐
│ N 项目 · N 主攻 · N 已完成   [🔍 搜索]  [全部▾]  ＋ 新建项目 │  ← 项目数 >12 才出现
└──────────────────────────────────────────────────────────┘
```

- **启用条件**：`allProjects().length > 12`（原文）——否则整组控件不渲染，**零噪音**；
- **搜索**：匹配**项目名** + **所属战略目标名**（`goalNameOf` 已存在），大小写不敏感（`toLowerCase().includes`）；
- **状态筛选**四值：`全部 / 进行中 / 停滞 / 已完成`；
  - `进行中` = 非 `isProjectDone` 且非 `isProjectStalled`
  - `停滞` = `isProjectStalled(p)`
  - `已完成` = `isProjectDone(p)`
  - ⚠ **口径全部复用既有派生函数**（`isProjectStalled` / `isProjectDone`），**不自己写判定**；
- **与全局 `showDone` 开关的关系**（这是本条最需要说清的）：
  - 筛选是**本地视图筛选**，叠在 `visibleProjects`（已受全局开关过滤）之上；
  - ⇒ 若页头开关设为"隐藏已完成"，则选「已完成」会得到**空结果**；
  - **处置**：此时显示一行提示 `已完成项目当前在页头被设为隐藏 · [显示已完成]`，点它直接切 `toggleShowDone()`；
  - **不搞两套口径**——全局开关仍然权威，筛选不偷偷绕过它；
- 两个控件都放在 `.ov-head` 内（与「＋ 新建项目」同排），**不新增行高**。

## 八、风险与回滚

| 风险 | 处置 |
|---|---|
| M7 移除两处开关后，用户一时找不到开关在哪 | 页头一处是全页最显眼的位置；且 `.ds` 统计仍显示「已完成 N」（隐藏时不显示），保留线索；项目总览筛「已完成」时空态会直接提示开关在哪 |

**回滚**：`git revert` 单个提交即可。T0 是纯逻辑收敛，M7/D-A/D-B 是 UI 增删，**无数据残留**。
