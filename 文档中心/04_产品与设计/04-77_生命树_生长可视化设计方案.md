## 〇、为什么是树：从产品定位出发的三个裁定

**裁定一：树不是新功能，是既有数据的「第二种长相」。**
方向台已经是六层思维链（愿景→使命→战略目标→项目→成功指标→任务）——它本来就是一棵树，只是以**清单与塔的形态**呈现，服务于「编辑与推进」。生命树不新增任何数据、不新增任何采集：它是同一份罗盘数据 + 行为时间戳的**只读诗性投影**。方向台是工作面，生命树是映照面——如同镜像引用之于资源卡：一个真身，多种长相。

**裁定二：树回答的是产品精神层的最后一个悬问——「来时路」。**
产品四个价值（看见方向 / 留下好奇 / 调用所需 / 策展成果）已经各有承载页面，但它们都在回答「现在」与「下一步」。用户说「看见自己的来时路、看见过程、看见结果」——这是**时间维度**的看见，目前只有画像洞察（数字形态）承担。生命树把这条时间轴画成**年轮与生长**：数字镜像是体检报告，生命树是林中散步。二者互链而不互替。

**裁定三：树必须是「镜子」，不能变成「鞭子」或「游戏」。**
这是本方案最重要的红线，直接沿用 B3 批次确立的「**镜子不鞭子**」原则与「七不原则」：

| 借树之口想说的话 | 允许的表达 | 禁止的表达 |
|---|---|---|
| 你最近没推进这个项目 | 枝头叶色转黄（季节语汇） | 枯树警示弹窗、「你的树快死了」推送 |
| 你连续做了很多 | 树干年轮变厚、冠幅变大 | 连续打卡天数、浇水量排行榜、等级与徽章 |
| 这件事还没开始 | 枝头一颗待放的花苞 | 红色逾期标记、倒计时压迫 |
| 你恢复了搁置的事 | 回芽动画（枯黄转回嫩绿） | 任何不可逆的死亡惩罚 |

⇒ 树里**没有负反馈循环**：搁置≠枯死（种子休眠在土里），归档≠断枝（越冬枝），删除可逆（回收站恢复＝回芽）。树的每一个「不好看」的状态，都必须有一条用户已知的、体面的回去的路。

## 一、隐喻系统：六层思维链 × 一棵树

### 1.1 主映射（在用户原案基础上细化）

| UI 层 | 树语 | 状态语言（数据驱动） |
|---|---|---|
| **愿景（L1）** | **根系**——深埋土里，平时不可见 | 「拨开土层」才显形（见 1.3 来时路）；愿景越长越宽＝根幅；愿景有原文，根有名字 |
| **使命（L2）** | **主根与树干**——向上生长的那根轴 | 干的**粗度＝累计完成事项总量**（执行量的年轮），干的**高度＝主枝（战略目标）的展开度** |
| **战略目标（L3）** | **主枝**——从干上分出的少数大枝 | 枝的走向与仰角由目标数决定；**越冬枝**＝已归档目标（休眠色，不断不删）；枝的受光面＝是否含主攻 |
| **项目（L4）** | **分枝**——主枝上的次级枝 | 分枝长度与垂度＝项目进度；**主攻项目＝向阳枝**（树冠受光最多的一枝，微光常驻）；停滞 14 天＋＝叶色转黄（季节语汇）；完成＝满枝硕果后木质化（转深色、稳定） |
| **成功指标（L5）** | **花与果**——枝头的结果位 | 0 任务＝**空枝花苞**（缺任务警示的树语：花苞虚线）；有任务＝开花；进度 100%＝**硕果成熟**（可摘，见 1.2）；验收标准＝果蒂标签 |
| **任务（L6）** | **叶**——树冠的基本单元 | 芽（待开始，带壳）／嫩叶（进行中，微光呼吸）／翠叶（已完成，饱和色）／黄叶（停滞 14 天＋）／落叶（软删进回收站，恢复＝**回芽**）；**子任务＝叶脉**（叶脉充盈度＝子任务完成比）；**叶在枝头的排布＝taskIds 轨道序**——F4 上线的拖拽排序，在树语里就是「修剪叶序」 |

### 1.2 两条关键闭环的树语化（不是装饰，是产品闭环的可见化）

- **好奇心＝种子（以好奇过滤信息）**：好奇心卡落在树下的土面。待探索＝土面微光种子；探索中＝破土嫩芽；**已求证＝抽出新梢**；已搁置＝休眠种子（仍在土里，不消失）；**好奇心转任务＝种子破土、接上枝头**——这正是 R166 以来「转化即出路」哲学的形象表达。
- **资源卡＝养分与水（调用所需）**：采集资源卡＝一场细雨灌根（一次性动画＋根部微光）；**调用（callCount）＝养分沿树干上涌**（回放时可见的光流，从根到曾被它支撑的那片叶）；资源经 SupportLink 挂到任务＝养分定向输送到某片叶。
- **硕果的归宿＝策展（策展成果）**：指标 100% 结出的成熟果实，**可摘**——摘果动作直达策展台，把这条指标下的成果组织成可分享的 HTML。「解决问题」闭环（调用→论证→展示）在树上的收口动作就是摘果。

### 1.3 用户说的「五个看见」→ 树的五个组件（方案主脊）

| 看见 | 树的承载 | 默认态呈现 |
|---|---|---|
| **看见行为**（今天做了什么） | 今日滋养：一场只属于今天的天气 | 完成今日三件事→整树 5 秒提亮呼吸（日照）；采集/调用→晨露细雨；树不评判今天做多做少，只如实落下这场天气 |
| **看见动机**（为什么做） | 根系与种子 | 愿景原文写在根上（拨土可见）；土面种子就是每一个还没转化的好奇——动机层永远在场，不催促 |
| **看见来时路**（从哪来） | 生长回放 + 拨土 | 时间轴从今天拖回写下愿景的那一天，树随拖动倒带重生长 |
| **看见过程**（此刻长成什么样） | 芽/叶/花/黄叶/越冬枝的状态语言 | 默认「现在」态：整树如实呈现六层的实时状态 |
| **看见结果**（结出了什么） | 硕果与年轮 | 成熟果可摘入策展；干切面年轮＝每月/季一圈，圈厚＝该期行为量，圈色＝当期主导目标的色相——**每一圈都不一样** |

## 二、画面与交互设计

### 2.1 页面构成（单屏、焦点唯一）

```
┌──────────────────────────────────────────────────────┐
│  生长 · 2026年11月        [现在 | 回放 | 年轮]   ⤓ 导出 │  ← 极简页头（三态切换＋导出）
│                                                       │
│                    🌳 树 舞 台                         │  ← 全幅唯一主角（线构树）
│              （点叶=任务详情 · 点果=指标下钻             │     每个元素都是通向真身
│               点枝=项目详情 · 点干=愿景使命原文）         │     的只读入口
│                                                       │
│ ～～～～～～～～ 土层（时间轴栖息地）～～～～～～～～～～ │  ← 回放态：scrubber；
│   🌰 种子区：好奇落土  ·  今日滋养：入台3 · 调出5 · 完成2 │     默认态：一行今日滋养摘要
└──────────────────────────────────────────────────────┘
   右下角：生长账本入口（能量公式的透明明细，见三.3）
```

### 2.2 三态

1. **现在**（默认）：整树实时状态。用户每天打开，看一眼就知道「我今天落了什么在这棵树上」。
2. **回放**：土层变时间轴，从今天拖回愿景写下那天；拖动即重生长（确定性重放，见三.2）；回放中养分上涌、种子破土等历史时刻逐帧可见——**来时路的具象化**。
3. **年轮**：镜头切到树干横切面，一圈＝一个自然月（或季），圈厚＝该期完成/采集行为量，圈色＝当期推进最多的战略目标的色相。年轮旁边一行小字：这一圈你主要长在了哪里。

### 2.3 交互细则

- **一切元素可点、点开即真身**：叶→任务详情抽屉；果→指标下钻抽屉；枝→项目详情；干/根→愿景使命原位编辑入口（导流回方向台，树自身只读）。
- **摘果**：成熟果长按/双击→确认气泡「把这条指标的成果策展出来？」→跳策展台新建，指标与相关资源预选。摘走的果实在枝头留下果蒂（曾结果的位置永远留痕——结果的证据）。
- **拨土**：根区 hover/下压→土层半透明化，根系与休眠种子显形；松手即掩。来时路的根不常驻，但永远可及。
- **天气动效全部一次性、事件驱动**：只在行为发生或回放经过时播放，无常驻循环动画；`prefers-reduced-motion` 下降级为静态色变。
- **空态**：还没有愿景时＝一粒种子躺在土面上＋一句「写下第一句愿景，树就有了根」（跳方向台愿景编辑）——与方向台 EmptyState 文案同一口吻。

### 2.4 美术方向：**线构树，不是插画树**（关键裁定）

产品的视觉基准是 Linear 结构语言（近黑画布、发丝线、克制装饰）。生命树的形态必须是**这套语言的有机变体**：发丝线枝干（1px–2.5px 线宽分级表达粗细）、表面阶梯着色（`--bg→--surface-3` 深浅表达前后景深）、语义令牌表达状态色（`--success` 翠叶、`--warning` 黄叶、`--accent` 微光与主攻向阳、`--text-3` 越冬枝）。**不做写实插画、不做氛围渐变、不做粒子堆砌**——树的「生命感」来自数据驱动的形态与一次性动效，不来自画面的堆料。新增少量 `--tree-*` 派生令牌（自既有语义令牌 color-mix 派生，禁止硬编码色值），六主题逐一走查（四主题即四种天光：深空暮蓝／极简晨白／光速夜黑／纸墨林间——同一棵树在不同主题下是不同时段的同一片风景，这正是用户要的「不一样的风景」的第一层含义）。

## 三、生长引擎：数据、算法、性能

### 3.1 数据源——全部既有，零新增采集

| 需要什么 | 来自哪里 |
|---|---|
| 六层结构与层级状态 | `compass`（vision/mission/directions/projects/metrics），只读 |
| 叶状态 | `tasks`：status / completedAt / updatedAt / taskIds 轨道序 / 子任务 |
| 花果状态 | metric.taskIds 聚合进度（compassMeta 同口径） |
| 种子 | `curiosities`：status 四态流转、fromCuriosityId 已退役——转化关系由任务描述与来源链接承担，树语中种子→接枝的连线以「转化事件」时间戳推断 |
| 养分 | `resources`：createdAt（雨）、callCount/lastCalledAt（上行养分）、SupportLink（定向输送） |
| 今日天气 | 当日事件聚合（入台/调出/完成），与调度台右栏同口径不同源的事实照旧明示 |

### 3.2 确定性重放——「同一份数据，长出同一棵树」

生长引擎是**纯函数**：`computeTreeState(data, at: Date) → TreeState`。以实体时间戳（createdAt / status 变更 / completedAt / callCount 时刻）在 `at` 之前的部分重放推导，**不依赖事件日志**（事件包有 5,000 条滚动上限，不可作为长期回放真源）。保证：① 回放可信（拖到任何一天，树就是那天的样子）；② 可导出分享（同样数据在别处长出同样的树）；③ 无 AI 参与形态计算——**树是规则镜像，不是 AI 生成**（不越「不做 AI 替你决策」的边界，也不产生任何出网）。

### 3.3 形态算法与能量账本

- **形态**：带种子的递归分形（L-system 变体）。主枝数＝战略目标数；分枝密度＝项目数；枝长∝项目进度；冠幅∝累计完成量；**叶位＝taskIds 轨道序沿枝排布**。角度扰动由数据指纹播种——同一数据永远同一棵树。
- **能量＝隐性，不是点数**：默认界面**不显示任何能量数字**，行为直接驱动形态与一次性天气。右下「生长账本」点开才见透明明细：「今日完成任务 2 → 叶＋2 / 干＋2 单位厚度」，公式可见、可解释——但**没有连续天数、没有等级、没有排行榜**（不做 KPI 压迫）。
- **性能红线**：路由级懒加载独立页；视图切换沿用 <40ms 红线（树静态帧为 SVG，动效仅在事件时刻）；叶数量 LOD——≤300 叶逐叶渲染，300–800 叶簇化，>800 叶密度团块（团块可下钻展开）；主 JSON 零新增写入（树状态不落库，实时计算）。

### 3.4 红线自查（本方案与五条红线逐条对表）

| 红线 | 本方案 |
|---|---|
| 卡间零挂载 | 树是渲染投影，不新增任何卡间字段；种子→接枝为时间戳推断，非数据关联 |
| 删除一律软删 | 落叶＝已软删；恢复＝回芽动画（回收站语义的树语版） |
| 主 JSON 无 base64 | 树不落库、导出走既有快照 |
| 令牌不出包 / Airtable 不回写 | 无涉 |

## 四、与既有版图的关系（落位裁定）

| 页面 | 角色 | 关系 |
|---|---|---|
| **方向台** | 工作面（编辑真源） | 树的每个元素点击后导流至此；页头新增「生长」视图入口（与项目塔/项目全景并列的第三种**看**法，但独立路由，不挤占方向台焦点） |
| **画像洞察** | 数字镜像（体检报告） | 页头互链：「看数字→画像，看自己→生长」；今日战报口径与树上的今日滋养同口径不同源的事实照旧明示 |
| **调度台** | 今日出发点 | 今日三件事全部完成时的「日照」时刻，可一键跳树看这场光落在哪片枝头（可选、不强制） |
| **策展台** | 成果出口 | 摘果动作的落点：指标成果预选进新策展台 |

**路由**：`/tree`（懒加载）；顶栏不新增常驻页签（避免与「三大固定系统页＋策展台」的导航结构冲突），入口收敛为方向台页头 + 画像互链 + `Ctrl+K` 可直达。

## 五、演进路线（三轮，每轮独立可交付）

| 阶段 | 内容 | 验收判据方向（交付时落 regression） |
|---|---|---|
| **G1 · 静态镜像** | 线构树渲染六层投影＋状态着色＋全元素点选直达＋空态种子 | 树节点数＝六层实体数（投影完整性断言）；点击链路逐条通；零写库断言；六主题走查 4×N 截图 |
| **G2 · 时间维度** | 生长回放 scrubber＋年轮模式＋确定性重放 | `computeTreeState` 纯函数单测式断言（同输入同输出）；回放至任意时点与该时点数据一致；事件日志不作为回放真源的负锚 |
| **G3 · 生命感** | 天气动效（日照/细雨/养分上涌）＋摘果→策展联动＋拨土＋生长账本 | 动效一次性（无常驻循环断言）；prefers-reduced-motion 降级；摘果只读跳转不写库；账本无连续天数/等级的负锚（镜子不鞭子） |

**命名候选**（页面名/对外名，待拍板）：「**生长**」／生命树／来时树／知源树。⚠ 不可叫「方向树」——该词已被六层思维链占用（术语表在案）。

## 六、一句话

> **方向台让你看见方向的样子，生命树让你看见方向的成长。**
> 以好奇落种，以调度滋养，以时间成林——万千可调用，终有一棵自己的树。
