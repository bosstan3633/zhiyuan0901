## 三、⚠️ 死代码：`CurationCenter.vue` 里的旧方向镜像机械

**根因**：`curationMigration.ts:93 migrateHubStructure()`（R61）第 ③ 步——

```ts
// ③ 镜像分类 → 原生资源分类
for (const c of d.categories) if (c.workspaceId === CURATION_WS_ID && c.curFrom) c.curFrom = undefined
```

注释原文：*「策展中心内镜像分类 curFrom 剥离——物化分类转为资源台原生分类（**镜像方向反转后溯源失效**）」*。同时第 ④ 步清空旧方向投射（`d.curationProjections = []`）。

**推论**：资源台自身分类的 `curFrom` 恒为 `undefined` ⇒ `CurationCenter.vue:66` 的 `isMirror = (c) => !!c.curFrom` **恒为 false**。于是下列代码路径**永不执行**：

| # | 死代码 | 位置 | 说明 |
|---|---|---|---|
| **D1** | `mixedCardsOf` 的 `curFrom` 分支 + `live:` 源卡 | `:301-320` | 未投射源卡（"源分类实时镜像"）——R56-27 已断言"独立分区取消" |
| **D2** | `LIVE_BASE` / `srcIndexOf` 源序垫后 | `:313-315` | 只服务 `live:` 卡 |
| **D3** | `onLiveDrop`（拖动即物化）+ `projectSourceCardTo` | `:726-905` | 只服务镜像分类视图 |
| **D4** | `.mirror-node` 树节点样式与 `isMirror` 分支（`📡` 图标、`✕ 移出投射`、`重命名（源分类不受影响）`） | `:995-1030` / `:1346-1347` | 恒不命中 |
| **D5** | `renderSections` 的 `isMirror` 标记 + `mirrorSourceLabel` | `:66-67` / `:286` | 恒为空串 |
| **D6** | `moveProjectionTo` / `onTreeDrop` 的镜像分类落卡分支 | `:751-905` | 目标分类恒不存在 |

> **注意**：`migrateCurationTree()`（R53）仍会**为存量遗留数据**物化 `curFrom` 分类，但 `migrateHubStructure()`（R61）随后把它们**剥离为原生分类**。两者是接力关系——R53 负责结构归一，R61 负责方向反转。**净效果 = 资源台分类无 `curFrom`。**

**这意味着**：退役这些死代码**不损失任何用户可见功能**，但会让**约 30 条回归断言失效**（它们锁的正是这些不存在的路径）。
