## 一、核心判断

> **主航线现在回答的是"我有什么目标和项目"——它是一份"清单"；但它应该回答"我的主线现在走到哪、下一步推哪个"——它应该是一条"路线"。**

这个判断由三个具体反差支撑：

| # | 反差 | 证据 |
|---|---|---|
| **1** | **主航线上的项目，信息量比"项目总览"还少** | 主航线项目 = 一个名字标签（`.chip-proj` 11px）；项目总览项目 = 🎯主攻/⚠停滞 chip + 服务战略目标 + 指标数 + 任务数 + 进度条 + 百分比。**反了**——"看主线"的地方信息最薄，"管项目"的地方信息最厚 |
| **2** | **视觉焦点落在"背景"而不是"主线"** | 愿景/使命卡用 accent 着色（`color-mix(accent 7%)` 底 + `38%` 边框），比战略目标卡（surface-2 中性底）**更亮**；而愿景/使命是**不常变的背景**，却占了第一行 |
| **3** | **"主攻"被淹没** | 产品定义"主攻 = 当前重心，置前并高亮"，但主航线上主攻只是 chips 里一个 accent 边框，与"更多 N"同处一行网格 |

## 二、主航线设计方案（M 系列）

> 每条格式：**问题 → 方案 → 理由 → 成本 → 优先级**。

### M1 【P0】愿景 / 使命：从"两个大卡"降为"一行锚点条"

- **问题**：`.mr-vm-row` 占第一行，两卡各 padding 10-14px + 2 行文本截断，约占首屏 90-110px；且用 accent 着色，抢走了主航线的第一眼。而这两句话**几乎不变**。
- **方案**：压缩为**单行锚点条**：
  ```
  愿景  <一句话…>          使命  <一句话…>              进入方向树 ›
  ```
  字号 12px、单行省略、高度 ≤ 44px；整条可点进方向树。空态显示"尚未设定愿景/使命"。
- **理由**：愿景/使命是主线的**起点铭牌**，不是主体。省下的首屏高度让给"航线"。
- **成本**：小（模板 + CSS）。**优先级**：P0。

### M2 【P0】战略目标卡：补期限、修正计数口径

- **问题**：目标头是 `[目标] 目标名 · 45% · 项目 N`。
  ① **没有期限**——`Direction.term`（远期/中期/近期）字段存在，但主航线完全没用（只在调度台用过 `dirTermLabel`，`CompassHome.vue:395`）。战略目标丢了"节奏"。
  ② **"项目 N"是总数**，不是活跃数。
  ③ **进度是"项目平均"**（`goalPct` = ΣprojectProgress.pct ÷ 项目数），一个刚建的空项目会把整体拉低，且无口径说明。
- **方案**：目标头改为：
  ```
  [目标]  目标名       中期 · 项目 3（主攻 1） · 进度 45%ⓘ
  ```
  - 期限取自 `dir.term`；未设置则不显示。
  - "主攻 N" 用 accent 着色。
  - 进度加 tooltip 说明口径（"项目平均进度"）。
- **理由**：战略目标是**有期限的阶段方向**，不显示期限等于丢了推进节奏；主攻数是"这个目标在不在动"的直接信号。
- **成本**：小。**优先级**：P0。

### M3 【P0】项目小模块：从"光名字"升级为"项目卡"

- **问题**：`.chip-proj` 只有名字（11px，max-width 220px，hover 才变色）。**在主航线上看不出项目推进状态**——没有进度、没有任务数、没有停滞/主攻标记。要看状态必须点进项目详情。这与"方向关系可追溯"（04-10 #4）相悖。
- **方案**：改为**两行项目小卡**：
  ```
  ┌──────────────────────┐    ┌──────────────────────┐
  │ ★ 项目名              │    │ 项目名        ⚠ 停滞  │
  │ ▓▓▓▓░░░░  43% · 3/7   │    │ ▓▓░░░░░░  20% · 1/4   │
  └──────────────────────┘    └──────────────────────┘
  ```
  - 主攻：★ 前缀 + accent 底 + accent 边框；
  - 停滞：⚠ 标记（复用 `isProjectStalled`，与项目总览同口径）；
  - 已完成：降透明度（对齐项目总览 `.archived` 的 `opacity:.55`）；
  - 迷你进度条复用 `.ov-progress` 的样式语言。
- **理由**：把"项目总览"的关键信息搬进主航线——**主航线才是"看主线"的地方**。用户不必再点进详情才知道项目停没停。
- **成本**：中（模板 + CSS；数据已有：`projectProgress(p)` 提供 pct/total/done）。
- **优先级**：P0（本方案的核心改动）。

### M4 【P1】新增"主攻聚焦条"

- **问题**：主攻是产品的重心语义（`focusedProjects()` = `isFocused && status!=='archived'`），但主航线上它只是网格里的一个边框，**不构成"当前主线"的读法**。
- **方案**：在锚点条下方加一条**聚焦条**，横排展示全部主攻项目：
  ```
  ★ 项目名 · 所属目标 · 进行中 · ▓▓▓▓░ 43% · 3/7 任务           进入详情 ›
  ```
  - 无主攻时显示轻引导：「还没有主攻项目 —— 去项目总览点 🎯 设为主攻」。
  - 主攻数 > 3 时横向滚动或折行。
- **理由**：**直接回答"我的主线是什么"**。与调度台"战略目标 / 推进项目"指标、项目总览的 🎯 按钮形成同一口径。
- **成本**：中。**优先级**：P1。

### M5 【P1】主航线就地可操作

- **问题**：主航线目前**纯只读**。新建项目在"项目总览"模块（`openCreate` 在 `CompassShell.vue`），设为主攻在"完整方向树"（`CompassTree.vue` 的 `toggleFocusProject`）。主航线想推进一步，得跳到别的模块。
- **方案**：
  - 每个目标卡底部加 `＋ 新建项目`（复用 `openCreate`，**预选该目标**，省一次选择）；
  - 项目小卡 hover 出现 `🎯`（设为主攻）与 `›`（进详情）；
  - 目标卡 hover 出现 `⋯`（改名 / 期限 / 删除，与方向树同语义）。
- **理由**：主航线是"规划下一步"的地方，创建与调整应就地完成（呼应"高频操作不上收藏夹，就上头部"）。
- **成本**：中。**优先级**：P1。

### M6 【P2】「更多 N」展开不再撑破网格

- **问题**：`toggleMore` 是**行内展开**（`expandedGoals`），展开后该目标卡变高，而 `.mr-goals-grid` 是 `auto-fill` 网格——同行其它卡高度不齐，出现错位。
- **方案**：展开后改为**卡内独立一行 chips + 「收起」**，并给目标卡设 `align-self: start`；或改为点击弹出层列出全部项目。
- **理由**：网格对齐是"美是核心生产力"的底线。
- **成本**：小。**优先级**：P2。

### M7 【P1】"已完成项目"开关收敛到一处

- **问题**：同一个 `store.ui.showDoneProjects` 字段，在**主航线**（`.mr-tool`）、**项目总览**（`.ov-toggle`）、**完整方向树**（独立页）**三处各放了一个开关**。
- **方案**：收敛为**方向台页头一处**（作为整个方向台的显示偏好），主航线与项目总览不再各放；方向树是独立满宽页，可保留。
- **理由**：同一开关出现三次是重复；页头一处语义更清晰。
- **成本**：小。**优先级**：P1。

### M8 【P2】主航线支持"只看某类项目"

- **问题**：项目变多后（当前网格已能放 6+ 个），主航线无法筛选。
- **方案**：主航线工具区加轻量筛选：`全部 / 进行中 / 停滞 / 已完成`，与项目总览共用偏好。
- **成本**：小。**优先级**：P2。

## 三、方向台整体（主航线之外）

| # | 优先级 | 问题 | 方案 |
|---|---|---|---|
| **D-A** | P1 | **主航线与项目总览信息重叠**——两者都在展示项目（名字/进度/目标）。分工不清。 | 明确分工：**主航线 = 看主线**（方向 → 目标 → 项目推进，读为主）；**项目总览 = 管项目**（新建/改名/置顶/删除/排序，写为主）。主航线瘦身 + 补可读性（M1-M6），项目总览保持"管理台"定位。 |
| **D-B** | P1 | 项目总览是 `repeat(3,1fr)` 固定三列，**无搜索、无筛选**；项目一多就找不到。 | 头部加搜索框 + 状态筛选（进行中/停滞/已完成）；项目数 > 12 时自动启用。 |
| **D-C** | P2 | **任务调度（`TaskManagerPanel`，1045 行）与调度台的"项目调度"面板功能重叠**——两处都能看任务、改状态、新建。 | 建议明确主次：调度台"项目调度"= 当日行动视角（跟三件事联动）；方向台"任务调度"= 全域管理视角。二者**保留但明确边界**，或把全域管理收敛到一处。属结构性议题，**建议单独立项**。 |
| **D-D** | P2 | 方向台页头只有标题 + "完整方向树"，**没有"主线状态"摘要**。 | 页头右端加一行摘要：`3 目标 · 5 项目 · 1 主攻 · 2 停滞`（复用已有计数）。 |
| **D-E** | P2 | 项目总览拖拽**只支持组内排序**，跨"置顶/全部"区需先手动置顶（`onProjDrop` 会提示"跨区移动请先用 📌"）。 | 允许跨区拖拽自动切换 `pinned` 状态（拖入置顶区即置顶）。 |

## 七、一句话总结

> **主航线不该是一份"我有什么"的清单，而应是一条"我走到哪、下一步推哪个"的路线。** 把背景（愿景/使命）压成一行，把主线（主攻 + 项目推进状态）提上来——用户打开方向台，第一眼就该看见自己的重心在哪里。
