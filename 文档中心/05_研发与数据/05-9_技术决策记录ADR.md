# 05-9 · 技术决策记录（ADR 摘要）

> 格式：决策 / 背景 / 取舍 / 影响。新增重大决策在文末追加。

## ADR-01 本地优先，不做云同步
背景：目标用户对数据主权敏感；同步=数据上他人服务器。取舍：放弃"多端实时"，换"零信任成本+零服务端运维"。影响：多设备用导出/导入；多窗口并发靠 R58 合并层。复审条件：出现强付费的团队场景需求。

## ADR-02 单根 JSON（chrome.storage.local）而非多键/SQLite
背景：数据量个人级（MB 级）、要求整包导出即迁移、防抖写简单可靠。取舍：全量序列化写（大库写入成本↑）换"导出=拷贝、导入=并集、迁移=一键"。影响：persist 有 JSON 清洗与防抖；性能预算监控大库；未来若破预算再评估分键（见 05-6）。

## ADR-03 附件走 IndexedDB，主数据不含 Blob
背景：附件大（≤20MB）、主数据要求轻与可 diff。取舍：两套存储+附件包导出补齐迁移。影响：回收站硬删需清理附件；导出 JSON 不含附件（另有附件包）。

## ADR-04 搜索=内存过滤+拼音按需，而非倒排索引
背景：个人库千级为主，内存过滤+LRU 拼音已满足三秒标准。取舍：省去索引维护复杂度，换超大库的扩展上限。影响：5000+ 卡场景列入预算监控，触发再建倒排（05-6 后续项）。

## ADR-05 删除一律软删 + 回收站
背景："信得过"是产品信任底座。取舍：存储体积↑、逻辑需处理回落。影响：所有删除入口必须走 deletedAt；引用方（策展/挂载）需处理源缺失回落（孤儿防扩散）。

## ADR-06 并发写=卡片级 LWW 合并而非锁（R58）
背景：多窗口/浮层并发是真实场景，整树替换曾丢改。取舍：合并层复杂度换数据完整性；非卡段保持段粒度（真冲突保本页）。影响：字段需 updatedAt 语义；极端同段并发仍可能有一侧覆盖（已文档化，见交付说明 V2.31）。

## ADR-07 网页浮层纯 Vanilla，不引 Vue 运行时
背景：注入体积与启动速度敏感。取舍：逻辑双写（与应用内浮层各一份）换轻量。影响：工具函数就地复制；行为一致性靠回归断言守门。

## ADR-08 资源台归一（R64）
决策：原「策展中心」转正为资源台（唯一资源卡存储与镜像源头，常量 `CURATION_WS_ID`），旧「工作台」分类树整体并入资源台根下同名根分类、原生卡随分类平移，工作台实体删除。背景：台面命名混乱、存储源头分散。取舍：一次性启动自动迁移（幂等标记 `hubMergedAt`，迁移前自动备份下载 JSON）换统一存储源。影响：所有采集入口默认落资源台·待分类；路由 `/curation` 保留兼容旧链接。

## ADR-09 Airtable 单向同步（R63–R64）
决策：仅「本地 → 用户自有 Airtable Base」单向推送，绝不回写本地；用户自带 Personal Access Token，知源不设服务器、不代持凭证。背景：用户的多表看板需求。取舍：放弃双向/自动云同步换数据主权零成本；限流（≤10/批、批间 200ms、429 退避 30s）+ 自愈重建（远端实测存在优先、本地映射兜底、撞已删记录降级转新建、单条失败仅记日志）。影响：增量游标 `cursorAt` + 映射表 `airtableMap`；镜像卡独立记录（幂等键 `卡ID:m:目标策展台ID`）。

## ADR-10 DHI 方向契合度退役（R64）
决策：不再计算 DHI 方向契合度百分比；方向第一格改为主数字「战略目标数」+ 副行「推进项目 N」。背景：DHI 百分比可解释性差、用户难以据此行动。取舍：放弃单指标拟合换可解释口径（战略目标/推进项目/未归档任务，日周累计三档可下钻）。影响：四格现为 战略目标（含推进项目）/ WCE 探索 / WRR 复用 / 未归档任务（N/M）。
