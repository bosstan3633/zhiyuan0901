### 视觉焦点契约（V3.8.7 起）

**每个工作面只允许一处 `--fs-display`（22px）级主体**，其余标题一律 ≤ `--fs-headline`。

| 工作面 | 唯一主角 | 次级焦点 | 首现版本 |
|---|---|---|---|
| **调度台** `/` | 今日三件事（22px + `shadow-lg`） | 三张卡 / 年度热力图（15px） | V3.8.7 |
| **方向台** `/compass` | **愿景**（`.tl-text`，22px + `shadow-lg`） | 攻坚项目（accent 边框 + 淡底） | V3.8.8 |

- 由判据 **W7-1/W7-2/W7-3、W8-1~W8-5** 把守；**W7-2 / W8-5 做全站现扫**，约束标题级 `display` 合计**恰好两处**（今日三件事 + 愿景），防止契约被后续轮次稀释。
- ⚠ **例外**：手册工具页与图标位（`.gs-io-icon` / `.cdf-icon`）允许 display；回收站现已内嵌设置页，不再作为独立工具页，见判据豁免说明。
- ⚠ **层级倒置是通病不是孤例**：V3.8.7 修掉热力图「指标 17px > 区块标题 15px」，V3.8.8 修掉方向台「面包屑 16px > 内容标题 11px」。**规则：区块内的大数必须小于该区块的标题**（W7-4 / W8-3 分别钉住）。
- ⚠ **方向台面包屑维持 16px**：R123 定案「工作台 / 项目详情 / 方向台三页页头统一」是跨页一致性决策，消倒置靠**抬内容标题**而非压导航。
- ⚠ **「愿景」这个词有两处不同含义，别混**：本表的主角是**方向台顶部那句语义根**（产品名与 Slogan「自有我方向」都指向它，故用 display）；而 V3.8.37 的 C5 曾把方向台**引导文案**里的「从一句愿景开始」改掉——因为六层结构的**最顶一层才是愿景**，方向台这一步引导的其实是**战略目标**层。同一份文件里两处都在，别看到「愿景」就以为是同一件事。

## 五、存储架构

> ★**2026-10-18 全表更正**：旧表写的键名**全部不是现行键名**（都是 V1 时代的短名，漏了版本后缀——差异见文末差异账第 2 行）。现行键由 `shared/storage/keys.ts` 的 `K` 字典持有，且 **R159 门禁规定「`src/**` 内除该文件外任何 `zy_*` 字面量即红」**——所以本文这张表只能是一份**导读**，不是可复制的键名来源。★**连旧键名都不在这里复述**：文档里每多写一份字面量，就多一个会与真源漂移的副本，而复述旧值还容易让自建校验假红（判据 `B8-6b` 就因此踩过一次）。

| 通道 | 键/库（`keys.ts` 常量） | 内容 | 写入时机 |
|------|-------|------|---------|
| **主数据** | `K.DATA` = `zy_data_v2` | 单根 JSON：resources/tasks/curiosities/argCards/workspaces/categories/tags… | repository.saveData（300ms 防抖） |
| **UI 偏好** | `K.UI` = `zy_ui_v2` | 主题/密度/排序/抽屉宽度等 | saveUIPrefs |
| **事件日志** | `K.EVENT_LOG` = `zy_event_log` | 操作流水（create/call/status/delete/restore/purge） | 随 saveData 带出 |
| **按日快照** | `K.DAILY_STATS` = `zy_daily_stats` | 热力图 / 复盘的时间序列真源（只增不淘汰） | dailyStatsStore 独立通道 |
| **热度** | `K.STATS` = `zy_stats_v1` | 卡片热度统计（独立键，单击不触发整库写） | 独立通道 |
| **AI 配置** | `K.AI_CONFIG` = `zy_ai_v1` | 密钥与模型配置（**只在本机，不外发**） | 设置页 |
| **附件** | `IDB_NAMES.ASSETS` = `zy_assets`（IndexedDB） | Blob 附件（≤20MB/文件） | 上传时直写 |
| **导出包标识** | `EXPORT_MARKERS.ASSET_PACK` = `zy_asset_pack` | 附件包 zip 的 manifest.type（**不是存储键**） | 导出附件时 |
| **运行期错误** | `K.ERROR_LOG` = `zy_error_log` | 页面报错流水 | 捕获时 |
| **会话缓存** | `K.PROJ_DIAG` = `zy_proj_diag_v1`（**chrome.storage.session**） | 方向台项目 AI 诊断报告：关浏览器即失效、不进主根、不随导出外发 | 生成时 |

- **★没有独立的「备份」存储键**：备份/导出走**文件下载**（JSON 快照直接落盘），不是往 chrome.storage 里另写一份。旧表曾列过一个备份键 —— 那个键**从不存在**，别去找。（差异见文末差异账第 2 行）
- **★迁移戳与迁移报告另有独立键**：`K.MIGRATE_BACKUP`（分类→标签迁移前全量备份）/ `K.MIGRATE_REPORT`（迁移报告，**刻意不进主根**——这是红线更正）/ `K.MIGRATE_OPTOUT`（回退开关）/ `K.AI_CAPTURE_ENRICH_MIGRATED`（一次性迁移戳，**不随备份外发**）。
- **★删除一律软删、永久保留**：全库无 `purge` / `retention` / 过期清理定时器——回收站的 5 个分区只是按 `deletedAt` 过滤展示。**没有「30 天自动清除」这回事**，任何文案不得承诺期限。
- **`K.LEGACY`** 登记 V1 时代遗留键（`lm_data_v5` 等），启动期清理。

## 附 · 本轮回填改了哪七类（2026-10-18 · V3.8.41）

写在最末不是为了自夸，是因为**这份文档此前最大的问题不是"错了几处"，而是"没人知道它错到哪一步"**——只有版本行被更新过，正文数字静默地停留在几个月前，而读者完全看不出来。

| # | 过时项 | 旧值 | 新值 | 为什么会静默 |
|---|---|---|---|---|
| 1 | **门禁基线整表** | 回归 1,675 / 带 3 条失败 · 索引 180 文件 43,113 行 · 实拍 100 图 · 入口 24↔26 | 2,141 通过 / 56 分片 · 279 个源文件 60,763 行 · 120 图 · 26↔29 | 门禁是**越修越好的东西**，旧读数不会自己失效，只会越看越像"还行" |
| 2 | **存储键名** | `zy_data` / `zy_ui` / `zy_stats` / `zy_backup` | `zy_data_v2` / `zy_ui_v2` / `zy_stats_v1` / **无 backup 键** | 旧键名是 V1 时代遗留；`zy_backup` 那行**纯属虚构** |
| 3 | **主题数** | 「六主题令牌」 | **四主题**（linear / raycast / apple / notion） | 四主题从 V3.8 就定型了，"六"是早期草稿数字的残留 |
| 4 | **AI 能力数** | 24 个 | **26 条声明 ↔ 29 调用点** | 逐轮 +1，文档没有跟着数 |
| 5 | **目录规模** | views 9 / components 24 / composables 18 / utils 37 | **13 / 26 / 24 / 46** | 组件随拆随合，起落不固定 |
| 6 | **视图清单** | 五大视图 | **六大视图**（补 `ProfileInsights.vue` `/profile`）+ `FieldEditor` 无路由 | 新页加进来时最容易只改 README 与透视卡，漏了架构图 |
| 7 | **版本同步清单** | 第 1 条写 `version: '3.8.6'`；缺 ManualPage | `version: '3.8.41'`；补第 7 条 + 三处"不是版本号但同批必须动" | 旧表第 5 条写 `v2/README.md`、第 7 条写"设置页关于（无需手改）"，而真实情况是**设置页读 manifest 没错，但手册页有一份手写版本文案** |

★**这一节的教训可以推广**：「活文档」三个字最容易变成"文档是活的"这种自我安慰。真正让它活着的不是文档本身，而是**「文档里的数字必须有人负责在每次发版时回仓实跑一遍」这件事**。V3.8.41 之前没人做，于是它静默腐烂了大约二十个版本。⇒ 从 V3.8.41 起，**架构总览的数字随每批交付一起回填**，且写明口径（如"含 `.css`，不含子目录"），让下一个人能判断该信几分。
