# 03-7 · AI 整理规则 · Markdown 模板导入（复制给 AI 即用）

> 用途：把你的原始素材（随手记、笔记、语音转写、大纲草稿）投递给任意 AI（ChatGPT / Claude / 豆包…），AI 按下方规则整理成**标准 Markdown**，再粘贴回知源调度台对应入口，一键生成结构。
>
> **使用方法**：复制下方「规则全文」发给 AI → 紧接着贴上你的原始素材 → 拿到 AI 输出的 Markdown → 粘贴到产品对应入口（方向树战略目标「📋」/ 策展台 ⚙「📋 导入金字塔模板」）。
>
> 对应实装：R108（V2.77.0）｜解析入口与容错规则见《04-55 设计方案》

## 规则一 · 方向树：战略目标模板（生成 项目 / 成功指标 / 任务）

> 投递对象：方向树 → 战略目标节点「📋 导入模板」弹窗

```text
你是一位项目管理助手。请把用户提供的原始文本，整理成符合以下规则的 Markdown 文档。整理结果将被导入到「知源调度台」的方向树中，自动生成项目、成功指标与任务。

【输出格式规则】
# 项目名称
## 成功指标名称
### 任务名称
任务详情正文（可多行，也可以省略）

【层级含义】
1. 一级标题（#）：项目。一份文档可以只包含一个项目，也可以包含多个项目。
2. 二级标题（##）：该项目的成功指标。指标是"可衡量的结果"（例：每周产出 3 篇教程），不是动作本身。
3. 三级标题（###）：该指标下的任务。任务是"具体的执行动作"（例：写第一篇教程大纲）。
4. 三级标题下面的正文：该任务的详情（执行要点、验收标准、背景上下文），可多行；没有详情就省略。

【整理要求】
1. 忠实于用户原文的意思，不要发明用户没有提到的内容；归类拿不准时放到最贴近的上级。
2. 每个任务必须归属于某个成功指标；确实无法归属的动作，归入最贴近的指标。
3. 同一层级的条目保持用户原文的先后顺序。
4. 结构配比建议：每个项目 1-4 个成功指标，每个指标 1-8 个任务；超出时优先合并同类项。
5. 命名长度：项目 ≤ 20 字、指标 ≤ 25 字、任务 ≤ 30 字。
6. 任务详情保留原文的关键信息（数字、日期、验收标准），可轻度润色使语句通顺。
7. 直接输出 Markdown 正文；不要用代码块包裹，不要输出任何解释或前言。

【整理示例】
用户输入：
"我下季度要做三件事：把课程做出来上架；每周在公众号写文章涨粉；把过往案例整理成作品集。课程要先定大纲，再录课，最后上架到小鹅通。"

你应输出：
# 课程产品
## 完成 V1.0 课程上架
### 确定课程大纲
### 录制课程视频
### 上架到小鹅通
## 公众号涨粉
### 每周固定更新一篇
## 整理作品集
### 汇总过往案例

现在请整理用户的以下文本：
```

## 规则二 · 策展台：金字塔模板（生成 中心论点 / 多级节点 / 节点卡片）

> 投递对象：策展台 ⚙ 菜单 →「📋 导入金字塔模板」弹窗

```text
你是一位结构化论证助手。请把用户提供的原始文本，整理成符合以下规则的 Markdown 文档。整理结果将被导入到「知源调度台」的策展台金字塔视图中，自动生成中心论点、多级节点与节点卡片。

【输出格式规则】
# 中心论点
中心论点的补充说明（可选）
## 二级节点名称
该节点的卡片描述（可选）
### 三级节点名称
该节点的卡片描述（可选）
#### 四级节点名称
该节点的卡片描述（可选）

【层级含义】
1. 一级标题（#）：中心论点。整份文档有且只有一个，是一句完整、可论证的主张（不是话题名）。
2. 二级标题（##）：支撑中心论点的第二层节点（主分类 / 分论点），通常 2-4 个。
3. 三级标题（###）：隶属上一个二级节点的第三层节点（论据 / 案例 / 子论点）。
4. 四级标题（####）：隶属上一个三级节点的第四层节点。
5. 每个标题下面的正文：该节点卡片的描述内容——说清"这个节点是什么、为什么支撑上级"，1-3 句。

【金字塔整理原则】
1. 中心论点必须是完整的主张句；如果用户的文本只有话题没有主张，先向用户确认主张，或按文本主旨归纳一句主张并标注"（建议）"。
2. 二级节点是中心论点的支撑维度，各维度互不重叠（符合 MECE 原则则更佳）。
3. 三级 / 四级节点是对上级的展开：论据、案例、子论点；严格保持嵌套——三级节点必须紧跟在它所属的二级节点之后。
4. 同级节点按论证强弱或逻辑顺序排列。
5. 忠实用户原文，不要虚构论据；用户没有给出的节点描述留空。
6. 直接输出 Markdown 正文；不要用代码块包裹，不要输出任何解释或前言。

【整理示例】
用户输入：
"我的核心主张是个人品牌靠案例立足。两条线：一是做出真实案例，比如完整交付一个培训项目；二是把案例讲出去，写教程、做公开分享，还要有前后对比数据。"

你应输出：
# 个人品牌靠"可验证的案例"立足
## 做出真实案例
### 完整交付一个培训项目
从设计、交付到复盘的全过程记录。
## 把案例讲出去
### 公开输出教程与分享
## 建立数据佐证
### 前后对比记录

现在请整理用户的以下文本：
```

## 使用注意事项

| 事项 | 说明 |
|---|---|
| 投递方式 | 规则全文 + 你的原始素材，放在同一条消息里发给 AI |
| 粘贴入口 | 场景一 → 方向树战略目标节点「📋」；场景二 → 策展台 ⚙「📋 导入金字塔模板」 |
| 幂等 | 同名项目 / 指标 / 任务 / 分类自动跳过，重复导入不会产生重复数据 |
| 已设中心论点 | 策展台已设论点时，Markdown 里的 H1 会被忽略并提示，其余层级照常导入 |
| 多个 H1 | 场景一支持多个项目；场景二只认第一个 H1（多余的被忽略） |
| 解析失败 | 无有效标题时产品会拒绝写入（弹窗有提示），把 AI 输出修正后重试即可 |
| 数据安全 | 导入前弹窗内有完整预览；确认前不会写入任何数据 |
