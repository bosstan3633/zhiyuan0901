## 1. 产品名称与内涵
- 中文名：**知源调度台**；视觉品牌：**知源**；日常简称：**知源**（首次出现用全称）
- 英文名：Zhiyuan Control Center（缩写 ZCC，仅用于 Logo/仓库/技术文档，文案中不混用）

**名称核心解释（标准释义）：**
> **知源，是知道自己为何出发，也知道所用信息从何而来。**
> **调度，是围绕自己的问题，让合适的信息、工具与材料参与行动。**

- 知源调度台不是以"拥有更多信息"为目的，而是帮助用户在信息与工具不断涌现的环境里，**保持自己的工作中心**。
- 向内，看见自己的方向、问题与好奇；向外，连接值得参考的信息源和可以借助的工具；在行动中，把外部资源组织为解决问题的助力，再将阶段成果策展成自己的表达。
- **边界声明**："知源"是一种品牌寓意，不表示产品自动保证信息真实、自动鉴别一手来源，或替用户完成判断。

## 2. 品类
**你在浏览器里的个人调度中台。**
面向普通用户的解释：**围绕自己的方向，组织探索、调用与成果的工作空间。**
不是书签管理器，不是笔记软件，不是待办清单，不是新标签页美化工具，也不是复杂驾驶舱。

## 3. 核心心智与视觉主题
- 心智画面：**外部万千，内有主线**——一条属于用户的行动路径：沿途留下好奇，接入所需工具与材料，并形成阶段成果。
- 主视觉不是资源仓库，也不是复杂驾驶舱。

## 4. Slogan 体系
| 层级 | 表达 | 用法说明 |
|---|---|---|
| **主 Slogan** | **万千可调用，自有我方向。** | 品牌立场，不作为兼容万种工具或自动执行的数量承诺 |
| **能力解释句** | 看见方向，留下好奇，调用所需，策展成果。 | 交代工作过程 |
| **品类解释句** | 你在浏览器里的个人调度中台。 | 回答"这是什么" |
| **品牌理念句** | 以好奇过滤信息，以调度致用于己。 | 保留思想资产，用于理念页、品牌手册扉页和深度宣讲；"过滤"指用户基于好奇作出选择，不宣传为自动信息过滤功能 |

三者分工：主口号强调主体性，解释句交代工作过程，场景文案落到具体情境；避免每一句都重复宏大理念。

## 5. 一句话定位
**知源调度台，是你在浏览器里的个人调度中台。**

完整定位陈述：知源调度台面向以浏览器为主要工作入口的独立知识工作者，将个人方向、好奇探索、工具与资源调用，以及主题成果策展组织在同一个工作环境中，帮助用户围绕自己想解决、想研究的问题推进每一天。

## 6. 目标用户
**首要用户不以职业名称或使用工具数量单独定义，而以工作方式识别：**
- 主要在浏览器中接触信息与开展工作；
- 需要独立决定研究什么、投入什么、如何交付；
- 同时使用多个信息来源和工具；
- 希望将探索与行动连接，并形成自己的成果表达。

优先验证人群：独立顾问、研究型创作者、独立研究者及多项目知识工作者。**这是市场进入假设，不是已经证明的付费排序。**

**不是为谁设计**：想找"存一堆链接就不看"工具的人；已有完整 Notion/Obsidian 工作流且满意的人；强依赖多人实时协作、自动云同步或自动化执行的人（当前边界，见 §11）。

## 7. 核心问题（产品所回应的问题）
知源回应的不是单纯的"信息太多"，而是：
> **外部可能性持续增加，个人却难以把方向、探索和行动组织在一起。**

这种断裂表现为：看到新工具就想尝试，却不清楚与当前问题有什么关系；产生好奇却没有后续承接；任务做了不少，却看不清它们如何连接长期方向；形成了材料和产出，却没有组织成能够表达判断的成果。

## 8. 核心价值（三项主要价值 + 贯穿方式 + 信任支撑）
**主卖点：在信息洪流中，有一个围绕自己展开工作的地方。**

| 层 | 内容 |
|---|---|
| 三项主要价值 | **看见方向**：今天的行动有来处。**留下好奇**：探索从自己的问题出发。**策展成果**：做过的事形成自己的表达。 |
| 贯穿方式 | **调用所需**：让信息源、工具与材料参与当前行动。 |
| 信任支撑 | 本地保存、无需注册账号、可导出迁移、删除可恢复（以当前版本验证结果为准；本地保存不等于自动备份）。 |

## 9. 核心功能事实（对外可讲的功能清单）
- **三大系统页 + 自定义工作台 ×N**：调度台（今日出发点：方向状态四指标 + 今日三件事 + 项目调度 + 好奇心培育）、方向台（主航线 + 项目总览 + 任务调度）、策展中心（灵活策展空间：分类树 + 混排网格 + 镜像），以及用户自定义的 N 个资源工作台。
- **六层结构（对外称"目标与行动"，少用未经解释的"方向链"）**：愿景 → 使命 → 战略目标 → 项目 → 成功指标 → 任务；任务可挂指标，未挂即"未归档任务"可级联归档。
- **全局搜索（Ctrl+K）**：任意网页浮层 + 新标签页内均可调出；标题/标签/分类/项目名命中；拼音与首字母匹配；双击直达。**这是对已收录条目的检索，不是全盘全文检索。**
- **快速采集（Ctrl+Shift+J）**：任意网页数秒收录，自动预填标题/URL/选中文本。
- **好奇心采集（Ctrl+Shift+I）**：念头速记，选中文本自动填入；可转为任务卡或资源卡。
- **今日三件事**：≤3 槽锁定当日最重要行动，与项目/指标关联，可复制昨日、导出 CSV。
- **方向状态四指标**：DHI 方向契合度 / WCE 好奇探索（含转化）/ WRR 资源复用 / 未归档任务；日/周/累计三档，四格均可下钻。
- **策展中心**：镜像分类与原生分类同树混排、卡片自由拖拽、源数据零影响；策展=围绕主题进行取舍、分层与表达（论证型策展可用"主题—判断—论点—证据"结构，不强制所有成果采用同一形式）。
- **回收站**：删除一律软删，可单条恢复或永久删除（含附件清理）。
- **导入导出**：JSON 全量导出/按工作台导出、CSV（UTF-8 BOM）、Markdown；书签 HTML 导入；导入前自动备份；并集合并。
- **附件**：图片/HTML/PDF 挂卡，IndexedDB 本地存储，单文件 ≤20MB。
- **主题与密度**：四套主题（深空薰衣草默认）、三档密度。

## 10. 数据与安全事实（信任基础）
- 数据 100% 存储本机：主数据 `chrome.storage.local` 单根 JSON（已申请 unlimitedStorage，无 10MB 上限）；附件存 IndexedDB。
- **无账号、无云端、无用户标识、无使用追踪、代码内无任何 http 上传**。
- 删除一律软删（回收站可恢复）；导入前自动备份到本地文件；多窗口并发写入有合并保护。
- 导出 = 一份 JSON/CSV/Markdown 文件，可拷贝到任何设备；迁移 = 导出 → 导入并集。
- 卸载扩展 = 数据随浏览器配置文件存在（导出是唯一推荐的长期备份方式）。
- **对外表达边界：本地保存 ≠ 自动备份；须提醒用户定期备份。**

## 11. 产品边界（我们不做什么）
不以复杂长文编辑、团队协作、云同步或自动替人决策为当前承诺；不将快捷搜索包装成全盘全文检索；不把资源链接和实际内容存储混为一谈；不做 AI 替用户决策；不做"第二大脑"；不做使用追踪与画像；不做 KPI 压迫式管理。

## 13. 标准术语（核心动词 + 名词）
| 术语 | 定义 |
|---|---|
| **调用** | 根据当前问题，组织信息源、工具、方法与材料，让它们参与任务（贯穿方向、探索与成果的工作方式；不暗示自动操控所有工具） |
| **策展** | 围绕主题进行取舍、分层与表达，形成可回看、可理解的成果 |
| **好奇** | 工作中冒出来的、值得追问的问题；先留下，回看时再选择是否投入探索 |
| **收录（入台）** | 把网页/文件/笔记/念头收进知源，成为一张卡；**对外首次使用"入台"时，解释为"收录到知源"** |
| **归位** | 给卡片归属：工作台、分类、标签、项目、指标 |
| **调出** | 需要时把卡片找回来并打开 |
| **复用** | 同一资源被再次调出使用（WRR 计数） |
| **校准** | 用方向状态与方向树检视行动与方向的关系 |
| 工作台 | 用户自定义的资源域（含分类树/看板/列表） |
| 调度台 | 默认首页：今天从哪里出发（**命名建议（未实施）**：内部评估将页面改称"今日/今日调度"，避免产品整体与单个页面同名） |
| 方向台 | 主航线 + 项目总览 + 任务调度 |
| 策展中心 | 跨工作台的灵活策展空间（含镜像） |
| 三件事 | 今日 ≤3 件最重要行动 |
| 主攻 | 被标记为当前重心、置前并高亮的项目 |
| 镜像 | 策展中心对源卡的引用式呈现，源数据零影响 |
| 未归档任务 | 未挂项目/指标或引用失效的任务 |

## 14. 禁止与慎用表述
- ❌ 不要说：收藏夹工具、笔记软件、新标签页美化、国产 Notion、第二个 Obsidian。
- ❌ 不要承诺：云同步即将上线、具体价格/上市时间、团队协作功能、买断制已开放。
- ❌ 夸大红线：**"掌控一切""永不迷失""自动识别可信来源""所有工具一键调用""链接万物"**——一律禁用。
- ⚠ 慎用："AI 驱动"（知源不替用户决策）；"智能推荐"；"三秒"等效率数字仅在经演示验证的动作上使用。
- ⚠ 不将用户描述成落后、失控或必须不停追赶的人；不打焦虑。
- ✅ 语言规范：对外首次使用"入台"解释为"收录到知源"；优先说"目标与行动"，少说未经解释的"方向链"；优先说"信息源与工具"，不用"链接万物"代替功能说明。
- ✅ 表达层级：**立场 → 体验 → 动作 → 证据**（例："自有我方向"是立场；"看见方向"是体验；"将今日任务关联到项目"是动作；真实界面和操作演示是证据）。
