## 一、时代背景：AI 加速与工具爆炸

我们正处在人类历史上从未有过的双重浪潮之中：**AI 加速**与**工具爆炸**。

- 一方面，大模型让"获取答案"的成本趋近于零——三秒一个回答，三十秒一篇总结；
- 另一方面，收藏夹、公众号、PDF、笔记软件、聊天记录、Excel 清单……信息以千百倍于消费速度的方式涌入，且没有任何一个工具能统摄它们。

**当获取答案太容易，而独立追问太难，人的认知能力就在被静默外包。** 知识工作者最珍贵的不是手里有多少信息，而是仍然保有**独立提问、独立串联、独立判断**的能力。这是这个时代最需要被守护的东西。

## 二、五重苦楚：知识工作者的真实摩擦

| # | 苦楚 | 日常画面 |
|---|------|---------|
| 1 | **收不齐** | 链接随手丢书签、PDF 丢硬盘、金句丢聊天记录——采集永远没有归处 |
| 2 | **看不见** | 信息进来即死，散落各处不成结构，无法形成自己的认知地图 |
| 3 | **找不回** | 搜索靠文件名和模糊记忆，时过境迁，再也回不到当时的上下文 |
| 4 | **信不过** | 被算法喂来的信息无法判断信度，收藏来源不明，引用时不敢用 |
| 5 | **带不走** | 数据锁在云服务里，换工具、换环境等于从头再来 |

这五重苦楚，指向同一个根因。

---

## 三、根因：工具不围绕人，人被迫围绕工具

- **工具碎片化**：书签、笔记、清单、搜索彼此孤立，信息在切换中流失；
- **算法绑架注意力**：Feed 流与推荐算法把"你想知道什么"替换成"它想让你看什么"；
- **云端锁定数据**：你的资产存在别人的服务器上，权限、价格、存续都不由你决定；
- **AI 替你决策**：自动化插件把判断权交给流水线，人退化为审核员。

**对抗技能爆炸与焦虑的唯一解法，是建立一套无法被外界算法冲垮的个人工作流底盘。**

---

## 四、知源是什么：贯通三现场的个人增强系统

**产品定义**：知源工作台**不是"资源收藏或调用工具"**，而是一个贯通**信息现场、资源现场与方向现场**的个人增强系统。

```
信息现场  ──►  资源现场  ──►  方向现场
（看到什么）   （留下什么）   （为什么做）
   采集           组织           执行
```

- **短期**：解决查找、调用和沉淀的现实摩擦；
- **中期**：建立用户自己的**高信度资源网络**与**可复用能力**；
- **长期**：帮助用户在 AI 加速与工具爆炸中，**保有问题、判断、节奏和方向**。

我们不需要又一个把人变成流水线审核员的自动化插件。知源做的是一套底层的**个人资源调度体系与心流脚手架**：将散落在书签、硬盘和对话记录中的高信度资产结构化，让每天的执行始终锚定在真正重要的主攻方向上。

---

## 五、方案：个人资源调度体系与心流脚手架

**资源调度**：所有高信度资产（资源、好奇、项目、任务）进入同一套本地结构，按你的逻辑组织，随时可调度、可串联、可溯源。

**心流脚手架**：把"从想法到落地"的每一步摩擦降到最低——

- 新标签页即思考起点：新想法 **≤5 秒**落地；
- 看板、分组、密度自适应：执行流永远锚定主攻方向；
- 双标记体系（置顶 + 星标）：重要的事不会被洪流冲走；
- 软删 + 回收站：敢于整理、敢于断舍离，永远有退路。

**本地优先**：`chrome.storage.local` 单根 JSON，**零账号、零云端、零订阅**。你的认知资产只属于你——迁移即复制粘贴，永久可控。

## 六、理论栈

| 理论 | 在产品中的落点 |
|------|---------------|
| **认知卸载（Cognitive Offloading）** | 工作记忆有限，把高信度资产外部化到可信容器，大脑只做判断 |
| **心流理论（Csikszentmihalyi）** | 降低认知摩擦、保持节奏，让执行进入心流而非琐碎切换 |
| **高信度资源网络** | 区分"信息流"与"高信度资产"，收藏即溯源，引用即可信 |
| **Local-First 软件理念（Ink & Switch）** | 本地存储、离线可用、数据主权归用户，云只作为可选的同步通道 |

> 晚上他打开罗盘，看到"湖北升学"项目下的资源地图（看得见）。明天的工作，依然锚定在这个方向上。这些数据存在他自己电脑里，明天、明年、换任何设备，都带得走（带得走）。

## 九、诚实边界：我们刻意不做什么

| 不做 | 原因 |
|------|------|
| ❌ **不做把人变成审核员的自动化流水线插件** | 判断权归人，不归流程 |
| ❌ **不做 AI 替你决策** | AI 是求证工具，不是认知代理；认知主权归用户 |
| ❌ **不做云端社交与协作** | 单机本地优先，数据主权不可谈判 |
| ❌ **不做大而全的"第二大脑"** | 聚焦资源调度与认知增强，其余交给专业工具 |

### 硬性规则（违反即返工）

| # | 规则 | 说明 |
|---|------|------|
| 1 | **版本号唯一来源 = `v2/src/manifest.ts`** | 改版本必须同步 `package.json`、设置页关于、手册页、`regression.cjs` 版本断言共 5 处 |
| 2 | **单向挂载红线** | 仅 TaskCard 持有 `mountedResourceIds/mountedCuriosityIds`；Resource/Curiosity/TagNode Schema 禁止出现 taskId |
| 3 | **删除一律软删** | 任何删除只写 `deletedAt`（回收站 `/recycle` 可恢复）；`stats.lastVisits` 只经 `recordResourceOpen` 更新 |
| 4 | **排序 computed 禁止 `.sort()`** | 支持拖拽排序的列表，渲染 computed 不得原地 sort |
| 5 | **样式只用 `tokens.css` 令牌** | 禁止硬编码色值；新增 UI 须在六主题下逐一走查 |
| 6 | **定位不走 tabs.query 的 hash** | chrome.tabs.query 返回不含 hash，页面内定位走 zy-where 询问链路 |
| 7 | **新增功能同步追加回归** | 每轮新功能必须在 `v2/scripts/regression.cjs` 追加断言项 |
| 8 | **构建前清空 dist** | vite 配置 `emptyOutDir:false`，不清理会累积多轮构建残留 |
| 9 | **迭代按轮次记录** | 每完成一轮在 `docs/` 落一份交付说明，并更新 regression.cjs 轮次注释 |

## 🌅 愿景

我们相信：

- **你的认知主权比任何云服务都重要**；
- **工具应该服从人，而不是人服从工具**；
- **在 AI 时代，"仍然能独立思考"是一项值得捍卫的能力**；
- **每一个有好奇心的个体，都值得拥有一个不背叛他的工作台**。

知源工作台的目标，是陪你走过 AI 时代最容易被同化的那些年——让你打开新标签页时，想起的第一件事不是"今天要看什么"，而是**"今天我想知道什么"**。

> **从好奇出发，向源头求证。**
> 这不只是一句 slogan，这是认知的练习，也是工具的立场。
